# BUG-413: 主卡片播放按钮加时间后排版错乱，需重评估设计

> **结论（2026-10-27 复核）：维持现状，不加第二个控件，本档关闭。**
> 现象不可复现（当前卡片没有独立的播放按钮，也没有任何排版错乱 —— 见下方验收证据）；
> 当初引发本档的那次「加播放按钮 + 时间」的尝试从未提交过。
> A/B 两案均被否，理由见「为什么不做」。

## 现象（当时的说法 vs 真实的「主卡片」）

「主卡片」= 文件域的条目卡 `MediaCard.tsx`。它**从来没有独立的播放按钮**，结构是：

- **整个封面是一个 `<button>`**（`MediaCard.tsx:386-432`，testid `media-card-cover`），点任意处
  ⇒ 打开查看器（视频即播放）；
- hover 时封面中央浮出一个圆形图标按钮 + 「浏览」文字（`:413-424`，BUG-381 加的可见性补丁）；
- 右下角另有一个**独立的时长徽标**（`:427-431`，`absolute bottom-1 right-1`）。

本档说的是：有人想在卡片上加一个**带时长**的播放按钮，结果它与右下角那个既有的时长徽标
**撞在同一个角位** ⇒ 排版错乱；于是停在 A/B 两案待拍板。**那次改动从未进过提交**
（`git log --all --grep=413` 零命中）。

## 根因

不是产品缺陷，是**两个控件抢同一个角**：时长徽标已占 `bottom-1 right-1`，任何新按钮放同一
区域必然重叠。

## 为什么不做 A / 都不做 B

- **A（把播放移到右侧并加绿色「播放」文字）**：会造出第二个「同义动词」入口 —— 点封面已经
  打开查看器，再给一个常驻播放键是**同一动作的第二种形态**，违反「一动词一端点」；而在
  240px 卡片上常驻文字按钮会挤占封面。
- **B（保留纯图标）**：就是现在这样 —— 封面 hover 出来的图标按钮已经是「纯图标」形态。
- 用户 2026-10-26 已确认「按钮已经加好了」⇒ 现状即达成意图；剩的问题（时长的可见性）由右下角
  那个徽标解决，两者各占一角、互不重叠。

## 修复

不改代码（结论：维持现状）。仅把结论与上面的理由写回本档，避免下次又被当成待办重新提出。
