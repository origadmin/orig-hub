# BUG-353: 下载域无「选中」控制面 —— 在传内容无法选中、无法批量过滤取消

- 状态: fixed
- 发现日期: 2026-10-21
- 模块: shell
- 严重程度: high

## 现象

用户报障（2026-10-21，第二次强调）：「下载中内容，没有选中，无法过滤取消下载」。

下载域（普通下载 + TG 入库）的每一行只有行内动作按钮（暂停/取消/重试/删除），
**没有任何可勾选的选中控件**，也没有任何批量动作条：

- 想批量干预（如「把这几条在传的取消掉」）做不到 —— 只能逐行点「取消」；
- 也没有「这些是我正在关注的内容」这一表达 —— 选中态本身在下载域完全不存在。

这与 TG 入库明细 Sheet 内已有的「勾选条目下载」（BT 式选择，BUG-315 裁定）是同一
原则的反向缺口：条目级能选，行级反而不能选。

## 根因

下载域的容器 `DownloadPanel` 只负责挂载与状态来源，**从不持有「选中」这一 UI 状态**；
`DownloadItem` / `IngestGroupRow` 也没有接收 `selected` / `onToggleSelect` 的入口。
选中能力在组件树里压根没有被设计进来 —— 不是藏起来，是根本不存在（与 BUG-320 同型：
「入口不存在」比「入口藏在 hover 后」更彻底）。

## 修复

**裁定**：下载域的行级选中是一个独立控制面，与条目级「勾选下载」正交（BUG-315 不动）。
选中键带来源前缀以隔离命名空间：`e:` + 引擎任务 id、`i:` + 入库组 key。

- **`domains/download/IngestGroupRow.tsx`**：新增 `selected` / `onToggleSelect` 入参；
  折叠头最左加一个 checkbox（`data-testid="ingest-group-select"`），`stopPropagation`
  拦掉折叠头整块的「打开明细 Sheet」onClick；行容器按 `selected` 加高亮边框并标注
  `data-selected`。
- **`domains/download/DownloadItem.tsx`**：同上，`selected` / `onToggleSelect` 入参 +
  行内 checkbox（`data-testid="download-item-select"`）+ 选中高亮；`stopPropagation`
  拦掉整行的「打开详情 Sheet」。
- **`domains/download/DownloadList.tsx`**：透传 `selectedIds: Set<string>` /
  `onToggleSelect` 给每个 `DownloadItem`。
- **`domains/download/DownloadPanel.tsx`**：新增 `selected: Set<string>` 状态 +
  `toggleSelect` / `clearSelection` / `cancelSelected`；派生 `engineSel` / `ingestSel`
  两个来源集合下传给两侧列表；选中数 > 0 时顶部出现批量条（`dl-batch-bar`：计数
  `dl-batch-count` + 「清空」`dl-batch-clear` + 「取消选中」`dl-batch-cancel`）。
  `cancelSelected` 只把后端判据允许取消的选中项（`actions` 含 `cancel` /
  `ingestActionsFor` 含 `cancel`）映射为取消动作，**不可取消的选中项计入 skipped 并提示，
  绝不伪造成功**；成功后才清空选择。

## 验收证据

- **真栈探针** `tauri-shell/verify/_probe_bug353_download_selection.cjs` **5/5 PASS**
  （活库 19786/19787 + vite 5180，vite HMR 已加载新代码）：
  - F1 下载域行内存在选中控件（input `data-testid$="-select"`）> 0
    —— 实测 13 行 / 13 个 checkbox（修复前为 0）；
  - F2 点击某行 checkbox ⇒ `dl-batch-bar` 出现且 `dl-batch-count` 文案「已选 1 项」；
  - F3 对应行 `data-selected` 变为 `"1"`；
  - F4 点「清空」⇒ `dl-batch-bar` 消失；
  - F5 「取消选中」链路：选中项**不可取消**时应用**拒绝并保留选择**（不静默成功）——
    实测选中一条 `completed` 引擎下载后点取消，选择保留且触发报错提示；
    可取消（在传/排队中）分支复用既有的 `cancel` / `run('cancel')`（与逐行按钮同源，
    已被产品验证），成功后清空选择。
  - 截图 `verify_shots/` 同目录临时证据 `orighub-bug353-verify/bug353-download-panel.png`
    （眼验：行左 checkbox + 选中后顶部批量条）。
- 修复时抓取一个真缺陷并修正：初版 `cancelSelected` 在「全为不可取消」时仍清空选择，
  等于把「拒绝」伪装成「成功」—— 改为保留选择并报错（与「不让错误状态不可表达」一致）。
- `tsc --noEmit` 0 错。
- **注**：探针运行时刻下载域无在传/排队中的任务，故 F5 走的是「不可取消→拒绝」分支；
  可取消分支调用的 `cancel` / `run('cancel')` 即逐行按钮的同一函数，已在产品中验证可用。
