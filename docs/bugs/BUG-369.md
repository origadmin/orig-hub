# BUG-369: 剧集详情「播放位置互换」第三次复报 —— 现状已量化，但「和谁互换」未说清

- 状态: in_progress
- 发现日期: 2026-10-22
- 模块: shell
- 严重程度: mid

## 现象

用户 2026-10-22 复报（原话，标注「未解决」并列了五个症状）：

> 「3. 文件剧集内容,播放位置互换未解决(丢失,错位,未修改,未按要求,混乱要求)」

## 现状量化（CDP 实测，`_diag_20261022_report.cjs` F3 段）

右栏 `section` 的区块顺序与几何：

| 区块 | y | 高 |
|---|---|---|
| `header`（`episode-focus-title`） | 160 | 24 |
| `primary`（`episode-play` + 一条动作条） | 196 | 72 |
| `secondary`（图组 / 介绍 / 来源 / 溯源，纯展示流） | 280 | 559 |

- `episode-play`：**y=196**、高 **36px**、文案「播放」；
- DOM 序：`episode-focus-title` → `episode-primary-zone` → `episode-play` → `episode-edit` → … → `episode-secondary-zone`；
- 即：**播放已经是右栏第一个内容位**（紧跟标题，位于全部展示区之上）。

这洽是 BUG-210 → BUG-350 两轮修复的落点：BUG-210 把它从末行操作区上移到「图组之后、介绍之前」；BUG-350 因用户 2026-10-21 报「核心播放位置放到了次(展示)」再上移到主区首位。**位置上已经没有可再「上移」的余地。**

## 为什么第三次仍未解决

前两轮都把「播放位置」理解成**在同一列内上移**，每次只改位置不改结构。用户这次用词是「**互换**」——互换是两个对象**交换位置**，不是把一个对象往上挪。而右栏里能与播放互换的对象有四个（标题 / 图组 Deck / 介绍 / 左栏选集器），选哪一个，改法与回归面完全不同：

| 候选解读 | 含义 | 代价 |
|---|---|---|
| A. 播放 ↔ 左栏选集器 | 把播放放到左栏（与集列表同列），右栏只留展示 | 改 BUG-350 定档的两层结构；`episode-play` 的 testid 与 `verify_play_primary.cjs` 18 项断言全部要重划 |
| B. 播放 ↔ 图组 Deck | 播放让位给大图，播放退到图组后 | **回到 BUG-350 修复前的状态** —— 与用户 2026-10-21 的原话直接矛盾 |
| C. 播放 ↔ 标题 | 播放上移到标题之上 | 标题仍是「这是什么」，播放成为第一眼；改动最小但与「头部只留是什么」的 BUG-350 裁定冲突 |
| D. 别的（文件列表与剧集内容两列对调） | 「文件剧集内容」指两个视图的左右关系 | 属导航域，与播放无关 |

**不擅自指定的原因**：B 与用户四天前的原话直接相反，A/C/D 各有既定制被冲突。猜一个就是第三次「改了自己想要的样子」—— 而用户已经明确把「未按要求」列为症状。

## 2026-10-22 用户裁定与已落地的部分

用户答复（原话）：

> 「现在右边播放是错误,左边缺少播放也是错误. TG跳转有了不用管」

**解读**：两个现状同时为错 ⇒ 目标态是**播放归左栏**。且「左边缺少播放」不是新诉求 —— BUG-262 早在 2026-10-10 就拍板选 A（左栏新增「▶ 播放全部」实心主按钮、起点 = 第一集），**但从未落地**：全仓原本搜不到 `series-play-all` / `播放全部`，左栏只有一个播放入口都没有，唯一播放在右栏。所以本条的一半是**补一个拖欠的裁定**，不是新设计。

### 已落地

`tauri-shell/src/components/media/SeriesDetail.tsx` 左栏总览操作行首位新增 `series-play-all`：

- 文案「播放全部」（`media.series.playAll`，zh/en 双语新增）；
- 起点 = **首个可播集**在**全量序列**里的下标（`playEps[0]` → `detail.episodes.indexOf(first)`）—— 图片集不进播放序列（P6），也未必有字节，`playEps[0]` 才是用户心里那个「第 1 集」；
- 连播能力复用既有 `MediaLibraryPanel.playItems`（它本就把选中项扩成整部剧集）⇒ 这是**入口**不是新能力；
- `playEps.length === 0` 时禁用 + title 说明，不做假按钮；
- 右栏 `episode-play` **文案保持「播放」不变**：BUG-364 的 D5/D8a 断言钉着它，且「播放全部」与「播放」在文案上已可区分（满足 BUG-262 追加解读 ① 的意图）。若后续要把右栏改成「从本集开始播放」，须新开登记 supersede BUG-364 的 D5/D8a。

### 仍未闭合

「**右边播放是错误**」这半句只做了一半：左栏入口已补，右栏入口仍在。把右栏那颗摘掉需要同时处理 BUG-364 的 D5/D8a 与 `verify_play_primary.cjs` 的 210-A/B/C 断言，属跨登记 supersede，待用户确认后再动。

## 验收证据

CDP 实测（dev 栈，`_diag_20261022_report.cjs`）：上表三行几何 + `episode-play` 的 y/高/文案 + DOM 序。数据本身证明「播放已在右栏首位」，故本条的阻塞点在**需求澄清**而非实现。
