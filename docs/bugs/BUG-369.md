# BUG-369: 剧集详情「播放位置」—— 第五次复报，根因是判据把错误形态钉成了正确形态

- 状态: fixed
- 发现日期: 2026-10-22
- 模块: shell
- 严重程度: mid

## 现象（第五次复报，2026-10-22）

用户附截图，原话：

> 「播放按钮位置不对,第五次提出!仍未修复.」

截图 = 剧集详情面板：左栏分集列表（首行 `S01E01 / 1 / 16:40`），右栏顶部一颗**横贯整行、
贴左边缘的绿色实心按钮**「▶ 播放」。用户圈出的位置 = 左栏分集行右侧该有播放入口的地方。

## 现状量化（第三次复报时的 CDP 实测，`_diag_20261022_report.cjs` F3 段）

右栏 `section` 的区块顺序与几何：

| 区块 | y | 高 |
|---|---|---|
| `header`（`episode-focus-title`） | 160 | 24 |
| `primary`（`episode-play` + 一条动作条） | 196 | 72 |
| `secondary`（图组 / 介绍 / 来源 / 溯源，纯展示流） | 280 | 559 |

- `episode-play`：**y=196**、高 **36px**、文案「播放」；
- DOM 序：`episode-focus-title` → `episode-primary-zone` → `episode-play` → `episode-edit` → …；
- 即：**播放已经是右栏第一个内容位**（紧跟标题，位于全部展示区之上）。

这是 BUG-210 → BUG-350 两轮修复的落点：BUG-210 把它从末行操作区上移到「图组之后、
介绍之前」；BUG-350 因用户 2026-10-21 报「核心播放位置放到了次(展示)」再上移到主区首位。

## 为什么前四次都没修好

前三轮都把「播放位置」理解成**在同一列内上移**，每次只改位置不改结构。用户第三次用词
是「**互换**」——互换是两个对象**交换位置**，不是把一个对象往上挪。而右栏里能与播放
互换的对象有四个（标题 / 图组 Deck / 介绍 / 左栏选集器），选哪一个，改法与回归面完全
不同，所以当时没有擅自指定。

第四次（BUG-369 首次落地）已经拿到用户裁定，但**只做了一半**：

- 左栏补了 `series-play-all`（「播放全部」）；
- 右栏那颗满宽 `episode-play` **留着**，理由是「摘它要同时 supersede BUG-364 的 D5/D8a
  与 `verify_play_primary.cjs` 的 210-A/B/C 断言，属跨登记 supersede」。

结果用户看到的是「**两个**播放入口，且**错的那个最显眼**」——比修之前更像没修。

### ★ 真正的根因：验收脚本自己把错误形态钉成了正确形态

`tauri-shell/verify/verify_play_primary.cjs` 是 BUG-210 时代写的，它的三条硬断言是：

| 旧断言 | 内容 |
|---|---|
| `210-A` | 全文档 `[data-testid="episode-play"]` **恰好 1 个**（右栏内恰好 1 个） |
| `210-B` | 它必须**晚于**标题、**早于**本集介绍 |
| `210-C` | 它的宽度 **≈ 父容器内容宽**（`w-full`，±2px）、高度 ≥ 32px |

`210-C` 里的 `Math.abs(v.btnW - v.parentContentW) <= 2` 就是「横贯整行」。**任何「把播放
挪走」的改动都会被这三条判成回归**，而 `RF` 反向证伪注入的是 `w-1/2`（让它变窄），
方向也一致 —— 整个脚本在**加固**用户投诉的那个形态。

⇒ 纪律：**判据与诉求方向相反时，实现改多少次都不会对。先翻转判据，再改实现。**

## 本次落地

### 代码（`tauri-shell/src/components/media/SeriesDetail.tsx`）

1. **删掉右栏那颗满宽播放主按钮**（原 `h-9 w-full gap-1.5 text-[13px]` +
   `data-testid="episode-play"`）。右栏职责 = 「这一集是什么」（展示 + 管理动作），
   播放归左栏。
2. **左栏每条分集行尾新增 `episode-row-play`**（用户圈的那个位置）：
   - 行本身是 `<button data-testid="episode-pick">`，HTML 不允许嵌套 button ⇒
     `span[role=button]` + `stopPropagation`（与既有 `episode-nobytes-cache` 同一模式）；
   - 有字节的视频集 ⇒ `Play` 图标、`title`=「从本集开始播放」（`media.episode.playFromHere`）；
     有字节的照片集 ⇒ `ImageIcon`、`data-kind="photo"`、开图册灯箱；
   - **无字节 / 无来源 ⇒ `return null`**（不做假按钮，BUG-324 复报的教训）。
3. 照片集的「查看大图」保留（照片没有可播的流，那是真能力），但降为动作条里的普通尺寸
   按钮 `episode-view-image`（`h-7 px-2.5 text-[11px]`），不再占满一行。
4. i18n 新增 `media.episode.playFromHere`（中「从本集开始播放」/ 英「Play from this episode」）。

### 判据（`tauri-shell/verify/verify_play_primary.cjs` 整篇重写）

| 新断言 | 内容 |
|---|---|
| `376-A` | `[episode-play]` 在**全文档**与**右栏**内计数均为 **0** |
| `376-D` | 右栏内**任何**可点击元素（`button` / `[role=button]` / `a`）的文案或 `title`/`aria-label` 都**不得**含「播放」/「play」—— 按**语义**扫，不只按 testid，改个名字不能复活 |
| `376-B` | `[episode-row-play]` 计数 ≥ 1，且**当前聚焦那一集**必须有 |
| `376-C` | 它在 `closest('[data-testid="episode-pick"]')` 内；宽度/行宽 ≤ 0.35（图标，不是满宽条）；命中区 ≥ 24×24 |
| `376-C(photo)` | `episode-view-image` 渲染时宽度**不得** ≈ 父容器内容宽 |
| `RF` | 把行内入口的 testid 改回 `episode-play` ⇒ `376-A/D` **必须 FAIL**；还原后 `sha256` 与 `git diff -- <该文件>` 文本逐字相同 |

`RF` 的还原自证不再比对「文件是否出现在 `git diff --name-only` 里」——修复未提交时该
文件**本来就在** diff 中，那样写在本地改完就永远红（旧脚本的洞）。

### 顺带修掉的两处判据缺陷（都是假红，与本缺陷无关）

1. **来源区 `210-D` 已过期**：旧断言是「无备用源 ⇒ 整块不存在、标题零命中」，那是
   BUG-210 的形态。BUG-265 已明确定为**两层门控**（源码 `episode-source-info` 上方
   注释）：信息段（区块标题 + 当前播放来源行）**恒渲染**，只有控件段（切换 / 摘除）
   在无备用源时不进 DOM。⇒ 判据按 BUG-265 的契约重写。
2. **`pane.innerText.match(/来源/g)` 太宽**：溯源区的字段标签 `media.item.sourceTitle`
   （「来源原文：xxx」）被算成区块标题命中 ⇒ 无备用源时判据报 1 处命中。改为
   「整段文字**恰好**等于『来源』」。

### 连带改动

`tauri-shell/verify/verify_bug_254_nobytes_visibility.cjs` 的 `(c)` 段原先靠点
`[data-testid="episode-play"]` 打开播放器，现改点该集的 `episode-row-play`
（行内入口只在有字节时渲染 ⇒「找不到」等价于旧语义的 `disabled`）。
