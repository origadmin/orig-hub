# BUG-402: 验收脚本无分级与索引 —— 开发完成后陷入「未知流程处置」，验证耗时不可预期

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: docs
- 严重程度: mid
- 报告: 用户 2026-10-23 17:47「verify的cjs污染,当前大量cjs,导致完成后进行大量时间进行无效验证…开发完成后不按照流程走,进行大量时间的未知流程处置这是事实,导致了开发缓慢」

## 现象（事实）

`tauri-shell/verify/` 现有 **220 个 cjs**，平铺无索引、无分级。开发完成后 AI 面临
「哪些必须跑、哪些不相关」不可判定 ⇒ 实际行为是要么漫跑全量（几十分钟）、
要么凭感觉挑（漏回归）。两种都是「未知流程处置」。

## 根因

验证脚本只有「单 BUG 证据」这一种身份，没有**复用身份**（冒烟 / 域回归 / 全量），
也没有「脚本 ↔ 域」的映射表。于是每次交付后都得重新发明验收范围。

## 修法（最小流程，不做大基建）

1. **verify/MANIFEST.md**：一张表 —— 脚本 × 域（files/download/tg/playback/engine/
   process）× 档位（S1 冒烟 / S2 域回归 / S3 全量）。新增脚本必须入表
   （check-bugs 同款门禁思路）。
2. **三级验收写进 `docs/standards/dev.md`**（已有文件追加一节）：
   - S1 冒烟：交付任何改动**必跑**，目标 < 60s —— 只含「服务起得来 + 三端口 +
     files 列表渲染 + 下载列表渲染」一条链；
   - S2 域回归：只跑**被改域**的脚本（按 MANIFEST 查表）；
   - S3 全量：发布前/用户点名才跑。
3. AI 交付汇报只引用 S1/S2 结果，S3 显式标注「未跑」—— 不再出现隐性的
   「漫跑或漏跑」。

## 验收证据

- `verify/MANIFEST.md` 落盘：221 个脚本 × 域（通用/tg/download/playback/files/engine/misc）× 档位；
- `docs/standards/dev.md` 追加「三级验收」节（S1 必跑 / S2 查表 / S3 显式标注未跑）；
- **S1 冒烟脚本 `verify/smoke.cjs` 实跑通过**：三端口 + 文件域 33 行真渲染 + 无页面
  错误 + 统一快照契约，全程 **4.3s**（目标 <60s）；
- 本轮 BUG-399/400 交付即按新流程回执：S1 4.3s + S2 两条（bug399/bug400 探针），
  S3 未跑。
