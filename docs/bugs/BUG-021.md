# BUG-021: CORS 未允许 PATCH/PUT —— 封面与元数据保存静默失败

- 状态: fixed
- 发现日期: 2026-09-17
- 模块: engine
- 严重程度: high

## 现象

浏览器控制台持续报：

```
Access to fetch at 'http://127.0.0.1:9877/api/media/items/160' from origin
'http://127.0.0.1:5180' has been blocked by CORS policy: Method PATCH is not
allowed by Access-Control-Allow-Methods in preflight response.
```

UI 上「看起来正常」——封面能显示（内存态已 `setPoster`），
但**一条都没落库**，刷新即丢失，每次进页面都要重新抽帧。

## 根因

`crates/orig-tg/src/main.rs` 的 `CorsLayer` 只放行了
`GET / POST / DELETE / OPTIONS`，而本功能新增的资料库写接口用的是
`PATCH`（改标题/封面/时长/剧集元数据/单集标题）与 `PUT`（全量重设标签集合）。
跨源预检直接拒绝，请求根本没到 handler。GET 属简单请求不需预检，
所以读路径一直正常，掩盖了问题。

## 复现

```bash
# 修复前：access-control-allow-methods 无 PATCH
curl.exe -i -X OPTIONS http://127.0.0.1:9877/api/media/items/1 \
  -H "Origin: http://127.0.0.1:5180" \
  -H "Access-Control-Request-Method: PATCH" | grep -i access-control-allow-methods
```

## 修复

`allow_methods` 补 `PUT` 与 `PATCH`（保留原有白名单 origin 与 header 设置，不放宽为 `*`）。

验收：
- 预检返回 `access-control-allow-methods: GET,POST,PUT,PATCH,DELETE,OPTIONS`
- `probe_write.py` 全量写路径 22 项通过
- 落库校验：抽帧后 `with persisted poster` 由 0 → 30 条

## 关联

- BUG-018（资料库层）、BUG-022（同批写路径缺陷）
- 教训：**读路径正常不能证明写路径正常**，跨源写方法必须单独做预检验证
