# BUG-483: 挂载把历史 failed 缓存任务重放成全局 toast——每次进 TG 插件都弹「下载过慢」旧失败

- 状态: fixed
- 发现日期: 2026-10-28
- 模块: shell
- 严重程度: medium

## 现象

用户原话：「[2026-10-27T22:11:02.926Z] 下载过慢：该条目耗时超过单条上限（默认 30 分钟），
已中止它以让队列继续。…… 这提示有什么意义吗? 每次进入TG插件都有莫名其妙的提示,让我以为
功能坏了.」

（toast 文本 = `tg.reasonTooSlow`；`[ISO] 文本` 形态即全局 toast 的复制格式
`MainLayout.tsx` `copyToClipboard(`[${new Date().toISOString()}] ${toast}`)` ——
时间戳是**点复制那一刻**生成的，不代表失败发生时刻。）

## 根因

两层叠加：

1. **持久化失败永不消失**：`GET /api/tg/cache/tasks` 的 `task` 语义是
   「running → 最老 queued → **最近一条已结束**」（`api/tg.ts` getCacheTask 注释）。
   库里存着 10 条历史 `failed` 任务（`cache_task` 表实测：124/136 的 error 含
   `download too slow … wall-clock limit`、216 的 `media not found` 等，最早一条
   挂于约 20 天前）——它们永远留在「最近一条已结束」候选里。
2. **挂载把状态重放成事件**：`TgPanel.tsx`「任务失败必须显式告知」effect 只判
   `status === 'failed'` 且本次挂载内未报过（`reportedFailuresRef` 是 `useRef`，
   **每次挂载都是新 Set**）→ `setError(describeTgFailure(...))`，而 store 的
   `setError` 是 `set({ error: e, toast: e })`——**同时升全局 toast**。于是每次进
   TG 插件（TgPanel 重挂载），历史失败被当新鲜事件再弹一次。

旁证：dev 栈实测当时 `task` 为 running(id 222)、环形日志 `/api/tg/logs` 无任何
too-slow 条目——toast 不来自引擎实时活动，纯属前端状态重放。

## 修复

失败告知 effect 增加**事件新鲜度判据**（`TgPanel.tsx`）：

- 新增 `panelMountedAtRef`（挂载时刻，**秒**——`cache_task.updated_at` 是秒级 epoch，
  首版误用 `Date.now()` 毫秒会让判据恒真、连新鲜失败也永不提示，已修正）；
- `cacheTask.updatedAt <= panelMountedAtRef.current`（失败发生在本面板实例挂载之前）
  ⇒ 属于状态恢复，不弹横幅/toast、不记入已报集合；
- 失败发生在挂载之后（updatedAt 晚于挂载时刻）⇒ 照常 `setError` 提示。

历史失败仍由任务行/缓存管理面板持久可见——信息不丢，只是不再重放。

改动文件：`tauri-shell/src/components/TgPanel.tsx`。

## 关联

- BUG-111（任务失败显式告知的来源）：本修复**保留**其目标（新鲜失败必须告知），
  只砍掉「历史失败在每次挂载时重放」的副作用。
- BUG-271（too-slow 判据与文案）、BUG-384（toast 可复制格式）：文案与格式本身正确，
  问题只在呈现时机。
