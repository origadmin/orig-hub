# BUG-334: 文件管理内容混乱——内部库条目流出到成品列表、非受管/无字节条目被显示

- 状态: fixed
- 发现日期: 2026-10-20
- 模块: shell
- 严重程度: mid

## 现象（用户原话，2026-10-20 第 1 点）

> 「文件管理管理内容混乱，内部库流出，非管理文件被显示。」

文件管理（文件域父行）列表里混入内部库条目（住在 `<下载路径>/library` 的媒体条目）与非受管/无字节条目，用户分不清哪些是自己的成品文件。

## 根因（实测定位）

cat-all 行集 = orig-tg `media_item`（已登记媒体）∪ daemon `GET /api/files`（受管成品），
按绝对路径去重合并（BUG-299 M2-T00a 的权宜实现）。对真实库实测（`store.db` 382 条带
`file_path` 的媒体条目 + `/api/files` 38 个成品）：

| 分类 | 条数 | 该不该出现在文件管理 |
|---|---|---|
| 路径落在引擎自用子目录（`.orighub/library`、`.blobs`、`library`） | **119** | 否 —— 内部库，用户原话「内部库流出」 |
| 路径在受管根**外**（`D:/test_videos/*` 等本地导入） | **226** | 否 —— 非管理文件，用户原话「非管理文件被显示」 |
| 受管根内普通路径 | 37 | 其中 **26 个已被 `/api/files` 枚举**，11 个磁盘上已不存在 |

关键结论：并集里**媒体那一半净增 0 行**（受管根内真实存在的 26 个全部已被 facts 覆盖），
带来的全是噪声与幽灵行。去重只按路径，识别不了「这条其实住在内部库」「这条没有字节」
—— daemon 侧 `ENGINE_OWNED_SUBDIRS` 只排除受管根根层，管不到 `media_item` 那一半。

## 修复

cat-all 行集**只由受管成品枚举决定**（`MediaLibraryPanel` 的 `catAllRows`）：

- 媒体条目不再单独成行 —— 内部库内容回它该在的地方（媒体库 / 剧集）；
- 受管根外的本地导入文件不占文件管理；
- 「只登记、盘上没字节」的条目（214 条 `file_path IS NULL`）本来就被
  `hasBytes` 挡在服务端，行级再加一道 `data-source="download"` 锚校验；
- 搜索框改为就地过滤成品名（否则文件管理里搜索会变成「什么都不发生」）；
- 底栏读数改为「受管成品 N 个 · 不含内部库与受管根外的文件」
  （`media.fileList.managedScope`），不再拿服务端 `total`（媒体条目数）冒充
  文件数 —— 那个数对「文件管理里有多少文件」是假的。
