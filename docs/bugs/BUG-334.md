# BUG-334: 文件管理内容混乱——内部库条目流出到成品列表、非受管/无字节条目被显示

- 状态: open
- 发现日期: 2026-10-20
- 模块: shell
- 严重程度: mid

## 现象（用户原话，2026-10-20 第 1 点）

> 「文件管理管理内容混乱，内部库流出，非管理文件被显示。」

文件管理（文件域父行）列表里混入内部库条目（住在 `<下载路径>/library` 的媒体条目）与非受管/无字节条目，用户分不清哪些是自己的成品文件。

## 根因（初步定位，修复时按验收深化）

文件域父行数据源 = orig-tg `media_item`（已登记媒体）∪ daemon `GET /api/files`（受管成品），两源在 `MediaLibraryPanel` 按绝对路径去重合并——设计自述在 `tauri-shell/src/api/files.ts` 头注释（「文件域父行（cat-all）= 已登记媒体 ∪ 本端点枚举的受管成品」）。

- `media_item.file_path` 可能指向内部 `library/`（内部库条目）或为 NULL（BUG-049 图片不落盘、BUG-188 纯图组只编目不落字节）；
- 去重只按路径，**不能识别「这条其实住在内部库」或「这条没有字节」** ⇒ 内部库内容与无字节条目混进成品视图；
- daemon 枚举侧已排除受管根**根层**的 `library`/`.orighub`（`download-engine/crates/orig-daemon/src/files.rs` `ENGINE_OWNED_SUBDIRS`），但排除管不到 `media_item` 那一半。

## 复现

打开文件管理父行，对照 `GET /api/files` 的 `roots`/`files` 与 `media_item` 中 `file_path` 以 `library` 开头或为 NULL 的条目，数列表里有多少行不在受管成品集合内。

## 修复方向

与 BUG-299（文件域数据范围，已升 critical）一并裁定：成品视图按「受管成品」过滤——内部库条目与无字节条目分层或分列展示，不得只靠在合并处加一条 if。

判据（建议）：

- 文件管理父行每行都能在受管成品集合或明确标注的库条目分层里找到出处；
- `file_path` 指向内部 `library/` 或为 NULL 的条目不混入成品列表；
- 反向证伪：构造一条内部库条目 ⇒ 必须不出现在成品列表（或被明确分层标注）。

## 关联

- BUG-299（文件域架构锁，违反标记在 `tauri-shell/src/domains/files/FilesPanel.tsx` 头注释）
- BUG-323（`library`/`.orighub` 根层排除出处）
- BUG-049 / BUG-188（无字节条目来源）
