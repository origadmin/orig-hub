# BUG-059: 设置页「清除缓存文件」直达全量清理，无范围选择

- 状态: fixed
- 发现日期: 2026-09-19
- 模块: engine+shell
- 严重程度: mid

## 现象

设置 → 常规 → Telegram 插件里的「清除缓存文件」是一次**全量**动作：点确认即清掉下载目录内
全部缓存字节。用户无法表达「只清这个频道的」「只清失败任务的残留」「只清超过 N 天的」
「只清没有入库归属的孤儿文件」——清理粒度只有「全清」一档，所以要么不动，要么全动。

缓存管理面板里能勾选删除的只是**任务记录**（`DELETE /api/cache/tasks?ids=`），
**磁盘字节**不在其中：`POST /api/cache/clear` 是无参全清。

## 根因

清理能力被建成「端点 = 动作」：`/api/cache/clear` 语义固定为全清，
`/api/cache/items/:id` 只能单条。缺少「按条件选定一个集合再清」这一层，
于是前端除了全清与逐条之外没有第三种表达，设置页只能把最危险的那档直接暴露在一个按钮上。

同一处还有一处不对称：任务记录侧已经完成「动词唯一、差异走参数」的重构
（`?scope=` 整档与 `?ids=` 集合互斥），字节侧没有跟进。

## 复现

1. 打开设置 → 常规 → Telegram 插件，读「清除缓存文件」旁的占用读数（如 `1.2 GB`）；
2. 点确认：占用直接归零，所有频道的缓存一并消失，无法只清其中一部分。

## 修复

「清除缓存文件」从**动作**改为**入口**：打开清理中心并落在「缓存字节」页签，先给影响面
（条目数 / 字节 / 孤儿 / 陈旧 / 失败残留 / 外部文件不参与），再由用户按档或多选后执行。

**引擎侧（`crates/orig-tg/src/cache.rs`）**——沿用任务记录侧已确立的契约：

- `POST /api/cache/clear` 一个动词三档互斥：`?ids=1,2`（集合）/ `?scope=all|orphan|stale|failed`
  （整档，陈旧档可带 `&olderThanDays=N`）/ 无参 = `all`；
- 非法输入一律 **422、绝不静默跳过**：空 `ids`、非整数 id、`0`/负数、未知 scope、`olderThanDays=0`；
- 越界（不存在）id → 200 且 `removed=0`，不误伤；
- `GET /api/cache/clear/preview` **只读**，返回值与 `stats` 及磁盘实占三方一致；
- 不变量未变：**外部文件永不删**（计入 `skipped`）、**条目永不删**（清字节后回到「仅入库」态）、
  `.part`（下载中）不算孤儿。

**界面侧**——`CacheManagerDialog` 升级为清理中心（「任务记录」/「缓存字节」两个页签），
设置页入口不再 `window.confirm` 就地全清：

- 分档按钮（全部 / 孤儿 / 陈旧 / 失败残留）**按可清理量禁用**，点任一档先出确认条
  （报出将清理几个文件、释放多少），不确认不动手；
- 条目勾选 + 「清理所选（N）」，与整档共用同一个确认条；
- **按频道选定**：频道归属已在预览明细里（每条带 `chatId`），整频道 = 一次勾选，
  仍走 `?ids=` 通道 —— 不新增清理档、不扩大危险半径（用户原话「只清这个频道的」）；
- 入口在**读回判据之前不禁用**：那时读数是「正在读取占用…」，与灰按钮同屏等于谎报
  「没什么可清」（新增 `cacheUsageLoaded` 区分「未就绪」与「无可清」）。

**两处口径纠偏**（都是「说的比做的多/少」）：

1. 「清空全部缓存字节」→**「清理全部缓存条目」**。全部档清的是**条目背书**的字节，
   孤儿只认独立档；旧文案会让人清完之后看见 1.1 GB 孤儿仍在而以为没清干净。
   契约测试 `4b-2` 把这条语义钉死（孤儿经 `scope=all` 必须仍在磁盘）。
2. 入口读数补「（另有孤儿文件 X）」：`stats.bytes` 只算条目背书的字节，漏报孤儿就是
   **读数低估** —— 界面写 850 MB 而磁盘另有 1.1 GB 可清理字节，会让人错过清理。

**一处链路修复**：清理中心有**两个宿主**（TG 面板有频道列表、设置页没有）。频道路径只从
prop 取标题的话，从设置页进来永远拿不到，chip 会静默退化成 `#-1002533442302`。现对话框在
未拿到宿主列表时自行补齐，并且是**有界翻页**（`/api/tg/dialogs` 单页上限 200，本机有 514 个
会话；实测 `limit=1000` 仍只回 200 + `hasMore=true`）+ 缓存空且 `scanning=true` 时**有界重试一次**。

## 验收证据

- 引擎契约（入库，可跨机器复跑）：`download-engine/verify/verify_cache_scopes.py`
  —— **46/46 PASS**，对**隔离实例**（mock 构建 + 端口 9878 + 每轮唯一库名）运行，
  由 `verify_shots/run_cache_clear_verify.sh` 一键拉起：
  - 预览结构完整 + `total+orphan` 与磁盘实占**三方逐字一致**；预览**零副作用**；
  - 端点半径 7 项全 422/无害（空 ids、`abc`、`0`、`-1`、未知 scope、`olderThanDays=0`、越界 id）；
  - 孤儿档：`.part` 不算孤儿、清完幂等、不动条目；
  - 外部文件 `scope=all` 后仍在磁盘且计入 `skipped`；
  - **`4b-2`：`scope=all` 后孤儿仍在磁盘**（↔ `4e` 由孤儿档清掉；两条成对，
    文件由测试自己建出并复验存在，故不可能空跑）；
  - 集合档集合差集、陈旧档阈值精确、`bytesFreed` 与磁盘实际释放量**逐字相等且非零**。
- 界面验收（入库，可跨机器复跑）：`tauri-shell/verify/shot_clear_center.cjs`
  —— **33/33 PASS**（真实实例 9877 + vite dev 5180，Playwright 运行期几何 + 真实接口读数）。
  真实库只走**取消**路径（清理不可逆），确定路径由上面的隔离实例覆盖：
  - 入口可见（`opacity=1` + 尺寸 + 中心命中自身）、禁用态与「可清理量为 0」一致；
  - **判据未读回时不禁用**（用延迟 3s 的预览请求造态，读数停在「正在读取占用…」）；
  - 点入口 → 打开清理中心且**落在「缓存字节」页签**（不再就地清理）；
  - 预览条目数 = `/api/cache/stats.files`；陈旧档报出阈值天数；外部文件为 0 时不出现；
  - 四档按钮齐备且按可清理量禁用；
  - 按频道：chip 数 = 在库条目涉及频道数、**显示频道标题**（非 `#-100…`）、
    点一下选中数 = 该频道条数、确认条报数 = 该频道条数、取消不丢选区；
  - 点「全部」→ 确认条报数 = 预览条目数 → **取消** → 占用读数与全部条目 `filePath`
    快照**逐字未变**（验牙）；
  - 「任务记录」页签回归（全选 + 筛选档仍在）；
  - 端点半径 4 项（空 ids / 非法 ids / 越界 id / 未知 scope）；
  - 全程占用与条目 `filePath` **逐字未变**（零副作用）。
- 产物（证据图 + `result.json`）：`verify_shots/round9-clear/`、
  `verify_shots/tg_cache_scopes/`（按 AGENTS.md §6 均不入库）。

## 进度（2026-09-19）

用户第 2 问（「里面的所有内容能否在外部哪个选项中单独删除，如果可以就没问题」）的核对结论：
**逐项都有入口**（逐项清单见 `docs/design/ROUND9-DESIGN-EVAL.md` §1「覆盖面清点」）。
其中一处缺口已补：「单个条目的字节清理」此前是**死端点** —— `DELETE /api/cache/items/:id`
后端一直存在，但全仓没有任何前端调用方，于是 GB 级缓存只有「整目录清」与「逐条删记录（不动字节）」
两条路。入口已加在条目编辑框内（清缓存 = 只删字节、记录保留；与「删除条目」语义分明），
验收 `tauri-shell/verify/shot_item_cache.cjs` **13/13**，全程**零副作用**
（取消路径断言 `filePath` 与缓存占用逐字未变；确定路径由 404/422 端点半径锁定）。

本 BUG 主体（分档清理 + 清理中心 + 按频道选定）已实施，证据见上。
