# BUG-475: 用户显式删剧后，monitor 重启按 source_key 自动重建，剧集「删了又回来」

- 状态: fixed
- 发现日期: 2026-10-28
- 模块: engine
- 严重程度: high

## 现象

媒体库删除一部 TG 自动成剧的「剧集」后，重启应用该剧集又重新出现，反复多次，像病毒。
用户原话：「错误数据完全无法删除. 剧集删除,重启又出现.已经好几次了,像病毒一样.」

## 根因

`Store::delete_series_explicit`（`download-engine/crates/orig-tg/src/media.rs`）负责用户显式删剧：它删掉剧集行、清掉分集墓碑（`media_episode_removed`），但**没有登记「剧集级删除封禁」**。

TG 自动成剧带幂等 `source_key`，monitor 重启后立即 tick，重跑缓存任务 /
`reconcile_unfiled_items`，经由两条自动建剧入口按 `source_key` 调 `create_series` 把剧集重建回来：
- `IngestCtx::ensure_series`（`download-engine/crates/orig-tg/src/routes.rs`，`Ok(None)` 分支）；
- `Store::file_items_into_series`（`download-engine/crates/orig-tg/src/media.rs`，`None` 分支）。

分集级早已用 `media_episode_removed` 墓碑实现「用户摘除 > 系统自动重建」（BUG-126）；
**剧集级此前缺失对应封禁**，是「删了又回来」的根因缺口。

## 复现

1. 媒体库删除一部 TG 自动成剧（带 `source_key` 的剧集）。
2. 重启应用（monitor 立即 tick，重跑缓存任务 / reconcile）。
3. 该剧集重新出现在媒体库。

最小确定性复现由回归测试覆盖：见本文「验收证据」一节。

## 修复

新增剧集级墓碑表 `media_series_removed(source_key PRIMARY KEY, removed_at INTEGER)`
（迁移落 `download-engine/crates/orig-tg/src/media.rs` 的 `migrate`）：

1. `Store::delete_series_explicit` 在删剧时，若读到 `source_key`，写一行封禁（`mark_series_removed`）。
2. 两个自动建剧入口（`ensure_series` 的 `Ok(None)` 分支、`file_items_into_series` 的 `None` 分支）
   在建剧前先查 `is_series_removed`，命中即放弃重建，底层 `media_item` 保持未归档态。
3. 手工剧集（`source_key = NULL`）无重建路径，不受影响。

改动文件：
- `download-engine/crates/orig-tg/src/media.rs`（`media_series_removed` 建表 +
  `mark_series_removed` / `is_series_removed` + `delete_series_explicit` 写封禁 + `file_items_into_series` 守卫）；
- `download-engine/crates/orig-tg/src/routes.rs`（`ensure_series` 守卫）。

## 关联

- BUG-126（fixed）：分集级墓碑（用户摘除 > 系统自动重建）。BUG-475 是同一哲学在剧集级的缺失。
- BUG-474（open）：同机多实例抢端口致 TG 断链；与删除复活无直接因果，但都属 media/tg 数据一致性。
