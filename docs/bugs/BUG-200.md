# BUG-200 集不能没有标题：空标题在后端「不可表达」，清空后保存表现为「保存了但没变」

- **状态**: fixed
- **发现日期**: 2026-09-30
- **模块**: engine+shell
- **严重程度**: medium

产品语义（用户 2026-09-30 裁定）：「集应该是默认可以没有标题的，因为剧集已经有名称了。」

## 现象

在剧集内页「编辑本集」面板里把标题清空后保存：

1. 前端直接拦下并报错 `media.episode.errTitleEmpty`（「标题不能为空 —— 空标题会让这条内容在资料库里变成一张认不出的卡」）；
2. 即便绕过前端拦截发出空串，后端也按「不改」处理 ⇒ 用户看到「保存成功，但标题没变」；
3. 用户据此认为「标题什么的都不能修改」——面板里标题字段只有 placeholder、没有可见标签，可改性不明显。

## 根因

1. **后端不可表达**：`EpisodeEdit.title` 是 `Option<String>`（`media.rs:3878-3881`），注释明写
   「缺省或纯空白 = 不改（**空标题不可表达**）」；`update_episode`（`:3340-3343`）用
   `edit.title.clone().filter(|t| !t.trim().is_empty())` —— 空串 / 纯空白落进 `None` 分支、保留旧值。
   于是「显式清空」与「不改」在数据上无法区分。
2. **前端硬拦**：`EpisodeEditPanel.tsx:63-66` 的 `if (!title.trim())` 直接 `onError` 后 return。
3. 该拦截源自 BUG-069 的旧裁定（「空标题前端即拦」）。

## 修复

把标题改成与 `description` **同一套双层 Option 契约**（缺省 = 不改；`null` / 纯空白 = 显式清空）：

1. `media.rs`：`EpisodeEdit.title` → `Option<Option<String>>` + `#[serde(default, deserialize_with = "nullable")]`；
   `update_episode` 改为
   `match &edit.title { Some(v) => v.clone().map(trim).unwrap_or_default(), None => cur_item_title }`。
   `media_item.title` 是 `TEXT NOT NULL`（`media.rs:228`），故「清空」落为**空串**而非 NULL。
2. `tauri-shell/src/api/media.ts`：`patchEpisode` 的 `title` 类型放宽为 `string | null`。
3. `EpisodeEditPanel.tsx`：删除空标题硬拦；提交 `title: title.trim() || null`（留空即显式清空）；
   给标题输入框补**可见标签**（此前只有 placeholder）。
4. 旧裁定变更：`media.rs` 单测 `episode_edit_empty_values_match_item_semantics` 原断言
   「空白标题不得抹掉旧值」，按新裁定改写为分别钉死「缺省 = 保持 / 纯空白 = 清空 / `null` = 清空」三种情形。

**诚实边界**：标题是**写穿到条目**的（分集行不持有副本），所以清空单集标题会让该条目在媒体库里
也成为无标题卡片。这是用户「剧集已经有名称了」裁定的直接后果，已知悉并接受。

## 关联

- BUG-069：旧裁定「空标题前端即拦」——本档按用户 2026-09-30 裁定变更（历史锚定，未改写 BUG-069 正文）。
- `shouldRenderEpisodeTitle`（`episodePresentation.ts:30-33`）：标题为空或与剧集同名时回落到 `S1E3`
  槽位标签，故无标题的单集在剧集内页显示正常。
