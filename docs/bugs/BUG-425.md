# BUG-425: `invalidateCache(prefix)` 不清在途请求——写前数据在失效后落回缓存，「改完又看到旧值」

- 状态: open
- 发现日期: 2026-10-24
- 模块: shell
- 严重程度: mid
- 影响面: 窗口窄——写操作须落在一次未完成的列表读请求的飞行途中；但窗口内症状正是 BUG-138 的原始病症，且封面回写（`onPosterReady`）这条路天天走

## 现象

BUG-138 给条目列表加了读缓存（`fetchCache.cached`），写操作后按前缀失效
（`invalidateCache(cacheKey.mediaListPrefix())`）。但失效只清**已解析**缓存：

`src/lib/fetchCache.ts:52-59`

```ts
export function invalidateCache(prefix?: string) {
  if (!prefix) { inflight.clear(); resolved.clear(); return }
  for (const k of [...resolved.keys()]) if (k.startsWith(prefix)) resolved.delete(k)
}
```

**在途表 `inflight` 一个都没动**。而在途 promise 的 `.then` 是无条件写回：

```ts
const p = loader().then((v) => { resolved.set(key, v); return v }) …
```

于是竞态成立：一次列表读请求在飞行途中（慢网 / orig-tg 偶发 ~14s stall 实测存在），
写操作落地并失效缓存；随后在途请求带着**写前数据**返回，`.then` 把它 `resolved.set`
进缓存 —— 失效被覆盖。更糟的顺序：失效 → 新读请求 p2 已装入新数据 → p1 才解析，
**旧数据覆盖新数据**。此后任何读都拿到写前那份，直到下一次失效。

实测证据（`verify/_probe_inflight_race.cjs`，打应用自己那份 fetchCache 模块，2026-10-24）：

```
loaderRuns: 1
inflightReuseSamePromise: true          （在途合并本身没问题）
staleSurvivesInvalidation: true         （失效后旧数据仍落进缓存 —— 竞态坐实）
secondReadLoaderRuns: 1                （失效后的再读不重发 loader，直接喂旧值）
```

同一形态在 BUG-138 验收脚本（`verify_bug138_media_list_cache.cjs`）的 C 段实测复现：
前缀失效后重进 items 视图 **0 次新请求**（在途旧 promise 被 `cached()` 合并复用）。

## 根因

`cached()` 的写回条件缺失：loader 在途时该键可能已被作废（写操作落地），
此时 loader 读到的就是写前数据，不该进缓存。`invalidateCache(prefix)` 也没有
把在途请求一并除名，导致后续 `cached()` 继续合并那条本该作废的在途请求。

注意 `invalidateCache()` 全清形态**没有**这个问题（`inflight.clear()` 先执行）——
所以走 `refreshAll` 的编辑/删除/导入路径不受影响，受影响的只有按前缀精细失效的旁路：
`refreshTags`（改标签）、`onPosterReady`（封面回写）、重缓存、移出分集。
其中 `onPosterReady` 的注释本身就写着「失效后那次请求回来的数据自带 poster，
不再重复生成」—— 竞态窗口内失效被在途旧数据覆盖，卡片就会按 `poster: null`
重新抽帧并再次 PATCH，每次进出重做一遍（该注释想避免的循环）。

## 修复

`cached()` 的写回改为**条件写回**：仅当这个 promise 仍是该键当前登记在途的那一条，
才写 `resolved`；`invalidateCache(prefix)` 同步把在途条目除名（promise 不取消——
发起它的消费者照旧拿到自己那份数据，但后续读必须重新发起）。

```ts
const p = loader()
  .then((v) => {
    // 失效竞赛：loader 在途时该键若已被作废，这次读到的是写前数据，
    // 不能写回缓存（否则「刚改完又看到旧值」，BUG-425）。
    if (inflight.get(key) === p) resolved.set(key, v)
    return v
  })
  …
```

判据（`verify_bug138_media_list_cache.cjs` 新增 B3，全部打真实模块）：
- B3-a：在途 stall 中按前缀失效 → loader 解析后 `peek(key)` 必须 `undefined`；
- B3-b：失效后的再读必须重新跑 loader（在途旧 promise 不得被合并复用）；
- B3-c：全清形态（`invalidateCache()`）行为不变（既有 B2/D3 已覆盖，防回归）。
