# BUG-320: 入库行「展开/收缩」入口不可见——只有一个装饰性 ▸ 字符，用户找不到明细入口

- 状态: fixed
- 发现日期: 2026-10-15
- 模块: shell
- 严重程度: high

## 现象（用户原话，2026-10-15 23:2x）

> 「展开/收缩根本看不到,样式有问题. 展开内容下载,停止,控制是否对策?」

下载页 TG 入库组行（`IngestGroupRow.tsx`）的展开入口是折叠头右上角一个**纯装饰字符**：

```tsx
<span className="text-xs text-muted" data-testid="ingest-group-caret">
  {open ? '▾' : '▸'}
</span>
```

逐项对照「根本看不到」：

1. **不是控件**：`<span>` 不是 `<button>` —— 无 `:focus` 环、无键盘可达、无
   `aria-expanded`、屏幕阅读器读不到状态，只有「点折叠头任意处」这一种隐式交互；
2. **视觉权重最低**：`text-[12px] text-muted`，与右侧一排 `Button` 挤在同一行，
   被动作按钮与状态徽标淹没；`▸`/`▾` 是 Unicode 几何字符，字形随字体退化，
   在高分屏上常被渲染成一个模糊小三角；
3. **无文案**：不写「明细/收起」，用户只能靠一个三角符号猜这里有可展开内容 ——
   同一份能力在 `CacheManagerDialog` 里是「Chevron 图标 + 已编入 N/M 文案」的
   真按钮（`cache-task-manifest-toggle`），两处样式与可发现性完全不一致。

用户同句追问的「展开内容下载、停止、控制」= **BUG-315（条目明细无控制）复报**：
明细行当时零按钮，本轮随入口修复一并补「单条下载」。

## 根因

- BUG-296 交付组清单时，展开入口按「装饰性指示器」实现，从未按**可发现控件**评审；
  BUG-300 复报③ 的补齐（按钮常驻、优先徽标、去媒体库查看）全部落在**组行层**，
  展开入口原样未动 —— 于是「组行修了、入口还是看不见」。
- 展开区是**懒加载**（首次展开才拉 `/items`），入口不可见 ⇒ 用户根本走不到
   BUG-296 投入的那一层信息，缺陷被完整掩蔽。

## 复现

1. dev :5180 → 下载 → 任一条 TG 入库组行；
2. 在折叠头上找「展开」入口：只有右上角一个 muted 小三角，与动作按钮同排；
3. 不点就没有任何文案/边框提示这里可展开 ⇒ 实测用户未发现（本次反馈）。

## 修复

1. **入口改成真控件**（本轮）：`<button type="button">` + `ChevronDown/ChevronRight`
   图标 + 文案（收起态「明细 N」/ 展开态「收起」），与 `CacheManagerDialog` 同款；
   带 `aria-expanded` / `aria-controls` / `title` / hover 与 focus 反馈，
   `data-testid="ingest-group-toggle"`。折叠头整块仍可点（不收回旧交互），
   但**入口自身必须独立可见、可聚焦**。
2. **条目级控制**（BUG-315 子项，本轮补齐「下载」）：明细行缺字节的条目给
   「下载」按钮 ⇒ `POST /api/tg/cache/tasks {chatId, messageIds:[id]}`（后端
   BUG-308 幂等：已入库拦下、活跃任务复用、缺字节复位重跑，不会重复下载字节）；
   组行在传时禁用并直出原因（避免与整批任务双跑同一条消息）。
3. **条目级「停止」明确不提供**：传输的最小单位是**任务**不是消息
   （TG 无真续传、队列不可抢占，见 BUG-300），条目级停止无法表达 ——
   与其做一个「点了实际取消整批」的假按钮，不如在展开区直说「停止请用整行的取消」。

## 复报与修复（2026-10-20，用户第三次明确「明细按钮删除」）

> 用户原话：「BUG:下砸的明细按钮删除没有修复,原因是什么? 明确过3次了」
> （「下砸」=「下载」的输入笔误。）

**为什么三次才做到**——前两次都把诉求读成了「改样式」而不是「删掉」：

| 时间 | 用户诉求（原话） | 实际做了 | 缺口 |
|---|---|---|---|
| 2026-10-16 | 「明细 N 按钮位置和样式都有问题」→ 问「位置和样式怎么调」 | 改成底部弹出 Sheet，**按钮保留**（`ingest-group-toggle`） | 只动了形态，没动存在性 |
| 2026-10-19 | 「下载明细**不要按钮**，只要选择（只有选中的才下载）」 | 删掉了 Sheet 内**条目级逐条「下载」按钮**，改为复选框 | 删错了对象：用户要删的是**明细入口按钮**，不是条目下载按钮 |
| 2026-10-20 | 「明细按钮删除没有修复，明确过 3 次了」 | 删除 `ingest-group-toggle` 入口按钮 | — |

**根因（判据层）**：验收脚本 `verify_bug320_expand_toggle.cjs` 的 A1–A5 断言的是
「入口**必须是**真 button（aria-expanded / 可聚焦 / 文案「明细 N」）」—— 判据把
「保留按钮」写成了正确形态。于是每一次「用户说不要按钮」都会被这个判据判成
「回归」，而「删掉按钮」会被判成失败。**判据与用户诉求相反，改多少次都不会对。**

**修复**：

- `IngestGroupRow.tsx`：删除 `ingest-group-toggle` 按钮整块（含 ChevronRight 图标与
  「明细 N」文案），`ChevronRight` import 一并移除。Sheet 唯一入口回归**折叠头整块**
  （`ingest-group-header` 的 `onClick={() => setSheetOpen(true)}` + `title`），
  Sheet 内容与条目选择控制不变。
- 判据翻转（关键）：`verify_bug320_expand_toggle.cjs` 的 A 组从「入口必须是 button」
  改为 **A0 入口按钮必须不存在**（`ingest-group-toggle` 0 个 + 全页面带「明细」文案的
  可交互控件 0 个 —— 按**文案**扫而不按 testid 扫，换形态长回来同样红）、
  A1 折叠头是入口、A2 点折叠头弹 Sheet、A3 关 Sheet 后按钮仍为 0。
- `verify_bug300_ingest_aggregation.cjs`：源码锚点同步翻转为「按钮不存在」，
  并新增一条**运行期** DOM 计数断言（源码锚会被注释/条件分支绕开，用户看到的是 DOM）。
