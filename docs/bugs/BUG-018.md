# BUG-018: 媒体库长期空白——只显示「TG 已缓存」媒体且无任何管理能力

- 状态: fixed
- 发现日期: 2026-09-17
- 模块: engine+shell
- 严重程度: high

## 现象

媒体库打开后没有任何内容，右侧 58% 宽度是一个纯提示区（`tg.selectToPlay` 文案），
用户无法新增、整理、检索任何内容。用户反馈「媒体库的显示问题和功能」都不可用。

## 根因

两层问题叠加：

1. **数据源过窄**：`MediaLibraryPanel` 只调 `listTgStored({ downloaded: true })`，
   即「TG 消息流水中本地已缓存的那部分」。实测该条件命中 **0 条**
   （`/api/tg/stored?limit=1000` 有 200 条记录，`downloaded=1` 为 0 条）——
   因为缓存需要用户逐条手动触发下载，而库里从未缓存过。于是媒体库恒为空。
2. **无资料库层**：后端只有 `media_message`（TG 同步流水，随频道自动增删、用户不可编辑），
   没有「用户可管理的目录」这一层，因此剧集/标签/图片管理无处落地。

## 复现

```bash
curl.exe -s "http://127.0.0.1:9877/api/tg/stored?downloaded=1&limit=1000" \
  | python -c "import sys,json;print(len(json.load(sys.stdin)['items']))"   # -> 0
```

## 修复

新建**资料库层**，与 TG 流水职责分离（`download-engine/crates/orig-tg/src/media.rs`）：

- 表：`media_item`（内容，本地路径或 TG 引用）、`media_series`/`media_episode`（剧集·季·集）、
  `media_tag` + `media_item_tag`/`media_series_tag`（标签交叉归类）。
- 路由 `/api/media/*`：内容 CRUD + 排序/类型/标签/剧集/散片过滤、剧集 CRUD + 批量编集、
  标签 CRUD + 全量重设、本地目录递归扫描导入、按 `Range` 切片读文件的 `raw` 端点。
- 前端重写为三维导航（内容 / 剧集 / 标签）+ 海报墙，支持多选、批量编集、批量打标签、
  目录导入、图片（图集）管理；播放仍交给既有全局播放器（`openViewer`）。

验收：`verify_shots/probe_media.py`（15 项，含 Range 206 校验）、
`verify_shots/probe_write.py`（22 项写路径）、`verify_shots/shot_media.cjs`（真实渲染截图）。
测试内容由 `verify_shots/seed_media.py` + `verify_shots/make_test_images.py` 生成
（76 视频 + 18 图片 / 6 剧集 / 7 标签）。
