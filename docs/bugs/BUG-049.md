# BUG-049 图片不需要缓存 —— 最多加入媒体库（缓存/入库语义区分）

- **状态**: fixed
- **严重度**: high（规则级）
- **模块**: orig-tg worker + routes / tauri-shell TgPanel
- **报告**: 2026-09-18，用户裁定「图片无法成为剧集，也不需要缓存。最多添加到媒体库，这点需要区别」。

## 现象

缓存按钮对图片与视频语义相同：点击图片「缓存」会走下载落盘；整组「缓存」会把封面图也下载。
用户裁定图片是浏览点，与视频是两条路径：视频=缓存（落盘）+入库+成剧；图片=不落盘，最多入库为浏览条目，UI 必须区分。

## 根因

worker 对所有消息一视同仁走 `cache_one` 下载；前端图片气泡复用「缓存」按钮。没有任何「图片不缓存」的规则表达。

## 修复

**规则**：图片 = 浏览条目（`media_item` kind=photo，`file_path=NULL`），永不下载落盘；浏览字节由 raw 端点现场代理 TG 缩略图。

- **worker**（`run_cache_task`）：消息类型为 photo（tg_message 行 media_type 优先，缺行才 RPC）→ `import_photo_item`（按 ref 幂等 upsert，不落盘、不 mark_downloaded）；已落盘的历史图片走原 cached_path 分支保留本地文件。
- **`media_item_raw`**：条目无 file_path 且 source=tg、kind=photo → 现场代理 `/api/tg/thumb` 字节（image/jpeg + 1d Cache-Control，不持久化）；媒体库/灯箱零前端改动即可显示。
- **新增 `GET /api/media/items/by-ref?source=&ref=`**：返回 `{id|null}`，前端判定「已入库」。
- **前端 TgPanel**：
  - 图片气泡按钮=「加入媒体库」（POST /api/media/items，source=tg）→ 成功后显「已入库」chip；历史已落盘图片保留「播放」。
  - 相册组按钮按构成区分：含视频=「缓存/继续」（图片由 worker 顺带入库，不落盘）；纯图组=「加入媒体库」，全入库后按钮收起显「已入库」。
  - i18n：`tg.addToLibrary` / `tg.inLibrary`。

## 验收

- `cargo test -p orig-tg --lib` 28/28；tsc 0 错。
- e2e（真实实例）：对图片消息入队缓存任务 → worker 日志「photo added to library (no cache by rule)」、缓存目录无新文件、`media_item` 新增 kind=photo 且 file_path 为空、`/raw` 返回 200 image/jpeg。
- UI 截图 `verify_shots/bug049/`：图片气泡「加入媒体库/已入库」、纯图组按钮语义。
- UI 交互实测：监控频道 feed 真实点击「加入媒体库」→ 气泡翻转「已入库」chip、DB 落行（id 369，photo，file_path NULL）、`/raw` 200 image/jpeg（12021 字节）。
- 媒体库「图片」页：无本地文件的 TG 图片条目（TG 图片 #14209-14213）经 raw 代理正常出图。
