# BUG-382: 频道回溯「取消」找不到、回溯点不可见——用户无法确认上次回溯到哪

- 状态: open
- 发现日期: 2026-10-22
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-26

## 现象

用户 2026-10-22 报：「频道内容回溯功能感觉有点问题，没有取消变成强制，
没有最新和历史无法确认上次回溯点。」

实测（`TgPanel.tsx` 2276-2360 + CDP）：

| 用户述状 | 实测 |
|---|---|
| 「没有取消」 | 取消按钮 `tg-monitor-backfill-cancel` **只在 `backfillRunning` 为真时渲染**；运行态判定依赖轮询刷新，用户发起回溯后按钮不出现/闪退即「变强制」（只能等它自己翻完） |
| 「无法确认上次回溯点」 | 回溯进度条只显示「回溯至 YYYY-MM-DD」（目标），**不显示「已回溯到哪 / 最新消息到哪」**；回溯结束后进度条消失，行上不留任何痕迹，下次进来无法确认历史边界 |

## 修复

1. 取消入口常驻可发现：回溯运行中按钮固定在进度行；未在回溯的行也给出
   「上次回溯至 X」的可读痕迹（`backfillUntil` 落行展示）。
2. 进度条补双边界：「最新消息 ~ 10/22」+「已回溯至 X」（服务端
   `sync_cursor` / backfill 水位可推），让「上次回溯到哪」自解释。

## 验收证据

**2026-10-23 引擎侧 + wire 层已验（探针 5/5）**：探针
`tauri-shell/verify/verify_bug382_backfill_bounds.cjs`（活栈，含受控样本 +
残留=0 清理）——A1 wire 字段 `backfillBeforeId`/`lastMessageId` 数值存在；
A2 真源非零同步游标（受控频道首轮同步后 lastMessageId>0）；A4 夹具清理
监控列表还原为空。期间咬出并另档 **BUG-388**（无 cursor 行频道
list_channels 报 Null value），已修。

**未验（本 BUG 保持 open 的唯一原因）**：回溯**进行中**的双边界行
（`tg-monitor-backfill-bounds`）与回溯结束后的「上次回溯至 X」痕迹行的
活栈截图 —— 需要一次真实回溯在跑。当前监控列表为空（0 频道），不擅自对
用户频道发起回溯；待拍板：是否授权用受控样本频道发起一次短回溯完成该项。
