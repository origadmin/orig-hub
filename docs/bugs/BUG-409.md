# BUG-409: 内容详情标题缺层级——缺「剧集→内容」面包屑层次感

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: shell
- 严重程度: mid

## 现象

进入内容详情页后，标题区域只显示「文件管理」，缺少「剧集 → 内容」的层级表达
（面包屑/层级标题），用户无法感知当前所处的层级位置。

## 根因（实测）

下钻剧集时 `fmode` 从 `lib-series` 换成 `series:<id>`（`nav/index.ts` 的 drill-in
模式）。而 `ContextBar#ViewTitle` 的副标题只认两种：

```ts
if (cat) sub = t(`files.cat.${cat}`)
else if (lib) sub = t('files.lib.series')
```

`libraryGroupOf('series:123')` 与 `fileCategoryOf('series:123')` 都返回 `null`
⇒ **副标题整个消失**，比在剧集墙上还少一级。

实测（`verify/_probe_series_ia.cjs`，改前，视口 1440×900，活栈真实数据）：

```
topbar: {"pageTitle":"文件管理","contextSub":null,"seriesTitle":"免费 AI 明星短剧在线制作 …"}
```

`pageTitle` = 文件管理、`contextSub` = **null** —— 用户看到的就是「只有文件管理」。

第二处缺口：剧名只有 `MediaLibraryPanel` 知道（`detail.title`），`ContextBar` 在外壳
另一棵子树里，`fmode` 只带数字 id。所以光给 `series:` 加个分支只能补出「剧集」一级，
补不出剧名。

## 修复

1. `nav` 不动（`series:<id>` 仍是唯一 drill-in 真源）。
2. 新增 store 切片 `filesCrumb` / `setFilesCrumb`（与 `filesActions` **同一个**
   跨子树通道形态：面板写、标题行读；不新开第三条路）。纪律写在类型注释里：
   **面板卸载 / 退出下钻必须立刻置 null**，否则标题行会挂着上一部剧的名字（假事实）。
3. `MediaLibraryPanel` 用 `detail` 驱动它（`detail ? detail.title : null`），
   卸载时清空。
4. `ViewTitle` 增加 `series:` 分支：`剧集 › <剧名>`；拿不到剧名时至少保留「剧集」一级。

## 验收证据

`tauri-shell/verify/verify_bug409_410_414_ia.cjs`（活栈 + 真实数据，视口 1440×900）
**9/9 PASS**，其中 409 四条：

- `409-A` `context-bar-sub` = `"剧集 › 免费 AI 明星短剧在线制作 …"`（含 › 且含剧名）；
- `409-B` `store.filesCrumb` 与页面 `series-title` 逐字一致；
- `409-C` `page-title` 仍为「文件管理」（一级不变，只补层级）；
- `409-D` 点「← 返回」回到剧集墙后 `sub` 退回「剧集」、`filesCrumb` = `null`
  （尾节没有残留）。

反向证伪用**改前实测**（同一脚本前身 `_probe_series_ia.cjs` 在未修改的栈上跑到
`contextSub=null`）—— 改后同一位置有值，不是「加了分支但值取不到」。
