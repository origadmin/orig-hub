# BUG-205 自动入库把单集误判为合集（caption 集号范围）：单集优先，合集仅手动编辑

- 状态: fixed
- 发现日期: 2026-09-30
- 模块: engine
- 严重程度: high

## 现象

用户在剧集内页反馈：「单集会变成多集合集。实际上任何情况都应该是单集，多集应该手动编辑修改才对。」

实测根因对应：一个 caption 含范围（如 `EP01-02 合集` / `第1-2集` / `10-20集合集`）的条目被自动入库后，
落成了**合集**（占 `episode_no..episode_no_end`），界面显示为 `S1E1-E2` 这类区间标签，
而用户期望它只是「第 1 集」——合集（多集）只能由用户在编辑面板里手动设置。

## 根因

自动入库路径（`download-engine/crates/orig-tg/src/routes.rs`）把 `parse_episode_range(caption)`
解析出的**范围端点**直接喂给 `append_episodes_ranged`，后者据此写 `episode_no_end`：

- `caption_range`（单条自动追加路径，`routes.rs`）：`...and_then(parse_episode_range).map(|(s, e)| (s, e.unwrap_or(s)))`
- 批量自动入库路径（`routes.rs` 旧 `ranged_items` 兼容分支）：同样 `.map(|(s, e)| (s, e.unwrap_or(s)))`

`parse_episode_range("EP01-02 合集")` 返回 `Some((1, Some(2)))`，于是自动路径落成了 `episode_no=1, episode_no_end=2`
的合集。这与用户裁定「任何情况都应该是单集，多集只手动」直接冲突。

## 复现

1. 媒体库 → 自动成剧 / 批量追加一个 caption 为 `EP01-02 集合集`（或 `第1-2集`）的视频。
2. 入库后该集显示为 `S1E1-E2`（合集）。
3. `parse_episode_range("EP01-02 集合集")` 单元测试返回 `Some((1, Some(2)))`，证明解析即范围。

## 修复

改动限于 `download-engine/crates/orig-tg/src/routes.rs` 两处自动入库路径：
将 caption 范围映射改为**只保留起点、丢弃终点**——`.map(|(s, _e)| (s, s))`。

效果：

- 自动入库一律落**单集**（取 caption 起点作集号），`episode_no_end` 恒为 NULL。
- 合集（多集）的唯一入口仍是用户在 `EpisodeEditPanel` 手动填「结束集」→ `PATCH /api/media/episodes/:id`
  下发 `episode_no_end`（BUG-153/204 已落地），显式、可审计。
- `append_episodes_ranged` / `add_episode_ranged` 的**显式**范围入参（手动/合并路径）不受影响，
  既有「合集合并保留区间」等契约（BUG-056）保持。

## 关联

- BUG-039：caption 集号范围解析的原始需求；本次是把它从「自动生效」收窄为「仅手动」。
- BUG-153 / BUG-204：合集终点的手动编辑入口（保留）。
- BUG-056：合并剧集须保留合集区间（显式路径，不受影响）。

## 验收证据

- 入库单元测试：`download-engine/crates/orig-tg/src/media.rs` 中
  `auto_import_never_creates_combined_episode_bug205`（跨机器可复核：
  `cargo test -p orig-tg auto_import_never_creates_combined_episode_bug205`，EXIT 0，1 passed）。
  该测试以 `parse_episode_range("EP01-02 集合集")` 得到 `Some((1, Some(2)))` 为根因证据，
  再套用修复后的 `.map(|(s, _e)| (s, s))` 映射喂入 `append_episodes_ranged`，
  断言结果 `episode_no=1, episode_no_end=None`。
- 回归：完整 `media::tests` 模块 `cargo test -p orig-tg media::tests` 全绿（54 passed，EXIT 0），
  其中 `append_ranged_places_collections_and_skips_conflicts` 证明**显式**范围入参仍落合集，
  即「手动多集」能力未受损。
- 反向证伪：把映射改回 `.map(|(s, e)| (s, e.unwrap_or(s)))` 即重现 `episode_no_end=Some(2)` 的合集，
  与缺陷态一致（已确认该表达式即根因）。
