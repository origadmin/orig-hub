# BUG-035：播放器沿用原生控件、播放时无分集列表；移植参照实现时暴露两处缺陷

- **状态**：fixed
- **日期**：2026-09-18
- **模块**：shell（`components/media/VideoPlayer.tsx`、`components/media/EpisodeList.tsx`、
  `components/MediaViewer.tsx`、`components/MediaLibraryPanel.tsx`、`hooks/*`）

## 现象

用户诉求（原文）：

> 「能不能参考 http://localhost:8080/watch?v=kM2oOBe5W 的播放器实现? 替换我们的播放器?
> 还有播放的时候最好能显示剧集的列表.」

此前 `MediaViewer` 只有 **195 行**，视频直接交给浏览器原生 `controls`。

## 参照物的实地核查（先查证，不靠猜）

`localhost:8080` 经确认为 **OrigStudio（orig-cms-ee 门户）**，构建产物 `lib-react`/`lib-axios`，
播放器源码是 `orig-studio-web/src/components/common/VideoPlayer.tsx`（1445 行）+ `hooks/useHls.ts`（513 行），
依赖 **`hls.js ^1.6.15`**。

两个关键事实决定了移植范围：

| 核查项 | 事实 | 影响 |
|---|---|---|
| 播放源 | `UseHlsOptions` 是**双源**：`src`（mp4/webm 直投）+ `hlsSrc`（.m3u8）；只传 `src` 时 hls.js 不激活 | **可移植**：orig-hub 走直投，剥离 HLS 层即可 |
| 剧集列表 | `Watch.tsx` 中 `episode|playlist|剧集|选集` **零匹配**——侧栏是"相关推荐 + 广告位" | **参照物没有这个功能**，属 orig-hub 新增 |

即：播放器可源码级参照，**剧集列表无先例可抄**，须自行设计。

## 移植范围（剥离 vs 保留）

剥离 —— orig-hub **没有对应数据源**，留着就是死代码：

- HLS（`hlsSrc`）：本地文件直投，无 m3u8 分片与转码产物 → 连带不引入 `hls.js` 依赖
- 清晰度切换（`qualities`）：单文件无多档
- 字幕 / 音轨：TG 与媒体库均无独立字幕文件
- 转码中遮罩（`isProcessing`）：不存在转码流程
- 进度条雪碧图预览（`spriteVttUrl`）：本机无 ffmpeg，无法生成雪碧图与 VTT

保留 —— 真正决定手感的部分：自绘进度条（缓冲段 + 指针拖拽）、
快捷键、控件自动隐藏、缓冲指示、错误遮罩与降级、**自动连播下一集倒计时浮层**。

`react-i18next` → orig-hub 自研 `useTranslation`；`lucide-react` 为图标库
（orig-hub 此前**零图标库**，本轮锁定 lucide：SVG 描边、与参照实现同源、符合团队 P0-1）。

## 快捷键冲突的处理

参照实现用 `←/→` 做快退/快进，而 `MediaViewer` 早已把 `←/→` 用作「上一个/下一个媒体项」。
**保留项目既有习惯**，把快退/快进改到 YouTube 同款的 `J/L`，零冲突：

| 键 | 行为 | 归属 |
|---|---|---|
| `←` `→` | 上一个 / 下一个媒体项 | MediaViewer |
| `Esc` | 返回 | MediaViewer |
| `Space` `K` | 播放暂停 | VideoPlayer |
| `J` `L` | 快退 / 快进 10s | VideoPlayer |
| `↑` `↓` | 音量 ±10% | VideoPlayer |
| `M` `F` `P` | 静音 / 全屏 / 画中画 | VideoPlayer |

## 移植过程中发现并修掉的两处缺陷

### 缺陷 1：视频只缩不放，缩在媒体区一角

`<video>` 原用 `max-h-full max-w-full`。**`max-*` 只能缩小、不能放大**，
所以分辨率低于容器的视频永远填不满。实测 480×270 的视频在 1300×800 的媒体区里只占中间一小块。

修复：`h-full w-full object-contain` —— 任意宽高比（含竖屏 1080×1882）都不变形且铺满。

### 缺陷 2：切到图片集后侧栏消失，再也切不回来

首版把侧栏条件写成 `seriesId && (kind === 'video' || kind === 'audio')`。
但**剧集可能是混合内容**（实测某剧集 = 3 个视频 + 7 张图片），
点到图片那一集时 `kind` 变为 `photo` → 侧栏整块卸载 → 用户无法再切回视频集。

修复：`showEpisodes = Boolean(seriesId)`，**刻意不按媒体类型过滤**。

## 实现

| 文件 | 职责 |
|---|---|
| `components/media/VideoPlayer.tsx` | 自绘控件播放器（进度条/倍速/PiP/全屏/快捷键/自动连播/解码提示） |
| `components/media/EpisodeList.tsx` | 分集侧栏（纯展示，不可达项显式禁用） |
| `hooks/useSeriesDetail.ts` | 分集数据单一来源（侧栏与「即将播放 第 N 集」共用） |
| `hooks/usePlayerSettings.ts` | 偏好持久化（音量/静音/倍速/自动连播） |
| `types.ts` | `ViewerItem` 增加 `seriesId` / `poster` / `episodeNo` |
| `MediaLibraryPanel.tsx` | 播放组构造：**选中项属剧集时扩成整部剧集** |
| `i18n/locales/*.json` | 新增 `player.*` 命名空间（27 条 × 中英） |

**后端与 API 零改动**：分集数据走既有的 `GET /api/media/series/:id`，
`EpisodeView` 字段（`item_id/season/episode_no/title/poster/duration`）本就齐全，
`MediaItem` 也已带 `seriesId`/`seriesTitle`。

### 一个必要的耦合点

`MediaLibraryPanel.playItems` 在选中项带 `seriesId` 时，会先 `getSeries(sid)`
把播放组**扩成整部剧集**再打开播放器。原因：分集侧栏的点击是在「当前播放组」内
按 `itemId` 定位的，播放组若只含一条，所有分集点击都会落空（表现为「点了没反应」）。
拉取失败时退回原列表播放，不阻断。

### 断言纪律（本轮踩到的坑）

首版断言写成 `s2.currentText !== before` —— 元素消失导致的 `null` 也能通过，
是**假阳性**，一度掩盖了「缺陷 2」。现版要求**每一项都必须有值**（`!!value && value !== before`）。

## 防再发

1. **`max-w-full/max-h-full` 不会放大图片或视频**，需要铺满时必须 `h-full w-full object-contain`。
2. **跨媒体类型的上下文侧栏，条件不要带上媒体类型**：混合内容（视频+图片）剧集里，
   按类型过滤会让侧栏在切换瞬间消失，用户失去返回路径。
3. **断言禁止用"不等于旧值"**：必须同时要求新值存在，否则元素消失即假阳性。
4. **移植前先核参照物有没有这个功能**：本次"剧集列表"在参照实现里根本不存在，
   若照抄会白做；反过来其双源设计（`src`/`hlsSrc`）则让直投场景的移植成为可能。
