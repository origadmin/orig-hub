# BUG-117：图片的「大图」实际是 Telegram 缩略图，且内容域越界调用传输域

- 状态: open
- 严重程度: mid
- 模块: engine
- 发现日期: 2026-09-22

## 现象

查看图片时画质受限，**「查看原图」无入口**；取图失败时是 404。

## 根因

`media_item_raw`（`routes.rs:2246` 附近）：当 `file_path` 为 NULL 时，**现场调用**
`st.client.thumb(chat, msg)` 去 Telegram 取一张**缩略图**（不是原图）代理给前端。

两个问题叠在一起：

1. **画质**：拿到的是缩略图，不是原图 —— 本地没有字节时只能给这个，等于「查看原图」
   这条路根本不存在。
2. **越界**：内容域（`media.rs` / 路由层）**直接调用传输域** `client.thumb()`。
   评审文档第 7 节定的铁律是：**内容域不 import grammers 类型；传输域不 import 表结构**。
   内容域只应返回 attachment 定位，由路由层调传输域代理。

## 为什么在离线优先下更严重

用户拍板「入库即落盘」之后，图片的字节应当**已经在本地**（见 BUG-115 / BUG-116）。
「只能看 TG 缩略图」在本地字节本该存在的前提下毫无价值 —— 它是「该落盘却没落盘」这个
错误的**表现**，不是一个可接受的功能。

## 修复方向

1. 图片入库即落盘（BUG-115），落盘后本条自动失去触发条件；
2. 把 thumb 代理**上移到路由层**，内容域只返回定位（模块边界收口）；
3. 保留「字节缺失」时的显式提示 + 重新缓存入口，不要静默给一张缩略图充数。
