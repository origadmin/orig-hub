# BUG-268: 续播（播放进度记忆）—— 全仓无进度存储，属**新能力立项**（非缺陷），用户已点头

- 状态: open
- 发现日期: 2026-10-10
- 模块: engine+shell
- 严重程度: mid

> **档位声明**：本档**不是缺陷档**，是**新能力立项档**。登记在此是因为用户要求「该入BUG入BUG」，
> 且 `BUG-262` 的待拍板项 N1 / N2 需要一个落点。**严重程度仅用于排序参考，不代表已有缺陷。**
>
> 来源：用户第 3 轮「**1. 推荐**」（对第 2 轮追问「如果播放过的从上次开始？弹出重新开始播放？」的答复）。

## 现象（现状：能力完全不存在）

### 现象 1：全仓没有播放进度存储

`localStorage` 的全部写入点（实测 grep，去掉测试文件）：

| 键 | 落点 | 存什么 |
|---|---|---|
| `STORAGE_KEY` | `tauri-shell/src/hooks/usePlayerSettings.ts:31,62` | 播放器**设置**（音量 / 静音 / 倍速） |
| 历史目录键 | `tauri-shell/src/lib/recentDirs.ts:8,22,32` | 最近下载目录（上限 10 条） |
| `ACCOUNTS_KEY` / `SETTINGS_KEY` | `tauri-shell/src/store/useStore.ts:100,123,497,590` | 账户绑定态 + 应用设置 |
| 兼容流标记 | `tauri-shell/src/components/media/VideoPlayer.tsx:770`（注释所述） | 哪条内容需要走兼容流 |

⇒ **没有任何一处记录「看到哪了」**。`VideoPlayer` 全程无 `currentTime` 的持久化写入；
`MediaViewer` 无进度持久化。既有文档已实测记录同一事实：
`docs/design/media-library-management-prd-2026-09-22.md:101`「继续播放（断点续播）| **无** |
`MediaViewer.tsx` 无进度持久化；`localStorage` 仅用于播放器设置/历史目录/账号」。

### 现象 2：全仓的 `resume` **全部是「下载」的暂停恢复**，与播放无关

| 落点 | 内容 |
|---|---|
| `tauri-shell/src/api/daemon.ts:71-74` | `POST /api/downloads/:id?action=pause｜resume｜cancel` |
| `tauri-shell/src/store/useStore.ts:257-261,408-409,453-459` | `resume(id)` / `resumeAll()` |
| `tauri-shell/src/components/DownloadItem.tsx:32,105` | 下载项「恢复」按钮 |
| `tauri-shell/src/components/ContextBarActions.tsx:83-100` | 「全部恢复」 |

⇒ 搜 `resume` 会**全部命中下载侧**，不构成播放续播能力的任何一部分。**不要把下载的 resume 误当续播。**

### 现象 4：与 `BUG-262` 的「起点 = 第一集」**语义互斥**

`BUG-262` 已拍板「左栏新增『▶ 播放全部』，起点 = **第一集**」。
同一按钮在「有进度 / 无进度」时**语义跳变**（无进度 ⇒ 从第 1 集；有进度 ⇒ 从上次），
「播放全部」这个文案在第二种情形下**说谎** ⇒ 必须二选一或**拆成两个入口**。
⇒ 本档与 `BUG-262` 的 N1 是**同一个待拍板项的两面**，必须一起定。

## 根因（新能力缺失，无「缺陷根因」）

- **前置能力缺失**：没有任何进度持久化层（表 / 本地）。这是所有续播形态的共同前置。
- **入口语义未定**：续播与 `BUG-262` 的主按钮抢同一个位置（现象 4）。
- **粒度未定**：记到「集」还是记到「秒」，决定存储结构与 UI 形态。

## 需求形态（用户第 2 轮原话 + 第 3 轮「推荐」）

用户原话：「**如果播放过的从上次开始？弹出重新开始播放？**」

⇒ 用户描述的是一个**三段式**交互：① 播过的 ⇒ 从上次开始；② 但**给一个「重新开始播放」的出口**。
即：**默认续播 + 显式可重头**，而不是「默认重头 + 显式续播」。

## 交付后必须满足（可证伪判据，预先声明）

1. **播放过的内容再次打开 ⇒ 起点 = 上次位置**（按 N2 粒度：秒级则允许 ±3s，集级则必须精确到集）。
2. **未播放过的内容 ⇒ 起点 = 第 1 集 / 0:00**（不得因为别的条目有进度而串位）。
3. **反向证伪**：清空进度存储后，判据 1 必须 FAIL（起点回到第 1 集）—— 证明判据确实咬住了「进度」而非别的机制。
4. **必须存在「从头开始」出口**（用户原话「弹出重新开始播放？」），且走该出口后**进度被重置**。
5. **写入不得引入播放性能回归**：不得用 `timeupdate` 逐帧写盘 / 写 `localStorage`（BUG-216 / BUG-217 教训）；
   反向证伪：若把写入改回 `timeupdate` 无节流，`node verify/_probe_render_churn_steady.cjs` 的
   `mutations/s` 必须显著上升（即判据 5 咬得住）。
6. **不得回退 `BUG-262` 的判据**：`verify_play_primary.cjs` 全 18 项（含 210-A 计数、210-C 宽度）在改动后仍 PASS；
   若按 N1-b 改动使判据 2 需再放宽，**必须当场登记为「判据迁就实现」**。
7. 判据 1 / 2 / 4 必须在**真实 UI** 上验（BUG-156）：播到中间 ⇒ 退出 ⇒ 重进 ⇒ 观察起点；不读内部变量。
