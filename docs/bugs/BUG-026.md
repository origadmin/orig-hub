# BUG-026: 缓存任务轮询导致页面卡顿 —— 每秒全量重渲染 + 高频读打 SQLite

- **状态**: fixed（2026-09-17）
- **影响面**: `tauri-shell/src/components/TgPanel.tsx`、`download-engine/crates/orig-tg/src/{state.rs,main.rs,routes.rs}`
- **报告**: 用户原话——「`/api/tg/cache/tasks` 请求导致页面卡顿。整个设计流程都有问题，流畅应该是第一优先度，状态也不可能 1 秒变几十次，这个设计有问题，设计思想也有问题，从思想、规则方面开始改进，然后修复问题。」

## 现象

缓存任务进行中（BUG-024 引入的 1s 轮询恢复进度）时页面明显卡顿；DevTools 里该请求持续出现。

## 根因（两层，均实证）

1. **前端：每秒一次整面板重渲染。**
   `refreshCacheTasks` 每秒 `setCacheTasks(新数组)` → TgPanel（1485 行组件）重渲染 →
   `MessageBubble` / `AlbumBubble` 是裸函数组件（无 memo）且回调全是内联箭头
   （`onDownload={() => doDownload(unit[0])}`，每次渲染新引用）→ 即使加了 memo 也会
   被回调击穿 → 30+ 个含视频海报/缩略图的气泡每秒全量 reconcile。Vite dev 模式下尤为明显。
   —— 下载一条媒体需要数秒，1s 轮询绝大多数tick里**状态根本没变**，全是无效重渲染。

2. **服务端：高频读打 SQLite。**
   `GET /api/tg/cache/tasks` 每次执行 `ORDER BY (活跃态优先), id DESC LIMIT 50` 的 DB 查询，
   与下载 worker（同一条 libsql 连接上的高频写）互相争用。读路径本应零 DB。

## 设计思想与规则（本轮确立，写入 AGENTS.md §5）

> **流畅是第一优先度**：进度类高频数据只允许影响「正在变化的那一小块 UI」，
> 不允许整面板重渲染；UI 更新频率必须与数据获取频率解耦。

- **轮询三律**：① 有活才轮（无活跃任务零请求）；② **等值短路**（快照签名未变不 setState）；
  ③ 任务终态即停（本套件实测 10s 窗口仅 7 次请求：任务完成后轮询自动停止）。
- **高频读 O(1)**：读走内存快照（worker 是唯一写者，每次 DB 变更后同步刷新快照），
  SQLite 只承担变更写入。
- **高频路径组件必须 memo + 稳定回调**：回调用 useEvent 模式（引用恒定、行为取最新闭包），
  子组件回传自己的数据（`onDownload(item)`），杜绝内联箭头击穿 memo。

## 修复

### 前端（TgPanel.tsx）
1. **签名短路**：`id:status:done:currentId:error` 组成签名，未变则跳过 `setCacheTasks`——
   一条媒体下载期间（数秒）所有轮询 tick 都是无渲染空转。
2. **useEvent 钩子**：稳定事件回调，引用恒定、行为永远取最新闭包（无陈旧闭包）。
3. **`MessageBubble` / `AlbumBubble` memo 化**；`AlbumBubble` 自定义比较器按
   done/total **值**比较 progress（对象每次重建但值多数未变）；
   回调改为数据回传式（`onDownload(item)` / `onPreview(index, items)`）。

### 服务端（state.rs / main.rs / routes.rs）
1. `AppState.cache_tasks: Arc<RwLock<Arc<Vec<CacheTask>>>>` 内存快照；
   `list_cache_tasks` 直接返回快照（clone Arc，零 DB、零深拷贝）。
2. 唯一写者刷新：enqueue / cancel / worker 的 mark_running、每次 progress、finish 之后
   同步 `refresh_cache_tasks()`；启动时（僵尸降级之后）建立首份快照。

## 防再发

- 新增高频轮询/订阅前必须回答：**状态不变的那次 tick 会渲染多少 DOM？** 答案不是「零」就不许上。
- 服务端新增被轮询的读端点前必须回答：**读路径碰 DB 吗？** 碰就要给内存快照。
- memo 化组件的回调禁止内联箭头——用 useEvent。
