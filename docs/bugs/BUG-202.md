# BUG-202 单集编辑入口与标题脱节：唯一入口被埋在右栏底部，用户误判「标题不能改 / 编辑被分开」

- 状态: fixed
- 发现日期: 2026-09-30
- 模块: shell
- 严重程度: mid

## 现象

用户在剧集内页反馈：「集可以整体单个按钮进入编辑修改模式，为什么分开？标题什么的都不能修改」。

实测结论：编辑**能力本身完整可用**——`EpisodeEditPanel` 可一次提交标题 / 介绍 / 季号 / 集号 / 结束集号（标题可空，BUG-200），后端 `update_episode` 写穿到 `media_item`（BUG-069），保存后 `refreshAll` 重拉。问题不在「能不能改」，而在**入口与它所改的标题在视觉上脱节**：

BUG-201 把两个入口合并为**一个** `episode-edit` 按钮，但该按钮被放在右栏**底部**的「编辑本集」块里，而标题显示在右栏**顶部**的标题行。两者相距一屏，用户打开单集后视线落在标题上、找不到改标题的入口，于是「标题不能修改」像真的一样。这正是用户说的「编辑被分开」——不是代码上有两处编辑逻辑，而是同一入口离它要改的内容太远、像被拆到了别处。

## 根因

`SeriesDetail.tsx` 在 BUG-201 收敛入口时，只删了重复按钮、没把唯一入口**上移**到标题行。设计文档 `docs/design/media-library-layout-design-2026-09-28.md:489` 的定档是「两个入口合一」，但合一后位置错了：编辑标题的按钮应当紧贴标题。现状违反该定档的**位置**语义。

## 复现

1. 媒体库 → 打开任意剧集 → 进入剧集内页（右栏单集区）。
2. 右栏顶部标题行只显示标题 + 槽位徽标，**没有编辑入口**。
3. 滚动到右栏底部才看到唯一的 `episode-edit`（「编辑本集」）按钮。
4. 结论：编辑入口与标题分处两端 ⇒ 用户感知「标题不能改 / 编辑被分开」。

## 修复

改动限于 `tauri-shell/src/components/media/SeriesDetail.tsx`：

1. 把唯一的 `episode-edit` 入口按钮 + 紧随其后的内联 `<EpisodeEditPanel>`（携带 `editBlockRef`）**从右栏底部上移到标题行**——紧跟在右栏头 `<h3>` 标题之后、槽位徽标之前。点一下即进入本集统一编辑态，所见即所改。
2. 右栏底部的「编辑本集」块**精简**为只保留结构性操作：上移 / 下移 / 移除（`episode-move-up` / `episode-move-down` / `episode-remove` 不变）。`editBlockRef` 一并迁到标题行面板。

**能力不减**：标题 / 介绍 / 季号 / 集号 / 结束集号仍全部在 `EpisodeEditPanel` 内可改；`episode-edit`、`episode-title-input`、`episode-season-input`、`episode-no-input`、`episode-end-input`、`episode-save` 等被验收脚本断言的 `data-testid` **全部沿用**。

## 关联

- BUG-197：同文件引入 `editingEpisode` 门控（默认 false、toggle 开关）。
- BUG-200（同日）：同一面板里标题可清空——入口上移后，标题（含空标题）仍在同一处改。
- BUG-201（同日）：把「编辑介绍」与「编辑本集」两个入口合并为一个 `episode-edit`；本档修的是合并后**位置放错**（埋在底部、与标题脱节）。
- BUG-069：分集只是位置，文案唯一真源 = 条目；`update_episode` 写穿 `media_item`，故编辑入口放在标题行语义正确。
