# BUG-003: 速度统计失准（完成后仍显示 / 进行中不准）

- 状态: fixed
- 发现日期: 2026-08-26
- 模块: engine+shell
- 严重程度: high

## 现象
- 下载完成 / 出错 / 暂停后，界面速度仍残留显示旧值（不归零）。
- 进行中速度抖动剧烈、长期偏低或偏高，与实际带宽不符。

## 根因
1. **多消费者污染 EMA**：`SpeedTracker` 的 EMA 采样原本写在 `progress()` 里，
   而 `progress()` 被多处调用（进度轮询 ticker、外部查询），每次调用都会
   `sample()` 推进采样指针 → 多消费者重复采样，EMA 被污染、失真。
2. **前端残留速度**：SSE 的 completed / error / paused 事件映射未将 `speed`
   显式置 0，旧速度在状态切换后继续显示。

`file: download-engine/crates/orig-core/src/engine.rs`（`SpeedTracker` / `progress` / `worker` / `progress_ticker`）
`file: tauri-shell/src/store/useStore.ts`（SSE 事件映射）

## 复现
- 进行中：观察速度是否稳定接近实测带宽（而非剧烈抖动）。
- 完成后：原显示速度应立即归 0。

## 修复
- `engine.rs`：
  - 新增只读 `SpeedTracker::current_ema()`（仅读取，不推进采样）。
  - `progress()` 改为只通过 `current_ema()` 取速度，且仅对活跃态
    （Downloading / Queued / Idle）取值，非活跃态返回 0。
  - `worker` Ok 分支新增**唯一** Range 模式采样点：
    `if self.supports_range { self.speed.sample(done); }`（此前缺失）。
  - 非 Range 模式的 `progress_ticker` 复用 Task 自身的 `SpeedTracker`
    （不再新建局部 tracker），并经由 `self_arc.progress()` 统一出口，
    保证每周期只采样一次。
- `useStore.ts`：completed / error / paused 事件映射中显式加入 `speed: 0`。

- `cargo build` → EXIT=0
- `npx tsc --noEmit` / `npm run build` → EXIT=0
