# BUG-236：语言设置仅中英两个语种，i18n 无语种扩展设计

- 状态: fixed
- 发现日期: 2026-10-09
- 模块: shell
- 严重程度: low
- 登记: 用户报告「常规语言不支持其他语种，仅 2 个，这是设计问题」
- 排期: 2026-12-26

## 现象

`src/i18n/locales/` 仅 `zh-CN.json`、`en-US.json` 两个语言包，语言选择只有两项。

## 根因

i18n 框架本身按语种文件加载（可扩展），但从未定义语种扩充流程：新语种 = 手抄一份
全量 JSON + 无回退链 + 无缺失键检测，扩充成本高且易漂移，事实上冻结在 2 个。

## 修法方向

列为设计债按需偿还：若产品定位不需要多语种，在设置项注明「当前仅支持中英」即算闭环；
若要支持，补齐「新增语种清单 + 缺失键回退 zh-CN + CI 键完备性校验」三件套再扩。
默认按前者处理（用户未表达多语种需求，报的是设计问题本身）。

## 验收证据
语种从「中英两分支」改为「locale 文件集合」：新增语种 = 放一个 locale 文件并在
`tauri-shell/src/i18n/index.ts` 的注册表登记，代码里不再出现按语种的分支。

判据：语种来源是文件清单而非硬编码 union；反向证伪：新增 locale 文件不改代码即不可选 = 原症状。
