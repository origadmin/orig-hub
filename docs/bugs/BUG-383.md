# BUG-383: 频道消息流「图/文上下堆叠」占空间，应改左右布局

- 状态: open
- 发现日期: 2026-10-22
- 模块: shell
- 严重程度: mid

## 现象

用户 2026-10-22 报：「频道内容显示排版可以改成左右布局了，图片和文字上下布局
太占地方，现在改了内容展示方式排版也需要变，而且点击展开按钮没有响应(6)，
功能没实现。」

两个子问题：

1. **排版**：`MessageBubble`（`TgPanel.tsx:2867`）当前图在上/文字在下垂直
   堆叠，一条带图消息占整整一屏高，信息密度低。用户裁定改**左右布局**
   （图左文右）。
2. **展开按钮**：相册折叠封面「点击展开」无响应 = **BUG-376**（memo 比较器
   漏 `expanded`），已修（`fdb2409`）。本轮实测复验：点击
   「2点击展开 2 项」后 `album-grid` 0→1，功能已恢复
   （`e7_tg_album_expand.png`）。本 BUG 只承担排版部分。

## 修复

`MessageBubble` 改左右布局：缩略图列（固定宽，如 96/120px）+ 文字列
（标题/caption/元信息/动作），窄视口下降级为上下。相册网格
（`AlbumBubble`）保持网格语义不变。

## 追节（2026-10-23 复报）：修复不完整 —— 三子问题实锤

> 历史锚定（BUG-082 先例：追节不改写正文）。

### 复报原文（2026-10-23）

「订阅浏览当前图片过小，导致文字高度>图片高度。需要调整。」
「订阅浏览部分还是上下，部分左右，修复不完整，样式突兀。」
「点击展开缺少收起，且展开不符合当前所有排布模式样式
（展开后变成上下了，需要重新设计）。」

### 实测（CDP 1440×900，活栈，三个监控频道取样）

| 事实 | 读数 |
|---|---|
| 单条 photo 图列 | PhotoBlock compact `h-20`(80px) + 列宽 w-32(128px)，`object-cover` |
| caption 高 vs 图高 | 107px vs 80px、268px vs 80px、250px vs 80px —— **文字高度>图片高度**实锤 |
| 同屏形态分裂 | 单条=左右（128px 图列）；file/audio=📄 行式横条；相册折叠态=**全宽大图**（`max-h-[40vh]`）+ caption 全宽在下（`TgPanel.tsx:3399`）+ 操作行 ⇒ 上下大块；相册展开态=全宽宫格 569×378 |
| 收起入口 | `album-collapse` 存在（状态行右侧 11px 小字「收起」，`t+8s` 持续在），但不显著 ⇒ 用户「缺少收起」 |
| 展开持久性 | 无自动收回（grids=1 持续 t+8s）—— 不是状态丢失问题 |

### 根因

BUG-383 首修只把 **MessageBubble 单条**改成了左右（`sideLayout`），
`AlbumBubble`（折叠封面全宽大图 + caption 全宽在下；展开全宽宫格）与
**file/audio 行式**没进同一套排布框架 ⇒ 四态并存（单条左右 / 文件行式 /
相册折叠上下大块 / 相册展开全宽宫格），用户观感「部分上下部分左右、样式突兀」。
图列 80px 是首修为省空间取的过小值，没对 caption 常见高度（2-4 行
18-107px）做下界保证。

### 修复设计（用户裁定方向：统一到左右排布模式）

1. 图列加大：w-32(128)→w-40(160)、PhotoBlock/VideoBlock compact
   h-20(80)→h-32(128) —— 覆盖 4 行以内 caption（107px）不出现「小人大人」。
2. 相册折叠态改左右：封面进左列（同单条尺寸 object-cover）+ 右列
   「相册 N 项」+ caption + 状态/操作，点击展开；与单条消息同构。
3. 相册展开态重新设计：保持左右框架 —— 左列封面 + 右列文字，
   宫格铺在**右列下方**（grid-cols-3，不超右列宽）⇒ 不再是全宽大块。
4. file/audio 统一：左列图标块（同图列尺寸）+ 右列文件名/大小/动作。
5. 收起入口显著化：宫格区右上角可见「收起」按钮（不止状态行小字）。
6. video 播放态切全宽是**有意例外**（128px 列播视频不可接受，首修注释
   明锁），瞬态、不纳入本轮统一面。
