# BUG-482: release 壳栈退化出双 daemon + 双 tg，自占双规范端口

- 状态: open
- 发现日期: 2026-10-28
- 模块: shell
- 严重程度: high
- 排期: 2026-11-04

## 现象

2026-10-28 05:50 本机实测，release 壳（orig-hub.exe pid 39552，01:47 启动）拉起的进程树：

- orig-daemon ×2（pid 39616 监听 19786、pid 32152 监听 19787），
  同一 exe：`tauri-shell\src-tauri\target\release\orig-daemon.exe`；
- orig-tg ×2（pid 8500、24064）；
- 19786 的 `/api/config` 报 tg 插件端口 19789（既非 19787 也非预期值）。

即：单壳实例跑出了两个 daemon、两个 tg、tg 端口漂到第三位 —— release 栈自身处于
退化态，且占死了 19786/19787 两个规范端口。

## 根因（待查）

嫌疑方向（未证实，需查壳侧 spawn/监督逻辑）：
- 壳认为首个 daemon 未在超时内应答（`main.rs` 注释提及壳只等 5 秒，daemon「到开始监听」
  可能超 5 秒），于是再 spawn 一个；首个实际已活，第二个 daemon 的 HTTP 落到 19787。
- tg 双实例疑为两个 daemon 各自拉起一个 tg 子进程。

## 复现
