# BUG-204 「编辑所有内容」名实不符：统一编辑面板没有图片管理，图无法增删替

- 状态: fixed
- 发现日期: 2026-09-30
- 模块: shell
- 严重程度: mid

## 现象

用户在剧集内页反馈：「我说了全部，图无法替换增删改」——本集编辑面板定位是
「编辑这一集的**全部**内容」，但图片不在其中：

- **增/替换**：必须退出编辑态，去面板外找独立的「给这一集挂图」按钮；
- **删**：整集图组没有逐张移除的入口（`media.ts` 有 `detachEpisodeImage`
  API 但无任何 UI 调用方——后端有端点 ≠ 用户能用）；
- **改**：图组状态只能在浏览态的跑马灯里看，编辑态里图片像不存在。

## 根因

`EpisodeEditPanel` 只承载标题 / 介绍 / 槽位，图片的增删替散落在 `SeriesDetail`
浏览态区块（`episode-attach-images` 按钮 + 跑马灯）， detach 能力纯后端孤儿端点。
「统一编辑」容器与图片能力没有接线。

## 复现

1. 媒体库 → 打开剧集 → 点「编辑本集」。
2. 面板内无任何图片相关控件；逐张删图在任何状态下都无入口。

## 修复

改动限于 `tauri-shell/src/components/media/`：

1. `EpisodeEditPanel.tsx`：新增「本集图组」区——
   - 缩略图列表（`episode-edit-images`）+ 每张 × 按钮（`episode-image-detach`）
     调 `detachEpisodeImage`（幂等 DELETE），**逐张删图首次有入口**；
   - 「管理本集图片」按钮（`episode-images-manage`）打开挂图选择器
     （replace-all 语义，勾选即新全集）——增 / 替换收进编辑态；
   - 空态提示（`episode-edit-images-empty`）；
   - 增删后经 `onChanged` 只重取详情刷新图组，**不退出编辑态、不丢草稿**
     （面板 key 稳定不重挂，标题/介绍草稿保留）。
2. `SeriesDetail.tsx`：把选择器入口经 `onPickImages` 交给面板
   （`setAttachingEpisodeId(cur.id)`，对话框仍归容器）；浏览态跑马灯保持不变。
3. `EpisodeExpanded.tsx` / `EpisodeBoard.tsx`（当前无活路径渲染）：接口补齐
   `onChanged` / `onPickImages` 透传，保持编译门禁与契约一致。
4. i18n：`zh-CN` / `en-US` 新增 `media.episode.noImagesAttached` /
   `detachImage` / `editImages`。

## 关联

- BUG-168：挂图 replace-all 语义与 `/api/media/episodes/:id/images` 端点（后端已有）。
- BUG-203：同日同面板——编辑态隐藏浏览态静态块，图片管理在面板内承接。
- BUG-191 教训的镜像：后端有端点 ≠ 用户能用；`detachEpisodeImage` 此前正是
  无 UI 调用方的死端点。

## 验收证据

- 入库脚本：`tauri-shell/verify/verify_episode_unified_edit.cjs`（跨机器可复核，
  全过 EXIT 0）。
- 修复后实测（2026-09-30，真实渲染）：`episode-images-manage` 在面板内且点击后
  挂图选择器打开（77 个候选项 + 确认按钮）；无图条目显示空态提示；
  编辑态下面板外独立挂图按钮为 0（能力已收进面板）。
- 前端 TypeScript 编译门禁 `node node_modules/typescript/bin/tsc --noEmit` 退出码 0。
- detach 链路核对：`episode-image-detach` → `detachEpisodeImage(ep.id, itemId)`
  （`DELETE /api/media/episodes/:id/images/:itemId`）→ `onChanged` 重取详情；
  本次实测条目无挂图未触发真实 DELETE（增删写路径以选择器确认挂图后同法复核）。
