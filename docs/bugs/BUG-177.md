# BUG-177: 「已开启却未连接」被当成合法产品状态 —— TG 入口门控只认开关不认服务

- 状态: fixed
- 发现日期: 2026-09-29
- 模块: shell
- 严重程度: high

## 现象

用户报告（2026-09-29）：**「不论是否『调试模式：TG 未连接』，TG 是由 daemon 控制的，开启了不应该有未连接的状态。
这个逻辑本身就不正确。TG 服务可用？否 → 不显示 TG，这是核心设计，这些逻辑当前全是乱的、错的。」**

具体表现：

- TG 开关开着，但 orig-tg 进程根本没在服务（本机 `bind 127.0.0.1:9877` 直接 `os error 10013`），
  侧栏**照样**显示 Telegram 入口；
- 点进去是一个写着「**调试模式：TG 未连接**」的面板 —— 把开发脚手架
  （`ORIG_TG_OFFLINE` 离线短路）渲染成了产品状态；
- 用户据此怀疑「数据是不是丢了 / 是不是根本没取到正确数据」（直接诱发 BUG-176 的误判）。

## 根因

三处各自为政，合起来造出「已开启但未连接」这个不该存在的状态：

| # | 事实 | 位置 |
|---|---|---|
| 1 | 入口门控**只返回 `tgEnabled`**，形参 `tgAvailability` 被 `void` 掉 | `store/selectors.ts:95-101`（修前） |
| 2 | 门控自己声明的契约是「开关开 **+ orig-tg 服务可达**」，代码没兑现 | `components/Sidebar.tsx:37-44` 注释 vs `selectors.ts` 实现 |
| 3 | `spawn()` 一返回就 `Ok(true)`，**不等子进程真的监听**；bind 失败的子进程立刻退出，daemon 仍报 `tg_enabled=true` | `download-engine/crates/orig-daemon/src/state.rs:186`（修前） |
| 4 | 面板把离线调试短路渲染成中性「调试模式」卡片，掩盖故障 | `components/TgPanel.tsx` 的 `tgDebugOffline` 分支 |
| 5 | 设置页在「开了但没跑」时显示「**启动中**」——永久失败时永远等不到 | `components/SettingsPanel.tsx`（修前 `tg.starting`） |

第 3 条是**物理根因**：`tg_start` 从不校验子进程是否真的开始服务，于是
「daemon 承诺 TG 已开启」与「TG 实际没有服务」可以长期共存。第 1 条让这个矛盾**可见地**暴露给用户。

## 修复

**核心设计（用户 2026-09-29 拍板）：TG 服务可用？否 → 不显示 TG。**

1. **入口门控**（`store/selectors.ts`）：`tgEnabled && tgAvailability !== null && status !== 'unreachable'`。
   - 服务不可达 → 不显示（daemon 的失职不该被包装成产品状态）；
   - 服务可达但未登录 → **照常显示**（BUG-094：登录是用户动作，藏了就永远登不上）；
   - 探测未返回（`null`）→ 不显示（未知 ≠ 可用）。
2. **弹回判据统一**（`components/MainLayout.tsx`）：改走同一个 `resolveTgFeatureReady`，
   不再另写一份 `status === 'unreachable'` —— 两份判据必然分叉。
3. **拉起必须验真**（`state.rs::tg_start_on`）：spawn 后有界等待端口出现监听；
   等不到就 kill + 清句柄 + 记 `tg_last_error` + **返回 `Err`**（不再谎报 `Ok(true)`）。
4. **托管自愈**（`state.rs::tg_supervise` + `main.rs`）：daemon 是 orig-tg 的唯一所有者，
   巡检 15s 探测、spawn 冷却 60s，开启却没在服务就自己拉起来。
5. **端口单一真源**：`tg_port()` 读 `ORIG_TG_PORT`（默认 9877），daemon 注入子进程的是**同一个值**；
   `GET /api/config` 新增 `tg_port` 与 `tg_last_error`，前端不再各自猜 9877。
6. **失败原因可见**：设置页 TG 开关旁显示 `tg_last_error`（`data-testid="tg-toggle-error"`），
   状态文案由「启动中」改为「启动失败」—— 入口被摘除后，这是用户唯一能知道「为什么没有 TG」的地方。
7. **删除调试态**：移除 `tgDebugOffline` 分支与 i18n `tg.debugOfflineTitle/Hint`（zh + en），
   产品里不再有「调试模式：TG 未连接」这种态。
