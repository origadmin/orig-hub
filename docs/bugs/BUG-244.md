# BUG-244: 永久失败（二进制缺失）不受 spawn 冷却约束 —— 巡检每 15s 重试一次并追加一行错误

- 状态: fixed
- 发现日期: 2026-10-09
- 模块: engine
- 严重程度: mid

## 现象

`TG_SPAWN_COOLDOWN`（60s）的判定读 `tg_last_spawn`，而该时刻**只在 `cmd.spawn()` 成功之后**写入
（`download-engine/crates/orig-daemon/src/state.rs::tg_start_on`）。「二进制缺失」分支在 spawn **之前**
就 `return`，于是冷却永不生效：巡检每 `TG_SUPERVISE_INTERVAL`（15s）重试一次，
注释里承诺的「二进制缺失这类**永久失败**不该变成每 15s 拉起一个立刻就死的进程」落空。

实测（2026-10-09，隔离实例 + `ORIG_TG_PATH` 指向不存在）：运行约 5 分钟，
`logs/errors.log` 累积 **2540 B ≈ 20 行**，即约每 15s 一行 —— 与 60s 冷却的承诺不符；
用户侧表现为「错误日志被同一条永久失败刷屏」（BUG-243 落地后才可见）。

## 修法

冷却覆盖**所有**失败路径：缺二进制这条早退路径同样记录 `tg_last_spawn`。

## 验收证据

- 修复后隔离实例（端口 29888、`ORIG_TG_PATH` 指向不存在）50 s 内 `logs/errors.log` 行数采样：
  `{"5s":1,"10s":1,"15s":1,"20s":1,"25s":1,"30s":1,"35s":1,"40s":1,"45s":1,"50s":1}`
  —— 全程**恒为 1 行**（启动那一次），15s / 30s / 45s 三次巡检都没有再产生新行（60s 冷却生效）。
  修复前同一场景为 ~15s 一行（5 分钟 2540 B ≈ 20 行）。
- `cargo build --release -p orig-daemon` 通过（`download-engine/crates/orig-daemon/src/state.rs`）。
