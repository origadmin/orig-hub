# BUG-310: 视频显示名无唯一规则——caption 缺失即空标题，item/episode/series 三层各写各的，同一视频多处名字不一致

- 状态: fixed
- 发现日期: 2026-10-14
- 模块: engine+shell
- 严重程度: mid

## 实施裁定（2026-10-15，经 AskUserQuestion 确认）

- **item 标题保留可改**（用户原话「我感觉中是可以修改的」）：不做「item 一律只读」。
  理由：音频 / 文档 / 未被归集进剧集的条目**没有剧集面板可改名**，一律只读会让这些内容
  彻底无法命名 —— 那是删能力，不是修缺陷。
- 落实的是**「规则唯一」**：新增只读来源事实字段 `media_item.source_title`，
  前端全部显名位置走同一个解析函数。

## 现象

用户指出（2026-10-14）：「视频本身是没有名称标题的,所有剧集中针对视频的名称标题的实现逻辑需要重新评估。」

- TG 视频消息无文件名；caption 缺失时 media_item.title 写入**空串**，卡片/列表名靠前端槽位标签兜底；
- 三个编辑面分别写三层（ItemEditDialog→media_item.title、EpisodeEditPanel→media_episode.title、
  SeriesEditPanel→media_series.title），「这个视频叫什么」没有唯一口径；
- 磁盘名（`{msg_id}-{caption_slug}.mp4`）在落盘时定死，后续 caption 补强或用户改名均不联动文件，
  库里显示名与文件名永久分叉。

## 根因

- `routes.rs:1809-1861` `register_media_item_t0`：标题只取 caption 首行；无 caption 非照片传空串。
- `media.rs:1675-1704` `upsert_media_item`：`title = COALESCE(NULLIF(excluded.title,''), title)`，
  空值不覆盖、非空即覆盖，补强顺序没有分层。
- 前端 `episodePresentation.ts` 槽位标签（S1E2）与卡面各取不同字段；三个编辑端点各自直写。

## 复现

1. 缓存一条无 caption 的 TG 视频；
2. 文件域卡片、剧集详情、下载记录三处显示名不一致（空 / S1E2 / 磁盘名）；
3. 在剧集里给该集改名，磁盘文件名不变；再在条目编辑改 title，剧集名又不变——三处永久分叉。

## 修复

按 **D24=A**（2026-10-14）：

- 显示名唯一规则：**用户自定义集名 > 剧名+集号（单集用剧名）> 来源原始名**；
  item 的来源标题降级为只读事实字段，人工命名只发生在编排层（series/episode）；
- 剧集/集改名**不动物理文件**（物理名与显示名解耦，物理侧见 BUG-309 hash 化与 BUG-311 整理工具）；
- 前端所有显名位置走同一个解析函数，消除三处兜底分歧。

## 验收证据

实现落点（`M2-T09`）：

- 引擎：`media_item.source_title` 列（pragma + ALTER + 一次性回填 `title`，只填 NULL ⇒ 幂等）；
  `upsert_media_item` / `update_media_item` 均写成「只认**第一个非空**的来源名」⇒ 用户改名
  只动 `title`，来源事实永不漂移；`resolve_display_name()`（媒体侧）、
  `MediaItem` 补 `sourceTitle` / `seriesSeason` / `seriesEpisodeNo` / `seriesEpisodeNoEnd` /
  `seriesEpisodeCount` 五个派生字段（卡片层算「剧名+集号」必需，否则卡片与详情页又会分叉）。
- 前端：`tauri-shell/src/lib/displayName.ts`（新增）—— **唯一**解析函数，实现
  「用户自定义集名 ＞ 剧名+集号（单集用剧名）＞ 来源原文」。
  接入点：`MediaCard`（卡片）、`EpisodeList`（播放器分集行）、`EpisodeExpanded`（展开态标题）、
  `SeriesDetail`（右栏聚焦标题 `episode-focus-title`）、`ItemEditDialog`（新增只读「来源原文」行
  `item-edit-source-title`，仅在与当前标题不同时出现）。
  分集**行态**中列仍走 `episodeRowTitle`（BUG-260 的行内去重规则）—— 那是「同一行内不要重复」，
  与「一个内容叫什么」是两条不同规则，已在两处文件头写明区分理由。

夹具：`legacy_db_migrates_to_source_title_without_failing_bug310`（旧库补列 + 存量回填 + 不丢数据）。

规则一致性说明：`resolve_display_name`（Rust）与 `resolveDisplayName`（TS）是**同规则两实现**
（前者供整理模板 `{集名}` 用，保证「库里显示的名字」与「整理出来的文件名」一致）。这是有意为之，
不是重复：Rust 侧无法复用 TS 函数，而整理在引擎侧执行。两侧规则差异由上面列出的夹具与人工核对兜住。
