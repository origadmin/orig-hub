# BUG-310: 视频显示名无唯一规则——caption 缺失即空标题，item/episode/series 三层各写各的，同一视频多处名字不一致

- 状态: open
- 发现日期: 2026-10-14
- 模块: engine+shell
- 严重程度: mid

## 现象

用户指出（2026-10-14）：「视频本身是没有名称标题的,所有剧集中针对视频的名称标题的实现逻辑需要重新评估。」

- TG 视频消息无文件名；caption 缺失时 media_item.title 写入**空串**，卡片/列表名靠前端槽位标签兜底；
- 三个编辑面分别写三层（ItemEditDialog→media_item.title、EpisodeEditPanel→media_episode.title、
  SeriesEditPanel→media_series.title），「这个视频叫什么」没有唯一口径；
- 磁盘名（`{msg_id}-{caption_slug}.mp4`）在落盘时定死，后续 caption 补强或用户改名均不联动文件，
  库里显示名与文件名永久分叉。

## 根因

- `routes.rs:1809-1861` `register_media_item_t0`：标题只取 caption 首行；无 caption 非照片传空串。
- `media.rs:1675-1704` `upsert_media_item`：`title = COALESCE(NULLIF(excluded.title,''), title)`，
  空值不覆盖、非空即覆盖，补强顺序没有分层。
- 前端 `episodePresentation.ts` 槽位标签（S1E2）与卡面各取不同字段；三个编辑端点各自直写。

## 复现

1. 缓存一条无 caption 的 TG 视频；
2. 文件域卡片、剧集详情、下载记录三处显示名不一致（空 / S1E2 / 磁盘名）；
3. 在剧集里给该集改名，磁盘文件名不变；再在条目编辑改 title，剧集名又不变——三处永久分叉。

## 修复

按 **D24=A**（2026-10-14）：

- 显示名唯一规则：**用户自定义集名 > 剧名+集号（单集用剧名）> 来源原始名**；
  item 的来源标题降级为只读事实字段，人工命名只发生在编排层（series/episode）；
- 剧集/集改名**不动物理文件**（物理名与显示名解耦，物理侧见 BUG-309 hash 化与 BUG-311 整理工具）；
- 前端所有显名位置走同一个解析函数，消除三处兜底分歧。
