# BUG-376: TG 相册折叠封面「点击展开」间歇性完全无反应

- 状态: fixed
- 发现日期: 2026-10-22
- 修复日期: 2026-10-22
- 模块: shell
- 严重程度: mid

## 现象

折叠封面的实现是 `<button data-testid="album-cover" onClick={onToggleExpand}>`
（`TgPanel.tsx` 3171-3205），点击应把该组换成 `[data-testid="album-grid"]`。

实测**同一会话内两种结果并存**：

| 相册 | 组内条数 | 点击结果 |
|---|---|---|
| msg 209192 | 2 | 展开成功：`grid 0→1`、`tiles 0→2`、`collapse 0→1`，MutationObserver 记到 29 条变更 |
| msg 209207 | 9 | 连点**两次**仍 `grid=0`，`mutations: []`（DOM 一个变更都没有） |

## 根因

`AlbumBubble` 是 `memo()` 包的自定义比较器，比较字段里**漏了 `expanded`**，末尾还多一句
恒真的 `&& true`：

```tsx
  a.highlighted === b.highlighted &&
  a.progress?.done === b.progress?.done &&
  ...
  a.progress?.itemBytesTotal === b.progress?.itemBytesTotal &&
  true,   // ← 恒真兜底，进一步掩盖漏字段
```

`expanded` 变化时 `setExpandedAlbums` 确实生效（实测 `expandedAlbums.size=1`、渲染侧
`has(key)=true`），但比较器判「相等」⇒ React 跳过重渲染 ⇒ 折叠态**永远展不开**。

**为什么表现为间歇性**：那一刻恰好有别的 prop 变化（进度轮询把 `progress.*` 换了）
把重渲染带了进来，于是「有时能展开」。这正是它极难靠手感定位的原因。

与同比较器里 BUG-364 的 `highlighted` 是**同型缺陷** —— 源码注释已写明那条教训，
却又漏了 `expanded`。说明「逐字段列比较器」这种写法本身在诱导复发。

## 修复

`tauri-shell/src/components/TgPanel.tsx`：比较器补 `a.expanded === b.expanded`，
删掉末尾 `&& true`，并把这条教训写进注释（指明与 `highlighted` 同型、指明间歇性成因）。

## 已排除的可能（都有实测）

| 假设 | 排除依据 |
|---|---|
| 判据认错形态（展开态不是 `album-grid`） | 209192 那次 `album-grid` 确实出现，且里面有 2 个 `tg-album-tile-*` |
| 点在游离节点上（轮询重渲染换了节点） | 点击瞬间 `document.contains(el) === true`（`detached: false`） |
| 视口外 lazy 图没加载 | 已 `scrollIntoView({block:'center'})`，且封面缩略图请求已发生（`coverThumbSeen: true`） |
| 判据读得太快/太慢 | 60ms 快速轮询 15s，`maxGrid` 恒 0 —— 不是「展开后又收起」，是**从未展开** |
| `fullPage` 截图扰动布局 | 改成视口截图后现象不变 |
| `setViewport` 传参错误 | 已修（`Page.setViewport` 收对象，不是两个数字） |
| 原生监听没派发 | `_probe_album_clickpath.cjs`：5 个相册全部 `nativeFired=1` |
| 祖先链 `inert` / `pointer-events:none` / `disabled` | 逐层体检全清白 |
| `onClick` 没挂上 | `_probe_album_reactprops.cjs` 读 `__reactProps$*`，`typeof onClick === 'function'` 且直接调用生效 |
| 键不匹配 | `_probe_album_dbg.cjs` 埋点：`toggle:album-...:size=1` / `map:album-...:has=true`，键与状态全对 |

排查链：`_probe_album_click.cjs`（真实鼠标 + `elementFromPoint`）→
`_probe_album_mutation.cjs`（MutationObserver 记账）→ `_probe_album_clickpath.cjs`
（原生派发 + 祖先链体检）→ `_probe_album_reactprops.cjs`（React props 直调）→
`_probe_album_dbg.cjs`（渲染侧埋点）。最后一步把「状态对、界面不动」直接指向
**渲染被跳过**，才落到 `memo` 比较器。

同时修的 6 个**判据自身缺陷**（首跑才暴露，逐条有注释留痕）：
`page.setViewport` 收对象；`waitUntil: 'domcontentloaded'`（`load` 要等几十张缩略图，
任一挂住则永不触发）；`performance.setResourceTimingBufferSize(20000)`（默认 250 条被挤爆）；
A1 先 `scrollIntoView` 再等（`loading="lazy"` 视口外不发请求）；A2 比对补 `chatId:` 前缀
（瓦片上只有裸 `messageId`）；A7 过滤 `favicon.ico` 404。
