# BUG-069: 「剧集里的视频」文案与视频不同源 —— 分集标题改不了、条目介绍在剧集里不显示

- 状态: fixed
- 发现日期: 2026-09-19
- 模块: engine+shell
- 严重程度: high

## 现象

用户第 9 轮（BUG-054 已发版后仍存在）：

> 「媒体库 **剧集里面视频标题无法修改**. 剧集里面**介绍内容没有填充进视频**. 这两个问题仍然存在.
> **内容剧集和视频应该是一致的,但是结果天差地远**.」

打开剧集详情 → 分集行只能看到「所指向条目**在分集行上的副本**」：

1. 点分集行的编辑 → 面板里只有「季 / 集 / 介绍」，**没有标题字段** ⇒ 在剧集路径下，
   这条内容的标题**根本不可改**（必须退回「全部内容」翻到那张卡才能改）。
2. 条目里明明有介绍，进入剧集后分集行与面板都是空的 ⇒「介绍没填进视频」。

## 根因（第二套真源）

`media_episode` 自带 `title` / `description` 两列，与 `media_item.title` / `media_item.description`
构成**两套真源**，而写入路径分属不同调用方：

- 分集路径（`add_episode` / `merge_series`）写分集列；
- 条目路径（`PATCH /api/media/items/:id`、缓存入库）写条目列。

`EpisodeView` 于是同时下发两套字段（`title`/`description` 来自分集行，`item_title`/`item_description`
来自条目），前端各处按不同分支挑不同名字读 —— 分叉是必然而非偶然：

- `SeriesDetail` 读分集副本；`EpisodeList` 写 `ep.title || ep.itemTitle` 的兜底链
  （**两个名字的来源**本身就说明没人知道该信哪个）。

实测真实库证实两条路径早已漂移：

```
media_episode.description  非空 1 / 45 行
media_item.description     非空 7 / 110 行
```

即「分集上有、条目上没有」与「条目上有、分集上没有」同时存在 —— 用户看到的「天差地远」。

另：分集编辑面板缺标题字段是**独立缺陷**（与真源无关），BUG-039 之后一直在。

## 复现

1. 媒体库 → 某剧集 → 分集行点「编辑」：只有季/集/介绍，**无标题**；
2. 同一条内容在「全部内容」里把介绍改掉 → 回到剧集，分集行与面板仍显示旧/空值；
3. 反向：在剧集里填介绍 → 「全部内容」卡片上不出现。

## 修复

**分集只是「位置」，文案唯一真源 = 条目**，写路径一律写穿。

engine（`download-engine/crates/orig-tg/src/media.rs`）：

- `EpisodeView` 的 `title`/`description` 改从 `media_item` 取（`get_series` 的 SELECT 用
  `i.title, i.description`，`media.rs:1236` 一带），**删除** `item_title`/`item_description`
  两个冗余字段 —— 同一份数据只留一个名字，前端无处可挑错。
- `update_episode` 写穿条目：`UPDATE media_item SET title = ?1, description = ?2 WHERE id = ?3`
  （`media.rs:130`）；标题取「本次非空值否则保留旧值」，介绍 `null` = 显式清空。
- `add_episode` / `add_episode_ranged` / `merge_series` 不再向 `media_episode.title` 写入；
  `EpisodeEdit.title` 只作**写穿入参**。
- 一次性迁移 `collapse_episode_text`（`media.rs:158`，标记 `mig.episode_text_to_item_v1`，
  `media.rs:32`）：条目介绍为空时用分集行历史值回填，随后清空死列；
  在 `backfill_item_text` **之后**执行（`media.rs:353-358`）。
  **只搬介绍、不搬标题** —— `media_item.title` 是 `NOT NULL` 且必有值，分集行上的标题只是快照，
  对它没有权威（写错方向会把用户改过的真标题覆盖成旧快照，单测已钉死）。

routes（`download-engine/crates/orig-tg/src/routes.rs:2491`）：`EpisodeReq` 去掉 `title`。

shell：

- `src/api/media.ts`：`MediaEpisode` 去掉 `itemTitle`/`itemDescription`；`addEpisode` 去掉 `title`。
- `src/components/media/SeriesDetail.tsx`：分集编辑面板新增标题输入框（`:717`），保存改走
  `patchEpisode({ title, description, season, episodeNo })`（`:255-276`）；**空标题前端即拦**
  （`:264-267`）—— 与后端「空标题不可表达」同一语义；分集行标题取 `ep.title`（`:615`）、
  介绍常显（`:776` 一带）。
- `src/components/media/EpisodeList.tsx:148`：删掉 `ep.title || ep.itemTitle` 兜底链。
- `src/components/MediaLibraryPanel.tsx`：`episodesToItems` 直接取 `e.title`/`e.description`。

契约测试覆盖的关键断言：

- 分集字段里**不再存在第二套** `itemTitle`/`itemDescription`（同一份数据只有一个名字）；
- 在剧集里改标题/介绍 → **条目**真的变了（写穿，不是只改副本）；
- 剧集详情 / 条目详情 / 条目**列表**三处**逐字**一致（标题与介绍各一条）；
- 反向：改条目 → 剧集详情里的分集标题同步跟着变；
- 空标题 = 保留旧值（200），介绍显式 `null` = 清空（200）；
- 越界半径：不存在的分集 id → 404（不静默成功）、`episodeNo=0` → 422。

UI 测试覆盖的关键断言（运行期读数 + wire 对照）：

- 分集行标题 = 条目当前标题（逐字）、分集行**含介绍**；
- 分集编辑面板**有标题输入框**且初值 = 当前标题（不是空）、介绍初值 = 条目的介绍（逐字）；
- 改标题+介绍 → 保存 → 分集行**立刻**是新值；`GET item` / `GET series` 与 UI 逐字一致；
- 还原：被借用条目的标题与介绍**逐字回到原值**（探针只借不改：真实库上只做「改名 → 还原」）。
