# BUG-076: 剧集分集标题编辑另起一行，且编辑态会被截断导致存错内容

- 状态: fixed
- 发现日期: 2026-09-20
- 模块: shell
- 严重程度: mid

## 现象

剧集详情里点分集的编辑按钮，标题输入框出现在**分集行下方另起的一块区域**里，而用户
期望的是「原行内编辑」。更严重的是：标题在列表里用 `truncate` 单行省略显示（`...`），
长标题在编辑态若沿用截断样式，用户看到并提交的是被截掉的字符串，
**保存后内容就是错的**——即「编辑时不能省略，不然内容就出错了」。

用户原话：「剧集中视频的标题编辑不需要新的一行吧？原本行编辑就行了。但是需要处理超出
换行，编辑的时候不能省略（...），不然内容就出错了。」

## 根因

`tauri-shell/src/components/media/SeriesDetail.tsx`：

1. 标题输入框被放在 `{editingEp === ep.id && (...)}` 的**下方展开块**内（原 723-732 行
   `pl-[4.25rem]` 区域的首个字段），与季号/集号/介绍同处一个独立行 → 视觉上「另起一行」。
2. 展示态标题 `<p className="truncate ...">`（现 626 行）用 `truncate` 单行省略。编辑控件
   若复用该样式，长文本不可见部分无法核对；`overflow-wrap: anywhere` 也未设置，
   超长无空格串（URL 式标题）不会换行。

## 复现

1. 媒体库打开任一有多集的剧集 → 右侧分集列表；
2. 点某集的铅笔图标 → 标题输入框出现在该行**下方**，而不是该行的标题位置；
3. 把标题改成一个超过容器宽度的长串 → 编辑框未换行/被截断，看不到全部内容即提交，
   保存结果与输入不符。

## 修复

- 标题输入**移入分集行内**：`editingEp === ep.id` 时，在原标题 `<p>` 的同一槽位渲染
  `<textarea data-testid="episode-title-input">`，不再在下方展开块重复一个标题字段
  （下方块只保留季号/集号/介绍）。
- `textarea` 而非单行 `input`：`rows={2}` + `resize-none` + `[overflow-wrap:anywhere]`，
  超长自动换行、完整可见，**编辑态绝不 `truncate`**。
- 展示态保留 `truncate` 单行（列表密度需要），但补 `title={ep.title || ''}` 让完整文本
  可 hover 查看——**截断只发生在只读态，编辑态零截断**。
- 编辑态下铅笔按钮让位给输入框（同一槽位互斥渲染），不出现两个标题控件。

验收锚点：`[data-testid="episode-title-input"]` 与分集行同一行（与缩略图顶边对齐）；
长文本下该元素 `scrollHeight > clientHeight` 时仍完整可见且无 `text-overflow: ellipsis`。
