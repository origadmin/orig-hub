# BUG-307: 撤回「视频/剧集」合并，恢复两者为独立入口；修复标签筛选样式

- 状态: in_progress
- 发现日期: 2026-10-14
- 模块: shell
- 严重程度: high

> 来源：用户 2026-10-14 对 BUG-306 / D19-⑦ 合并的回退裁定原话：
> 「视频有严重逻辑问题. 1. 混入了图片,分类出现严重逻辑错误. 2. 没有考虑视频(普通下载),
> 剧集(TG插件或者其他),两种方式. 当前显示破坏了剧集,视频,图片,整个逻辑没有一点对的.
> 3. 标签筛选样式有严重问题,"标签"很小,筛选很大,两个套用的是2套式样,看着根本不是一个东西,且无比丑陋.」
>
> 本档为任务文档（Agent 模式，本组直接实施）。它**撤回** BUG-306 / D19-⑦ 的「视频+剧集合并」，
> 并修复标签筛选样式。决策锚定 **D19**（追加 D19-⑨ 撤回节）。

## 现象（三条，逐条对应原话）

1. **「视频」入口混入了图片**：BUG-306 / D19-⑦ 把侧栏「视频」入口的落点改成了 `fmode: 'lib-series'`
   （`Sidebar.tsx` 合并注释 + `nav-child-lib-series` 标签被改成「视频」）。于是点「视频」进去的是
   **剧集墙**（`MediaLibraryPanel` `view==='series'`），而剧集墙的 `SeriesCard` 代表的是
   **可以含照片的剧集**（`selectedJoinable` 规则 `k==='video'||k==='photo'`）。⇒「视频」展示了带照片的剧集。
2. **视频 / 剧集 / 图片 三者逻辑全错**：合并让「视频」与「剧集」成了同一个入口（都指向剧集墙），
   原本应独立的「剧集」入口被吃掉；`cat:video` 子项被 `.filter(cat!=='video')` 故意不渲染。
   用户裁定「视频(普通下载)」与「剧集(TG插件或其他)」是**两种不同浏览方式**，须分开。
3. **标签筛选样式丑**：`MediaLibraryPanel.tsx` 标签区——「标签」用 `text-[10px] uppercase muted`
   （极小全大写灰字），筛选框 `h-6 flex-1 text-[10.5px]`（撑满整行的大输入框），两套式样、
   像两个不相关的东西。

## 根因

BUG-306 / D19-⑦ 的合并方向错了：它把「视频」入口**落点**改成 `lib-series` 剧集墙，并删掉独立「剧集」入口。
`MediaLibraryPanel` 的 `appliedFmode` effect **本来就同时支持** `cat:video → items 网格`
与 `lib-series → 剧集墙` 两条路径（合并纯是侧栏渲染层决定），所以撤回合并只需还原侧栏渲染层。

## 修复方向（已实施）

1. **撤回合并，恢复两个独立入口**（`Sidebar.tsx` 文件树子项）：
   - **视频**（普通下载）：`nav-child-cat-video`，标签 `files.cat.video`，落点 `cat:video`
     → items 网格（`kind=video`，**扁平视频库**，不混入图片）；
   - **剧集**（TG 插件或其他来源）：`nav-child-lib-series`，标签 `files.lib.series`，落点 `lib-series`
     → 剧集墙；
   - 其余分类子项（`music/image/doc/archive/other`）保持，`cat:video` 不再被合并吸收、独立渲染。
2. **重加 i18n 键** `files.lib.series` = 「剧集」/"Series"（BUG-306 曾当死键删，本档恢复）。
3. **顶栏副标题同源**（`ContextBar.tsx` `ViewTitle`）：`lib-series` 副标题由 `files.cat.video`
   改回 `files.lib.series`（剧集墙显示「剧集」，不再显示「视频」）。
4. **标签筛选样式统一**（`MediaLibraryPanel.tsx`）：「标签」标签与筛选输入框**同一套式样**
   —— 同字号（11px）、同字重（medium）、同前景色（`text-fg-soft`），去掉「极小 uppercase 小标签 +
   撑满大输入框」两套视觉；输入框高由 `h-6` 提到 `h-7` 与标签视觉权重一致。
5. **`nav/index.ts` 注释**：三处合并注释改为撤回后的真值（视频独立入口、`lib-series` 仅作落点判据、
   D18「视频=剧集」降级为**数据模型**不变量而非 UI 合并依据）。

## 可证伪判据（实施提交须引用 BUG-307）

> 每条判据须含**反向证伪**：喂错值/留旧逻辑必须 FAIL，不得报 0 或假绿。

1. **视频入口是扁平视频库**：点 `nav-child-cat-video` ⇒ `view==='items'` 且 `tab==='video'`
   （`kind=video` 过滤）；主区渲染 `media-grid` 条目卡，**不渲染** `series-wall-scroll` 剧集墙。
   **反向证伪**：`nav-child-cat-video` 落点改回 `lib-series`（旧合并逻辑）⇒ 进剧集墙、FAIL。
2. **视频不混入图片**：`cat:video` 条目列表的每一项 `kind==='video'`（后端已按 `tab='video'` 过滤）；
   剧集墙（`series-wall-scroll`）里**不会出现** `kind==='photo'` 独占的剧集被算进「视频」。
   **反向证伪**：去掉 `loadItems` 的 `kind` 过滤 ⇒ 图片进入视频列表、FAIL。
3. **剧集为独立入口**：侧栏存在 `nav-child-lib-series` 且标签 === 「剧集」（en-US === "Series"）；
   点它 ⇒ `view==='series'`（剧集墙）。`nav-child-lib-series` 与 `nav-child-cat-video` **同时存在**、
   标签不同。
   **反向证伪**：删掉 `nav-child-lib-series`（旧合并、入口被吃掉）⇒ 侧栏无「剧集」、FAIL。
4. **顶栏副标题同源**：进剧集墙时 `context-bar-sub` === 「剧集」（en-US === "Series"）；
   进视频网格时 `context-bar-sub` === 「视频」（en-US === "Videos"）。两处**不分裂**。
   **反向证伪**：`ViewTitle` 对 `lib-series` 仍返回 `files.cat.video` ⇒ 顶栏叫「视频」侧栏叫「剧集」、FAIL。
5. **标签筛选样式统一**：`media-tag-filter` 输入框与「标签」标签 computed 字号相同（均 11px）、
   同字重（medium）；「标签」标签 `text-transform` 不为 `uppercase`；两者视觉权重一致
   （`getComputedStyle` 实测，不读 className 推断）。
   **反向证伪**：把「标签」标签改回 `text-[10px] uppercase` ⇒ 字号/字重/transform 与输入框不一致、FAIL。
6. **i18n 无死键残留**：`files.lib.series` 在 zh-CN/en-US 均存在且非空白；
   `files.cat.video` 仍指向「视频」/"Videos"（未被合并挪用为剧集名）。
   **反向证伪**：删 `files.lib.series` 键 ⇒ 剧集入口/副标题缺文案、FAIL。
