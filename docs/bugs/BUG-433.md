# BUG-433: 相册组内首条没有任何预览入口——首条是视频时「整组的视频都无法播放」

- 状态: fixed
- 发现日期: 2026-10-26
- 模块: shell
- 严重程度: high

## 现象

用户 2026-10-26 原话：

> 如果第一条数据是视频，那么这个数据组的视频将完全无法播放（第一条没有播放功能）。

## 根因

`AlbumBubble` 的两处实现叠加，把 `items[0]` 变成死内容：

1. 宫格渲染 `items.slice(1, ALBUM_MAX_TILES + 1)` —— 首条被**故意排除**，
   注释理由是「首图已作为封面呈现，不入宫格」。
2. 封面那颗 `<button data-testid="album-cover">` 的唯一动作是
   `onToggleExpand`（展开/收起整组），**从不 `onPreview`**。

于是首条在折叠态（点击只展开）和展开态（宫格里没有它）**都没有预览入口**。
组内首条恰好是视频时，用户感知就是「这个数据组的视频完全无法播放」。

## 修复

宫格改为 `items.slice(0, ALBUM_MAX_TILES)`，首条也进格：

- 组内每一条都有独立可点入口；
- `tg-album-tile-N` 的下标**语义不变**（仍是 `N === items 下标`）——
  旧实现是 `slice(1)` 配 `testid=i+1` 的隐式偏移，正好等价，所以既有脚本不受影响；
  唯一新增的是 `tg-album-tile-0`；
- `isLastTile` 的溢出角标同步改为按 `items.length` 计算。

代价：首条缩略图与封面重复一次（「主图 + 全部缩略图」是通行形态）。
彻底方案（展开态取消独立封面、宫格即内容）属重设计，另立条目。

## 复现

TG → 任一频道 → 点第一个相册封面展开 → 修复前宫格里只有 `items[1..]`，
首条无任何可点入口；修复后出现 `tg-album-tile-0` 且点击打开播放器第 1 项。
