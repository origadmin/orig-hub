# BUG-399: 文件列表列头与行内容横向错位（"标题和内容完全不对齐"）

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: shell
- 严重程度: high
- 报告: 用户 2026-10-23 17:12 截图「文件管理,标题和内容完全不对齐啊,全部都是乱的」

## 现象（用户截图，事实）

「文件管理 → 全部」Explorer 列表里，列头（名称/类型/大小/日期/来源）与数据行的同列内容**横向不落在同一竖线上**：行的「视频」「226 MB」「2026-10-23」「TG」整体偏左约 190~215px，列头悬在空白处；行内名称前还有列头没有的图标元素，视觉上"全部都是乱的"。

## 取证（已落盘）

- `tauri-shell/verify/verify_bug399_column_alignment.cjs`：CDP 打开文件域 → 全部，量
  `file-list-header` 各列 span 与 `file-list-row` 同序单元格的 `getBoundingClientRect().left`，逐列对比。
- 探针实测根因：头/行轨道模板 `… 586px(名称) … 0px vs 212px(动作)`——
  ①列头末列空 span 使 `auto` 轨道塌 0px、行动作列实宽 212px ⇒ 名称列一头 812px
  一头 589px，类型/大小/日期/来源全体错位 216px，且各行动作列随「在 TG 中查看」
  有无各自伸缩（行与行也互不对齐）；②行在滚动容器内被垂直滚动条吃 10px、列头在
  容器外。名称前「多余图标」= TG 来源标题自带的 📱 emoji，非布局元素。

## 修法

1. **列模板收敛单一常量** `FILE_ROW_GRID`（`20px_24px_minmax(0,1fr)_64px_88px_104px_64px_216px`），
   头/行同一份；动作列从 `auto` 改**定宽 216px**（实测最宽行动作簇 212.5px），
   簇内 `justify-end` —— 头、行、行与行全部共线；
2. 列头挂 `overflow-y-scroll [scrollbar-gutter:stable]`、滚动容器挂
   `[scrollbar-gutter:stable]` —— 两侧预留等宽滚动条槽，列头与行轨道逐像素对齐。

## 验收证据

- 探针 `tauri-shell/verify/verify_bug399_column_alignment.cjs`（活栈 vite+真实数据）：
  - **正测**：头/行 computed grid-template-columns **完全相等**
    （`20px 24px 586px 64px 88px 104px 64px 216px`）；同序单元格 left 逐列相等
    （260 / 854 / 926 / 1022 / 1134 / 1206），0px 差；
  - **验牙（页内反向变异）**：把列头模板改回旧版 `..._64px_auto]` ⇒ A1（模板不等）
    与 A2（第 4~8 列 left 差 **216px**，即用户截图的错位量）全部转红；还原复绿。
    退出码 0，截图 `verify_shots/bug399-fixed.png`、原始错位对照
    `verify_shots/bug399-before.png`（证据 JSON 随探针落盘）。
- 代码落点：`tauri-shell/src/components/media/FileListView.tsx`（FILE_ROW_GRID 常量 +
  头/行同用 + gutter stable + actions justify-end）。
