# BUG-272: 剧集「年份」全库 46/46 为空 —— 字段**没有来源、没有默认、也没有定义语义**（发行年还是收录年？），新增与编辑两端都初始化为空

- 状态: open
- 发现日期: 2026-10-10
- 模块: engine+shell
- 严重程度: mid

> 来源：用户报告「**年份为什么是空的？为什么需要手动填入？今年是何年？这很难知道吗？**」
> —— 承接 BUG-258 的来源（「媒体库 → 内容 → 编辑：类型、年份的选项和作用，其中一个是空的」）。
>
> **本档为任务文档**（用户 2026-10-10 定：后续一律纯文档任务，代码由别的组负责）。

## 现象

### 现象 1：真库 46/46 部剧集 `year` 为 NULL

只读打开生产库（`%APPDATA%\com.origadmin.orighub\tg\store.db`）实测：

```sql
SELECT COALESCE(CAST(year AS TEXT),'NULL'), COUNT(*) FROM media_series GROUP BY 1;
-- ('NULL', 46)      ← 46 行，全部为 NULL
```

界面上该输入框因此**一直是空的**（`SeriesEditPanel.tsx:43` 的 `series.year != null ? … : ''` 恒取空串）。

### 现象 2：字段**没有任何来源** —— 全链路逐一排除

| 候选来源 | 实测结果 |
|---|---|
| `media_item` 列 | **无 year 列**（`id / source / ref / title / kind / file_path / poster / size / duration / width / height / added_at / description`） |
| TG 入库路径 | `routes.rs:1938` 建剧集传 `year: None`（BUG-258 已记） |
| 标题 / 文件名解析 | `media_item` 373 条里含 4 位年份的 **只有 5 条**，逐条看**全是噪声**：`photo--<chat>_<shard>`（`_<shard>` 是分片后缀）、`…--<chat>-<msg>`（`-<msg>` 是消息 id 尾巴）⇒ **解析不可行** |
| 视频容器元数据 | 引擎**未使用 `ffprobe`**（`grep -rn ffprobe download-engine/crates` → **0 命中**），不存 `creation_time` |
| TG 消息发送日期 | **未存储**（无 `message_date` / `sent_at` 字段） |
| 前端派生 | `grep -rn "getFullYear\|new Date()" tauri-shell/src` → **0 命中** ⇒ 前端**从不计算「今年」** |

⇒ **系统在任何路径上都不产生年份。** 这就是「为什么是空的」的完整答案：**没有上游**。

### 现象 3：两端都初始化为空，且文案只说「可选」

- **新增**：`SeriesDialog.tsx:25` `const [year, setYear] = useState('')`；
  `:77` 的 placeholder 硬编码「年份（可选）」—— **未走 i18n**。
- **编辑**：`SeriesEditPanel.tsx:43`；标签取 `zh-CN.json:558` `media.series.editYear` = 「年份」。

⇒ 用户看到的是「一个空框 + 一个『年份』标签」，**既不说为什么空，也不说填什么**。

### 现象 4（核心）：字段**语义未定义** —— 这才是「能不能自动填」的岔口

全仓检索「年份」只有两处文案（`zh-CN.json:558` `media.series.editYear`、`:598` `errYear`），
**没有任何文档或界面说明它指哪一个**：

- ① **发行年份**（剧集出品年，如 2019）—— **现有数据无从得知**（现象 2 已逐条排除）；
- ② **收录年份**（该剧集入库/收录到本库的年份）—— **当然可知**，就是 `added_at` 所在的年，**今年 = 2026**。

用户的追问「**今年是何年？这很难知道吗？**」**只在 ② 的语义下成立** —— 因为 ② 的答案就是**今年（2026）**。
而界面在**暗示 ①**：`SeriesHero.tsx:188` 与 `SeriesDetail.tsx:403` 都把 year 紧贴标题渲染成
`` ` · ${detail.year}` ``（如「某剧 · 2026」），读起来**像发行年**。

⇒ **界面在暗示 ①，用户的期待是 ②。这是本档的核心矛盾。**

## 根因

1. **字段先于语义落地**：`year INTEGER` 从**原始 DDL** 起就在 `media_series` 里（`media.rs:335`），
   但**没有任何路径写它、也没有任何文档定义它** ⇒ 它是一根**没有上游的管子**。
2. **BUG-258 只修了「清不掉」这半边**：该档把「年份全库为空」写成**现象 2**，但修复范围明确收在
   「**可清空**」契约（`SeriesPatch.year` 三态，`media.rs:4058`），并**主动裁定不回填**
   （`BUG-258.md` 修复节：「无从推断……凭空回填等于伪造事实，故不做」）。
   该裁定**在「发行年」语义下是对的**，但它**没有回答字段该不该存在、该是什么语义**。
3. **没有默认值**：即便按 ② 语义，也应在新增时预填当年，而两端都初始化为空串（现象 3）。

## 复现

只读核验（不需要改代码）：

```sh
# 1) 全库为空

# 2) 无来源

# 3) 无默认

```

## 修复方向（未实施；≥2 实质选项 + 1 个「不做」）

### 选项 A（推荐）：语义定为「**收录年份**」并**自动填** —— 直接回应「这很难知道吗」

- **新增剧集**默认填**当前年份**（取 `added_at` 的年；前端可用 `new Date().getFullYear()`）。
- **文案**从「年份」改为明确的「**收录年份**」（**改键值、不改键名** `media.series.editYear`），
  消除 `· 2026` 被读成发行年的歧义。
- **存量 46 行按 `added_at` 回填收录年** —— 这是**有据的**（`added_at` 就在库里），**不是编造**，
  与 BUG-258「不凭空回填」的裁定**不冲突**（那条禁的是「无据猜测」）。
- `涉及:` `SeriesDialog.tsx:25,77`、`SeriesEditPanel.tsx:43`、`zh-CN.json:558`、
  engine 一条一次性回填迁移（沿用 `ITEM_TEXT_SPLIT_MIG` / `EPISODE_TEXT_MIG` / `SERIES_KIND_NORMALIZE_MIG`
  同一套 `app_setting` 机制，`media.rs:30,33,47`）。
- `量化:` 前端 2 处默认值 + 1 个文案 + 1 条一次性迁移；**不动** `SeriesPatch` 契约。
- `回归风险:` 低 —— 不碰 BUG-258 的三态契约。
- `后果:` 46/46 立刻有值且**真实**（= 收录时间）；用户不再需要手填。

### 选项 B：语义定为「**发行年份**」，保持手填，但**把「为什么空」说清楚**

- 不动数据；文案改为「**发行年份**（可选，需手动填写）」，并在输入框 `title` / 空态给一句说明。
- `涉及:` `zh-CN.json:558`、`SeriesEditPanel.tsx:140-149`（`title`）、`SeriesDialog.tsx:77`（placeholder 走 i18n）。
- `量化:` 1 个文案 + 1 个 `title` + 1 个 placeholder 本地化。
- `回归风险:` 低。
- `后果:` **诚实但没解决问题** —— 46/46 仍为空，用户仍要手填（用户第三次追问可预期）。

### 选项 C：**撤下该字段**（无来源、无默认、全库空、无用户使用）

- 从 `SeriesDialog` / `SeriesEditPanel` / `SeriesHero` / `SeriesDetail` 移除年份的输入与展示；
  **DB 列保留**（不删列 —— 履历只增不减）。
- `涉及:` 4 个前端文件 + 2 个 i18n 键（**保留键、只停用** —— i18n「只删 UI 不删键」教训）。
- `量化:` 4 处移除。
- `回归风险:` 中 —— BUG-258 的三态契约**变得不可达**（契约仍在，只是没有入口）。
- `后果:` 界面上少一个永远为空的字段；但**若用户要的是「收录年」，撤掉就是答错题**。

### 选项 D：不做

- `涉及:` 无（0 行改动）。`量化:` 0。`回归风险:` 无。
- `后果:` 46/46 继续为空、继续要手填；「今年是何年」这个问题会再被问一次。

## 修复后必须满足（可证伪判据，预先声明）

1. **（若选 A）新剧集默认有年份**：走 UI 新建一部剧集、**全程不碰年份框**，保存后
   `GET /api/media/series/:id` 的 `year` **非 null**，且**等于当前年份**（今天 = **2026**）。
2. **（若选 A）存量回填有据**：46 行的 `year` 等于各自 `added_at` 所在年份；
   **不得**出现 `year` 早于 `added_at` 的年（那是编造）。
3. **语义可见**：界面文案能区分「收录年」与「发行年」——
   断言 `media.series.editYear` 的**值**包含限定词（**不再是光秃秃的「年份」**）。
4. **反向证伪**：
   - 选 A 时，把新增的默认值改回 `''` ⇒ 判据 1 **必须 FAIL**；
   - 选 B / C 时，把文案改回「年份」⇒ 判据 3 **必须 FAIL**。
5. **不破坏 BUG-258 的三态契约**：`PATCH {"year": null}` 仍能清空、`{}` 仍是不改
   （`media::tests::series_year_supports_explicit_clear` 与
   `routes::tests::patch_series_year_clears_on_explicit_null_and_keeps_when_absent` 必须继续通过）。
6. **不得伪造**：任何回填值都必须能追到库内既有事实（`added_at`）；
   **禁止**从标题正则硬猜（现象 2 已证 5/373 全是噪声）。
7. 判据 1 / 3 必须在**真实 UI** 上验（BUG-156），用后端响应与 `getComputedStyle` 判定，**不读 className**。
