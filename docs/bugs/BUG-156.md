# BUG-156：首行以 `#` 开头的 caption 被 `split_caption` 整行吞掉 —— 剧名丢失退化成「频道名 · 日期」

- 状态: fixed（代码提交 `b7eba612`；P4 判据**在产库满足**，见「修复后复核」第三/五节）
- 发现日期: 2026-09-23
- 模块: engine
- 严重程度: high

## 现象

真实频道 caption 的一种写法是首行**整行都是 `#` 打头的词**：

```
#18岁太奶奶驾到重整家族荣耀 #李柯以 #杨姝音 #孟娜
#大厨小婿 #陈姝君 #朱容君 #景漫
#存在感零 #杨幂 #赵今麦
#第七次心跳 #马芯妤 #张宸予 #国书瑄
#神雕侠侣 #刘亦菲
```

这些 caption 的**剧名就是第一个 `#` 词**（`#18岁太奶奶驾到重整家族荣耀`），后面的
`#李柯以` / `#杨姝音` 才是演员**标签**。但 `split_caption` 的规则是
「**行尾所有** `#` 开头的词一律弹掉」，于是**整行被清空** → 标题 = `None`
→ 剧集名退化成 `频道名 · 日期`，**真实剧名彻底丢失**。

且**两部同名、互相不可分辨**：


## 根因

`download-engine/crates/orig-tg/src/media.rs:2962` `split_caption`：

```rust
let title = {
    let mut toks: Vec<&str> = first.split_whitespace().collect();
    while let Some(last) = toks.last() {
        if last.starts_with('#') {
            toks.pop();          // ← 无条件弹掉「所有」行尾 # 词
        } else {
            break;
        }
    }
    toks.join(" ")
};
if title.is_empty() {
    return (None, body);         // ← 整行都是 # 词时，剧名直接判为「没有」
}
```

**规则本身没有错**（行尾 `#标签` 确实不该占标题位，`:4547-4550` 的单测就是为它写的）：
`标题行 #a #b` → 标题 `标题行`，正确。

**错在它假设「至少有一个非 `#` 词」**。当整行都是 `#` 词时，它无法区分：

| 情形 | 首行示例 | 第一个 `#` 词是 | 期望标题 |
|---|---|---|---|
| 标题 + 标签 | `标题行 #a #b` | **标签** | `标题行` |
| 纯 `#` 标题 + 标签 | `#剧名 #演员 #演员` | **剧名** | `#剧名` |

现有实现把两种情形都当第一种处理，第二种全军覆没。

**为什么一直没有被发现**：单测只覆盖了「标题 + 标签」这一种。
`split_caption_separates_title_and_body`（`media.rs:4542-4566`）的五个断言里
没有任何一条是「首行整行 `#` 词」。**判据缺样例**，所以实现缺口与测试缺口同时存在。

## 5 原则

### 原则（判据，必须先写下来）

1. **P1 剧名不丢**：任何首行都**不允许**把该行唯一的语义内容弹空。
   首行整行是 `#` 词时，**第一个 `#` 词必须保留为标题**。
2. **P2 标签仍不占标题位**：`标题行 #a #b` 仍必须得到 `标题行`（不得回归）。
   即：仅当**第一个**词以 `#` 开头时，第一个 `#` 词才被视为「标题」而非「标签」。
3. **P3 可证伪**：断言必须打在**生产调用链**上（`split_caption` 之后），
   不能只打在 `normalized_series_name` 上 —— 否则会出现「单测绿、产品丢剧名」。
4. **P4 不造新脏数据**：修复不得让 `#a #b` 这类**只有标签、没有剧名**的 caption
   产出 `#a` 这种假剧名。无法判定时宁可返回 `None`（走频道名兜底），
   也不能把演员名当剧名。
5. **P5 存量不删**：已退化为「频道名 · 日期」的剧集**不改名、不删除**（见「已知边界」）。

### 对策

把「弹尾 『#』词」的**起点**限制住：

- 先取首行分词 `toks`。
- **若 `toks[0]` 以 `#` 开头**（整行是紧凑式 `#剧名 #标签…`），
  则 `toks[0]` **是标题，不参与弹尾**；从 `toks[1:]` 开始弹尾。
- 否则行为**完全不变**（从最后一个词开始弹尾）。

即把「无条件全弹」改成「**至少留住第一个词**」。
判据 1/2 由此同时满足，且不引入「谁才是剧名」的启发式猜测 —— 因为
**`#` 出现在行首就是「这是剧名」的强信号**（标签不会占行首）。

### 分析（为什么这是根因，而不是表象）

- 用户报的缺陷 #3「后续内容全部是临时标题」有**两条**独立来源：
  1. `media_item.title` 为空（BUG-154 已修写入路径）；
  2. **本档**：`split_caption` 把整行清空，剧名**在入口处就没了** —— 这条链
     与 BUG-154 不同，它不经过 `unwrap_or`，而是**上游**就返回 `None`。
  两者都表现为「临时标题 / 只剩兜底名」，但**修一条不会修好另一条**。
  BUG-154 修完后本档仍然存在，这就是为什么「问题3 感觉没修」。
- 在产库命中率 4.1%（38/917），但**对该频道写法是 100% 致命** ——
  命中率低不等于可以放过：命中的每一部都**永久丢了剧名**。

### 防再发

1. **单测补样例**：`split_caption` 的判据必须新增两条
   - 正例：`split_caption("#剧名 #演员 #演员")` → `Some("#剧名")`
   - 反例（P4）：`split_caption("#演员1 #演员2")` 不得产出 `#演员1`
     —— 反例需先定裁定：若无法区分，则保持在 `routes.rs` 侧判定，不在 `split_caption` 造名。
2. **断言打在调用链上**：新增一条**集成级**单测，输入**真实 caption**，
   断言 `normalized_series_name(split_caption(cap).0)` 非空且**不含集号**
   —— 只测内层函数会再次漏掉本档。
3. **用例来源要真实**：`split_caption` 的单测样例此前是手写的
   （`这是标题` / `标题行 #a #b`），**没有一条来自真实库**。
   防再发要求从真实库取样（本档已留下 15 条真实首行），加入回归语料。
4. **门禁**：`scripts/` 下加一条「剧名为空率」检查 —— 对 `media_message.caption`
   跑 `split_caption`，空标题率超过阈值（如 5%）即报警。
   **基线必须取真正在产库**（`%APPDATA%\Roaming\com.origadmin.orighub\tg\store.db`）：
   修复前 **4.1%（38/917）**，修复后 **0**。回归红线按**绝对条数**设，
   不按百分比 —— 否则换库即失真（本档已因取错库连续误判两次）。
   脚本读取的库路径**必须由运行中后端 API 反查确认**，不得硬编码 `"production-app"` 标签。

- 本档**只修「新增」**，保证今后不再丢剧名。
