# BUG-335: 设置保存模式不清楚——同一页两套提交语义（即时 vs 显式保存）并存且无标识，底部保存键管什么不可见

- 状态: open
- 发现日期: 2026-10-20
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-26

## 现象（用户原话，2026-10-20 第 2 点）

> 「还有设置是否全部使用即时模式，取消最下面的保存模式？当前保存模式完全不清楚什么作用。」

同一设置页内，有的控件改完立即生效，有的要按底部全局「保存」，界面不告诉用户哪个是哪个、保存键到底管哪些。

## 根因

同一设置页两套提交语义并存且无标识：

- 分类规则 / 下载目录 / 代理走「编辑态 + 显式保存」：`SettingsPanel.tsx:353` `persistClassify`、`:416` `persistDownload`、`:458` `persistProxy`，由 `:553` `handleSave` 统一调；
- 主题等直接改 store 即时生效：`:234` 注释「直接即时生效，无需点保存」（`:126` `updateSettings` 入 store）。

全局「保存」「恢复默认」按钮只覆盖前者（`:112-113` 注释自述「作用于整个设置页（所有区块的编辑态）」），但用户无法从界面看出某控件属于哪套语义 ⇒ 「保存键管什么」不可见。形态是 M0 重整「只移动，不改读写」保留的历史双语义（BUG-298/M0-T07）。

## 复现

1. 改主题（即时生效）→ 不点保存 → 切走再回来仍在；
2. 改下载目录 → 不点保存 → 切走再回来丢失。

两者行为不同，界面无任何提示差异。

## 修复方向

二选一，需用户拍板：

- (a) 全部即时模式、取消底部保存键——与 BUG-234 修复后「下载目录保存即持久化到引擎」的形态一致；
- (b) 保留保存键，但给每个控件标注「即时生效 / 保存后生效」语义（哪套都不许静默）。

## 裁定记录（2026-10-20，用户裁定「根据实际选中其中一种方案」——以下按代码事实选型）

**结论：选 (b) 保留显式保存 + 语义标注。** 事实依据（全部代码取证，不按偏好）：

1. **即时模式只适合离散选择/开关，不适合文本域**。下载目录/代理地址/分类后缀/连接数都是文本或数字输入——即时持久化 = 每击键一次 daemon PUT：① 半成品值落盘（输到 `D:/Orig` 时切走，引擎拿到的是断路径）；② 请求风暴；③ 失去「改了不要」的反悔权（现在改一半不点保存 = 零副作用）。
2. **现已经是混合语义，且混合是合理的**：主题/开机启动/通知/语言走 `updateSettings` 入本地 store（本地偏好，无 daemon 往返）⇒ 即时；分类/目录/网卡/代理走 `persist*`（三个 daemon PUT 端点）+ 本地镜像 ⇒ 显式保存（`SettingsPanel.tsx:553-569` `handleSave`）。**「全即时」要把文本域也拖进 PUT，是负向改造。**
3. **用户看不清的只是口径，不是模态**：全局保存键实际覆盖「下载与存储 + 网络与代理」两个表单区，开关/主题不受它管——这句话现在界面上找不到。

**落地方向（实现弧执行，待用户批准）**：

- 保存键区加一行范围副标：「保存 目录 / 分类 / 网卡 / 代理」；主题、开机启动、通知等控件旁标「即时」；
- （增强，可选）表单区有未保存改动时保存键置 accent + 轻微 dirty 指示（不新增按钮）；
- 判据：每一个可改控件都能在界面自报「即时 / 保存后生效」；反向证伪：删掉任一标注 ⇒ FAIL。
