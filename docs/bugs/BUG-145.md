# BUG-145：媒体库不展示来源名 / 来源离线时无明路（PM 评估 S2/S3 落地）

- 状态: fixed
- 发现日期: 2026-09-23
- 模块: shell
- 严重程度: low

## 现象

媒体库内条目来自 TG 等来源时：（1）卡片/编辑页不展示「来源」标签，用户看不到这条内容从哪来；（2）TG 未连接时，「重新缓存」按钮是「点了必然报错」的活按钮，没有「来源离线」的明确提示与重连入口——把「一个来源不可用」渲染成隐性故障。

## 根因

媒体库组件此前直接依赖 `lib/tgmedia` 且未做来源标注。`mediaSources.ts`（BUG-098 落地，已随 `0c6b8f9` 入库）已把来源知识封死在适配器层，但媒体库消费侧未接上「来源标签」与「来源离线降级」两件事。

## 复现

媒体库卡片无「来源」行；TG 服务停掉后点「重新缓存」→ 报错而非置灰+提示。

## 修复

提交 `<hash>`（`fix(shell): surface source label and degrade re-cache when source offline (BUG-145)`）。

在 `mediaSources.ts` 既有适配器之上补齐消费侧：

- `sourceLabelKey(source)`：未知来源回退 `source.<source>`，i18n 新增 `source.tg/local/oss/s3/netdisk`。
- `MediaLibraryPanel`：批量探活可重缓存来源（`probeRecacheBackends`），来源离线时显示非阻断横幅 + 「重新连接」按钮；`recacheItem` 在来源不可用时先尝试 `ensureSourceBackend`，失败则如实告知、绝不静默。
- `MediaCard`：`recacheBlockedReason` prop 驱动按钮置灰 + title 原因；来源标签 `sourceLabelKey`。
- `ItemEditDialog`：信息区新增「来源：<label>」；清缓存改走 `clearCachedBytes`（库的动作，与来源解耦）。
- `ImportDialog`：`fmtSize` 统一从 `mediaSources` 取。

i18n 新增 `media.recacheUnavailable / sourceOfflineHint / reconnectSource / retryConnect / connecting / recacheQueued` 等。
