# BUG-368: 下载条目「图片无法选择」—— 两个选择面对图片的准入判据不同，缺一个可复现定位点

- 状态: open
- 发现日期: 2026-10-22
- 模块: shell
- 严重程度: mid

## 现象

用户 2026-10-22 复报（原话，标注「多次提出未解决」）：

> 「2. 下载条目图片无法选择多次提出未解决.」

## 已查实的部分（代码路径，非猜测）

下载域有**两个**条目选择面，准入判据不同：

| 选择面 | 文件 | 准入判据 | 图片是否可選 |
|---|---|---|---|
| 文件列表（Explorer） | `media/FileListView.tsx:132-141` | **无条件** —— 复选框常驻可见（BUG-040：禁纯 hover 显形） | **可選** |
| 入库明细 Sheet | `download/IngestDetailSheet.tsx:342,355,379` | `downloadable = !e.hasBytes`（**唯一**判据，无 kind 分支） | 取决于 `hasBytes` |

关键事实：`IngestDetailSheet` 的选择**不按 kind 分支**，只按 `hasBytes`。所以「图片无法选择」若发生在这一面，直接原因是该图片条目 `hasBytes = true`。

而 `hasBytes` 走 `probe_cached_bytes`（真盘探测，与分集视图同一套真值，BUG-132）。对图片条目它会为 true 的**唯一情形**是 BUG-049 明文保留的那条分支：「已落盘的历史图片走原 `cached_path` 分支保留本地文件」。也就是说：

- **普通 TG 图片**（`file_path = NULL`，设计态）⇒ `hasBytes = false` ⇒ **可選**；
- **历史已落盘图片**（有 `cached_path`）⇒ `hasBytes = true` ⇒ **无复选框、行不可点、无任何入口**。

后者落在 Sheet 里就是一行看得见、却完全无法操作的条目 —— 与用户描述的「无法选择」同形。

## 未修的原因（缺可复现定位点）

复报没有说清是**哪个面**（文件列表 / 入库明细 Sheet / TG 缓存管理面板 / 剧集挂图选择器），也没有说清是**哪种图片**（TG 浏览条目 / 历史落盘图片 / 集级挂图）。四个面的准入判据各不相同（已在上表列了两个），猜一个去改，改完大概率不是用户看到的那一个 —— 这正是 BUG-320「三次诉求只改样式不改结构」的成因。

已排除的可能：文件列表面对图片**没有**任何 kind 门槛（复选框恒渲染），所以「图片无法选择」不可能是这一面 —— 除非用户在说别的面。

## 需要用户提供（一条就够）

1. 哪个界面（下载域列表 / 点开某行的明细 / TG 缓存管理弹窗 / 剧集详情挂图）；
2. 那条图片长什么样（名字 / 有没有「缺字节」或「已入库」字样）；
3. 是「勾不了」还是「勾了没反应」。

## 验收证据

代码路径取证：`tauri-shell/src/components/media/FileListView.tsx:132`、`tauri-shell/src/domains/download/IngestDetailSheet.tsx:342`、`download-engine/crates/orig-tg/src/media.rs:1590`（`has_bytes` 注释：`probe_cached_bytes`，与分集/条目视图同一套真值）。
无 UI 侧复现记录 —— 复报未给出定位点，本条因此不开「已修」。

## 关联

- BUG-049：图片永不落盘的设计来源，以及「历史已落盘图片保留本地文件」这一条例外分支（本登记的可疑点）；
- BUG-040：复选框禁纯 hover 显形（文件列表面因此无 kind 门槛）；
- BUG-132：`has_bytes` 的真盘探测口径；
- BUG-320：判据与诉求方向相反 ⇒ 改多少次都不会对（本登记因此不猜着改）。
