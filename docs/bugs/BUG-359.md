# BUG-359: TG 图片气泡上压着一个半透明黑框「⬇ 缓存」按钮，与操作行的「缓存」是同一个动作的两个入口

- 状态: fixed
- 发现日期: 2026-10-21
- 模块: shell
- 严重程度: high

## 现象

用户 2026-10-21 复报（原话）：

> 「TG筛选下载逻辑混乱。详情内容无法选择，但是有黑框，不清楚用途。展示的内容也是混乱的。」

真栈实测（`tauri-shell/verify/_diag_round2.cjs` / `_diag_tg_geom.cjs`，1440×900）：

```
button[tg-photo-cache] "⬇ 缓存"  absolute  right-1.5 top-1.5  bg=black/65   ← 压在图片上的黑框
button "缓存"                    操作行内  h-32                  ← 同一个动作的第二个入口
```

同一条图片消息有**两个**缓存控件：一个是以 `bg-black/65` 半透明黑片形式压在图片
右上角的「⬇ 缓存」，一个是气泡操作行里的「缓存」。前者视觉上与图片内容抢同一块
像素、且形态是装饰性黑块，用户读不出它是按钮 —— 即「有黑框，不清楚用途」。

**取证过程中的两次自我纠错**（都记入纪律，防再犯）：

1. 首轮把 `elementFromPoint(按钮中心) !== 按钮` 一律判成「被盖住」。实测多数是
   **元素被滚动容器裁剪**（`rect.y` 为负、中心点落在容器可见区之外），
   `elementFromPoint` 对负坐标恒返回别的元素 ⇒ 假红。
2. 首轮把 Tailwind `disabled:pointer-events-none` 的禁用按钮也算进「不可交互」——
   禁用是正常态，不是缺陷。两类必须分开记录。

## 根因

`PhotoBlock` 用 `absolute right-1.5 top-1.5` 把缓存三态（⬇ / 转圈 / ✓）压在图片上，
与 `MessageBubble` 尾部的操作行按钮**重复表达同一个动作**。
（同族前科：BUG-328「卡片操作条绝对定位压在文字上」，本轮是列表气泡版本。）

## 修复

撤掉 `PhotoBlock` 的整块浮层（`tg-photo-cache` / `tg-photo-caching` / `tg-photo-cached`），
`PhotoBlock` 只保留预览；缓存入口收敛到气泡操作行**一处**（与视频同构）。
缓存三态不丢信息：操作行已有 Chip（已缓存 / 字节未就绪 / 失败）与按钮文案
（缓存中 / 排队中 / 重试缓存 / 缓存）承载同一组状态。
`PhotoBlock` 的 `item`/`onPreview` 之外三个 prop（`downloaded`/`downloading`/`onDownload`）
随之删除，唯一调用点同步改。
