# BUG-242: 门禁无作用域 —— 一次纯文档改动被迫跑全量缺陷门禁 6 分 39 秒（399 s），与改动零因果

- 状态: fixed
- 发现日期: 2026-10-09
- 模块: docs
- 严重程度: mid

## 现象

2026-10-09，一次**纯文档**改动（`docs/design/product-direction-and-ffmpeg-2026-10-09.md`、
`docs/review/product-direction-decisions-2026-10-09.md`、`docs/README.md` —— 共 3 个 `.md`、**0 行代码**）
在提交前跑了 `python scripts/check-bugs.py`，实测：

| 项 | 实测值 |
|---|---|
| 耗时 | **6 分 39 秒（399 s）** |
| 扫描对象 | **241** 条缺陷档（全量） |
| 本次改动触及的缺陷档 | **0** |
| 门禁结论与本次改动的因果关系 | **无** |

同一门禁在本仓的历史实测为 **231.8 s（3 分 54 秒）**；本次 **399 s**，慢 **71%**。
慢因不是校验逻辑，而是**逐条档案 spawn `git` 子进程**（`git cat-file -e` 与 `git check-ignore -q`，
`scripts/check-bugs.py` 的 `git_has_commit` / `git_ignores` 两个函数各被调数百次）。

用户（产品负责人）裁定：

> 「为什么就改了份文档还需要各种代码测试各种逻辑测试？完全脱离修改范围了，这套逻辑有严重问题啊，
> 大量浪费时间，也是完全错误逻辑。」

## 根因

四条，**缺一条都不会发生**：

| # | 根因 | 证据 |
|---|---|---|
| **R1** | **门禁脚本无作用域参数** —— 任何调用都是全量扫描 241 条档案 | `scripts/check-bugs.py` 改动前只认 `--quiet`（用法行与 `QUIET` 定义） |
| **R2** | **规范与实测不符** —— `AGENTS.md` §7 声明 check-bugs 为 pre-commit「**必需**」，但实装钩子只跑污染门禁 | `framework/.git/modules/orig-hub/hooks/pre-commit` 正文只有 `exec sh ".../scripts/check-pollution.sh"`；`git config core.hooksPath` 为空（exit 1） |
| **R3** | **为 R2 打的补丁习惯没有范围限定词** —— 「改了缺陷档要跑 check-bugs」在实践中退化成「提交前跑 check-bugs」 | 本次即照跑（改动集内 0 个 `docs/bugs/` 文件） |
| **R4** | **免检白名单只写在文档门禁那一节** —— `docs/rules/doc-first.md` §3.2 早已写「纯文档改动（`docs/**`）免检」，但它只覆盖**文档门禁**，没覆盖缺陷/代码门禁；本仓 7 个门禁**没有一张「改了什么 → 跑哪个」对照表** | `AGENTS.md` §7 只有「门禁 × 脚本 × 覆盖 × 钩子 × CI」，无「触发条件」列 |

> **R1 + R4 合起来就是那句「完全脱离修改范围」**：没有对照表（R4）⇒ 只能靠记忆跑；
> 工具又不能按范围裁（R1）⇒ 一次误跑就是 6 分 39 秒。

## 复现

1. 只改 `docs/design/` 或 `docs/review/` 下的 `.md`（**不碰** `docs/bugs/`）；
2. 提交前跑 `python scripts/check-bugs.py`；
3. 观察：耗时约 399 s、扫描 241 条档案、结论与本次改动无关。

耗时可直接量：`time python scripts/check-bugs.py`。

## 修复

三处，**工具侧为主**（规则靠人记，工具让误跑不花钱）：

1. **工具（`scripts/check-bugs.py`）**：新增 `--changed` / `--base <ref>` ——
   变更集（默认 `git diff --cached --name-only`；`--base` 取 `<ref>...HEAD`）
   不含 `docs/bugs/**` 且不含本脚本自身时，**直接 SKIP、退出 0**。
   作用域常量集中在脚本顶部 `SCOPE_PREFIXES` / `SCOPE_FILES`。
   **不带参数时行为完全不变**（仍是全量），CI 与人工全量核对继续可用；取不到变更清单时**退回全量**，不静默跳过。
2. **规范（新增 `docs/rules/gate-scope.md`）**：「改了什么 → 跑哪个门禁」对照表 +
   免检白名单（与 `doc-first.md` §3.2 **逐字对齐**，不另立一套）+ 反向证伪 G1–G4 +
   「不许用『保险起见』作为跑门禁的理由」的纪律条款。
3. **规范（`AGENTS.md` §7）**：补「门禁按变更范围选择」条款；并**订正**该表「本地钩子」列
   写的是「应有」行为而非实测 —— 在钩子修好前，**只有** `docs/bugs/**`（→ check-bugs）与
   含决策块的 `docs/**`（→ check-decisions）必须手工补跑，**其余改动不必**。

## 验收证据

**判据（可跨机器复核）**：

1. `scripts/check-bugs.py` 内可 grep 到 `--changed`、`--base`、`SCOPE_PREFIXES`、`SCOPE_FILES` 四处；
2. 暂存一个纯 `docs/design/*.md` 后执行 `python scripts/check-bugs.py --changed` →
   打印 `SKIP`、退出 0、**不进入全量扫描**（实测约 **2.9 s**，对比全量 399 s）（用例 G1）；
3. 暂存一个 `docs/bugs/*.md` 后执行同一命令 → **不得 SKIP**，必须真的进入全量扫描（用例 G2，
   这是唯一能证伪「永远 SKIP 的假门禁」的用例）；
4. **不带参数**执行 → 仍是全量扫描（用例 G3，回归：新增开关不得改变默认行为）；
5. 暂存集为空 → `SKIP` 且退出 0（不是 FAIL，用例 G4）；
6. `docs/rules/gate-scope.md` 存在且 §1 对照表可查；`AGENTS.md` §7 含「门禁按变更范围选择」条款。

**入库路径**：`scripts/check-bugs.py`、`docs/rules/gate-scope.md`、`AGENTS.md` §7。
