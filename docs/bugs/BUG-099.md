# BUG-099: TG 消息流内容 `#标签` 不高亮、不支持频道内筛选

- 状态: open
- 发现日期: 2026-09-21
- 模块: engine+shell
- 严重程度: mid

> 立项方式：项目所有者提出「内容 `#标签` 需要高亮，且支持频道内筛选；`#《xxx》` 也要能正确识别其中的 xxx，`《》` 是特殊化显示标志」。
> 本条是**评估档**（未实施），结论见 `docs/design/tg-ux-assessment-summary.md`。
> 关联：`docs/design/tg-ux-requirements.md`（产品）、`docs/design/tg-ux-tech-assessment.md`（技术）。

## 现象

1. caption 纯文本渲染，**零解析、零高亮**：单条消息 `TgPanel.tsx:1681-1684`、图片组 `:1901-1904`、
   搜索结果 `:1366`，都是直接 `{m.caption}`。
2. 「按标签筛选」完全不存在。

## 根因（关键：不是"没有解析器"，而是"解析器没接到消息流上"）

**`extract_hash_tags()` 早已存在且规则完整** —— `media.rs:2682`：

- 括号型标签：`PAIRS`（`:2685`）含 `《》（）()[]`，须**成对闭合**、不跨行；未闭合则退回裸标签规则（`:2713-2736`）。
- 裸标签：Unicode 字母数字 + `_` + `INNER = "-._·"`（`:2687`），尾部 INNER 字符剥除。
- 大小写不敏感去重、保留首次写法（`:2761`）；单标签 > `MAX_TAG_CHARS = 32`（`:2683`）丢弃。
- 30+ 条单测，含实测样例 `#《异世界男妓-瓦尔哈拉神枪馆》 EP-2`（`:3060`）。
- 注释（`:2675-2678`）已写明取舍：`#《…》` 在 Telegram 里**不成链接**，但中文频道普遍用它标剧名，
  不扩展则这类标题"一个都提取不到"。**所有者要求的「《》是特殊化显示标志」与现有实现一致。**

**但全仓唯一真实调用点是 `media.rs:2269`**（`collect_hash_tags`，`:2248`），走「加入媒体库」路径，
从 `media_message.caption` 读（`:2262`）。→ **未入库 / 未缓存的消息一条标签都没有**，
消息流里大部分内容不会高亮。这才是本条的真缺口。

## 评估结论

### 高亮：后端派生分段，前端只渲染（单一真源）

- 把 `extract_hash_tags` 重构为带偏移的 `scan_tags`，后端派生 `caption_segments` 一并返回，
  前端只负责按段渲染。
- **不在前端另写一份正则**。理由：TS 与 Rust 两份规则必然漂移，本项目已因此付过两次学费
  （BUG-069 分集标题 vs 条目标题、BUG-087 连接态三处）。
- 代价：需改 Rust 解析器签名与其 30+ 条单测。

### 筛选：通道已存在，只需加精筛

- `listTgMonitorMessages` **已支持 `q` 参数**（`api/tg.ts:150`、`:158`），后端 `store.search_messages`
  （`routes.rs:1475-1483`、`store.rs:513-554`）已可用且 `%`/`_` 已转义 —— **前端只是没传**。
- 但 `q` 是 **caption 子串**匹配：点 `#A` 会误命中 `#AB` 与正文里的 `A`，标签筛选一旦不准即失去可信度。
- 故推荐新增 `?tag=`：`caption LIKE` 粗筛取 `limit*K` 候选 → Rust 侧 `extract_hash_tags` 精筛 → 截断。
  **零 schema 变更、零回填**；代价是 `hasMore` 保守（而当前 `hasMore` 本就是保守估计，`store.rs:1492`）。
- **不推荐**本期新建 `media_message_tag` 关联表：唯一增量是「精确分页」，却要背 schema 迁移 + 全量回填
  + 与媒体库 `media_tag` 划边界的债（AGENTS.md §5 迁移铁律）。

### 落点修正（2026-09-21）：`?tag=` 应挂 `/api/tg/stored`，不是 `/monitor/messages`

所有者指出「**要考虑到监控的多频道筛选，不能只顾频道内筛选**」—— 据此复核三个端点后发现
原先锚定的 `/monitor/messages` 是**单频道**的，落点选错了：

| 端点 | 频道范围 | 分页 | 含未缓存 | 已有 `q` |
|---|---|---|---|---|
| `/api/tg/monitor/messages` | **单频道**（`channelId` 必填） | `beforeId` ✓ | ✓ | ✓ |
| `/api/tg/monitor/search` | 全部监控频道 | ✗（`limit=60` 平铺） | ✓ | ✓ |
| **`/api/tg/stored`** | **全部监控频道** | **`beforeId` ✓** | **✓** | **✓** |

`/api/tg/stored`（`routes.rs:1567-1591`，查询结构 `StoredMsgQuery` `:1545-1565`）注释明写
「聚合全部监控频道已入库媒体（**含未缓存行**）」，是唯一同时满足「跨频道 + 有分页 + 含未缓存」的现成通路。
其 `StoredQuery` 目前**无频道过滤字段**（只有 `downloaded_only` / `media_type` / `q` / `before_id` / `limit`）。

**修正后的推荐**：`?tag=` 挂在 `/api/tg/stored` 上，并新增**可选** `channelIds` 参数。
→ 频道内筛选与跨频道筛选共用同一套代码：传 1 个 id = 频道内，不传 = 全部监控频道，
传多个 = 任意频道子集。**零 schema 迁移**。

**选型判据（按数据量）**：消息量数千级、频道几十个以内 → `?tag=` 足够；
若单频道上万条且要求精确翻到筛选结果最后一页 → 才值得背落表的债。
**实施前先统计 `media_message` 行数再定。**

`?tag=` 方案的唯一真代价：`hasMore`（`items.len() >= limit`，`routes.rs:1589`）会偏保守 ——
粗筛候选被精筛过滤后一页可能凑不满，提前判定「没有更多」。缓解：取 `limit*K` 候选（K=4~8）。

### 建议边界：不复用媒体库 `media_tag`

消息流标签 = **caption 的只读派生投影**（不落库、不可编辑、不经 `media_tag`）；
媒体库标签 = 用户可编辑的持久资产。两边语义清晰，避免重演 BUG-069 双真源漂移。
代价：同一内容在两处标签可能不一致（前者现场解析、后者入库快照），需文案说明。

## 已拍板（2026-09-21 所有者拍定）

- **A-1③ `#《A》《B`》：维持现状（只产出一个标签）**，后续真出现「一个 `#` 带两对书名号」的实际样本再修。
  所有者原话：「暂时只看到一个，后续有 2 个再修复」→ 本期**不改 Rust 解析器**。
- **作用域（跨需求）**：标签筛选**必须同时支持跨频道与频道内**，不能只做频道内。
  所有者原话：「要考虑到监控的多频道筛选，不能只顾频道内筛选」→ 落点随之修正（见上文）。
- **搜索框落位（属 BUG-100）**：确认为**顶部上下文栏那一行居中** —— 该行左槽显示 `nav.tg` = "Telegram"
  （`zh-CN.json:7`），即方案 A。所有者原话：「我说的是 TG 的 Telegram 这个文字标题 居中」。

## 待拍板（阻塞开工）

- **A-1 `#《xxx》` 语法**（③ 已拍板维持现状，① ② ④ ⑤ 仍待定）：
  ① `#《A》` 与 `#A` 是否同一标签（建议：是，只差呈现）；
  ② 《》内是否允许空格/多词（建议：允许，整段为名，仅 trim）；
  ③ **`#《A》《B》`（一个 `#` 跟两对书名号）是否改为产出两个标签** —— **现状只产出 A，B 被丢**
     （`:2713-2736`：括号型只试探一组，消费完游标后 `prev='》'`，后面的 `《B》` 前无 `#`，压根不进标签分支）；
     `#《甲》#《乙》` 各带 `#` 时正常（单测 `:3072` 只覆盖这一种）。**所有者只举了单数样例，这是最易做错的点**；
  ④ 缺右《》→ 维持「丢弃并退回裸规则」（建议，兜底会让半个标题变标签）；
  ⑤ 括号型上限 32 → 64（建议，中文剧名 32 字偏紧），裸标签维持 32。
- **A-2** 筛选路径与作用域：
  - 路径：`?tag=` 挂 `/api/tg/stored` + 可选 `channelIds`（推荐，零迁移）
    vs 新建 `media_message_tag` 关联表（精确分页，但需迁移 + 全量回填 + 与 `media_tag` 划边界）。
    判据 = 数据量（数千级用前者，上万条且需精确翻到末页才用后者），**实施前先统计 `media_message` 行数**。
  - 作用域：已定「跨频道 + 频道内都要」，待定的是**是否支持勾选任意频道子集**（即要不要加 `channelIds`）。
  - 与全局搜索框是否互斥（激活筛选时清空搜索词）—— 仍未定。

## 验收要点（草案）

- 未入库（未缓存）消息的 caption 同样高亮出标签 —— 这是本条需求的灵魂，不能只覆盖已缓存消息。
- `#《A》《B》` 用例必须在验收里锁死（若 A-1③ 拍板为"产出两个"）。
- 点标签后，同频道内只留含该标签的消息；点 `#A` 不得捞出 `#AB` 或正文含 `A` 的消息。
