# BUG-071: 默认下载目录在 Windows 下解析出 `~`/依赖 `$HOME`，路径不可靠

- 状态: fixed
- 发现日期: 2026-09-20
- 模块: engine
- 严重程度: mid

## 现象

设置页「默认下载目录」在 Windows 上落盘路径不对：
- 表现一是路径里出现字面量 `~`（Windows 不展开 `~`），最终在**当前工作目录**下建出 `<CWD>/~/Downloads` 之类的畸形目录；
- 表现二是默认目录依赖 `$HOME` 优先探测，在原生 Windows 进程里 `$HOME` 往往不存在或被 MSYS/WSL 环境串改成 Unix 风格路径，导致默认目录指向一个 Windows 资源管理器里打不开的位置。

用户原话：「设置页面"默认下载目录"的路径问题，windows下不应该是~」。

## 根因

`download-engine/crates/orig-daemon/src/config.rs`：

- `default_download_dir()`（config.rs:431-439）按 `HOME` → `USERPROFILE` → `.` 顺序探测环境变量再 `join("Downloads")`。
  - `$HOME` 在 config.rs:432 被**优先**读取；原生 Windows 进程通常没有 `$HOME`（Windows 用的是 `USERPROFILE`），但若被 MSYS/Git Bash 环境串入，`$HOME` 可能是 `/c/Users/xxx` 等 Unix 风格路径，拼出来的目录对 Windows 不合法。
  - 仅用环境变量，**没有走 Windows 的 Downloads 已知文件夹 API**（`SHGetKnownFolderPath(FOLDERID_Downloads)`），所以即使用 `USERPROFILE` 也忽略用户把 Downloads 重定向到其它盘（很常见）的情况。
- `resolve_output` / `resolve_output_classified`（config.rs:443-475）对传入的 `req_dir` / `download_dir` 直接用 `PathBuf::from(...)`，**不会展开 `~`**。Rust 的 `PathBuf::from("~/Downloads")` 在 Windows 把 `~` 当成普通字符，于是 `<CWD>/~/Downloads` 被当成真实目录创建。
- 文档与注释把默认目录写成 `~/Downloads`（config.rs:8、download-engine/README.md:46），强化了「`~` 能展开」的错误心智模型。

## 复现

1. 在 Windows 上不配置 `download_dir`，启动 daemon；或把 `download-engine.toml` 的 `download_dir` 写成 `~/Downloads`；
2. 触发一次下载 / 看 `GET /api/...`（routes.rs:454 返回 `download_dir`；orig-tg `effective_download_dir` 在 routes.rs:629）；
3. 观察落盘位置：要么是 `<CWD>/~/Downloads`，要么指向一个资源管理器打不开的路径。

## 修复（已实施）

- 用 `dirs::download_dir()`（跨平台：Windows 走 `SHGetKnownFolderPath(FOLDERID_Downloads)`、macOS/Linux 走标准目录）替换手写的 `default_download_dir()`，杜绝 `$HOME` 串味与重定向失效。
- 对**配置/请求**里出现的 `download_dir` / `req_dir`，若以 `~` 开头，显式按 home 目录展开后再 `PathBuf::from`，绝不让字面 `~` 进文件系统（可在 `resolve_output` / `resolve_output_classified` 入口统一处理）。
- 同步修正 config.rs:8 与 README.md:46 的 `~/Downloads` 措辞，避免后续维护者再次误用。
