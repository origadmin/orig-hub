# BUG-342: 标题入库未清洗特殊符号与书名号——《》、emoji、# 标签原样进标题

- 状态: fixed
- 发现日期: 2026-10-20
- 模块: engine
- 严重程度: high

## 现象（用户原话，2026-10-20）

> 「完全错误的标题入库逻辑. 下载中可以看到特殊符号,书括号这些异常字符,都应该过滤掉.」

## 根因

标题链没有任何一级做字符清洗，原始 caption 直达用户可见标题：

1. **下载列表标题** = `cache_task_titles`（`routes.rs:1586`，BUG-232 v2 口径）
   原样取 `media_message.caption`；
2. **活数据实证**（2026-10-20 22:5x 探针真实栈）：
   - `GET :19786/api/activity?scope=all` → `"name":"《琼明神女录》第8集 连载中 全系列完整版"`；
   - `GET :19787/api/tg/cache/tasks/all` → `"title":"🌟🔥🔥🔥《妈妈陪儿子高考》EP10 原档观享 连载中 тн…"`；
   - 书名号、emoji、特殊符号（含西里尔混淆字符 `тн`）全部进标题；
3. **剧名链** `first_caption → split_caption → normalized_series_name`：
   BUG-152 只剥集号区段，且单测明确要求 `#《某剧名》` **原样保留**
   （`routes.rs:7411`）⇒ `#`、`《》`、emoji 前缀照样进剧名；
4. **前端** `displayTitle.ts`（BUG-251）只在**渲染层**决定包不包《》，
   不清洗标题自身——引擎层与渲染层两层都没洗。

## 复现

1. 任意带 `《》` / emoji / `#标签` caption 的频道内容入队入库；
2. 下载域任务列表、媒体库剧集名可见上述字符原样（见上方活数据样本）。

## 修复（已实施）

1. **唯一标题清洗函数** `clean_title`（`download-engine/crates/orig-tg/src/routes.rs:1681`，
   确定性白名单，不逐 case 打补丁）：
   - ① URL 删除（`://` 处截断保留前缀词；`t.me/…` 直连词整词删）；
   - ② 字符白名单：字母数字（含 CJK/西里尔）+ `-.,!?'"&+()` + `，。！？、；：·`；
     其余全剥——emoji、变体选择符、`《》【】「」『』`（用户点名的书括号）、`…`、`*`、`_`、
     全角括号、NBSP；
   - ③ 空白折叠单空格 + trim；
   - `#标签` **只删 `#` 字符、保留文字**（这批频道用 hashtag 做剧名标注，整词删会把
     标题本身删没——`#《快门沦陷》` ⇒ `快门沦陷`）；
   - 全符号标题清后为空 = 如实表达「没有标题」（BUG-154 纪律），由调用方回退链接手。
2. **串接点**（同一函数，禁止各写一套）：`cache_task_title`（下载面板行标题，
   `routes.rs:1621`——caption 优先、清洗后为空回落 file_name，BUG-220）与媒体库
   条目标题登记处（`routes.rs:1418-1420`）。
3. **不清洗 `normalized_series_name`**：那是剧集**身份键**的一部分
   （`episodic_group_key = tg:named:{chat}:{name}`），清洗会让存量剧集键失配 ⇒
   同一部剧裂成两部。显示侧清洗只发生在不参与身份的标题落点。
