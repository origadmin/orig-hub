# BUG-199 播放卡顿：本地播放器流畅而 WEB 卡死、HLS 流畅而当前不流畅 —— 根因是环回口上的全局投递节流

- **状态**: fixed
- **发现日期**: 2026-09-30
- **模块**: engine
- **严重程度**: high

关联用户反馈「播放卡顿问题越来越严重，我觉得是核心处理逻辑问题」并给出两点判据：
① 为什么视频播放器可以流畅播放，而通过 WEB 就卡死了；② 为什么 hls 播放可以流畅，但是当前就不行。

## 现象

用户在剧集内页 / 媒体库点播本地已缓存视频时，WEB（`<video>` 经 HTTP 拉取）卡顿乃至「卡死」；
而同一个文件用本地播放器打开流畅。用户据此指出这是「核心处理逻辑问题」，不是偶发抖动。

## 根因

播放主路径：`mediaItemUrl(id)`（`tauri-shell/src/api/media.ts:214`）→ `GET /api/media/items/:id/raw`
→ `media_item_raw`（`routes.rs:3061`）→ `serve_local_file`（`routes.rs:3183`）。
已排除「整文件读进内存」这一猜测：`serve_local_file` 支持 Range / 206 / ETag / Last-Modified，按 1 MiB 分块流式发送。

真正的差异是**全局投递节流**：

- `delivery_bps`（`routes.rs:3156`）返回稳态速率 = 码率 × `DELIVERY_BUDGET_FACTOR`（6.0，下限 1 MiB/s），
  `duration` 未知则 16 MiB/s；`delivery_due_secs`（`:3132`）在 `DELIVERY_BURST_SECS`（4.0 秒）突发信用之后
  按速率曲线 pacing，每发 1 MiB 块即 `sleep` 补足差额。
- 该节流为 BUG-033 而加：Chromium 读够 buffer 即 abort 连接、另起请求重取同一区域，
  实测 2x 播放 10s 内 137 请求 / 792 MiB（冗余 63x），唯一有效的杠杆是发送速率
  （限到 6 MiB/s 后冗余 29x → 1.97x）。该结论本身成立，勿仅凭直觉删除。

**但它被用在了错误的场景**：orig-tg 由 `config.bind` 固定为 `127.0.0.1`（`config.rs:14-38`，注释「仅本机」），
投递走**环回口**——带宽免费，冗余重取命中页缓存本就无害。节流却把**合法投递也一起放慢**，
且突发信用每个请求重置、每次拖进度都要重付一次 TTFB，反而诱发 Chromium 的
「连接太慢 → 中断重取」循环。于是：

- ① 本地播放器直读磁盘，不经过这一层 ⇒ 流畅；WEB 必经被 pacing 的 HTTP 层 ⇒ 卡顿。
- ② HLS 用大量小 `.ts` 分片顺序拉取、几乎不做大文件随机 Range 重取 ⇒ 不触发该循环 ⇒ 流畅；
  当前实现是大 mp4 + `bytes=S-` 返回 32 MiB 块（`OPEN_CHUNK`）+ 逐请求 pacing ⇒ 触发。

## 修复

节流改为**只在非环回场景生效**（BUG-033 的结论与其全部代码路径都保留）：

1. `routes.rs` 增加 `OnceLock` 环回开关与 `configure_delivery_loopback_only`（必须是 `pub`：
   `main.rs` 是**独立的二进制 crate**，`pub(crate)` 对它不可见）；`main.rs` 在 `Config::load()`
   之后按 `config.bind` 解析 `IpAddr::is_loopback()` 写入。
2. `delivery_bps`：环回 → 返回 `0.0`（不限速）；非环回 → 仍走 `bitrate × 6` 抑风暴。
3. `ORIG_TG_DELIVERY_BPS` 非 0 时**无视环回判定**直接启用，供真实远端场景手动开启。
4. `delivery_due_secs` / `DELIVERY_BURST_SECS` 的 pacing 与突发信用代码整体保留。
5. 测试：`serve_local_file_still_throttles` 改为显式设 `ORIG_TG_DELIVERY_BPS=1048576`
   （守住节流路径本身仍生效）；新增 `serve_local_file_unthrottled_by_default`（守住环回默认不限速）。

## 关联

- BUG-033（抑风暴节流的原始实测结论）：保留为**非环回**分支与环境变量开关，未被删除。
- `config.bind` 默认 `127.0.0.1` 是本修复成立的前提；若将来默认改成 `0.0.0.0`，节流会自动恢复。
