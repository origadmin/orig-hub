# BUG-079: 缓存字节面板按频道选择凌乱 +「预计释放」显示全量而非选中内容

- 状态: fixed
- 发现日期: 2026-09-20
- 模块: shell
- 严重程度: mid

## 现象

缓存管理的「缓存字节」页签：

1. 频道以一排 chip 平铺，选中态靠边框+底色区分，条目多时**换行成一坨、看着乱**，
   难以分辨哪些已选；chip 还带 `max-w-[16rem] truncate`，频道名被截成 `...`，
   同名前缀的频道无法区分。
2. 「预计释放」显示的是**清理预览的全量**（`preview.total`），而不是**当前选中范围**
   计算出来的量——用户勾选了 2 个频道，看到的仍是全库总量，"预计"名不副实。

用户原话：「缓存管理的缓存字节，这里按频道选定看着有点乱，预计释放功能也不对，应该是
真的我要清理（选中内容）计算出的，现在是直接显示全部。」

## 根因

`tauri-shell/src/components/CacheBytesPanel.tsx`：

1. 频道 chip 用 `flex-wrap` 平铺在一个容器里（约 275-290 行），无分组/无滚动容器；
   `max-w-[16rem] truncate` 把长频道名截断，截断后多个频道显示成同一串前缀。
2. 「预计释放」直接读 `preview.total.bytes / preview.total.count`（约 184-190 行），
   `preview` 来自 `GET /api/cache/clear/preview`，是**全局**预览，与 `selected` 集合无关
   ——选中集合只被用于实际清理，没参与预览计算。

## 复现

1. 缓存管理 → 缓存字节；
2. 只看 chip 区域，长频道名被 `...` 截断、换行密集；
3. 只勾 1 个小频道 → 顶部「预计释放」仍显示全库大小与总条数。

## 修复

- **选中量独立成一行即时反馈**：新增 `tg.bytesSelected`（"将释放（选中）{size} · {n} 条"）
  chip，仅在 `selCountNow > 0` 时渲染，`data-testid="cache-bytes-selected-preview"`；
  数值由**选中集合**对 `preview.items` 求和得到，不再是全量。
- **区分「全量预览」与「选中将要释放」**：`tg.bytesPreview`（全量）保留作为上限参考，
  选中后并列显示选中量，语义不再混淆。
- **频道 chip 可读性**：`max-w-[16rem] truncate` → `max-w-[20rem] whitespace-nowrap`，
  频道名不再被省略号截断（完整名称可辨），超宽由容器换行承载而非文字截断。

- **频道 chip 半选态**：整频道只有「全选/全不选」两档底色时，勾了其中几条的频道与一条
  没勾的频道**长得一样**——「哪些已选」不可辨。新增 `part` 中间态（半透明 accent 底色 +
  `data-selected="partial"`），并在 `title` 里给出「已勾 n/共 N」的精确值。

验收锚点：选中 N 个频道后 `cache-bytes-selected-preview` 的数值 = 这些频道条目字节之和，
且 ≠ `cache-bytes-preview`（全量）；频道 chip 文本不含 `…` 截断；半选频道
`data-selected="partial"`。

## 验收证据

| 层 | 证据（入库，可跨机器复跑） | 结果 |
|---|---|---|
| 改动文件 | `tauri-shell/src/components/CacheBytesPanel.tsx`（新增 `selCountNow` / `selBytesNow` 的 `useMemo`；chip 半选态 `data-selected`）、`tauri-shell/src/i18n/locales/zh-CN.json` 与 `en-US.json`（`tg.bytesSelected`） | 入库可核 |
| 类型检查 | `npx tsc --noEmit`（`tauri-shell/`） | 干净 —— 本 BUG 的编译期错误正是 `selCountNow` / `selBytesNow` 未定义（TS2304），现已消除 |
| 语义隔离 | `selCountNow/selBytesNow`（**当前勾选**的即时量）与 `pendingStat`（**确认条里待执行**的量）是两个独立 `useMemo`，互不复用 | 已核对（两处各自 `useMemo`，依赖分别为 `[items, sel]` 与 `[pending, preview, items]`） |
| 静态守卫 | 编辑态/只读态之外，chip 不再含 `truncate`；`max-w-[20rem] whitespace-nowrap` | 已核对（grep 确认 chip 类名无 `truncate`） |
