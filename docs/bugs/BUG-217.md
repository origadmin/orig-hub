# BUG-217 播放器控件层隐藏态仍参与合成 —— `showControls=false` 时整层 `opacity-0` 控件把 2x/4x 上屏节拍拉到裸 `<video>` 以下

- 状态: fixed
- 发现日期: 2026-10-08
- 模块: shell
- 严重程度: mid

## 现象

应用内播放器（`VideoPlayer`）的上屏节拍弱于同页面的裸 `<video>`（媒体库条目 472 =
HEVC 1280×720 60fps、同渲染尺寸 1440×807、都破缓存、同一 headful 会话）。BUG-216 已排除
「`timeupdate` 整树重渲染」；本档把差异锁定到**控件层隐藏态**。

`tauri-shell/verify/_probe_render_churn.cjs`（10s 采样，含播放开始后约 3s 的控件可见期，
3 轮中位）：

| 模式 | 倍速 | presented | gapP95 | gt25 | mutations/s |
|---|---|---|---|---|---|
| app（修前） | 2x | 56.3 | 33.2 | 37 | 3.9 |
| app（修后） | 2x | 57.0 | 19.4 | 26 | 4.0 |
| app（修前） | 4x | 54.5 | 33.3 | 48 | 5.6 |
| app（修后） | 4x | 56.1 | 33.0 | 36 | 5.7 |

运行时 DOM 实验（`probe_compositing.cjs`，同条件 3 轮中位）把差异锁定到控件层本身：

| 条件 | 2x presented/p95/gt25 | 4x presented/p95/gt25 |
|---|---|---|
| C 裸 video | 59.2/17.1/6 | 58.4/17.2/8 |
| B1 app 式祖先链 + 空 `opacity:0` 覆盖层 | 59.4/17.2/5 | 58.8/17.2/6 |
| B7 祖先链 + 忠实 alpha 渐变覆盖层 | 59.2/17.1/6 | 59.0/17.3/9 |
| B3 app 原样 | 55.4/33.1/43 | 54.3/33.2/52 |
| B10 只隐藏按钮行 | 58.1/17.5/18 | 58.2/17.3/13 |
| B12 整层控件始终隐藏 | 59.4/17.1/6 | 58.9/17.3/10 |

⇒ 覆盖层 / 合成上下文（B1 / B7）**不是**真因；**控件层（`role="toolbar"`，`absolute inset-0`）
在 `opacity-0` 时仍参与布局 + 绘制 + 合成**才是，其中按钮行是主成本（B10）。把整层控件移出
（B12）后 app 回到裸 `<video>` 水平（2x 6 / 4x 10）。

## 根因

`tauri-shell/src/components/media/VideoPlayer.tsx` 的控件层（`role="toolbar"`）用
`absolute inset-0` 铺满视频区，隐藏时只切 `opacity-0`（原 `:934-935`）：

```
className={cn(
  'pointer-events-none absolute inset-0 z-10 flex flex-col justify-end transition-opacity duration-300',
  showControls || !isPlaying ? 'opacity-100' : 'opacity-0',
)}
```

`opacity:0` 的元素**仍参与布局与绘制**（只是被以 0 透明度合成）：整层（渐变遮罩 + 进度条 +
按钮行 + 8 项倍速菜单等）仍在渲染树里，并被合成在 `<video>` 之上，使 `<video>` 失去直通
（overlay）呈现路径。实测只做 `opacity:0` 且去掉过渡（B6）仅部分改善（2x 57.0/24.3/28），
而把整层移出（B12）回到 59.4/17.1/6 ⇒ 代价来自「元素仍在布局 / 绘制 / 合成」，与透明度无关。

## 复现

```sh
cd tauri-shell
node verify/_probe_render_churn.cjs                  # 窗口①：前后对照（含约 3s 控件可见期）
EXPECT=display-none ROUNDS=3 RATES=2,4 node verify/_probe_render_churn_steady.cjs   # 窗口②：稳态（修后）
EXPECT=opacity-0    ROUNDS=3 RATES=2,4 node verify/_probe_render_churn_steady.cjs   # 窗口②：稳态（修前，先回退 VideoPlayer.tsx）
CONDS=B3,B12 ROUNDS=3 SAMPLE_MS=10000 node <temp>/probe_compositing.cjs   # 隔离「控件隐藏态」
```

`probe_compositing.cjs` 用 `verify/lib/cdp.cjs` 起一个 headful 浏览器，在同一 page 上按条件
注入 / 改动 DOM 后各跑 3 轮（2x / 4x），输出 presented / gapP50/p95/max / gt25 / mutations/s；
`B12` 用 `[role="toolbar"]{display:none!important}` 把控件层整段移出。

## 修复

`showControls=false` 时让控件层**真正不参与布局 / 绘制 / 合成**，同时保住无障碍契约：

1. `VideoPlayer.tsx` 新增 `chromeMounted` / `chromeShown` 两态：隐藏时先让 `opacity` 过渡到 0，
   **淡出结束**（`CONTROLS_FADE_MS=300`，与 `duration-300` 对齐）后才把控件层整层移出
   （`!chromeMounted && 'hidden'`）；显示时先挂载、下一帧再置 `opacity-1`，保证 300ms 淡入。
2. 隐藏态渲染一个 **sr-only 进度条**（`PlayerProgressBar compact`）：仍带 `role="slider"` /
   `aria-valuemin/valuemax/valuenow` / `aria-label`，仍由 `write()` 直写更新 —— 无障碍树仍可达，
   但不参与可见的布局 / 绘制 / 合成。`write()` 放宽为「只要 slider 在就更新 aria」
   （compact 态无 `played` / `buffered`）。
3. 装饰性 chrome（渐变遮罩、按钮行、时间文案）随整层一起 `display:none`。
4. 未触碰拖拽 / seek（BUG-165 语义）、倍速、播放暂停、`useDecodeHealth` 的调用与判据。

**判据**：B 的 `gapP95` 是否收敛到 C（±5ms）。
- 2x：A−C=0.5、B−C=2.0 ⇒ 收敛（但 2x 本就无可见期代价，A≈C）。
- 4x：A−C=**15.2**、B−C=**12.1** ⇒ **不收敛**。
⇒ **假设不成立**：给控件层加 `transform:translateZ(0)` 未能把可见期（4x）拉回 C 水平（B 仅比 A 好 3.1ms，远不够）。
各臂断言逐轮打印并校验：A `display:flex`（可见）、B `display:flex, transform:matrix(1,0,0,1,0,0)`（层提升已生效）、
C `display:none`（全程隐藏）；任一不符即 `exit 2`。

**控件层昂贵绘制属性核查**：`VideoPlayer.tsx` 中 `backdrop-blur-sm/md` 出现在**居中播放键 / 缓冲 / 错误文案 / 信息卡 /
倍速菜单**（均非「播放中常显的控件层」），`shadow-lg/xl/2xl` 在进度条拇指 / 信息卡 / 倍速菜单 / CTA，`drop-shadow` 在信息卡标题；
**常显控件层内**只有进度条拇指的 `shadow-lg` 与一条纯 alpha 渐变（B7 已证静态渐变不伤视频）。⇒ 可见期代价并非由某个昂贵滤镜直接造成。

**结论 / 处置**：假设不成立 ⇒ 按约定**不改产品代码**，`VideoPlayer.tsx` 保持 `a39f370` 字节；可见期（窗口①）代价的成因仍未定，
留待后续（或并入间歇冻结 / 环境线）。本实验不涉及任何产品行为变化。
