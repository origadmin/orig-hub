# BUG-263: 内容编辑弹窗整体未接 i18n —— 整窗硬编码中文，同窗中英混排

- 状态: open
- 发现日期: 2026-10-10
- 模块: shell
- 严重程度: low
- 登记: BUG-258 实现 worker 顺带发现、按文件归属约束停手未修（`i18n/locales/*.json` 当时归并行 worker 独占）。

## 现象

`tauri-shell/src/components/ItemEditDialog.tsx`（内容编辑弹窗）**通篇硬编码中文**，未走 i18n：
`编辑内容` / `类型：` / `大小：` / `归属：` / `标题` / `标签` / `取消` / `保存` / `清除缓存文件` 等。
而同文件「来源」一行走了 `t(sourceLabelKey(item.source))` ⇒ **同一个弹窗内中英混排**。

`SeriesEditPanel.tsx` 同类问题（`编辑剧集` / `年份（可选）` 等）。

英文界面（`getLanguage() === 'en-US'`）下这些文案仍显示中文。

## 成因（比「漏接 i18n」更具体，值得记档）

BUG-258 缺陷 3 的根因**不是**忘了写映射，而是**映射逻辑被复制成了两份**：
`MediaCard.tsx` 与 `ItemEditDialog.tsx` 各写一份 `kindLabel()`，而**内容弹窗那份漏了 i18n 映射**，
于是直接渲染后端原始枚举。BUG-258 已把映射上收到 `api/media.ts#seriesKindLabelKey()`，
消除了重复实现——**这才是该类缺陷的正解**（收敛单一真源，而不是逐处补翻译）。

本条是同一类缺陷的剩余部分：整窗文案仍未接 i18n。

## 修复方向

1. `ItemEditDialog.tsx` 全文接 i18n（约 15 个新键，`media.item.*` 命名空间）；
2. `SeriesEditPanel.tsx` 同批接；
3. 顺带核查是否还有第三份 `kindLabel()` 副本（BUG-258 声称已收敛为 `api/media.ts` 单一真源，需复核）。

反向验牙 = 把某个键改回硬编码中文，断言必须 FAIL。）
