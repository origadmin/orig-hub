# BUG-068: 媒体库左栏标签：计数 0 仍渲染 + chip 不保证单行 + 显示的数 ≠ 筛出条数

- 状态: fixed
- 发现日期: 2026-09-19
- 模块: shell
- 严重程度: high

## 现象

用户第 9 轮：「**媒体库底部标签 仍然显示大量 0 视频标签. 问题完全偏离.**」，并附要求
「省略 0 标签，还有过长标签截断，最大值、最小值样式都要测试，必须都能在一行显示」。

打开媒体库面板 → 左栏底部「标签」区：28 个标签**全部**渲染，其中 10 个尾部挂着 `0`；
长名标签把 chip 内部撑成两行。

**定位纠偏**：本项首轮被写成「导航标签」（`Sidebar`），而用户指的是**媒体库面板左栏底部**
（`MediaLibraryPanel` 的 `[data-testid="media-tag-list"]`）。首轮只改了侧栏、没打开媒体库面板
—— 这就是「问题完全偏离」的确切含义。

## 根因（三条，互相独立）

1. **渲染层无条件渲染**：`tags.map()` 遍历全部标签，计数 0 也照渲染。计数 0 的入口点下去
   必然得到空列表 —— 渲染它等于向用户承诺一个兑现不了的入口。
2. **计数语义与筛选语义不一致**：内容侧显示 `itemCount + seriesCount`，而内容侧的筛选
   **只匹配条目** ⇒ 显示 8、点开 6 条。数字必须等于点下去得到的条数。
3. **单行约束无人守**：chip 的类名里**既无 `truncate` 也无 `max-w` 也无 `whitespace-nowrap`**，
   长名直接把 chip 内部折成两行；计数也没有 `shrink-0`，会被名称挤掉。

## 数据侧事实（为什么会有 10 个 0 标签）

删条目/剧集只执行 `DELETE FROM media_item_tag` / `DELETE FROM media_series_tag` 清关联，
**不 GC `media_tag` 行本身** ⇒ 每次删除都留下一批 0/0 孤儿，越积越多。

实测真实库：`media_tag` 28 行、`media_item` 109 条、`media_series` 7 个，其中
**10 个标签是 0/0**（id 33/34/35/40/49/51/52/53/56/57）。

**engine 侧不改**：孤儿在数据层无害（仅几十字节），且「无关联的标签」本身是合法状态
（用户可先建标签后挂载）。正确的处置是**渲染层过滤 + 保留显式删除入口**，
而不是替用户自动销毁可能仍想保留的标签。

## 修复（`tauri-shell/src/components/MediaLibraryPanel.tsx`）

```
分类行/剧集行: 名称 min-w-0 flex-1 truncate ；计数 shrink-0 tabular-nums
chip:          inline-flex max-w-full items-center gap-1 whitespace-nowrap
  chip 名:     min-w-0 truncate          # 全名保留在 title 属性
  计数:        shrink-0 tabular-nums     # 永不先被压掉
渲染规则:      每侧只算该侧计数（内容=itemCount，剧集=seriesCount）
               计数 0 不渲染；唯一例外 = 当前选中项（否则选中态消失、无取消入口）
               整组为空时显示占位「—」，不留白板
```

**隐藏 ≠ 删除**：过滤只发生在渲染层，数据层原样保留 —— 不替用户销毁数据。

同时给分类行与标签容器补了稳定选择器（`media-cat-*`、`media-tag-list`、`media-tag-chip-*`），
避免验收脚本再靠文案匹配（`aside nav` 会命中主侧栏，第 8 轮已踩过一次）。

## 验收证据

| 层 | 证据 | 结果 |
|---|---|---|
| UI 真实渲染 | **脚本入库**：`tauri-shell/verify/shot_media_tags.cjs`（跑法与前置见文件头） | **18/18** |
| 产物 | `verify_shots/round9/result.json` + 5 张截图（产物不进库，AGENTS.md §6） | 已人工核对 |

关键断言（均为运行期几何/数据，非类名）：

- 内容侧 19 个 chip **零个计数 0**；库内 10 个 0/0 孤儿**一个都没出现在 DOM**；
- 分类行 `音频 0` 不渲染（实测只剩 `全部内容 109 / 视频 82 / 图片 27`）；
- **最小值 + 最长名**同时压：33 字标签名 + 计数 1 → chip 高 21.8px（单行）、
  宽 183 ≤ 容器 191、`scrollWidth > clientWidth`（截断生效）、计数宽 6.2px 未被裁切；
- **最大值**：计数 94 → 数字宽 12.3px，未被压缩；
- 全部 19 个 chip `white-space: nowrap` 且高度 ≤ 24px；
- **显示的数 = 点下去得到的数**：点「冰蝶网调冰山妈妈 2」→ 网格恰好 2 张卡片；
- 剧集侧 7 个 chip 全 > 0，只在内容侧挂载的标签（`1080p`）正确不出现，
  挂到剧集的标签显示 `seriesCount`（2，而非 item+series）；
- 隐藏不销毁：10 个孤儿在数据层仍在；探针标签经 `DELETE /api/media/tags/:id` 可显式删除（200）。

探针（超长名标签）**改完即还原**并断言还原成功：条目标签集合 `[41,42,43,44,48,55]` 逐字相等、
探针标签已从库中消失。

## 未做（有意）

- 不做自动 GC 孤儿标签（见「数据侧事实」；入口在「标签管理」对话框，用户可主动删）；
- 不处理标签**大小写近重复**（`AI短剧` vs `ai短剧`、`Ai成人短剧` vs `ai成人短剧`）——
  这是独立的数据清洗议题，不在本 BUG 范围。
