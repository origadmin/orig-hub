# BUG-266: 播放器没有「显示 / 隐藏控件」的常驻入口 —— 控件自动隐藏后整层被移出 DOM，只能靠「在画面上移动指针」叫回

- 状态: open
- 发现日期: 2026-10-10
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-26

> 来源：用户报告「**右上角应该显示菜单的显示隐藏按钮功能。**」

## 现象

### 现象 1：控件层是「底部一条工具栏」，全文件没有顶部 / 右上角锚定的元素

`tauri-shell/src/components/media/VideoPlayer.tsx:1417-1425`：

```tsx
<div
  role="toolbar"
  aria-label={t('player.controls')}
  className={cn(
    'pointer-events-none absolute inset-0 z-10 flex flex-col justify-end transition-opacity duration-300',
    chromeShown ? 'opacity-100' : 'opacity-0',
    !chromeMounted && 'hidden',
  )}
>
```

`flex-col justify-end` ⇒ 内容**底部锚定**（渐变遮罩 `:1426` + 进度条 + 按钮行 `:1443`）。
实测 `grep -nE 'top-2|right-2|top-0|absolute top' VideoPlayer.tsx` = **0 命中**
⇒ **播放器内没有任何「右上角」构件**。

全应用唯一一个右上角按钮是**自动连播倒计时**的取消按钮（`:1330-1333`，`absolute right-4 top-4`），
它只在倒计时出现（`{showCountdown && nextUp && ...}`），**不是**控件开关。

### 现象 2：播放中控件 3 秒后自动隐藏

- `HIDE_MS = 3000`（`:178`）。
- `pokeControls`（`:818-826`）：播放中、且倍速菜单 / 进度条 / 音量条未悬停时，3 秒后 `setShowControls(false)`。
- 触发 `pokeControls` 的事件：`onMouseMove`（`:1176`）、`onPointerDown`（`:1181`）、
  `onPlay`（`:1204`）、`:867` / `:938` / `:1549`。

### 现象 3：隐藏态不是「透明」，而是**整层移出 DOM**（BUG-217 的合成优化）

`chromeMounted`（`:619`）在淡出结束（`CONTROLS_FADE_MS = 300`，`:180` / `:631`）后置 `false`
⇒ `!chromeMounted && 'hidden'`（`:1423`）把整层 `display:none`，只留一个 **sr-only 进度条**
（`:1403-1414`）保住 `role="slider"` 的无障碍契约。

后果：控件层一旦隐藏，**DOM 里就不存在可点的「显示控件」按钮** —— 因为整个工具栏都不在了。

### 现象 4：唯一的叫回方式是「指针移动」，且没有键盘键位

- `onMouseMove={pokeControls}`（`:1176`）——桌面端鼠标移动即可叫回。
- `onPointerDown={pokeControls}`（`:1181`）——触屏点画面也能叫回，但**同一次点按还会冒泡到
  `<video onClick={togglePlay}>`（`:1198`）** ⇒ 触屏用户「想叫出控件」的代价是**顺带暂停 / 播放**。
- 键盘快捷键（`:1115-1160`）只有 `space`/`k`/`j`/`l`/方向键/`m`/`f`/`p` ⇒ **没有**「显示 / 隐藏控件」键。
- i18n（`zh-CN.json:481-517`）**没有**任何「显示控件 / 隐藏控件」类键。

⇒ 净效果：**用户无法主动「隐藏控件」**（只能等 3 秒自动隐藏），也**没有一个稳定可见的入口把它叫回来** ——
只能靠「在画面上动鼠标 / 点一下」。

## 根因

### 根因 1：控件层沿用的是「底部一条工具栏 + 自动隐藏」范式，没有为「主动切换可见性」预留入口

YouTube 式播放器的控件可见性是**被动**的（鼠标进入 ⇒ 显示，离开 / 静止 ⇒ 隐藏）。
用户要的「右上角显示 / 隐藏按钮」是**主动**语义（一个常驻开关）。当前信息架构里没有这个位置。

### 根因 2：BUG-217 把「隐藏」从视觉态变成了结构态，却没有同时补一个「反隐藏」入口

BUG-217 的修复目标正确（隐藏态整层 `opacity-0` 仍参与合成，把 2x/4x 上屏节拍拉到裸 `<video>` 以下；
见 `BUG-217.md` 的 B3 vs B12 对照表）。但它把「隐藏」升级成 `display:none` 之后，
**「隐藏」这个状态就再没有任何 DOM 落点**，于是「如何主动显示 / 隐藏控件」这个交互位被一起省略了。
BUG-217 验收只看「a11y 可达 + 上屏节拍」，**没有把「用户是否还能主动控制控件可见性」列入判据**。

### 根因 3：触屏路径下「叫回控件」与「播放 / 暂停」撞在同一个手势上

`onPointerDown`（容器）与 `<video onClick>` 在触屏上由同一次点按触发（现象 4）
⇒ 触屏用户没有一个「只叫控件、不改变播放态」的手势。这是「缺少常驻入口」在触摸设备上的放大形态。

## 复现

1. 打开任一可播条目，进入播放器，开始播放。
2. 鼠标静止 3 秒 ⇒ 控件层淡出并被移出 DOM（`document.querySelector('[role="toolbar"]')` 计算样式 `display:none`）。
3. 观察：屏幕右上角**没有任何**可点的「显示控件」按钮；`grep` 也搜不到顶部锚定元素。
4. 触屏设备上：点画面 ⇒ 控件回来，**但同时触发了播放 / 暂停**（`<video onClick={togglePlay}>`）。

## 修复方向（未实施；≥2 实质选项 + 1 个「不做」）

### 选项 A（推荐）：右上角常驻「显示 / 隐藏控件」按钮，独立于自动隐藏

- 在容器**右上角**（`absolute right-3 top-3 z-20`）新增一个按钮，`aria-label` 走 i18n（新增 2 键）。
- 语义 = **手动覆写**：点击「隐藏」⇒ 进入「用户强制隐藏」态，自动隐藏计时器不再把它叫回，
  且**指针移动也不叫回**（直到用户再点「显示」）；点击「显示」⇒ 回到自动隐藏语义。
- 与 BUG-217 的关系：手动隐藏时同样走 `chromeMounted=false`（保持合成优化），
  但**必须保留这一个按钮**（它在工具栏之外，不随 `chromeMounted` 移出）。
- `涉及:` `VideoPlayer.tsx`（新增 1 个状态 + 1 个按钮，约 20 行）；i18n `zh-CN.json` / `en-US.json` 各 +2 键。
- `量化:` 新增 1 个 `data-testid`（如 `player-controls-toggle`）、1 个受控状态；`role="toolbar"` 及其内 8 项不变。
- `回归风险:` 中 —— 必须证明「手动隐藏后指针移动不再叫回」不破坏既有 `pokeControls` 路径；
  BUG-217 的合成判据（`_probe_render_churn_steady.cjs`）必须在**自动隐藏**路径上仍 PASS。
- `后果:` 用户获得一个稳定、可预期的控件开关；触屏用户有了不改变播放态的手势（先隐藏，再点显示）。

### 选项 B：只加按钮，不做「手动覆写」（点击 = 立即切一次可见性）

- 最小实现：按钮点击即 `setShowControls(v => !v)`，不引入新状态。
- `涉及:` `VideoPlayer.tsx` 约 8 行 + i18n 2 键。`量化:` 1 个 testid。
- `回归风险:` 低 —— 不改 `pokeControls`。
- `后果:` **行为不自洽** —— 用户点「隐藏」后移动鼠标，控件又自己回来（自动隐藏计时器仍活着），
  「隐藏」按钮形同虚设。**不推荐**，但列出以说明「只加按钮」不够。

### 选项 C：不做按钮，改为给键盘加一个「切换控件」键（如 `c`）

- `涉及:` `VideoPlayer.tsx` 的 `onKey` switch 加 1 个 case + i18n 提示。
- `量化:` 1 个键位。
- `回归风险:` 低。
- `后果:` 键盘用户可用，但**用户明确要的是「右上角按钮」**（触屏 / 鼠标用户仍无入口）。

### 选项 D：不做

- `涉及:` 无（0 行改动）。`量化:` 0。`回归风险:` 无。
- `后果:` 控件可见性永远是被动的；触屏用户「叫控件」永远顺带切播放态。

## 修复后必须满足（可证伪判据，预先声明）

1. 播放中（控件自动隐藏后），**屏幕右上角仍存在一个可见、可点的控件开关**，
   其 `aria-label` 属于「显示 / 隐藏控件」语义（不是「取消自动播放」——那是倒计时按钮，`player.cancelAutoplay`）。
2. 点击该按钮 ⇒ 控件层可见性**翻转**；且按钮自身**不随控件层隐藏而消失**（它必须位于 `role="toolbar"` 之外）。
3. **手动隐藏态下，移动指针不得让控件层自动回来**（自动隐藏计时器被手动状态覆写）—— 反向证伪：
   去掉「手动覆写」状态（退化为选项 B）后，本判据必须 FAIL。
4. 触屏语义：**存在一个不改变播放态就能显示控件的手势**（点该按钮），
   或明确记录「触屏仍需点画面（顺带切换播放态）」为已知残余。
5. BUG-217 的合成判据不回退：`node verify/_probe_render_churn_steady.cjs` 在**自动隐藏**路径上仍 PASS
   （`[role="toolbar"]` 计算样式 `display:none`，`gapP95` 与修后基线同量级）。
6. 判据 1 / 2 / 3 必须在**真实 UI** 上验（BUG-156），可见性用 `getComputedStyle` 判定，不读 className。
7. 不得删除既有 `data-testid` / `role="toolbar"` / `aria-label`（BUG-149：播放器能力不可删）。

## 关联

- **BUG-217**（fixed）：**本档的直接前因** —— 它把隐藏态从 `opacity-0` 升级为 `display:none`（正确的合成优化），
  但没有补「主动显示 / 隐藏」入口。本档**不推翻** BUG-217 的合成裁定，只补它遗漏的交互位。
- **BUG-218**（open）：4x 倍速控件层**可见期**的节拍劣化 —— 与本档共用同一块控件层代码；
  若本档引入「手动常驻显示」，会让控件层可见期**变长** ⇒ 可能放大 BUG-218 的窗口。**两档须一起验**。
- **BUG-219**（in_progress）：播放卡顿（用户同批提出的第 4 条）—— 同一块播放器，本档改动不得使其回退。
- **BUG-245**（fixed）：兼容流常驻横幅移除 —— 同一「常驻构件是否该常驻」的判据线（BUG-148）。
- 设计真源：`docs/design/episode-internal-ia-v2-2026-09-29.md`（未覆盖播放器控件层信息架构）；
  播放器控件层此前无独立设计文档 ⇒ 本档新增的「常驻开关」需在实现时补一段设计依据（BUG-148：
  常驻 UI 必须同时验 happy path，且不得是「替实现道歉」的构件）。

## 待确认（口径）

1. **「菜单」指什么？** ① 整个控件层（`role="toolbar"`，含进度条 + 按钮行）—— 本档按此理解；
   ② 仅按钮行；③ 播放器的某个具体弹出菜单（倍速 / 选集）。若是 ③，落点与判据都要改。
2. **默认态**：控件默认可见（现状）还是默认隐藏（点击才显示）？
3. **与自动隐藏的关系**：手动「显示」后，是否恢复 3 秒自动隐藏？（本档按「是」设计，即手动态只在「手动隐藏」方向上覆写。）
