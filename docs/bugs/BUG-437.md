# BUG-437: 文字筛选不随监控内容更新——停在规则视图里连增量同步都不跑

- 状态: fixed
- 修复提交: 34d605a
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: mid

## 现象

用户 2026-10-27 原话：

> 文字筛选 应该根据监控的内容更新更新符合需求的数据

即：监控频道来了新消息、且新消息命中某条筛选规则时，界面一侧应该跟着出新的数据。
现状是打开规则后看到的是**打开那一刻的快照**，之后无论后台进多少命中数据，数字与
列表都不动，得退出重进。

## 根因（代码层逐行核对，非推断）

服务端**不是**瓶颈，瓶颈是「没人去问」。三处缺环：

1. **整个规则视图里一轮增量同步都不跑**。`TgPanel.tsx:1252-1285` 是唯一的主动同步
   effect，守卫是

   ```ts
   if (selectedId === null || !monitoredSet.has(selectedId)) return
   ```

   而进规则视图时 `tgMode = 'filter:<id>'`，`selectedId` 由 `:511` **单一派生**为
   `null`（`:494` 的 `tgFilterId` 是另一条互斥分支）⇒ 条件恒成立 ⇒ 直接 return。
   连带后果：它是唯一会重拉 `filters` 的地方（`:1264-1267`，注释明写「同步到新
   内容后也会重拉…否则命中数会停在旧值」），所以在规则视图里**连命中数都冻结**。
2. **命中面板本身不订阅任何更新**。`TgFilterPanel.tsx:127-155` 的取数 effect 依赖
   只有 `[filter.id]` —— 一次挂载拉第一页，此后与数据源断开。
3. **数据是新鲜的**：`Store::count_filter_hits`（`store.rs:1611`）每次现算
   `media_message JOIN monitored_channel` 的 LIKE 计数，没有缓存、没有快照表。
   慢的是壳不问，不是引擎不给。

## 复现

待补（需活栈）：起 daemon + orig-tg → 加一条命中某关键词的规则 → 停在规则视图 →
令该监控频道出新消息 → 断言规则 `hits` 不动、面板列表不增；退出重进后才看得到。
（上一轮在线验收时后端未起，此处不得空口称修。）

## 修复（已实施；用户 2026-10-27 裁定「显示全部数据，新到的换色标识」）

方案 A + 就地并入，两处改动：

1. **`TgPanel.tsx` 增量同步守卫**：`selectedId === null || !monitoredSet.has(selectedId) ⇒ return`
   改为「选中监控频道 **或** 正在看某条规则 ⇒ 跑」
   （`selectedId === null && tgFilterId === null ⇒ return`）；依赖数组同步加 `tgFilterId`
   （切进/切出规则要重挂节拍）。**0 新端点、0 新定时器**。
2. **`TgFilterPanel.tsx` 就地并入**：用服务端那个便宜计数（`filter.hits`，仍是单元口径）当闸门 ——
   - 首屏取到后把当时的 `hits` 钉成**基线**：必须用服务端总数，不能用已渲染数 ——
     Pagination 时后者恒小于前者，拿它比较会退化成「每次都以为有新内容」的无谓轮询；
   - `filter.hits` 高于基线 ⇒ 拉一次最新页，按**单元键差集**取出新单元、把它们的行前置并入；
     已有行保持原对象引用，不整列表重渲染；
   - 新单元进 `newUnitKeys` ⇒ 渲染时加 `ring-1 ring-accent/50` 并标 `data-new-hit="1"`
     （用户要的「新数据用其他颜色标识」）；
   - 勾选沿用 `loadMore` 同一把尺子：缺字节 ⇒ 默认入选，用户显式碰过的单元**不还原**。

未采纳：提示条 + 点击才刷新（用户明确不要，要「直接显示全部」）、整列表自动重载（会把用户
做过的减法加回去、拽走滚动位置）、30s 轮询整页（缩略图预取成本最高）。

## 验收证据

判据脚本：`tauri-shell/verify/verify_bug437_monitor_sync_in_filter.cjs`
（已入 `verify/MANIFEST.md`，域 `tg` / 档位 S2）。

真栈（daemon 19786 / orig-tg 19787 `Authorized` / vite 5180；实库 5 条规则：19、222、223、431、434）：

| 断言 | 结果 |
|---|---|
| TG 页可达、规则行已渲染 | PASS（`tg-filter-row` = 5） |
| 点开规则进 `tg-filter-panel` | PASS |
| 停在规则视图 75s 内 `/api/tg/monitor/sync` 请求数 **≥ 2** | PASS（实读 **3**） |

**判据验牙（反向变异）**：把守卫改回旧实现后跑同一脚本 ⇒ 计数从 3 掉到 **1 ⇒ FAIL**；
复原后回到 3 ⇒ PASS。阈值取 `>= 2` 而非 `>= 1`：TG 页另有第二处 `syncTgMonitor()` 调用点，
进 TG 页那一次改前改后都会发生 ⇒ `>= 1` 是恒绿断言，只有 60s 节拍真的在跑才 discriminates。
（反向变异前先 `curl http://127.0.0.1:5180/src/components/TgPanel.tsx` 确认 vite 真的供的是
那个版本 —— esbuild 会剥注释，不能拿注释当标记。）
