# BUG-403: 文件管理点击内容应显示详情与可操作功能，而非选中

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: shell
- 严重程度: high

## 现象

文件管理（「文件 → 全部文件」= `cat-all` 的 Explorer 列表）里，点一行得到的是**选中**：
行进选择态、顶部批量工具栏出现，但**看不到这条内容是什么**，也拿不到任何单条动作
（播放 / 打开目录 / 在 TG 中查看 / 编辑 / 删除）。

用户裁定（2026-10-23 原话）：

> 文件管理点击内容应显示详情与可操作功能，而非选中。

即：点击 = 看内容 + 就地操作；选中应是**显式勾选**，不是点击的副作用。

## 根因

交互模型把行的 `onClick` 绑成了选择，且**没有**「内容详情」这一层：

- `FileRow` 的行级 `onClick` → `onSelectToggle(id, shiftKey)`；打开只挂在
  `onDoubleClick` 与行内「打开」按钮上；
- 于是「想看一眼这条是什么」这个最常见的意图，只能靠**进入选择态**来表达 ——
  用户看到的是勾选框亮起 + 批量工具栏压下来，而不是内容；
- 详情信息（类型/大小/日期/来源/路径/字节态/剧集/标签）与单条动作散落在：
  网格卡的 `ItemEditDialog`（只有编辑）、行内按钮（只有打开/定位/删除/TG），
  **没有任何一处把它们聚在一行内容上**。

旧注释把「单击选中、双击打开」当成 Explorer 常识写进了
`FileListView` / `MediaLibraryPanel` 的文档注释里 —— 这正是缺陷长期没被发现的原因：
判据与用户诉求方向相反时，实现越「符合常识」离诉求越远（BUG-320 同型）。

## 复现

1. 起栈（`scripts/dev/dev-stack.cmd`），进「文件 → 全部文件」；
2. 单击任意一行：行变选中态、出现批量工具栏，**无**内容详情；
3. 期望：弹出内容详情（名称/类型/大小/日期/来源/字节态/路径 + 动作），且选中数仍为 0。

## 修复

推翻「单击选中、双击打开」，改为**单击 = 打开内容详情**，选中只走复选框：

1. 新增 `tauri-shell/src/components/media/ItemDetailDialog.tsx` —— 内容详情覆盖层：
   名称 + 类型/大小/日期/来源/字节态/剧集/标签/路径，动作区
   `打开（播放）/ 打开目录 / 在 TG 中查看 / 编辑信息 / 删除`。
   「编辑信息」由 `!fact` 门控 —— 受管成品（`fileFact`）没有可编辑的库字段，
   渲染一个点了没反应的按钮比不渲染更糟（BUG-327 同族）。
2. `FileListView.tsx`：行 `onClick` 改 `onOpenDetail(item)`、`cursor-pointer`；
   **删除** `onDoubleClick`（单击已经弹覆盖层，再叠一次播放会让用户同时看到两个
   东西，播放改为详情里的按钮）；`FileListViewProps` / `FileRow` 增加 `onOpenDetail`。
3. `MediaLibraryPanel.tsx`：新增 `detailItem` 状态（与剧集详情 `detail` 分名，
   避免遮蔽）、`revealItem` 回调；`<FileListView onOpenDetail={setDetailItem}>`；
   渲染 `<ItemDetailDialog>`。**每个动作先关详情再执行**（播放器/编辑框/删除确认/
   TG 域都是覆盖层或整域切换，叠两层遮罩用户会不知道自己在哪）。
4. `lib/reveal.ts`：把散在三处的 `import('@tauri-apps/plugin-opener')` + try/catch
   收口成 `revealItemPath(path, {onError, unsupported, failed})`；`FileListView`
   与面板详情共用同一通道（抄第三遍就该收口）。
5. i18n：新增 `media.itemDetail.*`（zh-CN / en-US 各 14 键）；
   `media.fileList.dblHint` 由「单击选中，双击打开」改为「单击看详情，勾选框选中」
   —— 文案与语义必须同向，否则用户按提示操作必错。
