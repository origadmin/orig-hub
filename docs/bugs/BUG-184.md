# BUG-184 TG 相册「继续 N/M」在没有任何缓存任务时出现：TG 图片被无条件判为已缓存

- **状态**: open
- **发现日期**: 2026-09-29
- **模块**: shell
- **严重程度**: mid

关联 BUG-049（TG 图片按需可取的代理语义）、BUG-170 / BUG-181（EntryState 家族）、BUG-148（实现约束 ≠ 产品信息）。

## 现象

用户在 TG 相册条目上看到 **「继续 1/6」**，据此认为「缓存已经开始了 / 还剩 6 个待续」，
但**实际没有任何缓存任务在运行**（缓存任务列表为空，磁盘未增长）。

用户原话：「没有进行任何缓存，默认图片显示后就变成了继续」。

对用户表现为「这个按钮在骗我」：按钮文案声称有进度，而进度不存在。

## 根因

分子不是任务进度，是**派生状态计数**；而其中「TG 图片」这一类被无条件算作已缓存。

| 位置 | 事实 |
|---|---|
| `tauri-shell/src/lib/entryState.ts:96` | `if (source === 'tg' && kind === 'photo') return 'cached'` —— **TG 图片无条件**判为已缓存（BUG-049 的代理语义：TG 图片按需拉取，视为总是可取），**不校验字节是否存在** |
| `tauri-shell/src/components/TgPanel.tsx:1801` | `downloadedCount={unit.filter((x) => entryStateFor(x) === 'cached').length}` —— 把上述「无条件 cached」的图片一并计入「已缓存数」 |
| `tauri-shell/src/components/TgPanel.tsx:2237` | `` `${t('tg.continue')} ${downloadedCount}/${items.length}` `` —— 文案由 **派生 cached 数 / 相册条目数** 拼出 |
| `tauri-shell/src/i18n/locales/zh-CN.json:300` | `"tg.continue": "继续"` |

**分母也不是任务总量**：`items.length` 是相册条目数（`:2237`），
与缓存任务端点的 `done/total`（`GET /api/tg/cache/tasks`，`routes.rs:1167-1194`；前端映射见 `types.ts:283-284`）**是两套数**。

**触发条件**：混合相册（例：1 张图 + 5 个视频）——渲染即 `downloadedCount = 1`（那张图）、
`items.length = 6`、`allDone = false`（`TgPanel.tsx:2090`）⇒ 命中 `:2237` 的 `downloadedCount > 0` 分支，
显示「继续 1/6」，**全程无任何任务**。

**关于「默认图片显示后就变成了继续」**：未找到 `onLoad` 驱动状态切换的代码路径
（`TgPanel.tsx` 的 `img` 只绑 `onError`，见 `:2284` / `:2374`；`tauri-shell/src/components/media/CoverImage.tsx:50` 的 `onLoad` 仅调 CSS `fit`）。
真实机理即上一条：图片条目在 `entryStateFor` 里**恒为 cached**，与图片是否渲染完成无关；
用户观察到的「图片显示后就变继续」是渲染时序上的巧合，不是因果。

## 复现

**已完成：静态证据链（决定性）**

```sh
# ① TG 图片无条件判 cached
sed -n '93,100p' tauri-shell/src/lib/entryState.ts     # → :96 photo ⇒ 'cached'

# ② 该派生值进入「已缓存」计数
sed -n '1798,1804p' tauri-shell/src/components/TgPanel.tsx   # → :1801 filter === 'cached'

# ③ 文案由该计数拼出
sed -n '2230,2242p' tauri-shell/src/components/TgPanel.tsx   # → :2237 继续 N/M
```

## 修复

方向（**修计数口径，不改 `entryState` 的语义本身**——TG 图片按需可取是 BUG-049 的既定语义）：

1. 「继续 N/M」的**分子**不得使用 `entryStateFor(x) === 'cached'` 这一派生值 ——
   它把「语义上可取」与「字节已在本地」混为一谈。应改用**真有本地字节**的口径
   （或直接改用缓存任务侧的 `done/total`，但那受 BUG-181 单飞契约约束，需一并考虑）。
2. **分母**与分子必须同源，否则分数本身无意义（当前分子是派生计数、分母是条目数）。
3. 仅在**确有缓存任务或确有部分字节**时才显示「继续」，否则保持「缓存」——
   即 BUG-148 口径：能力边界只在用户正因此受阻时出现，不能常驻成假进度。

> 具体取哪个口径（本地字节快照 / 任务侧 done-total / 二者合并）需设计，
> 且必须同时验 happy path（真有缓存进行中时文案仍正确）——不得为了让空态不显示而把进行中的进度也一并砍掉。

## 关联

- BUG-049：TG 图片「按需可取」的代理语义来源。本档**不否定**该语义，只否定它被拿来当**缓存进度**用。
- BUG-170 / BUG-181：`EntryState` 派生链与「排队不可见」同族 —— 本档是同一派生函数在**计数**用途上的又一次误用。
- BUG-148：把实现层的状态（派生 cached）当成产品信息（缓存进度）常驻到按钮上。

## 修复后验收要点（预声明 · 待 fixed 时转为 验收证据 并立真实证据）

1. **能力断言（打真实渲染 + 真实任务列表）**：打开一个「1 图 + 5 视频」的混合相册，
   `GET /api/tg/cache/tasks` 为空时 —— 按钮文案**不得**出现「继续」及任何 `N/M` 形态。
2. **反向证伪**：在真有缓存任务运行时，文案**必须**反映进度（不能为了修空态把进行中的进度砍掉）。
   若把「有任务」这一条故意破坏，断言必须 FAIL。
3. **反向证伪 ②**：把 `entryState.ts:96` 的 photo 分支临时改为 `'absent'`，上述空态断言必须 FAIL ——
   证明确实是该行导致，而非巧合。
4. **分母同源**：断言文案里的 `N` 与 `M` 来自同一数据源（可核验：两者随同一输入变化）。
5. 入库验收脚本（跨机器可复核）：待修复时新增 `tauri-shell/verify/verify_cache_button_truthfulness.cjs`。
