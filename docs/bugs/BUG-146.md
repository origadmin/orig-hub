# BUG-146：缺陷登记门禁 §13.3 规则冲突——未识别字段名静默失效 + 轻量档减免验收证据

- 状态: open
- 发现日期: 2026-09-23
- 模块: docs
- 严重程度: major

## 现象

`scripts/check-bugs.py` 门禁存在两类假绿：

1. **字段名硬编码**：`FIELD_RE` 把字段名写死在正则里，正则不匹配的字段被静默忽略——门禁完全不知道它存在，依赖该字段的规则恒不触发。实测：轻量档加的 `- 档位: light` 一直未被收录，「轻量档写了根因要报错」这条规则永远不生效，门禁却报 OK。
2. **轻量档减免过度**：旧逻辑对 `BUG->=056` 所有状态强制 `## 验收证据`（含 `open`），导致存量 `open` 档必 FAIL；而轻量档本应只减免「现象/根因/复现/关联」四段，不减免验收证据与履历完整性。

## 根因

`FIELD_RE` 字段名白名单漏收演进出的字段（`档位`/`Tier`）；`## 验收证据` 强制逻辑未按档位区分，与 `docs/rules/bug-registry.md`「轻量档只减免四段」冲突。

## 复现

对含 `- 档位: light` 且写了 `## 根因` 的档，门禁不应报 OK 却报 OK；对 `open` 状态的轻量档，门禁因缺 `## 验收证据` 误 FAIL。

## 修复

提交 `<hash>`（`fix(scripts): stop silently dropping unknown bug-registry fields and fix light-tier evidence rule (BUG-146)`）。

- 改为「先抓任意 `字段形状` 再查白名单」：`NOW_FIELD_RE` 收录 `档位/Tier`；`FIELD_SHAPE_RE` 探测 `- <名字>:` 形态，命中白名单外字段名时 **warn**（不 err，避免阻断并行会话的合法字段如 `发现方式`）。
- 验收章节按档位分流：轻量档 `## 根因` 存在 → err（误用档位，应升标准档）；`## 验收证据` 对标准/轻量档**同样必需**；`档位` 值不在 `{standard,light}` → err。

## 关联

- handover 报告 §13.3（门禁规则冲突）、`docs/rules/bug-registry.md` 二/三节

## 验收证据

> **当前状态 `open`，尚未修复。** 以下为修复后必须满足的可证伪判据。

**判据（每条必须能 FAIL）**：

1. 给轻量档加 `- 档位: light` 且写 `## 根因` → 门禁必须 err（此前恒 OK）。
2. 轻量档 `## 验收证据` 缺失 → 门禁必须 err（与标准档同要求）。
3. `- 档位: bogus` → 门禁必须 err（枚举外值）。
4. 存量含合法未知字段（`发现方式` 等）的文档 → 门禁 warn 而非 err，不阻断。

**反向证伪**：用一段含 `- 档位: light` 无 `## 根因` 且有 `## 验收证据` 的合法轻量档跑门禁 → 必须零报错。
