# BUG-215: 图片灯箱顶部两按钮（关闭/摘除）被自绘标题栏裁切 —— `fixed inset-0` 锚错参照系

- 状态: fixed
- 修复日期: 2026-10-13
- 发现日期: 2026-10-08
- 模块: shell
- 严重程度: mid

## 现象

图片浏览（灯箱）时，顶部两个按钮（右上「关闭 ✕」、左上「摘除挂图 🗑」）上半截被裁切，
看起来整体超出内容区上边框（用户截图：底部居中 `n/N` 计数 + 半透明遮罩下隐约可见侧栏，
特征指向 `media/Lightbox.tsx`）。不只是观感：按钮上半段的点击命中也被标题栏吞掉。

## 根因

- `Lightbox` 容器锚定 **webview 视口**：`fixed inset-0 z-50`（`tauri-shell/src/components/media/Lightbox.tsx:53`）。
- 自绘标题栏高 **40px**、`z-index: 60`、不透明背景（`tauri-shell/src/styles.css:85-96`）。
- 顶部按钮锚 `top-4`（16px）：close（`Lightbox.tsx:63`）、detach（`Lightbox.tsx:106`），
  按钮纵向占 16–56px，其中 16–40px 落在标题栏带内，且 `z-50 < z-60` ⇒
  上约 24px 被标题栏盖住 —— 视觉「超出边框」，实际点击目标亦被 `-webkit-app-region: drag` 拦截。
- 本质：**浮层参照系用 `inset-0`（视口），而可见内容框从标题栏下缘（y=40）开始**，
  边界参照系不一致。
- 同类排查面：仓内其它 `fixed inset-0 z-50` 浮层（如各居中 Dialog）内容不触顶暂不受影响，
  但**角部锚定元素**（`top-4` 类）都属同类风险，修复时一并 grep 排查。

## 复现

打开含挂图/图册的剧集 → 点图片进入灯箱 → 观察右上关闭 / 左上摘除按钮几何
（上半截被标题栏遮挡）。修复阶段按 UI 验收铁律用 viewport-相对几何断言
（`getBoundingClientRect()` 对 `window`，±2px，BUG-321 口径）+ Playwright 截图实证。

## 修复（已落地）

- `tauri-shell/src/components/media/Lightbox.tsx:59`：浮层由 `fixed inset-0` 改为
  `fixed inset-x-0 bottom-0 top-[var(--titlebar-h)]` —— 参照系从**视口**下移到
  **内容框（标题栏下缘）**；遮罩不再往标题栏区做无效绘制。
- `tauri-shell/src/styles.css:60`：新增 `--titlebar-h: 40px` 作为标题栏高度的**唯一真源**
  （`.titlebar` 的 `height` 也读它），浮层与标题栏不再各写一份 40px。
- 顶部按钮（close / detach）仍锚 `top-4`，但相对的是**下移后的浮层**，故落到 y=56，
  不再落进 16–40 的标题栏带内。

## 验收证据

活栈（vite :5180 / orig-daemon :19786 / orig-tg :19787）实测，验收脚本
`tauri-shell/verify/verify_bug_215_lightbox_titlebar.cjs`（CDP 活栈；BUG-321 口径
viewport-相对几何 ±2px + `elementFromPoint` 命中测试）：

- **绿态 `RESULT: PASS {"A_episode":true,"A_closeClick":true,"B_gallery":true}`**
  （只读验收：不写后端、不改数据；截图与几何 JSON 落 `tauri-shell/verify/evidence/BUG-215/`）。
- 实测几何：标题栏 `bottom=40`；浮层 `top=40`（**未**侵入标题栏带，故无需靠 z 层级兜底）；
  `close` / `detach` 均为 `top=56,bottom=96`（`>= 40`，完整可见），
  且**两个按钮中心点 `elementFromPoint` 命中自身**（`hitIsSelf=true`）⇒ 既看得见也点得到。
- **反向证伪**：把 `:59` 临时改回 `fixed inset-0` ⇒ 6 项断言按预期 FAIL ——
  浮层 `top=0` 侵入标题栏带、`z-index=50` 未高于标题栏 `60` 被盖住、
  `close`/`detach` `top=16 < 40` 上半截被切、且**中心点命中的是 `button`/`div` 而非按钮自身**
  （点击被吞），**完整复现「看不见 + 点不到」两侧症状**。
  ⚠️ 其中「close 真实点击生效」在红态**仍 PASS** —— 程序化 `.click()` 会绕过命中测试，
  所以它**不能**证明可点击；真正咬住缺陷的是 `elementFromPoint` 那两条。
- **字节级还原**（禁 git checkout）：改回后 sha256
  `d101005c29e44e91564169678223cd2512e203a7e3ba053df26797d6fa526262` 与基线一致，
  `git diff` 为空；复跑回绿。
- 场景说明（诚实边界）：A 覆盖集级挂图灯箱（close + detach 同框）；**B 目标剧集当前无图册
  瓦片，脚本按设计跳过**（`B_gallery=true`），故图册灯箱路径**未被本次覆盖** ——
  需另找带图册的剧集才能补齐。
