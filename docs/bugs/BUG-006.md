# BUG-006: 侧边栏「全部文件」展开/收起交互行为不纯

- 状态: fixed
- 发现日期: 2026-08-27
- 模块: shell
- 严重程度: mid

## 现象

1. 原「全部文件」整行按钮单次点击同时触发三件事：切到全部视图、翻转子菜单展开态、清空分类筛选，用户感觉「怪怪的」。
2. 第一次修复后仍未符合方案 1（干净拆分）或方案 2（单一按钮态机）：「全部文件」文字按钮点击时仍顺带强制 `setCatOpen(true)`，导致已折叠时点击文字会强制展开子菜单，chevron 与文字的职责没有真正分离。

## 根因

`tauri-shell/src/components/Sidebar.tsx:78-82`（第一次修复版）中 `handleSelectAll` 同时做了导航与展开控制：

```ts
const handleSelectAll = () => {
  onCategoryChange(null)
  onViewChange('all')
  setCatOpen(true)          // ← 文字按钮越界控制子菜单状态
}
```

虽然 chevron 按钮仅负责 `setCatOpen(o => !o)`，但文字按钮的副作用使整个交互仍是「两按钮杂交体」，既不是纯切分两动作，也不是单按钮状态机。

## 复现

运行 `C:/Users/godcong/.workbuddy/verify_env/verify2.mjs`（Playwright）：

1. 默认折叠态点击「全部文件」文字 → 修复前子菜单被强制展开；修复后子菜单仍折叠。
2. 当前在「下载中」视图点击 chevron → 修复后子菜单展开，「下载中」按钮仍保持高亮，视图未切换。
3. 子菜单展开状态下点击「全部文件」文字 → 视图切到全部（按钮高亮），子菜单保持展开（未被文字点击折叠）。

关键截图：
- `verify_shots/02-zh-chevron-expands-submenu-view-unchanged.png`
- `verify_shots/03-zh-click-all-switches-view-submenu-stays.png`

## 修复

`tauri-shell/src/components/Sidebar.tsx:78-82`（最终）：

```ts
/** 点击「全部文件」文字/图标：仅切到全部视图（方案1：不碰子菜单展开态，纯导航动作） */
const handleSelectAll = () => {
  onCategoryChange(null)
  onViewChange('all')
}
```

chevron 按钮保持仅翻转 `catOpen`，两者彻底解耦。

## 防再发

1. **决策纪律**：用户已明确选择的方案不再重复询问；本次深刻教训就是不应把「文字按钮顺带强制展开」当成方案 1 的实现。
2. **断言锁定**：Playwright 验收脚本对以下行为加硬断言并保存截图，回归跑脚本即可发现耦合复发：
   - 文字点击后 `catOpen` 不变（不强制展开/折叠）。
   - chevron 点击后当前视图不变。
3. **代码注释**：在 `handleSelectAll` 处显式写明「不碰子菜单展开态，纯导航动作」，提示后续维护者。
4. **人工走查**：侧栏交互改动必须先过真实渲染截图（非单纯类型通过）。
