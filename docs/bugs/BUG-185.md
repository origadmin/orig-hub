# BUG-185 相册缓存完成后操作行整行消失：完成态零入口、零状态提示

- **状态**: open
- **发现日期**: 2026-09-29
- **模块**: shell
- **严重程度**: mid

关联 BUG-184（同一 `downloadedCount` 派生口径的另一面）、BUG-170（EntryState 单源派生）、BUG-148（实现约束 ≠ 产品信息）。

## 现象

相册（多图组 / 含视频组）全部缓存完成后，该组的**操作区整行消失** ——
不是变灰、不是改文案，而是渲染成 `null`。

用户无法判断这是「已经完成了」还是「这个页面根本不支持缓存」，
产生认知错误（用户原话：「完成后没有任何按钮表示，所有按钮消失，造成认知错误（这个页面无法缓存？）」）。

## 根因

相册组的按钮区是一个三段三元表达式，**`allDone` 分支直接落到 `null`**，且相册没有像单条那样的完成态角标。

| 位置 | 事实 |
|---|---|
| `tauri-shell/src/components/TgPanel.tsx:2090` | `const allDone = downloadedCount >= items.length` |
| `tauri-shell/src/components/TgPanel.tsx:2222` | `) : !allDone ? (` —— 只有**非** `allDone` 才进入按钮渲染分支 |
| `tauri-shell/src/components/TgPanel.tsx:2225-2240` | `!allDone` 分支内：纯图组已入库 → 「已入库」文本（`:2226`）；否则 → 「缓存」/「继续 N/M」按钮（`:2228-2239`） |
| `tauri-shell/src/components/TgPanel.tsx:2241` | `) : null}` —— **`allDone === true` 时整块渲染 `null`** |
| `tauri-shell/src/components/TgPanel.tsx:2137` | 相册 tile 的点击是 `onPreview(i, items)`（**预览**，开 `tg-photo-preview`，`:2277`），**不是**「打开/播放」入口 |

**决定性对比（同一文件内的不对称）：单条消息完成后有明确出口，相册没有。**

| 位置 | 单条（MessageBubble） |
|---|---|
| `tauri-shell/src/components/TgPanel.tsx:1960` | `{cached && <Chip tone="success">{t('tg.downloaded')}</Chip>}` —— 完成态有**「已下载」角标** |
| `tauri-shell/src/components/TgPanel.tsx:1969-1972` | 完成后渲染**「播放」按钮**（`t('tg.play')`，`onClick={onOpenDownloaded}`） |

相册组**两样都没有**：既无 `tg.downloaded` 角标（`grep -n "tg.downloaded" TgPanel.tsx` 仅命中 `:1960` 这一处），
也无「播放/打开」按钮。故本缺陷是**相册特有**，不是全局设计。

> 与 BUG-184 同源：`allDone` 的分子 `downloadedCount` 同样是那个「TG 图片恒判 cached」的派生计数
> （`entryState.ts:96` → `TgPanel.tsx:1801`）。两个缺陷是同一口径在两个方向上的表现：
> 一个让**未开始**的组显示成「进行中」，一个让**已完成**的组显示成「不存在」。

## 复现

**已完成：静态证据链（决定性）**

```sh
# ① 按钮区三段条件：allDone 落 null
sed -n '2222,2241p' tauri-shell/src/components/TgPanel.tsx

# ② 完成态角标只在单条上有，相册没有
grep -n "tg.downloaded" tauri-shell/src/components/TgPanel.tsx   # → 仅 :1960

# ③ 相册 tile 是预览不是播放
sed -n '2134,2140p' tauri-shell/src/components/TgPanel.tsx       # → onPreview
```

## 修复

`tauri-shell/src/components/TgPanel.tsx`：

1. **`:2241` 的 `: null}` 不得保留** —— `allDone` 时必须渲染**明确的完成态**，
   而不是什么都不渲染。最小对齐：与单条一致，给出「已下载」角标 + 「打开/播放」入口。
2. 若沿用「已入库」文本形态（`:2226`），必须**与「无此功能」可区分** ——
   当前空白的失败模式正是「没有元素」与「功能不存在」在视觉上不可分辨（BUG-148 口径）。
3. 相册 tile 的 `onPreview` 可保留（预览是有用能力），但它**不能充当唯一的出口** ——
   用户需要一个语义明确的「打开/播放」动作。

> 具体呈现形态（角标 + 按钮 / 整组变成一条可点开的完成行）需设计；
> 修复必须同时验 happy path：**未完成**的组不得出现完成态元素。

## 关联

- BUG-184：同一 `downloadedCount` 派生口径的另一面（假进度 ↔ 完成态落空）。**两条应同批修复**，
  否则改了分子口径却不改 `allDone` 分支，仍会落空。
- BUG-170：EntryState 单源派生 —— 本档的 `allDone` 正是同一派生的消费端。
- BUG-148：把「没有元素」当成合法状态，用户无法区分「已完成」与「不支持」。

## 修复后验收要点（预声明 · 待 fixed 时转为 验收证据 并立真实证据）

1. **能力断言（打真实渲染）**：把一个相册缓存到全部完成 → 该组内**必须存在**可点击的
   「打开/播放」入口，且存在明确的完成态标识（角标或文本）。
   **断言「存在某个元素」不够**，必须断言其**可点击且能打开该组内容**。
2. **反向证伪**：把 `:2241` 恢复为 `null` → 上述断言**必须 FAIL**。
3. **不误伤（happy path）**：缓存**未完成**的相册组**不得**出现完成态元素
   （防止为了修完成态把未完成组也标成已完成）。
4. **与单条对称性**：同一批内容，单条路径（`:1969-1972`）与相册路径都应给出可点击出口 ——
   断言两者在完成态下都有出口，不得一侧有、一侧无。
5. 入库验收脚本（跨机器可复核）：待修复时新增 `tauri-shell/verify/verify_album_done_state.cjs`。
