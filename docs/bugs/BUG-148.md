# BUG-148：能力限制说明被做成常驻核心元素——搜索框作用域 chip 占据主视觉

- 状态: fixed
- 发现日期: 2026-09-23
- 模块: shell
- 严重程度: major
- 档位: standard

## 现象

TG 上下文栏的全局搜索框内，最靠前的位置常驻一枚 chip：「仅搜索已同步到本地的监控消息」；
搜索结果视图头部同样常驻同一条文案。

后果是**主客倒置**：用户第一眼看到的是「这个搜索有局限」，而不是搜索本身。一条能力限制
说明被渲染成与输入框同等权重的常驻构件，并且挤占 `w-80` 搜索框里本就紧张的输入宽度
（移除前输入框可用宽度被这枚 chip 与放大镜共同压缩）。

用户判定：「违反任何标准设计规范，也是绝对禁止项」。

## 根因

**没有任何设计依据要求它常驻**——是我自己加的：

- `git blame` 结果：搜索框内 chip 来自 `f437571`（2026-09-22，BUG-140「两个搜索框无作用域
  标注」的修复）；结果视图头部那行来自 `03bf4d4`（BUG-100 落位）；无命中空态那行来自
  `9a28947`（2026-09-20，最早）。
- BUG-100 的三条约束（独立 memo 子组件 + 300ms 防抖 / 三槽可收缩 / 切视图清空规则）与其
  验收要点（AC3b：全页 `input[type=search]` 恒为 1；搜索结果展示来自哪个频道）
  **均未要求常驻范围标注**。
- 真正被要求的是「两个搜索框并存时要有作用域区分」（BUG-140），而作用域区分的正确形态是
  在**需要区分时**出现（两个框同屏），不是把一个能力限制做成常驻卖点。

性质归类：把「实现约束」当「产品信息」递给用户。约束（`/api/tg/monitor/search` 只查本地
已同步消息、不做网络回补）是**事实**，但它属于「搜不到时解释原因」的场合，不属于常驻 UI。

## 复现

打开 TG 视图，看上下文栏搜索框：放大镜左侧有一枚灰色 chip，写着搜索能力的局限。

## 修复

限制说明**按需出现**，不做常驻元素：

- `TgGlobalSearch.tsx`：删除搜索框内的常驻作用域 chip（`tg-global-search-scope`）及其
  占位，输入框宽度归还给输入本身。
- `TgPanel.tsx` 结果视图头部：删除常驻范围说明，保留「命中数 + 清除」；左侧留空占位。
- **保留** `TgPanel.tsx` 无命中空态（`tg.searchNoMatch` 下方）的那一行——那是用户真的
  问「为什么搜不到」的时刻，此时给出原因才是正当的、可解释的，且不构成常驻噪音。
- i18n 文案本身不删：它是后端契约的准确陈述（`routes.rs:1547`），只是不该常驻。
