# BUG-287: 网页模式（非 Tauri 运行时）下「选择目录」能力缺失 —— BUG-072 只消除了报错（改禁用），未解决可用性；「两模式都要支持」目标下需网页可用的目录选择方案

- 状态: fixed
- 发现日期: 2026-10-12
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-26

> 来源：用户 2026-10-12 报障「库根目录和默认下载目录 这里有选择路径，**现在也变灰了**，
> 不仅仅是上面那个问题吧？」＋ 前一轮「**后续可能 2 种模式都要支持的**」。
> **本档为任务文档**（用户定：纯文档任务，代码由别的组负责）。
>
> **严重程度说明**：桌面（Tauri 二进制）**不受影响**，故定 `mid`；
> **若网页模式成为正式交付形态，应升为 `high`**。

## 现象

**网页模式**（`vite dev` 跑在普通浏览器，无 Tauri 运行时）下，设置页的
「**默认下载目录**」与「**库根目录**」两个目录选择器的「**浏览…**」按钮**置灰不可点**
（`tauri-shell/src/components/DirectoryPicker.tsx:126` `disabled={disabled || !inTauri}`）
⇒ 用户**无法用系统对话框选目录**，观感是「功能没了」。

## 这不是新缺陷，是 **BUG-072 的既有修复**（但它只修了「报错」、没修「可用性」）

- **`BUG-072`**（**fixed**，2026-09-20）：「网页调试模式下『浏览…』选择目录报错
  （`Cannot read properties of undefined (reading 'invoke')`）」。
  其修法（原文）：「把它从『点击即抛错』变成『**静默禁用 + 提示**』，错误环境即消失」。
- ⇒ **按钮置灰 = BUG-072 的修复效果，不是回归**（`git log -S '!inTauri'` 指向 `9a28947`，2026-09-20）。
- **但 BUG-072 的立足点是「网页模式 = 调试态」**；用户已明确「**2 种模式都要支持**」⇒ **前提变了**，
  于是「禁用」留下的可用性缺口需要**单独处理**（本档）。
- 已在 `BUG-072` 追加「## 后续变更（2026-10-12）」节（历史锚定，**不改写其正文**）。

## 现状可用手段（**有**，但用户看不见）

`DirectoryPicker.tsx` 在网页模式下**仍保留**两条通道：
- **手动输入路径**：`<Input>`（`:94-99`），其 `disabled` 只在 `disabled` prop 为真时生效，设置页**未传** ⇒ **可编辑**；
- **历史目录下拉**：`:100-121`（`localStorage` 持久化，可单条删除）。

⇒ 严格说网页模式**并非完全无法设置目录**，但：
- 提示只藏在按钮 `title`（tooltip）里（`:127`），**用户不易发现**；
- 按钮置灰给人的第一印象是「**功能没了**」（用户本轮原话即是此感）。

## 浏览器侧限制（决定了方案边界）

- **系统目录对话框不可替代**：浏览器的 File System Access API（`window.showDirectoryPicker()`）只返回
  **句柄（handle）**、**不返回绝对路径**（安全沙箱）⇒ **无法用于「设置一个路径字符串」**的场景。
- ⇒ 要「两模式都支持」，**只能**：① 强化手输 / 历史通道的**可见性**；或
  ② 由**后端**（`daemon` / `orig-tg` 本就有文件系统权限）提供「列出某目录的子目录」端点，
  前端做**服务端浏览选择器**。

## 修复（方向；**本档不改代码**）

1. **可见性改进（P0，最小改动）**：网页模式下把「可直接输入路径或选历史」从 `title` 提到
   **行内可见提示**（不违反 BUG-148：用户**此刻正受阻**，属正当提示；**桌面模式不显示**）。
2. **服务端目录浏览（P0，真方案）**：`daemon` / `orig-tg` 提供「列出指定目录的子目录」端点，
   网页模式做**服务端浏览选择器** ⇒ **两模式一致可用**，且不依赖 Tauri 插件。
   （须遵守既有约束：只读目录元数据、不新增媒体投递端点、不绕过背压。）
3. **不推翻 BUG-072**：网页模式**仍不得**抛 `invoke` 异常（其结论有效）；桌面模式行为**不变**。
4. **登记一个脆弱点（P1）**：`DirectoryPicker.tsx:37` 的 `const inTauri = isTauri()` 是**渲染期快照**
   （非 state、不响应式）—— 若 Tauri 注入 `__TAURI_INTERNALS__` **晚于**首次渲染，
   桌面模式会**误判为网页模式** ⇒ 按钮**误置灰**。建议改为 state + effect 探测，或确认注入早于渲染并加注释佐证。

用户裁定：**「都做」** —— 即**修复方向 1（行内可见提示）与 2（服务端目录浏览选择器）两条都实施**，**不是二选一**。

- **两者不冲突**：2 是**真方案**（两模式一致可用、不依赖 Tauri 插件）；1 是**最小可见性补丁**，
  可作为 2 落地前的即时改善，2 落地后**仍保留**（网页模式下提示「可手输 / 可浏览」）。
- **本档路线取舍已决**，**不再作为待拍板项回抛**。
- 其余两条**维持不变**，仍须满足：修复方向 3（**不推翻 BUG-072**：网页模式仍不得抛 `invoke` 异常、桌面行为不变）、
  修复方向 4（**脆弱点处置**：`DirectoryPicker.tsx:37` 的 `inTauri` 渲染期快照）。

## 验收证据

网页模式的目录选择已由「服务端浏览选择器」（本档列出的方案②）实现，不再是「置灰禁用」：

- `tauri-shell/src/components/DirectoryPicker.tsx:80-92` `pick()`：`!isTauri()` 时**不再报错、
  也不禁用**，而是 `setBrowserOpen(true)` 打开应用内目录浏览器；
- 浏览按钮的禁用条件只剩 `disabled`（`:157`），`!inTauri` 已从判据里移除 —— 这正是
  本档症状（「浏览…」置灰）消失的直接原因；
- 应用内浏览器数据来自 daemon 只读端点 `GET /api/fs/dirs`（`tauri-shell/src/api/daemon.ts`
  的 `listDirs`，只列子目录、错误带可读原因，失败不得渲染成「没有子目录」）；
- 选中的路径以**存储形式**（正斜杠）回写状态，展示侧走 `lib/pathDisplay.ts` 归一（BUG-332）。

判据（本机可核）：`grep -n "!isTauri()" -A 4 tauri-shell/src/components/DirectoryPicker.tsx`
必须命中「打开应用内浏览器」分支；`grep -n "disabled={disabled}" tauri-shell/src/components/DirectoryPicker.tsx`
必须**不含** `!inTauri`。反向证伪：把 `disabled={disabled}` 改回 `disabled={disabled || !inTauri}`，
网页模式下按钮即重新置灰 = 本档复发。
