# BUG-331: 验收跑范围外 bug——「只验收当前 BUG」无对照表、无工具裁剪，范围外回归混入本回合结论

- 状态: in_progress
- 发现日期: 2026-10-20
- 模块: docs
- 严重程度: high
- 排期: 2026-11-10

## 现象（用户原话，2026-10-20 清单第 0 点）

> 「当前所有开发流程有严重问题……会去跑所有不在范围的 bug 验收，这个应该在后续整体验收测试、回归测试、或异常报告在测试，当前完全违反规则，进行不需要的测试，浪费时间，人力，脑力，没有丝毫可行性，可用性，必要性。」

即：修复某个 BUG 的回合里，执行了对**不在本回合改动范围**的其他 BUG 的验收运行；范围外失败还会混进本回合结论，制造假红与误判。

## 根因

1. **作用域规则未覆盖「验收阶段」**：`docs/rules/gate-scope.md` §1 对照表的唯一判据是「本次变更的哪条路径落在门禁作用域里」，只管「提交前跑哪个门禁」，没有「验收阶段跑哪些 BUG 的验收脚本」这一行。
2. **规则本身未确认强制**：该文件 frontmatter `status: draft`、`decided-by: —`（原文「升为强制待主理人确认」）⇒ 执行与否靠记忆。
3. **无工具裁剪**：BUG-247 已给 `check-bugs.py` 加 `--changed`（改什么跑什么、范围外 SKIP），验收脚本集合没有等价 scope 判据；执行者按「保险起见」跑全套，正是 gate-scope.md §5.1 明令禁止的理由（「不许用『保险起见』作为跑门禁的理由」）。
4. **与 2026-10-09 实测缺陷同构**：纯文档改动跑 check-bugs 全量 399 s、结果与改动零因果（gate-scope.md §0）——范围外 bug 验收同理：结论与本回合改动无因果，纯付时间成本。

## 复现

任取一个改动集（例：`git diff --name-only` 只含 `tauri-shell/src/components/TgFilterPanel.tsx`），观察执行过程是否运行了与该路径无关的 BUG 验收脚本（如媒体卡/播放器类），以及其失败是否被计入本回合验收结论。

## 修复方向

- 验收启动先取本回合变更集 ⇒ 只运行落在其中的 BUG 的验收脚本；范围外回归归「整体验收 / 回归测试」批次（用户指定归属），不在开发回合里跑。
- 可仿 `check-bugs.py --changed` 给验收入口加 scope 判据（工具裁，不靠人记得）。
- `gate-scope.md` 的 draft 状态须经主理人确认升为强制，并在 §1 对照表补「验收阶段」一行。

## 裁定记录（2026-10-20，用户问「要效率、规范，哪种快？」）

**结论：工具裁——一次性建设换每回合零决策成本，且结构性不可能误跑。** 对比（两条路都按本仓实测数据算，不按感觉）：

| | 手工清单（执行者每回合记范围） | 工具裁（仿 `check-bugs.py --changed`） |
|---|---|---|
| 每回合成本 | 「想起来 + 对着清单核」= 每回合数分钟注意力，且**漏记无拦截** | 一条命令，自动 SKIP 范围外（check-bugs 实测 SKIP 约 **2.9 s** vs 全量 **399 s**，BUG-247 优化后全量 8 s） |
| 误跑代价 | 无拦截 ⇒ 随时发生（本就是本档现象） | **结构上不可表达**（变更集不含 ⇒ SKIP exit 0） |
| 一次性成本 | 0 | 约一次（scope 判据 + 组脚本；`check-bugs.py --changed` 已有成例可抄） |
| 规范强度 | 靠人记得同步 = 没有（`gate-scope.md` §3 原话：「为什么是『工具裁』而不是『规则劝』」） | 判据随工具走，漏记/多跑都被机器挡住 |

**最小实现方案**（待用户批准后实施）：

1. 组脚本 `scripts/run-bug-acceptance.sh BUG-330`（或等价的 `--only`），只跑该 BUG 登记的验收脚本（脚本名登记进 BUG 文件 `## 验收证据`，一处真源）；
2. 整体回归单独一个批次入口（`--all` 或 CI 定时），与开发回合物理分离——正是用户指定的「后续整体验收测试、回归测试、异常报告」归属；
3. `gate-scope.md` §1 对照表补一行「验收阶段」并在主理人确认后升强制。

## 实现（2026-10-28）

落地「工具裁」的验收入口 `scripts/run-acceptance.py`，三种模式与两处既有真源绑定：

| 模式 | 判据 | 何时用 |
|---|---|---|
| `--changed` | 变更集路径 → 域（tg / engine / download / files）→ 只跑该域脚本 | 开发回合默认 |
| `--only BUG-NNN` | 该档案 `## 验收证据` 节里出现的 `verify/*.cjs` | 单 BUG 复验 |
| `--all` | MANIFEST 全表 | 发布前 / 用户点名（开发回合禁用） |

真源不新增：脚本→域/档位读 `tauri-shell/verify/MANIFEST.md`，BUG→脚本读档案的
`## 验收证据` 节。范围外**结构上不执行**（`--changed` 未命中域时直接返回「跑 S1 冒烟即可」），
不存在「忘了裁」这条路径。

实测（`--dry-run`）：

```
$ python3 scripts/run-acceptance.py --changed
SKIP  changed=87 个文件未命中任何有脚本的域 ⇒ 运行 S1 冒烟即可（smoke.cjs）
$ python3 scripts/run-acceptance.py --only BUG-447 --dry-run
# scope: --only BUG-447 → 1 个脚本（范围外一律不跑）
  RUN verify/verify_bug447_i18n_keys.cjs [misc(i18n)]
```

未做的一部分：`docs/rules/gate-scope.md` 仍是 `status: draft` —— 把它升为强制是**规则变更**，
须主理人确认（本档不单方面改规则文件）。
