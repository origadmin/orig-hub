# BUG-333: 下载设置三概念主次不明——受管目录/库根目录/默认下载目录平铺并列，用户分不清该改哪个

- 状态: open
- 发现日期: 2026-10-20
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-26

## 现象（用户原话，2026-10-20 第 1 点）

> 「受管目录，库根目录，默认下载目录 3 种逻辑主次不明，场景不明。」

设置页同屏给出多个目录名词与取值，用户分不清哪个是自己该改的、其余分别管什么场景。

## 根因

BUG-323 已把关系重定为「库根 = `<下载路径>/library` 派生只读」「手动下载实际默认根 = 内容默认根（过禁写 C 盘规则后）」（`SettingsPanel.tsx:306-310` 注释与四个 state：`defaultDir`/`manualRoot`/`effectiveRoot`/`libRoot`）。引擎侧口径已收拢，但**界面仍把四个引擎字段平铺成并列名词**，没有按「用户决策量」分层：真正需要用户决策的只有「下载路径」一个，其余是派生值/兜底值/只读展示。名词并列 + 无主次标注 ⇒ 用户看到三套逻辑。

## 复现

打开设置-下载与存储，数一屏内出现的目录名词个数，逐个问「改了它会改变什么、不改它会怎样」——当前界面答不出主次。

## 修复方向

单一「下载路径」为唯一主决策项（输入框 + 保存，BUG-234 的 `PUT /api/config/download`）；库根/默认下载根/生效根降级为该输入框下方的只读派生说明（一行来源注释，如「库根 = 下载路径/library，只读」）。分层与措辞待用户拍板后实施。

判据（建议）：

- 下载设置里用户可改的目录输入框 = 1；
- 其余目录名词均为只读展示且各带一行「来源/派生关系」说明；
- 反向证伪：把某个派生值做成可编辑 ⇒ FAIL。

## 设计方案（2026-10-20，待用户选定；现状取证 = `SettingsPanel.tsx:653-770` 三张平级卡）

现状三卡平铺：①下载路径（可编辑 + 生效值直出 :660-687）②库根（只读 + 打开文件夹 :691-729）③受管目录（多根列表，下载根 locked :733+）。三个名词同字号同权重并列 ⇒ 用户问「我该改哪个」。

## 裁定记录（2026-10-20，用户选定）

**选方案 A（主次分层）。** 实施规格：一张主卡「下载路径」（目录选择器 + 保存 + 生效值直出保留），卡内两行只读派生说明（`库根 = <下载路径>/library` 带打开文件夹按钮；`管理范围 = 下载根（锁定）+ 你添加的 N 个目录`）；库根从平级卡降级为主卡内只读行；受管目录降次级卡（标题小一级 + 只读引导文案）。状态仍 `open`（实现待排期，与 330 弧不同文件、可并行）。

> **与 BUG-337 的分界（用户问「333 和 337 不是同一条吗」，2026-10-20）**：
> **不是同一条。** BUG-333 改**区块内容**（下载与存储区内部三个目录概念的主次分层）；
> BUG-337 改**左侧导航**（七区块命名统一 + 顺序/默认落点，把「下载与存储」提首位）。
> 两者唯一交汇 = 「下载置顶」这个方向一致，实现同在 `SettingsPanel.tsx`、改动不冲突，
> **可一个批次落地，但缺陷各自独立、各自验收**（不可用 333 的定标顺带覆盖 337）。

### 方案 A —— 主次分层（推荐）

- **一张主卡「下载路径」**：目录选择器 + 保存；卡内下方两行只读派生说明：
  - `库根 = <下载路径>/library（只读，打开文件夹按钮保留）`
  - `管理范围 = 下载根（锁定）+ 你添加的 N 个目录`
- 「库根」从平级卡**降级为主卡内的只读行**（打开文件夹 button 跟着走）；
- 「受管目录」降为次级卡（标题小一级、说明文字引导「只读管理范围，写入口只有下载路径」）。
- 版面说出的主次：**只有一件事可改，其余都是它的注脚**。用户决策量 = 1。

### 方案 B —— 三卡保留 + 关系标注

- 三卡结构不动，每卡右上角挂关系标签：库根卡「派生自 下载路径·只读」、受管卡「下载根已锁定」；
- 「下载路径」卡视觉加重（accent 边框 / 标题大一级）并置顶；另两卡降饱和。
- 改动最小，但主次仍靠用户自己读标签建立。

### 方案 C —— 两卡合并（与 BUG-334 文件域联动）

- 卡 1「下载路径」（含库根只读行）；卡 2「管理范围」（受管多根 + 一句「文件管理按受管范围展示」——把 BUG-334 的文件域口径在同屏交代）。
- 概念数 3 → 2，但改动面跨 BUG-334，需一并排期。

**建议 A**：概念主次由版面结构直接表达（不可改的降为注脚），不依赖用户读标签；B 适合想最小改动的排期，C 适合与 BUG-334 同批做。
