# BUG-080: 缓存清理后媒体库条目仍在但无法播放（字节已删、条目未同步状态）

- 状态: fixed
- 发现日期: 2026-09-20
- 模块: engine+shell
- 严重程度: mid

## 现象

用户疑问：「缓存会入库，这里缓存清理后库里面还能正确播放吗？」

实测答案：**不能。** 清理缓存只删了磁盘字节，媒体库里那条 `media_item` **行仍在**，
于是列表/剧集里那张卡片看起来还跟正常内容一样（有标题、有缩略图位、有播放按钮），
点进去却播不了——用户无法从界面判断"这条已经没字节了"。

## 根因

`download-engine/crates/orig-tg/src/cache.rs::purge_item`（208-225 行）清理一条缓存时只做三件事：

```rust
let bytes = std::fs::metadata(&it.file_path).map(|m| m.len()).unwrap_or(0);
let _ = std::fs::remove_file(&it.file_path);          // ① 删文件
let _ = st.store.set_item_file_path(it.id, None).await; // ② 条目 file_path 置 NULL
reset_tg_flag(st, &it.source, &it.ref_key).await;      // ③ 复位 TG「已缓存」标记
```

**没有第四件事：既不删 `media_item` 行，也不给前端任何"已无字节"的信号。**

后果链：

1. `media_item.file_path = NULL`，但 `id/title/thumb/kind` 全在 → 列表照常渲染成可播内容。
2. 播放走 `GET /api/media/items/:id/raw`（`orig-tg/src/routes.rs` 注册）。文件不存在时
   该端点返回 **404**（不是 500，也不降级）—— 播放器拿到 404 直接失败，
   `<video>` 甚至不一定触发 `onError`，表现为"点了没反应/黑屏"（见 BUG-034 同类静默失败）。
3. 图片类条目走 TG 缩略图代理路径，缩略图可能仍在 → **看起来更正常**，误导性更强。

这不是"该不该删行"的偏好问题：保留行本身是合理的（TG ref 还在，支持重新缓存），
**缺的是把"无字节"这个状态暴露出来**。

## 复现

1. TG 面板缓存一条视频 → 媒体库出现该条目 → 播放正常；
2. 缓存管理 → 缓存字节 → 清理该条（或整档 `scope=all`）；
3. 回媒体库：条目卡片仍在、外观与可播条目一致；
4. 点播放 → `GET /api/media/items/:id/raw` 返回 404 → 播不了，且界面未提示原因。

## 修复

- **后端**：`media.rs` 的 `EpisodeView` 增加 `has_bytes`，取 `file_path IS NOT NULL`
  （**不新增列、不迁移**，符合 BUG-032 的迁移克制）。`/api/media/items/:id/raw` 对无
  `file_path` 本来就回 404，未改状态码——如实反映"没有字节"，不降级也不伪装。
- **前端**：`lib/tgmedia.ts::hasMediaBytes` 作为唯一判据入口（优先级见下）；
  `MediaCard` 与 `SeriesDetail` 分集行据此呈现：无字节时封面位占位、不给播放按钮，
  TG 来源给「重新缓存」（`data-testid="item-recache"`，ref 仍在可取回），非 TG 标「文件已丢失」。
- **前端**：媒体库/剧集对 `file_path` 为空的条目渲染**未缓存**态：封面位显示占位、
  播放入口改为"重新缓存"（对 TG 来源可用，ref 仍在），而不是一个点了 404 的播放按钮；
  本地来源（非 tg、无 ref）则标"文件已丢失"。
- **不删 `media_item` 行**：保留元数据与剧集归属，支持重新缓存后原地恢复
  （与 BUG-029「双向删除联动」不冲突——那一条针对的是"删条目"，不是"清字节"）。
- **关键例外（实现中发现，勿漏）**：`file_path` 为空**不等于丢失**。TG **图片不落盘**
  （BUG-049），`raw` 端点现场代理 TG 缩略图字节，所以 `source=tg && kind=photo`
  即使无本地副本也照常可显。判据优先级必须为：
  ① TG 图片 → 恒视为有字节；② 后端 `hasBytes`（分集视图）；③ 有落盘路径。
  若直接用 `file_path IS NULL` 一把切，会把全部 TG 图片误标成"文件已丢失"。

验收锚点：清理后该条 `GET /api/media/items/:id/raw` 仍为 404，但 UI 上该卡片不再呈现
可播外观，且出现"重新缓存/文件已丢失"的可行动入口。
