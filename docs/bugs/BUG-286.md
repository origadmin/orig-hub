- 状态: open
- 发现日期: 2026-10-12
- 模块: shell
- 严重程度: mid

> 来源：用户 2026-10-12 报障「`Cannot read properties of undefined (reading 'invoke')` **设置里面的 BUG**，
> 这些是网页调试的专门问题吗？app 二进制模式是不是没有了？有没有办法解决网页打开时的问题，
> 因为后续可能 **2 种模式都要支持**的？评估下问题和范围。」
> **本档为任务文档**（用户定：纯文档任务，代码由别的组负责）。
>
> **严重程度说明**：桌面（Tauri 二进制）**不受影响**，故定 `mid`；
> **若网页模式成为正式交付形态（用户已明确「2 种模式都要支持」），应升为 `high`**。

## 现象

在**纯浏览器**里打开前端（`vite dev` 直开，无 Tauri 运行时）：
- **设置页**点击「打开库根文件夹」或「打开调试日志目录」⇒ UI 弹出
  `Cannot read properties of undefined (reading 'invoke')`。
- 同类问题散布在若干调用 Tauri 原生能力的入口（见「范围」）。

**桌面（Tauri 二进制）模式不受影响** —— 有 IPC 桥（`__TAURI_INTERNALS__`），这些功能正常。
**不是「二进制模式没有了」**，是「网页模式缺守卫」。

## 根因

**`invoke` 只在 Tauri 运行时存在；纯浏览器里它是 `undefined`。项目已有 `isTauri()` 守卫机制，但部分调用点漏加。**

### 事实 1：守卫机制**已存在**，且注释**原文就写着这个报错**

`tauri-shell/src/lib/env.ts:8-13`：
```ts
 * 纯浏览器里 `@tauri-apps/plugin-*` 调的是 Tauri 的 `invoke` IPC 桥，此时 `invoke` 为
 * `undefined`，直接调用会抛 `Cannot read properties of undefined (reading 'invoke')`。
 * 任何依赖原生的能力（系统对话框、文件系统、托盘…）调用前都必须先 `isTauri()` 守卫。
export const isTauri = (): boolean =>
  typeof window !== 'undefined' && '__TAURI_INTERNALS__' in window
```
⇒ 这是**已知设计**（两种运行形态并存），**不是意外**；缺的是**逐点落实**。

### 事实 2：设置页的报错来源 = `openPath`（无守卫 + catch 把原始异常上 UI）

`tauri-shell/src/components/SettingsPanel.tsx:386-410`：
```ts
/** 打开库根文件夹（tauri opener 通道；浏览器 dev 下无插件 —— 记录后静默） */
const openLibraryFolder = async () => {
  const target = libDirSaved || libDir
  if (!target) return
  try {
    const { openPath } = await import('@tauri-apps/plugin-opener')
    await openPath(target)                       // ← 纯浏览器：undefined.invoke ⇒ 抛
  } catch (e) {
    console.error('openPath failed', e)
    setError(e instanceof Error ? e.message : String(e))   // ← 把原始异常抛到 UI
  }
}
```
`openLogFolder`（`:400-410`）同型。
- **注释写「记录后静默」，实现却 `setError`** ⇒ **注释与实现不符**（用户看到的正是被 `setError` 上屏的那句原始报错）。

### 事实 3：设置页**加载时**无 invoke —— 报错只在**点击**时

`SettingsPanel.tsx:215-247` 的挂载 effect 调 `getTgConfig` / `getConfig` / `listInterfaces` / `loadClassify` / `loadProxy` / `refreshTgState`
—— **全部走 HTTP（`api/tg.ts`）**，且都 `.catch(() => {})`。故设置页**打开时不报**，**点按钮才报**。
（`setTgLibraryDir`（`:377`）也走 HTTP，不涉及 invoke。）

## 复现

1. `vite dev` 起前端，用**普通浏览器**（非 Tauri 窗口）打开。
2. 进入**设置**页 → 点「打开库根文件夹」（或「打开调试日志目录」）。
3. UI 弹出 `Cannot read properties of undefined (reading 'invoke')`。
   **对照**：同一操作在 Tauri 二进制里正常。

## 范围（评估结论）

- **受影响**：**纯浏览器模式**下所有**依赖 Tauri 原生能力**的入口 —— 打开文件/文件夹（opener/shell）、系统目录选择（dialog）、窗口控制（window）、以及 4 个 Rust 命令（`daemon_status`/`ensure_daemon`/`stop_daemon`/`tg_save_config`）。
- **不受影响**：**桌面二进制**全部功能；以及**已经走 HTTP 的能力**（媒体库、TG 数据、设置页读写、下载管理）—— 这些两模式通用。
- **判定口径**：**凡 `import '@tauri-apps/*'` 的地方，都是网页模式的潜在风险点**；是否有守卫决定「优雅降级」还是「报错/静默失败」。

## 修复（方向；**本档不改代码**）

**总目标：两种模式并存 —— 网页模式下原生入口要么优雅降级、要么隐藏，绝不把原始异常抛给用户。**

1. **统一守卫（P0）**：所有 `@tauri-apps/*` 调用前 `isTauri()` 检查（复用 `lib/env.ts`），
   消灭「裸调用 + 把原始异常 `setError` 上 UI」的组合。
2. **三档降级策略（P0，按能力性质分类）**：
   - **(a) 有替代通道 → 降级**：如 `ensureDaemon` 失败 ⇒ HTTP 健康探测（`MainLayout` 已有样板）。
   - **(b) 网页里有等价做法 → 替代**：如「打开文件夹」网页模式改为**显示路径 + 一键复制**（`navigator.clipboard`）；
     「选择目录」改为**手输路径**。
   - **(c) 确实不可用 → 隐藏 / 禁用**：入口在网页模式**不渲染**或置灰 + `title` 说明（**BUG-148**：实现约束只在受阻时出现，不做常驻道歉）。
3. **防回归（P1）**：加一条 lint / 审查规则 —— **禁止裸 `@tauri-apps` 调用**（必须伴随 `isTauri` 守卫或显式降级），
   否则新代码会再次漏掉（本档 7 处无守卫点即历史遗留）。
4. **不推翻既有降级**：`MainLayout` 的 HTTP 探测降级（BUG-090）不得回退。

## 关联

- **`tauri-shell/src/lib/env.ts`**：守卫真源（`isTauri()`），注释已写明本档报错。
- **BUG-090**（fixed）：`MainLayout` 的 HTTP 降级先例（Tauri 路径不可用时退到一次健康探测）。
- **BUG-148**（UI 信息层级）：能力边界只在受阻时出现 —— 网页模式该**隐藏**原生入口而非常驻道歉。
- **BUG-178**（fixed）：`tg_save_config` 由壳写配置 + 请 daemon 重启 —— 网页模式无壳，该入口须降级。
