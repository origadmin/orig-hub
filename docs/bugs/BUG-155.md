# BUG-155：媒体库工具条四个操作按钮零 view 守卫 —— items 专用选中集合跨视图泄漏

- 状态: fixed
- 发现日期: 2026-09-23
- 模块: shell
- 严重程度: high

## 现象

用户原话（2026-09-23）：

> 「全选本页 导入目录 新建剧集 标签管理 依然是全局过滤,有提出BUG,又丢失,没修复,
> 这个是最最最严重的问题.」

即：媒体库工具条上这四个按钮在**所有视图下都渲染**，它们的作用域**没有与当前视图对齐**。

用户侧感受：在剧集墙（series 视图）点「全选本页」，界面上**出现了内容被选中的状态**，
但**选中的对象在当前视图里根本看不见** —— 操作「跑到了另一个视图上」。

## 根因

`tauri-shell/src/components/MediaLibraryPanel.tsx`

**工具栏 header 在 `:767`，三种视图（`items` / `series` / `seriesDetail`）共用。**

同排控件的守卫状况**不一致**：

|---|---|---|---|
| 搜索框 | `:770-780`（testid `media-search-input` @ `:773`） | ✅ `view === 'items'` | f842309 已修 |
| 排序选择器 | `:781-794`（testid `media-sort-select` @ `:783`） | ✅ `view === 'items'` | f842309 已修 |
| 仅未归集 | `:795-805` | ✅ `view === 'items'` | f842309 已修 |
| **全选本页** | `:855-864` | ❌ **无** | **本档** |

| **标签管理** | `:881-888` | ❌ **无** | 见「产品裁定」 |

**分支结构**（`:808` → `:853` else → `:890` 结束）：

```tsx
{selected.size > 0 ? (
  <>{/* 已选工具栏：N 已选 / 加入剧集 / 移除 / 清除选择 */}</>
) : (
  <>

```

**整个分支只看 `selected.size`，零 `view` 条件。**

**`selected` 是 items 专用**（12 处使用点全部 items 级）：

| 行号 | 用途 |
|---|---|
| `:152` | `useState<Set<number>>(new Set())` 定义 |
| `:154-159` | `selectedJoinable`：`items.find(...)` 判 kind |
| `:544` | `confirmTargetIds`：`[...selected]` |
| `:808` | 工具栏已选态 UI |
| `:811` | `t('media.selected', { n: selected.size })` 计数 |
| `:818` | `selectedJoinable` 控制「加入剧集」可用性 |
| `:860` | **全选本页 → `setSelected(new Set(visibleIds))`**（`visibleIds = items.map(i => i.id)`，`:449`） |
| `:1015` | `MediaCard selected={selected.has(item.id)}` |
| `:1062` | `BulkTagDialog count={selected.size}` |
| `:1066` | `setItemTags(id, tagIds)` 遍历 |

**判定**：在 series 视图点「全选本页」→ `selected` 被塞入**当前不可见的 items id**
→ 界面切已选态（「N 已选 / 加入剧集 / 移除」）→ 但对象看不见。
**这是硬缺陷**，与用户所述「全局过滤」完全对应。

**第二个泄漏点**：`selected` 是跨视图共享 state。在 items 视图选中若干 → 切到 series 视图
→ 已选工具栏**仍在**（因为只看 `selected.size`）。**同样是作用域泄漏。**

## 产品裁定

用户称此条为「最最最严重」，但四个按钮**并非同一性质**：

1. **「全选本页」必须加 `view === 'items'` 守卫** —— 它操作 items 专用的 `selected`，
   在其它视图下**语义不成立**。
2. **「导入目录 / 新建剧集 / 标签管理」保持全局可见** —— 这三者是**合法的全局动作**，
   不依赖 `selected`，任何视图下都该能用。**不给他们加守卫。**
3. **视图切换时清空 `selected`** —— 消除已选工具栏跨视图泄漏。

## 复现

1. 进入媒体库（默认落在剧集墙，`view` 默认 `'series'`，`:146`）。
2. 点「全选本页」→ 出现「N 已选」「加入剧集」「移除」工具栏。
3. 观察：剧集墙上**没有任何卡片显示被选中** —— 选中的是当前不可见的 items。

## 修复

见 `docs/bugs/MERGE-4-DEFECTS-EVIDENCE.md` 问题4。**只改前端**：

1. 把「全选本页」**单独**包 `view === 'items'` 守卫（不是给整组加守卫）。
2. 加 `data-testid="media-select-all"`（当前该按钮无 testid，验收无锚点）。
3. 视图切换时 `clearSelection()`（`clearSelection` 已存在于 `:447` 附近）；确认进入
   `seriesDetail` 时也清空。

### 二、反向证伪（证明上表能 FAIL，不是恒真）

同一脚本内含跨视图对照断言：若守卫写成 `true`（即修复前形态），series 视图的
`selectAllByTest` 必须为 `true` → 该断言会 FAIL。实测 series `false` / items `true`
的**真实反差**存在，说明断言确实在读 DOM 而不是恒真。

此外，独立脚本 `diag_media_views.mjs` 先确认了视图切换的真实控件是
`media-cat-all` / `media-cat-video` / `media-cat-photo` 分类按钮（**不是**「全部/条目」文字），
脚本早期曾因走错切换路径导致 9/10 假 FAIL，修正后 13/13 —— 该假 FAIL 已定位为脚本缺陷。
