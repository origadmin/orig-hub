# BUG-408: 剧集合并保留/删除提示逻辑错误——标题/介绍/视频/图片三种处置混乱

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: engine+shell
- 严重程度: high

## 现象
合并时的「保留 / 删除」提示与处理逻辑存在严重问题，当前二元选择无法覆盖真实语义。
应区分三种处置方式：

1. **标题**：若两边都有标题，选其一；若某一边没有，选有标题的那一边。
2. **总介绍**：同理，选有介绍的那一边（缺失侧不覆盖有值侧）。
3. **视频**：评估 hash 冲突，判断是否同一集视频。若是同一集 → 记为两个源 A、B
   （多源同集）；若不是同一集 → 作为两个源、非同一集直接加入对应集。
   图片的处置方式与视频相同。

当前「保留/删除」二元提示与这三种语义不匹配，导致元数据与多源归属错误。

## 根因
**合并处置必须自动化，由已确立的视频防重复 hash 决定，不存在手动「保留/删除」动作**
（用户 2026-10-23 裁定：hash 是先前讨论确定的视频防重复核心设计，无需任何手动步骤）。
当前合并 UI 的二元「保留/删除」提示本身就是缺陷——它把本应自动判定的事丢给用户，
且无法表达下述三种语义。正确规则：

1. **标题 / 总介绍**＝取「有值侧」（缺失侧不覆盖有值侧），自动化、无人工；
2. **视频 / 图片**＝比较两源 hash——相同 ⇒ 同一集、记为多源 A,B；不同 ⇒ 非同一集、各自归入对应集。

代码层的三处具体缺口（实测）：

- `media_series` 的合并只 `COALESCE(description/year/poster)`，**标题根本没写进 UPDATE**；
- `COALESCE` 只认 `NULL`，不认**空串** —— 目标侧存着 `''` 时源侧的真实介绍永远继承不过来
  （「缺失」在本仓有 NULL 与空串两种落法）；
- 视频/图片的「是否同一集」完全没实现（同根因见 BUG-407），合并对话框文案还反过来
  向用户声明「本功能不做内容合并判断」。

## 修复

1. **元数据取有值侧**（`merge_one_source_in_tx` 的 `UPDATE media_series`）：
   判据从裸 `COALESCE` 改成 `CASE WHEN TRIM(COALESCE(x,'')) = '' THEN <源侧> ELSE x END`，
   并把 `title` 一并纳入（目标标题为空才继承源标题）。
   **两边都有标题时保留目标的** —— 目标就是用户在合并对话框里显式选的「保留哪一条」，
   那一步才是标题的决策点，引擎不替用户改主意。
2. **视频/图片按 hash 判定**（同批实现，详见 BUG-407）：hash 相同 ⇒ 同一集 ⇒ 视频进
   `media_episode_source`（多源）、图片进 `media_episode_image`（同集多图）；
   hash 不同、或**任一侧没有 hash** ⇒ 不同集、各自保留。**没有**任何手动「保留 / 删除」环节，
   也**不**按集号猜同一性 —— 没有 hash 就是没有文件，两边都空不存在「合并」
   （用户 2026-10-23 追加裁定，见 BUG-407 的引用块）。
3. **UI 文案如实**：`media.seriesMergeOrderHint` 从「本功能不做内容合并判断」改为描述
   自动规则；合并结果提示新增「另有 N 条同集内容归并为多源」。
