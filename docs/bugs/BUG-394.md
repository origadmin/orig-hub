# BUG-394: 回溯表单日期默认空白——不基于库内已有数据给默认值

- 状态: fixed
- 模块: engine+shell
- 发现日期: 2026-10-23
- 严重程度: mid
- 报告: 用户 2026-10-23 16:00（截图）「回溯的严重问题,没有区域日期问题严重,这里应该默认显示当前的最老数据吧?」

## 现象

点开频道行的「回溯」表单，日期输入框是**空白**（只显示 `yyyy/mm/日` 占位符）。用户必须凭记忆猜一个日期；表单对「库里现在最老的数据到哪天」只字未提，既不提示也不预填。

## 根因

展开表单时硬编码 `setBackfillDate('')`（`TgPanel.tsx` 回溯入口 onClick），且 `GET /api/tg/monitor/channels` 的 `MonitoredChannel` 根本没有「库内最老已入库消息日期」字段——前端想默认也没有真源可用。

## 修法（让默认值来自数据真源）

1. **引擎**（单一真源）：`MonitoredChannel` 增加 `oldestMessageDate`（unix 秒）= `MIN(COALESCE(msg_date, created_at))`（`media_message`，按频道）；`list_channels` / `get_channel` SQL 同步补列（空集 COALESCE 落 0，BUG-388 同型坑）。
2. **前端**：展开回溯表单时 `setBackfillDate(fmtDateOnly(ch.oldestMessageDate))`——UTC 口径（既有 `fmtDateOnly` 与服务端 `parse_date_utc` 同口径，避免时区差一天）；频道尚无数据（=0）时保持空白。
