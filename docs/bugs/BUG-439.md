# BUG-439: 筛选节两套输入框形态打架——检索框常驻占位，新建却在「+」里

- 状态: open
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: low

## 现象

用户 2026-10-27 原话：

> 文字筛选 的 过滤输入框可以收缩到 + 边上 展开收起

同一节（③ 筛选）里有**两个**输入控件，形态互不一致：

| 控件 | 位置 | 默认态 | 入口形态 |
|---|---|---|---|
| 新建规则（`tg-filter-input` + label + 添加/取消） | 节标题右侧 | **收起** | `+` 图标钮 → 浮层（2026-10-20 裁定） |
| 规则检索（`tg-filter-search`） | 展开区顶部（`px-1 pb-1`） | **常驻展开** | 一整行 Input 永远占着版面 |

即「输入」这一件事在同节里有两种呈现语言：一个是按钮，一个是永占一行领土的框。
用户要的是后者向上者对齐——**收起成图标钮，放在 `+` 旁边，点了才展开**。

## 根因

两个控件由两次不同时间的独立裁定各自固化的：

- 2026-10-20（BUG-344）：常驻「一行 Input + 添加按钮」被用户判为「严重破坏整体设计」
  ⇒ 改为节头 `h-7` secondary 图标钮 + 浮层。当时只搬了**新建**，没搬检索。
- BUG-320 纪律「入口可见性不搞『规则多了才出现』」被读成「搜索框必须常驻」——该纪律
  约束的是**入口不得随数据量显现/消失**，不是禁止折叠控件。可折叠 ≠ 条件渲染：
  折叠态仍是一个常驻可见的按钮，入口没有消失，只是不占版面。

判据被扩大解释 ⇒ 检索框保留了最占版面的形态。

## 修复方向（实施：折叠 - inline）

- 节头 `+` **左侧**增一个同 token（`variant="secondary" size="icon-sm"`、`h-7`）的
  漏斗/检索图标钮 `tg-filter-search-toggle`，`aria-expanded` + `aria-controls`。
- 折叠态不渲染 Input ⇒ 列表顶部空出一行；**规则少时省掉一整行的固定开销**。
- 展开态：在该图标钮下方（原位置）渲染 Input，自动聚焦；**再次点钮 / Esc** 收起。
- 收起时**清空检索词**：过滤条件藏在一个看不见的输入框里继续生效 = 一条隐形过滤
  ——用户会读到「列表变少了」却找不到原因（与 BUG-390「让 0 自带解释」同源：不可见
  的状态必须由界面承担解释，而不是让用户去猜）。

## 不做什么（刻意）

- **不**动新建浮层：它已符合用户裁定，再去统一形态属过度改动。
- **不**做条件渲染（规则数 ≥ N 才显示按钮）——直接违反 BUG-320。

## 复现

进入 TG 侧栏 ③ 筛选节 → 检索框应当**默认不可见**（只有节头的一个检索图标钮）→ 点它
输入框出现并可输入过滤→ 再点 / Esc 收起且检索词清空。

## 关联

- BUG-344（节头动作钮 token：可见性由边框+底色承担，不由尺寸+文字承担 —— 本条沿用其 token）
- BUG-320（入口不得随数据量显现/消失 —— 本条是折叠，不是条件渲染）
- BUG-390（不可见状态必须自带解释 —— 收起即清词，避免隐形过滤）
- BUG-440（同一句话的**字面读法**：新建筛选关键字输入框 `tg-filter-input` 行内收起成 `+` —— 本条当初误读成检索框，真正的「过滤输入框」在 BUG-440 收口）
