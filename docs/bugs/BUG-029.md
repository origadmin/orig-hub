# BUG-029 缓存不入媒体库 + 缓存任务无可观测面

- **状态**：fixed
- **日期**：2026-09-17
- **模块**：orig-tg（engine）+ tauri-shell（shell）
- **关联**：BUG-024（缓存任务服务端化）/ BUG-027（单飞重构）

## 现象

1. 点击「缓存」成功后，**媒体库（media_item）里什么都没有**——缓存只写 TG 消息库
   （media_message 的 downloaded/file_path），媒体管理整个功能对 TG 内容不可见。
2. 缓存任务**没有列表**：数量、进度、状态、失败原因均无处可看（仅有 feed 内的单任务
   进度条，历史任务/失败任务完全不可见）。
3. 媒体管理的「剧集思维」（series/episode：多选→加入剧集→季/集编排）对 TG 内容
   无从施展——根因同 1，条目根本不入库。

## 根因

- `download_one` 成功后只调 `upsert_message` + `mark_downloaded`（media_message 域），
  从不调 `upsert_media_item`。`import_media_items` 虽预留了 `source="tg"` 分支，
  但缓存链路上无人调用。
- `cache_task` 表数据齐全（status/total/done/error），但路由只有单结果契约
  （BUG-027 裁定 `{"task": 唯一}`），无列表/计数端点，前端也无管理面板。
- 剧集体系（media_series/media_episode + MediaLibraryPanel 的 series 视图 +
  AddToSeriesDialog 多选归集）早已存在，只是因 1 无米下锅。

## 修复

### engine（orig-tg）

- **缓存即入库**：`download_one` 成功后 `upsert_media_item(source="tg",
  ref="{chat_id}:{message_id}", title=caption||文件名, kind=classify_ext||mime前缀,
  file_path, size, duration)`。与 `import_media_items` 的 ref 约定一致，
  按 `(source,ref)` 幂等，重复缓存不产生副本。元数据缺失时从落盘文件兜底。
- **双向删除联动**（防状态漂移）：
  - 清缓存（`DELETE /api/tg/stored/{chat}/{msg}`）→ 同步删对应 media_item
    （新增 `Store::delete_media_item_by_ref`，级联清标签/剧集归属）；
  - 媒体库删 TG 条目（`DELETE /api/media/items/{id}`）→ 同步清 TG 缓存副本
    （`clear_downloaded`）。否则下次缓存 upsert 会把条目「复活」。
- **缓存任务列表**：`GET /api/tg/cache/tasks/all` → `{tasks, counts}`（活跃优先、
  上限 500，counts 覆盖六态）；`DELETE /api/tg/cache/finished` 清终态记录
  （活跃任务绝不清）。与既有单结果契约并存，不参与 1s 轮询。

### shell（tauri-shell）

- `api/tg.ts`：`listAllCacheTasks()` / `clearFinishedCacheTasks()`。
- 新组件 `CacheManagerDialog`：状态计数徽章行（缓存中/排队/完成/失败/中断/取消）+
  任务行（状态徽章、频道名、整组/单条、done/total 进度条、更新时间、错误信息、
  取消/重试/清除记录）。刷新遵守轮询三律：打开拉一次，有活跃任务 2s 轮询，
  全终态即停。Escape/遮罩点击关闭。
- TgPanel 频道 feed 顶栏新增「缓存管理」入口。

## 剧集思维使用路径（现状说明）

数据模型与 UI 已齐备，链路打通后即可用：

1. 缓存 → 自动入库为单条内容（媒体库可见）；
2. 媒体库**多选条目 → 「加入剧集」**（AddToSeriesDialog：选已有剧集或新建），
   按选中顺序自动编号季/集（`append_episodes`）；
3. 左栏「剧集」视图 → 剧集详情可再编排（SeriesDetail：季/集增删、描述、封面）。
