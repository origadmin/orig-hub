# BUG-471: 目录管理缺第三个动词「迁移」——清盘场景下无法把旧根下的字节搬进主目录，只能丢库或永不清盘

- 状态: open
- 发现日期: 2026-10-28
- 模块: engine+shell
- 严重程度: mid
- 排期: 2026-11-26

> 来源：用户（2026-10-28）「458 没问题，但是考虑到可能要清盘的情况，需要提供迁移功能，
> 堆入主目录，这样就都 OK 了」。

## 现象

换盘 / 清盘是必然发生的运维动作：旧盘要清空、旧分区要格式化、旧目录要下线。
当前目录管理（BUG-458 选项 A）只有两个动词：

1. **纳管**（`addManagedRoot`）—— 把一个根登记进受管集合；
2. **移出**（`removeManagedRoot`）—— 把根从受管集合摘掉。

用户此时只剩两个结局：

- 清盘 ⇒ 字节没了 ⇒ 按 BUG-458 裁定 C 第 2 条，该根下条目全部落入对账第 1 支
  （标「文件缺失」、剧集大面积变灰、无来源的明说「无法取回」）⇒ **清盘即丢库**；
- 不清盘 ⇒ 旧盘永远占着，主目录的「唯一新字节落点」形同虚设。

也就是说：**「换盘」这个真实运维动作在当前产品里不可表达。**

## 根因

1. **动词缺失**：受管根的接口面只有登记 / 移除 / 设主目录（`api/tg.ts:836-866`），
   没有「搬」。字节的物理位置被假定为「登记后永不改变」。
2. **判据使后果不可收拾**：缺失判定只挂「该位置是否仍被任一受管根覆盖」
   （BUG-458 裁定 C 第 2 条）。清盘后覆盖消失 ⇒ 不是「搬走了」而是「丢了」，
   库无法区分「字节搬到别处了」与「字节没了」——**同一状态两种成因，界面只表达一种**。
3. **红线把这条路一起封了**：BUG-468 裁定「库永不写用户磁盘」，当前没有任何
   例外通道 ⇒ 哪怕用户明确要求搬，也没有可批的落点。

## 复现

1. 目录管理里把主目录切到新盘 D2（BUG-458 裁定 C：旧条目不变、不判缺失）。
2. 试图把旧盘 D1 清空。
3. 直接删 D1 的文件 ⇒ 启动对账后 D1 下全部条目变灰（第 1 支）；
   手动移除 D1 根 ⇒ 同样变灰，且带「N 条失去字节」摘要。
4. 结论：无论走哪条路，只要清盘就丢库；不存在「搬」这个选项。

## 定稿（2026-10-28，用户拍板 + 专业评估）

**结论：做。迁移 = 目录管理的第三个动词，语义是「搬字节 + 改条目指向」，
目标位置为主目录；「堆入」= 保持源根内相对路径平铺，不做重命名整理。**

### 一、迁移的语义边界

| 项 | 定义 |
|---|---|
| 搬什么 | 受管根下的**字节**（条目关联的媒体文件），不搬库、不搬元数据 |
| 搬到哪 | 当前主目录（`/api/fs/roots/primary`），保留源根内相对路径平铺 ⇒ 「堆入」 |
| 改什么 | 条目的 `file_path` 指向新位置（条目属性写，**不是**用户文件内容写） |
| 不改什么 | `seriesKey` / 归档轴 / 来源坐标（`source + ref`）/ 剧集归属一律不动 |
| 不做整理 | 重命名、季集归位是 BUG-469 的活，迁移只搬不整理 |
| 单向 | 仍是单向（BUG-468 裁定 ①）：库认新位置，**不反向同步磁盘** |

### 二、执行顺序（让错误状态不可表达）

对用户磁盘的写只有「复制」和「删除旧文件」两步，顺序必须钉死：

1. **预检**：主目录剩余空间 ≥ 待搬字节总量（不足即中止，给出「需 X 剩余 Y」，
   不做搬一半）；目标同名冲突先算清。
2. **复制**：源 → 目标，**不删源**。
3. **校验**：逐条比对字节大小（可选：快速内容哈希抽样，默认不做，性能优先
   见 BUG-458 裁定 B）。
4. **改指向**：校验通过后才把条目 `file_path` 更新到新位置。
5. **删旧**：仅对「已校验 + 已改指向」的条目删源文件。
6. **收尾**：旧根移出受管集合（或提示移出），跑一次对账给摘要。

⇒ 任一环节失败：**保留原状**（旧文件在、条目指向旧路径），不允许出现
「旧已删、新未成」的中间态。

### 三、必须同步的三条判据（否则自造 BUG）

1. **迁移与移出必须原子**：迁移完成后旧根若仍留在受管集合，而文件已被删除
   ⇒ 对账把全部条目判第 1 支（文件缺失）⇒ **搬运成功却显示丢库**。
   故迁移收尾阶段必须把旧根移出受管集合（或至少标记为「已迁移、待清理」），
   不允许「搬完还挂着旧根」。
2. **中断可续、重跑幂等**：进度按条目落盘；重跑时目标已存在且大小一致 = 跳过，
   不一致 = 保留两者并标记冲突（**不覆盖、不静默丢字节**）。
3. **对账窗口**：迁移进行中不跑对账（单飞）；迁移结束作为**用户显式动作**
   按 BUG-458 裁定 B 时点 ② 跑一次并给摘要（搬了 N 条 / 跳过 M 条 / 冲突 K 条）。

### 四、红线例外（唯一一处，条件写死）

BUG-468 裁定「库永不写用户磁盘」在此开**一处**例外，条件全部满足才成立：

- 触发方是**用户显式点击**（不是自动、不是对账、不是启动扫描）；
- 写的内容限于「在目标位置复制」与「删除已校验并已改指向的源文件」；
- 删除**只能在复制 + 校验 + 改指向三者都成功后**发生；
- 全程进度与结果可见（状态栏 + 结束摘要）。

除此之外一律不写用户磁盘，不留第二个例外接口。

### 五、UI 表达

- 目录管理面板增加「迁移到主目录」动作（挂在某个受管根上），与「移除」
  分开呈现——**移除是破坏性的（丢字节），迁移是保字节的**，二者不可混同。
- 执行前确认卡显示：待搬条目数、字节总量、主目录剩余空间、冲突数。
- 「清盘」这个词只出现在用户侧意图里，界面措辞用「迁移」；迁移成功后
  再提示「旧目录现在可以安全清空」。

## 明确不做（排除项）

1. **不做重命名 / 整理**（BUG-469）—— 堆入即平铺，文件名不变。
2. **不引入增量/定时迁移**（BUG-458 裁定 B 性能红线）—— 只在用户点击时发生。
3. **不做双向关联**（BUG-468）—— 迁移后库不追踪目标位置的后续变动；
   用户自己挪走 ⇒ 下一次对账按第 1 支正常处理。
4. **不改归档轴 / `seriesKey` / 计数口径**。
5. **不做跨设备在线搬迁的断点续传**（与下载不同：本地复制由 OS 完成，
   中断按「条目级已完成」续跑即可，不需要字节级续传）。

## 关联

- BUG-458（open）：目录管理与裁定 A/B/C —— 迁移是目录管理的第三个动词，
  且必须满足裁定 C 的「移出才判缺失」。
- BUG-468（open）：位置关联裁定 ① 与「不写用户磁盘」红线 —— 本档是唯一的
  红线例外，条件写死在第四节。
- BUG-469（open）：剧集文件整理 —— 迁移只搬不整理，二者正交。
- BUG-311 / `OrganizeWizard`：条目级整理产物同样是字节落点，迁移需把它
  一并纳入待搬集合（不可漏）。
