# BUG-027: 缓存任务多请求并发 + 派生重取链 —— 1s 多次请求导致页面卡死

- **状态**: fixed
- **优先级**: P0（用户裁定「流畅应该是第一优先度」）
- **模块**: engine（orig-tg）+ shell（前端）
- **发现**: 2026-09-17，用户实测报告「/api/tg/cache/tasks 请求导致页面卡顿…1s 好几次请求」
- **关联**: BUG-024（缓存任务服务端化）、BUG-026（流畅度第一轮：memo + 读快照）

## 现象

真实环境（9877 + 5180）下点击缓存后页面完全卡死；网络面板可见 1 秒内多次请求
（不止 cache/tasks 轮询 1 次）。

## 根因（两层，均有量化证据）

1. **派生重取链（前端，卡死主因）**：`cacheProgressSig` effect 在每次任务进度变化时
   全量重取 `/api/tg/downloaded/{chat}`。真实频道有大量已缓存记录时，每次都是
   大 JSON 传输 + 主线程解析 + `setDownloadedPaths` 新 Map 触发整面板 reconcile。
   后端又允许**多任务并发**（每个 item_key 一个 worker），进度变化频率成倍叠加。
2. **多任务并发（后端，设计错误）**：入队即 spawn 独立 worker，任意多个任务可同时
   `running`。用户裁定：**「不论多少缓存在处理，task 应该只返回一个结果」**——
   一次只有一个任务在推进才是可理解、可流畅呈现的模型。

## 修复

### 后端（单飞 + 顺序队列 + 单结果契约）
- `state.rs`：`cache_worker_alive: AtomicBool`（进程内单飞门禁，
  `claim_cache_worker`/`release_cache_worker`）。
- `routes.rs::spawn_cache_task`：`claim` 失败 = 已有 worker → 新任务保持 `queued`
  等接续；worker 跑完当前任务（done/failed/cancelled）后按 FIFO 接续最老 queued，
  队列清空才退出。
- `routes.rs::list_cache_tasks`：响应从 `{"tasks": [...]}` 改为 **`{"task": <唯一>}`**
  （running → 最老 queued → 最近一条已结束；无则 null）。读路径仍是内存快照零 DB。
- `store.rs`：新增 `has_running_cache_task` / `next_queued_task` / `current_cache_task`。

### 前端（单轮询 + 删除派生重取链）
- `api/tg.ts`：`listCacheTasks()` → `getCacheTask(): TgCacheTask | null`。
- `TgPanel.tsx`：
  - `cacheTasks[]` → `cacheTask` 单对象；`activeTask`/`downloading`/`albumProgress` 单飞派生。
  - **删除 `cacheProgressSig` → `listTgDownloaded` 每变化重取链**；改为「任务从活跃 →
    终态」时一次性刷新（每任务恰一次）。
  - 轮询依赖只用布尔 `hasActiveTask`——进度变化不重建 interval，节拍恒定 1s。

## 验收

- 频率分桶取证（`verify_shots/diag_req_rate.cjs`，mock 12s 窗口）：
  - 修复前：`cache/tasks` 10 次 + **`downloaded` 派生重取 5 次**
  - 修复后：`cache/tasks` p50=**996ms（恰 1 req/s）** + `downloaded` **1 次**（仅收尾）
- 主契约 `run_cache_task_verify.sh`：**37/37**（新增单飞排队、取消后队列接续、
  排队任务真实落盘三组断言）。
- UI 回归 `run_cache_ui_verify.sh`：**11/11**（刷新恢复、无网络失败、无 console error）。
- 流畅度 `run_render_smooth.sh`：**7/7**——10s 窗口 7 次请求（≈1/s）、
  **主线程阻塞 >50ms 为 0**（全会话 0）。
- 单测 13/13；`npm run build` exit 0。

## 防再发（规则已写入 AGENTS.md §5）

- **单飞呈现**：进度类任务的端点只返回「当前一个」结果；执行侧单飞（同一时刻至多
  一个 worker），多任务一律排队 FIFO。
- **进度变化零派生请求**：轮询周期内只允许轮询本身的请求；任何重清单刷新只能由
  任务终态等**离散事件**触发，不得由进度变化触发。
