# BUG-260: 分集行把槽位标签渲染两遍 —— `S1E3 S1E3 4:26`，且照片集退化成「🖼 🖼」

- 状态: open
- 发现日期: 2026-10-10
- 模块: shell
- 严重程度: mid
- 登记: 主理人跑 BUG-254 验收时从实测读数发现（用户未报）。取证脚本
  `tauri-shell/verify/verify_bug_254_nobytes_visibility.cjs` 的行文本读数。

## 现象

剧集详情「分集列表」每一行把同一个槽位标签渲染**两次**：

| 分集 | 实测行文本 | 应为 |
|---|---|---|
| `epId=654`（无字节） | `S1E3S1E3未缓存` | `S1E3 未缓存` |
| `epId=652`（有字节带时长） | `S1E1S1E14:42` | `S1E1 14:42` |

照片集更退化：左列是 `🖼` 图标、中列再渲染一次 `episodeSlotLabel(ep)`，视觉上就是「🖼 🖼」。

## 根因（代码事实）

`tauri-shell/src/components/media/SeriesDetail.tsx` 的分集行是三列栅格
（`:568` `grid-cols-[auto_1fr_auto]`）：

- **左列** `:574-578`：`{photo ? '🖼' : episodeSlotLabel(ep)}` —— 槽位标识；
- **中列** `:579-585`：`{shouldRenderEpisodeTitle(ep, detail) ? ep.title : episodeSlotLabel(ep)}`。

`shouldRenderEpisodeTitle`（`src/lib/episodePresentation.ts:30-33`）判据是
「`ep.title` 非空 **且** 不等于剧集标题」。BUG-246/BUG-200 落地后「集不能没有标题」，
无标题分集的 `ep.title` 被**回填成槽位标签本身**（如 `"S1E3"`）⇒ 该判据为 `true` ⇒ 中列渲染
`ep.title` = 槽位标签 ⇒ 与左列逐字重复。

两处渲染**不是同一个表达式的重复调用**，而是「槽位标签」与「标题」两列都拿到了同一个字符串，
且判据只挡「标题 == 剧集标题」，**没挡「标题 == 槽位标签」**。

## 与 BUG-254 的关系（边界）

两行 `:574-585` 在 BUG-254 提交（`87a2683`）中均为**未改动上下文**（diff 里以空格前缀出现），
故本条是**既有缺陷**，由 BUG-254 的验收读数暴露，**不是 BUG-254 的回归**。

## 修复方向（待派工）

1. `shouldRenderEpisodeTitle` 增加一条判据：`ep.title !== episodeSlotLabel(ep)`
   —— 槽位标签已在左列展示，中列不该重复；这是「让错误状态不可表达」的正解（判据本身拒绝
   「标题就是槽位标签」这种无信息量的展示）。
2. 照片集：中列对 `photo` 分支不应再渲染槽位标签（左列已是 `🖼`），随第 1 条一并解决。
3. **不得**回退 BUG-200 的「集不能没有标题」：标题回填仍要保留，只是不重复**展示**。
