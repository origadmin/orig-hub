# BUG-414: 主卡片「删除剧集」与次卡片「从剧集删除」逻辑混乱

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: shell
- 严重程度: mid

## 现象

主卡片的「删除剧集」与次卡片的「从剧集删除」两个删除动作语义不清晰、边界混乱，
用户无法区分两者的作用对象与后果，需要厘清语义边界与归属。

## 根因（实测，不是猜）

两颗按钮其实是**同一类操作的两个粒度**：都只拆编排、**都保留内容条目**
（`media.confirmDeleteSeriesHint` 明写「剧集内的内容条目会保留在资料库（变为散片）」，
`media.episode.removeFromSeries` 明写「内容保留在资料库」）。但界面上：

| 位置 | testid | 可见文案 | 宽度 |
| --- | --- | --- | --- |
| 主卡片（剧集级） | `series-delete` | 删除剧集 | 62px |
| 次卡片（单集级） | `episode-remove` | 从剧集中移除（内容保留在资料库） | **218px** |

问题不在「语义真的不同」，而在**文案不同构**：

1. 一侧叫「删除剧集」——「删除」在别处（文件域 `item-detail-delete`）是**真删文件**，
   于是它被读成「比另一边更重」，实际后果却一样轻；
2. 另一侧把整句解释塞进按钮里，218px 成为动作条里最宽的一颗，把 编辑/挂图/查看/上移/
   下移 全挤到左边；
3. 两颗按钮**都没说粒度**（整部 vs 本集），而粒度才是它们唯一的真实差别。

## 修复（i18n + title，零逻辑改动）

统一成「动作 + 粒度」同构：

- `media.series.delete` = 「删除剧集」（不变），新增 `media.series.deleteHint`
  = 「整部剧集连同分集编排一起删除；内容条目保留在资料库（变为散片）」挂 `title`；
- `media.episode.removeFromSeries` = 「从剧集移除本集」（原为
  「从剧集中移除（内容保留在资料库）」），新增 `media.episode.removeFromSeriesHint`
  = 「只把这一集移出剧集；内容条目保留在资料库，不删文件」挂 `title` / `aria-label`。

接线点六处（一次改齐，不留一处旧文案）：`SeriesDetail`（`series-delete` /
`episode-remove`）、`SeriesHero`（`series-delete`）、`SeriesCard`（`series-card-delete`
的 title + aria-label）、`EpisodeExpanded`（`episode-remove`）、
`EpisodePhotoGrid`（`episode-photo-remove-*` 的 title + aria-label）。

**不动行为**：两个动作的端点、级联、确认弹窗全部原样 —— 用户报的是「分不清」，
不是「删错了」。
