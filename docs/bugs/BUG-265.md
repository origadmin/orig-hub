# BUG-265: 剧集内页「来源」块对所有剧集彻底消失 —— BUG-210 把「信息（正在从哪播）」与「控件（切换备用源）」合并成同一个门控

- 状态: fixed
- 发现日期: 2026-10-10
- 模块: shell
- 严重程度: mid

> 来源：用户报告「**视频来源问题没有解决，之前有的，现在来源又没有了。**」（同一诉求的第二次报告）

## 现象

### 现象 1：「来源」块对任何剧集都不渲染 —— 不是偶发，是必然

门控表达式（`tauri-shell/src/components/media/SeriesDetail.tsx:738`）：

```tsx
{(cur.sources ?? []).length > 0 ? (
```

生产库只读实测（`%APPDATA%\com.origadmin.orighub\tg\store.db`）：

| 表 | 行数 |
|---|---|
| `media_episode_source`（备用源表） | **0** |
| `media_episode` | 178 |
| `media_series` | 45 |
| 有来源行的 distinct `episode_id` | **0** |

⇒ 45 部剧的每一集 `sources.length == 0` ⇒ `0 > 0 = false` ⇒ 该块 **0/45 部剧渲染**，且**永不进入 DOM**（非 `hidden`、非 `opacity-0`）。

### 现象 2：用户说的「之前有的」有确切的分界点（git 取证）

`git log -S '(cur.sources ?? []).length > 0' -- tauri-shell/src/components/media/SeriesDetail.tsx` 命中 3 个提交：

| 提交 | 对「来源」块做了什么 |
|---|---|
| `feef4e8`（BUG-181） | 只给**内层 `<ul>`** 加门控；**块整体仍无条件渲染** |
| `5b1358b`（BUG-198，09-30） | 只去噪（删 `cur.ref` 行、删 `#itemId`、两行徽标合并成一行）；**块仍无条件渲染** |
| **`384db56`（BUG-210）** | **引入外层整块门控**：before = `<div …>{sourcesTitle}…</div>`（无条件）；after = `{(cur.sources ?? []).length > 0 ? (<div …>…</div>) : null}` |

⇒ **`384db56` 就是「之前有、现在没有」的分界点。** 用户报的是**真实变化**，不是记忆错乱。

### 现象 3：唯一残存的落点是一行小灰字，用户认不出那是「来源」

`SeriesDetail.tsx:648-652`（标题行 meta，**该 `<span>` 恒渲染**）：

```tsx
<span className="shrink-0 text-[11px] text-muted">
  {!isPhotoEpisode(cur) && cur.duration != null && hasMediaBytes(cur) ? `${fmtDuration(cur.duration)} · ` : ''}
  {cur.source ? `${t(sourceLabelKey(cur.source))} · ` : ''}#{cur.itemId}
</span>
```

即：信息退化成 `12:34 · TG · #394` 里的一段。**没有「来源」二字**，没有区块标题，视觉权重与「时长 / 条目号」同级。

### 现象 4：播放页完全没有来源落点

- `tauri-shell/src/components/media/VideoPlayer.tsx`：全文无 `source` / `sourceLabelKey` / TG-local 文案 ⇒ **不显示来源**。
- `tauri-shell/src/components/MediaViewer.tsx`：`cur.source` 只在 `:246` 用于重缓存，**不渲染**。

⇒ 「我正在从哪播」在全应用只有剧集内页标题行那一处，且只剩小灰字。

## 根因

### 根因 1：BUG-210 把「信息」与「控件」合并进了同一个门控

- 「来源」块里其实装着**两类东西**：
  - **信息**：当前播放来源（主版本行，`:742-750`，来源词在 `:748`）
  - **控件**：备用源列表 + 切换 / 摘除（`<ul>`，`:752-775`；`data-testid` 只有 `episode-source-switch`(`:763`) 与 `episode-source-detach`(`:771`)）
- BUG-210 的设计原则是 `docs/design/episode-internal-ia-v2-2026-09-29.md` §5 S4「**无备用源 ⇒ 来源区整块不渲染**」（原则「无选择即无控件」）。
- **但「无选择即无控件」只对「控件」成立，对「信息」不成立**（BUG-148：实现约束 ≠ 产品信息；能力边界只在用户正因此受阻时出现）。当前播放来源是**信息**，它不因「没有可切换的备选项」而失去意义。
- BUG-210 把两类东西**一起**门控掉，于是「没有备用源」这个**控件侧**的事实，把**信息侧**也一起删了。

### 根因 2：BUG-210 的自我论证是「信息可达」，而用户要的是「信息可见」

`docs/bugs/BUG-210.md:33` 原文理由：「『正在从哪播』已由标题行 meta 的 source 徽标（`:557-560`）承载，故门控不丢失该信息」。
⇒ **信息在 DOM 里可达 ≠ 用户能看见它。** 实测退化成一行小灰字（现象 3），且用户连续两次报告「来源没有了」。
⇒ 这条论证在**代码层成立、在产品层被证伪**。

### 根因 3：生产库备用源表 0 行，使门控退化为「永久隐藏」

BUG-261 现象 3 已登记：`media_episode_source` **0 行**，备用源功能在生产库里**从未被使用**。
⇒ 即使门控逻辑本身「正确」，它与真实数据组合后的**净效果 = 功能对全部用户永久不可见**。这是「判据在空集上退化」的典型形态。

## 修复方向（未实施；≥2 实质选项 + 1 个「不做」）

### 选项 A（推荐）：把块拆成「信息段」与「控件段」，各自门控

- **信息段**（恒渲染）：区块标题 + 「当前播放来源」行（来源词用 `sourceLabelKey`，无来源时显示 `local`）。
- **控件段**（`(cur.sources ?? []).length > 0` 门控，保持 BUG-210 原样）：备用源 `<ul>` + `episode-source-switch` + `episode-source-detach`。
- `涉及:` `SeriesDetail.tsx`（`:732-780` 拆两层门控）；i18n 需确认 `media.episode.sourcesTitle` / `sourcePrimary` 语义是否需拆成两键。
- `量化:` 拆 1 个块、门控从 1 层变 2 层；`data-testid` 新增 1 个（信息段容器）；既有 2 个 testid 不动。
- `回归风险:` 低 —— 控件段行为与 BUG-210 完全一致（无备用源时仍不渲染），只是信息段回来了。
- `后果:` 用户始终看得到「在从哪播」；「无选择即无控件」不被回退。

### 选项 B：整块恢复恒渲染（回到 BUG-198 形态）

- `涉及:` `SeriesDetail.tsx` 去掉外层门控。
- `量化:` 删 1 层门控。
- `回归风险:` 中 —— BUG-210 的原始诉求（无备用源时不要出现一整块空展板）**回归**。
- `后果:` 信息回来了，但「无选择却有控件标题」的噪声也回来了。

### 选项 C：维持现状，只把标题行 meta 的「来源」做显眼

- `涉及:` `SeriesDetail.tsx:648-652`（加「来源：」前缀或独立徽标）。
- `量化:` 改 1 处 JSX + 可能 1 个 i18n 键。
- `回归风险:` 低。
- `后果:` 最省事，但仍把来源塞在元信息行里，不是用户认得的「来源区块」。

### 选项 D：不做

- `涉及:` 无（0 行改动）。`量化:` 0。`回归风险:` 无。
- `后果:` 45/45 部剧永远看不到「来源」，用户第三次报告可预期。

## 修复后必须满足（可证伪判据，预先声明）

1. **无备用源**时（`media_episode_source` 0 行），剧集内页仍存在**可见的**「当前播放来源」信息，且其可见文案包含来源词（`TG` / `本地`），**不是**只剩 `#<itemId>`。
2. **无备用源**时，切换 / 摘除控件**不得出现**（`episode-source-switch` / `episode-source-detach` 命中 0）—— 即 BUG-210 的合理部分不被回退。
3. **反向证伪**：把「当前播放来源」也纳入 `(cur.sources ?? []).length > 0` 门控 → 判据 1 必须 FAIL。
4. **有备用源**时（临时挂一个再验），切换 / 摘除可用且行为与 `384db56` 之前一致。
5. 判据 1 / 2 必须在**真实 UI** 上验（BUG-156），用 `getComputedStyle` 判定可见性，不读 className。
6. 不得删除 `episode-source-switch` / `episode-source-detach` 两个既有 `data-testid`（BUG-149 / BUG-182 验收锚点）。
