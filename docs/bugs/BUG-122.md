# BUG-122：没有转码 / remux，也没有可播性探测 —— 部分格式下完也播不了

- 状态: open
- 严重程度: low
- 模块: engine
- 发现日期: 2026-09-22

## 现象

某些容器 / 编码（HEVC、部分 MKV）**下完了也播不了** —— 播放器直吃原始文件。

## 取证

```
grep -E "ffmpeg|transcode|remux"   （全仓）
→ 无任何转码 / remux 实现
```

## 为什么严重度定 low

它只在「S0（统一投递 + 背压）做完之后仍然播不了」时才成为瓶颈。在背压没修之前，
把问题归给编码会**修错地方**（BUG-034 教训：**先量真实上屏帧与 `videoWidth`**，
`videoWidth=0` 才是编码问题；`readyState` 满格不等于能播）。

## 修复方向

**先做能力探测，不引入全量转码**：

1. 探测容器 / 编码可播性（`probe_mp4_codec.py` 已有轨道与 codec 探测能力）；
2. 不可播时**明确告诉用户**（而不是黑屏或静默失败），给出可行动信息；
   参考 BUG-034 定的要求：解码异常不许静默，文案要给可行动指引；
3. 只有探测确认「确实有相当比例内容不可播」时，才评估按需 remux。
   CPU / 磁盘成本很高，先探测再决定。

## 注意

Playwright 自带 Chromium **不含** HEVC/AAC 等专有编解码器，其表现 ≠ WebView2。
涉编码的判断必须用 `BROWSER=msedge`（与 WebView2 同引擎），否则结论不可信。

## 关联

- BUG-034（解码异常不许静默、判据必须是 `videoWidth`）、BUG-114（先修背压再谈编码）。
