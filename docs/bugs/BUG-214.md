# BUG-214: 剧集墙多选只有「合并/清空」，缺基础批量操作（批量删除必须补），选择条固定顶部随滚动丢失

- 状态: fixed
- 发现日期: 2026-10-08
- 模块: shell
- 严重程度: mid

## 现象

媒体库剧集墙勾选 ≥2 条剧集后，选择条（`series-selection-bar`）只提供两个动作：
「合并剧集」「清空选择」。用户指出：多选场景必然需要基础批量操作，**批量删除是必须有的**；
其余批量能力缺失。同时选择条位置固定在内容区顶部普通流内，勾选视口外/下方的卡片后
向上浏览时选择条已滚出视野，动作条不可达 —— 位置需要重新评估（顶部/底部/左侧/右侧均可）。

## 根因

- BUG-186 落地多选时只覆盖了「合并」单一场景：
  `tauri-shell/src/components/MediaLibraryPanel.tsx:1127-1158` 的 `series-selection-bar`
  仅挂 `setMergeMultiOpen(true)` 与 `clearSeriesSelection`，无其他批量动作。
- 选择条渲染在 `overflow-y-auto` 内容容器（`MediaLibraryPanel.tsx:1122`）**内部顶部的普通流**里，
  非 sticky / 非 floating —— 长列表滚动后不可见。
- 对照 items 视图工具栏（`MediaLibraryPanel.tsx:925-969`）已有：加入剧集 / 批量标签 / 移除 / 清空，
  剧集墙没有对应物。
- 后端剧集域端点均为**单数**：`deleteSeries`（`tauri-shell/src/api/media.ts:422` →
  orig-tg `Store::delete_series_explicit`，`download-engine/crates/orig-tg/src/media.rs:2603`）、
  `setSeriesTags`（`api/media.ts:426`）；批量端点仅 `mergeSeriesMulti`（`api/media.ts:479`）
  与导出（`previewExport(seriesIds?)` / `exportMedia` 原生支持多剧集，`api/media.ts:332/362`）。

## 复现

媒体库 → 剧集墙 → 勾选 ≥2 条剧集 → 动作条只有「合并剧集/清空选择」；
勾选后向下滚动网格，动作条随之滚出视野。验收脚本在修复阶段按 UI 验收铁律
（Playwright 真实截图 + `data-testid` 导航）随修复提交入库。

## 修复（前置需求方案 —— 缺失批量功能评估，2026-10-08）

- **P0 批量删除剧集（用户点名必须）**。
  语义已核实：`Store::delete_series`（`media.rs:2584`）只删 `media_episode` 位置行 +
  `media_series_tag` 关联 + `media_series` 行，**不删 `media_item`、不回收字节**
  （符合 AGENTS.md §5「删除联动（单向）」：清组不删条目）。
  前端必须两步确认（列出将删剧名与集数 + 明示「条目与文件保留、仅解除归组」）。
  实现取态：先循环单数端点（选中量级小）；若实测卡顿再按「一动词一端点」提批量端点。
- **P1 批量打标**：复用 `BulkTagDialog` 形态，落 `setSeriesTags` 循环（与 items 批量打标同款）。
- **P1 批量导出**：`previewExport(seriesIds)` / `exportMedia` 已原生支持多剧集，只缺入口。
- **不做**：剧集→剧集「批量加入剧集」（与合并语义重叠且方向混乱）；
  批量改名/改类型（低频，单条编辑入口足够）。
- **位置评估（用户提出顶/底/左/右均可，按实际评估自决）**：采用**底部悬浮动作条**
  （floating action bar，浮在网格上方、距底约 16px、水平居中）。理由：
  ① 顶部条随滚动丢失是本 BUG 现象之一，sticky 吸顶仍常驻占一行、挤压网格高度；
  ② 批量动作发生在「选完之后」，视线焦点在网格内，底部条离选择区更近；
  ③ 左/右竖条压缩 `auto-fill` 网格可用宽度，且与左侧剧集侧栏 / 滚动条冲突。
  items 视图顶部工具栏条不动（它挂在既有工具栏行内，是工具栏扩展语义，不随滚动丢失）。
