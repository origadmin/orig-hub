# BUG-019: 内容归入多个剧集时，列表出现重复条目（JOIN 扇出）

- 状态: fixed
- 发现日期: 2026-09-17
- 模块: engine
- 严重程度: mid

## 现象

内容墙里同一条媒体重复出现多次；浏览器控制台报
`Encountered two children with the same key, 160`。
列表返回条数（97）大于真实内容数（94），分页计数随之失准。

## 根因

`crates/orig-tg/src/media.rs` 的内容行投影用 LEFT JOIN 取剧集归属：

```sql
FROM media_item i
LEFT JOIN media_episode e ON e.item_id = i.id
LEFT JOIN media_series s ON s.id = e.series_id
```

一条内容可同时被编入多个剧集（种子数据中 `scene_04_city_night.png` 同时命中
`05_images` 图集与 `city` 合集），JOIN 因此产生多行，前端以 `key=item.id` 渲染即冲突。

## 复现

```bash
python verify_shots/probe_fixes.py     # 修复前 FAIL: n=97 dups=[160,152,146]
```

## 修复

投影改为**标量子查询**，保证恒定一行一内容：

```sql
(SELECT e.series_id FROM media_episode e WHERE e.item_id = i.id
  ORDER BY e.season, e.episode_no LIMIT 1) AS series_id
```

多剧集归属取「季/集号最小」的那一个作为展示归属，语义确定且稳定。

验收：`probe_fixes.py` 断言 `无重复 id` + `列表长度 == reported total`。

- 与前端 React `key` 稳定性约束相关：后端契约须保证行唯一
