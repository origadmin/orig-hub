# BUG-198 剧集内页「来源」是信息展板而非播放来源切换器：塞了 ref/路径/内部 id 噪声

- **状态**: fixed
- **发现日期**: 2026-09-30
- **模块**: shell
- **严重程度**: high

关联用户长期抱怨「来源混乱（要的是切换视频，实际混乱）」「来源逻辑问题仍然没解决：这是切换视频来源用来播放的，不是需要任何信息」。
产品语义（用户裁定）：剧集内页的「来源」区是**切换视频来源来播放**的开关，
不是展示来源元数据的地方——用户不需要知道「这道菜怎么烧」（来源 ref / 下载路径 / 内部 itemId）。

## 现象

打开任一词集的右栏「来源」区，呈现的不是干净的版本切换器，而是信息噪声与两行长得几乎一样的徽章：

1. **主版本** 行：标题 + 一串内部 `#itemId`；
2. **来源** 行：`主版本` 徽章之外又一个「来源」徽章 + `cur.source` 标签 + **`cur.ref`（下载路径 / TG `chat:msg` 之类的「怎么烧的」细节）**；
3. 备用源列表里每行也带内部 `#itemId`。

用户原话：「去饭店吃饭还要知道这道菜怎么烧才能吃吗？」——`ref` / 路径 / 内部 id 全是用户播放时不需要的噪声，且两条徽章行外形相近、易混淆（哪行是「版本」、哪行是「来源」分不清）。

## 根因

`tauri-shell/src/components/media/SeriesDetail.tsx` 的「来源」渲染块（修复前 `:586-637`）：

- 多了一整条**单独的「来源」徽章行**，把 `cur.ref` 显式渲染出来 —— `cur.ref ? (<span title={cur.ref}>{cur.ref}</span>) : null`。
- 主版本行额外渲染 `#cur.itemId` 内部 id。
- `sourcesTitle` 徽章与 `sourcePrimary` 徽章两条视觉上几乎相同的 row 并列，造成「混乱」。

数据面：`MediaEpisode`（`api/media.ts:82-120`）有 `source?` 与 `ref?`；`EpisodeSourceRef`（`api/media.ts:125-129`）
**只有 `itemId` / `title?` / `kind?`**——备用源根本没有 origin 字段。所以 origin（TG/local）只能标在主版本上，
备用源只展示 title（已足以区分「哪道菜」）。

## 修复

把「来源」区从信息展板还原成**干净的播放来源切换器**（沿用 BUG-148 判据：实现约束 / 调试用信息不该常驻 UI）。
改动限于 `SeriesDetail.tsx` 的渲染块（`:586-630`）：

1. **删除** 单独的「来源」徽章行（含 `cur.ref` 渲染）——拿掉「怎么烧的」噪声。
2. **删除** 主版本行的 `#cur.itemId` 内部 id。
3. **合并** 为「主版本 = 当前播放来源」单行：标题 + 一个小的 origin 标签（TG/local，**只标「哪道菜」不标 ref 路径**）。
4. 备用源列表保留，每行只留 title（无内部 id）+ **「切为主版本」**（切主 = 切换后「播放」按钮就播这版）
   + 「摘除」（管理动作，不删能力，遵守 BUG-149）；`data-testid`（`episode-source-switch` / `episode-source-detach`）沿用不变。

未动任何能力：切主 / 摘除 / 播放全部保留，只是从「默认铺满信息」变成「显式、聚焦切换」。
不引入新 i18n 文案（保持 `media.episode.{sourcesTitle,sourcePrimary,switchPrimary,detachSource}` 不变）。

## 关联

- BUG-148（实现约束 ≠ 产品信息）：`ref`/路径这类调试信息只在失败 / 受阻时出现，绝不当常驻 UI 构件。
- BUG-197（同文件同日）：剧集内页默认编辑态；本档是「来源」区同一次清整的延续。
- `EpisodeSourceRef` 无 origin 字段 —— 备用源不标来源是数据面限制，不是疏漏。
