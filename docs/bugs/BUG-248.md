# BUG-248: 入库顺序倒置——「先入信息、再入字节」未兑现：入队只写任务行，媒体库条目要等 worker 轮到才登记

- 状态: open
- 发现日期: 2026-10-10
- 模块: engine
- 严重程度: high

## 现象

用户原文：「缓存→信息必然存在，先入信息→入库文件（队列）。当前流程完全违反这个意识。」

可观察的三段：

1. 点「加入媒体库」之后，**媒体库里没有这条内容**——它只存在于入库流水线的一行任务里；
2. **排队期间**（前面还有任务在跑时，可能几分钟到几十分钟）媒体库依然空白，
   用户无法确认「这批东西到底进没进来」；
3. 直到 worker 轮到这条并开始处理，条目才出现。

即当前顺序是「**入队 → 等 → 下载字节 → 顺带登记信息**」，与既定方向相反。

## 根因

**T0 事实登记（`media_item` 行）的调用点只在 worker 逐条处理路径上，不在入队路径上。**

- `IngestCtx::register_item()`（`download-engine/crates/orig-tg/src/routes.rs:1538`）就是
  T0 登记内核：写 `media_item`（`file_path=NULL` 待回填 = 字节未落、事实先在），
  注释自述「T0 事实登记：media_item 行（`file_path=NULL` 待回填）」。
- 但它的**唯一调用点是 worker**：`routes.rs:1922`（已缓存分支）与 `routes.rs:1940`
  （图片/视频分支，`cache_one_bytes` 下载之前）——两条都在
  **任务已转 `running` 之后**才执行。
- 入队端点 `POST /api/tg/cache/tasks`（`routes.rs:1122`）只写 `cache_task` 一行，
  **不登记 `media_item`** ⇒ 排队期间该内容在媒体库里根本不存在。

**这是 BUG-170 已裁定方向的「另一半」仍未兑现：**

- BUG-170 裁定：元数据登记瞬间完成，耗时的只有视频/图片字节
  （「先登记（`bytesPresence=absent`）→字节异步补齐」，入库不得等到任务结束）。
- BUG-246（本轮已 closed）只补齐了**消息元数据**那一半：入队即补 `media_message` 行，
  让排队任务能取到 caption。
- **条目本身（`media_item`）这一半没跟上来** —— 行仍然只在 worker 启动时出现。
- 连带后果：BUG-220 的「行内标题可辨认」只能在**流水线面板**里兑现，
  媒体库侧依然是「排队 = 不存在」。

## 复现

1. 让 worker 占用住（先入队一个较大的任务）；
2. 对若干条内容点「加入媒体库」（它们会排到 `queued`）；
3. 打开媒体库 → 这些条目**查不到**；打开入库流水线 → 只有任务行。

## 修复方向

**把 T0 登记前移到入队时刻**（与 BUG-170、BUG-246 同一条方向线，不是新方向）：

- 从 `IngestCtx::register_item()` 抽出与 `IngestCtx` 无关的登记内核（入队时没有
  `IngestCtx`：没有 slot/series 上下文），例如
  `async fn register_media_item_t0(st: &Arc<AppState>, chat_id: i64, msg_id: i64, photo_rule: bool)`；
  `register_item()` 改为调用它，**单一真源，禁止两处各写一份**（AGENTS.md §2）。
- 入队处理器（同 BUG-246 的那个 `tokio::spawn`，在 `cache_task` 落库之后）为任务内
  每条消息调一次：已存在（`item_id_by_ref` 命中）即跳过；登记失败**不阻断入队**（同
  BUG-246 的容错语义：只影响「先在」，不影响字节）。
- kind/caption 来源：`media_message` 行 —— BUG-246 已保证入队时补行，故入队时刻即可判
  kind 与标题（`meta_kind` / `split_caption`，与 `register_item` 同一把尺子）。

**必须一并定死的边界（避免引出新 BUG）：**

1. 登记后条目是 `bytesPresence=absent` 态。媒体库必须能**如实呈现**「信息已在、字节未到」，
   不得渲染成可播放条目；呈现能力需核对（BUG-240 的观测里已有 80/320 条缺字节条目，
   说明该态存在，但要确认卡片不谎报）。
2. **删除/取消任务不得顺手删条目**：条目是媒体库的事实（删任务 ≠ 删内容）。
   清理入口归 BUG-249 的批量动作，不在本条做。
3. **存量不回填**：与 BUG-246 同例，只对新入队生效；历史排队任务仍由 worker 兜底登记。
