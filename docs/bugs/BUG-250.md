# BUG-250: 媒体库主页在「无字节/无图」时仍发起 raw 请求（video 必 404），且主页不体现内容存在性

- 状态: open
- 发现日期: 2026-10-10
- 模块: engine+shell
- 严重程度: high
- 排期: 2026-11-10

## 现象

用户原文：「有视频没视频要在主页体现，有图片没图片也要主页体现（主要是主页浏览图问题），
当前请求会造成 404（没图的情况）。」

可观察：

1. 打开媒体库主页，无字节/无封面的条目**照样**发起 `GET /api/media/items/:id/raw`，
   video 类直接 **404**（控制台报错刷屏）；
2. 主页看不出一条内容「到底有没有视频 / 有没有图片」——剧集卡只显示名称与计数，
   条目卡只有类型标签；对无图条目没有明确空态。

## 根因

**B-1（404 的直接根因）：封面生成 effect 不判「有没有字节」，只为「渲染期」做了门控。**

- `tauri-shell/src/components/media/MediaCard.tsx:149-186`（video 抽帧）与
  `:188-207`（photo 缩略图）两个 `useEffect` 的判据只有 `item.kind !== 'video' / 'photo'`，
  **完全不判 `playable`**；而 `playable = hasMediaBytes(item)`（`:218`）直到渲染期
  （`:254` `{playable ? … : 无字节占位}`）才生效。
- 于是 effect 在**渲染之前**就已经对无字节条目发请求：
  `generateVideoPoster(mediaItemUrl(item.id), 1, 480)`（`:160`）/
  `generateImageThumb(mediaItemUrl(item.id), 480)`（`:193`）。
- 实测（本机 live，2026-10-10）：
  - `GET /api/media/items/689/raw` → **404**（该条 `kind=video`、`bytesPresence=missing`）；
  - `GET /api/media/items/686/raw` → 200 `image/jpeg`（photo + missing 走现场代理 TG 缩略图，BUG-049 规则）。
  - 库内 335 条的分布：`photo/missing` **83** 条、`video/missing` **5** 条、
    `video/present` 且无 poster **123** 条。
  ⇒ 每次进主页，这 88 条「不可用条目」都各发一次 raw；video 那批必 404。
  这与 BUG-239 的「封面请求随条目数线性增长」同源，但本条是**必然失败**的那一部分。

**B-2（存在性不可见）：剧集卡不承载「有没有视频 / 有没有图片」。**

- 条目卡有类型标签（`item-kind`）与无字节占位（BUG-080 的 `item-nobytes`，`:301`），
  但**剧集卡**（`SeriesCard.tsx` / `SeriesHero.tsx`）只有 `kindLabel`（series/collection/album）
  与封面，不体现该剧集内的内容构成。
- 后端 `SeriesView`（`download-engine/crates/orig-tg/src/media.rs:776`）只有
  `item_count`（`:705`）与 `episode_count`（`:791`）——**没有按类型统计**，
  所以前端**拿不到**「这个剧集有没有视频、有没有图片」。
- 无图条目在主页只表现为**空框**（`:275-279` 的 `KIND_ICON` 或 `genFailed` 后的 🚫），
  即「没图」与「图还没加载出来」不可分辨。

## 复现

1. 打开媒体库主页（items 视图与剧集墙分别看）；
2. 打开浏览器网络面板：对 `bytesPresence=missing` 的条目可见 raw 请求，video 那条 404；
3. 找一条既没有视频也没有图片的剧集 —— 界面上无从分辨。

## 修复方向

1. **封面 effect 补 `playable` 门控**（消除必然 404）：
   无字节 ⇒ 不发任何 raw/抽帧请求，直接进入空态呈现。
   注意 `playable` 需进入 effect 依赖，且换条目时要正确重置（现有 `startedRef`/`genFailed` 机制保留）。
2. **主页体现内容存在性**：
   - 后端 `SeriesView` 增按类型的构成统计（如 `videoCount` / `photoCount`，
     或 `kinds: ["video","photo"]`）——由剧集内条目一次 `IN` 查询聚合，**不要在渲染期按卡 N 次查**；
   - 前端剧集卡显式展示「视频 N / 图片 M」，无视频或无图片时同样如实显示（不得渲染成空）；
   - 无图条目（无 poster 且不可生成）显示**明确空态**，与「加载中」可分辨。
3. 判据（必须可自动化）：
   - 主页加载后对**无字节条目**的 raw 请求数为 **0**（CDP 网络计数），且 video/missing 条目不再出现 404；
   - 有内容条目回归不受影响（封面照常出现）；
   - 剧集卡上「视频/图片」读数与本剧集实际条目构成一致（具体数字比对）。

## 关联

- BUG-080（无字节占位：只做了渲染期门控，effect 漏了 —— 本条是它的补漏）
- BUG-239（封面请求随条目数线性放大；本条是其中「必然失败」的子集）
- BUG-240（缺字节条目不可辨识）、BUG-214（多选批量操作）
- BUG-248（入队即登记条目会让 `bytesPresence=missing` 的条目**变多**，本条更必须修，
  否则修复 248 会放大 404 噪声）

## 修复

**1. 封面的两个 effect 补 `playable` 门控**（`MediaCard.tsx`）：

- `playable = hasMediaBytes(item)` 上移到两个 effect **之前**（原先只在渲染期 `{playable ? …}`
  分支生效，effect 先于渲染跑）；
- video 抽帧与 photo 缩略图两个 effect 各加 `if (!playable) return`，并把 `playable` 进依赖；
- `thumbSrc` 不再对无字节条目回退 `mediaItemUrl(id)`（渲染期已走 `item-nobytes` 占位，
  这里再兜一层，任何路径都不把 `/raw` 当可用图源）。

**2. 剧集卡按后端事实门控 + 显示内容构成**（`SeriesCard.tsx` + `media.rs`）：

- `SeriesView` 新增 `video_count` / `photo_count`（按 `kind` 对剧集内条目计数）与
  `cover_has_bytes`，后者与 `cover_item_id` **同优先级**（photo 优先、回退首集）计算，
  避免「封面判了 A、可用性判了 B」；
- 前端 `coverHasBytes === false` 时不对 video 封面抽帧（老后端不下发该字段时按既有行为走）；
- 卡片新增 `series-content-kinds` 读数「视频 N · 图片 M」，0 也如实显示；
  字段缺失（老后端）时不渲染，不编造 0。
