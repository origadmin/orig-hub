# BUG-070: 播放页不是只读的（有标题编辑按钮）+ 右侧列表装饰性播放图标 + 进播放页重复拉同一部剧集

- 状态: fixed
- 发现日期: 2026-09-19
- 模块: shell
- 严重程度: mid

## 现象

用户第 9 轮（三问同轮提出）：

> 「② 播放页面仍然有问题. 右边列表有个**完全无用的播放 ICON**. 播放页面进入会进行**大批量相同请求**.
> `http://127.0.0.1:9877/api/media/series/xx` 请求了 8 次.
> ③ **播放是只读的,但是有个标题编辑按钮**.」

## 根因（三条，互相独立）

**① 播放器持有写入口。** BUG-054 为了让「播放页也能改标题」引入 `viewer.editable` +
`requestEditItem` 跨层回调，`MediaLibraryPanel` 在 `openViewer` 时按来源传 `editable`。
于是「播放器（只读消费者）」成了「编辑动作的发起者」—— 状态在 store 里可表达，
UI 就一定会渲出来。**只读是一次性的 props 判断，不是结构约束**，所以谁都挡不住它再被打开。

**② 装饰性图标。** `EpisodeList` 在**当前行尾部**渲染一个 `<Play>`，**没有 `onClick`**。
它长得像按钮、位置像按钮，但点了什么也不发生 —— 视觉承诺与行为不符。

**③ 同一部剧集被三个消费者各拉一次。** 剧集详情 `GET /api/media/series/:id` 的消费方：

| 消费者 | 位置 |
|---|---|
| 讲详情面板 | `MediaLibraryPanel.openSeries` |
| 进播放页 | `MediaLibraryPanel.playItems` |
| 侧栏 / 播放器标注 | `useSeriesDetail` hook（StrictMode 下双调） |

三处各自 `getSeries(id)`，**没有共享层** ⇒ 打开详情 + 进入播放的过程中同一部剧集被重复拉取；
React StrictMode 挂载两次再翻倍。实测 5 次（用户观感 8 次，量级一致）。

## 复现

1. 媒体库 → 打开剧集详情：Network 里 `GET /api/media/series/:id` 出现多次；
2. 点某集进入播放页：右侧分集列表当前行尾部有一个 `▶` 图标，点击无响应；
3. 播放页左上角有「编辑」铅笔按钮 —— 但播放页是只读的。

## 修复

### ① 播放页只读（结构性，不是加判断）

- `MediaViewer.tsx`：删除编辑按钮与 `onEditItem`；根节点加 `data-testid="media-viewer"`
  （供断言把作用域锚到播放器自身）。
- `store/useStore.ts`：删除 `viewer.editable`、`editItemId`、`requestEditItem`、`clearEditedItem`，
  `openViewer` 不再收 `editable` —— 让「播放页可写」这个状态**不可表达**。
- `MainLayout.tsx`：去掉 `onEditItem` 透传。

目的：不是「这次把按钮隐藏了」，而是**播放器结构上不再有写入通道**（原理优先于补丁）。

### ② 去掉装饰性播放图标

- `components/media/EpisodeList.tsx`：删除当前行尾部的 `<Play>`（无行为的控件不得长得像控件；
  行本身已是可点按钮）。

### ③ 剧集详情单一缓存源

- 新增 `src/lib/fetchCache.ts`：`cached(key, loader)` 会话内**共享同一个 Promise**
  （并发合流 + 结果复用），`peek(key)` 同步读，`invalidateCache(prefix?)` 显式失效；
  **不做时间过期** —— 数据变更一律由写操作显式作废，避免「陈旧窗口」这种不可解释的中间态。
- `src/hooks/useSeriesDetail.ts`：`loadSeriesDetail` 走缓存；`useSeriesDetail` 首帧直接
  `peek` 同步出内容（不闪空）；`peekSeriesDetail` 供播放器标注集号。
- `src/components/MediaLibraryPanel.tsx`：`openSeries` / `playItems` 改走 `loadSeriesDetail`；
  **`refreshAll` 改 `invalidateCache()`**（写操作后必须重取，缓存不得挡住刚保存的新值）；
  `loadSeries` / `loadMeta` 共用 `cacheKey.seriesList`（顺带消掉启动时的一次重复列表拉取）。

三项主诉各自的运行期断言：

- **只读**：播放页按钮集合实测 `["← 返回列表","","","","","1x","",""]` ——
  **自身不存在任何编辑入口**（作用域 = `[data-testid="media-viewer"]`）。
- **无装饰图标**：右侧分集行内 **svg 数 = 0**。
- **请求计数（按阶段，真实 wire）**：`A-open=1`、`B-play=0`（进播放页**零增量**）、`C-refresh=1`
  （保存后刷新 —— 写操作必须重取，缓存不得挡新值）；启动仅 1 次 `GET /api/media/series`。

### 断言口径（两次假阳性，已修）

首轮跑出 14/16，两条失败**均为断言自身缺陷、非产品缺陷**，修的是探针：

1. 「播放页无编辑入口」误报：我扫的是**整个 document**，而媒体库面板仍挂在播放器浮层**背后**
   （其卡片上的「编辑」按钮仍在 DOM）⇒ 改成把作用域锚到 `[data-testid="media-viewer"]`。
2. 「`series/xx` 请求 1 次」误报 2 次：我把 CORS **预检**计入真实请求
   ⇒ 计数前排掉 `initiator.type === 'preflight'`，并改为**阶段化计数**（A-open / B-play / C-refresh）。
