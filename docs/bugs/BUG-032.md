# BUG-032：旧库 + 新代码 → 服务健康但媒体库「全空」

- **状态**：fixed
- **日期**：2026-09-18
- **模块**：engine（媒体库 schema 迁移 / 启动期存储打开）

## 现象

服务 `/health` 返回 `{"status":"ok"}`，但数据面全空：

- `/api/media/stats` → `items=0 series=0 tags=0`；
- `/api/media/items` → `total=0`；
- `/api/tg/monitor/channels` → `[]`，`/api/tg/cache/tasks/all` → 计数全 0；
- 而磁盘上 `store.db` 明明有 **96 条 media_item / 6 个剧集 / 63 条分集 / 7 个标签**，
  文件 mtime 也不再变化。

写操作「成功」但落不到盘：`POST /api/media/tags` 返回 `{"id":1}`，
而库里既有 7 个标签、也不存在这个新标签 —— 全部读写都发生在一个**新库**上。

## 根因

`media::init()` 的建表批里混进了一条**依赖新列**的语句：

```sql
CREATE UNIQUE INDEX IF NOT EXISTS idx_media_series_source_key
    ON media_series(source_key) WHERE source_key IS NOT NULL;   -- 建表批内
...
ALTER TABLE media_series ADD COLUMN source_key TEXT;            -- 批之后才补列
```

`source_key` 只在批**之后**的 `ALTER TABLE` 里补。于是「旧库 + 新代码」首次启动时：

1. `conn.execute_batch(...)` 执行到该索引 → `no such column: source_key` → **整批失败**，
   放在它后面的 `media_episode` / `media_tag` / 其它索引一概没建；
2. `init()` 返回 `Err` → `Store::open` 返回 `Err`；
3. `main.rs` 当时**静默回落** `Store::open(":memory:")`；
4. 服务照常起、`/health` 照常 ok，但**所有数据落进内存空库** ——
   在用户眼里与「数据全没了」完全同形。

这是「静默降级」家族的典型：`build_client` 早已立下「不存在静默降级」的规矩
（BUG-023），但存储打开这条路径漏了。

## 修复

1. **迁移顺序**：该索引移出建表批，放到 `ALTER TABLE ... ADD COLUMN source_key` **之后**。
   规矩：建表批里只允许出现新旧库都存在的列。
2. **取消空库兜底**：`Store::open` 失败改为致命退出（新增 `EXIT_STORE_FAILED = 5`，
   打印实际库路径与原因），删除 `:memory:` 回落。理由与 `build_client` 同源 ——
   库打不开时「假装可用」比「直接不启动」贵得多：前者把 schema 错误伪装成用户数据丢失。

## 验收

- 新增单测 `media::tests::legacy_db_migrates_without_failing_open`：
  造一个**上一版 schema** 的库（`media_series` 无 `source_key`、`media_episode` 无 `description`）
  + 塞入旧数据 → `Store::open` **必须成功** → 列被补齐、索引建成、旧行仍在 →
  唯一索引真的生效（同 `source_key` 第二条被拒）→ 新库冷启动同样可用。
  该用例在修复前会失败（open 直接 Err），是防再发的机械证据。
- 真实旧库原地迁移：`store.db`（1.68 MB）在新代码上启动后
  `series cols` 多出 `source_key`，`items=96 / series=6 / tags=7` 全量可见，
  `/api/media/stats` 从全 0 变为真实计数，**0 条数据丢失**。
- 全量回归 `bash verify_shots/run_all.sh` → **ALL SUITES PASSED**。

## 关联

- BUG-023（TG 连接失败静默退化为 dummy）、BUG-021（CORS 静默失败）——
  同属「错误被伪装成正常态」家族。
- BUG-031（该缺陷由 BUG-031 的 `source_key` 迁移引入，并在其验收中被抓出）。
- 规则：**存储层 schema 变更必须配一条「旧库 → 新代码」的迁移单测**，
  且启动期依赖（库、会话、客户端）打开失败一律显式失败，禁止回落空实现。
