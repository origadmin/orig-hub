# BUG-364: 剧集「在 TG 中查看」冷面板定位竞赛误报 + 入口重复 + 播放按钮不按 kind 分支

- 状态: fixed
- 发现日期: 2026-10-21
- 模块: shell
- 严重程度: high

## 现象

用户报「按钮的问题」。取证发现三处独立缺陷，同一处界面（剧集详情）上同时可见：

1. **定位竞赛误报**（核心）：冷面板（面板停在别的频道）下点「在 TG 中查看」，20 页翻页预算被**空转 tick** 烧光——面板首屏要 4–19s 才到，而循环每 300ms 一轮、每轮都扣预算，约 6s 就判 `tg.locateFailed`。用户看到的是：`未能在 TG 面板定位到对应的来源消息` 的 toast 与「加载媒体中…」**同屏**，而消息实证在库（约第 7–10 页）。
2. **入口重复**：同一坐标三个同文案入口——来源块应用内跳转按钮 + 同行的 t.me 外链，文案同为「在 TG 中查看」；左栏选集器每行还有第三颗 10px 行级入口。用户分不出哪个会离开应用。
3. **播放按钮不按 kind 分支**：照片集（`kind=photo` 分集）主按钮显示「播放」+ Play 图标——错承诺（照片没有可播的流），且 `media.episode.viewImage` 键早已定义却没用上。

## 根因

1. `TgPanel.tsx` 定位循环把「没命中 + `hasMore`」一律当「该翻页」，且 `loadOlder` 的早退路径（面板未就绪/上一页在途/已无更多）**不翻页却照扣预算**——预算被空转烧光，首屏未到即误报。循环只区分「命中/未命中」，不区分「面板就没就绪」「面板加载失败」「用户已切走」这些**性质完全不同**的状态。
2. 入口去重历来只做「同 testid 不重复」，没有「同一坐标同一动作只留一个入口」的裁定；BUG-350 把来源块按钮降级为次要样式后，行级 10px 入口与外链同文案的问题没人收口。
3. 播放按钮的 onClick/title/icon/label 四个位置都不看 `kind`——照片与视频走同一条渲染路径，「播放」是写死的。
4. **渲染侧第二层缺陷（验收中曝光）**：`AlbumBubble` 的 memo 自定义比较器漏了 `highlighted`——定位命中时只有它翻转（false→true），比较器判「相等」⇒ React 跳过重渲染 ⇒ 相册根永远拿不到 `data-tg-highlight`，「在 TG 中查看」点了**不亮**。`MessageBubble` 走默认浅比较不受害，所以单条消息目标一直能亮、**相册内目标**不能亮——缺陷只在相册目标上现形，静态审查看不出来，被本登记验收探针（目标消息深度第 7 页、在相册里）正面抓住。

## 修复

**裁定**：定位循环四态分离（每态只做自己该做的事）；入口按「每颗来源一颗应用内入口」收敛；主按钮按 `kind` 分支。

- **`TgPanel.tsx`**：
  - `loadOlder` 改返回 `Promise<boolean>`（true = 这一轮真发起了一次翻页；早退/在途/无更多均 false），定位循环据此计预算——预算只对真实翻页生效；
  - 新增渲染期镜像 `feedReadyRef`（`!feedLoading && (feed.length > 0 || !hasMore)`）与 `feedErrorRef`；
  - 定位循环重写为四态：①命中⇒高亮+滚动+清焦点；②面板内容流失败⇒ surfaced 失败本身（`feedError`），不伪装「找不到」；③面板未就绪/已离开目标频道⇒只等待或静默取消，不扣预算；④就绪后仅真实翻页扣预算，预算尽才报 `tg.locateFailed`；
  - 历史状态栏加定位中指示（`data-testid="tg-locating"`，`tg.locating`）——等待不再无声；
  - `AlbumBubble` memo 比较器补 `a.highlighted === b.highlighted`（见根因 4）——高亮翻转必须穿透 memo，否则相册目标「点了不亮」。
- **`SeriesDetail.tsx`**：
  - 撤销行级入口 `episode-row-view-tg`（及 `epTgAt` 定义、`Send` import）——应用内跳转收敛为来源块「每颗来源一颗」（主版本行 + 各备用源行，入口贴着它解释的那条来源）；BUG-305 判据3 由本登记 supersede；
  - 主按钮按 `isPhotoEpisode(cur)` 分支：照片⇒「查看大图」（`media.episode.viewImage`）+ `ImageIcon` + 进图册灯箱；视频⇒原行为不变；
  - 两处 t.me 外链文案 `media.episode.viewInTg` → `media.episode.openInBrowser`（「在浏览器打开」）——testid/href 形状不变（BUG-285 ①a 不回归），①d 的文案值由本登记 supersede。
- **`i18n/locales/{zh-CN,en-US}.json`**：删 `media.episode.viewInTg`、加 `media.episode.openInBrowser`；加 `tg.locating`。
- **旧验证脚本同步**（supersede 网）：`verify_bug285_tg_source_link.cjs` 的 ①d 期望文案改 `Open in browser`；`verify_bug305_tg_jump.cjs` 判据3 行级入口期望从 `!== null` 改 `=== null`。
