## 现象

用户当前看到的前端与拍板后的目标 IA 之间存在结构性失配，且失配不止「少几个菜单」：

1. **一级导航只有三项**（全部 / TG / 设置），而拍板形态是**五项**（文件 / 下载 / Telegram / 共享 / 设置）。
   `ViewId = 'all' | 'tg' | 'settings'`（`tauri-shell/src/components/Sidebar.tsx:16-23`），
   「下载」至今**没有自己的落地页**，只能寄生在「全部」里。
2. **文件与下载共用一张任务表**：`MainLayout.tsx:177-189` 的 `baseVisible` 证明
   `view==='all'` 与三档下载过滤读的是同一份引擎任务列表 ⇒
   文件域里混着进行中任务、下载域里找不到独立入口。
3. **资料库（剧集/标签）被当作「全部」的子视图**（`MediaLibraryPanel.tsx` 的 `view` 三态），
   而非文件树下的一个分组；「未归档」无独立入口。
4. **侧栏无树**：无父行/子项/展开折叠结构，`RAIL_SERIES_LIMIT` 截断（BUG-259）后
   长列表的可达性靠「展开」按钮兜底，而非树形分组。
5. **TG 入口可被门控整体隐藏**：`resolveTgFeatureReady` 目前参与入口显隐 ⇒
   插件未启用时用户**看不到入口、也看不到引导**（BUG-094 的口径要改为只影响面板内容）。
6. **「在 TG 中查看」在桌面壳内无可达通道**（裸 `<a target="_blank">`，无 `on_navigation` 处理器）——
   与 BUG-285 同一处实现，本阶段只做 IA 搬迁，不重复修 BUG-285 的跳转语义
    （跳转重设计另见 `docs/design/tg-source-jump-2026-10-13.md`）。

## 根因

根因不是「导航写少了」，而是**前端从未按域（domain）划分**：

- 组件平铺在 `components/`（77 个前端文件无域归属，`01-frontend-architecture.md` 有全量处置表），
  状态集中在 `store/useStore.ts`，`view` 是一个自由字符串，任何面板都能把它改成任何值；
- 于是「下载中任务在哪」「文件域为什么有任务行」「未归档从哪进」这类**信息架构问题**
  在代码里没有对应结构可以回答，只能靠单个面板各自特判。

**本阶段不动根因本身**（域化拆分是 M0-T02/T03 的第一步，完整的后端/数据/插件分层见 M1/M7）。
M0 的边界是**把 IA 与外壳搬到位，数据流与业务逻辑一律「搬运不改写」**
（tasks.md 约定：允许移动/包裹/改导入路径，禁止顺手改数据流与业务逻辑）。

### 禁区（用户四轮裁定 §10.1，tasks.md §M0 引用）

1. **不改任何 API 端点**（M0 数据源仍在 orig-tg 的 `/api/media/*`，M1 才改向）；
2. **下载模块除导航外全部保留现状** —— `DownloadList` 卡片流、`DownloadItem` 悬停操作
   （暂停/恢复/取消/打开文件/打开目录/删除）、`DetailSheet`、`ContextBar` 逐档操作映射
   （清空仅已完成档）一律不动；
3. **不引入页内状态 tabs**（状态选择唯一载体是侧栏树）；
4. 来源筛选 chips 随 M3 接线引入，M0 不做。

## 复现

1. 启动前端（`npm.cmd run dev`，只起 5180）→ 侧栏只有「全部 / TG / 设置」三项；
2. 点「全部」→ 媒体墙里混入进行中下载任务（有进度条/速度的行）；
3. 想只看下载 → 只能用搜索/过滤，无「下载」这一落地页，也无「下载中/已暂停/已完成」三档；
4. 想找「未归档」内容 → 无入口（现状只能人眼扫 `series_id == null`）；
5. 停用 TG 插件 → 侧栏「TG」入口消失，用户没有途径知道它可被启用（对比目标态：入口常驻 + 引导卡）。

形态对照真值：`docs/design/module-restructure-2026-10-13/prototype/index.html`（v3）。
