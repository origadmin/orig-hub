# BUG-477: 底栏常驻「监控」按钮是错误理解造成的重复入口——频道属于监控，改的是频道

- 状态: fixed
- 发现日期: 2026-10-28
- 模块: shell
- 严重程度: mid
- 排期: 2026-10-28

> 来源：用户裁定「『监控频道』是完全错误逻辑，之前说的很清楚，**要改的是频道，频道属于监控**。
> 现在下面放一个监控（完全多余），完全违反设计简洁的核心逻辑。」

## 现象

1. 全局底部状态栏常驻一颗「监控」按钮（`StatusBarMonitor.tsx`，不论监控数多少都显示），
   点开下拉：监控频道列表 + 每频道「取消监控」按钮 + 回溯进度 + 新增计数。
2. 监控的管理能力**本就在 TG 视图的频道本体上**（频道开关 = 监控/取消，编辑频道 = 改监控对象）。
   下拉自己的提示都写着「在 TG 视图添加 / 管理监控频道」——即这个入口自身没有管理能力，
   只是重复展示 + 一个危险的快捷删钮。
3. 「取消监控」埋在底栏下拉里无任何确认（BUG-394 事故即验收脚本误点该钮**真删了监控频道**）。

## 根因

功能归属理解错误：把「监控状态」当成了一个需要常驻入口的独立功能域，在底栏另立按钮。
按用户裁定，**频道属于监控**——监控的管理动作全部归属 TG 视图的频道本体（在那里加/改/停），
底栏再放一个「监控」违反「一个语义一个入口」的简洁原则，且把破坏性动作（取消监控）
暴露在一个常驻、零确认的下拉里。

## 复现

任意视图下看底部状态栏：右侧常驻「监控 / 未监控 / 监控 {n}」按钮，点开即见频道列表与
「取消监控」钮——与 TG 视图内频道开关完全重复。

## 修复方向（已实施：整体拆除）

- 删除 shell 层组件文件 `StatusBarMonitor.tsx`（152 行，含下拉与「取消监控」快捷钮）；
  `MainLayout.tsx` 移除挂载点与 import（底栏右槽保留入库流水线 / 调试 / 连接状态）。
- 删除两个语言包共 24 个 `statusbar.monitor*` 键（`monitor` / `monitorCount` / `monitorNone` /
  `monitorTitle` / `monitorAbnormal` / `monitorDropdownTitle` / `monitorHint` / `monitorEmpty` /
  `monitorOffline` / `monitorUnmonitor` / `monitorBackfill` / `monitorNew`）。
- 监控状态的可见性由 TG 视图自身承担（频道开关即状态），不再有第二呈现面。

## 关联

- BUG-394（验收脚本误点「取消监控」真删频道）——事故现场即本档拆除的下拉内危险钮。
- BUG-169（连接状态唯一渲染点，底栏其余叶子不受本档影响）。
