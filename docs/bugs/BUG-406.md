# BUG-406: 剧集合并底部选中数量「2」语义不明、显示突兀

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: shell
- 严重程度: mid

## 现象
进入剧集合并流程后，底部显示一个数字「2」（表示当前选中数量），但该数字孤立出现、
无任何上下文说明它是什么、什么意思，用户难以理解其真正功能，体验突兀。

## 根因
BUG-393 统一选择条形态（提交 `eedd515`）在把三域收口到共享组件
`tauri-shell/src/components/ui/selection-bar.tsx` 时，把计数节点从各域原有的
语义文案（下载域原文是「已选 {n} 项」）换成了裸 `{count}`。形态统一了，语义丢了：
剧集墙、items 视图、下载域三处的计数都退化成孤立数字。

git 实证：`git show eedd515 -- .../DownloadPanel.tsx` 里
`- 已选 {selected.size} 项` → `+ countTestId="dl-batch-count"`（裸数字）。

既有判据佐证（说明这不是新造的判据方向，缺陷形态早就被旧判据抓着）：
- `tauri-shell/verify/verify_merge_frontend.cjs` 断言 `items-selection-count`
  匹配 `/已选\s*\d+\s*项|\d+\s*selected/i` —— 裸数字下为红；
- `tauri-shell/verify/_probe_bug353_download_selection.cjs` F2 断言
  `dl-batch-count` 匹配 `/已选\s*1\s*项/` —— 裸数字下为红。

## 复现
1. 进剧集墙，勾选 2 个剧集；
2. 看底部选择条第一个元素：只有「2」，没有任何说明它数的是什么。

## 修复
`SelectionBar` 增加**必填** prop `countLabel`，计数节点改渲染语义文案；
三个调用点各自用 i18n 生成（量词随域不同，组件不猜）：
- 剧集墙：`media.seriesSelectionCount`「已选 {n} 条」；
- items 视图：`media.selected`「已选 {n} 项」；
- 下载域：新增 `download.selectedCount`「已选 {n} 项」（恢复 BUG-393 前的原文，
  同时让 `_probe_bug353` 的 F2 判据重新可达）。

`countLabel` 不给默认值：漏传即 TS 编译红，不会静默退回裸数字。
下载域计数走 `useTranslation()`（语言切换可响应），JSX 里不硬编码中文。

## 验收证据
- 新增 `tauri-shell/verify/verify_bug406_selection_count_label.cjs`
  （静态 S1–S4 + 运行时 ①–⑤，ALL PASS，exit 0）：
  - 静态：span 渲染 `countLabel` 且不再出现裸 `{count}`；prop 必填；
    三个调用点全部传 `countLabel`；三处 i18n 键 zh/en 双份带 `{n}`。
  - 运行时：items 勾 1 = 「已选 1 项」、勾 2 = 「已选 2 项」（随选中数更新）；
    series 选 2 = 「已选 2 条」；下载域勾 1 = 「已选 1 项」。
  - 反证 ⑤：在真实 DOM 上把计数节点文本改回裸数字「1」，同一条判据当场抓到
    （证运行时段不是恒绿）。
- `npx tsc --noEmit` 通过（必填 prop 无调用点遗漏）。
- 截图：`verify_shots/bug406-selection-count/01-items-count-1.png`、
  `02-series-count-2.png`、`03-download-count-1.png`。
