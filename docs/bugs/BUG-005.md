# BUG-005: 「打开文件 / 打开目录」按钮无效且样式为纯文字

- 状态: closed
- 发现日期: 2026-08-26
- 模块: shell
- 严重程度: mid

## 现象
下载完成（completed）的任务，行内「打开文件」「打开目录」两个按钮点击完全无反应；
且这两个按钮为纯文字样式，与页面其它图标+文字按钮（顶部工具栏）视觉不一致，显得突兀。

## 根因
1. 调用未真正触发：原 `onClick={handleReveal}` / `onClick={() => handleReveal}`
   写法下处理函数不会被调用（箭头函数体返回函数引用而非执行），点击不产生任何行为。
2. 失败静默：原 `handleReveal` / `handleOpenDir` 的 catch 仅 `console.error`，
   即使 opener API 抛错也不会在 UI 提示，用户无从感知失败。
3. 样式不一致：操作按钮区原本只有「打开文件/打开目录」为纯文字，其它按钮（暂停/恢复/取消/删除）
   也未统一图标，整体缺图标层；与顶部工具栏的图标+文字规范不符。

`file: tauri-shell/src/components/DownloadItem.tsx`

## 复现
- 启动 Tauri 应用（dev 浏览器环境 `isTauri()` 为 false，按钮不渲染，需在真实壳内验证）。
- 完成一个下载任务 → 悬停该行 → 点击「打开文件」/「打开目录」→ 此前无任何反应；
  修复后应唤起系统文件管理器定位文件 / 打开所在目录；若 dest_path 缺失或 API 失败，
  顶部错误条显示「打开文件失败：... / 打开目录失败：...」。

## 修复
`tauri-shell/src/components/DownloadItem.tsx`（commit 4d97d6f）：
- 调用改为 `onClick={() => { void handleReveal(); }}` / `onClick={() => { void handleOpenDir(); }}`，确保真正执行。
- catch 中增加 `setError(...)`，把 opener 失败显式抛到 UI 错误条。
- 全部操作按钮（暂停/恢复/取消/打开文件/打开目录/删除）统一为「Lucide 内联 SVG 图标 + 文字」，
  与顶部工具栏视觉一致。
