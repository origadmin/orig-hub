# BUG-459: 播放界面右侧恒为 300px 分集列表、介绍被压在底部 96px 窄条——播放态应可切到「介绍」

- 状态: open
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-26

> 来源：用户报告「**简洁和播放菜单是不是改成 TAB 切换？因为一般播放时不看列表，
> 看文字介绍就够了吧？**」
>
> **更正（2026-10-27 二轮）**：本档初版把剧集详情页（`SeriesDetail`）的左栏 340px
> 当成「播放时的列表」，**事实错误** —— 用户原话「**根本没有左栏，左边是播放界面**」。
> 播放发生在**全局播放器页**（`MediaViewer`），其布局是「**左 = 播放画面、右 = 分集侧栏**」。
> 本档已按 `MediaViewer` 重写，原 `SeriesDetail` 左栏结论作废。

## 现象

播放界面 = `tauri-shell/src/components/MediaViewer.tsx`（全局播放器页，
`shell/MainLayout.tsx:268` 打开时独占整个内容区）。其主体是**左右两槽**：

1. **左（主区）= 播放画面**：`:225`
   `className="relative flex min-h-0 min-w-0 flex-1 items-center justify-center bg-black"`
   —— `flex-1`，画面占满剩余宽度（用户口中的「左边是播放界面」）。
2. **右 = 分集侧栏**：`:326-336`
   `{showEpisodes && seriesId && (<EpisodeList ... />)}`，
   `EpisodeList` 自身 `w-[300px] shrink-0 border-l`（`EpisodeList.tsx:118`）。
   可见性由 **`showEpisodes && seriesId`（数据结构）** 决定，**与「是否正在播放」无关**
   ⇒ 一旦是有剧集的视频，播放全程右侧 300px 恒为列表。
3. **文字介绍在底部一条窄条里**：`:348-357`
   `max-h-24 ... overflow-y-auto ... text-center text-xs ...`（`data-testid="viewer-text"`）
   —— 上限 96px 高、居中、11px 字号、需要滚动；多段正文在此被压成一条横幅。

用户判据：「一般播放时不看列表，看文字介绍就够了」⇒ 现状恰好相反：
**不看的东西（列表）占 300px 固定宽度，要看的东西（介绍）被塞进 96px 的窄条。**

## 根因

1. **布局只给了「画面 + 列表」两个槽，介绍没有槽位。**
   主体 `MediaViewer.tsx:213` 是 `flex min-h-0 flex-1`，仅两个子项：媒体区（`flex-1`）
   与分集侧栏（`shrink-0`）。介绍不是第三槽，只能退到主体之外的底部横幅
   （`:348`，`shrink-0` + `max-h-24`）—— 这是「没有槽位 ⇒ 降级成横幅」的结果。
2. **侧栏可见性由数据类型决定，不由呈现模式决定。**
   `showEpisodes && seriesId`（`:326`）只回答「这条内容有没有同剧的其它集」，
   不回答「用户此刻要不要看列表」。播放态没有对应的呈现模式分支。
3. **介绍的形态与剧集详情页不一致。**
   剧集详情里介绍是正文区（`SeriesDetail.tsx:697` `series-description`，
   `whitespace-pre-wrap` + 可展开）；播放页里同一段文字是 96px 居中窄条。
   同一段正文两处形态不同，长文在播放页必然读不全。

## 复现

1. 文件管理 → 剧集 → 打开一部多集剧集 → 点播放（进入全局播放器页）。
2. 观察：左（主区）是播放画面；右侧 300px 恒为分集列表；介绍在底部 96px 窄条内，
   超过 4 行即需在该窄条里滚动。
3. 播放全程不改变这一布局（侧栏可见性只随 `showEpisodes && seriesId` 变化）。

## 修复方向（未实施；≥2 实质选项 + 1 个「不做」）

### 选项 A（推荐）：右侧改 TAB（「列表」/「介绍」），播放时默认「介绍」

- 300px 侧栏顶部加两档 TAB：「列表」= 现状 `EpisodeList`；「介绍」= 本集/本剧正文
  （数据源同 `cur.description`，`MediaViewer.tsx:348` 已持有），可换行、可滚动、
  不做居中窄条。进入播放 ⇒ 默认「介绍」；用户切「列表」后记忆本次会话的选择。
- `涉及:` `MediaViewer.tsx:326-357`（侧栏包一层 TAB 容器 + 介绍面板，约 40 行）、
  i18n 2 键。
- `量化:` 新增 2 个 testid（如 `viewer-pane-tab-list` / `viewer-pane-tab-desc`）；
  300px 宽度不变；**底部 `viewer-text` 条撤销**（已裁定，见下）。
- `回归风险:` 中 —— `EpisodeList` 内的既有 testid（`episode-pick` 等）必须仍在
  「列表」TAB 内可达（BUG-149：能力不可删）；`viewer-text` 撤销后须确认验收脚本
  没有依赖它，否则改挂到「介绍」TAB 的容器上。
- `后果:` 播放期右侧给的是用户要读的东西；浏览 / 选集期与现状一致。与用户诉求逐字对齐。

### 选项 B：播放时收起右侧列表（保留一个展开把手）

- 播放中侧栏收成 ~36px 竖条（剧名 + 展开），点开恢复 300px；
  介绍从底部窄条提到侧栏展开态顶部（或保留底部条但加高到 `max-h-40`）。
- `涉及:` `MediaViewer.tsx:326` 与 `EpisodeList.tsx:118`（宽度状态化 + 折叠态）。
- `量化:` 播放态画面宽度 +264px。
- `回归风险:` 低 —— 不改侧栏内部结构，只改容器宽度与折叠。
- `后果:` 画面最大化（比 A 更利于观看），但「看介绍」仍需展开侧栏或读底部窄条，
  与「看文字介绍就够」的原话契合度低于 A。

### 选项 C：不动布局，只把底部介绍条加高并改为左对齐正文

- `:348-357` 的 `max-h-24` → `max-h-40`（或取消上限、随内容增长），
  `text-center` → `text-left`，字号 11px → 12.5px（与剧集详情一致）。
- `涉及:` `MediaViewer.tsx:348-357`。`量化:` 介绍可视高度 +64px。
- `回归风险:` 低。
- `后果:` 最小改动、介绍可读性提升，但 300px 列表依旧恒占（画面宽度没变），
  属症状级改善。

### 选项 D：不做

- `涉及:` 无。`量化:` 0。`回归风险:` 无。
- `后果:` 播放期画面永久被 300px 列表吃掉，介绍永久是 96px 窄条。

## 裁定（2026-10-27 用户拍板）

**采纳选项 A，并撤销底部 `viewer-text` 条。**

1. **方案**：300px 侧栏改为两档 TAB —— 「列表」（现状 `EpisodeList`）/
   「介绍」（本集 / 本剧正文，可换行、可滚动、左对齐正文、字号与剧集详情一致，
   **不是居中窄条**）。进入播放 ⇒ 默认「介绍」；用户手切「列表」后在本次会话内记忆。
2. **底部条撤销**：用户裁定「**选 A 底部肯定取消啊，这是基础逻辑问题**」——
   同一段正文在「介绍」TAB 与底部条两处显示即为重复真源（同一内容两个呈现点），
   必须只有一个。⇒ `:348-357` 的 `max-h-24 ... text-center text-xs` 横幅删除。
3. **落点**：`MediaViewer.tsx:326-357`；`EpisodeList.tsx:118`（宽度不变）。
   涉及 i18n 2 键（列表 / 介绍）。
4. **未覆盖项（不再反问，按既有判据处理）**：浏览 / 选集期与现状逐像素一致
   （TAB 默认「列表」），故 BUG-451 类的宽度回归面限定在播放态；
   `episode-pick` 等 testid 在「列表」TAB 内保持可达（BUG-149 能力不可删）。
