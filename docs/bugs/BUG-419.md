# BUG-419: 已置顶任务无法取消置顶（422）——`priority_endpoint_rejects_malformed_requests_bug277` 红灯

- 状态: open
- 发现日期: 2026-10-23
- 模块: engine
- 严重程度: mid

## 现象

`cargo test -p orig-tg --lib priority_endpoint_rejects_malformed_requests_bug277` 稳定 FAIL：

```
已置顶任务的取消置顶必须始终可用:
(422, {"error": "priority only applies to queued tasks (or to unpinning an already pinned one)"})
```

用例的意图是「**已置顶**任务的取消置顶必须始终可用」，但端点返回 422 —— 说明「取消置顶」
这条分支的判定条件把它自己排除了（错误文案里明明写着「or to unpinning an already pinned
one」，实际却不放行）。

## 影响

用户置顶一个已经开跑 / 已完成的任务后，**再也取消不了**：置顶是队列序的唯一用户意图，
置顶位被钉死等于队列顺序不可恢复。

## 复现

```sh
cd download-engine
cargo test -p orig-tg --lib priority_endpoint_rejects_malformed_requests_bug277
```

## 根因

未定位（本档为发现登记）。2026-10-23 做 BUG-407/408 时全量跑单测发现；`git stash` 掉当批
改动后同样失败 ⇒ 与当批改动无关。可疑点：优先级端点的「允许态」判定只看了任务机状态
（queued），没有为「unpin」单独开一条无条件通道。

## 关联

- BUG-277（优先级端点，本用例所属）
