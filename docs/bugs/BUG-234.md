# BUG-234：下载目录修改完全无效——设置只写 localStorage，引擎无运行时更新链路

- 状态: open（**修复已落地并端到端验证通过，待部署重启生效**：运行中的 daemon 进程本次会话无权终止）
- 发现日期: 2026-10-09
- 模块: engine+shell
- 严重程度: high
- 登记: 用户报告「目录修改逻辑无效，下载目录设置无法改变」

## 现象

设置页修改下载目录并保存后，实际下载落盘位置不变。

## 根因（全链路核实）

保存动作根本到不了引擎，链路三层全断：

1. **shell**：`handleSave`（`SettingsPanel.tsx:358-374`）调 `updateSettings({downloadDirectory: dir})`，
   实现（`useStore.ts:493`）**只写 localStorage**，无任何后端调用；
2. **daemon**：`GET /api/config` 只读；运行时更新端点只有
   `PUT /api/config/classify`、`PUT /api/config/proxy`、`PUT /api/config/tg`（`routes.rs:892-896`），
   **没有 download_dir 的 PUT**；
3. **引擎配置**：`config.rs:208` 仅在启动解析 download-engine.toml 时读 download_dir，
   无热更新路径。

对照：分类规则/代理/TG 开关都有「运行时生效 + 持久化」的 PUT 端点，
download_dir 是唯一漏网的设置项——属实现缺位，不是设计取舍。

## 修法方向

仿 classify/proxy：daemon 增 `PUT /api/config/download`（运行时生效 + 持久化到
download-engine.toml），shell handleSave 接上调用。注意与 BUG-235（库根目录设计）联动——
若库根与下载目录的关系要重构，先定关系再落端点，避免端点落两次。

## 修复（2026-10-09，代码已落地）

- 引擎：`orig-daemon/src/config.rs` 新增 `save_download_dir`（顶层键 `download_dir`；
  与段重写器不同，单独实现；**写正斜杠** —— 最小 TOML 解析器只 `trim_matches('"')`
  不做反转义，Windows 反斜杠会被当转义序列读坏）；`routes.rs` 新增
  `PUT /api/config/download`（body `{"dir": "..."}`，空串 = 清除回退系统默认）并注册路由。
- 壳：`api/daemon.ts` 增 `saveDownloadConfig`；`SettingsPanel` 新增 `persistDownload`
  并在 `handleSave` 中 `await`；进入设置页时以**引擎为唯一真源**初始化目录显示
  （`GET /api/config.download_dir` 优先，回写本地镜像）。
- 测试锚点：`download-dir-picker`、`settings-save`（原无 testid，探针无法驱动）。

## 验收证据

- **端到端（隔离实例，真实 HTTP + 真实落盘）**：以临时目录为 CWD、独立端口 29786 启动
  新构建 daemon（`ORIG_TG_PATH` 指向不存在路径以免拉起子进程），实测：
  `PUT /api/config/download {"dir":"D:/Verify/BUG-234"}` →
  `GET /api/config` 读回 `D:/Verify/BUG-234` → toml 落盘 `download_dir = "D:/Verify/BUG-234"`；
  再 PUT 空串 → 读回 null 且 toml 该行被移除。全链路通过，无副作用（临时目录已清理）。
- **UI 路径（设置页保存 → 引擎生效）探针已写就**：
  `tauri-shell/verify/verify_bug234_download_dir.cjs`（改输入 → 点保存 → 读引擎
  `/api/config` → 断言一致，结束恢复原值）。**未执行**：运行中的 daemon 是无权终止的外部进程
  （见下），旧二进制没有该端点，UI 一切到旧 daemon 必然失败。
- 部署缺口（2026-10-09 深夜复核，按 sync-sidecars.sh 的「*.locked-by-<pid>」惯例处理）：
  - 运行中的 daemon（PID 51848）是 **2026-09-29 构建**（实测 `/api/config` 无 `logs` 字段、
    `PUT /api/config/download` 404），且本会话**无权终止**：`taskkill /F`、`Stop-Process -Force`
    提权后一律「拒绝访问」，其 `Get-Process.Path` 读取为空 ⇒ 属于另一安全上下文（提权/他人会话），
    且 daemon 没有优雅退出端点，无法远程请它退出。
  - 处置：把运行中的可执行文件改名 `download-engine/target/release/orig-daemon.exe.locked-by-51848`
    （Windows 允许重命名运行中的 exe），再把新构建落到该路径，并 `sh scripts/sync-sidecars.sh`
    同步到 externalBin 源与壳 target（debug/release）—— 即**四处副本都已是新构建**，
    **下次引擎启动即生效**；在那之前 live 实例仍跑旧代码（本档因此保持 open）。
