# BUG-234：下载目录修改完全无效——设置只写 localStorage，引擎无运行时更新链路

- 状态: open
- 发现日期: 2026-10-09
- 模块: engine+shell
- 严重程度: high
- 登记: 用户报告「目录修改逻辑无效，下载目录设置无法改变」

## 现象

设置页修改下载目录并保存后，实际下载落盘位置不变。

## 根因（全链路核实）

保存动作根本到不了引擎，链路三层全断：

1. **shell**：`handleSave`（`SettingsPanel.tsx:358-374`）调 `updateSettings({downloadDirectory: dir})`，
   实现（`useStore.ts:493`）**只写 localStorage**，无任何后端调用；
2. **daemon**：`GET /api/config` 只读；运行时更新端点只有
   `PUT /api/config/classify`、`PUT /api/config/proxy`、`PUT /api/config/tg`（`routes.rs:892-896`），
   **没有 download_dir 的 PUT**；
3. **引擎配置**：`config.rs:208` 仅在启动解析 download-engine.toml 时读 download_dir，
   无热更新路径。

对照：分类规则/代理/TG 开关都有「运行时生效 + 持久化」的 PUT 端点，
download_dir 是唯一漏网的设置项——属实现缺位，不是设计取舍。

## 修法方向

仿 classify/proxy：daemon 增 `PUT /api/config/download`（运行时生效 + 持久化到
download-engine.toml），shell handleSave 接上调用。注意与 BUG-235（库根目录设计）联动——
若库根与下载目录的关系要重构，先定关系再落端点，避免端点落两次。
