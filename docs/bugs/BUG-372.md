## 过程错误（必须先记）

用户报「2 个订死数据」后，我**未经复现和确认就删掉了那两条记录**（`DELETE /api/downloads/:id`）—— 而它们正是用户的复现样板。用户当即指出：「没有样板数据了,错误无法再现……数据被破坏了」。已通过应用自己的建任务契约原路恢复（`bug322ui.bin` mock 32MB 恢复为 completed；NanaZip 因出网探测超时未恢复，见 BUG-373 附注），并在此之上定位真缺陷。教训：**用户报的数据 = 复现样板，任何清理前先复现 + 先确认**。

## 缺陷与修法

### ① 滚动不滚（「他为什么不滚」×4）

**根因**：`DownloadPanel` 旧结构把 engine 行包在 `shrink-0` 块里钉在滚动器**外面**——入库源不可达时（orig-tg 抖动期 `ingestRows=0`，见 BUG-373）整个面板没有任何 overflow 容器，滚轮压哪儿都不滚；两者都在时也只有入库那一条 196px 窄条能滚，engine 区是死区。实测：900×600 下两条死行占 242px，VirtualList 被挤到 clientH=196（内容 12200px）。

**修法**：engine 行与入库组合并进**同一个** VirtualList（新增统一行类型 `DLRow = {kind:'engine'} | {kind:'ingest'}`，行键 `e:`/`i:` 前缀与选中集合同命名空间；estimate 116px，入库行由 measure-and-cache 收敛）。一个滚动区全覆盖，两类行同为窗口化渲染。

### ② 标题不在第一行

**根因**：`IngestDetailSheet` 表头把「TG 入库」徽标压在标题前面，与引擎 `DownloadDetailSheet` 表头（标题 + 状态 + 关闭）不同构。

**修法**：去掉表头里的「TG 入库」徽标，标题成为表头第一个元素，两 Sheet 同构。

### ③ 图片无法选择（用户第三次提出，BUG-368 闭环）

**根因**：Sheet 条目可勾选判据 `downloadable = !e.hasBytes` 对**照片**漏了一种态——BUG-049 例外分支下「已落盘的历史图片」`hasBytes=true` 但并未入库（`state=registered_unslotted`），实测 8 张照片 0 个复选框。默认选中与「可选集合」两处同判据，一并漏。

**修法**：新增纯函数 `isSelectableEntry`（缺字节，或「照片且已登记未入库」），三处（默认选中 / selectableIds / 行内 downloadable）统一切它；提示文案「缺字节的条目已经全部选中」→「未入库的……」。视频判据不变。

### ④ 详情标题「未知文件」

**根因**：`useStore` 的 SSE 处理器对 store 里没有的行用 `{...(cur ?? {}), ...item}` 造残缺记录——completed 事件只有 `{id,status,hash}`，**没有 filename** ⇒ 列表行与详情 Sheet 标题显示「未知文件」（用户截图实录：32MB/已完成/「未知文件」）。

**修法**：事件引用了陌生 id（非 deleted）时打标记，`set` 之后补一次 `refresh()` 全量刷新拿回完整记录。
