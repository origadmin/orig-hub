# BUG-123：点击前没有类型信号 —— 点图片却进入视频播放器

- 状态: fixed
- 严重程度: high
- 模块: shell
- 发现日期: 2026-09-22

## 现象

用户点开一张图片，进到的却是**视频播放器**。

## 关键判读：这不是「分流缺失」

先验证现有逻辑是否存在，再谈缺什么。**分流是对的**：

```ts
// MediaViewer.tsx
modeOf(kind) => k === 'photo' ? 'browse'
              : (k === 'video' || k === 'audio') ? 'play'
              : 'none'
```

`MediaLibraryPanel.toViewerItem(i)` 也确实传了 `kind`。所以把责任归给「没做分流」
**会修错地方**。

## 真正的根因

**点击之前用户无法分辨自己点的是图片还是视频** —— 网格里视频条目和图片条目
**都只显示一张缩略图**，且悬浮层**在每一张卡片上挂同一个播放三角**，
点击前没有任何类型信号。

即：「封面（展示物）」与「内容（播放物）」在**视觉与层级上未分离**，
用户的点击意图与系统实际给出的东西对不上。

## 修复（`5242262`）

`MediaCard.tsx`：

1. **悬浮图标按类型分流**（`KIND_ACTION_ICON`）—— 图标只表达「点开会进入哪种视图」，
   **不表达「能不能播」**：

   | `kind` | 图标 | 语义 |
   |---|---|---|
   | `video` | `Play` | 播放 |
   | `photo` | `ZoomIn` | 看图（**绝不能用播放三角，那正是本缺陷的误导源**） |
   | `audio` | `Music` | 播放器，但载体是音频 |
   | `file` / 未知 | `Maximize2` | 中性的「打开」，不承诺任何媒体行为 |

2. **常驻类型徽标**（`data-testid="item-kind"`，`bottom-1 left-1`）—— 不 hover 也能分辨。
   位置选左下角，理由是四角只剩它空着：左上 `left-1 top-1` 是集号徽标，
   右上 `right-1 top-1` 是多选勾选框，右下 `bottom-1 right-1` 是时长徽标。
   带 `pointer-events-none`，不吞掉封面按钮的点击。

### 与原计划的偏差（如实记录）

- **「N 张」张数徽标未实现**。原计划里图片卡片要加「9 张」这类张数角标，
  但 `media_item` **一行就是一个文件**，条目层不存在「N 张」的聚合 —— 没有数字可渲染。
  要显示张数必须先引入相册聚合（当前数据模型没有）。此处**不做假徽标**。
- **徽标位置**由原计划的左上改为左下（理由见上，左上已被集号占用）。

> **交互层硬约束**：任何「只用一张缩略图代表条目」的设计都会复现本条缺陷。
> 换皮、换布局时这条不能丢 —— 卡片必须在点击前就给出类型信号
> （hover 图标 + 常驻徽标，两者互补：前者要悬停，后者不用）。

## 验收证据

**入库验收脚本**：`tauri-shell/verify/verify_card_kind_signal.cjs`（零第三方依赖，
底层 `verify/lib/cdp.cjs`，用 Node 内置 `WebSocket` 驱动本机 Edge）。

**复现命令**（先起 daemon 与 `npm run dev`，默认 `APP_URL=http://127.0.0.1:5180/`）：

```sh
cd tauri-shell
node verify/verify_card_kind_signal.cjs                  # 期望 exit 0
APP_URL=http://127.0.0.1:59999 node verify/verify_card_kind_signal.cjs   # 证伪 1，期望 exit 2
ORIG_VERIFY_REVERT=1 node verify/verify_card_kind_signal.cjs             # 证伪 3，期望 exit 1
```

### 正向：25/25 断言通过，exit 0

| 断言 | 实测值 |
|---|---|
| ★ 图片卡片悬浮层**不含**播放三角（`lucide-play`） | `photo=30 含播放三角=0` |
| 图片卡片悬浮层是看图语义（`lucide-zoom-in`） | `zoom-in=30/30` |
| 图片卡片均存在悬浮操作层（上一条非空转） | `无悬浮层=0` |
| 图片卡片常驻徽标文本为「图片」 | `不符=0` |
| 图片徽标常驻可见（class 不含 `opacity-0`，无需 hover） | `不常驻=0` |
| 图片徽标 `pointer-events-none`（不吞掉封面点击） | `非穿透=0` |
| 图片分类卡片数 == 后端 photo 条数 | `dom=30 backend=30` |
| 视频卡片悬浮层**仍是**播放三角 | `play=85/85` |
| 视频卡片不含看图语义图标 | `zoom-in=0` |
| 视频卡片常驻徽标文本为「视频」 | `不符=0` |
| 视频分类卡片数 == 后端 video 条数 | `dom=85 backend=85` |
| `KIND_ACTION_ICON` 四类 + 未知兜底映射齐全（源码级） | `video:Play / photo:ZoomIn / audio:Music / file:FileText / FALLBACK=Maximize2` |
| 无未捕获页面异常 / 无 console error | `[]` / `[]` |

> 「视频分类」一组是**对照**：证明播放三角是被**移走**了，而不是被**全删**了 ——
> 只测图片侧的话，一个「把所有图标都删掉」的实现也会全绿。

### 反向证伪（验收的验收）—— 三条全部实测

| # | 通道 | 期望 | 实测 |
|---|---|---|---|
| 1 | `APP_URL` 指向死端口 `59999` | exit 2 | **exit 2**，`RESULT: UNREACHABLE`、`nothing is listening on 127.0.0.1:59999` |
| 2 | 活体篡改：把统一播放三角注回图片卡片悬浮层，用**同一段检测代码**重测 | 必须报出 | `tamper: before=0 after=1 restored=0`，断言 PASS（检测器**非空转**） |
| 3 | `ORIG_VERIFY_REVERT=1`：把修复前形态注回真实 DOM（图标改回播放三角 + 移除徽标） | exit 1 | **exit 1**，`20/25 assertions passed`、`RESULT: FAIL (5 failed)` |

证伪 3 具体变红的 5 条（正是本缺陷的判据）：

```
FAIL ★ 图片卡片悬浮层不含播放三角（lucide-play） -> photo=30 含播放三角=30 首个="lucide lucide-play h-4 w-4"
FAIL   图片卡片悬浮层是看图语义（lucide-zoom-in） -> zoom-in=0/30
FAIL   图片卡片常驻徽标文本为「图片」            -> 不符=30 样本=[null,null,null]
FAIL   图片徽标常驻可见（class 不含 opacity-0）  -> 不常驻=30
FAIL   图片徽标 pointer-events-none              -> 非穿透=30
```

即：**缺陷真出现时这套断言会红**，不是一组恒绿的假断言。

### 未覆盖（如实标注）

- 媒体库当前 **`audio=0`、`file=0`**，这两条分支的**渲染结果本轮无法在真实页面验证**，
  只有源码级映射核对。等有对应类型数据后需补渲染断言。
- 结果产物落在仓库外（`os.tmpdir()/orighub-verify-card-kind/`，遵守 AGENTS.md §6 污染防线），
  故**不以产物路径作为可核证据**；跨机器可核的是上面那个入库脚本本身。
