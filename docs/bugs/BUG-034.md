# BUG-034：播放「非常卡」与倍速失效 —— 解码异常全程静默，播放器不告知也不降级

- **状态**：fixed（可见性部分）／测量结论部分受限
- **日期**：2026-09-18
- **模块**：shell（`MediaViewer` / `TgPanel.VideoBlock` / `lib/decodeHealth.ts`）

## 现象

用户主诉（原文）：

> 「播放还是不流畅，非常卡。**前端的播放器核心有问题吗？当前倍速什么都不行啊。**」

## 排查结论（先给答案）

**前端播放器核心不是主因。** 逐项排除，每项都有线上实测数据：

| 嫌疑 | 实测 | 结论 |
|---|---|---|
| 投递 / 背压（BUG-033 引入） | 同源 API P50 5.7ms、P95 6.9ms；全程 `readyState` 恒 4；`buffered` 末点正常推进；**seek 回填 0ms**（seek 耗时 360–490ms） | 排除 |
| 前端播放器实现 | 同素材同引擎：app `MediaViewer` 2x 达成 **77.4%**、裸 `<video>` 2x 达成 **72.6%**；1x 两者均 **100.5% / 100.3%**、丢帧 0 | 排除（app 略优于裸 video） |
| 元素重建 / 状态风暴 | 两段观测 `loadstart=+0`、`emptied=+0`，元素重建 **0 次**；`key=media-${id}`、`src` 为稳定 URL 串 | 排除 |
| GPU 解码能力 | 基线（Intel Iris Xe）2x 39.1fps／丢帧 23.21%；强制 `--force_high_performance_gpu` 切到 **NVIDIA RTX 3060** 后 2x 40.1fps／丢帧 24.40% | 排除（独显无改善） |
| 素材编码（HEVC） | H.264 1080p@3.9Mbps 2x 达成 84.8%／丢帧 **0**；HEVC 1080×1882@10.4Mbps 2x 达成 75.3%／丢帧 12.5% | 有影响，但**非唯一** |

### 测量局限（必须记录，否则会误导后续判断）

本机 Playwright 环境存在 **~40–43 fps 的呈现上限**：不同编码、不同码率、不同 GPU
**一致**撞在该数值上（H.264 需 50fps→实测 42.7；HEVC 需 60fps→实测 40.1），
且 1x（需 30fps）在所有配置下均 100% 达成。合成器时钟实测 55.5Hz（headless 与 headed 一致），
推测为虚拟合成器 / 窗口不可见节流所致。

**因此本机测得的 2x「丢帧率/跳变率」绝对值不可用于判断真实体感**，
只能用于**同环境横向对比**。用户真实 WebView2 体感需在其环境实测。

## 根因（确证部分：两个「静默失败」）

播放器此前对视频轨的两种异常**完全没有感知**，因为它们都不触发 `onError`：

### 1. 视频轨不可解 → 黑屏但 app 沉默

容器能解析、音频能解，但视频轨编码不受支持（典型：无 HEVC 扩展时的 `hvc1`）。
实测指纹：**`videoWidth === 0`、`readyState === 4`、`duration` 正常、`onError` 从不触发**。

```
Chromium（无 HEVC）播 hvc1 素材：video: 0x0  readyState=4  duration=202.246009
```

用户看到的就是「黑屏 + 走动的控制条」，而界面不给出任何说明。

### 2. 解码吞吐不足 → 丢帧但无提示

高分辨率/高码率 + 倍速时 `droppedVideoFrames` 持续增长，而 `readyState` 恒为 4、缓冲充足。
**凭缓冲类指标永远看不出来**，用户感知就是「莫名卡」。

## 修复

新增 `tauri-shell/src/lib/decodeHealth.ts`（两处播放器共用，避免重复实现）：

- `useDecodeHealth(ref, resetKey)` → 返回 `'ok' | 'strained' | 'unsupported'`
  - `unsupported`：`readyState >= 2 && videoWidth === 0` 持续 > 3s
  - `strained`：丢帧速率 > 3 帧/秒且连续 4 个采样点（≈2s）；`seeking`/`paused` 期间跳过以免误报
- `decodeStateKey()` → i18n key 映射
- 接入 `MediaViewer.tsx` 与 `TgPanel.tsx` 的 `VideoBlock`，底部浮出提示
- i18n 词条：`tg.decodeUnsupported`、`tg.decodeStrained`（zh-CN + en-US）

提示文案刻意给出**可行动信息**，而不是只报错误：
「解码吃力：画面在丢帧，调低播放速度会明显更流畅」。

## 关联

- BUG-033：投递背压。本缺陷确认背压**未**造成退化（seek 回填 0ms）。

## 防再发

1. **测视频流畅度禁止用 `timeupdate` / `rAF`**：前者约 4Hz 会漏检短卡顿，后者是合成帧
   ——video 冻住时照样 60fps。必须用 `requestVideoFrameCallback` + `getVideoPlaybackQuality`。
2. **判「卡」必须先量合成器时钟**：若「需求 fps（源fps×倍率）> 刷新率」，瓶颈是呈现层而非解码，
   两者修法完全不同。
3. **拿 GPU 做对照时要确认真的换了 GPU**：把 WebGL `UNMASKED_RENDERER` 记进证据，
   否则「换独显无改善」可能是没换成功。
4. **`readyState` 满格不代表能播**：视频轨不可解时它同样是 4，必须另看 `videoWidth`。
