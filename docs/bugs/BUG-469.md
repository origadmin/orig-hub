# BUG-469: 缺「剧集文件整理」——以剧集为单位把内容（文字）/ 视频（多集）/ 图片按需求归位

- 状态: open
- 发现日期: 2026-10-27
- 模块: engine+shell
- 严重程度: mid
- 排期: 2026-11-26

> 来源：用户报告「**一个功能遗漏了，剧集文件整理。剧集分为内容（文字）、视频（多集 1+）、
> 图片。应该按需求整理放置。**」
>
> 注：本条原拟用 BUG-466，该号已被并行会话占用（下载主列表端点回归），故顺延为 469。

## 现象

一部剧集由**三类资产**构成，但现有整理能力只能按「条目集合」处理，
不能按「剧集 + 资产类型」处理：

1. **内容（文字）**：剧集标题 / 介绍 / 标签 / 年份，以及分集标题与本集介绍
   （`SeriesEditPanel`、`EpisodeEditPanel.tsx:146-264`）。**没有落盘通道** ——
   文字只存在于库里，整理产物里不含它。
2. **视频（1 集或多集）**：`media_episode` 的 `season` / `episodeNo` / `episodeNoEnd`
   （合集区间，BUG-153）；一个文件也可能装多集。
3. **图片**：剧集封面（`resolveSeriesCover`）、本集题图 / 图组
   （`EpisodeExpanded.tsx:371` 的 88×120 瓦片、`EpisodeImagePickerDialog`）。

现有整理 = `OrganizeWizard`（`components/media/OrganizeWizard.tsx`，D24-A / BUG-311）：
**条目级**四步（选条目 → 选模板 → 选产物根目录 → 预览全表 → 执行），
挂载点 `MediaLibraryPanel.tsx:2129`；模板变量已覆盖剧集维度
（`api/media.ts:617-620`：`{剧名}` `{季}/{season}` `{集}/{episode}` `{集名}` `{来源}`
`{日期}` `{ext}`，支持 `{season:02}` 零填充）。

**缺的是「剧集级」这一层**：输入是「条目 id 集合」而不是「一部剧」，
因此无法表达「视频放进 `Season 01/`、图片放进 `extras/`、文字导出成 `metadata`」
这类按资产类型分派的整理需求。

## 根因

1. **整理引擎的输入模型是条目集合，不是剧集。**
   `organizePreview(itemIds, ...) / organizeApply(itemIds, ...)`（`api/media.ts:659-681`）
   只接受 `itemIds` ⇒ 剧集结构（season / episode / 图片归属 / 文字）在入口处被摊平成
   一堆互不相关的条目；模板只能在**单条文件名**层面还原剧集维度，
   **目录层级无法按资产类型分派**。
2. **图片与文字没有进入整理的资产模型。** 整理产物按条目生成；剧集封面与本集题图是
   「挂在剧集 / 分集上的图」（`episode.images`），不是待整理条目集合的一部分；
   文字根本不是条目。
3. **安全边界已定、可复用**：`OrganizeWizard.tsx` 头部注释（09 §15.2 红线）——
   整理**绝不修改 blob 或 `media_item.file_path`**（播放永远走 blob）、幂等（`skip`）、
   同名加序号、产物不是唯一字节来源 ⇒ 剧集级整理可直接继承这套边界，
   不必重新论证「整理会不会搞坏库」。

## 复现

1. 文件管理 → 选一部剧集（含视频 + 图片）→ 走整理向导。
2. 观察：只能在**条目**层面选模板，无法表达
   「视频 → `Season 01/`、图片 → `extras/`、文字 → `metadata.json`」；
   剧集封面 / 本集题图不在待整理集合里；文字没有任何落盘选项。
3. 想「按需求整理放置一部剧」⇒ 只能手工分批选条目 + 手改模板，图片与文字仍缺。

## 修复方向（未实施；≥2 实质选项 + 1 个「不做」）

### 选项 A（推荐）：新增「整理剧集」入口——以剧集为单位、按资产类型分派目录

- 在剧集详情（或剧集墙多选）加「整理剧集」：预览表按资产类型分组
  （视频 / 图片 / 文字），每组一个子模板（默认
  `{剧名}/Season {season:02}/{剧名} S{season:02}E{episode:02}{ext}`、
  `{剧名}/extras/{集名}{ext}`、`{剧名}/metadata.json`），可整组关掉（只整视频）。
- `涉及:` 新增 `SeriesOrganizeWizard.tsx`；引擎 `download-engine/crates/orig-tg/src/organize.rs`
  增加按剧集展开的输入（series_id + 资产类型掩码）与文字导出；i18n 若干键。
- `量化:` 1 个新入口 + 3 类资产子模板；复用既有 `/api/media/organize/preview|apply`。
- `回归风险:` 中 —— 必须继承「不改 blob / 不改 `media_item.file_path` / 幂等 / 同名加序号」
  四条红线（引擎夹具 `organize::tests` 已锁）；不得让整理产物变成唯一字节源。
- `后果:` 「剧集文件整理」名实相符；三类资产可按需分别放置或跳过。

### 选项 B：不加新入口，给现有向导补「按剧集展开」的选条目方式

- 整理向导里加「选一部剧 = 展开为该剧全部条目（含挂图）」的快捷选择，
  模板仍单一（靠 `{season}` 等变量区分目录）。
- `涉及:` `OrganizeWizard.tsx` 选择步 + 一个按剧集展开的读端点。`量化:` +1 个快捷方式。
- `回归风险:` 低 —— 不动引擎整理逻辑。
- `后果:` 视频可按季 / 集分目录；**图片与文字仍缺**（单一模板无法分派两类产物）。

### 选项 C：只补「文字导出」（metadata 落盘）

- 整理产物里附带一份剧集 / 分集文字（标题、介绍、标签、季集号）。
- `涉及:` 引擎导出 + 向导多一个勾选项。`量化:` 每剧 1 个文件。`回归风险:` 低。
- `后果:` 补上「内容（文字）」这一类，但目录分派（视频 / 图片分开放）仍未解决。

### 选项 D：不做

- `涉及:` 无。`量化:` 0。`回归风险:` 无。
- `后果:` 整理永远停留在条目级；剧集的三类资产无法按需求一次性归位。

## 关联
