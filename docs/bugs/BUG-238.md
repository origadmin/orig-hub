# BUG-238：插件化管理框架缺失——TG 开关是孤例，ffmpeg/外置播放器/未来功能无统一模型

- 状态: open
- 发现日期: 2026-10-09
- 模块: engine+shell
- 严重程度: high
- 报告轮次: 用户报告「ffmpeg 应该也作为插件，播放器应有外置默认播放器选项；Telegram 插件
- 类型: epic
- 延期至: 2026-12-15（理由：设计级工程，需独立里程碑；详见关联设计文档）
  是否应该作为功能管理的一个？后续下载、上传等等其他功能插件可能都需要单独开启关闭设置；
  如果没有安装（ffmpeg）使用外置系统默认」

## 现象

- TG 是唯一有启停端点的可选功能（`PUT /api/config/tg`），但它是**特例**而非框架产物：
  状态散在 tgService/常规页签/daemon 配置各处（BUG-233 的根因）；
- ffmpeg 无插件身份（BUG-237）；播放器无「外置默认播放器」关联选项；
  未来的上传等功能无统一开关/状态/设置挂载点。

## 设计裁决建议（用户已在描述中给出方向，本文档落为结构）

统一 FeaturePlugin 模型，每插件四元组：`enabled`（开关）/ `status`（健康与端口/
错误，BUG-233 的数据源）/ `settings`（各自参数）/ `fallback`（缺席时的降级路径）：

| 插件 | 开关 | 缺席降级 |
| --- | --- | --- |
| telegram | 已有 PUT /api/config/tg | 功能隐藏，主流程不受阻 |
| ffmpeg（新增） | 未安装自动降级 | 转码流不可用 → 外置/系统默认播放器播 raw；设置项可显式指定路径 |
| 外置播放器（新增） | 关联系统默认或指定程序 | 无 |
| 下载/上传（未来） | 预留 | — |

daemon 侧一张插件注册表 + `GET /api/plugins` 汇总状态，shell 设置页遍历渲染
（about 页签的 TG 状态、ffmpeg 状态都从注册表来，不再逐个手写）。

## 关联

- BUG-233（about 缺 TG 状态）的长期修法挂在本框架上；
- BUG-237（ffmpeg 设置）的形态裁决在本框架内完成；
- 与用户既定原则一致：拒绝把状态藏进设置深处，「让错误状态不可表达」。
