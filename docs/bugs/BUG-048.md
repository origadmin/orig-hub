# BUG-048 混编相册（1 封面图 + 1 视频）不成剧 —— 「缓存不入库」

**状态**: fixed
**优先级**: critical
**模块**: orig-tg / routes.rs（缓存 worker 成剧门槛）
**日期**: 2026-09-18

## 现象

用户缓存后内容不出现在媒体库（剧集墙无任何新内容）。实测（任务 12/13/14，
20:48 与 21:42/21:44 三次缓存）：文件已缓存、`media_item` 已入库（条目 356-361），
但**没有任何剧集生成**——媒体库落地视图是剧集墙，用户看到的就是「缓存不入库」。

## 根因

BUG-044 把成剧入口改成「视频对裁剪后 `video_pairs.len() >= 2` 才成剧」。
TG 频道的真实构成是**每个 EP 一条相册 = 1 封面图 + 1 视频**：裁剪后只剩 1 条视频
→ 永远不过门槛 → 永不成剧。图片不入剧集的规则本身正确，但门槛把「1 视频组」
一并杀掉了，属于规则落地时的回归。

## 修复（routes.rs）

成剧门槛按组形态区分：

- 有 `group_id` 的相册组：**≥1 条视频即成剧**（图片不入剧集，只收视频分集）；
- 无 `group_id` 的多选：≥2 条视频才成剧（保持单条消息缓存不成剧的既有语义）；
- 纯图片组：不成剧，且**必须留日志**（`group has no video item(s), skip series`），
  禁止静默跳过（BUG-043 教训）。

## 数据修复

存量孤儿视频（已入库、不在任何剧集）通过重放缓存组修复（文件已在盘、条目已入库，
worker 只补成剧，幂等）：

- 任务 15/16（重放 13/14）：series 59/60，各 1 集，封面 video，标签并入剧集
- 任务 17/18（重放 10/11、12）：series 61/62，各 1 集
- 修复后孤儿视频 = 0（剩余 33-66 为「码率阶梯」测试数据，本就不属于剧集）
- 任务 6/8/9 为纯图片/无条目组，按规则不成剧，仅条目入库（正确行为）

## 验收

- `cargo test -p orig-tg --lib` 28/28（修复后编译+全量回归）
- 服务重启（real + Authorized）后重放 4 组，日志显式 `series N with 1 episode(s)`
- DB 断言：`kind='video' AND id NOT IN (SELECT item_id FROM media_episode)` 为空
- UI 截图 `verify_shots/bug048/f_series_wall_final.png`：剧集墙出现全部修复剧集
