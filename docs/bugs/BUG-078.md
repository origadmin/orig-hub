# BUG-078: 缓存任务「重试」新建一条任务 +「删除」确认框出现在面板顶部而非当前任务下

- 状态: fixed
- 发现日期: 2026-09-20
- 模块: engine+shell
- 严重程度: mid

## 现象

缓存管理面板的任务记录列表里：

1. 对一条**终态**（failed/cancelled）任务点「重试」，列表里**多出一条新的 queued 任务**，
   原失败记录仍在——用户看到「一条失败 + 一条新建」，而不是同一条任务重跑。
2. 点单条任务的「删除」，确认框出现在**面板最上面**，与所点任务隔着一屏，
   用户无法确认「删的是哪一条」；期望是**当前任务行下面**展开确认，或在删除按钮上方弹出。

用户原话：「重试会新加一个任务，而不是原任务重试。点击删除会在最上面出现删除框，而不是
当前任务下面，或者删除按钮上面弹出删除确认。」

## 根因

1. **重试 = 重新入队**：前端 `retry(task)` 调 `enqueueCacheTask({chatId, messageIds, groupId})`
   （`tauri-shell/src/components/CacheManagerDialog.tsx` 原 283-290）。后端
   `enqueue_cache_task` 只对**活跃**任务（queued/running）幂等复用，遇到终态任务走
   `INSERT` 新行 → 必然增生记录。语义上「重试」被实现成了「再来一单」。
2. **删除确认是全局单例**：`confirm` 状态只有一个（无归属），确认条固定渲染在列表容器的
   顶部（`CacheManagerDialog.tsx` 原 473 附近），与触发它的任务行无位置关联。

## 复现

1. 缓存管理 → 任务记录：制造/找到一条 failed 任务 → 点重试 → 观察列表条数 +1；
2. 滚动到列表中部 → 点某行删除 → 确认框出现在面板顶部，需回滚才知道受影响的是哪条。

## 修复

- **原任务重试（语义复位）**：
  - 后端新增 `Store::retry_cache_task(id)`（`orig-tg/src/store.rs`）：
    `UPDATE cache_task SET status='queued', done=0, error=NULL WHERE id=? AND status NOT IN ('running','queued')`
    ——只复位**终态**，活跃态不动（避免同一条被两个 worker 双跑），**复用同一 id**。
  - 新增端点 `POST /api/cache/tasks/:id/retry`（`orig-tg/src/cache.rs::retry_task`），
    复位后 `refresh_cache_tasks()` + `spawn_cache_task(st, id)` 立即重跑。
  - 前端 `api/tg.ts` 新增 `retryCacheTask(id)`；`CacheManagerDialog` 的 `retry` 改为
    `retryCacheTask(task.id)`，不再 `enqueueCacheTask`。
- **删除确认内联到任务行**：`confirm` 由布尔改为 `{ kind: 'one' | 'batch', id?: number }`。
  - `kind==='one'` → 确认框渲染在**该任务行内部**（`confirm.id === task.id`），
    `data-testid="cache-confirm-inline"`，含「是/否」两个按钮；任务在跑时追加提示。
  - `kind==='batch'` → 仍走顶部确认条（批量本来就没有单一归属行）。

验收锚点：重试后列表条数不变且该行 id 不变、状态回到 queued；点第 N 行删除时
`cache-confirm-inline` 出现在该行 DOM 子树内，而非面板顶部。
