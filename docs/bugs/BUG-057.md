# BUG-057: 媒体库条目卡片没有逐条删除入口，只能「先勾选再批量移除」

- 状态: fixed
- 发现日期: 2026-09-19
- 模块: shell
- 严重程度: mid

## 现象

媒体库要给某一条内容收尾（删除），必须先点卡片勾选框把选区建起来，再点顶部工具栏的
「移除」——选择态成了**删除的前置仪式**。缓存管理面板刚改成「逐行删除 + 批量删除」双通道，
两边操作语义不一致；用户诉求是把同一套搬到媒体库。

现状取证（前端源码）：

- `tauri-shell/src/components/media/MediaCard.tsx` 只有 `onEdit`（编辑）与
  `onSelectToggle`（勾选），**没有任何删除入口**；
- `tauri-shell/src/components/MediaLibraryPanel.tsx` 的删除动作条只在
  `selected.size > 0` 时渲染（`{selected.size > 0 ? (...) : ...}`），
  即「未选中时界面上不存在删除」；
- 后端能力齐备：`DELETE /api/media/items/:id` 与 `DELETE /api/media/series/:id` 均已存在
  （`tauri-shell/src/api/media.ts`），缺的只是入口，不是能力。

## 根因

媒体库的删除被建模成**批量动作**，单条删除只能退化成「大小为 1 的批量」。
批量动作条又挂在选择态之下，于是单条删除的路径长度 = 勾选 + 工具栏 + 确认，
且发现性依赖用户先意识到勾选框的存在。

## 复现

1. 打开媒体库「内容」视图；
2. 把鼠标移到任意卡片上：可见控件只有勾选框与「编辑」，无删除；
3. 不勾选任何卡片：工具栏里不存在任何删除按钮。

## 修复

卡片右下角改为**常驻动作条**：`删除`（Trash2，悬停转危险色）与 `编辑` 同级并列，
两者都在 `MediaCard.tsx` 内、都在 `opacity=1` 下可点 —— 单条删除不再需要先建立选区。

- **单一删除通道**：确认状态机 `confirmDelete` 增加显式 `ids?: number[]`，
  单条删除走 `{kind:'items', ids:[it.id]}`，批量仍走勾选集合，两者共用同一个
  `doDeleteItems(ids)`（避免「单条删除」与「大小为 1 的批量」各自漂移出两套确认文案）；
- **影响面如实回报**：确认框按目标集报「单条」或「批量」，并额外提示
  「其中 M 条已归入剧集」——删掉某季最后一集会在剧集侧留下空季，这属于用户必须
  在动手前知道的事；
- 文案新增 `media.confirmRemoveOne` / `media.confirmRemoveItems` / `media.confirmGroupedWarn`
  （中英同步，键位对齐）。

另修一处同域缺陷：`DELETE /api/media/items/:id` 对**不存在的 id** 原本一律回
`{"ok":true}`，即「说成功了但其实什么都没删」。现改为如实回报 `removed: 1|0`，
幂等语义保留（重复删同一条仍是 200，不改成 404 —— 那会让「重试」这类客户端逻辑误判为失败）。

## 验收证据

- 证据脚本（入库，可跨机器复跑）：`tauri-shell/verify/shot_media_delete.cjs`
  —— **17/17 PASS**（真实实例 9877 + vite dev 5180，Playwright 运行期几何 + 真实接口读数）。
- 覆盖的关键断言：
  - 未 hover 与 hover 两种状态下 `item-delete` 均 `opacity=1` 且中心命中自身
    （不看类名，用 `getBoundingClientRect` + `elementFromPoint`）；
  - 单条删除确认框文案是**单条**语义（`media.confirmRemoveOne`），不是「大小为 1 的批量」；
  - 归入剧集的条目额外出现 `confirm-grouped-warn`；
  - **点取消 → 条目数、剧集列表与条目 `filePath` 快照逐字未变**（验牙：确定路径不可逆，
    真实库只走取消路径）；
  - 批量删除路径回归：勾选 2 条仍如实报 2；
  - 删除不存在的 id → `status=200 且 removed=0`（不得盲回 ok）。
- 产物（证据图 + `result.json`）：`verify_shots/round9-delete/`（按 AGENTS.md §6 不入库）。
