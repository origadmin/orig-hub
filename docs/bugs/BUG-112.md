# BUG-112：剧集里的图片无法从剧集中移除（图册区没有移除入口）

- 状态: fixed
- 严重程度: high
- 模块: shell
- 发现日期: 2026-09-22

**发现方式**：用户报告「剧集中图片居然是无法从剧集中删除的」。实地核对前端渲染路径后确认
属实，且**不是后端能力缺失** —— 后端接口一直都在，是前端没接上。

## 现象

剧集详情页底部的「图片 · N」图册区（`data-testid="series-gallery"`）里，每一张图都只是
一个打开灯箱的按钮：

```tsx
// SeriesDetail.tsx:539-556
{photoEps.map((ep, i) => (
  <button type="button" onClick={() => setViewerIndex(i)} ... >
    <img src={mediaItemUrl(ep.itemId)} ... />
  </button>
))}
```

**没有任何「移除」/「删除」入口**。而同一个文件里，分集列表的每一行**都有**「移除」按钮：

```tsx
// SeriesDetail.tsx:766-774
<Button ... onClick={() => onRemoveEpisode(ep)}
        title="从剧集中移除（内容保留在资料库）">移除</Button>
```

差别只在于这一行渲染在分集列表里，而分集列表只含非图片内容。

## 根因

`SeriesDetail.tsx:178-183` 把 `detail.episodes` 一分为二：

```tsx
const photoEps = detail.episodes.filter((e) => e.kind === 'photo')
const playEps = detail.episodes.filter((e) => e.kind !== 'photo')
```

图片走**图册区**（533-556 行），视频走**分集列表**（565 行之后）。而「移除 / 上移 / 下移 /
编辑」这一整套行内操作**只实现在分集列表那一段**。于是：

**「从剧集中移除一张图片」这个动作在 UI 上根本不存在** —— 用户能加，不能删。

后端能力是齐的，没接上而已：

- `DELETE /api/media/episodes/:id`（`routes.rs:2893`）一直存在；
- `Store::remove_episode`（`media.rs:1900`）会删行 → **重排该季后续集号** → 更新
  `updated_at` → `prune_empty_series`（删空剧集），逻辑完整。

## 为什么算核心逻辑错误而不是「少了个按钮」

1. **能进不能出**是数据完整性问题，不是体验瑕疵：图片一旦编进剧集，就没有任何正向路径
   把它摘掉。
2. **唯一的替代路径语义不对**：在「全部内容」里删条目走的是
   `DELETE /api/media/items/:id` —— 那会**连字节一起删**（`routes.rs:2107` 起，含 TG 缓存
   双向联动）。用户想要的「从这部剧里去掉这张图、内容还在资料库里」无法表达。
3. 用户视角里这是**明确的核心能力缺失**：归档容器必须支持摘除成员。

## 修复方向

在图册区补上移除入口，复用既有 `onRemoveEpisode`（后端无需改动）：

- 每张图右上角 hover 显示「×」；或点开灯箱后在灯箱内提供「从剧集移除」。
- 文案与分集保持一致：**「从剧集中移除（内容保留在资料库）」**。
- 移除后刷新剧集详情（`openSeries` + `loadMeta`），与现有 `onRemoveEpisode` 实现一致。

### 修复时必须一并确认的风险（否则等于没修）

BUG-029 定下的教训是「**单向删除会在下次 upsert 时复活**」。图片分集若由 TG **自动成剧**
产生（按 `source_key` 幂等重建），摘掉 `media_episode` 行后，下一次同步可能把它**重新编回
剧集**，表现为「删了又回来」。因此验收必须包含：

1. 移除一张 TG 来源的图片 → 刷新详情页，图册区数量 -1；
2. **触发一次 TG 同步 / 重新缓存** → 该图片**不得**重新出现在该剧中；
3. 资料库「全部内容」里该条目**仍在**（内容未被删）。

若第 2 条做不到，说明需要一条「已摘除」的负向记录（类似 tombstone），而不是只删行 ——
这一点要先取证再定方案，不要想当然。

`tauri-shell/src/components/media/SeriesDetail.tsx` 图册区（539-577）：

- 新增「移除」按钮（`series-gallery-remove`）：右上角 `×`，`group-hover` /
  `focus-visible` 显示，**复用既有 `onRemoveEpisode(ep)`**（后端无需改动），
  文案与分集列表一致，带 `title` 与 `aria-label`；
- `node node_modules/typescript/bin/tsc --noEmit` **0 错误**。

### 已取证：摘除后**会被重新编回**（这是本条尚未完成的部分）

实测（本机 orig-tg，2026-09-22）：

| 步骤 | 结果 |
|---|---|
| `append` item143(photo) → epId393 | 图册出现 |
| `DELETE /api/media/episodes/393` | 图册清空 |
| **再次 `append` [143]** | `{"added":1}` → **epId394，图片复活** |

代码印证：`append_episodes_ranged`（`media.rs:1714`）**只按当前 `media_episode` 行去重**；
`remove_episode`（`:1900`）**不写任何「已摘除」负向记录**；全库无外键级联。
另一条复活路径：移除**唯一**分集 → `prune_empty_series` 删掉剧集 → 下次同步按
`source_key` 落空 → **新建剧集并重新编入**。

→ 因此本条状态是 **`in_progress` 而非 `fixed`**：入口已可用，但「移除」会在同步 /
重新加入后失效。**正修见 BUG-126（tombstone 负向记录）。**
