# BUG-398: 回溯表单无显式「关闭」入口（"无法关闭"）

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: shell
- 严重程度: high
- 报告: 用户 2026-10-23 16:43「回溯没有关闭! 无法关闭! 这个问题提过多少次了?」

## 现象（实测，非推测）

点开频道行的「回溯」表单后，表单里**只有一个「开始回溯」按钮**。用户若不想起一个回溯，找不到任何关闭/取消方式——只能点「开始回溯」被迫发起一次回溯，或去点行内那个语义不明的「回溯」toggle 碰运气。用户多次反馈「回溯无法关闭」。

> 注：运行态回溯的「取消」按钮（`tg-monitor-backfill-cancel`，仅 `backfillRunning` 时渲染）属已开 **BUG-382**（取消可见性）。本 BUG 专指**表单本身的关闭入口缺失**。后端取消路由 `DELETE /api/tg/monitor/backfill/:id` → `clear_backfill`（归零 `backfill_until`）机制本身正确、可用。

## 根因：表单只有「开始」一个出口，无关闭钮

`TgPanel.tsx` 回溯表单（原 `tg-monitor-backfill-form`）底部仅 `tg-monitor-backfill-start` 一个按钮；收起表单的唯一方式是再点行内 `tg-monitor-backfill-open` toggle（`setBackfillFor(backfillOpen ? null : ch.id)`），但该入口**不可发现**——用户看不出来「同一个回溯按钮再点一下就关掉」，于是感知为「关不掉」。

## 修法（表单内显式关闭入口 + 保留 toggle）

表单底部改为「关闭 / 开始回溯」并排：
- 新增 `tg-monitor-backfill-close`（`variant=ghost`）：`onClick` → `setBackfillFor(null); setBackfillDate('')`；
- 既有 `tg-monitor-backfill-start` 不变；
- 行内 `tg-monitor-backfill-open` toggle 仍保留（再点即关），作为次要路径。

i18n 新增 `tg.backfillClose`（zh:「关闭」/ en:「Close」）。
