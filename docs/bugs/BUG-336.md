# BUG-336: 调试日志路径分隔符混用——同一条路径里 `/` 与 `\` 并存（ORIG_TG_DATA 原样入 PathBuf，join 后混用，原样下发原样展示）

- 状态: open
- 发现日期: 2026-10-20
- 模块: engine+shell
- 严重程度: mid

## 现象（用户原话，2026-10-20 第 4 点）

> 「调试日志 也有路径问题，windows 和 linux 路径分隔符混用 '/'、'\' 不分。」

设置-关于页的调试日志路径串里，同一条路径同时出现 `/` 与 `\`（如 `D:/OrigHub\logs`）；用户照路径去资源管理器找、或复制粘贴进地址栏都可能出错。

## 根因

1. `tg_data_dir()`（`download-engine/crates/orig-daemon/src/state.rs:917-921`）对环境变量 `ORIG_TG_DATA` 原样 `PathBuf::from(d)`——正斜杠不归一化；
2. `log_dir()` = `tg_data_dir().join("logs")`（同文件 `:966-968`），在已含 `/` 的基路径上 join 即产出 `D:/x\logs` 混用；
3. `routes.rs:804-806` 以 `to_string_lossy()` 原样下发，前端 `SettingsPanel.tsx:1533`（`logPaths?.dir`）直接展示，无归一化。

BUG-243 建立单一日志根时只统一了「目录在哪」，没有统一「路径串长什么样」。

## 复现

设 `ORIG_TG_DATA=D:/Verify/TG`（正斜杠）启动 daemon → `GET /api/config` 的 `logs.dir` 形如 `D:/Verify/TG\logs` → 设置-关于页原样展示该串。

## 修复方向

单一归一化点（产出侧优先）：daemon 下发前把日志路径归一为平台分隔符；与 BUG-332 的展示层归一化分工分层——存储/wire 可保持规范正斜杠，但**同一条展示路径内不得两种分隔符并存**。

判据（建议）：

- 下发的三条日志路径（`dir`/`orig_tg`/`errors`）在 Windows 下各自不含 `/`；
- 反向证伪：喂混用基路径必须被归一化（判据有牙）。
