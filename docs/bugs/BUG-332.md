# BUG-332: 路径显示用正斜杠——Windows 下应显示 `\`，存储妥协（BUG-234 写正斜杠）原样漏给用户

- 状态: open
- 发现日期: 2026-10-20
- 模块: shell
- 严重程度: mid

## 现象（用户原话，2026-10-20 第 1 点）

> 「路径显示也有问题，windows 使用的是 \，实际显示的是 /。」

设置页等处展示的下载/存储路径在 Windows 下用正斜杠（如 `D:/OrigDown`），与资源管理器及用户心智中的 `\` 不一致。

## 根因

BUG-234 的持久化实现**故意写正斜杠**：最小 TOML 解析器只 `trim_matches('"')` 不做反转义，Windows 反斜杠会被当转义序列读坏（`docs/bugs/BUG-234.md` 修复节）。存储层用正斜杠是**正确的妥协**，但前端 `SettingsPanel.tsx:319-321` 以引擎原始串为唯一真源直接进编辑态与展示（`const engineDir = c.download_dir ?? ''; setDir(engineDir)`），**没有「展示层按平台归一化」一环** ⇒ 存储规范与展示规范耦合成同一个字符串，存储的妥协原样漏给用户。

## 复现

1. Windows 打开设置-下载与存储，看目录输入框/展示值形如 `D:/OrigDown`；
2. 或 `GET /api/config` 的 `download_dir` 与 UI 展示值比对（同为 `/`，即无归一化）。

## 修复方向

展示层设单一归一化点：仅 Windows 展示时 `/`→`\`；编辑回传与存储/wire 不变（正斜杠保留）。

判据：

- 设置页所有路径展示串在 Windows 下不含 `/`（`file://` 类 URI 若另有用途须单独处理，不得误伤）；
- 反向证伪：喂一个含 `/` 的引擎值，展示必须转成 `\`（判据有牙）。
