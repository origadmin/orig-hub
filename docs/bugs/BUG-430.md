# BUG-430: 分集动作条上的「上移/下移」两颗图标按钮语义不明、位置突兀，且同一动作有两个入口

- 状态: open
- 发现日期: 2026-10-26
- 模块: shell
- 严重程度: mid

## 现象

用户 2026-10-26 原话：

> 编辑中的上下切换按钮功能是什么? 位置比较突兀,功能也让人迷惑.

用户把它理解成「编辑中的上下**切换**按钮」，即以为它是「切上一集 / 切下一集」。
实际语义是**排序**：把当前这一集与同季的上一集 / 下一集**换位**（改的是集序，
不是切换正在看的那一集）。用户读不出这个意思，说明入口的表达到位程度不够。

三个具体问题：

1. **纯图标、无文案**：`ChevronUp` / `ChevronDown` 两颗 `h-7 px-2` 的方按钮，
   界面上没有任何文字，语义只存在于 `title` tooltip 里
   （`media.episode.moveUp` =「上移一位（与本季上一集换位）」）。
   不悬停就完全不知道是干什么的；而且「上移」与「上一集」在中文里极易混淆。
2. **位置突兀**：它们夹在「重新缓存」（条件渲染，无字节时才出现）与
   「从剧集删除」（`text-destructive` 的破坏性动作）之间。排序是**结构编辑**，
   却和「删除」贴在一起，误点代价不对称。
3. **同一动作两个入口**：`SeriesDetail.tsx` 的右栏主动作条与
   `EpisodeExpanded.tsx` 的折叠卡动作区**各自渲染一份**，且用了**完全相同的
   `data-testid`**（`episode-move-up` / `episode-move-down`）——
   与「同一动作只留一个入口」的既有裁定（BUG-361 同族）相反，
   也让任何按 testid 取元素的判据拿到哪一份变成不确定。

另外，用户称其为「编辑中的」按钮，实际它们**不属于编辑态**：编辑态下
`EpisodeEditPanel` 里并没有上下切换控件（`EpisodeEditPanel.tsx` 里
`Chevron|Arrow|上一|下一|prev|next` 全部无命中），这两颗按钮是**恒显**的。
用户把它和「编辑」按钮归为一组，恰恰说明当前分组方式在视觉上没有边界。

## 根因

待定位（候选：图标按钮缺少可读文案 / 分组未按「结构编辑 vs 破坏性动作」分层 /
两个渲染点重复实现同一动作）。方案需先拍板：

- 方向 A（最小）：给两颗按钮补可见文案（「上移」「下移」）或合并成一颗
  「排序」下拉，并把它们从「删除」旁边移开；
- 方向 B：排序改为左栏选集器上的拖拽 / 行内手柄（那里本来就是集序的展示面），
  右栏不再出现排序入口 —— 顺带消掉重复入口与重复 testid。

## 复现

剧集详情 → 右栏动作条（`episode-primary-zone`）→ 观察 `episode-move-up` /
`episode-move-down` 两颗纯图标按钮的位置与可读性；再对比折叠卡
（`EpisodeExpanded`）里同名的两颗。

## 修复

待修复（需先在 A / B 两个方向里拍板）。
