# BUG-111：任务失败原因（持久化在 DB）在界面上原样直出传输层原文

- 状态: fixed
- 严重程度: mid
- 模块: shell
- 发现日期: 2026-09-22

**发现方式**：修完 BUG-110 后检查 daemon 聚合路径 `/api/activity`，在真实响应里发现一条
**仍然留存**的失败任务，其 `error` 字段是传输层原文：

```json
{"kind":"cache","status":"failed","actions":["retry"],"updated_at":1790013912,
 "error":"request error: dropped (cancelled)"}
```

`updated_at` 换算为 **2026-09-22 02:05:12**（早于当天 05:29 的重启）。

这条记录同时补上了 BUG-110 里缺失的那一项 —— **链路静默死亡确实真实发生过**，
不再是「只靠代码推断」。任务 id=65 至今仍在库里（`/api/tg/cache/tasks/all` 报 `failed: 1`），
也就是说修复前用户**随时都能在界面上看到**这条英文原文。

## 现象

两处渲染点都把持久化的 `task.error` 原样显示：

- `src/components/TgPanel.tsx`（任务失败提示）：只特判了「受保护内容」
  （`/os error 5|拒绝访问|access denied/` → `tg.protectedMedia`），
  **其余一律直出原文** —— 含 `request error: dropped (cancelled)`。
- `src/components/CacheManagerDialog.tsx`（缓存任务列表）：**完全没有分类**，
  `{task.error}` 直接渲染，连特判都没有。

## 根因

与 BUG-110 同源：**给用户看的 TG 文案没有单一真源**。BUG-110 修的是
「HTTP 响应体原文」这条路径（`api/tg.ts::request()`），而本条是**另一条路径** ——
失败原因由后端**持久化进 DB**、经 daemon `/api/activity` 聚合回传、再由组件渲染。

所以即便后端文案改好了，只要渲染点不分类，界面上仍是原文。

同一语义两处实现（TgPanel 有特判、CacheManagerDialog 没有）本身也是缺陷：
改需求时会齐刷刷错成一样（BUG-087 的教训）。

## 修复

在 `lib/tgReason.ts` 增加 `describeTgFailure(raw, t)` —— 与 `classifyTgReason`
（只回答「属于哪一类」）不同，它给出**可直接渲染的最终字符串**，把三件事收在一处：

1. 「受保护内容」的领域特例（优先于通用分类）；
2. `classifyTgReason` 分类 → `t(key)`；
3. 分类不出 → **保留原文**（与 `api/tg.ts::tgFailureMessage` 同一条理由：
   把「没有这个任务」说成「Telegram 暂时不可用」是谎报，还会给出错误的可行动指引）；
   原因为空 → 兜底 `tg.cacheFailed`。

两处渲染点改为共用它；原文由调用方 `logTgReason` 留痕。
`describeTgFailure` **保持纯函数、自己不打日志** —— 否则同一条原因在
正文与 `title` 两个渲染点会被记两遍。

## 验收证据

- 改动文件（跨机器可核验）：`tauri-shell/src/lib/tgReason.ts`、
  `tauri-shell/src/components/TgPanel.tsx`、`tauri-shell/src/components/CacheManagerDialog.tsx`；
  验收脚本 `tauri-shell/verify/verify_tg_error_i18n.cjs`。
- `tsc --noEmit` **0 错误**。
- `verify_tg_error_i18n.cjs` **17/17 PASS**（真实页面 `import` 真模块），新增 4 条针对本条：

```
PASS  persisted task error "dropped" renders the i18n network text
      -> "无法连接到 Telegram，请检查网络与代理设置后重试。"
PASS  protected media keeps its dedicated message
      -> "该内容受保护或访问被拒绝，无法缓存，可尝试在线播放"
PASS  unrecognised task error keeps its raw reason -> "no active cache task with this id"
PASS  empty task error falls back to tg.cacheFailed -> "缓存失败，请重试或改为在线播放"
```

  - 第 1 条用的就是**库里真实留存的那条原文**（`request error: dropped (cancelled)`）。
  - 第 3 条是反向证伪：认不出的原因必须保留原文，防止「把一切都不加区分地翻译」。

## 遗留

- 库里那条历史失败任务（id=65）的 `error` **仍是旧原文**。修的是渲染层，
  旧数据不会改写 —— 现在界面上会显示中文（因为渲染时分类），但 DB 里的值不变。
  若日后出现「显示中文、日志里是英文」的对照差异，属预期，不是不一致。
- daemon 侧 `/api/activity` 自身只是透传，未做分类；分类统一放在前端单一真源，符合既有约定。
