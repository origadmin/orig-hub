# BUG-346: 勾选无行级视觉反馈——选中态在界面上不可表达（点是选非）

- 状态: fixed
- 发现日期: 2026-10-21
- 模块: shell
- 严重程度: high

## 现象

用户夜报第 1 条：「下载状态不对，现在选中文件应该是选中，但是现在中是灰色，非
选中。整套逻辑有严重问题，不符合当前任何基础逻辑，违反常识。」

复现：入库流水线面板勾任意行，界面上**唯一变化**是复选框自身的勾；整行（容
器、标题、徽标、动作区）纹丝不动，与未选中行肉眼同。
结果 = 用户勾完看到的是「灰色的、没选上」，只能靠逐一比对 checkbox 内部像素确
认状态——违反「选中必须可见」这条基础约定。

## 根因

`CacheManagerDialog.tsx` 的 TaskRow（第 358-378 行）容器样式是**常量**：

```
className="rounded-md border border-border-subtle bg-surface-2/40 p-2.5"
```

`selected` prop 只流向 `<input type="checkbox" checked={selected}>`，从来没有进
入行容器 ⇒ **选中态没有呈现面**。同类形态：

1. `TaskRow`（第 358 行起）：勾选无任何行级状态；
2. `IngestDetailSheet` 明细行的选中态用 `bg-accent/5`——暗底上几乎不可见，与未
   选中的对比度不足以肉眼区分；
3. 批量条虽然有一 reading（`cache-selected-count` 读 N 条），但它挂在列表外，
   用户核对「哪几行被选中」时只能回头数 checkbox。

这不是「样式不够醒目」的偏好问题：**状态存在但没有表达通道**——「存在≠可用」，
按「让错误状态不可表达」的原理，选中态必须是行自身的属性，而不是一个 3.5px 复
选框的私有像素。

## 修复（已实施）

1. **行级选中态**：`selected` 进容器样式——`border-accent/60` +
   `bg-accent/[0.07]`，与 hover 态分层（hover 不变色，避免二者混淆）；
2. **复选框放大到可点尺寸**：行内与全选框一律 `h-4 w-4`（16px）+
   `accent-accent`（14px 是点不准的）；
3. **明细 Sheet 同步**（`IngestDetailSheet.tsx`）：`bg-accent/5` ⇒
   `bg-accent/10 ring-1 ring-accent/50`——选中态必须有**边界**（描边）而不仅是
   底色深浅；
4. **可观测性**：行容器带 `data-selected` + `aria-selected`，自动化可直接断言。

## 验收证据

- 探针 `tauri-shell/verify/_probe_bug348_pipeline.cjs` 判据 S1：勾选前后行的
  `backgroundColor`/`borderColor` 实测变化（`rgb(63,63,70)` →
  `oklab(0.695…/0.6)`）+ `data-selected="1"` + `aria-selected="true"` +
  复选框 16×16——**验牙**：把容器装回无 selected 分支的坏形态后 S1(legacy)
  必 FAIL（勾选前后一字不变），实测如此；
- 截图 `verify_shots/bug346-selected-row.png`：选中行绿描边 + 微绿底 +
  绿勾，与未选中行一眼可辨；批量条同步出现「选中 1 条」。

## 关联

- BUG-344：控件尺寸/状态的一等 token（本 BUG 是它的状态侧延伸）；
- BUG-327：「存在≠可用」——存在但不可见即视为不存在；
- BUG-149：批量删除的选择工具条（选中态是它的前置能力）。
