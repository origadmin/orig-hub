# BUG-262: 剧集内页没有「整季开播」入口 —— 左栏零播放入口、封面不可点、唯一入口是右栏逐集 ▶；而新增左栏入口与右栏 ▶ 会构成「同一命令的两个主按钮」

- 状态: open
- 发现日期: 2026-10-10
- 模块: shell
- 严重程度: mid

> 来源：用户报告「播放按钮的位置不应放在右侧详情区，而应在左侧提供一个『播放全部』的入口；右侧的单集播放按钮是否保留待定，感觉可能存在冲突，但不一定需要修复，请一并重新评估并给出结论。」

## 现象

### 现象 1：左栏（剧集总览 + 选集器）没有任何播放入口

`tauri-shell/src/components/media/SeriesDetail.tsx` 左栏 `<aside>`（`:369-601`）的元素与可点面：

| 区块 | 行号 | 可点面 / onClick 落点 |
|---|---|---|
| 总览海报 | `:370-390`（`series-cover` 在 `:373`） | **无 onClick**（纯 `<div>`） |
| 标题 / 元信息 / 标签 | `:393-412` | 无可点面 |
| 剧集介绍块 | `:414-468` | `series-desc-toggle`、`series-desc-edit` → 开编辑面板 |
| 总览操作行（5 个按钮） | `:470-522` | `series-edit`(`:478`) / `series-tag-edit` / `series-merge` / `series-export` / `series-delete` |
| 选集器 | `:530-601`（`episode-picker` 在 `:542`） | `episode-picker-collapse`(`:535`) 折叠；`episode-pick`(`:567`) → **只 `setFocusedEpisodeId(ep.id)`** |

左栏全部可点面的落点只有四类：开剧集编辑面板、开标签面板、折叠选集器、**选集行聚焦**。**没有一处调用 `onPlay`** ⇒ 左栏不存在任何播放入口。

### 现象 2：封面不可点 —— 2026-09-17 承诺的「替代入口」在现形态里没落地

`.workbuddy/memory/2026-09-17.md:110` 记载当日改动原文：

> **shell**：`MediaLibraryPanel` 左栏删逐条剧集列表仅留入口；`SeriesDetail` 去「▶播放全部」/常驻播放按钮、**改封面点击进查看器**+可编辑剧集/单集介绍；

取证：

- 现形态封面（`:370-390`）**无 onClick**。
- `git log --all -S 'data-testid="series-cover"' -- tauri-shell/src/components/media/SeriesDetail.tsx` 只有 1 个提交（`feef4e8`），该处 `onClick` 命中计数 **0** ⇒ 封面在 `SeriesDetail` 里**从未可点**。
- 唯一把封面做成可点的实现是**孤儿组件** `SeriesHero.tsx:145-148`（`onClick={props.onOpenCover}`），且它开的是**封面灯箱**（`media.series.coverOpen`），**不是播放器** ⇒ 与 09-17 记录的「进查看器」也不一致。

⇒ 09-17 那次移除**既没有留下替代的播放入口，也没有留下替代的封面点击**（`SeriesHero` 全仓零 import，见 `episode-internal-ia.md:24` 的孤儿清单）。

### 现象 3：唯一播放入口在右栏，且无字节时禁用

- `SeriesDetail.tsx:705` `episode-play`（`:695` 起注释）：`h-9 w-full` 实心、`disabled={!hasMediaBytes(cur)}`、`onClick={() => playEpisode(cur)}`。
- 语义 = 「从**当前聚焦的那一集**开始」。

### 现象 4（关键事实）：连播能力**已经存在** —— 缺的不是能力，是「起点 = 第一集」的入口

调用链（逐段已核对）：

1. `SeriesDetail.tsx:193-194`：`playEpisode(ep)` → `props.onPlay(detail.episodes.indexOf(ep))`
2. `SeriesDetail.tsx:115-116`：`onPlay` 契约注释原文「**从第 index 集开始播放（整季作为一个播放组，支持 ←/→ 切换）**」
3. `MediaLibraryPanel.tsx:462-465`：`playEpisode(index)` → `playItems(episodesToItems(detail), index, detail.title)`
4. `MediaLibraryPanel.tsx:396-416`：`playItems` 内若选中项属于剧集 → `loadSeriesDetail` → `episodesToItems(d)`（**整部剧集**）→ 按 `id` 定位起点 → `:407` `openViewer({ items: toViewerItems(all), index: start, title: d.title })`
5. `VideoPlayer.tsx:64-65 / 1083-1089 / 1317`：`nextUp` + `autoPlayNext` ⇒ 播完自动弹「即将播放」倒计时

⇒ **点任意一集的 ▶，打开的已经是整季序列**（同一条 `openViewer`、同一份 `items`、同一套自动连播），**唯一差别是起始下标**。

⇒ 用户要的「播放全部」在**运行时语义上已实现**；缺的是「起点 = 第 1 集」的**入口位置**与**可见性**。

## 冲突评估（用户问：右侧单集播放按钮是否保留、是否冲突）

**结论：冲突成立，但它不是「位置冲突」，而是「同一个命令的两个主按钮」。**

- 「左栏播放全部」与「右栏播放本集」调的是**同一条链**（`playItems` → 同一 `openViewer` → 同一整季 `items` → 同一自动连播），差别只有起始下标。
- 若两者都做成实心主按钮，则**同一屏出现两个外观等价、行为高度重叠的主按钮** —— 用户无法从外观判断差别在哪，这正是用户感到的「冲突」。
- **定档的准确作用域**：`episode-internal-ia.md:137` 与 `episode-internal-ia-v2-2026-09-29.md:131` 都写「▶ 播放本集 ← 唯一实心主按钮，独占一行，位置随集不变」，但该节标题是「**期望形态（右栏）**」⇒ 「唯一」是**右栏范围内**的约束。严格按字面，左栏加按钮**不违反该句**；**违反的是其意图**（一屏一主操作）。
- **已验收回归风险（量化）**：BUG-210 的验收脚本 `tauri-shell/verify/verify_play_primary.cjs` 有 18 项断言，其中
  - `210-A`（`:471-472`）断言 `[data-testid="episode-play"]` **全文档恰好 1 个** ⇒ 若新按钮复用同一 testid 会**直接 FAIL**；
  - `210-C`（`:482`）断言该按钮宽 ≈ 父容器内容宽 ±2px ⇒ 绑定右栏布局。
  ⇒ 任何改动都必须**同步改写脚本**，且**不得靠改断言变绿**（BUG-156：判据必须打在真实调用链上）。

## 修复方向（未实施；A/B/C 三选一 + 一个「不做」）

### 选项 A（推荐）：左主右辅，语义分化

- 左栏在动作行（`:470`）之前加「▶ 播放全部」实心主按钮（新 testid `series-play-all`），语义 = 从**第一个有字节的集**开始整季连播（起点定义见「待确认 2」）。
- 右栏 `episode-play`（`:705`）**保留但降为描边次按钮**、文案改「从本集开始播放」，与左栏形成「整季 / 从这集」的显式对照。
- `涉及:` `SeriesDetail.tsx`（左栏 + 右栏按钮）、`i18n`（zh/en 各 1~2 键）、`verify_play_primary.cjs`（210-A/210-C 按新语义改写）。
- `量化:` 新增 1 个 testid；改 1 个既有 testid 的 variant 与文案；改 2 项断言。
- `回归风险:` 中 —— 210-A 唯一性断言必须重写；210-C 宽度断言需重新绑定。
- `后果:` 一屏仍是**一个实心主按钮**（在左），「从本集播」作为次操作仍在场，**不丢任何能力**。

### 选项 B：只加不删（最小改动）

- 左栏加「播放全部」，右栏 `episode-play` **原样不动**，两按钮均实心、靠文案区分。
- `涉及:` `SeriesDetail.tsx` + i18n；`verify_play_primary.cjs` 的 210-A 需放宽为「右栏内恰好 1 个」。
- `量化:` 新增 1 个 testid；改 1 项断言。
- `回归风险:` 低（改动面最小）。
- `后果:` 能力不丢，但**留下两个外观等价的主按钮** —— 用户感到的「冲突」被固化。

### 选项 C：不加按钮，恢复「封面点击 → 从第一集开播」

- 把封面（`:370-390`）改成可点 → 整季开播（= 09-17 曾承诺的形态，但当时实现的是灯箱）。
- `涉及:` `SeriesDetail.tsx` 封面 + i18n（`title` 文案）。
- `量化:` 0 个新按钮；1 处 `div` → `button`；改 0 项 210 断言。
- `回归风险:` 低（不触碰右栏）。
- `后果:` 不新增主按钮、不违定档；但**可发现性差**（用户原话是「缺少入口」，把入口藏在封面上等于让用户猜），可能仍不满足其诉求。

### 选项 D：不做（维持现状）

- `涉及:` 无（0 行改动）。
- `量化:` 0。
- `回归风险:` 无。
- `后果:` 维持「整季连播已通过右栏 ▶ 可达，但须先点中某一集」的现状；用户「从第一集开始」的诉求**仍未被满足**。

## 修复后必须满足（可证伪判据，预先声明）

1. 若采纳 A/B：左栏存在**可见的**整季开播入口（testid `series-play-all`），点击后播放器打开的是**整季序列**、起始项 = 首个可播集。
2. 若采纳 A/B：**一屏内实心主按钮数量 ≤ 1**。判定必须读 `getComputedStyle` 的实际背景/变体结果，**不读 className**（Tailwind「追加修正类」会被层序静默吃掉）。
3. **反向证伪**：删掉左栏入口 → 判据 1 必须 FAIL；把右栏按钮改回实心 → 判据 2 必须 FAIL。
4. 不得删除右栏 `episode-play` 的既有 `data-testid`（BUG-149 / BUG-210 验收锚点），除非同步改写 `verify_play_primary.cjs` 并给出替代锚点。
5. 「起点 = 第一个有字节的集」必须可证伪：构造「第 1 集无字节、第 2 集有字节」的剧集，点「播放全部」后**播放器当前项必须是第 2 集**（现状无此入口，无从验）。
6. 全部改动须在真实 UI 上验（BUG-156），并在 `verify_play_primary.cjs` 上重跑至全绿。

## 待确认（口径）

1. **「播放全部」的落点**：① 左栏动作行（`:470-522`）之前，与「编辑 / 标签 / 合并 / 导出 / 删除」同区；② 选集器区块标题行（`:530-538`，与「收起」并列）；③ 封面右下角浮层按钮。
2. **「播放全部」的起点**：① 第 1 集（若该集无字节，播放器会停在失败态）；② 第一个**有字节**的集（跳过空集，但用户可能以为「从第 1 集开始」）；③ 第 1 集但**自动跳过**无字节集（需播放器支持）。请指认。
3. **右栏 `episode-play` 的处置**：保留为实心（选项 B）/ 降为描边（选项 A）/ 移除（需 BUG-149 论证，且会破坏 BUG-210 的验收锚点）。
4. **「播放全部」对图片集（photo）是否生效**？现状 `MediaViewer` 按 kind 分流（photo → browse，视频 → play），整季 `items` **混编但分组**；若「播放全部」的起点落在图片集，实际进入的是**图片浏览**而非播放 —— 需要明确文案与期望行为。
