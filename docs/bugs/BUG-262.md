- 状态: open
- 发现日期: 2026-10-10
- 模块: shell
- 严重程度: mid

> 来源：用户报告「播放按钮的位置不应放在右侧详情区，而应在左侧提供一个『播放全部』的入口；右侧的单集播放按钮是否保留待定，感觉可能存在冲突，但不一定需要修复，请一并重新评估并给出结论。」

### 现象 4（关键事实）：连播能力**已经存在** —— 缺的不是能力，是「起点 = 第一集」的入口

调用链（逐段已核对）：

3. `MediaLibraryPanel.tsx:462-465`：`playEpisode(index)` → `playItems(episodesToItems(detail), index, detail.title)`
4. `MediaLibraryPanel.tsx:396-416`：`playItems` 内若选中项属于剧集 → `loadSeriesDetail` → `episodesToItems(d)`（**整部剧集**）→ 按 `id` 定位起点 → `:407` `openViewer({ items: toViewerItems(all), index: start, title: d.title })`

## 冲突评估（用户问：右侧单集播放按钮是否保留、是否冲突）

**结论：冲突成立，但它不是「位置冲突」，而是「同一个命令的两个主按钮」。**

- 「左栏播放全部」与「右栏播放本集」调的是**同一条链**（`playItems` → 同一 `openViewer` → 同一整季 `items` → 同一自动连播），差别只有起始下标。
- 若两者都做成实心主按钮，则**同一屏出现两个外观等价、行为高度重叠的主按钮** —— 用户无法从外观判断差别在哪，这正是用户感到的「冲突」。
- **定档的准确作用域**：`episode-internal-ia.md:137` 与 `episode-internal-ia-v2-2026-09-29.md:131` 都写「▶ 播放本集 ← 唯一实心主按钮，独占一行，位置随集不变」，但该节标题是「**期望形态（右栏）**」⇒ 「唯一」是**右栏范围内**的约束。严格按字面，左栏加按钮**不违反该句**；**违反的是其意图**（一屏一主操作）。
- **已验收回归风险（量化）**：BUG-210 的验收脚本 `tauri-shell/verify/verify_play_primary.cjs` 有 18 项断言，其中
  - `210-A`（`:471-472`）断言 `[data-testid="episode-play"]` **全文档恰好 1 个** ⇒ 若新按钮复用同一 testid 会**直接 FAIL**；
  - `210-C`（`:482`）断言该按钮宽 ≈ 父容器内容宽 ±2px ⇒ 绑定右栏布局。
  ⇒ 任何改动都必须**同步改写脚本**，且**不得靠改断言变绿**（BUG-156：判据必须打在真实调用链上）。

## 修复方向（**已决：用户 2026-10-10 拍板选 A**；原选项留痕见下）

### 选项 A（推荐）：左主右辅，语义分化

- 左栏在动作行（`:470`）之前加「▶ 播放全部」实心主按钮（新 testid `series-play-all`），语义 = 从**第一个有字节的集**开始整季连播（起点定义见「待确认 2」）。
- 右栏 `episode-play`（`:705`）**保留但降为描边次按钮**、文案改「从本集开始播放」，与左栏形成「整季 / 从这集」的显式对照。
- `涉及:` `SeriesDetail.tsx`（左栏 + 右栏按钮）、`i18n`（zh/en 各 1~2 键）、`verify_play_primary.cjs`（210-A/210-C 按新语义改写）。
- `量化:` 新增 1 个 testid；改 1 个既有 testid 的 variant 与文案；改 2 项断言。
- `回归风险:` 中 —— 210-A 唯一性断言必须重写；210-C 宽度断言需重新绑定。
- `后果:` 一屏仍是**一个实心主按钮**（在左），「从本集播」作为次操作仍在场，**不丢任何能力**。

### 选项 B：只加不删（最小改动）

- 左栏加「播放全部」，右栏 `episode-play` **原样不动**，两按钮均实心、靠文案区分。
- `涉及:` `SeriesDetail.tsx` + i18n；`verify_play_primary.cjs` 的 210-A 需放宽为「右栏内恰好 1 个」。
- `量化:` 新增 1 个 testid；改 1 项断言。
- `回归风险:` 低（改动面最小）。
- `后果:` 能力不丢，但**留下两个外观等价的主按钮** —— 用户感到的「冲突」被固化。

### 选项 C：不加按钮，恢复「封面点击 → 从第一集开播」

- 把封面（`:370-390`）改成可点 → 整季开播（= 09-17 曾承诺的形态，但当时实现的是灯箱）。
- `涉及:` `SeriesDetail.tsx` 封面 + i18n（`title` 文案）。
- `量化:` 0 个新按钮；1 处 `div` → `button`；改 0 项 210 断言。
- `回归风险:` 低（不触碰右栏）。
- `后果:` 不新增主按钮、不违定档；但**可发现性差**（用户原话是「缺少入口」，把入口藏在封面上等于让用户猜），可能仍不满足其诉求。

### 选项 D：不做（维持现状）

- `涉及:` 无（0 行改动）。
- `量化:` 0。
- `回归风险:` 无。
- `后果:` 维持「整季连播已通过右栏 ▶ 可达，但须先点中某一集」的现状；用户「从第一集开始」的诉求**仍未被满足**。

## 裁定（2026-10-10 用户拍板）与三项追加解读

> 用户原话：「1. A　2. 第一集开始,如果播放过的从上次开始? 弹出重新开始播放? 3. 可以不修改,暂时不影响其他功能,是否和选项1冲突也需要重新评估。」

### 已定

| # | 项 | 裁定 |
|---|---|---|
| 1 | 方案 | **A** —— 左栏新增「▶ 播放全部」实心主按钮 |
| 2 | 起点 | **第一集**（整季从头播） |
| 3 | 右栏 `episode-play` | **暂不修改**（保留实心），理由「暂时不影响其他功能」 |

对本档原「待确认」的处置：**待确认 2（起点）已定 = 第一集**；**待确认 3（右栏处置）已定 = 暂不修改**；**待确认 1（左栏落点）改为工程师自决**（属方案内执行细节，不再回抛）；**待确认 4（图片集）仍然开放**。

### 追加解读 1：右栏保留实心与选项 A **确实冲突**，但冲突的性质是「信息层级」而非「功能」

- **功能上不冲突**（用户的判断成立）：两个按钮都能用，互不破坏，各自链路完整。
- **信息层级上冲突**：两者**调同一条链**（`playItems` → 同一 `openViewer`、同一整季 `items`、同一自动连播），**差别只有起始下标**（0 vs 当前聚焦集）⇒ 一屏出现两个**外观等价**的实心主按钮，用户无法从外观判断差别。这正是用户感到的「冲突」。
- **结论：可以按「暂不修改右栏」执行**，但必须同时满足两条，否则这个决定**没有任何门禁能守住**：
  1. **文案必须可区分**：左栏按钮文案「播放全部」，右栏按钮从 `media.episode.play`（现「播放本集」）改为**「从本集开始播放」**（1 个 i18n 键）。只加按钮、不改文案 = 用户真的分不清。
  2. **必须补判据（门禁缺口）**：`tauri-shell/verify/verify_play_primary.cjs` 的 `210-A`（`:471-472`）**只数 `[data-testid="episode-play"]` 的数量**，新增一个 `series-play-all` **不会让它 FAIL** ⇒ 现有脚本**测不出「多了一个实心主按钮」**，属**门禁假绿**。必须新增一条按 `getComputedStyle` 实际背景判定的「实心主按钮计数」判据（**不读 className**）。
- **登记为已知残余**：「一屏两个实心主按钮」在本次交付后**依然存在**。本档**不因「用户说可以不改」而销案**；等下次动右栏时一并处理。

### 追加解读 2：起点 = 第一集 与「从上次开始」**不能同时成立在同一个按钮上**

用户第 2 条同时提了两件事，但二者语义互斥：

- 「播放全部 = **从第一集开始**」⇒ **起点固定**的命令，天然**不续播**。
- 「播放过的**从上次开始**？弹窗**重新开始播放**？」⇒ **续播**命令，起点由进度决定。

⇒ **必须二选一，或拆成两个入口**（例如主按钮「播放全部」恒从头；续播作为独立的「继续观看」入口，或点击时弹窗二选一）。**不得**让同一个按钮在「有进度 / 无进度」时**语义跳变** —— 那会让「播放全部」这个词说谎。

### 追加解读 3：「从上次开始」当前**无法实现** —— 播放进度存储不存在（属**新能力**）

本轮只读取证（实测）：

| 检查项 | 结果 |
|---|---|
| 前端 `localStorage` 用途 | 只有三类：播放器设置（`usePlayerSettings.ts:31,62`）、历史目录（`recentDirs.ts:8,22,32`）、账户与设置（`useStore.ts:100,123,497,590`）。**无播放位置** |
| `resume` 标识符全仓 | 全部是**下载**的暂停/恢复（`api/daemon.ts:71-74`、`useStore.ts:257-261,408`、`DownloadItem.tsx:32,105`），**与播放无关** |
| 进度持久化 | **不存在**（生产库 `media_*` 无位置/进度列） |
| 既有裁定 | `docs/design/episode-internal-ia.md:172` R7 明写「**本轮不做续播（无进度存储）**」；`docs/design/media-library-management-prd-2026-09-22.md:174,272` R10（续播 / 最近播放）**已移入 §4.2 提案区**，理由「无用户原话支撑，需用户点头才立项」 |

⇒ **用户本次点头 = 该提案的立项前提已满足**；但它是**新能力**，不属于本档（入口位置）的范围，**建议另立一档**。最小代价已可预判：① 进度存储（表列或独立表）；② 上报节流 —— **禁用 `timeupdate` / `rAF`**（BUG-034 铁律），须按固定间隔或事件采样；③ 恢复与清除策略；④ 「继续观看」入口与文案。

## 修复后必须满足（可证伪判据，预先声明）

1. 若采纳 A/B：左栏存在**可见的**整季开播入口（testid `series-play-all`），点击后播放器打开的是**整季序列**、起始项 = 首个可播集。
