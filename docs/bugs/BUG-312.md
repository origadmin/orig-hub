# BUG-312: 下载页「清空历史」将误删 TG 入库记录（前瞻风险：M3 来源合并后逐条 DELETE 不区分来源）

- 状态: open
- 发现日期: 2026-10-14
- 模块: shell
- 严重程度: mid

## 现象

用户裁定（2026-10-14 原话）：「下载任务完成后清理历史不应该清理 TG 的入库记录。」

现状不触发（TG 任务尚未进下载列表，/api/activity 前端零消费见 BUG-300）；
**M3 一旦把 TG 任务并入下载列表**，现有「清空」会对 TG 行逐条发
`DELETE /api/cache/tasks/:id`，把承担「TG 全部下载索引」的 cache_task 历史抹掉。
本档为前瞻登记，防止 M3 实施时遗漏来源分流。

## 根因

- `tauri-shell/src/store/useStore.ts:488` `clearCompleted`：对过滤出的终态任务逐条 `DELETE`，
  无来源/能力判断。
- 删除端点按任务类型分发（引擎任务 / TG cache_task），TG 删除端点已有独立语义
  （api/tg.ts:455-523），但调用方不区分。

## 复现（M3 合并后）

1. 列表含 3 条 HTTP 终态 + 2 条 TG 终态任务；
2. 点「清空」；
3. 期望：3 条 HTTP 清除、2 条 TG 保留（管理仅在设置·缓存管理）；
   无防护实际：5 条全删，TG 入库索引丢失。

## 修复

按 **D21=A④**（2026-10-14）：

- 插件注册来源能力位（引擎 clearable=true / TG=false，M7 后 manifest 声明），
  clearCompleted 只删 clearable 的终态任务，混合选择后给 toast
  「TG 入库记录在 设置→Telegram→缓存管理 中管理」；
- TG 行保留重试/取消，删除仅设置缓存管理；media_item 与字节永不被「清空历史」触碰（AGENTS §5）。
- 夹具：3+2 混合清空 → 0+2，cache_task 行数对账。
