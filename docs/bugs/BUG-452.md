# BUG-452: 关闭 APP 后右下角托盘（Daemon 图标）消失、下载随之停止——关窗即退，违背下载工具常理

- 状态: partial
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: high
- 排期: 2026-11-03

> 状态说明（2026-10-28）：代码已落盘且编译期可核验（`CloseRequested` 拦截为 hide），
> 但**行为级验收必须在 release 壳跑**（dev 栈是纯前端 SPA，不含 Rust 窗口/托盘生命周期），
> 而 release 壳当前打不开（BUG-446，webview 挂起）⇒ 判据写完未执行，不得记 fixed。
> BUG-446 闭合后按 §验收证据 的 4 条判据复跑，通过再转 fixed。

## 现象

用户 2026-10-27 截图（`Clipboard_Screenshot.png`，约 20:00）报告：

> 「关闭APP后Daemon(右下角ICON)被删除了. 作为下载工具,这个流程是不符合正常逻辑的.」

点窗口关闭（标题栏 X 或系统关闭）后：右下角托盘图标消失、后台下载中断。作为下载工具，
正确流程应是「关窗 → 最小化到托盘、下载继续、托盘常驻」；当前实现把关闭窗口等同于退出
整个 APP。

## 根因：`lib.rs` 缺 `CloseRequested` 处理

- 标题栏关闭入口 `TitleBar.tsx:64-69` `handleClose` → `getCurrentWindow().close()`。
- Tauri v2 中 `close()` 最后一个窗口会触发 `WindowEvent::CloseRequested`；若无人拦截，
  窗口被销毁、run loop 结束、`app.exit` ⇒ **托盘（`main-tray`）随之销毁**，且
  `tauri-plugin-shell` 的 `RunEvent::Exit` 处理器会杀掉托管的 `orig-daemon` sidecar
  ⇒ daemon 变孤儿、下载中断。
- `lib.rs` 的 `.setup()`（:599-625）建了托盘（菜单「显示 / 退出」），但**全程没有**
  `.on_window_event(...)` / `CloseRequested` 拦截 ⇒ 关窗即退。这正好是 roadmap T-1
  「关窗不退出」未落地的体现。

## 修复

在 `lib.rs` 的 `tauri::Builder` 链上补 `.on_window_event(...)`（`.setup()` 之后、
`.invoke_handler()` 之前）：

```rust
.on_window_event(|app, event| {
    // BUG-452：关窗不退出——点 X / 标题栏关闭 → 最小化到托盘，下载继续、托盘常驻、daemon 不杀。
    if let tauri::WindowEvent::CloseRequested { api, .. } = event {
        api.prevent_close();                       // 拦截默认关闭
        if let Some(w) = app.get_webview_window("main") {
            let _ = w.hide();                       // 改为隐藏，进程不退出
        }
        shell_trace("[on_window_event] CloseRequested → prevent_close + hide (tray resident, downloads continue)");
    }
})
```

- `api.prevent_close()`：阻止窗口销毁（Tauri 2.11.5 `CloseRequested { api: CloseRequestApi }`，
  `CloseRequestApi::prevent_close()` 经 channel 通知 run loop 取消关闭）。
- `w.hide()`：窗口隐藏而非销毁 ⇒ 前端与 `orig-daemon` sidecar **继续存活**，下载不断。
- **真正的退出**仍只走托盘「退出」菜单（`app.exit(0)`，:617）：它触发 `RunEvent::ExitRequested`，
  由 `tauri-plugin-shell` 的退出处理器杀掉托管的 sidecar，进程干净退出。

> 与单实例锁（`single_instance` 插件）天然协同：窗口隐藏后被二次启动会经
> `get_webview_window("main").show()+set_focus()` 重新唤起（:588-594），不会出现「点开没反应」。

### 明确的产品决定（roadmap §8 决策 D-1）

关窗到托盘后下载**继续**（不是暂停）。理由：用户以「下载工具」视角批评，期望关闭窗口后
任务继续在后台跑（与 IDM / qBittorrent 等一致）。若日后要支持「关窗暂停」可配置，
改这里即可；当前按下载工具常理默认「继续」。

### 代码落地

`tauri-shell/src-tauri/src/lib.rs`（`.on_window_event(...)` 新增于 `.setup()` 与
`.invoke_handler()` 之间）。

## 验收证据

### 代码层（已落盘，API 已对版）

- 对照 `tauri-2.11.5/src/app.rs:118-121`：`CloseRequested { api: CloseRequestApi }`、
  `CloseRequestApi::prevent_close()`（:103-105）—— 本修复的字段名与调用签名与该版本一致，
  编译期可核验。
- `TitleBar.tsx:64-69` 的 `handleClose` 走 `getCurrentWindow().close()`，必触发
  `CloseRequested` ⇒ 被本处理器拦截为 hide，无需改前端。

### 真机验收判据（需 `tauri build` 重建 Rust 壳后执行；前端 dev 栈无法驱动托盘/窗口关闭，故未在此跑）

1. 启动 APP，开始一个下载任务，确认 `orig-daemon` 进程存活（如 `tasklist | grep orig-daemon`）。
2. 点标题栏 X / 系统关闭窗口。
3. **PASS 判据**：右下角托盘图标**仍在**；下载任务**继续**；`orig-daemon` 进程**未退出**；
   点托盘「显示 Orig Hub」窗口重新出现且下载进度连续。
4. 点托盘「退出」：**PASS 判据** = 进程完全退出、托盘消失、`orig-daemon` 被回收（无孤儿）。
