# BUG-474: 同机多 orig-hub 实例抢默认端口 19786/19787，把真实 orig-tg 挤到 19788/19789，TG 全断

- 状态: open
- 发现日期: 2026-10-28
- 模块: engine+shell
- 严重程度: high
- 排期: 2026-11-10

## 现象

`npm run tauri dev`（README 文档的 dev 流程）或运行 release app `orig-hub.exe` 后，
TG 面板打不开 / 显示异常，dev 启动→打开→TG 正确打开三条主干全部失败。

实测（2026-10-28 04:10，本机）：release 实例 `orig-hub.exe`(pid 39552) 拉起的两个 daemon 中，
有一个(pid 32152) 错误地绑定了 **19787**（本该是 orig-tg 的端口），把两个真实
orig-tg(pid 8500 / 24064) 挤到 **19788 / 19789**。前端从 `/api/config` 读到的 `tg_port`
与 tg 实际监听端口不一致 ⇒ TG 整条链路断掉。

## 根因

1. **daemon 无端口独占 / 单例护栏**：`orig-daemon` 默认监听 19786、tg 默认监听 19787
   （`config.rs:93` 注释缺省 19786；`state.rs:26` `TG_PORT=19787`）。端口被占用时
   只有 `tg_reselect_port` 顺延，但 daemon 自身也会去抢 19787，监管逻辑错乱，
   出现「daemon 占 tg 端口、tg 被顺延」的畸形布局。
2. **Tauri 应用无「同机仅一个实例」约束**：`tauri.conf.json` 的 `beforeDevCommand`
   把 `orig-daemon`/`orig-tg` 当 sidecar 拉起；release app 启动时同样拉起一套 sidecar。
   两个 Tauri 实例（release app 与 `tauri dev`，或 app 二次启动）各自拉起 sidecar 抢
   同一对默认端口 19786/19787 ⇒ 互斥冲突。这是「dev 启动 / 打开 / TG 正确打开」
   三条主干全失败的直接运行态根因。

## 复现

- 运行 `orig-hub.exe`（release）→ `netstat` 看 19787 被某个 `orig-daemon` 占用，
  `orig-tg` 落到 19788/19789。
- 或：release app 运行中再跑 `npm run tauri dev` ⇒ dev 的 sidecar daemon/tg 与 release
  抢 19786/19787。

## 验收证据

- 端口→进程映射（2026-10-28 04:10，`Get-NetTCPConnection`）：
  `19786→39616(orig-daemon)`、`19787→32152(orig-daemon，应为 orig-tg)`、
  `19788→8500(orig-tg)`、`19789→24064(orig-tg)`。
- `curl 127.0.0.1:19788/api/tg/session` → `phase:Authorized, user_id:523058983`
  （真实 tg 在 19788 是健康的，只是端口不对）；
  `curl 127.0.0.1:19787/api/tg/session` → 返回的是 daemon 的响应（端口错配）。
- 父进程关系（Win32_Process）：32152 / 39616 / 8500 / 24064 的父进程均为
  `orig-hub.exe`(39552) ⇒ 是同一 app 实例内部的端口错配，非外部进程侵入。
- 可核命令：`Get-NetTCPConnection -State Listen | ? LocalPort -in @(19786,19787,19788,19789)`
  与 `curl 127.0.0.1:19787/api/tg/session`、`curl 127.0.0.1:19788/api/tg/session`。

## 关联

- BUG-472（fixed）：dev 栈起来后前端连默认端口显示「媒体服务未运行」——同源「端口与前端
  指向不一致」类缺陷。
- BUG-453（fixed）：dev/release 二进制已分离，但**端口/会话仍共用默认 19786/19787**，
  未做实例级隔离 ⇒ 多实例必然撞端口。
- BUG-446（open）：release 壳打开即 Application Hang；本缺陷是 release 实例内部端口错配，
  二者叠加使 release 入口完全不可用。
