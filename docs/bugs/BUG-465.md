# BUG-465: 文件管理按钮入口混乱——库级与剧集级动作同屏混排、同义入口重复、播放类落位缺失

- 状态: open
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: high
- 排期: 2026-11-10

> 来源：用户 2026-10-27 截图报障（红框 = 混乱按钮，蓝框 = 可优化落位的按钮）：
> 「**按钮位置混乱。红色的是我标出来的混乱按钮，标签有 2 个，按钮的位置入口也都
> 考虑不全。蓝色我感觉播放全部或者其他部分按钮可以优化放入的地方。**」

## 现象

同屏出现**两组不同作用域**的动作，且出现同义重名入口：

1. **上下文栏库级四件套**（`shell/ContextBarFilesActions.tsx:33-82`）：
   导入目录（primary，`page-primary-action`）/ 新建剧集（`media-new-series`）/
   导出（`media-export-preview`）/ 标签管理（`media-tag-manage`）。
2. **左栏剧集实体动作 7 颗**（`SeriesDetail.tsx:747-839`，同一个
   `flex flex-wrap gap-1.5` 容器）：播放全部（`series-play-all`）/ 编辑（`series-edit`）/
   标签（`series-tag-edit`）/ 合并到…（`series-merge`）/ 拆分剧集（`series-split`）/
   导出预览——完整性校验（`series-export`）/ 删除剧集（`series-delete`）。
3. **同义重复**（用户原话「标签有 2 个」）：
   - 「标签管理」（库级，`ContextBarFilesActions.tsx:75-82`）
     vs「标签」（剧集级，`SeriesDetail.tsx:776-788`）；
   - 「导出」（库级，`:67-74`）vs「导出预览——完整性校验」（剧集级，`:817-828`）。
   两条路径词面几乎相同、作用域不同，用户无法从文案判断该点哪个。
4. **无分组、无主次**：播放类（播放全部）、编辑类（编辑/标签）、结构类
   （合并/拆分）、导出类、破坏类（删除剧集）混在同一行、同一视觉权重
   （`SeriesDetail.tsx:747`；单集侧同样 7 颗混排 `EpisodeExpanded.tsx:232-320`）。
5. **死代码持有重复 testid**：`SeriesHero.tsx:122` 与
   `ContextBarFilesActions.tsx:71` **共用 `data-testid="media-export-preview"`**；
   `grep -rn "<SeriesHero"` 全仓 0 命中（只在注释里被引用）⇒ 该组件未挂载，
   但它与线上按钮抢同一个 testid 契约，验收脚本按 testid 点击时会指向错误元素。

## 根因

1. **落位规则只做了「库级 vs 实体级」二分，没有「同屏去重」规则。**
   BUG-317 / BUG-451 定的是「库级四件套进上下文栏」，实体级动作进实体表面；
   两者在**同一屏同时可见**，规则没有覆盖「同屏时文案必须可区分」这一层
   ⇒ 同义词各挂一处，重复入口合法存在。
2. **7 个动作共用一个 `flex flex-wrap gap-1.5`**（`SeriesDetail.tsx:747`），
   没有分组容器、没有视觉分级（primary/secondary/ghost、危险色只给了删除）
   ⇒ 主次不可辨，位置由 flex-wrap 的换行结果决定（宽度一变布局就变）。
3. **播放类入口的位置从未被统一裁定**：播放全部在左栏（BUG-262），
   单集播放在右栏展开态（`episode-play`，`EpisodeExpanded.tsx:285-295`），
   另有一个全局播放器页（`MainLayout.tsx:268` 独占内容区）—— 三个播放入口
   分属三处，用户截图的蓝色区域即指此处的落位缺失。
4. **testid 契约没有唯一性校验**：同一个 id 被两个组件占用，
   且占用者之一是未挂载的死代码，静态检查未覆盖。

## 复现

1. 文件管理 → 剧集 → 打开任一部剧集进入详情。
2. 观察：上方上下文栏有「导出 / 标签管理」；左栏有「标签 / 导出预览——完整性校验」。
3. 数「标签」相关入口 = 2，「导出」相关入口 = 2；左栏 7 颗按钮同一权重混排，
   窗口宽度变化时换行位置随之变化。
4. `grep -rn "media-export-preview"` ⇒ 命中 2 个组件，其一（`SeriesHero`）未挂载。

## 修复方向（未实施；≥2 实质选项 + 1 个「不做」）

### 选项 A（推荐）：实体级动作分组 + 文案显式区分 + 清死代码

- 左栏 7 颗按性质分组：① 播放（播放全部）② 编辑与标签（编辑 / 标签）
  ③ 结构（合并到… / 拆分剧集）④ 导出与危险（导出预览 / 删除剧集，破坏类末位 + 二次确认）；
  组间用分隔线与间距区分，破坏类独立末位并走 danger 变体。
- 文案区分作用域：库级保持「导出 / 标签管理」，剧集级改为「本剧导出预览 /
  本剧标签」（zh/en 同步）。
- 删除未挂载的 `SeriesHero.tsx`（或改其 `media-export-preview` → `series-hero-export`），
  消除重复 testid 契约。
- `涉及:` `SeriesDetail.tsx:747-839`、`EpisodeExpanded.tsx:232-320`、
  `ContextBarFilesActions.tsx`、`SeriesHero.tsx`、i18n 2~4 键。
- `量化:` 动作数量不变（7），新增 4 个分组容器 testid；删除 1 个冲突 testid。
- `回归风险:` 中 —— **所有既有 `data-testid` 必须保留**（验收脚本依赖，
  BUG-149 能力不可删），只改容器与文案；需重跑引用这些 id 的 verify 脚本。
- `后果:` 主次可辨、同义词消失、死契约清除；改动集中在布局与文案层。

### 选项 B：先只做「去重 + 文案区分」，不动分组

- 剧集级「标签 → 本剧标签」「导出预览 → 本剧导出预览」，删 `SeriesHero` 的冲突 testid；
  分组留待下一轮。
- `涉及:` 2 处文案 + 1 处死代码。`量化:` 布局 0 改动。
- `回归风险:` 低。
- `后果:` 消掉「标签有 2 个」的困惑，但「7 颗同权重混排」的视觉混乱仍在。

### 选项 C：把剧集级动作整体收进一个「⋯」溢出菜单

- 主区只留「播放全部 / 编辑」两颗，其余进溢出菜单。
- `涉及:` `SeriesDetail.tsx:747-839` 重写 + 新增菜单组件。
- `量化:` 可见按钮 7 → 2。
- `回归风险:` 高 —— 大量既有 testid 需迁到菜单内（菜单未展开时不可点，
  验收脚本必须改成「先展开再点」，易造成假阴性）；且与「入口必须可见」
  的一贯判据（BUG-040：hover 才显形等于没有入口）冲突。
- `后果:` 版面最干净，但能力可发现性下降。**不推荐**。

### 选项 D：不做

- `涉及:` 无。`量化:` 0。`回归风险:` 无。
- `后果:` 用户每次进详情都要在两组同义按钮间猜；窗口宽度一变换行位置就变。
