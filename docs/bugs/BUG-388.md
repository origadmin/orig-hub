# BUG-388: 新监控频道无 sync_cursor 行时 list_channels 报「Null value」——监控列表整体不可用

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: engine
- 严重程度: high

## 现象

BUG-382 活栈验收（`verify_bug382_backfill_bounds.cjs` 受控样本路径）实测：
对空监控列表 `POST /api/tg/monitor/channels` 返回 `{"ok":true}` 后，
`GET /api/tg/monitor/channels` 返回 `{"error":"Null value"}` —— **整个监控
列表接口对「刚添加、还没跑过同步」的频道必炸**，用户加频道后列表直接打不开。

## 根因

`add_channel`（store.rs:991）只写 `monitored_channel`，**不建** `sync_cursor`
行；`list_channels` 的标量子查询

```sql
(SELECT COALESCE(sc.backfill_until, 0) FROM sync_cursor sc
  WHERE sc.channel_id = c.channel_id)
```

在 `sync_cursor` **零匹配行**时返回 NULL（`COALESCE` 在子查询内部，包不住
「没有行」的空集），rusqlite `r.get::<_, i64>` 读 NULL 即
`InvalidColumnType::Null` → 序列化成 `{"error":"Null value"}`。

`backfill_until` 列（BUG-327）就有同款隐患，只是存量频道恰好都有 cursor 行
被掩盖；BUG-382 新增 `backfill_before_id` / `last_message_id` 两列同模式，
受控样本（无 cursor 行）第一次把它打穿。

## 修复

三处标量子查询 `COALESCE` 外移：`COALESCE((SELECT sc.<col> FROM sync_cursor sc
WHERE sc.channel_id = c.channel_id), 0)` —— 空集显式落到 0，不再依赖
「cursor 行恰好存在」。

## 验收证据

探针 `tauri-shell/verify/verify_bug382_backfill_bounds.cjs`（活栈，含受控
样本 + 残留=0 清理断言）：

| 判据 | 修复前 | 修复后 |
|---|---|---|
| A1 wire 字段（backfillBeforeId/lastMessageId 数值） | FAIL（GET 报 Null value） | PASS |
| A2 真源非零同步游标 | FAIL | PASS |
| A4 夹具清理（监控列表还原为空，残留=0） | PASS | PASS |

单测：`monitored_channel_list_without_cursor_row_bug388`（无 cursor 行的频道
list_channels 必须返回 0 值字段而非 Err）。验牙：装回旧 SQL（COALESCE 在
子查询内）该单测必红。
