# BUG-378: 《时停手表》EP1-3 三集裂成两个剧集，EP3「丢失视频」

- 状态: fixed
- 发现日期: 2026-10-22
- 模块: engine
- 严重程度: high

## 现象

用户 2026-10-22 报：「筛选：时停手表 -> 《时停手表》EP1-3 原档观享 连载中 丢失视频。
另外缺少跳入对应那一条的跳转入口。」

实测（orig-tg 19787）：

| 事实 | 值 |
|---|---|
| 相册组 | `-1003969766003` 3265(photo)+3266(video)+3267(video)+3268(video)，media_message.group_id 全 = 14331794048475109 |
| caption | 只挂 3268：「🌟⚡️🔥《时停手表》EP1-3 原档观享 连载中 ⭐⭐⭐」 |
| 整组缓存任务 | `cache_task` 201：`items=[3268,3267,3265]`（**漏 3266**） |
| 剧集 486 | 「🌟⚡️🔥《时停手表》EP1-3 原档观享 连载中 ⭐⭐⭐」，`source_key=tg:named:-1003969766003:🌟⚡️🔥《时停手表》`，含 EP1(1586=3268)/EP2(1587=3267) |
| 剧集 266 | 「🌟⚡️🔥《时停手表》」，`source_key=tg:group:-1003969766003:14331794048475108`，含 EP1(1260=3266) |

⇒ 用户打开《时停手表》EP1-3 只见 2/3 集，EP3（条目在库、字节 present）
「丢」进了另一部同名短剧集。

## 根因

`file_items_into_series`（`media.rs:5043`）的剧集键派生：
`(chat, msg) → cache_task_msg_index` 取**任务行**的 `(group_id, first, items)`；
组级剧名 `first_caption(chat, items)` 只翻**该任务入队的消息集合**。

- 3266 是很早一次**单条任务**导入的：`items=[3266]`，caption 空 ⇒ name 空 ⇒
  键退化成 `tg:group:{chat}:{任务行 group_id}`，而那个任务行的 group_id 是
  **陈旧的 108**（`media_message` 权威值是 109）⇒ 键 `tg:group:…108` ⇒ 剧集 266。
- 3267/3268 走任务 201：组内有 caption ⇒ name 非空 ⇒ 键 `tg:named:{chat}:时停手表`
  ⇒ 剧集 486。

**named 键与 group 键是两套互不相交的命名空间**，同一相册因此裂成两部。
与 BUG-292「两处规则分叉 ⇒ 同一条内容裂成两个剧集」同型：键的 group 分量
信了任务行快照，没信 `media_message` 的权威组归属。

## 修复

1. 键派生改以 `media_message` 为权威：name 为空时（单条/子集任务拿不到组内
   caption）按该消息的**权威 group_id** 取同组全部消息再找一次 caption；
   退化键的 group 分量同样取权威 group_id，任务行 group_id 仅作
   media_message 缺失时的兜底。
2. 数据修复：`media_episode` 把 1260 从 266 挪到 486（ep3），删空壳 266。
3. 回归测试：单条任务 + 组内 caption 挂别条 ⇒ 键必须与整组任务一致
   （装回旧实现必红）。
