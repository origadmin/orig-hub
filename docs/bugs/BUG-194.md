# BUG-194 会话缓存里 156 条 title 为空串：列表渲染成认不出的空白行

- **状态**: open
- **发现日期**: 2026-09-29
- **模块**: engine+shell
- **严重程度**: mid

关联 BUG-192（追查置顶频道时顺带查出）、BUG-037/039（同一性判定）、BUG-149（判据打在实质）。

## 现象

对会话缓存做体检（2026-09-29 实测，`GET /api/tg/dialogs` 分页取全 519 条）：

```
总数 519
标题为空/纯空格 : 156   （全部为正 id，即用户 / 私聊）
有名称          : 363   （频道 / 群组 279，用户 / 私聊 84）
重名            : 12 组（如「全网鉴黄中心」×3、「1」×3）
```

156 条 `title` 是 `''` 且 `username` 为 `None`。

前端 `groupChannels`（`tauri-shell/src/components/TgPanel.tsx:584-597`）**只按搜索词过滤，
不过滤空标题** ⇒ 列表里会渲染出 **156 个空白行**，用户无法分辨任何一个。

## 根因

`channel_from_dialog`（`download-engine/crates/orig-tg/src/grammers.rs:888-900`）：

```rust
title: peer.name().unwrap_or_default().to_string(),
```

`peer.name()` 对**解析不到名字的 peer** 返回 `None`，`unwrap_or_default()` 直接兜底成空串
——**一个「没有名字」的事实被降级成了「名字是空字符串」，信息就此丢失**，且没有任何标记说明
「这条是解析失败的」，与「真的叫空名字」无法区分。

补充事实：这 156 条全为正 id（用户 / 私聊），频道与群组（负 id）**没有出现空标题**
⇒ 影响面是用户 / 私聊这一类，不是全部会话。

## 修复

不许再用 `unwrap_or_default()` 把「未知」降级成「空」：

1. `Channel` 的 `title` 允许表达「无名称」，或**补一个可展示的兜底标识**
   （例如 `已删除账户` / 用 id 末段，取哪种属产品裁定，**不许直接留空**）；
2. 更好：枚举时区分「名字为空」与「peer 解析失败」，后者不应静默入库成一条无名记录；
3. 前端对无名称条目给可识别占位（不许渲染成完全空白的一行）。

## 验收

- 对 519 条会话断言：**`title` 为空串的条数 = 0**（当前 156）；
- 每个条目在列表里都有**可辨识的展示文本**；
- 频道 / 群组部分（279 条）不受影响，不回归；
- **反向证伪**：把 `unwrap_or_default()` 注回，验收脚本必须**变红**（EXIT ≠ 0）；
  证伪须自动还原并自证（`sha256` 前后一致）。
