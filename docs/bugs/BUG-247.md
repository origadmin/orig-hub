# BUG-247: 缺陷门禁逐次 spawn git —— 全量跑 916 次子进程、399 s（最慢 7 分 0.8 秒），而候选集合有限且可预先枚举

- 状态: fixed
- 发现日期: 2026-10-10
- 模块: docs
- 严重程度: mid

## 现象

`python scripts/check-bugs.py` 全量跑的耗时与「判据复杂度」完全不成比例：

| 实测 | 值 |
|---|---|
| 耗时（2026-10-09 一次） | **399 s（6 分 39 秒）** |
| 耗时（同日另一次，同一份档案） | **420.8 s（7 分 0.8 秒）** |
| 耗时（历史记录，241 条时） | 231.8 s（3 分 54 秒） |
| 登记条数 | 241 → 246，耗时随之**线性增长** |
| 门禁**逻辑**本身 | 纯字符串与正则比对，无重活 |

**它不是慢在判据上，而是慢在「问 git 的方式」上**（见根因）。

**影响面（本条真正要解决的问题）**：登记册当时有 **53 条未终态缺陷**
（`open` 50 + `in_progress` 2 + `partial` 1），而**每一次修缺陷都要动 `docs/bugs/**`**
⇒ 每次修缺陷的提交都要付一次全量门禁 ⇒ 53 × 约 7 分钟 ≈ **6 小时纯等待**。
**「紧迫性大降」的判断因此是错的**：修完作用域（BUG-242）只挡住了「纯文档/纯代码改动」，
挡不住「修缺陷」这一大类 —— 而后者正是当时的全部工作。

## 根因

`scripts/check-bugs.py` 的两个判定函数**逐次 spawn 子进程**：

- `git_has_commit(sha)` → 每次 `git cat-file -e <sha>^{commit}`
- `git_ignores(rel)` → 每次 `git check-ignore -q -- <rel>`

而它们在扫描 242 份档案时被**反复**调用 —— 同一个路径会在几十份档案里重复出现。

**实测计数**（把 `subprocess.run` 换成只计数的假实现，脚本见「复现」）：

| 命令 | 调用次数 |
|---|---|
| `git check-ignore` | **871** |
| `git cat-file` | **45** |
| **合计** | **916 次子进程** |

**去重后的候选其实很小**：`PATH_RE` 命中 **284** 个不同路径、`HASH_RE` 命中 **66** 个不同 hash。
即 **871 次调用只问了 284 个不同问题**（约 3.1 倍冗余）。

单次 `git` 进程启动在本机约 **430–460 ms**（399 s ÷ 916 ≈ 435 ms），
**916 × 435 ms ≈ 399 s —— 与实测吻合**。

> 结论：**成本 = spawn 次数 × 进程启动开销**，与判据复杂度无关。

## 复现

```python
import subprocess, collections, importlib.util, sys
sys.argv = ["x", "--quiet"]
calls = collections.Counter()
class R:
    def __init__(s, rc, out=""): s.returncode, s.stdout, s.stderr = rc, out, ""
def fake(a, *x, **k):
    calls[tuple(a[:2])] += 1
    return R(0, "")
real = subprocess.run
subprocess.run = fake
spec = importlib.util.spec_from_file_location("cb", "scripts/check-bugs.py")
m = importlib.util.module_from_spec(spec); spec.loader.exec_module(m)
m.main()
subprocess.run = real
print(sum(calls.values()), calls)
```

改前输出 **916**；改后输出 **2**。耗时可直接量：`time python scripts/check-bugs.py --quiet`。

（注意：该假实现返回 `rc=0` 且空输出，会让门禁报出一批「提交不存在 / 路径不存在」的 ERROR ——
那是**假实现的产物**，不是登记册的真实状态。它只用于**计数**。）

## 修复

**「先扫一遍文件取出全部候选 → 各发一条批量命令」**：

1. 新增 `_prefetch_git()`：预扫 `docs/bugs/*.md`，用 `PATH_RE` / `HASH_RE` 收齐候选，然后**各发一条**命令 ——
   `git check-ignore --stdin -z`（NUL 分隔，避免路径含空格或非 ASCII 时产生歧义）与
   `git cat-file --batch-check`（一次问完所有 hash）。
2. `git_ignores` / `git_has_commit` 改为**先查缓存**（`_IGNORED` / `_COMMITS`）；
   缓存未建立时才退回原来的逐次实现。
3. **语义不变**：批量命令 rc 不在允许集合内（无 git / 非仓库 / 命令缺失）时缓存保持 `None`
   ⇒ **自动退回逐次实现**，不静默降级、不改变判定结果。
4. `git cat-file --batch-check` 的回显是**解析后的完整 hash**（只有缺失行才回显输入表达式），
   故「存在」按「候选是某个已解析完整 hash 的**前缀**」判定 —— 不依赖行序、不依赖回显格式。

**效果**：**916 次 → 2 次**；全量跑 **399 s → 2.787 s（约 143×）**。

5. **降级路径不变**：令批量命令不可用（例如 `git` 不在 PATH）后跑，必须仍能给出结论
