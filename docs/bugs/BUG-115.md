# BUG-115：「加入媒体库」只入库、不落盘 —— 断网后打不开

- 状态: open
- 严重程度: high
- 模块: engine+shell
- 发现日期: 2026-09-22

## 现象

用户点了「加入媒体库」，断网后再打开，**内容打不开**。

## 用户认知与实际行为

- 用户以为：**进了我的库 = 在我电脑上**。
- 实际：只写了索引，**字节还在 Telegram**（图片连 `file_path` 都是 NULL）。

## 根因

`media_item` **没有「字节状态」字段**，编目与落盘被压成同一个动作，而 TG 面板的按钮
按内容类型走了两条不同的实现：

```
TgPanel.tsx:1885-1915
  含视频 → 文案「缓存」      = 落盘 + 入库
  纯图   → 文案「加入媒体库」 = 只入库、不落盘
```

**同一个按钮、两种语义**，用户无从分辨。

## 已定案（用户 2026-09-22 拍板）

> 「肯定是离线优先啊，当前是一个下载工具，缓存不就为了流畅本地播放的么？」

- 「加入媒体库」与「缓存」在**用户可见层**合并为一个动作：**「缓存到媒体库」**
  （内部由编排层按序驱动：编目 → 落盘 → 置 `byte_state=cached`）；
- **取消「只入库、不落盘」这个用户可见终态** —— 它是本条、BUG-116（行为不一致）、
  BUG-117（大图退化成缩略图）三个问题的**共同源头**；
- **图片同样落盘**；
- 缓存失败必须**显式给重试入口**，**不得静默降级为「仅入库」**。

> **用户 2026-09-22 追加澄清（防止把这条读成"合并模块"）**：
> 「视频、图片、内容**有先后**，原本分离式是为了让**两个模块各自工作、不互相影响**。」
>
> 即：合并的是**用户可见的动作**，**不是**编目与落盘这两个模块 ——
> 两者**仍保持正交解耦**（有先后、各自工作、互不影响）。见评审文档第 3 节。

## 修复方向

1. **编排层按序驱动**：编目 → 落盘 → 置 `byte_state=cached`。
   落盘失败**不毁编目** —— 条目保留、标 `byte_state=absent`、给显式重试入口。
   要禁止的是「**已入库却无字节、且不标状态、也不给重试入口**」这种**静默态**，
   不是禁止「编目先于落盘」（后者正是用户要保留的解耦）。
   —— 注意：写成「落盘失败则不入库」是把两个模块**重新耦合**，与用户澄清相悖。
2. `byte_state` 常态为 `cached`；`absent` / `partial` 是**异常或过渡态**，UI 必须能解释
   并给重试入口，不能当作一种合法的「已入库」状态。
3. 按钮按状态呈现（不再按内容类型）：未缓存→「缓存到媒体库」；缓存中→进度+取消；
   已缓存→「已缓存」+播放入口；失败→重试。
