# BUG-135：删除媒体条目时文件删除与 clear_downloaded 失败被静默吞——接口假成功

- 状态: open
- 发现日期: 2026-09-22
- 模块: engine
- 严重程度: mid

## 现象

删除媒体条目时，若磁盘文件删除失败（文件被占用、只读等）或 `clear_downloaded` 失败，接口照常返回成功，界面无任何提示——用户以为删干净了，实际字节还占着磁盘；下次按 `source+ref` 幂等 upsert 还会把条目「复活」（BUG-029 时代实测过的「删不掉」表象）。

## 根因

`routes.rs:2107-2140` `delete_media_item` 中两处吞错：

```rust
let _ = std::fs::remove_file(p);
let _ = st.store.clear_downloaded(chat, msg).await;
```

这与同文件 `reset_tg_flag` 的既有判定（BUG-109：「失败必须如实报错」）**自相矛盾**——同一个文件里两种纪律。

## 复现

Windows 下用播放器打开条目文件（占用锁）→ 在媒体库删除该条目 → 返回 200 成功，文件仍在磁盘。

## 修复

- 失败必须如实上报；部分成功也要如实区分（参照 `removed: 0` 的幂等删除语义与 BUG-109 判定）。
- 前端对「条目已删但字节未回收」给可行动提示（如「记录已删除，文件被占用未能清理，可稍后在缓存管理中回收」）。
