# BUG-314: 下载侧栏违规新增「已取消」树档——主 NAVI 标准化被破坏（BUG-300 复报③ 引入的回归）

- 状态: fixed
- 发现日期: 2026-10-15
- 模块: shell
- 严重程度: high

## 现象

用户 2026-10-15 原话：「严重的状态逻辑问题,"已取消"不是暂停? 主NAVI数量是严格限制和标准化的,
现在莫名多了一个,无标注无逻辑添加的"已取消",没有任何提示.」

下载父行展开后出现**第四个**树子项「已取消」（`data-testid="nav-child-dl-cancelled"`），
与 running/paused/done 三项并列。标准化下载树只有三项；且 `cancelled` 是**终态**，
与 `paused`（引擎暂停态）并列成「档位」把终态与活跃态混成一排。

## 根因

BUG-300 复报③「取消不消失」修复中，我方自行把 `cancelled` 加进 `DL_FILTERS`
（`tauri-shell/src/nav/index.ts`）并在 `shell/Sidebar.tsx` 渲染成第四子项 —— **未经导航
标准化流程**：无标注规范、无逻辑说明、未向用户提示即上线。`nav/index.ts` 与
`domains/download/ingestGroups.ts` 里「2026-10-15 用户裁定」注释与事实不符：
用户 ③ 的原话只要「记录不消失」，从未裁定「独立树档」—— 是我方解读越权。

## 复现

1. dev :5180 → 侧栏「下载」父行展开；
2. 数树子项：出现 `nav-child-dl-running/paused/done/cancelled` **四项**（标准化为三项）。

## 修复

撤档，记录可见性改由既有标准化机制承担：

1. `nav/index.ts`：`DlFilter` 与 `DL_FILTERS` 回退为 `all/running/paused/done` 四项，
   删「2026-10-15 用户裁定」注释；
2. `shell/Sidebar.tsx`：`DL_KEY` 删 cancelled；子项计数删 cancelled 分支；
3. `shell/MainLayout.tsx`：侧栏 counts 删 cancelled（引擎+入库合并计数整项）；
4. `domains/download/DownloadPanel.tsx`：删 `case 'cancelled'` 树档过滤；
5. `domains/download/ingestGroups.ts`：`groupInBucket` 删 cancelled 档与注释；
6. i18n 两语删 `download.cancelled` 键；
7. **保留**：`summarizeGroups` 的 `cancelled` 计数与概览「已取消」读数（次级信息，非导航），
   「全部」档本就含终态行 —— 取消后记录仍在列表里、可数、可重试。
