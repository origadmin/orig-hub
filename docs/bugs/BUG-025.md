# BUG-025: `/api/tg/code` 在未登录（含服务不可用）时回「已授权」—— 交验证码即伪造出登录态

- 状态: fixed
- 发现日期: 2026-09-17
- 模块: engine
- 严重程度: high

## 现象

TG 不可用（无凭证 / 连不上 MTProto）时，调用 `POST /api/tg/code` 提交验证码，
服务端返回 **HTTP 200 + `{"phase":"Authorized"}`**，但实际什么都没做：

```
POST /api/tg/code {"phone":"+100...","code":"00000"}
-> 200 {"phase":"Authorized"}     # 服务端处于 unavailable，根本没有人处理这个验证码
```

前端据此认为「登录成功」，随后所有业务请求才逐个 503/401 —— 用户看到的是
「明明登录成功了，进去却什么都打不开」，与 BUG-023 的「登录丢失」互为镜像。

## 根因

`crates/orig-tg/src/routes.rs` 的 `code()` 处理器把提交阶段收敛成一句：

```rust
LoginPhase::Anonymous | LoginPhase::Authorized => LoginPhase::Authorized,
```

三处叠加导致这句成为「伪造登录」：

1. **`Anonymous` 被折叠成成功**：只有 `CodeRequired` / `PasswordRequired` 才真正
   把验证码交给客户端；`Anonymous`（压根没发起登录）直接返回 `Authorized`，
   既不校验也不报错——这是纯粹的状态伪造。
2. **不可用时的 `view()` 恰好返回 `Anonymous`**：`UnavailableClient::view()` 为保持
   空对象语义返回 `LoginPhase::Anonymous`，于是**不可用必然落进伪造分支**——
   故障被翻译成「登录成功」，故障越严重、欺骗越彻底。
3. **`code()` 未做可用性前置检查**：只有业务读写端点走了 `ensure_authorized`，
   登录链路的 `start()` / `code()` 没有 —— 偏偏这两条是用户最先碰到的。

## 复现

```bash
# 生产二进制、无凭证（TG 不可用），隔离端口
ORIG_TG_PORT=9881 ORIG_TG_DB=/tmp/t.db ORIG_TG_SESSION=/tmp/t.session \
  download-engine/target/release/orig-tg.exe &
curl -s -X POST http://127.0.0.1:9881/api/tg/code \
     -H 'Content-Type: application/json' \
     -d '{"phone":"+10000000000","code":"00000"}'
# 修复前：200 {"phase":"Authorized"}   ← 撒谎
# 修复后：503 {"error":"telegram unavailable: ..."}  ← 说真话
```

## 修复

1. **`code()` 先判可用性**：入口处 `ensure_available(st)?`，不可用 → 503 + 原因；
   `start()` 同样处理（否则「发码」会返回一个永远不会到来的成功）。
2. **`Anonymous` 不再折叠成成功**：改为显式 400「尚未发起登录，请先调用 /api/tg/start」，
   只有 `CodeRequired` 收到验证码、`PasswordRequired` 收到密码才推进阶段。
3. **`ensure_available` / `ensure_authorized` 顺序固化**：先可用性、后登录阶段 ——
   顺序反了会把「服务故障」伪装成「401 未登录」（BUG-023 的核心误导路径）。

## 验证

`verify_shots/run_availability_verify.sh` 的 S1 场景（23/23）新增断言：
不可用时 6 个 TG 端点全部 503 且**原因可读**，并且**明确排除 `not authorized` 这类
「未登录」伪装**；`/api/tg/diag`、`/api/tg/session` 下发 `available=false` + 原因。

## 关联

- BUG-023（连接失败静默退化 dummy）—— 同一根因家族：**对外状态与真实状态不一致**。
  023 是「服务不可用却说可用」，025 是「登录没发生却说已登录」。
- **防再发**：登录链路的每个阶段推进都必须由**真实客户端的一次成功调用**驱动，
  不允许存在任何「按当前阶段推断出成功」的默认分支；
  空对象模式的对象必须**只返回错误**，绝不返回推进性状态。
