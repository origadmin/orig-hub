# BUG-237：ffmpeg 设置未实现——引擎有解析链、壳层零呈现，参考项目未分析

- 状态: open
- 发现日期: 2026-10-09
- 模块: engine+shell
- 严重程度: mid
- 登记: 用户报告「ffmpeg 设置没有实现，参考项目没有分析」，
  参考项目 https://github.com/Lake1059/FFmpegFreeUI

## 现象

设置页无任何 ffmpeg 项：不显示检测到的 ffmpeg 路径/版本、无二进制管理
（内置/指定路径/未安装降级）、无转码参数设置。引擎侧已有第 4 落点解析链
（`routes.rs` resolve_ffmpeg_path：含 `%LOCALAPPDATA%/OrigHub/bin`），但这一事实
对用户完全不可见——本机 ffmpeg 已就位，设置页却无从知晓。

## 根因

ffmpeg 一直是引擎内部实现细节，从未被当作用户可见的**能力/插件**建模（与 BUG-238
同源）。参考项目 FFmpegFreeUI（ffmpeg 的 GUI 封装，参数可视化）尚未做调研分析，
转码参数（preset/crf/fps，见 EncodeProfile）暴露给用户的形态无设计输入。

## 修法方向

1. 先做 FFmpegFreeUI 调研（功能面：参数 UI、二进制管理、任务队列），产出分析结论；
2. 最小闭环：设置页 ffmpeg 状态行（检测路径/版本/是否可用）——与 BUG-233 的
   状态呈现同批实现；
3. 参数 UI 与「ffmpeg 作为插件/未安装走系统默认播放器」的形态随 BUG-238 插件框架
   一起定。
