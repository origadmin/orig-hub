# BUG-407: 剧集合并逻辑错误——合并后剧集累加、视频集出错

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: engine+shell
- 严重程度: high

## 现象
剧集合并逻辑存在严重错误。示例：剧集 A 含 1,2,3，剧集 B 含 2,3,4，合并后正确结果应为
1,2,2,3,3,4（其中 2、3 各有两个源），即「同集多源归并、不同集各自保留」。但当前实现
合并后剧集被累加，视频集（episode 集合）出现错误——区间/槽位处理未能按「集号」归并，
导致集号重复累加而非同号多源。

## 根因（实测定位）

`merge_one_source_in_tx`（`download-engine/crates/orig-tg/src/media.rs`）**没有任何
「同一集」判定**，只有两条规则：

1. 去重维度是 `item_id`（`have.get(season).contains(item_id)`）—— 只回答「这条记录在不在
   目标同季」，不回答「这个集号是不是同一集」；
2. 声明位被占 ⇒ `next[season] + 1` **续编**（原 `:4342-4348` 的 `declared_free` 分支）。

于是 A 的第 2 集（B 的第 2 集想落的槽）被判「被占」⇒ B 的第 2 集被编成第 4 集，
B 的第 3 集编成第 5 集 ⇒ 用户看到 1,2,3,4,5,6 而不是 1,2,2,3,3,4。
`media_episode_source`（备用源表）在整个函数里**零写入**，所以「一集多源」在合并场景
永远不可达 —— 这正是 BUG-284 报的同一件事的另一种说法。

设计文档 `docs/design/episode-multi-source-design-2026-09-22.md` §12 D1 早已拍板 **A（同槽
归并为多源）**，但代码从未落地（D1 之后只有 BUG-186 加了批量入口，引擎零改动）。

## 修复

`merge_one_source_in_tx` 在槽位分配**之前**插入一道「同一集判定」，命中就不占新集号，
而是把源条目降为目标对应分集的**备用源**。判据**只有一条**：

| 判据 | 结论 |
|---|---|
| 两侧 `content_hash` 相同（非空） | 同一集（同一个文件，与集号无关） |
| hash 不同，或**任一侧没有 hash** | 不同集 ⇒ 各自保留、续编 |
| 声明区间是合集（`episode_no_end > episode_no`） | 只走续编（占多槽，不参与归并） |

> **集号（同季同集号）不构成同一性依据。** 用户 2026-10-23 追加裁定原文：
> 「同槽且两侧都没 hash 的条目现在会归并成一集多源……这是永远不可能的事情，文件怎么可能
> 没有 hash，hash 是根据文件内容生成的，**没有 hash 说明没有文件，两边都是空，不存在合并**。」
>
> 该裁定推翻了本档首版实现里「同槽 + 两侧 hash 不冲突 ⇒ 同一集（L1 回退）」那一条：
> 两侧都没文件时根本不存在「同一份内容」，按集号认会把两条空记录错误地钉成一集多源。

落位：视频进 `media_episode_source`（`merge_attach_same_episode`，幂等 + `item_id`
全表 UNIQUE 冲突如实记入 `skipped`）；图片进 `media_episode_image`（同集多图）。

配套改动：

- `MergeReport` 新增 `merged_same_episode`（同集归并条数）与既有 `sources_attached`
  （视频备用源条数，此前恒为 0）；路由 JSON 一并下发 `mergedSameEpisode` / `sourcesAttached`；
- 前端 `MergeResult` 补两字段，合并结果提示把「同集归并 N 条」说出来 —— 只说 `added`
  会让用户以为「少搬了东西」；
- 合并对话框文案从「本功能不做内容合并判断」改为如实描述自动规则。

**单测**（`download-engine/crates/orig-tg/src/media.rs`，各 1 passed）：

| 用例 | 断言 |
|---|---|
| `merge_series_merges_same_slot_into_multi_source_bug407` | A/B 的第 2、3 集同文件 ⇒ `(集号,主条目,[备用源])` 逐项等于 `[(1,A1,[]), (2,A2,[B2]), (3,A3,[B3]), (4,B4,[])]`，`media_episode_source` 真有两行 |
| `merge_series_no_hash_never_merges_bug407` | 两侧都无 hash ⇒ `[(1,A1,0源), (2,B1,0源)]`，`merged_same_episode=0`，备用源表 0 行 |

**反向证伪（两条，证明用例在守）**：

1. 关掉 hash 判据 ⇒ `merge_series_merges_same_slot_into_multi_source_bug407` **FAIL**：
   `assertion failed: 只有 B 的第 4 集占新集号  left: 3  right: 1`（退回续编 1,2,3,4,5,6）。
2. 把判据退回「同槽即同一集」的错法 ⇒ `merge_series_no_hash_never_merges_bug407` **FAIL**：
   `assertion failed: 没有文件就没有「同一份内容」，不得归并  left: 1  right: 0`。

**回归**：`cargo test -p orig-tg --lib` → 330 passed / 2 failed；两个失败
（`cache_task_rerun_is_idempotent`、`priority_endpoint_rejects_malformed_requests_bug277`）
在 `git stash` 掉本次改动后**同样失败** ⇒ 与本号无关的既有缺陷。
