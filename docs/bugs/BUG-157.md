# BUG-157：污染门禁的「仓库根白名单」在**外层仓视角下完全失效** —— 仓库根积了 46 个探针残留而门禁恒 PASS

- 状态: fixed（提交 `294a2788`）
- 发现日期: 2026-09-23
- 模块: build
- 严重程度: high
- 档位: standard

## 现象

`projects/orig-hub/` 的仓库根目录下积了 **46 个一次性探针/临时文件**
（`.tmp-find.txt`、`.tmp-fmt3.txt`、`.zz7.txt`、`.chk2.txt` …），
其中最大的单个文件 306 KB。这些文件**在仓库根长期存在**，
而 `scripts/check-pollution.sh` 对它**一次都没有告警**（恒 `EXIT=0`）。

`AGENTS.md` §7 早已预警过这个失败模式，原文：

> 历史教训：pre-commit 曾无条件 `exec` 一个从未入库的脚本 → 恒 exit 127 把所有提交锁死；
> 随后改成「缺了就跳过」，**污染门禁又长期空转（根目录因此积了残留）**。

本档就是这句预言的**实际发生**。附带影响：工作区未跟踪文件一度达 **529 个**，
是本轮编辑器大量 `EBADF`/`EPIPE` 报错的诱因之一（报错本身归因宿主 fd 生命周期，与本仓无关）。

## 根因

门禁脚本用 `git rev-parse --show-toplevel` 定位「仓库根」，据此做白名单判定：

```sh
ROOT=$(git rev-parse --show-toplevel 2>/dev/null) || exit 0
ROOT_WHITELIST=".gitignore AGENTS.md README.md download-engine.toml"

for f in $STAGED; do
  case "$f" in
    */*) : ;;                                          # ① 有斜杠 → 直接跳过
    *) is_root_whitelisted "$f" || bad "root-level file not in whitelist: $f" ;;
  esac
```

**这个仓库是一个 monorepo 的子目录**（`framework/projects/orig-hub`）。
从 orig-hub 内跑该脚本时：

1. `git rev-parse --show-toplevel` 解析到的是**外层 `framework`**，不是 `orig-hub`；
2. 于是 `git diff --cached --name-only` 给出的路径全都带 `projects/orig-hub/` 前缀；
3. 带斜杠 → 命中 `*/*) : ;;` → **白名单检查一次都没执行过**。

### 反向证伪（证明「该 FAIL 却 PASS」）

```sh
cd projects/orig-hub
cp AGENTS.md .probe-pollution-test.txt
git add -f .probe-pollution-test.txt
sh scripts/check-pollution.sh   # 期望 FAIL，实测 EXIT=0，一条都没报
```

### 同类第二处漏洞：临时文件规则只认「后缀」

```sh
case "$f" in
  *.tmp|*.bak|*.orig|*~|*.swp|*.swo|*.log)
```

只匹配**后缀**，而实际残留是 `.tmp-find2.txt`（`.tmp-` 是**前缀**）——
`.gitignore` 里的 `*.tmp` 同样拦不住。两条防线同向失效。

### 第三个漏洞：门禁只看 `git diff --cached`

残留文件**从未被 `git add`**，因此即使规则(1)写对了也不会命中。
「未 staged」不等于「无污染」——`AGENTS.md` §6 的判定口径是
「**未跟踪或未忽略 = 违规**」，与门禁只查 staged 的实现**不一致**。

## 复现

```sh
cd projects/orig-hub
# 1. 确认残留（本档发现时的量级）
ls -1A | grep -cE '^\.(tmp-|zz|chk)'      # → 46
# 2. 确认门禁无感
sh scripts/check-pollution.sh; echo "EXIT=$?"   # → EXIT=0（假绿）
# 3. 构造根目录非法文件再跑
cp README.md .tmp-evidence-check.txt
git add -f .tmp-evidence-check.txt
sh scripts/check-pollution.sh; echo "EXIT=$?"   # 修前 EXIT=0，修后 EXIT=1
```

## 5 原则

### 原则（判据，必须先写下来）

1. **门禁必须在任何 CWD 下对「本项目的根」判定正确** —— 不能假设
   `git rev-parse --show-toplevel` 就等于项目根。
2. **白名单必须按「项目根相对路径」判定**，而不是按 git 仓库根的相对路径。
3. **临时/探针文件必须同时覆盖前缀与后缀两种命名** ——
   只堵一种命名等于没堵。
4. **判定口径必须与 `AGENTS.md` §6 一致**：未跟踪且未忽略 = 违规，
   不能只看 staged。
5. **门禁本身要有反向证伪**：构造一个必然违规的输入，它必须 FAIL；
   否则「门禁通过」不具备任何证据力。

### 对策

1. 不再依赖 `--show-toplevel` 判断「谁是我这个项目的根」，改为**由脚本自身位置反推**：
   `SH=$(cd "$(dirname "$0")" && pwd)` → `ROOT=${SH%/scripts}`，
   此时 staged 名字就是相对本根的路径。
2. 规则(1) 对剥出的本地路径做白名单判定，使 `.tmp-find2.txt` 被识别为**根目录文件**。
3. 新增 `is_dot_scratch()`，覆盖 `.tmp-* / .tmp_* / .tmp.* / .scratch* / .probe* / .dbg-* / .zz*`，
   **仅对仓库根的 dot-prefixed 文件生效**。取舍：引擎合法的 `.tmp` 是**扩展名**
   （`<name>.tmp`，写在 data 目录内），根目录 dotfile 无合法用途；`.tmp` 扩展名规则原样保留。
4. 规则(2)/(4)-(8) 保留原语义，在剥离后的本地路径上重跑；
   cabin 判定（规则 6）仍用 `download-engine/*|tauri-shell/*`。

### 分析（为什么这是根因，而不是表象）

- 不是「有人忘了清理」那么简单 —— **清理治标，门禁失效治本**。
  46 个残留能被写进去而无人察觉，是因为**唯一的防线是瞎的**。
- 三个漏洞是**独立**的、**同向**的：前缀命名绕过(3)、斜杠路径绕过(1)、
  未 staged 绕过(3)。修任意一个都不足以拦住本轮残留 —— 这解释了
  为什么它「长期空转」而不是「偶尔漏检」。
- `--show-prefix` **在 monorepo 根返回空串**（这是个反直觉行为）：
  因此「从外层跑时剥 `projects/orig-hub/` 前缀」这条看似自然的修法**根本不通** ——
  必须靠**脚本自定位**。该行为已写入脚本注释。

### 防再发

1. **门禁自检脚本**：新增反向证伪用例，4 个 case 必须分别给出正确结论：

   | case | 期望 |
   |---|---|
   | 根 `.tmp-xxx.txt` | **FAIL** |
   | 根 `.probe-xxx.txt` | **FAIL** |
   | `docs/` 下正常 `.md` | **PASS（不得误伤）** |
   | 根 `foo.md`（白名单外） | **FAIL** |

2. **口径对齐**：门禁若要覆盖「未跟踪残留」，需另加一条
   `git ls-files --others --exclude-standard` 的检查（本档未做，见「已知边界」）。
3. **不得再出现「声称有钩子实则没有」**：本仓外层 `core.hooksPath` 为空、
   `.git/hooks/` 只有 `.sample`，但 `AGENTS.md` §7 表格声称「本地钩子=必需」——
   文档与现实的差距本身是**下一个同类缺陷**（见「已知边界」）。

## 已知边界（如实记录，不假装已解决）

- **本档只修门禁的逻辑漏洞，未新增「未跟踪文件」扫描**。门禁仍是 staged-only，
  即：残留只要不被 `git add`，就必须依赖作者自觉。把扫描扩到未跟踪文件
  会引入大量噪声（构建产物、AI 目录等），**需先定白名单，属独立决策**，
  不在本档擅自扩大。
- **本档发现的 46 个残留文件未被删除**（符合最高规则「禁止任何删除动作」）。
  它们被**整体搬移**到仓外隔离目录
  `%TEMP%\orighub-root-residue-20260923-205001\`（46 个文件 / 577,955 字节，逐一回读校验）。
  未做任何删除，可随时取回。
- **钩子与文档不一致**：外层仓当前无 commit-msg 钩子，`AGENTS.md` §7 却称其为必需。
  需单独建档，不在本档处置。

## 验收证据

### 一、反向证伪（**独立于实施者**，由 team-lead 另构造）

清空工作区后，构造一个必然违规的输入：

```sh
cd projects/orig-hub
cp README.md .tmp-evidence-check.txt
git add -f .tmp-evidence-check.txt
sh scripts/check-pollution.sh
```

实测输出：

```
[POLLUTION] root-level file not in whitelist: .tmp-evidence-check.txt
[POLLUTION] dot-prefixed scratch/probe file at repo root: .tmp-evidence-check.txt

Commit blocked by pollution gate (AGENTS.md §7).
```

**`EXIT=1`**（两条规则同时命中）。

**修前对照**（同一构造，回退到 `294a2788^` 的逻辑）：**`EXIT=0`，静默通过** ——
即「该 FAIL 却 PASS」，门禁失效成立。

### 二、四象限证伪（期望值必须两个方向都能变红）

| case | 期望 | 实测 |
|---|---|---|

| 根 `.probe-xxx.txt` | FAIL | **FAIL exit=1** |

**两个方向都验证过**：违规必须红（6/6 命中），合法不得误伤（`docs/` 正常文档 PASS）。

工作区清理干净后全量跑，`check-pollution.sh` → **`EXIT=0`**。
