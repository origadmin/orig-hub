# BUG-039：媒体库无冲突模型——同集多缓存来源与合集视频无法表达

- 状态: fixed
- 发现日期: 2026-09-18
- 模块: engine+shell
- 严重程度: high

## 现象（用户裁定）
「没有考虑冲突点：第一集有 3 个缓存来源怎么处理？有 1-2 两集合集视频怎么处理？当前逻辑无法达成。」
- 多来源：同一集（如 EP1）被多个 TG 相册发布，自动成剧按 `source_key`（相册）各建一部剧；
  BUG-037 合并把它们搬进同一部剧时只能**各占一个位置**（假位置），或被跳过丢失。
- 合集：一个视频文件含 1-2 两集，现有模型 `episode_no` 只能表达单槽位，
  后续集会撞位/错位。

## 结构方案（裁定）
- **槽位 = 位置，起点身份**：`UNIQUE(series_id, season, episode_no)` 不变；
- **合集范围**：`media_episode.episode_no_end`（可空，NULL=单集）。占用区间 =
  `[episode_no, episode_no_end ?? episode_no]`；「下一个可用位」=
  `MAX(COALESCE(episode_no_end, episode_no)) + 1`；
- **同槽多来源**：新表 `media_episode_source(episode_id, item_id UNIQUE, created_at)`。
  主条目在 `media_episode.item_id`；多出来的来源挂备用，不挤占位置。
  内容同一性不做自动判定（同内容≠同记录，沿用 BUG-037 裁定），挂载/切换由用户显式触发。

## 实现
- engine（`media.rs`）：
  - `append_episodes_ranged(series_id, season, &[(item, Some((start,end)))])`：
    声明区间完整空闲才落声明位，否则回退到最大终点之后并**保留宽度**；
    占用快照按每号展开检测重叠；
  - `attach/switch/detach_episode_source`（切换为单事务：删备用行 + 旧主转备 + 新主上位）；
  - `EpisodeEdit.episode_no_end: Option<Option<i64>>`（缺省=不改/null=改回单集/数字=改终点），
    换位时区间宽度跟随移动；
  - `parse_episode_range(caption)`：`EP01-02`/`第01-02集`/`10-20集合集`/`EP07`/`第5集`/`#12`
    （宽度 ≤99 拒年份式歧义区间）；
  - 自动成剧落位接入 caption 区间解析；`EpisodeView` 下发 `episodeNoEnd` + `sources`。
- shell：API 四函数 + 分集槽位显示 `S1E1-2` + 「N 源」徽标（点击切主）。

`cargo test -p orig-tg --lib` 25/25（新增 3 测：区间解析 12 断言、带范围追加落位/回退/幂等、
