# BUG-169: 「实时已连接」三处渲染点被用户裁定为「三个状态点未收敛」—— 唯一状态点 = 唯一渲染点

- 状态: fixed
- 发现日期: 2026-09-24
- 模块: shell
- 严重程度: mid
- 档位: standard

## 现象

用户重申「"实时已连接" 3 个状态点仍然没修复」并定性为严重事故。

BUG-087 的方案是「三处同读一个真相源」（sidebar-conn / context-conn / statusbar-conn
全部消费 `store/connState.ts` 的 `useConnState`），BUG-164 补齐了下载视图顶栏分支。
工程视角这是「单一真相源、多渲染点」，但用户视角它就是**三个状态点**——
用户裁定的「唯一状态点」语义是**唯一渲染点**，不是「多处渲染同一状态」。

## 修复

全应用只保留**一处**连接状态点。初版保留顶栏 `context-conn`，用户复核「为什么不是
右下角留下?」后**终裁改定唯一渲染点 = 底栏右下角**——结构性理由：底栏在
`MainLayout` 根部单次渲染、不按视图分叉（顶栏灯恰恰在 BUG-164 出过「下载分支
整类视图漏接」事故），且连接状态是惯例的状态栏语义。

- `Sidebar.tsx`：移除底部 `sidebar-conn` 指示块（及其 `useConnState`/`CONN_*` 订阅）；
- `ContextBarStatus.tsx` / `ContextBarActions.tsx`：移除顶栏 `ConnLight`（含组件本体，
  顶栏只留速度/数量/操作按钮）；
- `MainLayout.tsx`：底栏右下角 `statusbar-conn` 是**唯一**渲染点（点 + 文案 +
  速度读数同处，BUG-134 来源不变）。

与 BUG-167 的关系：BUG-167 消灭了「瞬时错误升级为全局断言」的第二真相源；
本条把「同一真相源的多处渲染」收敛为唯一渲染点。真源唯一（`useConnState`）+
渲染唯一（`statusbar-conn`，右下角）+ 无旁路断言（BUG-167）= 用户的
「唯一真相源，唯一状态点」。

## 验收证据

终版（右下角）：CDP 探针四视图快照（`all` / `media` / `tg` / 返回 `all`）：

```
每视图 document 内 [data-conn-state] 恰好 1 个：
  {id: "statusbar-conn", s: "live", rect: {x:1357, y:876}}   —— 4/4 视图一致（右下角）
「实时已连接」文案出现次数 = 1（顶栏/侧栏不再出现）            —— 4/4 视图一致
```

「恰好 1 个」判据在修复前（3 个渲染点，此前多轮探针均实录 3 项）必然失败，非恒绿。
截图亲验：右下角一枚绿点「实时已连接」，顶栏/侧栏无重复指示。
`tsc --noEmit` 干净；入库验收脚本 `verify/shot_context_bar.cjs` 断言同步改定
（顶栏右槽必须无连接态 + 底栏必须存在唯一状态点）。

跨机器可核引用（入库路径）：`tauri-shell/src/shell/MainLayout.tsx`（底栏
`statusbar-conn` 唯一渲染点）、`tauri-shell/src/shell/Sidebar.tsx`（移除
sidebar-conn 块）、`tauri-shell/src/shell/ContextBarStatus.tsx`（移除
ConnLight）、`tauri-shell/verify/shot_context_bar.cjs`（验收口径同步）。
