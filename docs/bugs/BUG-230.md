# BUG-230: raw 直解路径在本机环境全程卡顿（1x 卡 / 2x 非常卡 / 4x 无法播放），stream 转码流流畅 ⇒ 播放主路径翻转为 stream-first，raw 退役为下载/导出端点

- 状态: fixed
- 发现日期: 2026-10-09
- 模块: shell
- 严重程度: high

## 现象（用户实测事实，推翻 BUG-229 的前提）

- 1x（raw 直解）：卡顿；2x（raw 原生 playbackRate）：非常卡；4x：完全无法播放。
- 切到 stream（服务端转码 H.264 30fps）：流畅。
- BUG-229 的修复「可直解源保持 raw + playbackRate」建立在「本机直解流畅」的前提上
  （其探针依据是 item 673 单一条目 effRate 0.995）。用户真实环境全量否定该前提：
  直解吞吐对库内内容（HEVC/高帧率）不够，倍速下更甚——「整个设计和实现脱离实际」。

## 结论（设计裁定，2026-10-09 用户拍板）

- **播放一律 stream-first**：有 compatSrc（`/api/media/items/{id}/stream`）即从转码流起步；
  非 1x 起对应 FRC 变体（`streamUrlAtRate`），1x = 基础转码流。
- raw 端点保留，但**不再参与播放**——只作为下载/导出（orig-studio-ee 上传）/原始数据端点。
- stream 承受能力（已有事实，无需再测）：输出恒为 CFR 30fps H.264 + AAC，浏览器解码负载
  极轻；源 fps 只影响 ffmpeg 解码 CPU，不影响输出帧率；高倍速档已用 ultrafast + 30fps
  降采样（BUG-229 同批引擎改动），缓存落盘受 `ORIG_TG_PROXY_MAX_BYTES` LRU 预算约束。

## 改动

- `tauri-shell/src/components/media/VideoPlayer.tsx`：
  - `rememberedCompat`（localStorage 记忆，BUG-208/224 遗迹）删除，换成
    `streamFirst = Boolean(compatSrc && compatSrc !== src)`；
  - 挂载即 stream（1x=基础流、非 1x=FRC 变体），`usingCompat`/`compatTriedRef`/
    `baseCompatRef` 初值随之；
  - 换档 effect 注释更新为 stream-first 语义（BUG-229 风暴由 LRU 兜底 + 同容器变体
    间切换，不再 raw↔stream 往返）；
  - `readCompatSet`/`COMPAT_KEY` 随记忆机制一并移除。
- N² 防护保持：`/stream` 源上 `video.playbackRate` 恒 1（时间轴压缩由服务端负责）。
