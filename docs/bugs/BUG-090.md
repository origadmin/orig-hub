# BUG-090: 浏览器开发模式下连接态恒为 offline —— Tauri `invoke` 不可用时失败被静默吞掉，指示器与事实相反

- 状态: fixed
- 发现日期: 2026-09-21
- 模块: shell
- 严重程度: high

## 现象

BUG-087 把三处连接指示统一之后，暴露出更深的真缺陷：**三处一致地显示「daemon 未连接」，
但应用此刻明明在跟 daemon 正常通信**。

反证（页面内实测）：

- `fetch('http://127.0.0.1:9876/health')` → **200** `{"status":"ok"}`
- `fetch('http://127.0.0.1:9876/api/downloads')` → **200** `[]`
- `performance.getEntriesByType('resource')` 里 9876/9877 的 `/api/downloads`、`/api/config`、
  `/api/tg/session` **反复成功**（单次 3–7ms）

即：链路是通的，指示器在说谎 —— 用户被告知「未连接」，却能看到数据正常刷新。

## 根因

五环链条，每环在当时都「说得通」，合起来就是假故障：

1. `tauri-shell/src/components/MainLayout.tsx:40-43`：
   `ensureDaemon().then(() => daemonStatus()).then(setDaemon).catch(() => {})`
2. `tauri-shell/src/api/tauri.ts:5-12`：`daemonStatus()` = `invoke('daemon_status')`、
   `ensureDaemon()` = `invoke('ensure_daemon')` —— **都是 Tauri Rust 命令**
3. 纯浏览器开发模式（直接开 `localhost:5180`，无 Tauri 宿主）下 `invoke` 不可用
   → Promise reject → `.catch(() => {})` **把失败咽掉**，不留任何痕迹
4. `tauri-shell/src/store/useStore.ts` 初值 `daemon: null` → 永远保持 null
5. `selectDaemonAlive = (s) => s.daemon?.alive === true` → false →
   `connState.ts` 的 `if (!daemonAlive) return 'offline'` → 三处全部 offline

本质是**用「宿主有没有回报状态」冒充「链路通不通」**：只有桌面宿主能回答前者，
而后者任何时候都能由真实通信结果回答。

## 复现

1. 起 dev server（不开 Tauri 宿主），浏览器打开 `http://127.0.0.1:5180/`；
2. 读 `[data-testid=statusbar-conn]` / `[data-testid=sidebar-conn]` 的 `data-conn-state`
   —— 修前恒为 `offline`、文案「daemon 未连接」；
3. 同时 `fetch('http://127.0.0.1:9876/health')` 返回 200 —— 两者自相矛盾。

## 修复

原则：**不新增任何轮询请求**（AGENTS.md §5：轮询周期内只允许轮询本身的请求）。
存活一律由**已有请求**的成功/失败反推，探活只在启动期发一次。

1. **启动期一次性 HTTP 探测兜底**（`MainLayout.tsx`）：Tauri 路径 reject 时不再
   `.catch(() => {})` 静默吞掉，改为发**一次** `GET {DAEMON_BASE}/health`
   （`api/daemon.ts` 已有的 `health()`），成功 → `setDaemonAlive(true)`，
   失败 → `setDaemonAlive(false)`。这一次是启动期请求，不是轮询。
2. **存活由既有信号反推**（`store/useStore.ts`）：新增 `setDaemonAlive(alive)`，
   只改 `alive` 一个字段（`managed` / `port` 等宿主信息不被 HTTP 成功改写）：
   - SSE 连上（`subscribeEvents` 的 `onOpen`）→ `alive = true`；
   - 既有 5s 兜底 `refresh()`（仅 SSE 断线时才跑）成功 → `alive = true`，失败 → `false`
     （恢复后自动翻回，无需任何新请求）。
3. **Tauri 模式行为不变**：托管 spawn 仍是主路径，`managed: true` 语义保持。

## 验收证据

真实浏览器（零依赖 CDP 驱动，纯浏览器开发模式、无 Tauri 宿主）实测，
页面加载后 0.8s / 1.5s / 3s / 5s / 35s 五次采样：

- `[data-testid=statusbar-conn]`：`data-conn-state="live"`，文案「实时已连接」
- `[data-testid=sidebar-conn]`：`data-conn-state="live"`，文案「实时已连接」
- （`context-conn` 在下载视图下按设计不渲染；BUG-087 已实测它与另两处同源同值）

**零新增轮询**的证据（`performance.getEntriesByType('resource')`，全程未清理）：

- `/health` 请求数：5s 时 2 → 35s 时**仍为 2**（dev 的 StrictMode 双挂载导致 2 次；稳定后不再增长）
- `/api/downloads` 请求数：5s 时 2 → 35s 时**仍为 2**（SSE 连通 ⇒ 5s 兜底轮询不触发）
- 资源条目总数：89 → **89**（30s 内零新增请求）

页面 `pageErrors` 为空。
