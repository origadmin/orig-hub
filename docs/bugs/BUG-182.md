# BUG-182 多源区「摘除备用源」接错端点：按钮在、文案对、testid 在，但能力事实不存在

- **状态**: open
- **发现日期**: 2026-09-29
- **模块**: shell
- **严重程度**: mid

关联 BUG-149（重构不是删能力的授权）、BUG-039（多源能力来源）、BUG-148（实现约束 ≠ 产品信息）。

## 现象

剧集内页（活实现 `SeriesDetail.tsx` 右栏）的**多源区**，每个备用源行上有两个按钮：
「切为主版本」与「摘除」。用户点「摘除」后，**备用源没有消失**；极端情况下还会把**同一
`item_id` 的挂图**摘掉。

对用户表现为「这个按钮点了没用」——但因为按钮存在、文案正确、图标正确、
`data-testid="episode-source-detach"` 也在，**任何按 testid 计数的验收脚本看它都是绿的**。

## 根因

`SeriesDetail.tsx` 的「摘除」按钮绑定的是**摘挂图**的处理函数，不是**摘源**的函数。

| 位置 | 事实 |
|---|---|
| `tauri-shell/src/components/media/SeriesDetail.tsx:39` | `import { mediaItemUrl, switchEpisodeSource, detachEpisodeImage, moveEpisode } from '../../api/media'` —— **没有 import `detachEpisodeSource`** |
| `tauri-shell/src/components/media/SeriesDetail.tsx:583` | 「摘除」按钮 `onClick={() => detachImage(cur.id, s.itemId)}` |
| `tauri-shell/src/components/media/SeriesDetail.tsx:221-222` | `const detachImage = (epId, itemId) => applyChange(() => detachEpisodeImage(epId, itemId))` |
| `tauri-shell/src/api/media.ts:502` | `detachEpisodeSource(episodeId, itemId)` —— **定义存在，全仓零调用**（`grep -rn "detachEpisodeSource" tauri-shell/src download-engine` 无命中） |
| `tauri-shell/src/api/media.ts:522` | `detachEpisodeImage(...)` —— 被上面那条链实际调用 |

`item_id` 在两个域里的语义不同：**备用源是 video**（`trg_media_episode_source_video_only_ins/upd`
只接受 `kind='video'`），**挂图是 photo**。同一个 `item_id` 不可能同时属于两者
（`media_episode_source.item_id` 还是**全表 UNIQUE**），因此该调用**必然打空或打错对象**。

同文件 `:778`（灯箱内）也调用 `detachImage` —— **那一处是对的**，本就是摘挂图。
本缺陷只存在于 `:583` 这一处误用。

## 复现

**已完成：静态证据链（决定性）**
上述 5 行调用链 + import 清单 + 全仓零调用 grep，可直接复核；`detachEpisodeSource`
在 `tauri-shell/src` 与 `download-engine` 内除自身定义外**零出现**。

**未完成：运行时观测**
按本仓今日裁定（`open` 状态缺陷的「复现」节必须含真实观测），本档**如实标注**：
运行时观测（起服务 → 造一条带备用源的分集 → 点「摘除」→ 观测 `media_episode_source`
行数与 `media_episode_image` 行数）**尚未执行** —— 原执行者因模型调用频率超限中断。
**修复动工前必须补做一次**，并把观测结果追加到本节。

## 修复

`tauri-shell/src/components/media/SeriesDetail.tsx`：
1. `:39` import 增加 `detachEpisodeSource`；
2. `:583` 的 `onClick` 改调 `detachEpisodeSource`（**不要**复用 `detachImage`，
   两者语义不同，复用正是本缺陷的成因）；
3. `:778` 灯箱那处**保持**调 `detachImage`（本就是摘挂图，不得一并改掉）。

`tauri-shell/src/api/media.ts:502` 的 `detachEpisodeSource` 保持现状（它是对的，只是从没被调用）。

## 关联

- BUG-149：本档是该条的**实质违反** —— 按钮、文案、testid、验收锚点全在，能力事实不存在。
- BUG-039：多源能力的来源。
- 与「多源区语义重做」同批处理（见 `docs/design/episode-source-and-library-ux-2026-09-29.md`）：
  该设计要把「切为主版本 / 摘除」从常驻裸按钮改为「播哪个（当次生效）」+「设为默认播放（永久）」，
  本档的第 2 项修复必须与那次重排**同时**落地，避免改完又被覆盖。

## 修复后验收要点（预声明 · 待 fixed 时转为 验收证据 并立真实证据）

1. **能力断言（打真实调用链，不打内部函数）**：造一条「1 主 + 1 备用源」的分集，
   点击 `[data-testid="episode-source-detach"]` 后：
   - `media_episode_source` 该行**消失**（备用源真被摘除）；
   - **`media_episode_image` 行数不变**（反证没有误摘挂图）——这条是本档的核心断言，
     因为原缺陷的表现正是「该变的没变、不该动的动了」。
2. **反向证伪**：把 `onClick` 故意改回 `detachImage`，上述断言**必须 FAIL**。
   否则断言是假绿。
3. **不误伤**：灯箱内的「摘图」（`:778`）行为逐字不变 —— 点它挂图**应当**消失。
4. 入库验收脚本（跨机器可复核）：`tauri-shell/verify/verify_episode_source_actions.cjs`。
