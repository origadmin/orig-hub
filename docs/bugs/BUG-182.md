# BUG-182 多源区「摘除备用源」接错端点：按钮在、文案对、testid 在，但能力事实不存在

- **状态**: fixed
- **发现日期**: 2026-09-29
- **模块**: shell
- **严重程度**: mid

关联 BUG-149（重构不是删能力的授权）、BUG-039（多源能力来源）、BUG-148（实现约束 ≠ 产品信息）。

## 现象

剧集内页（活实现 `SeriesDetail.tsx` 右栏）的**多源区**，每个备用源行上有两个按钮：
「切为主版本」与「摘除」。用户点「摘除」后，**备用源没有消失** —— 表现为「这个按钮点了没用」。

> **收口时修正（2026-09-29）**：本档初稿曾写「极端情况下还会把同一 `item_id` 的挂图摘掉」，
> 经真实点击验收证明**不成立**（见「验收证据」的诚实边界）。备用源是 video、挂图是 photo，
> 同一 `item_id` 不可能兼属，故该调用只会 `removed:0` 打空 —— 真实表现是「点了没反应」，
> **不会误删挂图**。原文作为推断保留在下方「根因」表内，此处以实测为准。

对用户表现为「这个按钮点了没用」——但因为按钮存在、文案正确、图标正确、
`data-testid="episode-source-detach"` 也在，**任何按 testid 计数的验收脚本看它都是绿的**。

## 根因

`SeriesDetail.tsx` 的「摘除」按钮绑定的是**摘挂图**的处理函数，不是**摘源**的函数。

| 位置（修复前） | 事实 |
|---|---|
| `tauri-shell/src/components/media/SeriesDetail.tsx:39` | `import { mediaItemUrl, switchEpisodeSource, detachEpisodeImage, moveEpisode } from '../../api/media'` —— **没有 import `detachEpisodeSource`** |
| `tauri-shell/src/components/media/SeriesDetail.tsx:583` | 「摘除」按钮 `onClick={() => detachImage(cur.id, s.itemId)}` |
| `tauri-shell/src/components/media/SeriesDetail.tsx:221-222` | `const detachImage = (epId, itemId) => applyChange(() => detachEpisodeImage(epId, itemId))` |
| `tauri-shell/src/api/media.ts:502` | `detachEpisodeSource(episodeId, itemId)` —— **定义存在，全仓零调用**（修复前 `grep -rn "detachEpisodeSource" tauri-shell/src download-engine` 除自身定义外无命中） |
| `tauri-shell/src/api/media.ts:522` | `detachEpisodeImage(...)` —— 被上面那条链实际调用 |

`item_id` 在两个域里的语义不同：**备用源是 video**（`trg_media_episode_source_video_only_ins/upd`
只接受 `kind='video'`），**挂图是 photo**。同一个 `item_id` 不可能同时属于两者
（`media_episode_source.item_id` 还是**全表 UNIQUE**），因此该调用**必然打空** ——
`detachEpisodeImage(videoItemId)` 在 `media_episode_image` 里找不到该行，幂等删除 `removed:0`，
两表行数都不变，用户看到的就是「点了没反应」（2026-09-29 实测证实，见「验收证据」）。

同文件灯箱内那处（修复前 `:778`，修复后 `:794`）也调用 `detachImage` —— **那一处是对的**，本就是摘挂图。
本缺陷只存在于多源区按钮这一处误用。

## 复现

**已完成：静态证据链（决定性）**

上述 5 行调用链 + import 清单 + 全仓零调用 grep，可直接复核。

**已完成：运行时观测（2026-09-29 收口时补做）**

起隔离实例（copy 在产库 + `ORIG_TG_OFFLINE=1` + 端口 18761）+ headless Edge 真实点击。
造一条「1 主 + 1 备用源 + 2 挂图」的分集 → 点 `[data-testid="episode-source-detach"]`：

- **修复前形态**（`ORIG_VERIFY_REVERT=1` 注入 `detachImage`）：`media_episode_source` **1→1**
  （备用源没被摘）、`media_episode_image` **2→2** —— 证实「点了没反应」，**未误删挂图**。
- **修复后形态**：见「验收证据」。

## 修复

`tauri-shell/src/components/media/SeriesDetail.tsx`：
1. `:39` import 增加 `detachEpisodeSource`（落地为 `:42-43` 的多行 import）；
2. 多源区「摘除」按钮改调 `detachSource`（新增助手，落地为 `:237-238`；按钮 `onClick` 落地为 `:599`）
   —— **不要**复用 `detachImage`，两者语义不同，复用正是本缺陷的成因；
3. 灯箱那处（修复后 `:794`）**保持**调 `detachImage`（本就是摘挂图，不得一并改掉）。

`tauri-shell/src/api/media.ts:502` 的 `detachEpisodeSource` 保持现状（它是对的，只是此前从未被调用）。

| 观测 | 点击前 | 点击后 | 判据 |
|---|---|---|---|

**反向证伪（`ORIG_VERIFY_REVERT=1`，脚本自动把 `:599` 注入为修复前的 `detachImage`）→ EXIT 2（如期转红）**

- **核心断言 FAIL**：`media_episode_source` **1→1**（备用源没被摘）—— 正是「该变的没变」。
- 「灯箱摘图不触碰备用源」亦 FAIL（sources=1）。
- 结果 10/12 → `FALSIFICATION CONFIRMED`。
- 证伪跑完**自动还原**：脚本自校验文件 `sha256 before == after`（`0be3f7f0…`）逐字节一致；
  独立核对 `git diff -- SeriesDetail.tsx | sha256` 在证伪前后**同为**
  `174e4dbd9b93021982519363e9449c7d3c6834ee400794f05b2515e7445d8f74`。
  （说明：该修复本身是未提交改动，故 `git diff` 非空 —— 此处等价证据是「diff 哈希证伪前后一致 + 文件 sha256 逐字节一致」。）

**诚实边界（判别性说明）**：反向证伪中「不该动的动了」在本场景**观测不到** ——
备用源是 video、挂图是 photo，同一 `item_id` 不可能兼属，故修复前代码的 `detachImage(videoItemId)`
只会 `removed:0` 打空（两表行数都不变），**不会真删到挂图**。因此本档的**判别性断言是「备用源行消失」**；
「挂图行数不变」是防另一类错实现的护栏（本场景下修复前后两版都过）。此点已如实标注在脚本头注释。
