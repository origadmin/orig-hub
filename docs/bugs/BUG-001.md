# BUG-001: 下载文件不自动嗅探 / 不按实际文件类型命名

- 状态: fixed
- 发现日期: 2026-08-26
- 模块: engine
- 严重程度: mid

## 现象
下载任务落盘文件名仅取 URL 路径末段（如 `download.php`、`file?token=xxx`），
不识别 `Content-Disposition` 头里的真实文件名；且当服务端返回 `download.php`
但实为 zip 时，不会按 `Content-Type` 补齐 `.zip` 扩展名，导致文件无正确扩展名、
双击无法识别类型。

## 根因
`probe()` 只从 `url.path` 末段取文件名，既忽略 `Content-Disposition`
（RFC 5987 的 `filename*` 优先于 `filename`），也不做 `Content-Type → 扩展名`
的纠正。

`file: download-engine/crates/orig-protocol-http/src/lib.rs`（`probe` 函数）

## 复现
对返回 `Content-Disposition: attachment; filename*=UTF-8''real-name.zip`
或 `Content-Type: application/zip` 但 URL 为 `.../download.php` 的链接执行
`probe()`，观察返回的 `Metadata.filename`。

## 修复
- `orig-protocol-http/src/lib.rs`：新增模块级自由函数
  `parse_content_disposition`（RFC 5987 解析）、`percent_decode`、
  `ext_for_content_type`（Content-Type→扩展名映射）、`resolve_filename`
  （Content-Disposition > URL 末段，并按 Content-Type 补齐缺失扩展名），
  并在 `probe()` 中接入：`cd` 取自 `range_resp` 与 `head_resp` 的
  `Content-Disposition`，最终文件名经 `resolve_filename` 计算。
- `orig-daemon/src/routes.rs`（`add`）：文件名优先级改为
  `req.filename` → `meta.filename`（嗅探名）→ URL 末段 → `{id}.bin`，
  使探针嗅探到的真实文件名在第 2 顺位生效。
