# BUG-362: TG 无 caption 图片的兜底标题是 `TG 图片 #{msg_id}`，抹掉了「来自哪个 TG 会话」

- 状态: fixed
- 发现日期: 2026-10-21
- 模块: engine
- 严重程度: high

## 现象

用户 2026-10-21 复报（原话）：

> 「1. 样式混乱 "NanaZip_7.0.1843.0_Binaries.zip" 在第一行. TG弹窗标题在第二行.」

真栈实测媒体库（`文件管理`）列表前 19 行标题，**五种互不相干的命名方式并排**：

```
#1  NanaZip_7.0.1843.0_Binaries.zip        ← 原始文件名
#2  TG 图片 #2099092                        ← TG 兜底（用户说的「TG弹窗标题」）
#3  TG 图片 #2099093
#4  TG 图片 #2099094
#5  🌟🌟🌟《时停手表》EP1-03 原著独享…      ← 真 caption
#7  未命名视频 #1574 SE4                    ← 另一种兜底
#18 photo--1_3.jpg                          ← 内部文件名
#19 abc--1-2.mp4
```

用户要看的是**这条内容来自哪个 TG 会话**（他要的「TG弹窗标题」），
而 `TG 图片 #2099092` 只说了「这是 TG 的一张图」—— 会话名被抹成一个编号。
第 1 行的原始文件名与第 2 行的编号并排，即用户感知的「样式混乱」。

## 根因

`download-engine/crates/orig-tg/src/routes.rs` 两处兜底标题写死为
`format!("TG 图片 #{msg_id}")`：

- `register_media_item_t0`（新登记，routes.rs:2232）
- `strengthen_registered_item`（补强，routes.rs:2324）

同一文件里**剧集命名**已经会用 `channel_title(st, chat_id)` 取频道名
（routes.rs:2689，取不到才退 `TG {chat_id}`），图片兜底却没有用这把尺子。

## 修复

两处兜底标题统一为 `{频道名} · 图片 #{msg_id}`；取不到频道名才退
`TG {chat_id}`（与剧集命名同一把尺子，绝不退空串——空标题不可辨识）。
`strengthen_registered_item` 的 fill-empty 语义不变：已坐实的标题不被改写。

`另一个频道 · 图片 #41` —— 证明频道名真的来自频道表，而非碰巧等于某个常量。
