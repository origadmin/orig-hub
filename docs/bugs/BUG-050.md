# BUG-050 规则失联：无需求模型导致功能互相破坏

- **严重级**: process / critical
- **状态**: fixed
- **报告轮次**: 2026-09-18 第八轮后（用户裁定：「当前逻辑非常混乱——不清楚需求胡乱修改；各功能之间相互破坏；修改无法正确完成功能」）

## 现象

BUG-031→049 逐轮补丁式修改，规则只存在于对话里：
1. BUG-044 把成剧门槛写成「视频 ≥2」，杀掉了 BUG-031 的单视频相册成剧 → 「缓存不入库」（BUG-048）。
2. BUG-044 启动迁移摘除图片分集但**不重算剧集 kind** → 全视频分集的「城市与科技合集/自然风光合集」仍挂「相集」徽标（展示与事实脱节）。
3. 图片语义三轮三变（缓存→分集封面→入库不落盘），UI 文案与规则长期不一致。

## 根因

需求模型没有落成文件，每轮修改各自解释规则，后续修复破坏先前假设。

## 修复

1. **规则成文**：`docs/MEDIA-RULES.md` 为媒体库域单一真源（R1 图片/视频二分、R2 入库与缓存语义、R3 成剧规则、R4 标签解耦、R5 冲突模型、R6 监控搜索、R7 剧集组织约束 + 验收铁律）。后续任何改动先对齐该文件，违反即 BUG。
2. **全规则对账**（真实实例逐条核验）：图片混入剧集/备用源 = 0；新图片条目全部无本地文件；UI 按钮语义（缓存/播放/加入媒体库/已入库）分布正确；缓存任务 23/24 正常完成（代理下载慢≠挂起）。
3. **kind 残留修复**：启动迁移增加重算——分集全视频的 album/collection 回归 `series`；真实库 11 部剧全部修正。

## 验收

- `cargo test -p orig-tg --lib` 28/28（`startup_repair_detaches_non_video_episodes` 扩展 kind 重算断言）。
- 真实实例：kind 分布 `[('series', 11)]`；截图 `verify_shots/audit/c_wall_fixed.png` 相集徽标清零。

## 遗留

- 同名剧集堆积（`频道 · 日期` × N）是 R3+R7 的推导结果；跨相册归并无自动信号（BUG-037），归并用既有「剧集合并」入口由用户操作。若要按 `#《剧名》` 自动聚合，需用户拍板后另立改动。
