# BUG-131：媒体库工具条搜索/排序仅 items 视图生效却恒渲染，series 视图产生假筛选态

- 状态: fixed
- 发现日期: 2026-09-22
- 模块: shell
- 严重程度: high

## 现象

用户原话（2026-09-22）：「媒体库的搜索栏,仅限部分页面有效,但是媒体库全局显示。」

实际比诉状更严重，共四层：

1. **搜索框可见但无效**：打开媒体库默认落在剧集墙（`view` 默认 `'series'`），主区工具条的搜索框恒渲染，但输入对剧集列表毫无作用。
2. **排序同样无效**：排序选择器同样无视图守卫恒渲染，series 视图下切换排序毫无效果。
3. **假筛选态**：series 视图输入搜索词后，剧集墙空态显示「无匹配 + 清除筛选」，但**实际并未按词过滤**——界面在撒谎。
4. **同类筛选两套行为**：标签 chip 点击会主动切到条目视图，而搜索不会；同排三个控件（搜索/排序/仅未归集）有三种作用域做法。

## 根因

`tauri-shell/src/components/MediaLibraryPanel.tsx`：

- `:112` `const [view, setView] = useState<View>('series')` —— 默认落点恰是搜索不生效的视图。
- `:690-697` 搜索框、`:698-708` 排序选择器：均**无 view 守卫**恒渲染。
- `:709-719` 「仅未归集」复选框：**有** `view === 'items'` 守卫 —— 同排三控件三种作用域。
- `:189-198` `loadSeries` 只吃 `activeTagId`，完全不消费 `search`；`:206` 加载 effect 硬守卫 `if (!alive || view !== 'items') return`。
- `:463` `filterActive = activeTagId !== null || search.trim() !== '' || unassignedOnly` —— `search` 被计入但 series 视图根本没有过滤发生 → 假筛选态来源。
- `:656-660` 标签 chip 点击 `if (!seriesSide) setView('items')` 主动切视图。

## 复现

1. 进入媒体库（默认剧集墙）→ 工具条输入任意搜索词。
2. 观察：剧集列表不变（请求 URL 也不带 `q=` 参数），但空态/筛选提示按「已过滤」呈现。
3. 切换排序选择器 → 无任何效果。

## 修复

方案待用户拍板（评估文档 Q2/Q3）：

- **方案 A（推荐）诚实收窄**：搜索框/排序仅 items 视图渲染；`filterActive` 只在真正会过滤的视图计入 `search`；标签 chip 与搜索行为对齐。
- **方案 B 功能增强**：搜索/排序扩为对 series 也生效（需为 `loadSeries` 新写消费逻辑，独立特性）。

**交付约束：搜索框 / 排序 / filterActive 三件必须同批交付**——拆开交付会留下「半修好的假筛选态」，比不修更糟。

顺带补验收锚点（当前缺口）：搜索框与排序选择器均无 `data-testid`，建议 `media-search-input` / `media-sort-select`。
