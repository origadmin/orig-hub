# BUG-187 本地 pre-commit 只跑污染门禁：安装路径写死旧内容，缺陷登记门禁在本地静默不执行

- **状态**: open
- **发现日期**: 2026-09-29
- **模块**: build
- **严重程度**: mid

关联 BUG-158（钩子恒不执行）、BUG-157（`--show-toplevel` 解析错位致门禁失效）、AGENTS.md §7（门禁表）。

## 现象

「pre-commit 该跑什么」在本仓有**三个互相不一致的说法**，而**实际生效的是最弱的那个**：

| 来源 | 声明的 pre-commit 内容 |
|---|---|
| `AGENTS.md` §7 门禁表 | 缺陷登记一致性（`check-bugs.py`，**必需**）+ 决策项可拍板性（`check-decisions.py`，**必需**）+ 目录污染 |
| `scripts/hooks/pre-commit`（AGENTS.md 称「钩子权威副本」） | `check-bugs.py --quiet` + `check-pollution.sh`（无 `check-decisions.py`） |
| `scripts/install-hooks.sh:16-19`（**唯一安装路径**） | 只有一行 `exec sh …/scripts/check-pollution.sh` |

实测（本工作副本，2026-09-29）：

- `git commit` **12~19 秒**完成，`check-bugs.py` 一次都没跑；
- 手工跑同一脚本需 **231.8 s**（3 分 52 秒）—— 两者相差一个数量级，提交若真跑过它不可能这么快；
- 后果实测：20:24 的提交把 **4 处 `check-bugs` ERROR** 一并提交入库（文档改完未过门禁就落库），
  直到事后手工复跑才发现并修正。即**本地提交从未经过登记门禁**，只有 CI（`registry` job）会拦。

## 根因

`scripts/install-hooks.sh` 里两个钩子的安装方式**不同源**：

| 钩子 | 安装方式 | 实测与权威副本的关系 |
|---|---|---|
| `commit-msg` | `cp "$ROOT/scripts/hooks/commit-msg"`（`:23-26`） | `diff` **IDENTICAL** ⇒ 单一真源，正确 |
| `pre-commit` | 内联 heredoc 写死（`:16-19`） | `diff` **DIFFERENT** ⇒ 内容停在旧版本，权威副本的修订没跟过来 |

`scripts/hooks/pre-commit` 的头部注释专门记录了历史教训（「曾无条件 exec 一个从未入库的脚本 → 恒 exit 127 锁死所有提交」；
「随后改成缺了就跳过 → 污染门禁长期空转」）。**installer 自己正是同类问题的又一个实例**：
权威副本被修订后，安装路径没有跟着改 —— 钩子在跑，但比权威副本弱。

> 与 BUG-158 的区别：那条是「钩子目录指向不存在的路径 ⇒ 钩子恒不执行」。
> 本档是「钩子执行了，但安装的内容比权威副本弱 ⇒ 其中一道门禁静默不存在」。
> 修好 BUG-158 不覆盖本档 —— 实测本副本 `core.hooksPath` 已为空、`commit-msg` 生效、`pre-commit` 仍弱。

## 复现

```sh
# ① 已安装钩子与权威副本不同（实测 DIFFERENT）
diff "$(git rev-parse --git-path hooks)/pre-commit" scripts/hooks/pre-commit

# ② 已安装钩子只跑污染门禁（实测：一行 exec check-pollution.sh）
cat "$(git rev-parse --git-path hooks)/pre-commit"

# ③ 安装路径写死旧内容（唯一安装入口）
sed -n '15,20p' scripts/install-hooks.sh

# ④ 对照：权威门禁要 3.9 分钟，而提交只花十几秒
python scripts/check-bugs.py        # 实测 231.8 s
git log -1 --format='%h %ad %s' --date=iso   # 提交耗时 12~19 s
```

## 修复

方向：**pre-commit 也走 `cp` 权威副本**，与 `commit-msg` 对齐，消除内联副本。

1. `scripts/install-hooks.sh` 删掉 `:16-19` 的 heredoc，改为
   `cp "$ROOT/scripts/hooks/pre-commit" "$HOOKS/pre-commit"`（与 `:23-26` 同形）。
2. 顺带定夺**契约不一致**：AGENTS.md §7 说 `check-decisions.py` 是 pre-commit 必需，
   而权威副本里没有它 —— 要么补进权威副本，要么改文档（**不得**让两处继续各说各话）。
3. **副作用必须一并处置**：`git commit` 会在 pre-commit 期间持有 `index.lock` 约 **4 分钟**，
   多会话并行时会让其他会话的 `git add` / `git commit` 报 `index.lock` 冲突。
   故修复**不能只改一行**：要么明确接受并行期提交变慢，要么先给 `check-bugs.py` 提速
   （其 231.8 s 里 **667 次 `git` 子进程 spawn** 占绝大部分，可用 `git check-ignore --stdin`
   + `git cat-file --batch-check` 批量化到约 1 s）。

> 本档**不擅自安装**权威钩子：安装会让并行会话的提交被 4 分钟的 `index.lock` 卡住，
> 属跨会话影响，需先定夺副作用处置（第 3 条）。

## 关联

- BUG-158：`core.hooksPath=NUL` ⇒ 钩子恒不执行。本档是**同一后果的另一条路径**，修 BUG-158 不覆盖本档。
- BUG-157：`--show-toplevel` 在外层仓解析错位 ⇒ 污染门禁失效。本档已实测本副本 `--show-toplevel`
  解析**正确**（返回 orig-hub 路径），故不是同一因。
- AGENTS.md §7 末：「钩子权威副本在 `scripts/hooks/`（钩子本身不入库）：新克隆必须 `bash scripts/install-hooks.sh`」
  —— 本档说明**按该指引操作得到的钩子弱于权威副本**。

## 修复后验收要点（预声明 · 待 fixed 时转为 验收证据 并立真实证据）

1. **同源断言**：`bash scripts/install-hooks.sh` 之后，
   `diff "$(git rev-parse --git-path hooks)/pre-commit" scripts/hooks/pre-commit` **必须无差异**。
2. **反向证伪（门禁真的在跑）**：故意在 `docs/bugs/README.md` 造一处状态不一致 →
   `git commit` **必须失败**并打印 check-bugs 的错误行；恢复后提交必须成功。
   当前形态下同一操作会**成功**（这是本档的核心症状）。
3. **不得靠 `--no-verify` 绕过**（AGENTS.md §2）；若为了绕过并行冲突而必须跳过，须显式授权并登记。

   （断言「已安装钩子 == 权威副本」+「造错必被拒」两件事，并自证还原）。
