# BUG-472: 「一条命令起 dev 栈」起来后前端仍连默认端口，界面显示「媒体服务未运行」

- 状态: fixed
- 发现日期: 2026-10-28
- 修复日期: 2026-10-28
- 模块: build
- 严重程度: high
- 排期: 2026-11-03

## 现象

`python3 scripts/hub.py dev start` 报告三项在线（29786 / 29787 / 5180），产物与源码一致，
但浏览器打开 5180 时主区一直是：

> 媒体服务未运行 ［尝试连接］

状态栏右下角同步显示「daemon 未连接」。此时 `curl 127.0.0.1:29787/api/media/stats`
能拿到完整数据（items=648 / series=176）—— 服务在跑，界面说没有。

## 根因（两处，缺一不可）

1. **端口没有随世界一起下发**：dev 世界把 daemon/orig-tg 挪到 29786/29787（BUG-453 的
   dev/release 隔离），但 `dev_stack.ensure_vite()` 用 `env=None` 起 vite
   ⇒ 前端 `import.meta.env.VITE_DAEMON_PORT` / `VITE_TG_PORT` 全是 undefined
   ⇒ 退回 `api/daemon.ts` 的 19786 与 `api/tg.ts` 的 19787 默认值，连的是**另一个世界**。
2. **`tg_port` 在启动瞬间为 None**：`GET /api/config` 只有在 daemon 接管 orig-tg 之后
   才给出 `tg_port`；`dev start` 结束后立刻起 vite 时该字段仍然是 `None`
   ⇒ 即使只补 `VITE_DAEMON_PORT`，orig-tg 仍连错。必须退回本世界的规范端口。

## 为什么「之前一直没发现」

`smoke.cjs` 的 M2 断言 `file-list-row / media-card / series-card` 出现行数 > 0，
它在默认端口 19786 下跑（或根本没人跑）时表现为「连不上」；
而**页面空白时 BUG-447 的 C1 扫描仍然全绿** —— 空页面扫不到 raw key 是无意义的恒绿。
本条被查出来，正是因为给 C1 加了「页面必须真有内容」的前置断言后 smoke 变红。

## 修复

`scripts/dev/dev_stack.py::ensure_vite()` 启动 vite 时下发：

```python
env["VITE_DAEMON_PORT"] = str(DAEMON_PORT)          # 29786
env["VITE_TG_PORT"] = str((cfg or {}).get("tg_port") or TG_PORT)  # None -> 29787
```

`tg_port` 仍以 daemon 的 `/api/config` 为真源（可能被顺延），只在缺失时退回规范端口。

## 验收证据

- 修复前：`DAEMON_PORT=29786 TG_PORT=29787 node tauri-shell/verify/smoke.cjs`
  → `M2_files_view_renders: FAIL rows=0`（页面「媒体服务未运行」）。
- 修复后：同一条命令 → `M2_files_view_renders: PASS rows=33`，`verdict: PASS`。
- 注入核对（vite 实际下发的值）：
  ```
  curl -s http://127.0.0.1:5180/src/api/daemon.ts | head -1
  → import.meta.env = {... "VITE_DAEMON_PORT": "29786"}
  curl -s http://127.0.0.1:5180/src/api/tg.ts | head -1
  → "VITE_TG_PORT": "29787"
  ```
- 连带：`verify_bug447_i18n_keys.cjs` 补「页面非空」前置 + 扫描器声纳自检后 **4/4 PASS**
  （此前在空页面上是假通过）。
