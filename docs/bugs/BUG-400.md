# BUG-400: 文件页工具条信息架构错误（搜索/读数/排序位置）

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: shell
- 严重程度: high
- 报告: 用户 2026-10-23 17:12「1. 搜索应该在顶部标题栏 2. 占用 登记 这些应该在底栏显示状态吧? 3. 最近添加 需要重新评估位置,第二栏当前感觉多余」

## 现象（用户裁定，结构性问题）

文件页标题栏（ContextBar）下方挂着一条独立工具条（`MediaLibraryPanel` 内 `<header>`），
塞了三样东西：

1. 搜索框「搜索标题…」—— 用户裁定：**应在顶部标题栏**（与 TG 域 `TgGlobalSearch`
   同位，中槽）；
2. 「占用 23.7 GB · 登记 33.4 GB」读数 —— 用户裁定：**应在底栏显示状态**（列表底部
   状态条）；
3. 排序下拉「最近添加」—— 位置需重评；搜索与读数搬走后这条工具条只剩它一个，
   **第二栏（工具条整行）没有存在的必要**。

## 修法（信息架构对齐页面结构规范）

- 搜索框 → `ContextBar` 文件域中槽（`FilesGlobalSearch`，与 TG 域 `TgGlobalSearch`
  同形）；状态走 `store/filesSearch.ts`（input/committed 防抖 300ms，BUG-100 同模式），
  面板只订阅 `committed` 驱动 `loadItems`。剧集视图（lib-series）不挂 —— 搜索对
  剧集墙无效，恒渲染但恒无效等于控件撒谎（BUG-131 口径）。
- 占用/登记 + 双击提示 + 分页事实 → **全局状态栏**（MainLayout `<footer>` 的
  `LibraryReadout` 叶子，`store/libraryReadout.ts` 供原始数字、叶子做 BUG-133 口径
  回退与格式化）。面板内**不造第二条底栏**（「底栏」= 用户指的全局那条；面板内
  再叠一条就是双底栏，正是「多余的栏」）。
- 排序：cat-all **溶入列头**（名称/大小点击排序、日期 recent↔oldest 互切带 ↓/↑
  箭头，`file-sort-*` testid）；分类网格视图（cat:video 等）保留排序下拉 ——
  能力不删（BUG-149）。cat-all 整行工具条撤销。
- 面板卸载/切视图清空 store（读数与提示不跨视图遗留）。
