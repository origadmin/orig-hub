# BUG-360: TG 筛选行可访问名粘连（"琼明神女录14 条"）、命中计数无分隔、删除钮命中区 28×28 低于阈值

- 状态: fixed
- 发现日期: 2026-10-21
- 模块: shell
- 严重程度: high

## 现象

用户 2026-10-21 复报（原话）：「TG筛选下载逻辑混乱……展示的内容也是混乱的」「不清楚用途」。

真栈实测（`tauri-shell/verify/_diag_tg_geom.cjs` / `_diag_round2.cjs`，1440×900）
筛选行 `tg-filter-row` 内部结构：

```
button "琼明神女录14 条"  rect={x:198,y:168,w:239,h:36}     ← 行主体，无 aria-label
  p   "琼明神女录"        rect={x:206,y:176,w:171,h:20}
  span[tg-filter-hits-count] "14 条" rect={x:385,y:174,w:44,h:24}
button "✕"                rect={x:441,y:172,w:28,h:28}     ← 28×28，低于 ≥36px 阈值
```

三个问题：

1. **可访问名粘连**：行主体 `<button>` 没有 `aria-label`，其可访问名由内容拼出 =
   `"琼明神女录14 条"` —— 词条与计数之间没有任何分隔，读起来像一句话。
   这正是「展示的内容也是混乱的」在可访问性上的同一件事。
2. **命中计数无 `aria-hidden`**：计数既是视觉元素又进可访问名，与行主体重复表述。
3. **删除钮 28×28**：低于 BUG-327 已门槛化的「命中区 ≥36px」，在 192px 侧栏里
   既难点中也读不出是按钮（裸 `✕` 字形 + ghost 变体）。

> 取证纠错：首轮把 `tg-panel-root` 的 `textContent`（"文字筛选 琼明神女录14 条✕ …"）
> 当成「全部挤在同一行」的证据。那其实是**整个面板的扁平化文本**，不是一行的布局 ——
> 几何实测词条与计数之间本来就有 8px 间距。真正的问题在可访问名与命中区，不在间距。

## 根因

筛选行是「一个 button 包住标签 + 徽标 + 计数」的平铺结构：没有给 button 提供
`aria-label`，也没有把装饰性计数从可访问名里摘掉。删除钮用了 `size="icon-sm"`
（`h-7 w-7` = 28px），未按 BUG-327 的命中区阈值取尺寸。

## 修复

- 行主体 button 增加 `aria-label={t('tg.filterRowA11y', {label, n})}`
  （zh：`筛选规则：{label}，命中 {n} 条`；en：`Filter rule: {label}, {n} hits`）
  —— 可访问名变成结构化句子，不再是粘连串。
- 行主体增加 `data-testid="tg-filter-chip"`（BUG-360 修复方向要求的固定组件锚点）。
- `tg-filter-hits-count` 增加 `aria-hidden="true"`（已由 aria-label 说明，不重复进名）。
- 删除钮 `size="icon-sm"` → `size="icon"`（`h-9 w-9` = 36×36），并补
  `data-testid="tg-filter-remove"` 供验收断言。
