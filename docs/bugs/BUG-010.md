# BUG-010: 前端 BUILTIN_CLASSIFY 与 daemon 规范分类键不一致

- 状态: fixed
- 发现日期: 2026-08-27
- 模块: shell
- 严重程度: high

## 现象
设置页 → 下载 → 自动分类里，前端内置分类出现 `Audio / Programs / Discs / Torrents / Data / Web` 等分类，但下载内核（daemon）实际只按 `Videos / Music / Images / Documents / Archives`（未知归 `Others`）建目录与分类。两侧分类键不一致，导致：
- 音频文件被 daemon 归入 `Music`，而 UI 旧默认显示 `Audio` → 显示与实际磁盘目录对不上；
- UI 出现 daemon 永远不会创建的「幽灵分类」（Programs/Discs/Torrents/Data/Web），误导用户；
- 若用户照旧 UI 保存规则，部分扩展名（如 `csv`/`iso`）会被映射到不存在的分类键，与 daemon 行为脱节。

## 根因
`tauri-shell/src/components/SettingsPanel.tsx` 的 `BUILTIN_CLASSIFY` 是前端自造的一套扩展名→分类映射，未与 `download-engine/crates/orig-daemon/src/config.rs` 的 `ClassifyConfig::defaults()` 对齐。daemon 规范 key 为 `Videos/Music/Images/Documents/Archives`，且 `csv→Documents`、`iso→Archives`、音频统一为 `Music`（无 `Audio`）。

## 复现
对照 `config.rs:33-55` 的 `defaults()` 与 `SettingsPanel.tsx` 旧 `BUILTIN_CLASSIFY` 的 key 集合即可发现差异（Audio/Programs/Discs/Torrents/Data/Web 在 daemon 侧不存在）。

## 修复
将前端 `BUILTIN_CLASSIFY` 完全改写为与 daemon `defaults()` 一致：
- 视频：mp4/mkv/avi/mov/wmv/flv/webm/m4v/mpg/mpeg/ts/rmvb → Videos
- 音频：mp3/flac/wav/aac/ogg/m4a/wma/opus/ape → Music（删除 Audio）
- 图片：jpg/jpeg/png/gif/bmp/webp/svg/ico/tiff/tif/heic → Images
- 文档：pdf/doc/docx/xls/xlsx/ppt/pptx/txt/md/rtf/odt/epub/mobi/csv → Documents（csv 从 Data 改归 Documents）
- 压缩包：zip/rar/7z/tar/gz/bz2/xz/zst/iso → Archives（iso 从 Discs 改归 Archives）
- 删除 Programs/Discs/Torrents/Data/Web 整组（daemon 无对应 key；这些扩展名统一落入 `Others`）。

并新增 `BUILTIN_CATEGORY_KEYS` 集合，供 BUG-009 的「只读翻译标签」逻辑判定规范 key。

## 关联
- BUG-008（同区域布局）、BUG-009（同区域翻译，依赖本修复保证 key 与 daemon 一致）
- `download-engine/crates/orig-daemon/src/config.rs:33-55`（`ClassifyConfig::defaults` 为唯一规范来源）
