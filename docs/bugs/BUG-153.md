# BUG-153：合集分集的「结束集号」不可编辑 —— 后端支持全集，前端只传起点

- 状态: fixed
- 发现日期: 2026-09-23
- 模块: shell
- 严重程度: high

## 现象

用户原话（2026-09-23）：

> 「多集无法编辑,集数只能修改前,然后不明-N,后续内容视频累加.」

即：一条**合集**分集（如 `S1E3-4`，一个文件含第 3~4 集）在编辑时，
**只能改「第 [N] 集」（起点），无法改「结束集」（终点）**。
改完起点后，渲染出的编号是 `S1E?-4` 这类**不明形式**（起点变了、终点还是旧值，区间关系错乱）。

## 根因

**后端能力齐备，前端只接一半。**

| 层 | 位置 | 事实 |
|---|---|---|
| 后端类型 | `media.rs:2927-2929` | `EpisodeEdit { episode_no_end: Option<Option<i64>> }` —— **三态语义完备**（不传=不改 / null=清除 / 值=设定） |
| 后端处理 | `media.rs:2401-2415` | `update_episode` **完整处理区间终点**（宽度平移 / 改单集） |
| 前端编辑入口 | `SeriesDetail.tsx:172-178` | `openEpisodeEdit` 只 set `epTitle`/`epDraft`/`epSeason`/`epNo` —— **无 `episodeNoEnd`** |
| 前端 state | `SeriesDetail.tsx:139/142/143` | 只有 `epTitle` / `epSeason` / `epNo` —— **无 `epEnd`** |
| 前端提交 | `SeriesDetail.tsx:298-303` | `patchEpisode(epId, { title, description, season, episodeNo: no })` —— **从不传 `episodeNoEnd`** |
| 前端 UI | `SeriesDetail.tsx:814-840` | 只有「第[季]季 第[集]集」两个输入 —— **无区间终点输入** |
| 渲染 | `SeriesDetail.tsx:619-622` | `S{season}E{episodeNo}{episodeNoEnd != null && > episodeNo ? \`-${episodeNoEnd}\` : ''}` |
| TS 签名 | `api/media.ts:371` | 已声明 `episodeNoEnd` —— **零调用** |

**判定**：前端提交时不传 `episodeNoEnd`，后端 `Option<Option<i64>>` 得到 `None` =
「不改终点」，于是**沿用了「按宽度平移」的分支保留旧终点**。
用户改起点后，终点没跟着改 → 区间关系错乱 → 渲染成不明形式。

**关键后果**：用户**无法把合集改回单集**（需要显式传 `null`，而前端只会省略字段）。

## 复现

1. 造一条 `episode_no_end != null` 的分集（合集，如 `S1E3-4`）。
2. 打开该分集编辑 → **只有「第[N]集」输入，没有结束集输入**。
3. 把起点从 3 改成 5 → 保存。
4. 观察：渲染成 `S1E5-4` 之类（起点 5 > 终点 4，区间非法）或按后端平移逻辑得到非预期值。

## 修复

见 `docs/bugs/MERGE-4-DEFECTS-EVIDENCE.md` 问题2。**只改前端**：

1. `openEpisodeEdit` 新增 `setEpEnd(...)`；新增 `epEnd` state。
2. 编辑 UI 增加「结束集」输入（`data-testid="episode-end-input"`），placeholder 写「留空=单集」。
3. 提交时构造 `episodeNoEnd`：**留空 → 必须显式传 `null`**（表达「改回单集」）；填值 → 传该值。
   **不能省略字段**——省略等于「不改」，会丢失用户意图。
4. `epEnd` 有值时校验 `>= epNo`；非法输入（非数字/负数/小于起点）要拦截或内联提示。

### 三、反向证伪（证明上表不是假绿）

1. **改选择器必 FAIL**：把脚本中 `episode-end-input` 全量改名后重跑 →
   `FAIL 1. 编辑面板出现 episode-end-input-NOPE | present=false` → `ERROR ... (aborted)`，`1/2 PASS`。
   证明该断言真的在读 DOM，不是恒真。
2. **清空必须真退回单集**（本次核心）：实现若「有值才传字段」，清空后后端语义是「不改」，
   判据 6 必然 FAIL。实测 `end: null` 通过，且 API 级「省略 vs null」对照（第一节）独立证明了
   两者行为不同 —— 这正是原缺陷（前端从不传该字段）的反面。
3. **断言随目标集号自适应**：徽标期望串由 `E{no}-{end}` 拼出（上次硬写 `1-3` 造成假 FAIL，
   实际渲染 `S1E2-3` 完全正确）。**过程中出现的 2 次 FAIL 均系脚本断言错误，非产品缺陷**，
   已定位并修正（目标集错配 409 vs 410、硬写字符串），最终 8/8。
