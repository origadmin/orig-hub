# BUG-435: 回溯把历史补进库之后，筛选/已存列表不自动刷新——要手动重进才看得到新内容

- 状态: open
- 发现日期: 2026-10-26
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-26

## 现象

用户 2026-10-26 原话：

> 回溯后筛选内容不更新（这是之前的感觉，不清楚是否修复了。）

回溯是长跑（后台每轮翻一页），期间会不断有更早的消息入库。但界面上的
筛选结果 / 已存内容列表不会随回溯推进而更新 —— 用户只能手动重进频道
或点「有新内容」提示条才看得到。

## 根因（代码层核对，未做 UI 复现）

`TgPanel.tsx` 里**没有任何「回溯状态变化 ⇒ 重查列表」的接线**：

- 全文只有一处 `setFeedReloadTick`（第 2986 行），触发者是「有新内容」提示条，
  即**用户手动点击**；
- 唯一的定时器是 `setInterval(() => void refreshCacheTasks(), 5000)`
  （第 1050 行），刷的是**缓存任务队列**，不是内容列表；
- `backfillUntil` 从 `> 0` 变成 `0`（回溯结束，服务端 `clear_backfill`）这个
  状态跃迁没有任何消费者。

即：回溯把数据写进了库，前端**不知道**，也就不会去重查。

## 复现

待补（用户自述为「感觉」，需确认具体是「筛选命中列表」还是「已存内容列表」，
以及期望的刷新时机：回溯每推进一页就刷、还是回溯结束刷一次）。

## 修复

待修复。候选方案（需拍板）：

- **A（最小）**：监听 `backfillUntil` 的 `>0 → 0` 跃迁，跃迁时 bump 一次
  `feedReloadTick` 并重查筛选/已存列表；
- **B（渐进）**：回溯进行中按 `backfillBeforeId` 推进（游标变化）节流刷新，
  例如每推进 N 条或每 30s 刷一次，避免长跑期间界面完全静止。

A 只解决「结束后看不到」，B 才解决「过程中一直是旧的」。倾向 A 先落地。
