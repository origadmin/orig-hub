# BUG-073: 自动分类落盘键/展示名未解耦（手动添加只有名称+类型，无独立磁盘键）

- 状态: wontfix
- 发现日期: 2026-09-20
- 模块: engine+shell
- 严重程度: low

## 现象

设置页的自动分类把文件归进子目录，但**磁盘子目录名与展示名共用同一个字符串**，手动添加又只提供 `名称`+`类型` 两个输入，导致二者无法解耦：

- **内置分类**：`category` 是写死的英文规范键（`Videos`/`Music`/`Images`/`Documents`/`Archives`/`Others`，`orig-daemon/src/config.rs:33-56`），`classify()` 返回它（`config.rs:68-74`），`resolve_output_classified` 把它 `base.join(category)` 当**磁盘目录名**（`config.rs:456-475`）；UI 用 `t('category.'+c.category)` 翻成中文显示（`SettingsPanel.tsx:464`）。→ **磁盘英文键，显示中文**。
- **手动添加分类**：编辑器只收 `名称`+`类型`（后缀）两个输入（`SettingsPanel.tsx:512-536`）；`名称` 直接灌进 `category` 字符串，**既是磁盘键、也是展示值**，落盘和显示都用用户输入原文本（中文界面下即中文）。→ **磁盘中文、显示中文**。

于是中文界面下磁盘上混着 `Downloads/Videos/...` 与 `Downloads/动漫/...`：内置钉英文键、自定义交母语。这不是"中文还是英文"的偏好问题，而是**自定义分类缺独立磁盘键、添加表单不给键**的结构性矛盾。

用户原话（已纠正原"语言" framing）：「A 方案的话添加怎么处理？因为名称+类型，只有这两个添加项。当前不是语言的问题，是这个问题。」

## 根因

1. 分类的 `category` 字符串被强制同时承担 **磁盘键 / classify 键 / i18n 键（缺翻译回退自身）** 三重角色（`i18n/index.ts:4-7` 的设计约束即是此）。
2. 手动添加表单（`SettingsPanel.tsx:512-536`）只有 `名称`+`类型`，`名称` 一个人扛"展示名+磁盘键"，没有地方录入/推导一个独立于母语的稳定键。
3. 因此内置（英文键）与自定义（用户母语键）永远不一致，且无法在不破坏表单约束的前提下谈"语言中立"。

## 复现

1. 设置页开启自动分类，观察内置分类（视频/音乐…）落盘到 `Downloads/Videos/...`；
2. 手动新增分类「动漫」绑定 `.mkv`，下载后落盘到 `Downloads/动漫/...`；
3. 磁盘上同时存在英文键目录与中文键目录——命名策略不统一的真实形态暴露（切换 UI 语言不会改变已落盘目录名，因为键本身没变）。

## 设计裁定（用户 2026-09-20，已定）

> 用户明确裁定：**维持现有单字符串模型（名称=键=磁盘名），不引入 key/name 双列、不做 slug、不迁移。** 自定义分类"建议用英文命名"（以便日后在 locale 补 `category.<Key>` 翻译即自动本地化），但**中文命名直接创建中文文件夹也完全可接受**。因此"内置英文文件夹 + 自定义（用户母语）文件夹并存"是**已接受的产品策略，非缺陷**。

- **裁定要点**：
  1. 添加表单维持 `名称`+`类型` 两个输入，不动数据模型；自定义分类的 `名称` 直接作为磁盘子目录名与 classify 键（沿用 `SettingsPanel.tsx:466-478`、`config.rs:474`）。
  2. UI 在添加处**建议英文命名**：因英文 `名称` 落入 `category.<Key>` 命名空间（`i18n/index.ts:4-7`），日后只要在 locale 补翻译即免费自动本地化（与内置分类同机制，零代码改动）；中文命名则 self-fallback 显示原文本、落中文目录，同样合法。
  3. 明确：**内置英文目录 / 自定义用户母语目录 并存 = 已接受策略**，禁止后续以"命名不统一"为由改代码（符合 `AGENTS.md` R-D 规则：符合设计即非 bug）。
- **零成本复用点**：此裁定不新增任何机制，仅把"英文自定义名可自动本地化"的能力显性化给用户（现有 self-fallback 已支持），故无需实现层改动。
- **剩余微动作（可选，非必须）**：把 `zh-CN.json:56` 占位符 `"新分类名，如 Videos"` 补一句"用英文命名可日后自动翻译"，把"建议英文"的意图显性化。该项完成后即可将本 BUG 以 `wontfix`（accepted-by-design）关单。
- **否决项**：A1（slug 推导 + 模型加列 + 迁移）、A2（显式磁盘键字段）均**不采用**——会破坏"只名称+类型"约束且收益被"建议英文"覆盖。
