# BUG-384: 错误提示不带数据——不可说明、不可调试、不可跟踪（第 5 次）

- 状态: open
- 发现日期: 2026-10-22
- 模块: shell
- 严重程度: high

## 现象

用户 2026-10-22 报：「像前面那个缺少数据支撑的错误完全无法说明具体，
无法调试排错，无法跟踪，无法修复（提出5次了）。」

现状：界面错误统一走 `setError(e.message)` 纯文本（`TgPanel` /
`MediaLibraryPanel` / `DownloadPanel` 皆同）。失败时用户看到一句话，
没有 **对象标识**（item id / ref / chat:msg / 任务 id）、没有 **状态码**、
没有 **时间**、没有 **可复制的诊断串** ⇒ 用户无法在报告里说清「哪一条
坏了」，开发者无法复现，规则上「让错误状态不可表达」的反面。

## 修复

错误呈现统一升级为「一句话 + 可展开的结构化详情」：

- 必带字段：`对象`（id/ref）、`来源`（哪个端点/动作）、`状态码或错误码`、
  `时间`、`原始消息`；一键复制整串。
- 落点：全局 error 呈现组件一处实现，三个域共用（不各写一套）。
