# BUG-191 「在媒体库中查看该内容」打开的是编辑面板：文案承诺「查看」，行为是「编辑」

- **状态**: fixed
- **发现日期**: 2026-09-29
- **模块**: shell
- **严重程度**: mid

关联 BUG-120（「编辑」与「改名」割裂）、BUG-069（分集文案真源）、BUG-149（判据打在实质而非名字上）。

## 现象

剧集内页展开某一集后，操作行有**两个**按钮（`EpisodeExpanded.tsx:252-271`）：

| testid | 行 | 文案 | 实际行为 | 一致性 |
|---|---|---|---|---|
| `episode-play` | `:256-261` | `media.episode.play`（播放） | `props.onPlay` → 播放器 | **一致** |
| `episode-goto-item` | `:263-270` | `media.episode.gotoItem` = **「在媒体库中查看该内容」**（`i18n/locales/zh-CN.json:572`；en-US 同行为 `"View this content in the library"`，`en-US.json:572`） | `props.onGotoItem` → **打开 `ItemEditDialog` 编辑面板** | **矛盾** |

`onGotoItem` 的落点在 `MediaLibraryPanel.tsx:1101-1116`：先 `setView('items')` / `setDetail(null)` /
`setActiveSeriesId(null)`，再 **`setEditing(await getMediaItem(itemId))`**；`editing` 非空时渲染的是
`ItemEditDialog`（`:1357-1361`）。

⇒ 用户点「查看」得到的是**编辑界面**。这正是 2026-09-29 用户反馈的「播放界面变编辑界面」。

## 根因

**不是缺播放能力，是「文案」与「行为」两条真源分叉。**

- 同层 `episode-play` 已经在做真播放，播放入口并不缺失；
- 问题只在 `episode-goto-item` 这一个按钮：它**宣称**查看、**执行**编辑。

成因是开发者替用户假设意图 —— `MediaLibraryPanel.tsx:1102-1105` 的注释原文写着
「从单集层直达该内容在媒体库里的**编辑位**」「打开编辑面板才是用户的真实目的」。
该假设从未与按钮文案对齐，于是同一按钮有了两个互相矛盾的真源。

按 testid 或按文案检索的验收脚本会判它「有该能力」（按钮、文案、testid 三者俱在），
⇒ 属 BUG-149 记录的实质违反形态（能力事实上不存在/不符）。

## 修复

**禁止保留「文案说查看、行为是编辑」的现状。** 二选一：

1. **让行为匹配文案**：`onGotoItem` 改为打开查看器/播放器
   ——`openViewer({ items: [toViewerItem(await getMediaItem(id))], index: 0, title })`
   （形态与 `MediaLibraryPanel.tsx:396` 处理 `pendingMediaFocus` 的那处一致，`openViewer` 在 `:90` 取到）。
   编辑能力不因此丢失：分集另有 `episode-edit` / `episode-slot` 编辑入口（见 BUG-171 索引行）。
2. **让文案匹配行为**：`media.episode.gotoItem` 改为「编辑该内容」，并**另开**一个真正「查看」的入口。

若「查看」与「编辑」都要保留，**必须拆成两个按钮、两个 testid**，不许一个按钮承担两种语义
（BUG-120 的教训：同一语义两份实现，改需求时齐刷刷错成一样）。
