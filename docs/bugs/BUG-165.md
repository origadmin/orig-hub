# BUG-165: 进度条拖拽期每个 pointermove 都提交 seek —— 请求风暴（未松手=未确认态却发请求）

- 状态: fixed
- 发现日期: 2026-09-24
- 模块: shell
- 严重程度: mid
- 档位: standard

## 现象

用户报「进度条拖拽会出现莫名请求，没有释放之前应该是未确认状态，你去请求就完全不对了」。

wire 实测（CDP `Network.requestWillBeSent` / `loadingFailed`，真实后端 + 真实鼠标事件
`Input.dispatchMouseEvent` 驱动一次 2s 拖拽 20 步 + 按住 0.8s）：拖拽窗口内
**7 个媒体流请求、7 个全部被取消**——每次移动写 `v.currentTime` 都中止上一个请求再发新的。
按住不动的 0.8s 里也没有任何「确认」动作，请求却已经发出去了。

## 根因

`tauri-shell/src/components/media/VideoPlayer.tsx`（修复前 `:282-303`）：
`onBarPointerDown` 一按下就 `seekToRatio`，`onBarPointerMove` 对每个有 pointer capture
的移动事件都调 `seekToRatio` → 直接写 `video.currentTime`。自绘进度条全仓仅此一处
（TG 面板播放器用原生 `controls`，拖拽行为归浏览器管），受害面即媒体库播放器。

代价：① 未确认位置也发请求，纯浪费；② 每个请求都吃掉一份 BUG-163 的突发信用，
拖拽风暴与正在进行的投递抢同一条节流管道；③ 每次 seek 都触发解码基线重置。

## 修复

拖拽只更新视觉、松手才提交（`tauri-shell/src/components/media/VideoPlayer.tsx`）：

- 新增 `dragRatio` 状态（null = 未在拖拽）：`onPointerDown`/`onPointerMove` 只
  `setDragRatio`，**不写 `currentTime`**；
- `onPointerUp`/`onPointerCancel`：此刻才 `seekToRatio(dragRatio)` 提交唯一一次 seek，
  并清空 `dragRatio`；
- 条面渲染与时间标签、`aria-valuenow` 改用 `shownSec = dragRatio * duration ?? currentTime`，
  拖拽中条面照样跟手（纯视觉），松手后回到真实播放位置。

## 验收证据

- `tsc --noEmit` 通过（exit 0）。
- 同一探针脚本（CDP 真实鼠标事件 + Network 域计数）修复前后对照，判据非恒绿：

  | 阶段 | 拖拽窗口内请求 | 拖拽窗口内被取消 |
  |---|---|---|
  | 修复前 | 7 | 7 |
  | 修复后 | **0** | **0** |

  修复后松手后 3 个请求 = 提交 seek + 续播取数（正常；修复前为 0 是因为最后一次
  拖内 seek 恰好已把目标位置取回——那 7 次浪费正是本条要消除的）。
- 跨机器可核引用（入库路径）：`tauri-shell/src/components/media/VideoPlayer.tsx`
  （`dragRatio` 状态 + `onBarPointerUp` 提交点）、复用
  `tauri-shell/verify/lib/cdp.cjs` 即可复现同一计数。
