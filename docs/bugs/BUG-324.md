# BUG-324: TG 侧入库入口「编入」术语外泄 + 全应用无下载域跳转出口 + 与下载域重复一份条目级明细

- 状态: fixed
- 发现日期: 2026-10-17
- 模块: shell
- 严重程度: mid

## 现象（用户原话，2026-10-17）

> 「编入 不应该有编入. 不应该缺少下载跳转.」

> 「说了入口只需要简易内容,全部都在下载里面,其他都不要!」

三件事，一句话各一件：

1. **「编入」是内部术语**，却出现在界面上三处：
   - TG 缓存管理面板**行内按钮**「编入 X/Y」（`tg.manifestSlottedCount`）；
   - 该按钮展开的**逐条清单**里每条的状态徽标（「已编入」/「已登记未编入」）；
   - 下载域明细抽屉 `IngestDetailSheet` 的**汇总**（`（已编入 N / 未编入 N / 无条目 N）`）
     与**每条徽标**（「已登记未编入」）。
2. **全应用除侧栏外没有任何到下载域的跳转出口**：`grep "'download'"` 命中只有
   `Sidebar.tsx`。用户在 TG 侧看到一条入库记录，想看它的条目明细/重试/删除，
   只能自己回想「这在下载页」再手动点侧栏 —— 而条目级明细与管理的家正是下载域。
3. **TG 侧重复了一份下载域已有的能力**：`CacheManagerDialog` 里的
   `TaskManifestPanel`（逐条清单 + 每条状态 + 历史批次）与下载域 `IngestDetailSheet`
   是同一份数据的两次实现，后者还更全（多历史批次、条目级下载按钮）。

## 根因

- 「编入」是数据层词汇（`media_item` 被挂进剧集 = slot in），BUG-296 交付组清单时
  直接把它当标签文案用了，从未过「界面语汇」评审；下载域后来照抄了同一套词
  （`entryMeta`），于是同一个内部术语在**两个域**同时外泄。
- BUG-300/BUG-320 两轮都在补**下载域**的条目级能力，TG 侧那份 `TaskManifestPanel`
  成了无人维护的重复实现 —— 用户从 TG 侧点进去，看到的是一份更弱的副本，
  且没有出口通向更强的那份。
- 跨域跳转当时只有两个方向（`handleOpenMedia`：入库→媒体库；`handleOpenTg`：
  媒体库→TG），**入库→下载**这一条从未接上 —— 因为设计上没把「条目级明细的家」
  定下来，两个域各自长了一份。

## 复现

1. dev :5180 → Telegram → 右上「入库流水线」入口 → 面板；
2. 任一行右侧有「编入 X/Y」按钮；展开后每条带「已编入 / 已登记未编入」徽标；
3. 面板里没有任何通向下载页的按钮；行内也没有 —— 条目级管理只能靠侧栏自己找。

## 修复

按用户三句裁定逐条落地（**不加任何用户没要求的东西**）：

1. **撤「编入」**（界面语汇统一到「入库」）：
   - 下载域 `IngestDetailSheet.entryMeta`：`已登记未编入` → `已登记未入库`；
     汇总 `（已编入 N / 未编入 N / 无条目 N）` → `（已入库 N / 未入库 N / 无条目 N）`；
   - TG 侧「编入 X/Y」按钮与其逐条清单徽标随第 2 条一并撤除；
   - 随之成为孤儿的 10 个 i18n 键删除（`tg.manifestToggleHint` /
     `manifestSlottedCount` / `manifestGap` / `manifestSlotted` / `manifestRegistered` /
     `manifestMissing` / `manifestHasBytes` / `manifestNoBytes` / `manifestLoading` /
     `manifestLoadFailed`）。**保留** `tg.manifestInFlight` / `tg.manifestAccum`
     （`IngestDetailSheet` 仍在用，其文案不含「编入」）。
2. **撤 TG 侧重复的条目级明细**：删 `CacheManagerDialog` 的 `TaskManifestPanel`
   组件、`manifestOpen` state、`getCacheTaskItems` import、`GroupManifest` /
   `ManifestEntry` 类型引用、行内 toggle JSX 与底部挂载点。能力不丢 ——
   下载域 `IngestDetailSheet` 有同一份（且更全）。
3. **补下载域跳转出口（每行一个）**：`CacheManagerDialog` 每行新增
   「去下载查看」（`cache-task-godownload`）→ 先 `onClose()` 再 `onOpenDownload()`。
   顺序不可换：面板开合态是 store 里的 `tgCacheManagerOpen`，只跳不关的话切回
   TG 域会把面板又弹出来。接线链路：`MainLayout.handleOpenDownload`
   = `useEvent(() => handleNavigate('download', { dlFilter: 'all' }))`
   → `TgPanel.onOpenDownload` → `CacheManagerDialog.onOpenDownload`
   → 行内 `onGoDownload`（`useEvent` 恒定引用，否则 `memo` 行组件失效）。
   出口由宿主提供（宿主没给时按钮不渲染），与「去媒体库查看」同一约定。

**刻意不做**：TG 侧不保留任何逐条清单/条目级动作（用户「其他都不要」）；
「编入 X/Y」不改成别的按钮（它同时是逐条清单唯一入口，撤入口即撤按钮）。

## 关联

- BUG-296：组清单（`manifest`）数据源 —— 本缺陷撤掉的是它的**第二处**呈现。

## 复报修正（同日）：能渲染的按钮必须能做它承诺的事

**用户复报**：「按钮有了,但是功能全部没有实现」。

**查到的真缺陷**：`CacheManagerDialog` 把 `goDownloadRow` **无条件**透给行组件，
于是只要宿主没提供 `onOpenDownload`，按钮**照样渲染** —— 点了只 `onClose()` 关面板、
不切视图，是一个**能点但做不成事**的死按钮。本组件自己的注释还写着「宿主没给
`onGoDownload` 时整个按钮不出现」，**实现违背了承诺**。

**为何正好表现为用户看到的形态**：HMR 只热更了 `CacheManagerDialog`（按钮出现），
而 `MainLayout` 新增的 `onOpenDownload` 尚未生效时，就是这个死按钮状态 ——
用户看不到任何报错，只看到「按钮有了但功能没实现」。

**修法**：`const goDownload = onOpenDownload ? goDownloadRow : undefined`，
两个调用点改传 `onGoDownload={goDownload}`。宿主未接线 ⇒ 按钮**不渲染**（诚实 UI），
与 `onGoLibrary` 同一约定。
