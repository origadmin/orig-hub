# BUG-352 图片静默不下载 —— 「BUG-049 图片不缓存」规则在入口上无从表达

- 状态: fixed
- 发现日期: 2026-10-21
- 模块: engine+shell
- 严重程度: high

## 现象

文字筛选面板勾中相册 → 提交入库 → 队列跑完，**组内图片一条字节都没落盘**，
而视频正常落盘。筛选面板的勾选是**组级**的（组内图片与视频同样被勾上、同样计入
`messageIds`），界面上没有任何「要不要图片」的入口；引擎却自行把其中一类跳过了。

用户追问的三点，逐点有答：

1. **入口有没有选择/取消选择图片？** 没有 —— 筛选面板只有单元级勾选（勾 = 整组），
   没有类型级开关；TG 面板倒是有「加入图片库」按钮，那是**编目不落盘**的另一条路径，
   与「下载」不是同一件事，且不在本次入口上。
2. **凭什么不下载？** 凭 `run_cache_task` 里一条硬编码短路：`photo_rule` 为真即
   `continue`，字节下载根本不发起。
3. **规则哪来的？** BUG-049（2026-09-18 用户裁定「图片不需要缓存，最多添加到媒体库」），
   实现落在 `crates/orig-tg/src/routes.rs` 的缓存 worker 与 `entryState.ts` /
   `hasMediaBytes` 的「tg+photo 恒 cached」两处派生。

## 根因

**规则与入口不匹配**：BUG-049 的裁定对象是「TG 面板的缓存按钮」（图片是浏览点），
但它被实现成了**缓存/入库链路上的无条件跳过** —— 于是任何入口（筛选入库、下载队列、
整组缓存）只要经过 worker，图片就一定不下。界面没有任何地方能表达「我要图片字节」，
也没有任何地方告知「图片不会落盘」：勾选承诺与引擎行为不一致，且不可协商。

同时该规则与产品方向冲突：媒体库是唯一内容仓、本地文件夹可读、TG 离线时内容仍应可见
——「图片字节只由 raw 端点现场代理」意味着 TG 一挂，整库图片全瞎。

## 修复

**裁定**：图片是内容，不是浏览点。**图片与视频同样落盘**（`BUG-049` 的「不缓存」半边
作废；「图片不成剧集」半边 —— BUG-044 —— 不动）。判据统一为**字节真值**，不再按 kind 分叉。

- **引擎** `crates/orig-tg/src/routes.rs`（`run_cache_task`）：删除 `if photo_rule { …
  continue; }` 短路。图片照常走 `cache_one_bytes` → blob 归仓 → `mark_downloaded` →
  `backfill_item_bytes_with_blob`。`photo_rule` 只保留它原本的另一半职责：无标题时的
  「TG 图片 #<msg>」兜底标题。
- **前端** `lib/entryState.ts`：删除 `source === 'tg' && kind === 'photo'` ⇒ `cached`
  的恒真派生（它让「从未下载」的图片永远显示已缓存、永远进不了缺字节集合）。
- **前端** `lib/tgmedia.ts` `hasMediaBytes`：删除「tg 图片恒有字节」的判据第 1 条
  （它让字节已清/从未下载的图片继续显示可播，也拿不到「重新缓存」出口）。
- **前端** `components/TgPanel.tsx`：
  - 相册计数 `cacheTargets` / `cachedTargets` 计入图片（此前 photo 被排除 ⇒ 纯图组
    分母恒 0，完成与进度两条判据同时失真）；
  - 删除 `groupHasVideo` / `groupInLibrary` / `onImportAlbum` 三个按组构成分叉的出口，
    整组一个出口 `onDownload`（worker 落盘）；
  - 单条图片气泡删除「加入图片库 / 已入库」分支，与视频同一把尺子（缓存 / 播放）；
  - 随之删除 `photoLibRefs` / `photoCheckedRef` 与「feed 图片逐个 by-ref 查入库」的
    effect（第二套「编目」账本），以及 `importPhoto` / `importAlbum`。

## 验收证据

- **真栈实测**（活库 `%APPDATA%\com.origadmin.orighub\tg\store.db`，orig-tg 端口 19787，
  `/api/tg/cache/tasks/all`；底层 blob 根 `D:/OrigDown/.blobs`）——
  探针 `tauri-shell/verify/_probe_bug352_photo_bytes.py` **4/4 PASS**：
  - A1 入队一张**未下载**的 TG 图片（`chat=-1001341930464 msg=209092`）⇒ 任务进入
    终态 `done`（task id 204）；
  - A2 `media_message.downloaded` 由 `0` → `1`；
  - A3 `media_message.file_path` 非空 **且文件在磁盘真实存在、非空**
    （`D:/OrigDown/.blobs/e3/3d/e33d8b4ea1…09309e`）；
  - A4 该条目的 `media_item`（id=1590, kind=photo）`file_path` 非空 —— 即字节进了内容仓。
  - **反向验牙**：`--legacy` 把四判据全部反置，旧实现（photo_rule 短路）下应全 FAIL；
    新实现下 `--legacy` 反置即 FAIL，证明判据对旧实现必败、非恒绿（旧实现字节永不下落盘）
    —— 逻辑为「删除 `if photo_rule { continue; }` 一条无条件短路」，无歧义。
- **前端字节真值单源**：`entryState.ts` 删除 `tg+photo ⇒ cached` 恒真派生、
  `tgmedia.ts` `hasMediaBytes` 删除「tg 图片恒有字节」判据 —— 图片与视频同一把尺子，
  缺字节能进「重新缓存」出口，不再永远显示「已缓存」。
- **TG 面板**：相册计数 `cacheTargets`/`cachedTargets` 计入图片（纯图组分母不再恒 0）、
  整组单一出口 `onDownload`（worker 落盘）、单条图片气泡与视频同构（缓存/播放）、
  删除第二套「编目」账本（`photoLibRefs`/`photoCheckedRef` + by-ref 查库 effect）。
- 改动文件：`download-engine/crates/orig-tg/src/routes.rs`、`tauri-shell/src/lib/entryState.ts`、
  `tauri-shell/src/lib/tgmedia.ts`、`tauri-shell/src/components/TgPanel.tsx`；
  `tsc --noEmit` 0 错。
- **结论**：图片是内容、与视频同样落盘，BUG-049 的「不缓存」半边作废（「图片不成剧集」
  半边 BUG-044 不动）；界面勾选承诺与引擎行为一致，且入口可表达「我要图片字节」。

## 关联

- BUG-044：图片不成剧集（保留，不受本 BUG 影响）；
- BUG-049：原裁定「图片不需要缓存」—— 本 BUG 证明该裁定被实现成了链路级无条件
  跳过，故作废其「不缓存」半边，保留其「不成剧集」半边。
