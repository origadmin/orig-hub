# BUG-056: 剧集合并丢弃合集范围，且槽位规则与批量追加不一致

- 状态: fixed
- 修复者: 主理人（工程师 429 限流，主理人接手）
- 修复 commit: a7bd631
- 发现日期: 2026-09-19
- 模块: engine
- 严重程度: high

## 现象

源剧集里存在「EP01-02 合集」这类**一个文件占两个槽位**的条目时，把它合并到目标剧集后：

- 合集退化为单集（剧集详情里只剩 `第1集`，不再是 `1-2`）；
- 其后的单集被编成 `第2集`，与合集内的第 2 集**语义撞位** —— 界面上看起来「第2集」出现了两次
  （一次是合集的区间、一次是独立条目），观众无法判断哪个才是第 2 集。

同理，用户提出的「多个都是第 1 集的视频」在合并后既没有按同槽多源归并（`media_episode_source`），
也没有在报告里如实回报，只是被顺序改号，来源信息丢失。

## 根因

同一语义「一个条目占用哪些槽位」在仓内存在**两条不一致的实现**：

- `download-engine/crates/orig-tg/src/media.rs` `merge_series()` 的续编起点用
  `SELECT season, COALESCE(MAX(episode_no), 0) ... GROUP BY season`
  —— **只看起点，不看终点**；
- 同文件 `append_episodes_ranged()` 的占用快照用
  `SELECT episode_no, COALESCE(episode_no_end, episode_no)` —— **终点参与「下一可用位」计算**
  （BUG-039 已确立的规则）。

并且 `merge_series()` 里的搬移 INSERT 列清单是
`(series_id, item_id, season, episode_no, title, origin_series_title, origin_episode_no)`，
**不含 `episode_no_end`** —— 合集区间在合并时被直接丢弃，这一点与 `add_episode_ranged()`
（带 `episode_no_end` 列）也不一致。

三条路径三种规则，合并路径是唯一漏掉区间的那条；用户的「1-2 合集问题」与
「多个 1 集视频没处理」是同一处缺口的两面。

## 复现

1. 建剧集 A：加入一个 `EP01-02 合集` 条目（`episode_no=1, episode_no_end=2`）；
2. 建剧集 B：加入一个 `EP03` 条目；
3. 把 B 合并进 A；
4. 观察 A 的区间：合集条目的 `episode_no_end` 变为 `NULL`，EP03 落在 `episode_no=2`。

三条新增单测覆盖：

1. `merge_series_preserves_episode_no_end_range`：源含「EP01-02 合集」+ 两个单集合并进空目标，
   合集区间逐字保留（`episode_no_end=Some(2)`），第 3、4 集仍是 3、4（不退化、不撞位）。
2. `merge_series_range_conflict_keeps_width_and_falls_back`：源合集「EP01-02」与目标 ep=1
   冲突时，回退到 ep=2，宽度保留为「EP02-03」（不是单集），并断言整个目标占用集合无重叠。
3. `merge_series_idempotent_on_repeat`：重复合并同一对剧集，第二次 `added=0`、`skipped=[]`，
   库状态不再变化（不报错，避免污染上层 UI）。

### 路上踩到的真实 bug（已修）

第一版 `slot_end` 实现把单集意外设成 `Some(slot)`（而非 `None`），会把单集标成 `Some(slot)`
的「退化区间」，`get_series` / UI 会以为是合集。修法：`slot_end` 必须与源**一致**——源是单集就 NULL。

### 设计取舍

- **续编两集而非同槽归并**：源剧集内 `UNIQUE(series_id, season, episode_no)` 已保证同槽不重复；
  与目标冲突时按「最大终点之后」回退，与 `append_episodes_ranged` 行为一致。
  同槽归并（冲突时挂 `media_episode_source`）属于 BUG-103 正修范围，留 `sources_attached` 字段
  占位，待拍板。
- **幂等边界不报错**：源剧集已删时第二次合并返回 `added=0` 而非 `Err`，避免 UI 反馈污染。
  库状态严格不再变化（无新行、无删除）。
