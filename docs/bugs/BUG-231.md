# BUG-231：TG 侧播放器标题显示**频道名**而非内容标题 —— 用户完全不知道在看什么内容

- 状态: fixed
- 发现日期: 2026-10-09
- 模块: shell
- 严重程度: high
- 登记: 用户指认「西瓜短剧(AI短剧) 显示标题完全错误，要显示内容」

## 现象（用户裁定核心）

「要求是记录标题，不是频道；现在是显示频道，完全不知道内容。」

在 TG 面板点播频道消息（及全局搜索命中预览）时，播放器标题栏显示的是
**频道名**（如 `西瓜短剧(AI短剧)`），不是正在播放的内容标题。

## 根因

渲染层（`MediaViewer`）只是透传：`viewer-title = title || cur.caption || '未命名'`。
**错在调用方**——`TgPanel.tsx` 两处把频道名当标题传进播放器：

| 位置 | 场景 | 错误传参 |
| --- | --- | --- |
| `onGlobalHitPreview`（原 922 行） | 全局搜索命中 → 预览 | `title: hit.channelTitle` |
| `openPlayable`（原 1145/1151 行） | **频道消息流点播** | `title: selectedChannel?.title` |

后者是用户实际高频路径：点开频道 → 播放消息 → 标题栏永远是频道名。
原注释「标题带频道名」表明这是 BUG-137 时代的设计决定，把**分组维度**
误用成了**内容标题**。

## 修复

- 两处改为传**内容标题**：`hit.caption?.trim()` / `item?.caption?.trim()`，
  caption 为空时留空由播放器兜底（`未命名`），频道名绝不顶替。
- 频道名仅保留其正确用途：频道列表、搜索结果分组 key、缓存分组头。
- 全库清点：`openViewer` 共 6 处调用点，库侧 3 处（item.title/series.title）
  本就传内容标题，TG 侧 2 处错误已修，无其他频道名入参。

  - 路径 B `onGlobalHitPreview`：全局搜索「石家庄」→ 展开命中行 → 点播放（`tg-hit-play`）→ 播放器标题 =

## 流程追溯（本次错登记的教训）

首版登记误把「入库标题噪音」当核心，与用户指认的「频道名顶替标题」牛头不对马嘴。
教训：**登记 BUG 前必须先向用户确认或自行定位到「用户看到错误字符串的确切界面」，
把现象写成用户视角的原话，不得从代码侧推测症状替代**。
