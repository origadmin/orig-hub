# BUG-254: 无字节内容在剧集墙/分集列表/播放器三处不可辨 —— 播放器还把「没有视频内容」误诊成「浏览器无法解码」

- 状态: fixed
- 发现日期: 2026-10-10
- 模块: shell
- 严重程度: high

## 现象

用户原话：「4. 媒体库无视频内容没有提示，导致多余点击，影响观看，这是流程思路不清晰。」

条目**只有信息、没有字节**（`media_item.file_path IS NULL`）—— 这是 BUG-170 裁定的设计内态
（先入信息 → 后入字节），且在 BUG-248（入队即登记）落地后**大量存在**。
但用户从「列表 → 点进去播放」这条链路上，大部分位置看不出这一态。

## 取证（2026-10-10，QA 实测，剧集墙 37 张卡）

| 位置 | 无字节是否可辨 | 实际渲染 |
|---|---|---|
| 媒体库 items 视图卡片 | ✅ | `data-testid="item-nobytes"` 占位 +「缓存已清理」+「重新缓存」入口 |
| **剧集墙卡片** | ❌ | **37 张卡全部没有任何提示**，0 处标记 |
| **剧集详情 / 分集列表** | ❌ | 看不出哪一集缺字节；缺字节的分集行**仍显示时长**（如 3:33）—— 那是假信息，误导性强；只有聚焦后的播放按钮置灰 + hover tooltip |
| **播放器** | ⚠️ **误诊** | 对无字节条目报「浏览器无法解码该格式…」—— 把「没有内容」说成「格式不支持」，用户会去折腾编码而不是去补字节 |

旁注：`EpisodeRow.tsx:126` 的 `data-testid="episode-nobytes"` 是**孤儿组件** —— 全仓零 importer，
已实现但从未被挂载。

## 措施方向

1. **剧集墙卡片**：缺字节的剧集给出可见标识（可复用 BUG-250 已下发的 `coverHasBytes`，或按
   `videoCount`/`photoCount` 与「可导出字节」的差额判定）；
2. **分集列表**：逐集标注「无字节」，且**不得**再显示该集的时长（假信息不能留）；
3. **播放器**：把「无内容」从「解码失败」里分出来，给可执行的下一步（如「重新缓存」入口），
   不用误导性的编码文案；
4. 判定`episode-nobytes` 这个孤儿组件的归属：复活它，或说明为何不用 —— 不留死代码。

## 关联

- BUG-248（入队即登记 —— 本条是它的 UI 后果）、BUG-250（items 卡片已有 `item-nobytes` 占位）、
  BUG-170（先信息后字节的裁定）
- BUG-176（界面无法区分「没有内容」与「取不到内容」）

## 修复

**不动 engine**：`SeriesView.coverHasBytes`（`media.rs:802`）与 `EpisodeView.hasBytes`
（后端 `file_path IS NOT NULL` 探测）两个真值字段**早已下发**，只是前端没消费。本条纯 shell。

判定口径统一走既有 `hasMediaBytes()`（`lib/tgmedia.ts:148`）：
`tg+photo → true`（BUG-049 不落盘）→ `bytesPresence==='present'` → `hasBytes` → `Boolean(filePath)`。

1. **剧集墙**（`SeriesCard.tsx`）：`coverHasBytes === false` 时在封面右上角渲染
   `data-testid="series-nobytes"`（`CloudOff` + `text-amber-500` + 「未缓存」，与 BUG-250
   的 `item-nobytes` 同一套视觉语言）。老后端不下发该字段（undefined）时不渲染，不编造。

2. **分集列表**（`SeriesDetail.tsx` 的 `episode-pick`，即真正挂载的那个列表）：
   每集用 `hasMediaBytes(ep)` 判定尾列 —— 有字节显示时长，**无字节改显
   `data-testid="episode-nobytes"` 且不显示时长**（时长属假信息）。右栏当前集的
   meta 行（`:637`）同步门控，避免在详情区又露出一次假时长。

3. **播放器**（`VideoPlayer.tsx` + `MediaViewer.tsx`）：新增 `hasBytes` / `onRecache` 两 props。
   `hasBytes === false` 时渲染专属 `data-testid="player-nobytes"` 遮罩（`player.noContent`
   文案 + 「重新缓存」按钮），并**压制** fatal / halted / decode 三类解码失败遮罩
   （它们加了 `!noContent` 门控，并统一挂 `player-decode-error`）——
   「没有内容」从此不再被说成「浏览器无法解码该格式」。
   前置：`ViewerItem` 补 `hasBytes` / `ref` / `source`，`toViewerItem` 透传
   `hasMediaBytes(i)`、`episodesToItems` 透传 `e.hasBytes`/`e.ref`/`e.source` 与
   `bytesPresence`（此前一律填 `'local'`/`itemId`，重缓存会走错适配器）。

4. **孤儿组件处置**：`EpisodeRow.tsx` / `EpisodeBoard.tsx` 经全仓 grep 确认**零 importer**
   （仅注释提及；`SeriesDetail.tsx:101` 已明示分集列表被 `EpisodeList` 取代）⇒
   按「不留死代码」**删除**这两个文件。`episode-nobytes` 这一 testid 契约随之**迁移**到
   真正挂载的 `episode-pick` 行（见措施 2），verify 脚本的断言对象未变。

i18n 新增 `player.noContent`（zh-CN / en-US），「重新缓存」复用既有 `media.recache`。

### 跑通过程中修掉的验收脚本缺陷（非产品缺陷）

首跑报 `CDP command failed: Object reference chain is too long`。根因在脚本自身：
`waitForFunction` 的谓词**返回 DOM 元素**而非布尔（`verify_bug_254_nobytes_visibility.cjs`
