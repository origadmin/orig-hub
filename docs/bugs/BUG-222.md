# BUG-222: 回收临时文件页签选择模型混乱：分档按钮静默丢弃「按频道选定」，且单频道时频道选择整块消失

- 状态: open
- 发现日期: 2026-10-09
- 模块: shell
- 严重程度: high

## 现象

用户原文：「包括临时文件回收也充满混乱，包括但不限于按频道选定，等等（所有）。」

「回收临时文件」页签同屏存在**三套互相覆盖的选择机制**，用户无法预期一次点击会清掉什么：

1. 上一排四个**分档按钮**（清理全部 / 孤儿 / 陈旧 / 失败档）—— 点下去直接构造执行目标；
2. 中间一排**按频道 chips** —— 点下去只改「勾选集」，本身不清理；
3. 下面**逐行勾选** + 「清理所选」。

直接后果（危险）：

- 用户先点「频道 A」chip（看到 chip 高亮、底部显示「已选 N 项」），再点「清理全部」⇒ 执行的是
  **scope=all**，清掉**所有频道**，勾选被静默丢弃 —— 最直觉的操作路径导向最危险的结果。
- 只有一个频道时（`chatGroups.length > 1` 不成立，`CacheBytesPanel.tsx:283`），频道 chips
  **整块不渲染** ⇒ 「按频道选定」这个能力在单频道场景下凭空消失。
- 「陈旧 30 天」阈值是写死常量（`:32`），界面上不显示阈值依据，却把它和「全部」「孤儿」并列成
  同权重按钮 —— 看不出哪一档最危险。

## 根因

`CacheBytesPanel` 把「**选择域**」（勾选集：逐行 / 整频道）与「**清理档**」（all/orphan/stale/failed）
两套互斥概念**平铺在同一屏**，并用同一个 `pending` 状态承载：

```ts
type Pending = { kind: 'scope'; scope: ScopeKey } | { kind: 'ids'; ids: number[] } | null
```

`pending` 一旦被分档按钮写成 `{kind:'scope'}`，勾选集 `sel` 就**不参与执行**
（`:78-83` 按 `p.kind` 二选一）——这不是显示瑕疵，是**选择被静默丢弃**。
与 AGENTS.md §2「一动词一端点、差异走参数、互斥组合一律显式报错」同源：
一屏只能有一个选择域，两个并存就必须让它们可组合或互斥可见，不能静默取其一。

## 复现

1. 起服务，确保下载目录内有 ≥2 个频道的缓存文件；
2. 打开「入库流水线 → 回收临时文件」；
3. 点「频道 A」chip（高亮）→ 点「清理全部」→ 确认条显示的是**全部**条目数，不是频道 A 的条目数；
4. 清到只剩一个频道 → 频道 chips 区域消失。

## 修复方向

- **单一选择域**：分档按钮不再直接执行，改为「按档**装载**到选择集」（全部/孤儿/陈旧/失败 各是一
  种装载方式），与逐行勾选、整频道勾选作用于**同一个选择集**；执行动作只剩一条
  「清理所选 N 项（释放 X）」。
- 频道 chips 不再受 `length > 1` 限制（单频道也要能一键全选/取消），缺失标题退回 `#<chatId>`。
- 确认条必须复述**来源**：「按频道 A 选出的 N 项」/「陈旧档（>30 天）N 项」，让用户核对选择依据；
  阈值写进按钮文案或悬浮，不藏在常量里。
