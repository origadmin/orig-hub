# BUG-367: 文件列表同一列里五种命名方式并排，且 `未命名视频 #1574` 在四行上重复

- 状态: open
- 发现日期: 2026-10-22
- 模块: shell
- 严重程度: high
- 排期: 2026-11-10

## 现象

用户 2026-10-22 复报（原话，标注「多次提出未解决」）：

> 「1. 下载标题不统一行问题,多次提出未解决.」

先排除一种误读：**标题确实在同一行**。CDP 实测文件列表前 40 行的名称列几何完全一致 —— `h=18`、`w=670`、`fontSize=12px`、`getClientRects().length=1`（无换行）、行 y 等差 34px。所以「不统一行」不是排版问题，是**命名不统一**。

同一列里实测并排五种互不相干的命名方式（`FileListView` → `resolveDisplayName({ item })`）：

| 行 | 显示名 | 形态 |
|---|---|---|
| item 1586 | `🌟⚡️🔥《时停手表》EP1-3 原档观享 连载中 ⭐⭐⭐ S1E1` | 来源原文 + 集号后缀 |
| item 1584 / 1582 / 1580 | `未命名视频 #1574 S1E4` / `S1E3` / `S1E2` | **同一个 `#1574`** + 集号 |
| item 1575 | `🌟🔥🔥🔥《时停手表》EP7 原档观享 连载中 ⭐⭐⭐` | 来源原文，**无**集号后缀 |
| item 1574 | `未命名视频 #1574 S1E1` | `#1574` + 集号 |
| item 1573 | `TG 图片 #4838` | 兜底名 |

**最严重的一条**：`未命名视频 #1574` 在**四行**上重复出现（1574 / 1580 / 1582 / 1584），仅靠行尾的 `S1E1`–`S1E4` 区分。用户在这一列里认不出哪个是哪个 —— 四行同名，其中三行的名字还是**第四行的 item id**。

## 根因（两条，都待修）

1. **兜底名用了 item id 且可跨行重复**：`resolveDisplayName({ item })` 在条目无标题时退回 `未命名视频 #{item_id}` / `TG 图片 #{msg_id}`。id 是**内部主键**，不是用户可辨的名称；更糟的是它会在多行上重复（同一批内容的多个条目共享一个可读标识时，退回来的都是同一个 id）。
2. **集号后缀时有时无**：item 1586 有 ` S1E1`、item 1575 没有。同一个列表里同一部剧的两行，一个带集号一个不带。

与 BUG-362 的关系：BUG-362 修的是**新登记**时的兜底标题带频道名（`{频道名} · 图片 #{msg_id}`），`fill-empty` 语义保证存量标题不被改写 —— 所以本次实测到的 `TG 图片 #4838` 是**存量旧数据**，不在 BUG-362 的修复范围内。本登记要解决的是**显示层**：存量数据的名字已经这样了，界面怎么把它们区分开。

## 待修方向（未动手，需与用户对齐「统一成哪种」）

- 兜底名不得单用 item id；至少要带**可区分维度**（集号 / 消息 id / 来源频道），并保证同一列表内**不重复**；
- 集号后缀要么全带要么全不带，不能同一部剧两行两种。

**不擅自指定的原因**：用户说「统一」，但没说是哪一种。五种形态各自的出现条件都由既有登记决定（`resolveDisplayName` 三层显名、BUG-362 的 fill-empty、BUG-255 的集数口径），猜一种就是又一次「改了自己想要的样子」。

## 验收证据

取证脚本 `tauri-shell/verify/_diag_20261022_report.cjs`（F1 段，真实浏览器 CDP）：前 40 行 `distinctHeights=[18]`、`distinctFonts=["12px"]`、`widthMin=widthMax=670`、`multiRectRows=0` ⇒ 版式统一；问题全在名字文本本身（见上表）。

## 关联

- BUG-362：新登记兜底标题带频道名（存量不改写，故本登记仍需处理显示层）；
- BUG-310 / D24-A：`resolveDisplayName` 三层显名（本登记的问题出在第三层退回项）；
- BUG-299：文件域取 Explorer 列表语义（本登记的载体）。
