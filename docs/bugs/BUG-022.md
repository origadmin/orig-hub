# BUG-022: PATCH 请求体强制要求 id —— 前端局部更新全部 422

- 状态: fixed
- 发现日期: 2026-09-17
- 模块: engine
- 严重程度: high

## 现象

CORS 修复后，控制台错误由「CORS blocked」变为
`Failed to load resource: the server responded with a status of 422 (Unprocessable Entity)`，
封面、时长、剧集封面依旧无法保存。

## 根因

`crates/orig-tg/src/media.rs` 的更新入参把目标 id 声明为**必填字段**：

```rust
pub struct ItemPatch {
    pub id: i64,          // 无 #[serde(default)]，缺失即反序列化失败
    pub title: Option<String>,
    ...
}
```

而前端（以及任何 REST 客户端）按惯例只在 **URL 路径**传 id、body 里只放要改的字段，
例如 `PATCH /api/media/items/160` + `{"poster":"data:image/jpeg;base64,..."}`。
axum 的 `Json` 提取器在进入 handler 前就因缺 `id` 返回 422，
handler 里那句 `body.id = id` 永远执行不到。`SeriesPatch` 同病。

## 复现

```bash
curl.exe -s -o /dev/null -w "%{http_code}\n" -X PATCH \
  http://127.0.0.1:9877/api/media/items/160 \
  -H "Content-Type: application/json" -d '{"title":"x"}'      # 修复前 -> 422
```

## 修复

- `ItemPatch` / `SeriesPatch` **移除 `id` 字段**（目标由路径决定，避免出现
  「路径 id」与「body id」两个真相源）。
- `Store::update_media_item(id, &patch)` / `update_series(id, &patch)` 改为显式接收 id。
- 路由侧不再需要 `body.id = id` 补写。

验收：`verify_shots/probe_write.py` —— 22 项写路径断言全通过，
覆盖 item/series/tag/episode 的 PATCH 与 tags 的 PUT，并含回滚清理。

## 关联

- BUG-021（同批写路径缺陷，先被 CORS 掩盖）
- 契约原则：**资源的身份只应有一个来源**（URL 路径），body 只承载变更集
