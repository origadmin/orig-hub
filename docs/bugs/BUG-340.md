# BUG-340: TG 二级菜单节头污染——原始计数/监控数文案/后台扫描状态破坏样式，数据未就绪时渲染 "—"

- 状态: fixed
- 发现日期: 2026-10-20
- 模块: shell
- 严重程度: high

## 现象（用户原话，2026-10-20）

> 「布局调整完毕,但是"(524) 3 个监控中 正在后台扫描订阅列表…" 仍然是破坏样式的方式,
> 数字,监控数,扫描,这些全是错误内容,为此还删除了错误的标题分组。」
>
> 「数据异常时显示(-),这是完全不对的,菜单栏数据没有获取时就应该不显示.
> 从来没有需要显示(-)的要求。」

## 根因

`TgPanel.tsx` 三节节头把**汇总数字与过程状态**当成了节头内容，而它们不是导航内容：

1. **频道节头**（`:2250-2283`）：标题右侧依次渲染 `(${channels.length})`（用户观测值
   `524` = dialogs 全量扫描数，对「选监听频道」这个动作零信息量）、
   `t('tg.monitoredCount')`（「N 个监控中」，`zh-CN.json:337`）、
   `t('tg.scanning')`（「正在后台扫描订阅列表…」，`:355`）+ 脉冲圆点。
   三项全是过程态/汇总态——用户判定「全是错误内容」。
2. **筛选/监控节头**（`:1938`、`:2165`）：
   `({filtersResolved ? filters.length : '—'})` /
   `({monitoredResolved ? monitoredList.length : '—'})`——未就绪时渲染 `—`。
3. **此前的修错方向**：BUG-330 第三次复报只修了「频道 (524)」塞在 truncate 标题里被截
   （900×600 实测 scrollW 54 > clientW 44），把计数拆成独立 shrink-0 span
   （`:2253-2255` 注释）——修的是**截断**，没修「这些内容不该出现在菜单里」，
   所以用户再看仍是「破坏样式」。
4. **`—` 兜底之错**：把「未获取」渲染成一个可见字符。用户口径：菜单栏数据没有获取时
   就应该不显示——**不渲染才是诚实的「没有」**；渲染 `—` 反而制造了一个需要用户
   解释的符号，且与「取不到 ≠ 没有」（BUG-318）的诚实方向相反（那条纪律要求的是
   **可区分**，不是**补一个字符**）。

## 复现

1. 打开 TG 面板：频道节头可见 `(N)` + 「N 个监控中」；后台扫描期间另有
   「正在后台扫描订阅列表…」+ 脉冲点；
2. daemon/orig-tg 未就绪时进 TG 面板：三节节头计数变 `—`。

## 修复（已实施）

1. 节头只保留：**节标题 + 规定动作按钮**（按钮尺寸走 BUG-344 token）。
   计数、监控数文案、扫描状态文本、脉冲点全部撤出二级菜单；
2. `—` 兜底一律改「不渲染」（`resolved ? n : null`），三处同改；
3. 计数不清零、只换位置：规则/监控的条数由**行本身**呈现；需要总数的侧栏徽标走
   既有同源口径（BUG-082 三处同源），不在二级菜单重复造汇总；
4. 扫描进行态不占版面：刷新按钮禁用即可，不上状态文本。
