# BUG-074: 网页调试阶段 orig-tg 离线态未真正生效，且离线在 UI 上表现为红色错误环境

- 状态: fixed
- 发现日期: 2026-09-20
- 模块: engine+shell
- 严重程度: mid

## 现象

用户（调试网页模式期间，紧接离线短路改动之后）：

> 「好像设置起效了，但是网页模式完全无法调试啊。我需要一个调试环境，而不是一个错误环境。」

即：orig-tg 设成离线后，网页端看到的不是「调试环境」而是一片错误 —— 与「调试期去除多余流程」的诉求相悖。

## 根因（两条，互相独立）

**① 离线短路根本没真正生效。** 当时 9877 上跑的是**旧 sidecar 副本**：`GET /api/tg/diag` 返回旧 schema
`api_mode:"dummy"`、`api_configured:false`，**没有** `mode` / `unavailable_reason` 字段。而我加离线逻辑的那份
构建在 `download-engine/target/release/orig-tg.exe`（含新 diag + 离线短路），只是「四副本」之一；运行实例来自另一份
陈旧副本（sidecar 四副本铁律），所以离线改动从未生效。「设置起效了」其实是对旧 `dummy` 态的误读。

**② 离线/不可用在 UI 上被当成错误。** 即便离线真正生效，网页端仍会刷红：
- `useStore.refreshTgSession` 的 `catch` 调 `setError(...)` ⇒ 每次加载弹红色「503 / fetch failed」toast；
- `TgPanel` 在 `tgAvailability.status !== 'ok'` 时渲染红色 `border-danger` 的「Telegram 不可用」错误框。

对调试期的**预期离线态**而言，这些是噪音不是信号 —— 等于没有调试环境。

## 复现

1. 以旧副本起 orig-tg（或任意未带 `ORIG_TG_OFFLINE` 的启动）→ 打开网页调试端；
2. 观察：TG 相关红色错误框 / 红色 toast 常驻；整体观感是「错误环境」而非可调试界面。

## 修复

### ① 让离线态真正生效

- 重新 `cargo build --release -p orig-tg`（离线逻辑本就在代码里），`bash scripts/sync-sidecars.sh`
  同步四副本，再以 `verify_shots/restart_tg.py` 离线重启（它默认置 `ORIG_TG_OFFLINE=1`）。
- 现在 diag 落 `mode:"unavailable"` + `unavailable_reason:"offline debug mode: MTProto connect skipped..."`；
  `GET /api/tg/session` 返 **200 + available:false**（状态端点不 503，BUG-023 契约只要求**数据端点**诚实 503）。

### ② 离线=中性调试态，不是错误

- `store/useStore.ts`：`refreshTgSession` 的后台可用性探测失败时**不再弹红色错误 toast**
  （仅记录 `tgAvailability: unreachable` 状态；侧栏据此隐藏 TG，故障仍可见，只是不报警）。
- `components/TgPanel.tsx`：当 `tgAvailability.status==='unavailable'` 且 `reason` 匹配 `/offline debug mode/`
  时，渲染**中性**「调试模式：TG 未连接」面板（`border-border-subtle` + `text-muted`），替代红色错误框；
  真实的故障（unreachable / 真实不可用）仍走红色框。
- `i18n`：新增 `tg.debugOfflineTitle` / `tg.debugOfflineHint`（zh-CN + en-US）。

目的：调试期 TG 离线是可预期的**中性态**，UI 据它干净地隐藏/标注，而不是把每次加载变成错误现场。
