## 根因

### 根因 1：入库侧的「清洗」只覆盖集号一种，且不覆盖存量

- `split_caption`（`download-engine/crates/orig-tg/src/media.rs`）：只取 caption **首行** + **弹掉行尾的 `#标签`** + 截断 120 字符。**不处理** emoji、`《》` / `【】`、集号、推广语。
- `normalized_series_name`（`routes.rs:3268`）：用 `episode_span` 剥掉**集号及其后一切** —— 这是全仓**唯一**的「标题清洗」逻辑，且**只在新建剧集时调用**；`find_series_by_source_key` 命中已有剧集时**显式保留原标题**（`routes.rs:1921-1928` 只打 debug 日志）⇒ **存量脏标题永不回溯**。
- `import_cached_file`（`routes.rs:1066`）：`title = caption_title.unwrap_or_default()` —— BUG-154 已正确地不再拿文件名兜底，但 caption 本身带装饰就**原样入库**。

### 根因 2：`isRawFileName` 只认前缀形，漏掉后缀形

`tauri-shell/src/lib/tgmedia.ts:60`：`/^[a-z]+--\d+_\d+/i` —— 只匹配**以 `--` 开头的落盘名**（`photo--1004418016251_2000`）。实测存在**后缀形**（`…_AI成人短剧_黄果短剧--1003815558259-1952`，**25 条**）**完全判不到**，于是它作为正常标题渲染。

### 根因 3：分集标题是死列，用户实际编辑的是 `media_item.title`

`media.rs:234` 的一次性迁移 `UPDATE media_episode SET title = NULL, description = NULL` 把分集文本腾空（实测 `media_episode` 178 条中 title 非空 **0**、description 非空 **0**）。⇒ 任何「给分集标题加清理」的改动都打在**死列**上（与 BUG-156 同型：判据打在非生产链上）。**正确落点是 `media_item.title`。**

### D2 清理规则集（该剥什么、不该剥什么）

- **该剥（实测均有命中）**：① 频道 emoji 装饰串；② `#话题标签`；③ 包裹用的 `《》` / `【】`（**剥括号、留内容**）；④ 集号 `EP<n>` / `第<n>集`（复用既有 `episode_span`）；⑤ 推广语短语（`新剧首更` / `连载中` / `内群` / `原档` / `完整剧集` …）；⑥ 下载器内部名后缀 `--<chatid>-<msgid>`。
- **不该剥（须显式保护）**：① 标题里的**语义性 emoji**（如 `❗️` 表警示）—— 与装饰难区分，需用户指认口径；② 剥完为空的极端情形（实测 **1 条**：item 616 = `😃`）⇒ **必须回退**为原值或可辨识占位，**不得写空**。
- `涉及:` 新建 1 个纯函数（前后端择一，**必须单点**，禁各写一套）；`量化:` 规则 6 类剥除 + 2 类保护；`回归风险:` 中（误剥即改错用户数据）；`后果:` 决定清洗的「准」与「全」。
- **不做**：无规则、保持现状（= D1-d 的前提）。
