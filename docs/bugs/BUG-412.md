# BUG-412: 视频编辑与显示排版冲突——切换后布局不一致、图文相反

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: shell
- 严重程度: high

## 现象

视频内容（分集）的「显示态」与「编辑态」切换后排版完全不一致：图与文字的位置在两种
状态下相反，没有统一化、标准化，导致切换后用户一下子找不到原来的内容/控件。

用户 2026-10-26 再次复报（原话）：「视频内容编辑后图片和介绍位置完全相反.无限次提出了!
从来没有改,这是严重,且最严重的问题!」

## 根因（2026-10-26 定位）

显示态（`SeriesDetail` 右栏次区）与编辑态（`EpisodeEditPanel`）各写一份布局、顺序相反：

- 显示态（`!editingEpisode`）：**本集图组（Deck）→ 本集介绍（`episode-focus-desc`）**；
- 编辑态（`EpisodeEditPanel`）：**介绍 textarea → 图片区块（`episode-edit-images`）**。

一进编辑，图与介绍上下互换，即用户看到的「完全相反」。

## 复现

进入任一分集详情 → 点「编辑」：显示态图在上、介绍在下；编辑态变成介绍在上、图在下。

## 修复

把 `EpisodeEditPanel` 的图片区块前移到介绍 textarea **之前**，使两态都是
「图片 → 介绍」；顺带给介绍输入补可见标签与 `data-testid="episode-desc-input"`
（此前只有 placeholder，位置不可断言）。

判据（`verify/verify_bug412_edit_layout_order.cjs`，真实 UI，按 `getBoundingClientRect().top` 量）：
1. 编辑态：`episode-edit-images`（或空态）top < `episode-desc-input` top；
2. 显示态：本集图组标题 top < `episode-focus-desc` top（无图/无介绍记 N/A）；
3. 两态结论一致（都图片在前）；4. 无页面错误。
