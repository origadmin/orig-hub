# BUG-140：TG 分组模式频道过滤搜索框与全局消息搜索并存，无作用域标注

- 状态: open
- 发现日期: 2026-09-22
- 模块: shell
- 严重程度: low

## 现象

TG 视图同时存在两个「搜索」输入框：

- 上下文栏全局搜索（`TgGlobalSearch`）：搜**全部监控频道的消息**；
- 分组模式头部的搜索框：只**筛频道列表**（频道标题/用户名）。

两者同屏时外观一致，无任何标注说明作用域差异；用户在分组模式想搜消息时极易输错框。~~placeholder 误导~~（更正：`tg.searchPlaceholder` = 「搜索频道标题或用户名」，文案本身是准确的，问题只在两框并存无标注）。

## 根因

`TgPanel.tsx:269` `search` state + `:1380-1385` 分组模式搜索框 + 消费点 `groupChannels`（`:464-477`，只过滤频道名/用户名）；全局在 `TgGlobalSearch.tsx`（`store/tgSearch.ts`）。频道详情消息流的第三处搜索框已被 BUG-100 删除（`:1469-1470` 注释可证）——残留的是**分组频道过滤**这一个，语义上合法但呈现上与全局框无法区分。

## 复现

TG → 左侧进入任一分组 → 顶部上下文栏与分组头部各有一个外观相同的搜索框；在全局框输入频道名（把分组框的功能期望错置）→ 得到消息命中而非频道过滤。

## 修复

轻改：给两框加作用域标注（分组框加「筛选频道」前缀/图标；或全局框 placeholder 强调「搜消息」）；或评估在分组模式隐藏全局框。修复前先 grep `tg.searchPlaceholder` 的全部消费点（当前仅 `:1383` 一处）。
