# BUG-327: 入库明细底部面板「看得见却用不了」——默认零选中、全选与行复选框相距 1371px、批量按钮像装饰、正文 10–11px

- 状态: fixed
- 发现日期: 2026-10-20
- 模块: shell
- 严重程度: high

## 现象（用户原话，一句里四条投诉）

> 「底部弹出样式,操作全部对. 选中的=要下载的. 入库=要下载的. 实际: 全部非选中.
> 全选和选中偏离,按钮完全无法找到,用户体验极差,大量基础问题,不限于这些.
> 还有弹出内容字体小得看不清.」

第一句是**肯定**（底部弹出的形态、交互都对了），问题全在**默认值与可读性**：
功能在，但用户看不出「要下载什么」、找不到「下载」在哪、也看不清条目内容。

实测（`verify/_diag_ingest_sheet_ux.cjs`，1440×900，一组 10 条缺字节条目）：

| 用户说的 | 实测 |
| --- | --- |
| 实际：全部非选中 | 可下载 10 条，`checkedRows=0`、`dataSelected=0` |
| 按钮完全无法找到 | 按钮 68×29px、11px 白字，`disabled=true`（未选中即禁用），挤在窗口最右下角 |
| 全选和选中偏离 | 全选框左边缘 **x=1387**，行复选框 **x≈16** —— 相隔 **1371px** |
| 字体小得看不清 | 面板 61 个文字叶子节点：**56 个 11px**、1 个 10px、3 个 12px |
| （附带）点不动 | 唯一可命中区是 **12×12px** 复选框；全选标签 36×15px |

## 根因（四条，各自独立）

1. **默认值方向选反**。BT 式选择的「默认」被实现成空集合
   （`setSelected(new Set())`）。于是面板一打开：10 条全非选中 + 按钮灰着，
   等于告诉用户「没有要下载的」—— 与「选中的=要下载的、入库=要下载的」直接矛盾。
   缺字节 = 还没入库 = 要下载的，默认就该是全选、用户只做减法。
2. **全选被标题挤到最右**。表头 `flex-1` 的「条目明细」把 `shrink-0` 的全选
   推到右端 —— 控制这些框的开关，和这些框本身，在视觉上毫无关系（1371px）。
3. **没有半选态**。`<input checked={allChecked}>` 只能表达「全选/全不选」，
   取消 1 条后全选框看起来和「一条没选」完全一样 ⇒ 用户说的「偏离」。
4. **唯一命中区是 12px 的框**。行不可点，只能精确点中小方块；
   按钮 29px 高、11px 字、未选中还 `opacity-40` —— 视觉上像装饰而不是动作。

## 修复（逐条对应，均在 `IngestDetailSheet.tsx`）

| 投诉 | 改法 |
| --- | --- |
| 默认全非选中 | 清单加载后**预选全部缺字节条目**（`filter(!hasBytes)`）；整批在传时不预选（此时选择无法兑现，见 BUG-320 ③） |
| 全选和选中偏离 | 全选挪到**条目复选框那一列**（实测左边缘差 4px，原 1371px）；加 `indeterminate`（半选显示横线） |
| 按钮无法找到 | 按钮 `68×29 → 121×36`、`11px → 13px` 加粗、文案永远带数量（「下载选中 10 项」）；未选中时**不消失**只禁用（消失才是真的找不到） |
| 字体看不清 | 条目 `11 → 13px`、说明 `10 → 12px`、全选与徽标 `10/11 → 12px`；面板内最小可读字号 12px |
| 点不动 | **整行可点选**（≥36px 高，hover 高亮、选中行淡底），复选框只作状态指示（`16×16`），行内点击 `stopPropagation` 防双触发 |
| （同类清扫，用户「不限于这些」） | 抓手 `title="拖拽"` 是**假提示**（面板不能拖）→ 去掉，只留视觉暗示；`✕` 命中区 24×24 → 32×32 + `aria-label`；无标题条目右列由 `title ?? label` 改 `title ?? #messageId`（原来整列「图片 图片」重复，白占一列宽度） |

配套：`verify/lib/cdp.cjs` 新增 `page.setViewport()`（按最矮受支持窗口判「能不能找到」，
不是只在舒服的 1440×900 下判）。

## 为什么「操作全部对」却仍然不可用

功能判据（按钮存在、复选框可勾、Sheet 能开）全绿 —— 这正是前几次修完仍被投诉的原因：
**「存在」与「可用」是两件事**。本轮把每条投诉都换成几何/字号数字再改，
验收脚本也按数字断言（高 ≥36px、字号 ≥13px、左边缘差 ≤4px、默认选中数 = 可下载数）。

## 验收证据

- 门禁脚本（新增，可复核）：`tauri-shell/verify/verify_bug327_sheet_selection.cjs`
  → **20 PASS / 0 FAIL**，产物 `verify_shots/bug327-sheet-selection/`（两张截图 + `report.json`）。
  锁的判据：源码三条结构锚（预选/indeterminate/整行 onClick）、默认全选、全选框
  checked 且非半选、按钮默认可用且文案带数、全选与行复选框同列（≤4px）、
  真实鼠标点行内标题 ⇒ 取消该条、半选 `indeterminate=true`、半选态点全选 ⇒ 全选、
  全选态点全选 ⇒ 全不选且按钮仍渲染、按钮高/字号/在视口内/命中是自己、
  条目与说明字号、面板最小字号 ≥12px、复选框 ≥16px、最矮窗口 900×600 下按钮仍在视口内、零页面异常。
- **反向证伪**：`--expect-legacy`（把默认值断言反置成旧行为「一条都不选」）
  → **1 条转红**，证明「默认全选」这条判据不是恒绿。
- 回归：`verify_bug320_expand_toggle.cjs` **10/10**、`verify_bug300_ingest_aggregation.cjs` **ALL PASS**。
- 诊断脚本（保留）：`tauri-shell/verify/_diag_ingest_sheet_ux.cjs`
  —— 把「看不见 / 点不到 / 看不清」变成可复核数字，后续同类投诉先用它取证再动手。
