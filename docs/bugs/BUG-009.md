# BUG-009: 自动分类编辑器内置分类名未翻译

- 状态: fixed
- 发现日期: 2026-08-27
- 模块: shell
- 严重程度: mid

## 现象
设置页 → 下载 → 自动分类，内置分类（Videos/Music/Images/Documents/Archives）在编辑器里以英文 key 直接显示，未随界面语言翻译；「归档到子目录 {name}」提示里的 `{name}` 也直接是英文 key。与 BUG-007（侧边栏分类标签多语言）不一致。

## 根因
编辑器每一行的分类名用的是裸 `<input value={c.category}>`（`SettingsPanel.tsx` 旧 `:374`），存的是规范 key（磁盘子目录名 / classify_rules 键 / 前端筛选值），显示层未走 `category.<Key>` 命名空间；`catDir` 提示（`旧 :410`）直接插值 `c.category`。
`i18n/locales/*.json` 里 `category.Videos` 等词条早已存在，只是编辑器没调用 `t()`。

## 复现
切换语言（设置 → 常规 → 简体中文 / English），打开下载 → 自动分类，观察内置分类行与归档提示。

## 修复
- 分类名显示：规范 key（Videos/Music/Images/Documents/Archives/Others）在编辑器内**只读**，以翻译标签展示 `t('category.'+c.category, undefined, c.category)`，禁止重命名（重命名会与 daemon 分类键脱节、产生双重目录）；自定义分类仍可自由编辑。
- 归档提示：`<p>{t('downloads.catDir', { name: t('category.'+c.category, undefined, c.category) })}</p>`。
- 缺失词条的 key（自定义分类）安全 fallback 到 key 本身。

## 关联
- BUG-007（侧边栏分类多语言，同一翻译体系）
- BUG-010（规范 key 对齐后才保证这些 key 与 daemon 一致，翻译才真正对应到磁盘目录）
- `i18n/index.ts` 的 `t(key, vars?, fallback?)` 与 `category.<Key>` 命名空间约定
