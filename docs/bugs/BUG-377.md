# BUG-377: 「已暂停」档不含停止项（失败/取消/错误/中断全不可见）

- 状态: fixed
- 发现日期: 2026-10-22
- 模块: shell
- 严重程度: high

## 现象

用户 2026-10-22 报：「全部下载-> 已暂停没有看到暂停内容(失败,取消,错误),所有停止项
都应该在里面。API接口也应该需要优化。」

实测（CDP，`e4_downloads.png`）：侧栏「已暂停 30」，但下载域列表里呈现的是
「TG 入库 … 已中断」行（ingest 侧 interrupted），引擎侧 `paused` 与 ingest 侧
停止项（interrupted/cancelled/error）**不在同一个桶里**——徽标数与列表行
各算各的，用户点进「已暂停」看不到失败/取消/错误的行。

## 根因

`MainLayout.tsx` 侧栏计数与 `DownloadPanel.tsx` 列表过滤**各写一份谓词**：
徽标用 `d.status === 'paused'`（只认引擎 paused），列表用另一套 switch ⇒
改一处就分裂成「徽标 3、列表 0」。ingest 侧的停止终态（BUG-319 的
`interrupted` 等）没有任何一档承担。

## 修复

统一到单一谓词源 `dlBuckets.ts`（`countEngineBucket` / ingest 桶分类），
「已暂停」档 = 所有停止项（paused + error + cancelled + interrupted），
徽标与列表共用同一个分类函数 —— 「数出来的 = 筛出来的」由构造保证。
（实现由并发写者落地于工作区：`dlBuckets.ts` / `DownloadPanel.tsx` /
`ingestGroups.ts` / `MainLayout.tsx`。）
