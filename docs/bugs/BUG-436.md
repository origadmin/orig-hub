# BUG-436: 筛选入库后整组只剩一条有标题，其余落成「未命名视频」

- 状态: fixed
- 发现日期: 2026-10-26
- 模块: engine+shell
- 严重程度: high

## 现象

用户 2026-10-26 报：「未命名视频问题。筛选入库时，因为包含多组数据，视频标题应该以
文字筛选默认为主，当前缺少标题名称，变成了未命名视频。」

即：用**文字筛选**命中一批内容入库后，同一次筛选里的多个相册组只有一条拿到标题，
其余全部空标题；点开播放，返回行显示「未命名」。

复报（本轮）：第一版修复把「文字筛选默认」误读成「组内 caption」——但**筛选词是用户
在筛选框打的那段字**（`EnqueueCacheReq.title_hint`），与 TG 消息原文（组内 caption）
不是一回事。且第一版修复只把 `title_hint` 接到了 worker 落盘路径
（`import_cached_file`），**没接**入队时刻的登记路径（`register_media_item_t0` /
`strengthen_registered_item`），导致入队瞬间无 caption 的视频标题即空 →「未命名视频」。

## 根因（实测，非推断）

### 一、引擎侧：入库只读「这一条自己的 caption」

`routes.rs#import_cached_file` 原来只取 `message_meta(chat, msg).caption` 来
`split_caption` 出标题。而 Telegram 相册**只在一条消息上挂 caption**，其余成员
`caption` 恒为空串 —— 于是整组入库只有 1/N 有条目名。

实测（`orig-tg` 库 `media_message`，频道 `-1004457697592`）：

| 组 `group_id` | 消息号 | 谁带 caption |
| --- | --- | --- |
| 14337886644989745 | 1306–1307 | **1307**（组内最后一条） |
| 14338021678254041 | 1308–1313 | **1313**（组内最后一条） |
| 14338523815214145 | 1314–1316 | 无（整组无 caption） |

注意「挂在哪一条」**不固定**：早期取证看到的是首条，这里是末条。所以修法不能假设
位置，只能问「这组里有没有、是哪一段」。

存量规模（同一库，只读统计）：

- `media_item` 里 `source='tg'` 且标题为空：**211 条**
- 其中同组消息里**确实有** caption 可继承：**182 条**
- 剩下 29 条同组也无 caption ⇒ 无题可补（如实留空，见下「不做什么」）

### 二、壳侧：播放器返回行绕过了唯一显名函数

`MediaLibraryPanel#toViewerItem` 把 `caption: i.title` **原样**透传。`MediaViewer`
的返回行是 `title || caption || t('player.untitled')` ⇒ 空串一路落到底 ⇒「未命名」。

而「这条内容叫什么」早就有唯一解析函数 `lib/displayName.ts#resolveDisplayName`
（D24-A / BUG-310 三层优先级：用户自定义集名 ＞ 剧名+集号 ＞ 来源原文），
文件域卡片、剧集详情、分集列表、条目编辑弹窗都走它 —— 只有播放器这条路径自己透传
裸 title。同一个视频于是在卡片上有名字、点开变「未命名」。

实测（`verify/_probe_untitled_where.cjs`，改前）：
条目 `id=1645` / `ref=-1004457697592:1308` / `seriesTitle=📱【时停手表】` ⇒
`viewer-title` 文本 = `"未命名"`。

### 三、复报根因：筛选词（title_hint）才是「文字筛选默认」，且必须贯穿两条登记路径

用户要的「以文字筛选默认为主」= **筛选入库时用户打的那段筛选词**（`title_hint`），
不是组内 caption（那是 TG 消息原文，与筛选词不是一回事）。第一版修法有两处错：

1. **优先级错位**：把 `title_hint` 当成「组内 caption 的别名」，落到 caption 之后
   兜底；但用户明确要它是**首要**默认。
2. **路径遗漏**：只接到 worker 落盘路径 `import_cached_file`，**没接**入队时刻的
   登记内核 `register_media_item_t0` / `strengthen_registered_item`
   （BUG-248/246 把登记前移到入队时刻）。于是入队瞬间无 caption 的视频标题即空 →
   立刻显示「未命名视频」，且若 worker 迟迟轮不到这条任务，标题就一直空着。


## 修复

### 引擎（两条路径都要，缺一不可；筛选词优先于组内 caption）

标题兜底优先级（统一，两路径同源）：① 本条自己的 caption ＞ ② **筛选词 `title_hint`
（用户打的筛选文字，首要默认）** ＞ ③ 组内共用 caption（仅非筛选入库、无筛选词时回落，
保留原 BUG-436 行为）＞ ④ 全空则落空标题，由展示层如实表达「未命名」。

1. **写入路径（worker 落盘）**：`import_cached_file` 增 `title_hint: Option<&str>` 形参；
   本条无 caption 时**先**用 `title_hint`（`clean_title` 白名单，BUG-342），仍空才回落
   到 `Store::group_caption(channel_id, group_id)`。worker 调用处
   （`IngestCtx` 路径）传 `task.title_hint.as_deref()`。
2. **入队时刻登记路径（BUG-248/246 前移的登记）**：`register_enqueued_items` 与
   `register_media_item_t0` / `strengthen_registered_item` 均增 `title_hint` 形参；
   入队端点 `enqueue_cache_task` 把 `req.title_hint` 贯穿到 `register_enqueued_items`
   （入队瞬间即落正确标题，不依赖 worker 轮到）。`IngestCtx::register_item` 也把
   `task.title_hint` 透传给 `register_media_item_t0`。照片兜底 `{频道} · 图片 #{msg_id}`
   （BUG-362/049）在**无筛选词**时仍生效，有筛选词时统一用筛选词。
3. **存量路径**：`Store::backfill_empty_titles_from_group_caption()`，`main.rs` 启动时
   跑一次（与 BUG-421 的 `repair_old_library_root_rows` 同一个位置、同一条纪律）。
   只填空、拿不到就不编、幂等。

四条判定都走同一把尺子：`split_caption` 取首行 → `clean_title` 白名单（BUG-342）。

### 壳

`toViewerItem` 只在本条**没有**自己的标题时才问 `resolveDisplayName`；有标题照旧用
标题（不做「统一改用解析名」的扩大改动）。`TgFilterPanel#ingest` 已把
`filter.keyword || filter.label` 作为 `titleHint` 透传给 `enqueueCacheTask`。

## 不做什么（刻意）

- **不**拿落盘文件名或频道名当标题 —— 空串纪律（BUG-154）不变。29 条同组也无
  caption、且非筛选入库的条目仍留空，让展示层如实表达「没有标题」。
- **不**覆盖已有标题 —— 用户改过的名字一个字不动（守卫写在 SQL 的 `WHERE` 里，
  并发重跑同样安全）。
- **不**给整组拼序号（「组名 2」之类）—— 那是编造信息，用户没要。
- **不**批量重写 `description`：组 caption 的正文归属是另一条决策（BUG-281 已有
  「剧集级介绍」口径），不在本次范围。


## 验收证据

- 单测：`download-engine/crates/orig-tg/src/store.rs`
  `backfills_empty_titles_from_group_caption_bug436` —— 三条判据（组内有 caption 的
  空标题被补 / 已有标题不动 / 组内无 caption 仍留空）+ 重跑零改写。
- 单测（复报：筛选词是首要默认，且贯穿入队登记路径）：`download-engine/crates/orig-tg/src/routes.rs`
  - `register_t0_uses_title_hint_without_caption` —— 无 caption 视频 T0 登记用筛选词作标题 /
    有 caption 不被筛选词覆盖 / 无 caption 无筛选词落空标题（BUG-154）。
  - `import_cached_file_prefers_title_hint_over_group_caption` —— 有筛选词时**优先于**组内
    caption / 无筛选词时回落组内 caption（保留原行为）。
- 壳侧类型检查：`tsc --noEmit` 通过。
- 取证脚本：`tauri-shell/verify/_probe_untitled_where.cjs`（改前 `viewer-title` =
  `未命名`）。
