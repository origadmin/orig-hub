# BUG-253: 播放器总时长取的是实时转码管道的瞬时 duration —— 实测显示 0:07 / 0:08，而真值 4:02

- 状态: fixed
- 修复日期: 2026-10-10
- 发现日期: 2026-10-10
- 模块: shell
- 严重程度: high

## 现象

用户复报（原话）：「播放时间问题仍然未解决：0:32 / 0:01」

`当前时间 / 总时长` 这组读数不可信：**当前时间会大于总时长**，或总时长显示成一个远小于真实片长的值。

## 取证（2026-10-10，QA 运行时实测，同一视频条目）

| 读数 | 值 |
|---|---|
| `video.duration` | **14.67 s** |
| UI 时间标签 | **`0:07 / 0:08`** |
| 真值（`ffprobe` 与 `GET /api/media/items/<id>` 两边一致） | **242 s** |
| `durationchange` 事件 | 12 s 内 **85 次**（管道时长剧烈抖动） |

## 根因（首轮推断；2026-10-10 已派定位加固逐条证实/证伪）

1. 换档 effect 在 `sameStreamTarget(targetSrc, activeSrc)`（`VideoPlayer.tsx:698`）处**提前 return**
   ⇒ `probeStream()`（`:712`）**从不被调用** ⇒ `contentDurationRef` 拿不到时长真源；
2. 总时长只能被 `<video>.duration` 付成 —— 那是**实时转码管道的当前时长**（仍在增长），
   于是读数随机漂移，用户在某个抖动窗口就可能看到 `0:32 / 0:01`（当前时间 > 总时长）；
3. `streamSeekableRef = useRef(!initialFrc)`（`:648`）对**冷缓存 live 流**误判为「可任意 seek」
   ⇒ 快进被钳回片头附近的 ~1 s 处。

## 进行中（2026-10-10）

派出定位加固，要求逐条给出「证实/证伪 + 原始证据」，并回答关键问题：
**总时长应该取哪个真源才可靠**（候选：`GET /api/media/items/<id>` 的 duration 字段 /
`/stream` 响应容器头的 mvhd / 首帧 metadata 探测），以及**冷缓存 live 流场景下该真源是否可得**
—— 若不可得，UI 应诚实不显示一个假总数，而不是给一个会跳变的数字。

- 证据落 `tauri-shell/verify_shots/playback-duration/`。

## 关联

- BUG-225 / BUG-226（换档与位置恢复）、BUG-229（fMP4 乱序 range 风暴）、BUG-230（stream-first 裁定）
- BUG-207（停载遮罩）、BUG-245（兼容流横幅移除）

## 修复（2026-10-10）

真源总时长从条目元数据 `item.duration`（`GET /api/media/items/<id>` 返回的 `duration` 字段，由前端各 ViewerItem 构造点一并下发）进入播放器，作为 `contentDurationRef` 的初始化值并**钉死**：

1. `VideoPlayerProps` 新增 `duration?: number | null` 入参；`MediaViewer` 把 `cur.duration` 透传进来。
2. `contentDurationRef` 初始化为 `duration ?? null`（挂载即确立真源），`onDurationChange` / `onLoadedMetadata` 仅当该值仍为 `null` 时兜底用元素 `duration`，**一旦确立绝不回写**——直接切断「0:32/0:01」的根因（live 转码流瞬时时长抖动）。
3. `streamSeekableRef` 初始化改为 `useRef(!activeSrcAtMountRef.current.includes('/stream'))`：原生 `/raw` 源可拖、转码 `/stream` 冷流保守置 `false`，只在 `commit` 经 BUG-229 的 seekability 探针确认可服务 Range 时才翻 `true`，**不重新引入 fMP4 乱序 range 风暴**。
4. 换档（1x↔2x）effect 里 `probeStream` 的探针时长只在真源缺失时补兜底、不覆盖真源；切速**不重置**已显示总数。

ViewerItem 真源 `duration` 透传链路：`types.ts`(ViewerItem.duration) ← `MediaLibraryPanel.toViewerItem` / `TgPanel.toViewerItems` / `CacheManagerDialog` 构造点（均由 `MediaItem.duration` / `FeedItem.duration` 填）← `MediaViewer` 透传给 `VideoPlayer`。
