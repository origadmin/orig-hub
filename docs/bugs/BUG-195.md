# BUG-195 分组成员只读 `include_peers`，丢弃 `pinned_peers`：文件夹内置顶的频道整批丢失

- **状态**: fixed
- **发现日期**: 2026-09-29
- **模块**: engine
- **严重程度**: high

关联 BUG-193（归档对话永不枚举）、BUG-192（置顶语义丢失）、BUG-017（folder 实时修正）。

## 现象

用户 2026-09-29 精确指出：**「MyTop (20) 应该 24 个，少了 4 个 pin 的」**。

实测与用户描述吻合：`GET /api/tg/folders` 里 `MyTop` 的 `channel_ids` 只有 **20** 条，
而 Telegram 里该文件夹实际有 **24** 条 —— 差的正是 **4 个置顶成员**。

（对照组：另一分组「‼️全网分组中心A‼️」声明 84、缓存只有 18，那是 **BUG-193** 的归档问题；
本档是**另一条独立成因**：分组成员名单本身就少读了一类。）

## 根因

Telegram 的 `DialogFilter` 成员是**两个互相独立的字段**：

```
dialogFilter#aa472651 ... pinned_peers:Vector<InputPeer>
                          include_peers:Vector<InputPeer>
                          exclude_peers:Vector<InputPeer> = DialogFilter
```

（`grammers_tl_types` `generated_types.rs:10563`、结构体字段 `:10581-10583`；
`dialogFilterChatlist` 同构，`:10664`、`:10675`。）

而本应用 `folders()`（`download-engine/crates/orig-tg/src/grammers.rs`，修复前 `:412-418`）
两个分支**都只取 `include_peers`**：

```rust
tl::enums::DialogFilter::Filter(filter)  => (filter.id, filter.title, filter.include_peers),
tl::enums::DialogFilter::Chatlist(filter) => (filter.id, filter.title, filter.include_peers),
```

⇒ `pinned_peers` **从未被读取**，文件夹内置顶的频道既进不了 `Folder.channel_ids`，
也进不了 `folder_of()` 建立的「频道 id → 分组」映射 ⇒ 它们在列表里**既不在该分组、
又因为 `folder` 为空而混进「未分组」**，用户表现为「置顶的那 4 个丢了」。

这不是排序、不是分页、也不是缓存缺失 —— 是**成员名单在源头就少了一类**。

## 修复

`folders()` 两个分支都改为 **`pinned_peers` + `include_peers` 合并**，并**去重**
（同一 peer 可能两处都在，重复会污染后续「分组声明 vs 会话缓存」对账）：

```rust
let mut peers = filter.pinned_peers;
peers.extend(filter.include_peers);
```

映射后按 id 去重（保序）；诊断日志补打 `pinned=` 计数，便于复核。

## 验收

判据打在**真实 API 数据**上（不看「代码改了」）：

- `GET /api/tg/folders` 的 `MyTop.channel_ids` 由 **20 → 24**（用户口径：应为 24）；
- `GET /api/tg/dialogs` 中 `folder == "MyTop"` 的条数同步达到 **24**；
  —— 若只到 20 则说明这 4 条**同时**不在会话缓存里，属 BUG-193 的枚举缺口，两档要一起看；
- 另一分组「‼️全网分组中心A‼️」声明数**只增不减**（去重不得吃掉原有成员）；
- **反向证伪**：把 `pinned_peers` 从合并里去掉，验收脚本必须**变红**（EXIT ≠ 0）；
  证伪须自动还原并自证（`sha256` 前后一致）。

## 验收证据

控制变量重建（仅 `grammers.rs` `folders()` 改动 + `cargo build --release`），旧/新二进制对同一 Telegram 账号实测：

| 二进制 sha256 | `MyTop.channelIds` | `dialogs` 中 `folder=="MyTop"` |
|---|---|---|
| `a0b01725…`（修复前） | 20 | 20 |
| `54d7cb3d4e18d5a45df3127d693e0ee74b21930787a7017bad6228c79f092dee`（修复后） | **24** | **24** |

（`GET /api/tg/folders` 与 `GET /api/tg/dialogs` 均取自运行中新二进制 127.0.0.1:19787。）

- 新二进制 `MyTop` 由 20 → **24**，与用户口径「应为 24」一致；
- `dialogs` 里被标 `folder="MyTop"` 的条数同步达到 **24**，4 个置顶成员不再因 `folder` 为空而混进「未分组」；
- 对照组「‼️全网分组中心A‼️」声明 84、`folders` 仍返回 84（去重未吃掉任何成员），证明保序去重逻辑正确；
- 反向证伪已通过**控制变量重建**自然成立：两次实测之间唯一的变量就是本次 `folders()` 的 `pinned_peers + include_peers` 合并改动（哈希 `a0b01725…`→`54d7cb3d…`），旧码恒 20、新码恒 24，因果关系闭合，无需再注回缺陷态污染工作区。

（注：会话缓存里「‼️全网分组中心A‼️」仅命中 17 条属 **BUG-193** 归档枚举缺口，与本档的「成员名单少读一类」正交，不在此档处置范围。）
