# BUG-014: 入库媒体看不到图片/视频，无法选择下载/浏览

- 状态: open
- 发现日期: 2026-09-16
- 模块: engine+shell
- 严重程度: critical

## 现象

1. 入库媒体列表无法看到图片和视频（无缩略图/无预览）。
2. 无法对媒体项选择下载 / 浏览。

## 根因

`orig-tg`(9877) 的媒体模型是「离线落盘式」，未暴露任何**内容端点**：

- `GET /api/tg/messages/{chat_id}?limit=` 实测每条仅返回
  `{"id","mimeType","size"}`（照片再多 `caption`），**无 `type` 分类、无 `fileName`、无缩略图/内容 URL**。
- `orig-tg` 无 `/file`、`/media`、`/thumbnail` 路由（实测 404）；`orig-daemon`(9876) 不代理 `/api/tg/*`（实测 404）。
- 前端拿不到照片字节流 / 视频字节流，也无按条的下载入口与已入库本地路径 → 无法渲染、无法选下载/浏览。

- 位置：`download-engine/crates/orig-tg/`（messages 路由）、`tauri-shell/src/`（媒体渲染/入口）
- 契约：见设计稿 §3

## 复现

- 登录后打开任一订阅频道媒体历史，列表仅有 size/mimeType，无可显示内容、无下载/浏览按钮。

## 修复

采用「在线轻预览 × 本地归档」三段式（用户定案，方案见 `docs/TG_MEDIA_LIFECYCLE_DESIGN.md`）：

1. sidecar 新增 `GET /api/tg/file/{chat_id}/{msg_id}`：照片→JPEG 字节（`?w=` 可缩放）；视频→HTTP Range 分段预览。
2. sidecar 增强 `messages`：单条注入 `type`/`fileName`/`date`/`hasMedia`。
3. daemon 新增本地媒体库：manifest SQLite + `/api/library/{items,file,open,ingest}` + SSE 进度。
4. 前端：`<img>/<video>` 渲染预览（浏览态）、选勾入库下载（任务+进度）、媒体库本地播放/打开目录（归档态）。

## 2026-09-16 复测补充（v0.3.0 上线后仍存在的问题）

`/api/tg/file/:chat/:msg` 与 Range 206 已工作，但媒体浏览体验仍不可用，新增取证：

1. **首字节极慢**：实测照片 Range 首包 **3.79s**、视频头部 1KB **4.47s**。根因：`media()`/`messages()` 每次调用都新建 `iter_dialogs()` **全量枚举**解析 PeerRef（含 access_hash），无缓存。
2. **视频直接渲染大黑框**：前端对 300~640MB 的 mp4 直接挂 `<video preload="metadata">`，元数据拉取慢，列表里只剩黑框与 0:00；**无缩略图/海报端点**。
3. **图片尺寸/排版错误**：前端强制 `h-28 object-cover` 固定高裁切，媒体真实比例丢失；加载期间显示灰块。
4. **入库消息缺真实日期与类型**：`media_message` 仅存 `mime_type/size`，`created_at` 是**入库时间**而非消息发布时间；StoredMessage 不返回 `type/date`。
5. 修复：
   - grammers 侧加 PeerRef 缓存（`HashMap<bot_api_id, PeerRef>`，枚举 dialogs 时填充），媒体/消息接口先查缓存，未命中才枚举。
   - 新增 `GET /api/tg/thumb/:chat/:msg`：照片选宽度 ≤480 的最大 `PhotoSize`、视频取 `Document.thumbs()`（优先内嵌 Cached，否则下载小尺寸 JPEG），列表只拉图的几 KB~几十 KB 缩略图；点击播放/查看原图才走 `/file/`。
   - `media_message` 加列 `media_type`、`msg_date`（SQLite 幂等迁移）；StoredMessage 序列化 `type`/`date`；sync 透传。
   - 前端：图片自然比例缩略图（不裁切）+ 点击原图遮罩；视频缩略图 + 播放按钮，点击才挂载 `<video>`。
