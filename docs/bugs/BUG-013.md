# BUG-013: 分组（TG 频道列表）加载极慢、分组缺失、分页停在 50 条

- 状态: open
- 发现日期: 2026-09-16
- 模块: engine+shell
- 严重程度: high

## 现象

1. 前端「无法获取分组信息」，分组/订阅列表拉不出来。
2. `GET http://127.0.0.1:9877/api/tg/dialogs` 早期实测恒为全量平铺数组，耗时 **15.5s**、~30-50KB。
3. **2026-09-16 复测（v0.3.0 代码）新增实锤现象**：
   - `GET /api/tg/folders` 在「账号确有自定义聊天文件夹」（用户确认）的情况下返回 `[]` → 左栏只有「未分组」。
   - 频道总数恒为 **50**，滚动续拉无效果（前端显示「未分组 50」）。

## 根因（2026-09-16 代码取证，三个独立缺陷叠加）

1. **无分页/无缓存**（原始根因）：`dialogs()` 全量枚举，首包 15.5s。
2. **假增量分页，缓存永不增长**：`routes::dialogs` 缓存不足时循环调用 `GrammersClient::take_dialogs(limit)`，而该方法**每次都新建 `iter_dialogs()` 从头发枚举**，反复 upsert 同一批前 50 条；`total` 恒为 50，达到 `need=offset+limit` 后立即 break，第二页 `offset=50` 读缓存为空。
   - 位置：`crates/orig-tg/src/routes.rs` dialogs handler、`crates/orig-tg/src/grammers.rs` `take_dialogs()`。
3. **分组 id 空间不匹配 + folders 解析为空**：
   - `folders()` 中 `DialogFilter.include_peers` 取的是 Telegram 裸 id（`InputPeerChannel.channel_id`，如 `2533442302`），而 `channel_from_dialog()` 用的是 Bot API 对话 id（`-1002533442302`），`folder_of` 映射永不命中（即便 folders 有数据也全部落入「未分组」）。
   - `GET /api/tg/folders` 实测返回 `[]`：代码只接受 `DialogFilter::Filter` 变体，`dialogFilterChatlist`（共享文件夹）被 `let-else continue` 跳过；是否为解析层问题需加原始响应诊断日志在重编译后实证（用户确认账号建过自定义文件夹）。
   - 位置：`crates/orig-tg/src/grammers.rs` `folders()` / `folder_of()` / `channel_from_dialog()`。

## 复现

- 对多订阅账号调用 `GET /api/tg/dialogs?limit=50` → total 恒 50、hasMore=false；`GET /api/tg/folders` → `[]`（账号实际有自定义文件夹）。

## 修复（v0.4.0 方案，2026-09-16 定案）

1. **缓存优先 + 后台全量扫描**（替代假游标增量）：
   - `GET /api/tg/dialogs` 永远先读 SQLite 缓存分页秒回；缓存为空（或 `refresh=1`）时 spawn 后台任务执行**一次**全量 `iter_dialogs`（带 folder 映射）逐条 upsert，响应增加 `scanning` 标志，前端据标志延迟重试。
   - 用 `AppState` 上的扫描互斥状态保证同一时刻只有一个全量扫描任务；启动授权后自动触发首扫。
2. **folders 修复**：
   - 加诊断日志（filters 总数、变体、title、include_peers 数）实证空响应来源；
   - 同时接受 `DialogFilter::Filter` 与 `DialogFilter::Chatlist`；
   - `include_peers` 统一转换为 Bot API 对话 id（Channel/Supergroup = `-1000000000000-id`，Chat = `-id`，User = `+id`，含 FromMessage 变体），与 dialogs id 同空间。
3. 前端：三栏布局（分组｜组内频道/监控中｜内容），dialogs 缓存秒回 + scanning 轮询。

> 完整方案见 `docs/TG_MEDIA_LIFECYCLE_DESIGN.md` v0.4.0 增补。
