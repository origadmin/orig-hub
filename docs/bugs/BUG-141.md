# BUG-141：i18n 硬编码中文文案 253 行分布 25 文件——en-US 界面混中文（BUG-128 同病新实例）

- 状态: fixed
- 发现日期: 2026-09-22
- 模块: shell
- 严重程度: low
- 排期: 2026-12-26

## 现象

`tauri-shell` 是双语应用（`i18n/locales/{zh-CN,en-US}.json`，各 433 key 完全对齐，`t()` 引用 0 缺失——这两项健康），但大量**渲染给用户的文案绕过了 i18n 通道**：全仓非注释行含中文字符串字面量 **253 行、分布 25 个文件**。切 en-US 时这些位置仍显示中文，与周围英文混排（BUG-128 同类，单语可见缺陷）。

媒体域重灾区（行数）：

- `media/SeriesDetail.tsx` 51（含 `:32-36` `KIND_LABEL` series/collection/album——BUG-128 只修了 MediaCard 的同款，这里是**同病新实例**）
- `media/ImportDialog.tsx` 11（含 `:8-13` `KIND_LABEL` + 全对话框文案）
- `media/ItemEditDialog.tsx` 9（「编辑内容」「清除缓存文件」等）
- `media/MediaCard.tsx` 9（`:287/:297/:389-394` 「缓存已清理」「重新缓存」「删除」等）
- 其余：DownloadDetailSheet 25、DownloadItem 23、AddDownloadDialog 17、SeriesDialog 13 等。

## 根因

与 BUG-128 相同：**引入新文案时没走 i18n 通道，且现有门禁不检测硬编码文案**（不会红）。BUG-128 修复只覆盖了 MediaCard 的 `KIND_LABEL` 一处，同款模式在别处仍在滋生。

## 复现

切 en-US → 媒体库剧集详情页 / 导入对话框 / 卡片空态按钮 → 中文残留。

## 修复

批量接线到 `media.*` 命名空间（评估用 `docs/rules/bug-registry.md` §五 批量登记：一次提交关多条，body 列全部编号）。必须遵循 BUG-128 的两个教训：

1. **不复用**复数分类名（`media.videos` 等）——徽标是单数类型名，语义不同；
2. 组件内用 `useTranslation()` 而非裸 `t()`——`t` 不订阅 `settings.language`，被 `memo` 包着的组件切语言不会重渲染。

zh-CN 渲染值不得改变。建议配套门禁（扫描非注释行中文字面量，控制误报率）防再生。

i18n 硬编码中文按扫描清单整改：命中项按文件替换为 key，并在 zh-CN / en-US 双侧补齐；
扫描器同时收紧（只报真正的 UI 文案，不再把注释与日志算进来）。
