# BUG-193 归档（非主文件夹）对话永不进入会话缓存：66 个分组内频道在列表里根本不存在

- **状态**: open
- **发现日期**: 2026-09-29
- **模块**: engine
- **严重程度**: high

关联 BUG-192（置顶语义丢失）、BUG-017（folder 实时修正）、BUG-179（缓存优先服务）。

## 现象

用户 2026-09-29 二次反馈「仍然找不到 pin 的那几个」。

**用 Telegram 自己的分组声明去对齐会话缓存**，差异直接坐实：

```
GET /api/tg/folders   ->  ‼️全网分组中心A‼️  channel_ids = 84
                          MyTop              channel_ids = 20

GET /api/tg/dialogs   ->  缓存 519 条（分页 200+200+119 全取到，非截断）

分组 ‼️全网分组中心A‼️ : 声明 84，在缓存里 18，★ 不在缓存里 66，被标注 folder 17
分组 MyTop            : 声明 20，在缓存里 20，★ 不在缓存里  0，被标注 folder 20
```

⇒ **66 个 Telegram 明确声明属于「‼️全网分组中心A‼️」的频道，应用会话缓存里根本没有这一行。**
用户找不到的是**缺失的数据**，不是排序、不是标识、也不是分页。

（对照：`MyTop` 20/20 全部在缓存里且 folder 标注正确 ⇒ 分组机制本身工作正常，
问题只出在「这 66 条压根没被枚举到」。）

## 根因

grammers-client **0.10.0** 的 `DialogIter`（`src/client/dialogs.rs:28-29`）构造请求时固定：

```rust
exclude_pinned: false,
folder_id: None,
```

`folder_id: None` 即**只取主文件夹**，**归档对话（`folder_id=1`）永不返回**。

而本应用 `dialogs()`（`download-engine/crates/orig-tg/src/grammers.rs:364-381`）用的正是
`self.inner.iter_dialogs()`，**全仓没有任何一次带 `folder_id` 的补充枚举**，
也没有对 `GetDialogFilters` 返回的 `channel_ids` 做「声明了却没枚举到」的补齐。

⇒ 归档频道进了 Telegram 分组（`GetDialogFilters` 看得到），却永远进不了本应用的会话列表。

**已排除**：不是 `exclude_pinned` 造成的漏枚举 —— 该字段首屏 `false`、翻页后
（`dialogs.rs:115`）置 `true`，是 Telegram 的正确用法（置顶只在首屏返回一次），
置顶对话**不会**因此丢失。

## 修复

1. 枚举补上归档：在主文件夹枚举之外，**再用 `folder_id: Some(1)` 枚举一次**（或改用
   `messages.getDialogs` 传 `folder_id` 的两种取法合并），合并进 `dialog_cache`；
2. 或者更稳：**以 `GetDialogFilters` 的 `channel_ids` 为基准对账** —— 声明了却枚举不到的，
   走 `resolve_peer` / `GetChats` 补齐一条最小记录，至少让它在列表里可见；
3. `Channel` / `dialog_cache` 增 `archived` 语义（或在 folder 之外单列），
   让「归档」在 UI 上如实表达，不要和「未分组」混为一谈。

## 验收

判据打在**真实 API 数据**上（不是「代码改了」）：

- 对每个 Telegram 分组做对账：`folders` 声明的 `channel_ids` 与 `dialogs` 缓存取到的 id 集合
  **差集为空**（当前 `‼️全网分组中心A‼️` 差集 = **66**，须降到 0）；
- `MyTop` 保持 20/20 不回归；
- **反向证伪**：把归档枚举注掉，验收脚本必须**变红**（EXIT ≠ 0）；
  证伪须自动还原并自证（`sha256` 前后一致）。
