# BUG-151：搜索结果点击没有内容浏览，直接进播放器

- 状态: fixed
- 发现日期: 2026-09-23
- 模块: shell
- 严重程度: high
- 档位: standard

## 现象

用户报告：「搜索结果没有浏览点击不显示消息内容，反而进去播放的问题」。

在 TG 全局搜索结果里点任意一条命中，**没有「查看这条消息内容」这一步**——直接打开内置
播放器开始放。用户想核对「这是不是我找的那条」（读 caption / 看是哪张图哪个视频）时，
被迫先进入全屏播放态，再退出、再点下一条。

`TgPanel.tsx:1406` 的 onClick 是唯一动作：

```tsx
onClick={() => onGlobalHitPreview(hit)}
```

## 根因

**搜索结果的行点击被直接绑成了「预览/播放」，中间缺一个内容浏览的落点。**

`onGlobalHitPreview`（`TgPanel.tsx:719`）的全部职责就是开播放器：

```ts
const onGlobalHitPreview = useEvent((hit: TgStoredMessage & { channelTitle?: string }) => {
  const item = fromHit(hit)
  const seq = playableHits
  const idx = seq.findIndex((u) => u.key === item.key)
  openViewer({ title: hit.channelTitle, index: idx < 0 ? 0 : idx, items: toViewerItems(idx < 0 ? [item] : seq) })
})
```

这里没有任何「展开/查看内容」的中间态。对比同一份代码里的普通 feed：
流内条目先渲染成**气泡**（`PhotoBlock` / `MediaBubble` / 相册宫格，`TgPanel.tsx:1575`
起），caption、时间、类型徽标、下载态都看得见，**再点才进播放器**。搜索结果作为一条独立
的呈现形态，只做了「一行文字 + 跳播放」，丢掉了浏览这一步。

### 这是呈现层的缺口，不是「用户不会用」

搜索结果的行里已经显示了 `caption` 摘要（`:1415`），说明这里本来就承担「让用户确认是哪一条」
的职责；但它把「确认」和「打开」压成了同一次点击，于是确认动作被跳过了。用户要找的内容
可能是一条**纯文本/说明性消息**（实测 `media_message` 里有 13 行 mime 与 type 双缺、无媒体），
对它「进播放器」必然失败——渲染成「不支持预览」，而消息正文根本没地方看。

### 与 BUG-137 的叠加

`:723` 的 `seq = playableHits` 是**照片+视频混排**的命中集（与 BUG-150 同一个错：
按「可播」而非「同型」构造），所以点图片后的连播会串到视频。两个缺陷在同一个函数里叠加。

## 复现

1. TG 视图 → 在上下文栏搜索框输入「的」（实测命中 30 条）：结果按频道分组列出。
2. 点任意一条 → **直接进入全屏播放器**，没有先看到消息内容/正文的中间态。

## 修复

**判据：搜索命中的点击必须先在结果内展示该条内容，播放是二次动作。**

- 命中行改为**两段式**：行本身是「选中/展开」（在结果视图内就地展示该条的消息内容 ——
  正文/介绍全文、类型、时间、大小、下载态），行内另给显式「播放/查看」按钮进播放器。
- 展开态复用 feed 侧已有的气泡呈现（`PhotoBlock` / `MediaBubble` / 相册宫格），不另写一套 ——
  同一份内容两个来源、两种样子必然漂移（与 SettingsPanel 注释警告的反模式同源）。
- 无媒体可播的命中（`type` 为 `file` 或双缺兜底为 `file`）：**不给播放按钮**，
  只展示正文，避免「点进去是不支持预览」。
- 展开态点击播放时，邻居序列取**同型子集**（BUG-150 的 `playableGroupOf`），
  不再用混排的 `playableHits`。

### 修复前 / 后对照

| 断言 | 修复前 | 修复后（实测 detail） |
|---|---|---|
| 点命中行后**不**打开播放器 | 播放器打开（`viewer-*` 出现）→ FAIL | `viewerOpen=false` → PASS |
| 点命中行后出现内容展开态 | 无 `tg-hit-detail` → FAIL | `detailExists=true` → PASS |
| 展开态含该条正文全文 | — | `detailText="想刀一个人的心是藏不住的\n\nfrom 叮当猫猫－有趣的事\n\n#207041\n9/23 18:36\n加入媒体库\n播放"` |
| 行 `aria-expanded=true` | 无该属性 → FAIL | `aria=true` |
| 展开态内点「播放」→ 播放器打开 | — | `hadPlayBtn=true viewerOpen=true` |

### 反向证伪（证明断言测的是展开态本身）

- 仅取消「播放」按钮的 onClick、**不动展开态挂载点**后重跑，
  「点行不开播放器」与「展开态存在」两条**仍然成立** —— 说明这两条断言由展开态本身满足，
  不是被播放按钮顺带满足的（禁用类证伪的常见陷阱：取消行为却不动挂载点，需确认断言仍独立成立）。
- 「播放」按钮的存在性另有独立断言（`hadPlayBtn=true`），与上面两条互不依赖。

### 与 BUG-150 的交叉（搜索侧序列同型）

- 点**图片**命中 → 播放器为浏览态（`hasImg=true, hasVideo=false`），序列分母 **10**。
- 该分母等于 **photo 命中数（10）**，而非全部命中数（30）—— 修复前混排构造时必为 30，故可证伪。

### happy path 未被改坏
