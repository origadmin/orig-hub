# BUG-434: TG 视频被拼成库域转码流地址——播放器先起在必然 404 的死链上，白等一轮才回退

- 状态: fixed
- 发现日期: 2026-10-26
- 模块: shell
- 严重程度: high

## 现象

用户 2026-10-26 原话（第 1 条与第 5 条）：

> TG中点击视频的严重问题，后台视频在加载，界面依然是展示界面。
> 也就是说，没有播放行为，但是做了播放动作。
>
> 视频播放页面也出问题了。当前 stream 播放一直在读，然后请求 /raw
> （这个我记得功能不再支持了）。问题原因不明。

点开 TG 相册里的视频后，播放器一直停在加载态（`readyState=0`），画面不出帧。

## 根因（实测定位）

`MediaViewer.tsx` 对所有视频条目都自己拼兼容流地址：

```tsx
compatSrc={cur.kind === 'video' ? mediaItemStreamUrl(cur.messageId) : undefined}
```

`mediaItemStreamUrl` 是**媒体库**端点（`/api/media/items/<库内条目号>/stream`），
而 TG 场景下 `cur.messageId` 是 **Telegram 消息号**。两个域的 id 空间毫无关系，
拼出来的是跨域错位的地址。

实测（频道 `-1004457697592`，相册首条 = 视频消息 1309）：

```
/api/media/items/1309/stream          → HTTP 404
/api/tg/file/-1004457697592/1309      → 慢（要回源 Telegram），readyState 长期 0
```

而 `VideoPlayer` 的 `streamFirst = Boolean(compatSrc && compatSrc !== src)` 为真，
于是播放器**先起在这条 404 上**，等它报错才回退到 `src`。用户看到的就是
「后台一直在加载、画面还是展示界面」。

## 修复

把「转码流地址」从**播放器自己拼**改成**调用方显式声明**：

- `types.ts` 的 `ViewerItem` 新增 `streamSrc?: string`（仅媒体库条目填）；
- `MediaLibraryPanel.toViewerItem` 填 `streamSrc: i.kind === 'video' ? mediaItemStreamUrl(i.id) : undefined`；
- `MediaViewer` 改为 `compatSrc={cur.kind === 'video' ? cur.streamSrc : undefined}`，
  不再 import `mediaItemStreamUrl`；TG 不填 ⇒ 播放器直接起在 `src` 上。

不在 `MediaViewer` 里用 `chatId === 0` 之类的隐式约定判别来源 —— 谁有转码流谁声明。

## 复现

TG → 频道 `-1004457697592` → 展开首个相册 → 点首条（视频 7:05）。

## 关联

  只修正了「地址从哪来」，能力本身保留

  TG 一直用 `/api/tg/local` / `/api/tg/file`

## 遗留

用户第 5 条提到的「然后请求 /raw」在**媒体库**播放路径上**未能复现**：
`_probe_playback_requests.cjs` 对剧集 219 / 条目 662 实测 `/raw` 请求数 **0**。
若仍能看到 `/raw`，需要用户给出具体条目号与操作步骤 —— 现有两条路径
（TG 用 `/api/tg/*`、媒体库用 `/api/media/items/*/stream`）都不会发 `/raw` 请求，
除非条目 `kind` 不是 video（音频/图片走 `/raw` 属正常）。
