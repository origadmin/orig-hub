# BUG-317: 页面设计无统一标准——下载页为标准样式（顶部标题/主按钮/次级信息/三级筛选），大部分页面违反，需重新制定与全站收敛

- 状态: open
- 发现日期: 2026-10-15
- 模块: shell
- 严重程度: high
- 排期: 2026-11-10

## 现象

用户 2026-10-15 原话：「4. 下载作为标准样式, 顶部标题,主按钮 次级信息 三级按钮筛选(需评估是否需要)
如果按照这个标准,大部分页面的设计是完全违反的. 需要重新制定,重新评估,统一化,标准化.」

用户给出标准样板的**信息层级四件套**：① 顶部标题 ② 主按钮 ③ 次级信息 ④ 三级按钮筛选
（并明确标注第④项「需评估是否需要」——是否纳入标准由我方评估后定，**不是既成事实**）。
以该标准衡量，大部分页面「完全违反」。

已有一次同族收敛（BUG-313，设置页，fixed）只覆盖**设置页**的区块卡/标题/间距/字号
（组件级），**页面级信息层级**（标题区/主操作/次级信息/筛选的层级与位置）从未成文，
M0 模块重整（BUG-298）后各页面各自生长。

## 根因

- 规范真空：BUG-313 立的单一真源是 `SectionCard` 等**组件级**样式；页面级结构
  （谁是标题、谁是主按钮、次级信息放哪、筛选放哪、各页是否都要这四层）**无一条
  成文规则**，也无验收脚本校验页面结构一致性 ⇒ 页面可以随便长。
- 无样板锚点：下载页是用户心中的标准样式，但它从未被**宣告**为标准（无 testid
  契约、无文档、无回归守卫），其它页面没有对齐目标。

## 复现

1. dev :5180，依次打开下载 / 文件 / Telegram / 设置各页；
2. 按四件套逐页核对：有无顶部标题、主按钮是否唯一且在标题区、次级信息（计数/
   状态摘要）位置是否一致、筛选在第几层；
3. 大部分页面缺层、层级顺序颠倒或把筛选当主按钮平铺。

## 修复

1. **立标准**：以用户四件套为骨架起草页面结构规范（标题区 / 主按钮 / 次级信息 /
   三级筛选的层级、位置、样式契约），第④项筛选**先评估再定去留**（评估输出：
   哪些页面有筛选刚需、哪些是空转入口 —— 参照 BUG-304「标签 TAB 空转」先例），
   评估结论回文档后再动代码。
2. **全站评估表**：逐页按四件套打分（缺哪层/违反哪条），形成差距清单，按严重度
   排实施顺序；不一次性重写所有页面。
3. **收敛实施**：从差距最大的页面开始（候选：Telegram / 文件，以评估表为准），
   每页改完配 CDP 活栈回归（层级存在性 + 位置 + testid 契约）。
4. **门禁**：`tauri-shell/verify/` 加页面结构回归（逐页断言四件套层级），反向证伪：
   删掉标题/把筛选提为主按钮必须 FAIL。
5. 与 BUG-313 的关系：313 是组件级（卡内排版），本条是页面级（信息层级），
   两层规范并存不互相覆盖；实施时先出规范文档再动代码（doc-first）。
