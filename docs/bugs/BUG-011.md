# BUG-011: 运行中反复弹出 Terminal 小窗

- 状态: fixed
- 发现日期: 2026-09-16
- 模块: engine + shell
- 严重程度: mid

## 现象

UAT 环境：APP 运行期间会弹出 Terminal（命令提示符）小窗，用户反馈「一直在弹」「不停弹」，干扰操作。

## 根因

`orig-daemon` 与 Tauri 主进程均为 Windows GUI 子系统（`#![windows_subsystem = "windows"]`），**没有控制台**。当其用 `std::process::Command` / `std::process::Command::new` spawn 一个**控制台程序**（如 `route.exe`、`netstat.exe`、`wmic.exe`、`taskkill.exe`）时，Windows 会为子进程**新建一个控制台窗口**，窗口一闪而过，视觉上就是「Terminal 小窗反复弹出」。

具体 spawn 点：
- `download-engine/crates/orig-net/src/probe.rs:146` → `route print`（`GET /api/interfaces` 探测默认路由接口时触发，每次打开网卡/设置相关 UI 都会执行）
- `tauri-shell/src-tauri/src/lib.rs` → `netstat`(port_owner_is_daemon、kill_port_owner)、`wmic`、`taskkill`（daemon 启动/端口冲突重启管理时触发）

修复前这些命令 spawn 均未设置 `CREATE_NO_WINDOW`。

## 复现

打开会触发 `/api/interfaces` 的前端页面（网卡选择、设置保存），或触发 daemon 端口管理，观察弹出命令窗口。弹窗频率随这些命令被调用的次数增加。

## 修复

给所有 Windows 控制台命令 spawn 加 `CREATE_NO_WINDOW`（`creation_flags(0x0800_0000)`），子进程不再新建控制台窗口：
- `orig-net/src/probe.rs` `route print`
- `tauri-shell/src-tauri/src/lib.rs` `netstat`(×2)、`wmic`、`taskkill`

验收：重新构建 daemon 与 Tauri 主程序后，触发上述路径不再弹出 Terminal 窗。
