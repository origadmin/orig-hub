# BUG-017: Group view missing members — dialog_cache.folder covered only 37/510 channels

- **Status**: fixed
- **Severity**: major（分组视图成员缺失，84 频道的分组只显示 18）
- **Date**: 2026-09-16
- **Owner**: AI agent

## TL;DR

| 项 | 内容 |
|---|---|
| 问题 | 「全部订阅/分组」成员远少于实际（全网分组中心A 应 84 只显 18，未分组 473） |
| 根因 | dialog_cache 表 folder 列覆盖不全（历史扫描写入不完整），dialogs API 直接返回该残缺列 |
| 解决 | dialogs 返回时用 TG 实时 DialogFilter（folders API）channel_ids 映射实时覆盖 folder 字段 |
| 变更范围 | routes.rs dialogs handler（前端 fetchDialogs 翻页已在本日早些修复） |
| 不变项 | dialog_cache 数据与后台扫描逻辑保留（离线兜底）；folders API 本身不变 |
| 关键验证 | curl 全量 510 条：folder 覆盖 84/20 全对、未分组 406 |
| 核心洞察 | 同一事实（频道→分组）存在两个来源时，必须以权威源（TG 实时状态）为准，缓存列只作兜底 |

## 证据

- folders API：全网分组中心A=84 引用、MyTop=20 频道
- dialogs API（修复前）：510 条中 folder 非空仅 37，473 条 folder 为空
- 前端按 folder 过滤 channels → 分组成员缺失（修复前端翻页后 count 到 510 仍缺）
- **补查（修复后）**：84 引用中 66 个在订阅会话里不存在，抽样 3 个调 messages 均报 "chat not found in subscribed dialogs" —— 属 **TG 分组里保留的失效引用（已退订/频道已删）**，非缺陷；分组视图显示 17 个真实可访问频道是正确口径

## 修复

routes.rs `dialogs`：read_dialogs 后以 `client.folders()` 的 `channel_ids → title` 映射覆盖 `it.folder`；folders 读取失败时静默保留缓存旧值（离线容错）。

## 同批修复（缓存库口径）

- 缓存库列表原先混入未缓存媒体 → 前端 listTgStored 调用补 `downloaded:1`，只显示已缓存内容。
