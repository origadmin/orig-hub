# BUG-105: 「能不能播」判数据库字段不判磁盘 —— 字节被删后仍显示已缓存，且没有重新缓存入口

- 状态: fixed
- 发现日期: 2026-09-21
- 模块: engine
- 严重程度: high

> 立项方式：所有者对「入库流水线」做完整流程评估后点名要修的两条 P0 之一。
> 评估档：`docs/design/ingest-pipeline-assessment.md` 第 3.2 条（P0）。
> 编号说明：098~103 在我动手前已被他条占用，故顺延至 105。

## 现象

用户手动删除落盘文件（或用别的方式清了磁盘）后：

- 系统仍判定「可播」——后端只看 `media_message.downloaded` / `file_path IS NOT NULL`
  这类**标志位**，不校验文件是否真的还在磁盘上；
- 前端 `TgPanel.tsx` 用 `local ? tgLocalFileUrl(u.chatId, u.messageId) : tgFileUrl(...)`
  决定播放源，于是走本地 URL → 404；
- 且因为状态仍是「已缓存」，**不会出现「重新缓存」入口** —— 用户卡死在这里，
  只能自己去数据库里改标志位。

## 根因

`GET /api/tg/downloaded/:chat_id`（`routes::downloaded_map`）把 DB 的 `downloaded` 标志位
直接翻译成「messageId → 落盘路径」清单，而这份清单就是前端 `local` 的唯一来源：
**「在清单里」= 对外承诺「这个文件能本地播」**，但承诺之前从未看过磁盘。

对比：`routes::cached_path`（下载幂等跳过用）**已经** stat 过一次磁盘，说明这个判据在本仓
并非没有先例，只是没被接到「能不能播」这条链路上。

## 修法

在返回本地可播状态前校验 `file_path` 对应的文件**实际存在且大小 > 0**：

- 新增 `cache::probe_cached_bytes(path) -> BytesPresence`，**三态**而非布尔：
  - `Present`（存在且非空）→ 正常给出路径，走本地播放；
  - `Missing`（确认不存在 / 零字节 / 不是文件）→ 从清单剔除，**并复位 DB 状态**；
  - `Unknown`（stat 失败但不是 NotFound：权限、被独占、路径非法…）→ 从清单剔除
    （不承诺本地播）但**不复位状态**，另记一条日志。
- `downloaded_map` 按上述三态处置，`Missing` 走既有的 `Store::clear_downloaded`
  （置空 `file_path` + 复位 `downloaded`），使前端「缓存 / 重新缓存」入口自然出现。
  **这是修复的核心目标，不是可选项**：只剔除清单而复位不了状态的话，
  `TgPanel` 里派生自 `m.downloaded` 的徽标与入口仍是「已缓存」，用户照样卡死。

### 为什么必须是三态

`cache.rs::inside_dir` 有个已被点名的坑：canonicalize 失败时**静默返回 false**，
把「判断不出来」和「确实不在目录内」混为一谈。若这里照抄成布尔，
一次瞬态 stat 失败（例如杀毒软件正在扫描、文件被独占）就会把条目复位成未缓存，
进而触发一次无谓的重新下载。故 `Unknown` 必须能被区分：
**不承诺可播，但也不改写状态**。

### 性能（这是被轮询的读端点）

- AGENTS.md §5 规定「被轮询的读端点不许碰 DB」。本端点**原本就是**一次 DB 读，
  本次修改**没有新增任何 DB 读**；新增的只有 `tokio::fs::metadata` ——
  stat 文件系统不是 DB，是允许的。
- 一次请求至多 stat 该频道已缓存的行数（典型几十行）。stat 是单次系统调用、微秒级，
  远低于一次 DB 查询，故**不做批量上限裁剪**：裁剪等于放行未校验项，
  本条缺陷（「已缓存」却 404）会原样复发。
- 复位写入只在**确认缺失**时发生，且复位后该行不再进入 `list_downloaded`
  （`downloaded = 0`），故**一次收敛**，不会每轮重复写。
  用 `tokio::fs` 而非 `std::fs`，避免同步 syscall 占住运行时线程。

## 验收证据

- 三态判据：`download-engine/crates/orig-tg/src/cache.rs`
  `cache::tests::probe_cached_bytes_needs_a_non_empty_file` ——
  非空文件 `Present`；零字节、不存在、空路径一律 `Missing`。
- 目录不是文件：同文件 `cache::tests::probe_cached_bytes_rejects_directories`。
- 三态必须互不相同（防止后人合并成布尔）：同文件
  `cache::tests::bytes_presence_has_three_distinct_states`。
- 端点契约变更落在 `download-engine/crates/orig-tg/src/routes.rs` 的
  `downloaded_map`（三态处置 + 复位 + 日志）。
- 门禁：`cargo build` / `cargo test -p orig-tg`（58→59 项全绿）/ `scripts/check-bugs.py`
  / `scripts/sync-sidecars.sh --check` / `scripts/check-pollution.sh`。
