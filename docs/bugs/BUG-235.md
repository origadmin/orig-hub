# BUG-235：库根目录与下载路径/子目录分类体系脱节——两个互不相干的真实目录树

- 状态: open
- 发现日期: 2026-10-09
- 模块: engine+shell
- 严重程度: high
- 登记: 用户报告「下载设置的库根目录路径有严重问题，脱离了下载路径，
- 排期: 2026-11-10
  也脱离了子目录的核心设计」；关联用户同轮提出的「媒体库并入核心」方向（见 BUG-238 关联讨论）

## 现象

- 下载目录（download_dir + 自动分类子目录）是一棵树；
- 库根目录（library root，媒体库字节落盘）是另一棵树；
- 两者无任何从属/映射关系。下载完成的文件与媒体库条目的**放置关联**要靠额外的
  注册/搬运动作，同一内容两处存在或互不知道——正是用户指出的「下载文件归类放置/
  放置关联问题」。

## 根因

库根是后加的独立配置（shell `persistLibrary` 独立持久化），落地时未与既有的
「下载目录 + 自动分类子目录」体系对齐：没有定义为它的子结构、也没有反向声明
下载目录属于库根。设计层缺一条裁决：**单一目录树还是受控双树**。

## 修法方向（待拍板后实施）

与用户已拍板的「媒体库是唯一内容仓、单一库根、本地文件夹直接可读」对齐，推荐：
**库根 = 唯一根，下载目录默认收纳为库根下的 downloads 子树**（或库根即下载分类树的
父目录），下载完成即按分类落位并由媒体库登记，不再有第二个根。涉及
`download-engine.toml` 配置语义、daemon 路径解析、shell 设置页呈现，动面前需拍板。
