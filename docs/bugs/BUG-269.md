# BUG-269: 按钮外观割裂 —— 同一语义在不同页面得到「有背景 / 有边框」与「无背景 / 无边框」两种形态

- 状态: open
- 发现日期: 2026-10-10
- 模块: shell
- 严重程度: low

> 来源：用户报告「**按钮统一化，我发现部分按钮有背景，部分按钮没有背景和边框，这点需要统一化，不能造成割裂。**」

## 现象

### 现象 1：仓库里**同时存在两套按钮体系**

**体系一 —— 共享组件 `tauri-shell/src/components/ui/button.tsx`**（`Button`），5 个 variant：

| variant | 类名（`:8-16`） | 外观 |
|---|---|---|
| `default` | `bg-accent text-white hover:bg-accent/90 shadow-sm font-medium` | **有背景**（强调色） |
| `secondary` | `bg-surface-2 text-fg-strong hover:bg-surface-2/80 border border-border-subtle` | **有背景 + 有边框** |
| `ghost` | `text-fg-mid hover:bg-surface-2 hover:text-fg-strong` | **无背景、无边框**（hover 才出背景） |
| `destructive` | `bg-danger text-white hover:bg-danger/90` | **有背景**（危险色） |
| `outline` | `border border-border-subtle bg-transparent text-fg-mid hover:bg-surface-2` | **有边框、无背景** |

**体系二 —— 裸 `<button>`**，各自手写 `className`，**不经过** `variantClasses`。

⇒ 两套体系并存 ⇒ 同一语义在两个体系里外观可以完全不同。**这正是用户看到的「割裂」。**

### 现象 2：同一语义、两种形态的**实测对照**（每组已独立复核行号）

> **下表路径以 `tauri-shell/src/components/` 为根**（注意本仓 `components/` 与 `components/media/` **混放**：
> `SeriesDetail` / `SeriesCard` / `MediaCard` / `Lightbox` 在 `media/`；`MediaLibraryPanel` / `CacheManagerDialog` 在根）。

| # | 语义 | 落点 A（有背景 / 有边框） | 落点 B（无背景 / 无边框） |
|---|---|---|---|
| 1 | **删除 / 移除** | `media/SeriesDetail.tsx:519-520` `variant="outline"`（有边框） | `media/MediaCard.tsx:481` 裸 `<button>`（hover 才出现的图标） |
| 2 | **删除 / 移除** | `media/SeriesCard.tsx:245` 裸 `<button>` | `media/SeriesDetail.tsx:519-520`（同上）—— 同为「删除」两形态 |
| 3 | **重新缓存** | `media/SeriesDetail.tsx:865-866` `variant="outline"`（有边框） | `media/MediaCard.tsx:381` 裸 `<button>` |
| 4 | **关闭** | `CacheManagerDialog.tsx:937-938` `variant="ghost"` `size="icon"`（无背景无边框） | `media/Lightbox.tsx:57` 裸 `<button>` |
| 5 | **次要动作 / 返回** | `MediaLibraryPanel.tsx:1095-1096` `variant="outline"`（有边框） | `MediaLibraryPanel.tsx:967-968` `variant="ghost"`（无边框） |
| 6 | **来源切换 / 摘除** | —— | `media/SeriesDetail.tsx:759` / `:767` 裸 `<button>`（两个都是裸的） |

⇒ **同一文件内**（第 5 组：`MediaLibraryPanel.tsx:967-968` vs `:1095-1096`）就有 ghost 与 outline 两种「次要动作」形态；
**同一语义**（第 1/2/3 组）跨文件形态相反。**不是个别疏漏，是没有规则。**

### 现象 3：`Button` 组件**有**变体体系，但**没有**「语义 → variant」的映射规则

`ui/button.tsx` 定义了 5 个变体，但**全仓没有任何文档说明「什么语义该用哪个 variant」**。
于是「次要动作」在 `MediaLibraryPanel.tsx:967-968` 被写成 `ghost`、在 `:1095-1096` 被写成 `outline` —— 两者都「说得通」，
差别只在写的人当时想什么。**规则缺失是根因，不是实现疏忽。**

## 根因

### 根因 1：两套体系并存，且裸 `<button>` 是「默认路径」

`ui/button.tsx` 是共享组件，但**没有 lint / 门禁阻止裸 `<button>`**。
新写一个按钮时，「写裸 `<button>` + 抄一段类名」比「先想该用哪个 variant」更快 ⇒ 裸 `<button>` 持续增加。

### 根因 2：缺「语义 → variant」映射表 ⇒ 同一语义的选择不可复现

「次要动作」可以是 `ghost`（无边框）也可以是 `outline`（有边框），二者都是合法选择
⇒ 不同页面必然分叉。**判据缺失 = 分叉是必然结果，不是偶然。**

### 根因 3：图标按钮与文字按钮的边界未定义

`variant="ghost" size="icon"`（`CacheManagerDialog.tsx:937`）是一种「无背景图标按钮」；
但同样的「无背景图标按钮」在 `MediaCard.tsx:481` / `SeriesCard.tsx:245` 是裸 `<button>`
（并且额外带「hover 才显示」的行为，那是另一层语义）。⇒ 「图标按钮」没有统一样式入口。

## 修复方向（未实施；≥2 实质选项 + 1 个「不做」）

### 选项 A（推荐）：收敛到 `ui/button.tsx`，并补一张「语义 → variant」映射表

- 新增设计文档节（建议落在 `docs/design/media-library-layout-design-2026-09-28.md` 或新建
  `docs/design/button-consistency.md`），定义映射：
  - **主操作**（保存 / 播放全部 / 确认）→ `default`
  - **次要操作**（取消 / 返回 / 导出预览）→ `outline`
  - **工具栏 / 行内图标**（关闭 / 刷新 / 更多）→ `ghost` + `size="icon"`
  - **破坏性操作**（删除 / 移除 / 清除）→ `destructive`（或在图标态用 `ghost` + 危险色文字，**须二选一并写明**）
- 把裸 `<button>` 按映射表改成 `<Button variant=...>`（**不改变功能、位置、`data-testid`**）。
- `涉及:` `ui/button.tsx`（可能需补 1 个 `icon-ghost` 语义）+ 约 10~20 处调用点 + 1 份设计文档。
- `量化:` 改动点需先实测（见判据 2）；新增 0 个组件、1 份映射表。
- `回归风险:` 中 —— 触碰面广，必须逐处验「功能不变、位置不变、testid 不变」。
- `后果:` 同一语义全库外观一致；新按钮有可循规则。

### 选项 B：不收敛组件，只抽一个 `btnClass()` 纯函数

- 建 `src/lib/btnClass.ts`，返回类名字符串；`Button` 与裸 `<button>` 都调它。
- `涉及:` 新增 1 个纯函数 + 全部按钮调用点。
- `量化:` 同 A 的调用点数量。
- `回归风险:` 中（同上）。
- `后果:` 外观统一，但**组件仍有两套**（`Button` 与裸 `<button>`）⇒ 未来仍会分叉。

### 选项 C：只统一用户点名的几组（删除 / 关闭 / 重缓存）

- `涉及:` 约 6 处。
- `量化:` 6 处。
- `回归风险:` 低。
- `后果:` 用户当下看到的那几处齐了，**规则仍缺失** ⇒ 下一个新按钮继续分叉（现象 3 未解）。

### 选项 D：不做

- `涉及:` 无。`量化:` 0。`回归风险:` 无。
- `后果:` 割裂持续；且 `BUG-262` 新增的 `series-play-all` 会成为**第 3 种**形态。

## 修复后必须满足（可证伪判据，预先声明）

1. **同一语义在全部落点使用同一 variant**（按映射表）：逐语义抽查 ≥3 组（删除 / 重新缓存 / 关闭），
   每组所有落点的 `getComputedStyle` 背景与边框**判定结果一致**（**不读 className**）。
2. **裸 `<button>` 的计数收敛**：先实测当前基线（带 `bg-` 类 / 不带 `bg-` 类的计数），
   修复后**带背景类与不带背景类不再混用于同一语义**；若选项 A，另需给出「仍存在的裸 `<button>` 清单及理由」
   （例如「播放器控件层内部按钮」可豁免，**须显式列出豁免范围**）。
3. **反向证伪**：把任一已统一的按钮改回裸 `<button>` + 手写类名 ⇒ 判据 1 必须 FAIL。
4. **不得改变功能**：每个被改按钮的 onClick / disabled / 位置 / `data-testid` **逐项不变**；
   反向证伪：故意改掉某按钮的 `data-testid` ⇒ 既有验收脚本（如 `verify_play_primary.cjs`）必须 FAIL。
5. **必须同时验 happy path**（BUG-148）：统一后每个按钮仍可点、仍触发原动作（不是只比对样式）。
6. 判据 1 / 5 必须在**真实 UI** 上验（BUG-156）。
7. **新按钮受约束**：`BUG-262` 的 `series-play-all`、`BUG-266` 的 `player-controls-toggle` 必须按映射表落地
   （即本档的规则**向前生效**，不只修存量）。

## 待确认（口径）

1. **「有背景」与「无背景」哪个是默认？** 用户说「不能造成割裂」，但没说以哪一侧为准。
   本档按「**主操作有背景、次要操作有边框、图标操作无背景**」设计（选项 A 的映射表）；
   若用户希望**全部**按钮都有背景 + 边框，映射表整体上移一档（`ghost` → `outline`）。
2. **破坏性操作**（删除）：用 `destructive`（红色实心）还是 `ghost` + 危险色文字？现状两种都有
   （`SeriesDetail.tsx:519` 是 outline、`MediaCard.tsx:481` 是裸图标）⇒ 需拍板一种。
3. **豁免范围**：播放器控件层（`VideoPlayer.tsx` 的 8 个控件按钮，白色图标 + `hover:bg-white/15`）
   是否算「统一」的一部分？它处于**深色视频背景**之上，语义与库页面不同 ⇒ 本档**建议豁免**，但需用户确认。

### 复报现象：同一页面里两个「展开/收起」控件外观不同

实测（CDP 驱动真实 Edge，视口 1440×900，真库；剧集内页 `SeriesDetail`，
打开介绍溢出的剧集「Jellyfish · 码率阶梯」，介绍 `scrollHeight=447` > `DESC_CLAMP_PX=64`）。

**该页共只有 2 个 展开/收起 按钮**（对全页 `button` 按文本/aria/testid 过滤后计数 = 2）：

| 项 | A. 剧集介绍旁 `series-desc-toggle`（`SeriesDetail.tsx:549-557`） | B. 选集器头部 `episode-picker-collapse`（`SeriesDetail.tsx:661-668`） |
|---|---|---|
| 默认文本 | **展开** | **收起** |
| 尺寸 | 33 × 20 | 33 × 20 |
| 字号 / 字重 | 10.5px / **400** | 10.5px / **400** |
| padding / radius | 2px 6px / 4px | 2px 6px / 4px |
| **文字色** | `rgb(16, 185, 129)` = **accent 绿** | `rgb(113, 113, 122)` = **muted 灰** |
| **hover 类** | `hover:bg-accent/10` | `hover:bg-surface-2 hover:text-fg-mid` |
| **所在容器方向** | `flex shrink-0 flex-col items-start gap-1`（**竖列**，与「编辑」同列） | `flex items-center gap-2 … font-semibold`（**横排**，与「9 集」「缓存缺失 0 集」同行） |
| 父容器字重 | 400（无继承压力） | **600**（头部行 `font-semibold`）⇒ 靠**显式 `font-normal` 纠回** |
| 位置（实测 rect） | x 694–727, y 472（介绍段顶） | x 710–743, y 641（选集器头部行） |
| i18n 键 | `media.series.descShowMore` / `…ShowLess` | `media.episode.expand` / `…collapse` |
| 点击效果（实测） | 介绍块 `h 64 → 447`（`maxHeight 64px→none`、`overflow hidden→visible`） | 选集器 `h 285 → 0` |

⇒ **几何与排版完全一致（33×20 / 10.5px / 400 / 2px 6px / 4px），差的是颜色与默认文案** ——
与用户「**稍微**不一样」的描述吻合。

### 本实例相对 §现象 2 的两条**新轴**

1. **同文件、同页面**（§现象 2 的实测对照全部是「跨文件」或「同文件不同区域」；
   本条是**同一张卡片内**两个对等控件分叉）。
   ⇒ 说明「没有规则」的后果比原档估计更重：**连一个组件内部的两次书写都会分叉**。
2. **文案键也分叉**：两处中文都是「展开/收起」，却来自**两套键**
   （`media.series.descShowMore/Less` vs `media.episode.expand/collapse`）。
   中文下看不出，**英文下直接暴露** —— `en-US.json` 实测：
   `"Show more" / "Show less"` vs `"Expand" / "Collapse"`。
   ⇒ 同一语义在同一语言下出现两种英文表述，属本档「同一语义」判据的**新增落点**。
