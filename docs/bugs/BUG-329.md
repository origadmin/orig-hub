# BUG-329: TG 监控增强——频道未读条数 + 文字筛选（每条规则 = 一条虚拟监控）

- 状态: fixed
- 发现日期: 2026-10-19
- 模块: engine+shell
- 严重程度: mid

## 现象（用户原话）

> 「TG 监控 功能需要加强. 1. 监控频道更新数据条显示.
> 2. 文字筛选过滤功能支持(从数据中过滤出对应的符合文字条件的内容,用于入库筛选.)」

改造前的实测状态：

- `GET /api/tg/monitor/channels` 只返回 `{channelId, title, username, addedAt}` ——
  **一个条数都没有**。用户看不出「哪个频道有新东西」。
- 筛选只有 `GET /api/tg/monitor/search?q=`：单一全局关键词，命中后**只能看不能选**，
  没有「勾选 → 入库」的通路。

## 四项口径（AskUserQuestion 确认，2026-10-19）

| 问题 | 用户裁定 |
| --- | --- |
| 条数口径 | 「显示**自上次点开以来新增**条数」 |
| 筛选方式 | 「**多次作为多条**,不是单一过滤. 一条相当于一条监控.」 |
| 结果用途 | 「筛出列表 + **手动勾选**入库」 |
| 匹配字段 | 「标题/说明 + 文件名」 |

第 2 条是本轮最容易做歪的一条：它不是「在同一个频道里叠加多个关键词的 AND/OR」，
而是**每条规则各成一个并列条目**（= 一条虚拟监控频道），各自算命中、各自成列表。

## 实现

### 后端（`download-engine/crates/orig-tg`）

1. **已读游标**：`monitored_channel` 新增 `last_read_message_id`（幂等迁移
   `migrate_monitored_channel_last_read`）。存量语义 = **现有库里的消息一律视为已读**
   （`= MAX(message_id)`）——否则升级后第一眼就是「438 条新内容」，那不是「自上次点开
   以来」而是「自开天辟地以来」。
   `newCount` 由 `message_id > last_read_message_id` 现算（`list_channels`/`get_channel`），
   不另存计数列（存了就会和真实行漂移）。
2. **点开 = 已读**：`POST /api/tg/monitor/channels/:id/read` → `mark_channel_read`，
   游标推 `MAX(..., last_read_message_id)`（**只进不退**：消息被清理后 `MAX()` 会变小，
   直接赋值等于把已读的旧消息重新变成未读）。
3. **筛选规则表** `monitor_filter(id, label, keyword, created_at)` + 四个端点：
   `GET/POST /api/tg/monitor/filters`、`DELETE /api/tg/monitor/filters/:id`、
   `GET /api/tg/monitor/filters/:id/messages`。
   匹配 `caption LIKE %kw%` **OR** `file_name LIKE %kw%`，JOIN `monitored_channel`
   限定在监控范围内，带出 `channelTitle` 与 `fileName`。
4. 关键词里的 `%`/`_` 按字面匹配（`like_pattern` 转义）；同关键词幂等（重复添加只更新显示名）。

### 前端（`tauri-shell`）

- 监控行右侧新增未读徽标 `+N`（`tg-monitor-new-badge`），`newCount === 0` **不渲染**
  ——一排「+0」既占位又暗示有新内容。点行即 `openMonitored`：本地先乐观归零，
  再 `POST .../read` 落账（失败静默，下次拉列表回到服务端真值，不产生「本地假归零」）。
- 左栏新增「文字筛选」区块：每条规则 = 一个并列条目（名字 + 关键词 + 命中数 + 删除），
  下方一个输入框即加新规则（显示名缺省同关键词，少一层表单）。
- 点规则 → 第二列切到 `TgFilterPanel`（`components/TgFilterPanel.tsx`）：
  命中列表（标题兜底 caption 首行 → 文件名 → `#消息号`）+ 勾选 + 批量入库。
  - **入库按相册（group_id）分组（2026-10-21 裁定①）**：同一频道里的多相册各自成一条
    缓存任务（带 `groupId`），不再按 `chatId` 把所有命中拍平成一条。无 `group_id` 的单条
    自成一组。`POST /api/tg/cache/tasks` 一次只接受一个 `chatId`，跨频道仍拆开。
    `filter_messages` 现回写 `group_id`（`MonitorFilterHit.group_id`），前端据此分组。
  - **图片永远不进「剧集」媒体库（2026-10-21 裁定② 修订，核心硬规则）**：图片与视频一样
    **可勾选、可入缓存下载**，但由**后端** `file_items_into_series` 的 kind 预切（只收
    video）保证图片永不占集号——它只作为库内内容（`cat:image` 图片库）或混编视频集的
    **图片位**（`media_episode_image`）存在，绝不成为 `media_episode` 分集。前端**不再**
    在筛选面板禁用照片：早期把照片整行 `disabled` 造成「第一张是图片仿佛整个列表无法入库」
    的假象，已剔除。「图片不入剧集」是**后端数据层不变量**（kind 预切 + `trg_media_episode_video_only`
    触发器 + 启动修复三重挡），不是面板层禁用。
- 默认**全选「缺字节」条目（含图片）**：沿用 BUG-327 的裁定（选中的 = 要下载的，用户只做
  减法）。「手动勾选」指提交动作由用户触发，不是初始零选中——零选中配灰按钮正是上一轮被
  投诉的形态。已缓存条目复选框 disabled（勾了也只会被 `alreadyIngested` 拦下）。

## 过程中踩到的两个假判据（记录以免重犯）

1. **`--with-new-channel` 造不出样本**：`add_channel` 会把游标初始化到该频道当前
   `MAX(message_id)`，所以「库里有存量行的频道」加进来就是全已读；再叠加
   `monitor/sync` 是**单飞**的（daemon 的 30s tick 可能正占名额，返回 `started:false`
   却什么都没做），第一版样本恒为 0。修法：只挑 `/api/tg/stored` 里没出现过的频道
   （= 无存量行），且同步**重试到 `started:true`** 为止。
2. **`[data-verify-target]` 残留**：`document.querySelector` 取全文档第一个匹配，
   上一段用例没清标记 ⇒ B6 点回了 B4 的规则行，「点不动」被误读成「半选不可见」。
   现每段用例先 `removeAttribute` 再标记。

## 已知边界（未做，等裁定）

- `GET /api/tg/monitor/search?q=`（既有全局搜索）仍只匹配 `caption`，**不含 `file_name`**。
  本轮只让**新筛选功能**匹配双字段；改既有搜索属未点名的行为变更，按「只报告不擅动」未改。
- 筛选命中上限 200 条（`TgFilterPanel` 默认 `limit=200`，后端 clamp 500），无分页游标。
- 默认全选在命中量大时（实测 750 条 → 展示 200）会让「入库选中（200）」一次入队 200 条。
  按钮文案带确切数量、不会静默，但若更希望「默认不选」需另行裁定（一行改动）。

## 验收副作用（如实记录）

`--with-new-channel` 造正向样本时会临时监控一个真实频道并跑一轮同步，验完**自动取消监控**
（`monitored_channel` 行与 `sync_cursor` 行都删掉）。但同步写入的 ~100 条 `media_message`
**元数据行**留在库里（无字节、无 `media_item` 行）——`remove_channel` 的既有语义就是
「保留已入库消息」。这些行不参与筛选（`filter_messages` JOIN `monitored_channel` 限定范围）、
也不出现在 `/api/tg/stored`（实测该端点只回监控中的频道），故对用户不可见。
默认（不加该 flag）运行不产生任何副作用。

## 关联

- BUG-327：同一条「选中的 = 要下载的」选择语义来源；本轮的默认全选与 `indeterminate`
  处理直接沿用其判据。
- BUG-220：`file_name` 列的由来——大量视频消息没有 caption、只有文件名；筛选匹配文件名
  与命中行标题兜底都依赖它。
- BUG-049：原「图片不缓存、只登记为浏览条目」规则终结。图片**可下载入缓存「图片库」**，
  但**永远不进「剧集」媒体库**——后端 `file_items_into_series` kind 预切只收 video +
  `trg_media_episode_video_only` 触发器 + 启动修复三重保证；前端打开图片入口
  （`useGoLibrary` / `MediaLibraryPanel.toViewerItem`）对非 video 一律 `seriesId=null`，
  旧照片分集数据也不会被当剧集打开。门禁反向证伪的「照片行应 disabled」FAIL 证明该判据有牙。
- BUG-102：`monitor/sync` 单飞；门禁造样本时必须重试到 `started:true`。
