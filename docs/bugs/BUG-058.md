# BUG-058: 导航标签不保证单行 —— 计 0 未省略、长名未截断、计数无界

- 状态: in_progress
- 发现日期: 2026-09-19
- 模块: shell
- 严重程度: low

## 现象

媒体库左侧导航有两个「标签」族，两者都不保证一行显示：

1. **分类行**（全部 / 视频 / 图片 / 音频，`MediaLibraryPanel.tsx`）：名称已有
   `min-w-0 flex-1 truncate`，但右侧计数 `<span className="shrink-0 text-[10px] text-muted">{count}</span>`
   **无宽度约束**，计数到 5 位以上会把名称挤成省略号之外的空壳；
2. **标签 chip 行**（`MediaLibraryPanel.tsx` 的 `tags.map`）：chip 是
   `rounded-full border px-2 py-0.5 text-[10.5px]`，内部 `{tag.name}` + `<span className="ml-1 opacity-70">{count}</span>`
   —— **既无 `truncate` 也无 `max-w` 也无 `whitespace-nowrap`**。标签名一长，chip 宽度跟着涨，
   在 `flex flex-wrap gap-1` 容器里被压到换行，变成「chip 内部两行」；
3. 计数为 **0 的标签照常渲染计数**，与「省略 0 标签」的既定约定不符。

同类问题在主导航 `tauri-shell/src/components/Sidebar.tsx` 也存在：标签 span 是
`className="flex-1 text-left"`，**没有 `truncate`/`min-w-0`**，长文案下会与计数徽标挤在一行外。

## 根因

「导航行必须单行」这条约束没有被任何一处代码表达：允许收缩（`min-w-0`）与允许截断
（`truncate`）是两件事，标签族只做了前者（甚至没做），且计数没有 `tabular-nums` + 宽度上限。
计数的显隐由 `count > 0` 决定的地方（Sidebar）与无条件渲染的地方（chip）**规则也不统一**。

## 复现

1. 建一个名字极长的标签（例如 40 个半角字符）并挂到若干条内容上；
2. 打开媒体库：左侧 chip 换行、撑高 rail 行；
3. 把某标签的关联内容全部删除，使其计数为 0：chip 上仍显示 `0`；
4. 计数增长到 5 位数（可用脚本批量挂钩造数）：分类行名称被挤没。

## 修复

待实施。方案见 `docs/design/ROUND9-DESIGN-EVAL.md` 第 3 节：统一「导航行单行原语」——
`min-w-0` + `truncate`（名称）+ `shrink-0 tabular-nums`（计数）+ 计数为 0 时**不渲染**
（与 Sidebar 现有规则对齐）；chip 加 `max-w-[...]` 与 `truncate`，`title` 保留全名。
验收必须覆盖**最小值（0、空名、1 字符）与最大值（长名 + 5 位计数）**两端。

## 验收证据

未修复，暂无。修复后必须提供：Playwright 造数后逐行测量
`scrollWidth <= clientWidth`（单行）、`offsetHeight == 单行高度`，
并用截图留存最小/最大两组形态。
