# BUG-186 剧集合并入口仅存在于剧集内页：媒体库剧集墙无法多选剧集进行合并

- **状态**: open
- **发现日期**: 2026-09-29
- **模块**: shell
- **严重程度**: mid

关联 BUG-037（合并功能来源）、BUG-153 / BUG-155（items 视图选择模型）、BUG-149（重构不是删能力的授权）。

## 现象

用户要合并两条剧集时，必须：**先打开其中一条剧集的内页** → 点总览卡上的「合并」按钮 →
在弹出的对话框里用下拉框选「被并入的另一条」。

而**媒体库剧集列表页（剧集墙）完全没有多选**，无法「选中 A + 选中 B → 合并」。

用户原话：「媒体库页面，应该支持多个剧集选择点击合并，然后进行剧集合并（当前在播放详情页），
这里合理性和逻辑上感觉有严重问题。」

> 位置澄清：用户说的「播放详情页」实际是**剧集内页**（`view === 'seriesDetail'`，即媒体库中
> 点开某条剧集后的详情面板），不是视频播放器。合并没有挂在播放器上。

### 逻辑不合理的三点（本档的核心）

1. **操作层级与入口位置错位**：合并是**剧集（series）级**的对等操作，
   入口却挂在 series 的**内页**——必须先进入一条，才能操作它的同级实体。
2. **方向由「你先打开了谁」隐含决定**：`target` 硬编码为当前剧集（`SeriesDialog.tsx:231`），
   用户无法直接表达「A 与 B 合并，保留 B」；要换方向就得退出、打开另一条、再来一次。
3. **不可逆操作却以轻量形态承载**：合并**删除源剧集**（`media.rs:2451-2461`），
   却只靠一个下拉框 + 两步按钮完成，且删除后果在对话框文案中未显著提示。

## 修复

方向（**具体交互形态需设计**，本档只给判据边界）：

1. **媒体库剧集墙支持多选剧集**：复用 items 视图已有的选择模型（`MediaLibraryPanel.tsx:155` 的
   `selected` 模式可参照），或另立剧集选择集；选中 **≥2** 条时出现「合并」动作。
2. **合并方向必须显式**：确认界面要能表达「保留哪条 / 并入哪条」——
   因为源会被删除（`media.rs:2451-2461`），方向不可由「打开顺序」隐含决定。
3. **不可逆后果要在确认界面可见**：删源是硬删除，确认文案需让用户明确知道
   「哪一条会被删除、其分集将被搬走」。
4. **内页入口的去留**：保留或移除均可，但**不得**在没有新入口的情况下直接撤掉旧入口
   （BUG-149：重构不是删能力的授权）。

> 注意：本修复是**新增可达路径**，不是简单搬迁。剧集墙多选 + 合并方向选择 + 删除后果提示
> 三者需一起设计，否则会把「位置不合理」换成「操作更危险」。
