# BUG-258: 剧集「类型」的选择在每次启动后被静默改回「剧集」（3 个选项里 2 个实际不可达）；「年份」全库为空且一旦填入就无法清空；内容编辑弹窗里的同名「类型」是只读且未本地化的原始枚举

- 状态: open
- 发现日期: 2026-10-10
- 模块: engine+shell
- 严重程度: high

> 来源：用户报告「媒体库->内容->编辑: 类型,年份的选项和作用,其中一个是空的。」

## 现象

### 现象 1：类型有 3 个选项，但改动会被系统悄悄撤销

编辑面板 `tauri-shell/src/components/media/SeriesEditPanel.tsx:10` 把
`KINDS = ['series','collection','album']` 硬编码成 3 个下拉选项，文案取自
`media.series.kindSeries / kindCollection / kindAlbum` = 「剧集 / 合集 / 图集」
（`tauri-shell/src/i18n/locales/zh-CN.json:544-546`）。保存走
`patchSeries(id, {title, description, kind, ...})`（`SeriesEditPanel.tsx:76-82`），
后端 `update_series` 原样写入 `media_series.kind`（`download-engine/crates/orig-tg/src/media.rs:2251`）。

**但每次启动，`migrate()` 都会把「有分集、且分集全是 video/photo」的剧集强制改回 `'series'`。**

实测（2026-10-10，全程在**只读副本**上做，未碰真库）：

| 步骤 | 结果 |
|---|---|
| 真库 `media_series.kind` 分布 | `series` **45 条（全部）** |
| 取一个有 14 个分集的剧集，模拟用户保存 `kind='album'` | `album` ✅ 写入成功 |
| 执行 `media.rs:486-495` 那条 UPDATE | **受影响 1 行** |
| 回读该剧集 | `series` ❌ 被打回 |
| 负控：新建一个 **0 分集**的剧集 `kind='album'` | 不受影响，保持 `album` |

⇒ **用户在界面上把剧集改成「合集」或「图集」，当场保存成功，重启后变回「剧集」，没有任何提示。**
这也解释了真库 45/45 全是 `series` 的观测。

### 现象 2：年份全库为空，且一旦填上就再也清不掉

真库实测：`media_series` 45 行，`year` **45/45 为 NULL** —— 界面上这个输入框一直是空的。

这是用户所说「其中一个是空的」的直接来源：**类型有 3 个可选项，年份没有任何值。**

而更麻烦的是它**单向**（只能设、不能清）。链路两端各缺一环：

- **前端** `SeriesEditPanel.tsx:64-73`：年份留空 ⇒ `yearValue` 保持 `undefined` ⇒
  `:81` 的展开 `...(yearValue !== undefined ? { year: yearValue } : {})` **根本不发这个键**。
- **后端** `SeriesPatch.year: Option<i64>`（`media.rs:3922`）⇒ 收到 `None` 就是「不改」，
  `update_series` 用 `patch.year.or(s.year)`（`media.rs:2256`）**保留旧值**。

⇒ 「空」与「不改」在契约上无法区分，**年份只能设、不能清**。

**对照**：同结构的 `description`（`media.rs:3916-3917`）与 `poster`（`:3920-3921`）都用了
`Option<Option<String>>` + `nullable` 反序列化来区分「清空」与「不改」——
**`year` 是这三个可空字段里唯一漏掉该契约的**。

### 现象 3（旁支）：内容编辑弹窗里的同名「类型」是只读的原始枚举，且没有年份

「媒体库 → 内容 → 编辑」打开的是 `ItemEditDialog.tsx`，其中：

- `:125` `<p className="truncate">类型：{item.kind}</p>` —— **只读文本**、
  **硬编码中文标签**、且直接渲染后端原始枚举（`video` / `photo` / `audio` / `file`），
  **没有走 i18n**。同仓已有 `media.kindVideo / kindPhoto / kindAudio / kindFile`
  （`zh-CN.json:412-415`）四个中文键，此处用的是原文。
- 该弹窗**没有「年份」**（`media_item` 表本身无 year 列，`media.rs:224-238`）。

⇒ 同一个词「类型」在两个编辑面里行为不同：剧集面板**可改**（下拉）、内容弹窗**只读**（文本）；
一个面有年份、另一个面没有。用户说「其中一个是空的」，无论他指的是哪个面，都有实测可查的问题。

## 根因

### 根因 1：`migrate()` 的 kind 回填条件在 BUG-044 放宽分集范围之后**恒真**

`media.rs:486-495`：

```sql
UPDATE media_series SET kind = 'series'
  WHERE kind IS NOT 'series'
    AND EXISTS (SELECT 1 FROM media_episode e WHERE e.series_id = media_series.id)
    AND NOT EXISTS (
        SELECT 1 FROM media_episode e JOIN media_item i ON i.id = e.item_id
         WHERE e.series_id = media_series.id AND i.kind NOT IN ('video','photo'))
```

它的原意是「kind 必须反映实际构成」（注释 `:484-485`，BUG-044 残留）。
但**同一份 `migrate()`** 在 `:526-541` 建了触发器，**只允许 `video|photo` 成为分集**。
于是第二个 `NOT EXISTS` 子句对任何**有分集**的剧集**恒为真** ⇒ 这条语句的实际语义退化成：

> **任何有分集的剧集，每次启动都会被强制改成 `'series'`。**

它不再是「纠正错误徽标」，而是「**抹掉用户的选择**」。`migrate()` 在
`download-engine/crates/orig-tg/src/store.rs:362`（`Store::open`）**无条件调用** ⇒ 每次启动都会跑。

> 换个说法：**「类型」这个字段当前只有「剧集」一个可达值** —— 只要剧集有分集；
> 而「所有缓存内容都进剧集」是既有产品裁定（`media.rs:496-499`）。
> 实测 45/45 全是 `series`，与这个推论完全一致。

### 根因 2：年份缺少「可清空」契约

见现象 2。`SeriesPatch.year` 是该结构里唯一没有 `nullable` 处理的可空字段。

### 根因 3：内容侧「类型」是展示，不是编辑

`ItemEditDialog` 的设计里 `kind` 属「条目固有属性」（由落盘分类决定，见
`media.rs:1278-1292` `set_item_bytes` 会按扩展名校正 kind），因此没有做成可改控件。
问题不在「只读」，而在**它既没本地化、也没说明「不可改」** —— 用户看到的是一个与剧集面板
同名的字段，行为却完全不同。

## 修复方向（未实施）

1. **修 migrate 的条件**（根因 1，须最先做）：把「纠正历史脏徽标」与「抹掉用户选择」分开。
   最小改法是把这条 UPDATE 的适用范围收回到它本来的目标 —— 只处理 **BUG-044 之前**由旧自动成剧
   写入的混编 `collection/album` 脏数据，例如加时间戳条件，或改成**一次性迁移**
   （用 `app_setting` 记 flag，跑过就不再跑）。
   **不建议直接删掉这条语句**：它确实修过真实的脏徽标（`media.rs:484-485` 有据）。
2. **给年份补 `nullable` 契约**（根因 2）：`SeriesPatch.year` 改 `Option<Option<i64>>` +
   `#[serde(default, deserialize_with = "nullable")]`，`update_series` 改三态 `match`；
   前端在「原本有值、现在被清空」时显式发 `year: null`
   （`tauri-shell/src/api/media.ts:435` 的类型也要一并放开）。
3. **内容侧「类型」本地化 + 标注不可改**（根因 3）：`ItemEditDialog.tsx:125` 改走
   `media.kindVideo/Photo/Audio/File`；若「不可改」是设计，就把这一点写在标签上
   （如「类型（自动识别，不可改）」）。这与 BUG-148 同源：**能力边界要在用户正因此受阻时出现**，
   而不是留一个看起来能改、实际只读的同名字段。
4. **若「合集/图集」本来就不该存在**：正确做法是**从编辑面板撤下这两个选项**，
   并把「剧集只有一种类型」写成文档层裁定，而不是留 3 个选项让其中 2 个静默失效。
   撤入口必须走 BUG-149 的流程（先查是否来自已验收需求）。

## 修复后必须满足（可证伪判据，预先声明）

1. 把某剧集类型改成「合集」→ **重启服务** → 该剧集类型**仍是「合集」**。
   **反向证伪**：把 `media.rs:486-495` 那条 UPDATE 恢复成现状，判据 1 必须重新 FAIL。
2. **0 分集**的剧集类型在重启后同样保持不变（负控；与现状一致，用于防止「一刀切删掉整条迁移」）。
3. 年份：给某剧集设年份 → 保存 → 清空 → 保存 → 重新读该剧集，`year` 为 `NULL`。
   **反向证伪**：把 `SeriesPatch.year` 改回 `Option<i64>`，判据 3 必须 FAIL。
4. 年份留空且原本就为空时，保存**不得**把已有年份写坏（「不改」语义仍须可用）。
5. 「内容 → 编辑」弹窗里的类型文案为中文（不出现裸 `video`/`photo`/`file`）；
   若不可改，文案或 `title` 必须说明它不可改。
6. 判据 1 / 3 / 5 必须在**真实 UI 上验**，不得只看接口返回（BUG-156：判据要打在真实调用链上）。

## 关联

- **BUG-044**：把分集放宽到 `video|photo` 的那次改动 —— 根因 1 里那条 UPDATE 就是它的残留。本档不推翻它。
- **BUG-148**：实现约束 ≠ 产品信息 —— 根因 3 的处置依据。
- **BUG-149**：撤入口/能力前必须查是否来自已验收需求并走缺陷档案 —— 修复方向 4 的约束。
- **BUG-191**：文案与行为分叉（按钮写「查看」，行为是「编辑」）—— 与现象 3 的「同名字段两种行为」同源。
- **BUG-024 / BUG-077**：可空字段与「不改」语义的既有先例。

## 待确认（口径）

1. **用户指的是哪个「编辑」界面？** 本档把两个面都登记了：剧集编辑面板（`data-testid="series-edit"`
   → `SeriesEditPanel`，**唯一同时有类型 + 年份的地方**）与内容编辑弹窗（`data-testid="item-edit-dialog"`
   → `ItemEditDialog`，只有类型且只读）。「其中一个是空的」在剧集面板上精确对应
   「**年份 45/45 为空**」；若用户指的是内容弹窗，那「空的那个」是**缺失的年份字段**。
   请确认是哪一个（或两个都要修）。
2. **「合集 / 图集」这两个类型还需要吗？** 若需要 → 必须修 migrate（修复方向 1）；
   若不需要 → 应从编辑面板撤下这两个选项，并把「剧集只有一种类型」写成裁定（修复方向 4）。
   这是**产品决策**，不是工程实现细节。
3. **年份要不要可清空？** 若「填错了就永远改不掉」可以接受，则可不做修复方向 2；
   但需在文档层说明理由（同 BUG-257 待确认 3 的处理方式）。
