# BUG-431: 回溯进度块三处硬伤——取消按钮裸出键名、状态自相矛盾、进度不可见

- 状态: fixed
- 发现日期: 2026-10-26
- 模块: shell
- 严重程度: high

## 现象

用户 2026-10-26 截图复报（原话）：

> 数据回溯展示问题：文字有严重问题，进度也不可见。

截图里那一行（TG → 监控中 → 某频道行下方）同时有三处硬伤：

1. **原始键名直出**：取消按钮渲染成 `tg.backfillCancel`，不是中文。
2. **标题被截断**：「回溯中（至 2026-01-01…」——目标日期被省略号吃掉。
3. **状态自相矛盾**：标题说「回溯中」，副行却说「回溯尚未开始 · 最新 #9719」。
   而且「#9719」是消息号，对用户没有日历意义，等于没有进度。

## 根因

三处各有独立成因，**没有任何一处会报错**，所以长期没人发现：

1. `tg.backfillCancel` 只在 `en-US.json` 里定义，`zh-CN.json` 漏了。i18n 缺键的
   默认行为就是**回退成键名**（不抛错、TS 不报、测试不红）⇒ 中文界面裸奔。
   仓库里当时**没有任何键对齐闸门**，这类缺陷只能靠肉眼撞见。
2. 标题用 `t('tg.backfillRunning', {date})`，模板本身带「（至 {date}）」，
   外层是 `block truncate` + `min-w-0 flex-1`。频道列只有约 200px，右侧还要
   放一颗按钮 ⇒ 日期必然被 `text-overflow: ellipsis` 吃掉。
3. `backfillBeforeId === 0` 被译成「回溯尚未开始」，但它的真实含义是
   「第一页还没翻完、游标未建立」——回溯**已经开始了**。而「进度」原来只输出
   两个消息号（`#游标` / `#最新`），用户既不知道回溯到哪一天，也不知道还剩多少。

## 修复

`tauri-shell/src/components/TgPanel.tsx`（回溯进度块整段重写）：

- 标题只留「回溯中」（`tg.backfillRunningTitle`，短文案，窄栏不截断）；
- 日期与进度改为 `flex-wrap` 的多段并排 —— **宁可换行，也不许把日期截成
  「2026-01-01…」**；
- 进度改用**日期轴**表达：`oldestMessageDate` 是库内最老已入库日期，回溯每翻
  一页它就往旧走 ⇒「至 2026-01-01 · 已回溯至 2026-07-06 · 还差 187 天」是单调、
  可与 API 逐字核对的真进度；
- `backfillBeforeId === 0` 的文案改为「正在定位起点…」（`tg.backfillLocating`），
  消除「回溯中 × 尚未开始」的矛盾；
- 保留 BUG-382 的「最新 #N」边界，但降为最次一级（消息号对用户没有日历意义）；
- 新增满宽脉冲条 `tg-monitor-backfill-bar`，只表达「还在跑」，**不谎报百分比**。

**刻意不做百分比**：分母是「本次回溯起点」，后端 `sync_cursor` 只存了目标日期与
游标、没存起点；拿 `now` 或最新消息日去凑分母会在点击瞬间就报出 50%，比不显示
更误导。要真百分比必须先加一列 `backfill_start_date`，属后端改动，不在本号范围。

配套（防复发）：

- `scripts/check-i18n-keys.py` 新增键对齐闸门 —— 以**全集**为基准（不是选一个
  「参考语言」，否则参考语言自己缺键时另一侧只算「多余键」而放过，正是本号的
  形状），缺键 / 占位符漂移 / 空值三条都判红。`media.organize.varsHint` 是唯一
  豁免（花括号是给用户看的模板语法，`organize.rs:173-197` 中英文变量名都收）。
- i18n 两个语言包补齐 5 个新键（`backfillRunningTitle` / `backfillCancel` /
  `backfillTarget` / `backfillReachedDate` / `backfillLocating` / `backfillRemaining`）。

## 复现

修复前：TG → 监控中 → 任一 `backfillUntil > 0` 的频道行下方，可直接看到
`tg.backfillCancel` 裸键、「回溯中（至 …」截断、以及「回溯尚未开始」的矛盾文案。
