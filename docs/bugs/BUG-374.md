  - 「这么明确的标题问题,都框出来了,还没改好」

## 根因

下载域两个详情 Sheet 各持有一份**手写复制**的外壳（`fixed inset-0 … rounded-t-2xl border bg-surface shadow-2xl`），`components/ui/` 无共用 Sheet 组件。两份抄完之后各改各的，于是漂移成用户看见的样子：

| | 引擎 `DownloadDetailSheet` | 入库 `IngestDetailSheet` |
|---|---|---|
| 顶部强调线 | **有**（网卡配色渐变） | **无** |
| 抓手 `⠿` | 内嵌在标题行、排在标题**前面**（还带 `title="拖拽"`） | **单独占一行**，把标题挤到第二行 |

两种压法都让「标题不是第一行」——BUG-372 只摘了「TG 入库」徽标，抓手还在，所以用户第四次提时仍然复现。

## 过程错误（必须先记）

第一版修复我做了**远超授权**的改动：给入库 Sheet **加上**顶框（用户问「为什么有的有、有的没有」，正确取向是去掉丑陋的那个，不是给另一边加）、整体移除抓手、把关闭按钮从 33×28 放大到 36×36、新增 `components/ui/bottom-sheet.tsx` 共用外壳并重构两个 Sheet。用户当即纠正：「为什么要加丑陋的顶框,为什么样式大改? 改问题就改问题,问题外的为什么胡乱全改了?」

已整体回退（`git checkout` 两个文件 + 删除新组件，回退前备份到 `/tmp/bug374_backup/`），重做为**最小 diff**。教训与 BUG-372「未经确认删样板数据」同源：**用户报的范围就是授权的范围；「统一」不等于「我选一种形态推广到全部」**。未点名的同域残留（此处 = 两份手写外壳的重复本身）按 BUG-324 纪律**只报告不擅动**。

## 修法（最小 diff，只碰用户报的两件事）

1. **顶框**：删掉引擎 Sheet 的渐变强调线 —— 用户直言其丑陋 ⇒ 统一取向「两边都没有」。
2. **标题归位**：删掉两个 Sheet 的抓手 `⠿`（它压在标题前或占一行在标题上；且 `title="拖拽"` 是 Sheet 做不到的承诺）。入库 Sheet 标题行 `pb-2` → `py-3`：抓手行删掉后标题行需要上边距，取值与引擎侧表头一致。
3. **一律未动**：关闭按钮尺寸、`aria-label`、Esc 处理、遮罩、业务逻辑、其余样式。

## 未擅动（只报告）

- **两份手写外壳的重复本身**（本次缺陷的根因）仍在：下次再改外壳仍会漏一边。要根治需抽共用组件，属架构改动，**未经用户点名不做**。
- `AddDownloadDialog`（新建下载，居中弹窗）无顶框、标题已是第一个子元素（BUG-371 统一过）—— 与这两个底部 Sheet 形态不同类，未动。
