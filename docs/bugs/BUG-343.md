# BUG-343: `/api/activity` 无谓轮询——请求不停、数据不更新、语义不清

- 状态: fixed
- 发现日期: 2026-10-20
- 模块: engine+shell
- 严重程度: high

## 验收证据

- 探针 `tauri-shell/verify/_probe_bug343_polling.cjs`：D1 休眠（活库正躺
  interrupted 任务=用户报障同款状态，20s 零请求）、D2 退避档位（不可用窗口
  3s→15s→30s）、D3 自动回血（不靠用户动作的下一档拉取即恢复 + 恢复后再休眠）；
- 2026-10-20 重部署后实测 **ALL PASS（7 项）**：D1 `first=1 after20s=1`
  （零请求）、D2a `gap1=3213ms`、D2b `gap2=15107ms`、D2c `gap3=30205ms`、
  D2d 退避期间每次拉取都带不可用语义（banner 数据源，n=4）、D3/D3b 恢复后
  不靠用户动作回血且回血后再休眠；
- 前端单测级验证：退避分支在「有活」口径修正前是**死代码**（`hasWork` 混入
  `sourceUnknown` 使 `!active && sourceUnknown` 永假）——探针 D2 的档位断言
  守这个修正，装回旧实现必败。

## 现象（用户原话，2026-10-20）

> 「api/activity请求逻辑有问题,一直在请求,完全不清楚到底在干什么,
> 核心是所有数据完全没有更新! 更不需要调用任何接口. 当前频繁导致的问题是什么原因?」

## 根因

轮询三律（有活才轮 / 等值短路 / 卸载即停）与在场门控都在，但**「来源不可用」
例外把轮询变成永续**，而不可用窗口内数据冻结——「请求不停 + 数据不动」同时成立：

1. `useIngestGroups.ts:203-207` 3s 定周期；`:222-225`
   `hasWork = 有活(在传/停滞) || sourceUnknown`；
2. orig-tg 不可用（监督重启实测约每 10-15 分钟一次，见项目记忆）⇒ `pull` 早退
   （`:174-180`）：**不清空行、不更新 tasks**，只置 `unavailable`，且
   `sourceUnknown = true` ⇒ 轮询停不下来；
3. **活数据实证**（2026-10-20 22:5x 探针）：`/api/activity` 正返回
   `status:"interrupted"` + `error:"应用重启：传输被中断，可重试继续"` 的任务行——
   orig-tg 刚重启过，当前正处「行冻结 + 续轮」窗口；
4. 每次 `/api/activity`，daemon 都全量 HTTP 读 orig-tg
   `/api/tg/cache/tasks/all`（`activity.rs:443-470`）⇒ 前端 3s 一轮 =
   daemon→orig-tg 3s 一次全量读取；orig-tg 不在时这批请求全部失败重试；
5. **「数据完全没有更新」的机制**：不可用窗口内行是**断开前快照**（BUG-318 设计
   使然），而 TG 域上下文栏的入库小计数（`MainLayout.tsx:283-284`）**不读**
   `unavailable` ⇒ 计数冻结且无任何解释——用户看到的就是「一直在请求、
   数字永远不动」；
6. **「不需要调用任何接口」的冲突点**：轮询门控含 TG 域是 2026-10-17 入口终裁
   （上下文栏「入库流水线」小计数在 TG 域渲染）；若该入口撤/改，门控应收回——
   与既有裁定冲突，需拍板（见修复 3）。

## 复现

1. orig-tg 重启（或杀掉）期间停留在 TG/下载域；
2. 网络面板可见 `/api/activity` 每 3s 一次不间断；入库行/计数停在断开前快照；
3. 现行设计靠永续轮询兜「恢复后回血」（BUG-318），代价就是用户看到的
   「一直在请求」——恢复回血与请求风暴是同一枚硬币的两面。

## 修复（已实施）

1. **轮询改三闸**：在场 + 有活 + （来源可用 **或** 退避中）；来源不可用 ⇒
   退避轮询（3s → 15s → 30s 封顶；恢复后立即回快节奏）——保住 BUG-318 的
   自动回血，去掉 3s 死磕；
2. **「无活」判定收紧为只在传（queued/running）**：停滞（failed/interrupted）
   任务永远不会自己变好（orig-tg 重启只把残留 running 降级成 interrupted 且
   不自动重跑，见 main.rs stale 降级 + RETRYABLE_STATES 只响应显式 retry）——
   用户报障时的活库状态正是「一条 interrupted 躺在 feed 里 + 3s 死磕」。
   显示不变（行照常摊在概览），只是不轮。等值短路 / 卸载即停 / 在场门控不变；
3. **「更不需要调用任何接口」落地**：无活 + 来源已知 ⇒ **休眠**（一个请求都不发，
   `refresh()` / 切回在场 / 用户动作再拉）——TG 域入口保留（2026-10-17 终裁
   不动），入口在场但无活时零请求。**决策记录**：daemon 侧 TTL 缓存不做
   （单消费者：只有本前端的唯一 hook 在轮，多客户端重复读的假设不成立；
   真有第二个消费者时再议）；
4. **TG 域上下文栏小计数读 `unavailable`**：不可用时明示「暂不可读」，
   不把冻结旧值/零值当正常渲染。
