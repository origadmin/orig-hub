# BUG-176: 媒体库整页依赖 TG 服务进程 —— TG 不可达时库「整页失明」，且界面无法区分「没有内容」与「取不到内容」

- 状态: fixed
- 发现日期: 2026-09-29
- 模块: shell
- 严重程度: high
- 排期: 2026-11-10

## 现象

用户报告：**「媒体库有严重的逻辑问题，我记得数据有的，但在『调试模式：TG 未连接』下数据完全丢失，
不清楚是没有数据，还是根本性错误没有获取正确数据。」**

即：TG 显示未连接时，媒体库变成一片空白（头部统计整行消失、内容计数显示 `—`、
主区只剩「媒体服务未运行 / 重试连接」），**用户无法从界面上判断库里究竟有没有内容**。

## 根因

**媒体库的全部数据端点托管在 `orig-tg` 进程（9877）里**，不在常驻的 `orig-daemon`（9876）。
TG 进程一旦不可达（未启动 / 崩溃 / 端口绑不上），`/api/media/*` 全部连不上 ⇒ 媒体库整页失明。
这与代码自己写下的契约相反：

- `tauri-shell/src/lib/mediaSources.ts:110-112`（探活判据）自述：
  「这里刻意**不碰 TG**：媒体库管的是「入库之后的字节」…TG 挂掉…都不该让媒体库变成空面板」；
- `MediaLibraryPanel.tsx:949-953`（渲染）自述：
  「TG 没起只意味着「暂时不能原路取回字节」…这里写死成整页占位是错的」；
- **但** `getLibraryStats()` 走的 `MEDIA_BASE = TG_BASE`（`api/media.ts:8-11`），判的正是 TG 服务本身。

即：**「资料库 API 应独立于来源服务」只写在注释里，架构上没有兑现**：

| 事实 | 位置 |
|---|---|
| 媒体库 29 个 handler 全在 orig-tg | `download-engine/crates/orig-tg/src/routes.rs:82-157` |
| 媒体库业务逻辑 6576 行全在 orig-tg | `download-engine/crates/orig-tg/src/media.rs` |
| 媒体库表与 TG 表同库（同一 `store.db`） | `media.rs:224-269` + `store.rs:302-328` |
| 前端资料库基址 = TG 基址 | `tauri-shell/src/api/media.ts:8-11` |

**次生缺陷**：面板的「重试连接」按钮走 `ensureLibraryBackend()` → `ensureDaemon()`
（`lib/mediaSources.ts:127-130`），**只拉 daemon，从不拉 orig-tg** —— 所以从媒体库面板点重试，
在这台机器上永远拉不起资料库后端。

## 复现

同一份库（含 6 条条目），只切换资料库后端可达性：

```sh
# A：后端可达
cd download-engine && ORIG_TG_PORT=18777 ORIG_TG_DB=<seed.db> ./target/debug/orig-tg.exe &
cd tauri-shell && TG_BASE=http://127.0.0.1:18777 node verify/verify_media_library_backend_independence.cjs
#   → 3/3 PASS   头部「6 项 · 1.9 GB」、全部内容 6、视频 6

# B：杀掉 orig-tg（库文件不变），再跑同一脚本
#   → 2/4 FAIL   头部统计整行消失、内容计数 null、explicitness=false
```

自动化：`tauri-shell/verify/verify_media_library_backend_independence.cjs`
（后端不可达时，核心断言「界面显式告知『库内容暂不可读取（并非没有内容）』」**必然 FAIL**）。

## 验收证据
「取不到」与「没有」分开表达：整页不再由单一 alive 布尔决定，而是
backend{unknown/up/down} + 原因（`probeLibraryBackendDetail`）：
down 且**无** last-known 才占位，文案显式说明「库内容暂不可读取（并非没有内容）」+ 原因 + 重试；
down 但**有** last-known ⇒ 内容照常渲染 + banner 直出原因；失败一律不清数据；
down 期间退避续轮（3→6→12→24→30s，单一计时器，恢复归零）；用户点重试才请 daemon 重启宿主。

落点 `tauri-shell/src/components/MediaLibraryPanel.tsx`、`tauri-shell/src/lib/mediaSources.ts`。
反向证伪：把 banner 去掉并让失败清空数据，TG 一挂媒体库立刻变成「空库」= 原症状。
