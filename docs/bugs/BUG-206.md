# BUG-206 播放界面把内部 id 当「无标题」兜底显示：消费面不漏内部主键

- 状态: fixed
- 发现日期: 2026-09-30
- 模块: shell
- 严重程度: low

## 现象

用户反馈：「来源编辑显示ID没什么问题,但是播放显示ID是不是过了?」

即：编辑面（SeriesDetail 的来源徽标 `#<itemId>`）显示内部 id 是管理需要，用户认可；
但**播放面**（MediaViewer 播放器 / EpisodeList 分集侧栏）在标题为空时也会把
`#<内部id>` 渲染成可见文案——线上实测 238 个媒体条目里 id=592/511/512/513 等
大量条目 title 为空，播放它们时返回行就显示 `#592`，把 DB 主键漏给了观看者。

## 根因

消费界面有 4 处「无标题」兜底直接用了内部 id：

1. `MediaViewer.tsx` 返回行标题：`title || cur.caption?.trim() || `#${cur.messageId}``
2. `MediaViewer.tsx` 图片缩略带 hover 提示：`it.caption?.trim() || `#${it.messageId}``
3. `MediaViewer.tsx`「即将播放」卡片标题：`nextItem.caption?.trim() || `#${nextItem.messageId}``
4. `EpisodeList.tsx` 无标题视频集：`ep.title || (photo ? … : '') || `#${ep.itemId}``

`messageId` / `itemId` 就是 `media_item.id`（主键）。编辑面显示它是管理定位；
播放面是消费界面，没有任何显示主键的正当性——兜底应该是人可读的中性文案。

## 修复

四处兜底统一换成 i18n 中性文案 `t('player.untitled')`（zh: 未命名 / en: Untitled）：

- 新增 `player.untitled` 键（`zh-CN.json` / `en-US.json`）。
- 内部 id 不进可视文案，但 `data-testid="media-viewer"` 上的 **`data-message-id`
  属性保留**——自动化探针仍按 id 定位，用户不可见（管理与消费的边界落在
  「可见文案 vs DOM 属性」，而不是各写一套）。
- 编辑面 `SeriesDetail` 的来源徽标 `#{cur.itemId}`（用户已认可）不动；
  死代码（EpisodeBoard/EpisodeExpanded）中的同类兜底不在此变更范围。

## 关联

- BUG-203/204：同一批「编辑=管理面 / 播放=消费面」边界梳理；本条把边界延伸到 id 显示。
- AGENTS.md §5「命名不得超出行为」同理：可见文案不得暴露仓储概念。
