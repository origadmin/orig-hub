# BUG-391: 相册封面被等高拉伸破坏；展开宫格应在底部纵向拉伸而非分列左右

- 状态: fixed
- 模块: shell
- 发现日期: 2026-10-23
- 严重程度: mid
- 报告: 用户 2026-10-23 04:07 截图 + 原话「展开应该底部拉伸展示,但是不应该分左右……当前左右展示把第一张图片上下拉伸破坏了」「第一张图片可以不加入下面的展示」。

## 现象

相册气泡（折叠态长 caption / 展开态）左列封面被拉伸到与右列同高（BUG-387 的等高机制），首图纵横比被破坏；展开后的宫格在右列与封面分列左右，用户要的是**向下**展开。

## 根因

BUG-387 把四类块统一成「左列 flex-1 等高 + 右列内容」框架，对相册而言右列是长 caption 或宫格 ⇒ 封面（首图）被 `flex-1 + absolute inset-0 h-full` 拉到行高。等高机制对单条块成立，对「首图是内容本体」的相册是破坏。

## 修法（用户裁定的新形态）

1. 封面不再等高拉伸：左列去掉 `self-stretch/flex-1`，封面图自然比例（`h-auto max-h-72 w-full object-cover`）。
2. 展开宫格移出左右框架，放气泡**底部**全宽纵向拉伸（`open && items.length > 1`）。
3. 首图已作为封面呈现，**不入宫格**（宫格 = `items.slice(1)`；瓦片 testid/preview 索引保持 = items 下标）。

## 探针工程注记

展开会触发 feed 重渲染 + 轮询换页（DOM 相册集合会变），探针读数必须**按封面 data-message-id 作用域**定位被点击的相册，且 `page.evaluate(fn, arg)` 必须显式传参——作用域参数漏传时会静默回落「DOM 第一个相册」，把别的相册的几何读进来（本次调试中 P2 假红的根因）。
