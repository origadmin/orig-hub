# BUG-093: 侧栏 Telegram 导航项消失——9877 上残留着验收脚本以离线模式拉起的 orig-tg

- 状态: fixed
- 发现日期: 2026-09-21
- 模块: shell
- 严重程度: high

## 现象

用户报「TG 不见了，这是严重的回退错误」。侧栏导航实测只剩 7 项，`nav-tg` 被整条过滤掉：

```
["nav-downloading","nav-activity","nav-paused","nav-completed","nav-failed","nav-media","nav-settings"]
```

## 根因

门控本身没有坏，坏的是**门控依赖的运行时状态**。链路上每一环都取证过：

1. `tauri-shell/src/components/Sidebar.tsx:316`
   `NAV_ITEMS.filter((item) => item.id !== 'tg' || (tgBound && tgReady))`
   —— `nav-tg` 只在两个条件同时成立时才渲染。
2. `tgBound` = `accounts.tg.bound`（`MainLayout.tsx:215`），源头是
   `GET http://127.0.0.1:9877/api/tg/session` 的 `phase === 'Authorized'`
   （前端 TG 走 9877，见 `src/api/tg.ts:15`，不是 daemon 的 9876）。
3. 9877 上跑的是 **PID 22956，启动于 2026-09-20 16:23:35**，路径
   `download-engine/target/release/orig-tg.exe`；它是被验收脚本
   `verify_shots/restart_tg.py` 拉起的。
4. 该脚本第 33-34 行：

   ```python
   if os.environ.get("ORIG_TG_ONLINE") != "1":
       env["ORIG_TG_OFFLINE"] = "1"
   ```

   即**未显式要求在线时默认注入离线**。
5. `download-engine/crates/orig-tg/src/main.rs:119-133` 的 `offline_short_circuit()`
   见到 `ORIG_TG_OFFLINE=1` 就直接跳过 `GrammersClient::connect`，返回
   `Availability::Unavailable("offline debug mode: MTProto connect skipped ...")`。
6. 于是 `/api/tg/session` 返回 `phase:"Anonymous"` → `tgBound=false` → 导航被过滤。

**关键排除项**：门控由更早的提交 `06e7a8e` 引入，本轮对 `Sidebar.tsx` 的改动只有两处
（引入 `connState`、修 `allActive`），**不是本轮改动引入的回退**。

## 修复

不改代码——把运行环境恢复成「在线」这一正常态：

1. 备份凭据与会话到系统临时目录（`%TEMP%\orighub-tg-backup\`）：
   `session.session` / `store.db` / `config.json`；
2. 停掉残留的离线实例（PID 22956）；
3. 以 `ORIG_TG_ONLINE=1 python verify_shots/restart_tg.py` 重新拉起，
   该脚本用 `Popen` + `wait()` 托管，符合 AGENTS.md §5 的进程托管约定
   （Windows 无真 exec，`os.execve` 会让服务刚连上就被回收）。
