# BUG-479: 导出流程重设计——「导出预览 + 完备性校验」对话框作用不明、范围不明

- 状态: open
- 发现日期: 2026-10-28
- 模块: shell
- 严重程度: high
- 排期: 2026-11-04

> 来源：用户 2026-10-28 逐条裁决 BUG-478 时的内容级问题：
> 「导出预览 —— 完备性校验 设计混乱，一个弹出，完全不清作用，无法理解导出内容，
> 范围也不对，什么页面的东西？」
> 同日二次裁决（BUG-478 二次记录）：卡片级「导出本剧」与右上角库级导出开同一个
> 对话框，唯一差别是预勾当前剧 —— 伪差异，卡片级入口已拆除（一语义一入口）。
> **本档承接内容级问题本体**：对话框本身必须重设计。

## 现象

1. 打开导出弹窗后用户无法回答三个基本问题：**导出什么、导到哪、缺什么**。
2. 「完备性校验」作为弹窗内的一个区块出现，与导出动作的关系不可理解——
   校验是流程的一部分，不是并排的一块信息。
3. 范围语义混乱：候选集恒为全库，勾选集才决定导出范围，但界面没有把
   「当前范围 = 勾选集」讲清楚；从详情页进入时用户以为是「导出这一部」。

## 根因

- 对话框按「实现结构」组织（清单 + 校验 + 按钮堆），没有按「导出流程」组织。
- 完备性信息（缺失项、不可导出项）与导出目标、范围选择没有因果呈现：
  缺什么导致什么后果、是否阻塞导出，全都不明。

## 修复方向（待拍板后实施）

1. 改为一条可理解的导出流程：**选范围 → 看清单（含缺失项标注）→ 确认导出 → 结果**，
   每步只回答一个问题。
2. 完备性校验改为流程内呈现：缺失项逐条标注（哪部剧缺哪集、缺的是什么——
   未缓存 / 无来源 / 格式问题），并明示「缺失项是否阻塞导出」。
3. 范围语义显式化：进入时顶部一句话讲清当前范围（勾选 N 部 / 来自哪里）。
4. 引擎端点语义（`getSeriesManifest` / 导出端点）随流程一并对齐，不在壳层假装修好。
