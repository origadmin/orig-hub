# BUG-133：媒体库「占用空间」展示登记值——清缓存后数字不变，答不出磁盘真值

- 状态: open
- 发现日期: 2026-09-22
- 模块: engine+shell
- 严重程度: high

## 现象

清缓存后，媒体库侧展示的「占用空间」数字不变，用户自然质疑「是不是没删成功」；而缓存管理面板的字节数（磁盘真值）明明下降了——同一个存储事实两套账，且媒体库那套**答不出「这些条目现在实际占了多少磁盘」**。

## 根因

- `media.rs:2676-2694` `library_stats()`：`total_size = COALESCE(SUM(size), 0) FROM media_item` —— 这是**登记值**（声明字段求和）。清缓存只置空 `file_path`、**不清 `size`**（BUG-051/BUG-096 裁定：清缓存只回收字节，条目永不删）——所以「登记体积不变」本身是**正确行为**。
- `cache.rs:843-872` `cache/stats`：`bytes` 是下载目录内真实字节。
- **缺陷在于展示口径**：把登记值当「占用空间」呈现给用户，违背直觉且与磁盘真值互相矛盾。

## 复现

1. 记下媒体库「N 项 · X」中的 X。
2. 清缓存（回收全部字节）→ X 不变；`GET /api/cache/stats` 的 `bytes` 下降为 0。

## 修复

口径修正（评估文档 Q4 方案 A，推荐）：

- 主口径 = **磁盘实际占用**（清缓存后数字下降，符合直觉）；
- 登记值作次口径显式标注含义（如「媒体库登记（不含已清字节）」）；
- **不改 BUG-051 行为**——错的是展示口径与文案，不是「登记保留」本身。
