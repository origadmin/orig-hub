# BUG-427: 左栏选集器「▶ 播放入口」整列不齐——行尾右对齐使图标 x 随右侧文本宽度漂移

- 状态: fixed
- 发现日期: 2026-10-26
- 模块: shell
- 严重程度: mid
- 影响面: 剧集详情左栏每一行；时长字符数不同的行之间图标错位 5.78px，整列看起来是歪的

## 现象（用户第六次报障，2026-10-26）

用户附 **87×268** 窄条截图（左栏行尾 `▶ 时长` 一列），原话：

> 「播放按钮位置拍板错乱！我先次提出问题。同样藐视我的问题！」

截图像素扫描（逐行找绿色三角）给出客观位置：

| 行 | 时长 | 三角 x 范围 | 中心 |
|---|---|---|---|
| 首行（选中） | `11:34` | 17–27 | 22 |
| 其余 6 行 | `5:12` / `7:34` / `7:20` / `8:52` / `7:06` / `8:41` | 23–33 | 28 |

⇒ 首行的 ▶ **整体左移 6px**，整列图标不在一条竖线上。这就是「错乱」的物理形态。

## 根因（CDP 实测，`verify/_probe_rowplay_align.cjs`）

行结构是 `grid grid-cols-[auto_1fr_auto]`，行尾（第 3 列）是
`span.flex.items-center.gap-1.5`，内含 `[▶][时长]`。该列 `auto` 宽且整行右对齐，于是

```
▶.x = 列右缘 − 时长文本宽 − gap(6) − 24
```

时长文本一变宽，▶ 就被推着走。实测：

| 行 | 时长 | 时长格宽 | ▶.x |
|---|---|---|---|
| row#0 | `11:34`（5 字符） | 28.88 | **468.13** |
| row#1–6 | `5:12` 等（4 字符） | 23.09 | **473.91** |

**极差 5.78px**。`fmtDuration` 只产出 `m:ss`（4–5 字符）与 `h:mm:ss`（7–8 字符）两种形态，
所以字符数差异是**常态**，不是个例。

> 注意：这不是「按钮该放哪」的问题，而是「同一列里图标没对齐」的问题。
> 用户在 BUG-369 已经拍过板（播放入口归左栏行内），本轮**不动那个决定**。

## 为什么前几轮没抓到

`verify_play_primary.cjs` 的 `376-C` 只断言「行内入口宽度/行宽 ≤ 0.35、命中区 ≥ 24×24」——
它钉的是**单行内的比例**，跨行的**列对齐**不在判据里。所以 20/20 全绿，用户看到的仍是歪的。

⇒ 纪律：**「存在且尺寸合规」不等于「排布整齐」**。跨行一致性必须单独立判据。

## 修复

`tauri-shell/src/components/media/SeriesDetail.tsx`：

1. 组件体新增 `durCellCh` —— 本剧最长时长字符数：

   ```tsx
   const durCellCh = detail.episodes.reduce((m, ep) => {
     if (isPhotoEpisode(ep) || ep.duration == null) return m
     return Math.max(m, fmtDuration(ep.duration).length)
   }, 0)
   ```

2. 时长格改为 `text-right` + `style={{ minWidth: `${durCellCh}ch` }}`，并加
   `data-testid="episode-duration"`（判据锚点）。

`font-mono` 下 `1ch` 恒等于一个字符宽 ⇒ 所有行的时长格**同宽**，其左缘固定 ⇒
左侧的 ▶ 也固定。时长本身仍右对齐（右缘不动），**视觉上只是原来就歪的图标归位**。

### 为什么不把 ▶ 挪到行末

「▶ 放行末」同样能对齐（右缘锚定），但那会**再动一次用户正在看的位置** ——
正是 BUG-369 记下的教训「判据与诉求方向相反时，实现改多少次都不会对」。
本轮取最小 diff：位置不动，只把列宽钉住。
