# BUG-007: 内置分类标签不支持多语言设置

- 状态: fixed
- 发现日期: 2026-08-27
- 模块: shell
- 严重程度: mid

## 现象

设置页与侧栏的内置分类（Videos / Music / Images / Documents / Archives）始终以英文原始 key 显示；用户切换系统/应用语言后，分类子菜单仍显示英文，无法跟随语言偏好。自定义分类也缺乏本地化显示机制。

## 根因

1. `SettingsPanel.tsx:23-24` 使用硬编码 `BUILTIN_CLASSIFY: Record<string, string>` 作为显示文本，没有词条机制。
2. `Sidebar.tsx` 直接把从 daemon 取到的 `cat` key 渲染为子菜单文本。
3. 项目整体无 i18n 框架/词条文件。

同时存在关键约束：**分类名同时是磁盘目录名、`classify_rules` 的键、以及前端筛选值**。如果直接翻译 key 会破坏已归档目录与筛选逻辑，因此只能做显示层本地化。

## 复现

运行 `C:/Users/godcong/.workbuddy/verify_env/verify2.mjs`（Playwright）：

1. 启动应用默认中文 → 侧栏子菜单应显示「视频 / 音乐 / 图片 / 文档 / 压缩包」。
2. 进入设置 → 常规 → 语言，切换为 English → 刷新后侧栏应显示「Videos / Music / Images / Documents / Archives」。

## 修复

1. 新增文件翻译模式 i18n，无第三方依赖：
   - `tauri-shell/src/i18n/locales/zh-CN.json`
   - `tauri-shell/src/i18n/locales/en-US.json`
   - `tauri-shell/src/i18n/index.ts`（`t()` / `useTranslation()` / `setLanguage()` / `applyLanguage()`）
2. `tauri-shell/src/types.ts`：`AppSettings` 增加 `language: LanguageValue`（`'zh-CN' | 'en-US'`）。
3. `tauri-shell/src/store/useStore.ts`：`loadSettings` 默认按 `navigator.language` 推断语言偏好，未识别时回退 `'zh-CN'`。
4. `tauri-shell/src/main.tsx`：启动时调用 `applyLanguage(...)`，同步 `<html lang>`。
5. `tauri-shell/src/components/SettingsPanel.tsx`：常规 Tab 增加「语言」切换器，即时写入 localStorage 并调用 `applyLanguage`。
6. `tauri-shell/src/components/Sidebar.tsx`：导航、分类子菜单走 `t('category.<Key>', default)`；分类 key 作为目录/筛选值不变，显示层本地化为中文/英文。
7. `tauri-shell/src/components/MainLayout.tsx`：顶部工具栏、状态栏文案全部 `t()` 化。

## 防再发

1. **代码层**：新增 UI 文案必须经 `t(key)` 或 `t(key, default)`；禁止在组件中硬编码用户可见文字。
2. **分类约束**：内置分类新增/重命名时，必须在 `src/i18n/locales/zh-CN.json` 与 `en-US.json` 同步添加 `category.<Key>`；否则 `useTranslation` 会自动 fallback 到 key 本身。
3. **验收层**：Playwright 脚本将语言切换与分类本地化断言落盘为截图/JSON，回归可自动发现漏翻。
4. **范围层**：本次仅覆盖 shell 导航、设置、状态栏、分类标签；`DownloadItem` 卡片内部（如「已完成」「均速」「暂无下载任务」）尚未纳入 i18n，后续单独建卡，避免一次 PR 范围膨胀。
