# BUG-091: tg_start 只看子进程句柄不探端口，会 spawn 出第二个 orig-tg

- 状态: fixed
- 发现日期: 2026-09-21
- 模块: engine
- 严重程度: mid

## 现象

daemon 接口契约体检抓到的矛盾态（同一时刻实测）：

```
curl -s --noproxy '*' http://127.0.0.1:9877/health                -> 200   # orig-tg 确实在跑
curl -s --noproxy '*' http://127.0.0.1:9876/api/config            -> "tg_enabled":true,"tg_running":false
```

即「服务活着，但 daemon 说没启动」。此状态下用户在设置页点「启动 TG」，`tg_start()`
会真去 spawn 一个 orig-tg —— 要么 9877 bind 失败起不来，要么跑出双进程争抢同一份
会话文件与 SQLite 库。

## 根因

`download-engine/crates/orig-daemon/src/state.rs:76-95`（修前）：

```rust
pub async fn tg_is_running(&self) -> bool {
    let mut g = self.tg_child.lock().await;
    match g.as_mut() { Some(c) => ..., None => false }
}

pub async fn tg_start(&self) -> std::io::Result<bool> {
    if self.tg_is_running().await { return Ok(true); }
    ...cmd.spawn()?...
}
```

存活判据**只**看本进程持有的 `Child` 句柄。但 orig-tg 完全可能由别的发起方拉起 ——
上一轮 daemon 遗留、手动启动、开机自启 —— 那种情况下本进程手里根本没有句柄，
`tg_is_running()` 恒为 false，`tg_start()` 据此无条件 spawn。

判据与事实不同源：句柄回答的是「我拉的孩子还在吗」，而 UI 要的是「这个端口上有没有人在服务」。

## 复现

1. 已有一个 orig-tg 在 9877 上跑（例如上一轮 daemon 遗留）；
2. 再起一个 orig-daemon（它的 `tg_child` 为空）；
3. `GET /api/config` 读到 `tg_running:false`；
4. `PUT /api/config/tg {"enabled":true}` → 修前 spawn 出第二个进程。

## 修复

`tg_is_running()` 改成两条路径，先托管后外部：

- `tg_managed_alive()`：保留原逻辑（句柄存在且未退出，已退出自动清句柄）—— `managed`
  语义与 `tg_stop()` 照旧，未托管仍是「我拉的孩子」；
- `tg_port_has_listener(port)`：对 `127.0.0.1:{port}` 做一次 TCP connect 探测（500ms 超时兜底），
  连得上就说明已有一个实例在服务；
- `tg_start_on(port)` 据此在端口已被占用时**直接返回 true、不 spawn**；
- `tg_start()` / `tg_is_running()` 分别为 `tg_start_on(TG_PORT)` / `tg_is_running_on(TG_PORT)`，
  端口真源仍是 `TG_PORT` 常量，`PORT` 环境变量不再参与子进程注入。

副作用（预期内）：`/api/config` 的 `tg_running` 现在如实反映「9877 上有没有人在服务」，
矛盾态消失。外部实例我们拿不到句柄也就 kill 不掉，`tg_stop()` 对它无能为力 ——
这是既有前提，已在代码注释里写明，不在本次修复范围。

## 验收证据

单测（`download-engine/crates/orig-daemon/src/state.rs`，入库，跨机器可核）
覆盖「端口被占用但无 child 句柄」这一实测矛盾态：

```
state::tests::start_skips_spawn_when_port_occupied_without_child_handle ... ok
state::tests::port_probe_detects_listener                               ... ok
state::tests::port_probe_reports_false_when_idle                        ... ok
state::tests::not_running_when_idle_port_and_no_child                   ... ok
```

前两条断言探测为真；第三条守卫反向（空闲端口不得误判为已启动，否则会永久假死在「已运行」）；
第四条断言「端口已占用 → 判为运行中」，且 `tg_start_on()` 返回 `true` 后
`tg_child` **仍为 None**（即确实没有 spawn 第二个进程）。

- 改动文件：`download-engine/crates/orig-daemon/src/state.rs`
- 门禁：`cargo test -p orig-daemon` 19 passed / 0 failed；
  `python scripts/check-bugs.py` 与 `sh scripts/check-pollution.sh` 均 EXIT 0
