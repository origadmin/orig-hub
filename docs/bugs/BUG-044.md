# BUG-044：图片混入剧集 —— 「图片不入剧集」规则级缺失

- 状态: fixed
- 发现日期: 2026-09-18
- 模块: engine
- 严重程度: critical

## 规则（用户裁定，最高优先级）
**图片是浏览点，与视频完全无关。播放一个视频永远不能播到一张图片。**
剧集分集与备用源只能是视频；图片不参与成剧、不参与编集、不参与集号排序。

## 现象
TG 缓存后图片视频混乱：整组相册（视频+图片）全部被自动成剧编成剧集，
纯图片组被编成「album 图集」；播放序列、分集列表里图片与视频混排。

## 根因
「剧集只收视频」这一不变量**没有任何一层在守**：自动成剧把整组条目
（含 photo）直接 `append_episodes_ranged`；手动入口不校验 kind；
数据层无约束 —— 错误状态在任何路径上都可以表达。

## 修复（规则级，三层）
1. **数据层不变量（触发器）**：`media_episode` / `media_episode_source` 的
   INSERT 与 UPDATE OF item_id 各挂 BEFORE 触发器，
   `(SELECT kind FROM media_item WHERE id = NEW.item_id) IS NOT 'video'` →
   `RAISE(ABORT)`。条目不存在（kind=NULL）同样拒绝。
   任何写路径（自动/手动/合并/未来新增）都无法把非视频挂成分集或备用源。
2. **入口过滤**：自动成剧只取视频条目（(message_id,item_id) 成对裁剪，
   caption 集号对位不被打乱），纯图片组不成剧；不再派生 album/collection，
   成剧一律 `series`。手动单加/批量追加混入非视频 → 显式 422（附被拒明细）。
3. **启动修复迁移**：打开库时摘除全部非视频分集与备用源；失去全部分集的
   剧集随之删除（连带标签关联）——历史脏数据回到合规态。
4. 前端「加入剧集」按钮：所选含非视频时禁用（i18n 提示）；后端 422 兜底。
5. 顺带修正 `import_cached_file` mime 兜底 kind：`image` → `photo`
   （与扩展名分类/stats/筛选的规范键对齐）。

## 验收
- 单测 `episode_slots_reject_non_video_items`：图片/未知条目直插、upsert 冲突
  改挂、备用源挂载全部被拒且不留脏行。
- 单测 `startup_repair_detaches_non_video_episodes`：旧库脏数据（混编剧+纯图剧）
  打开后图片分集被摘、纯图剧整体清除、混编剧只留视频集。
- 实例重启后：纯图「album」剧集消失、混编「collection」只剩视频集（HTTP 验证 + 截图）。
