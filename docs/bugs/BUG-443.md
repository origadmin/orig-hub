# BUG-443: serve_local_file 的 ETag/Last-Modified 全由 mtime 派生——LRU 触摸即失效、跨盘迁移击穿缓存

- 状态: open
- 发现日期: 2026-10-23
- 模块: engine
- 严重程度: mid

## 现象

已缓存视频在应用内分段播放时，浏览器媒体字节缓存（range 复用）频繁失效，已取的字节被重复下载，
播放与浏览双重卡顿、出网流量放大（与 BUG-199/033/229 同类症状但根因不同）。

## 根因

`serve_local_file`（`download-engine/crates/orig-tg/src/routes.rs:6194`）的缓存校验头完全由文件
**mtime** 派生：
- `etag = format!("{:x}-{:x}", total, mtime_secs)`（`routes.rs:6300`）；
- `Last-Modified = http_date(mtime_secs)`（`routes.rs:6308`）。

而代理命中时，投递路径会**主动 `set_modified(now)` 刷新 mtime** 以喂 LRU 预算
（`routes.rs:5625`、`routes.rs:5672`）——这个为 LRU 做的触摸会**连带改变 ETag/Last-Modified**，
使 Chromium 的媒体字节缓存失效，下次同片段请求重新走网络拉取，已取 Range 作废。
此外，库根跨磁盘迁移 / 内容根从 D: 落到临时盘（BUG-421 类迁移、`%TEMP%` 夹具）导致 mtime 变化时，
同一文件也会被判成「新资源」而击穿缓存。

## 复现

1. 应用内播放一部已缓存视频，确认首次拉取若干 Range；
2. 命中代理 LRU 触摸（`routes.rs:5625/5672` 的 `set_modified`）后，再播同一片段；
3. 观察 Range 未被浏览器媒体缓存复用（Network 面板 200 而非 206 缓存命中）。

## 修复

ETag 改为内容/身份稳定量（如 `content_hash` 或 `size + content_hash`），与 mtime 解耦；mtime 仅用于
`Last-Modified` 展示，不参与 ETag。LRU 触摸（`set_modified`）不得改变 ETag。存量无 hash 的条目可
暂用 `size + inode` 之类稳定标识过渡。
