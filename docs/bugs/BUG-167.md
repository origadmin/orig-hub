# BUG-167: 瞬时 TG 传输错误升级为全局「无法连接到 Telegram」toast —— 与三处「实时已连接」灯同屏矛盾的第二真相源

- 状态: fixed
- 发现日期: 2026-09-24
- 模块: shell
- 严重程度: medium
- 档位: standard

## 现象

用户报「无法连接到 Telegram，请检查网络与代理设置后重试。现在问题有点乱。
"实时已连接"3 个状态点，要求唯一真相源，唯一状态点」。

CDP 活体实锤同屏矛盾（`orighub_banner_probe.cjs` / `orighub_banner_locate.cjs`）：
下载视图三处连接灯全 `live`（sidebar/context/statusbar），TG 视图订阅列表正常加载
（4 个监控频道在列），但屏幕顶部弹出红色「无法连接到 Telegram」。此刻引擎侧诚实：
`/api/tg/session` → `available:true`，`/api/tg/diag` → `unavailable_reason:null, link_alive:true`。

## 根因

第二真相源链路：

1. `api/tg.ts request()` 失败时抛 `tgFailureMessage(...)`，`classifyTgReason` 把
   `dropped|connect|timeout|i-o…` 等传输层原文判为 `tg.reasonNetwork`
   （「无法连接到 Telegram…」——对**单次请求失败**用了**持续性不可用**的断言文案）；
2. TgPanel 的**后台加载**（订阅列表挂载拉取、扫描轮询、内容流首载、滚动翻页、
   全局搜索、监控列表加载）失败时调用 store `setError`；
3. store `setError` 是 error+toast 双写（`useStore.ts` `setError: (e) => set({ error: e, toast: e })`），
   `MainLayout` 把 toast 渲染成全局红色横幅。

于是「一次瞬时请求失败」升级成了「全局无法连接」的状态断言，与 SSE/引擎真相源
（三处连接灯 `useConnState`，BUG-087/164 已统一）直接矛盾。BUG-023/088 已立的
「面板顶部横幅是可用性唯一表述」约定被这条旁路打穿。

## 修复

`tauri-shell/src/components/TgPanel.tsx` —— 按「后台静默 / 用户动作保留反馈」分岔：

| 调用点 | 性质 | 处置 |
|---|---|---|
| 订阅列表挂载拉取 + 冷启动补扫（`fetchDialogs` 自身 catch） | 后台 | 静默（原文已由 `tgFailureMessage` 记日志） |
| 扫描轮询（2.5s `fetchDialogs(false)`） | 后台 | 静默 |
| 监控列表挂载加载 | 后台 | 静默 |
| 内容流首载失败 | 后台 | 改**面板内联**提示 `tg.feedLoadFailed`（局部、重选频道即消失，不再断言「无法连接」） |
| 滚动翻页 `loadOlder` | 后台 | 静默，可再滚动重试 |
| 全局搜索 | 后台 | 静默（结果区为空即信号） |
| 「重新扫描订阅」按钮 | 用户主动 | 保留全局反馈（用户在等的动作结果） |
| 监控增删 / 缓存操作 / 设置保存 / 登录（AccountsPanel） | 用户主动 | 保留全局反馈 |

`fetchDialogs` 不再吞错，改为向上抛、由调用方分岔。i18n 新增
`tg.feedLoadFailed`（zh: 「内容加载失败，重新选择频道或稍后重试」）。

修复后不变式：**「无法连接到 Telegram」文案当且仅当出现于 (a) 用户主动操作真实失败
（该请求确实没打通，如实）或 (b) 引擎 `available:false` 的横幅（引擎真相源）**。
后台瞬时错误永不产生该文案——三处连接灯（唯一真相源 `useConnState`）不再被打脸。

```

C 内容区内联提示 ................... feedLoadFailed 文案可见（截图 orighub_bug167_inline.png）
D 验牙：注入 setError 判据可判红 ... toast=true「无法连接到 Telegram…」
```
