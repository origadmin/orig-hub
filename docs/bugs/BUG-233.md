# BUG-233：设置-关于只有下载引擎（daemon）状态，没有 Telegram 插件状态

- 状态: fixed（关于页已补 TG 插件状态块，真实 UI 探针 PASS；长期随 BUG-238 插件注册表统一）
- 发现日期: 2026-10-09
- 模块: shell
- 严重程度: mid
- 登记: 用户报告「设置中关于的 telegram 插件状态仍然没有修复」（此前已提出过 tg 状态
  无监听、状态分散是否是设计问题，均未落地）

## 现象

设置页「关于」页签（`SettingsPanel.tsx` about 分支）只渲染下载引擎一项：
`daemon?.alive` 红绿点 + 端口。TG 插件是否启用、是否在线、端口、错误原因一概不可见。

## 根因

- about 页签实现（`SettingsPanel.tsx:1037-1064`）从未包含 TG 项；
- TG 的 enabled/running/error 状态只存在于「常规」页签的开关区块（`tgService.enabled`、
  `tgRunning`、`tgError`，`SettingsPanel.tsx:89,926-955`）——状态数据已有，**呈现缺位**；
- 与 BUG-238（插件化管理框架缺失）同源：没有统一的插件状态注册表，各处自行拼凑，
  新增插件状态就会再漏一处（用户此前质疑「状态分散是否是设计问题」成立）。

## 修法方向

短期：about 页签补 TG 状态行（enabled/在线/端口/错误），复用 tgService 现有状态，
不新造第二套轮询。长期：随 BUG-238 插件注册表统一出「插件状态区」，about 页遍历注册表渲染，
不再逐插件手写。

## 修复（2026-10-09）

- `SettingsPanel.tsx` about 页签新增 `about-tg` 区块：服务层（进程：启用/运行/端口/失败原因）
  与链路层（Telegram 连接状态，`tgLink.state`）分开呈现 —— 与常规页签同一语义（BUG-178），
  不合并成一个含糊的绿点；开关仍只在「常规」，此处只读状态，动作不重复安放。
- i18n：zh-CN/en-US 各补 7 个 `about.tg*` 键。
