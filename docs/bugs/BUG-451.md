# BUG-451: 文件域上下文栏「搜索输入框 × 库级动作组」重叠——关窗即退的同一张截图里暴露的布局缺陷

- 状态: fixed
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: high

## 现象

用户 2026-10-27 截图（`Clipboard_Screenshot.png`，约 20:00）同时报告两处缺陷，其一：

> 「标题的输入筛选框和按钮重叠了。」

文件管理页（files 视图）顶部上下文栏：中槽的**搜索输入框**与右槽的**库级动作组四件套**
（导入目录 / 新建剧集 / 导出 / 标签管理）在常见窗口宽度下**互相压住**——搜索框右缘盖住
第一个按钮（导入目录）的左缘，导致按钮点不到、筛选框也错位的视觉与交互双重故障。

> 与 BUG-452 同源截图：用户以「下载工具」视角批评流程，「重叠」与「关窗即退」是同一张图里的两个问题。

## 根因：`gridCls` 的窄窗修复只覆盖了 `view==='tg'`

上下文栏是三列 CSS Grid（`ContextBar.tsx` 的 `gridCls`）。文件域右槽是 4 个按钮，实测总宽
**≈358px**（导入目录 98 / 新建剧集 100 / 导出 50 / 标签管理 74 + 3×12px gap）；中槽搜索框是
`w-80`(320px) + `min-w-0`。

原 `gridCls`：

```tsx
const gridCls = cn(
  'grid min-w-0 flex-1 items-center gap-3',
  view === 'tg'
    ? '…max-[1100px]:grid-cols-[auto_minmax(0,1fr)_auto]'   // ← 只有 tg 有窄窗修复
    : 'grid-cols-[minmax(0,1fr)_auto_minmax(0,1fr)]',        // ← files/download/status 都走这
)
```

文件域走 `else` 分支的 `1fr auto 1fr`：**左右两 `1fr` 轨道要平分剩余空间**，但右槽内容
358px 远超它在窄窗里分到的 `1fr` 份额 ⇒ 右槽以 `shrink-0`+`justify-end` **向左溢出**，
压住中槽 320px 搜索框。TG 视图因为 2026-10-17 已加过窄窗修复（`max-[1100px]:auto 1fr auto`）
所以不重叠，而文件域漏了这层保护。

> 注：`minWidth=900` 的壳窗口下，内容区（窗口 − 侧栏 ≈192px − 内边距）实际只有 676px，
> `1fr auto 1fr` 的 `1fr` 轨道仅 ≈166px，远小于右槽 358px ⇒ 必溢出。这不是「视口断点冒充
> 宽度不足」（那是 BUG-270 对 Deck 图组的口径），而是本组件真实的内容宽度溢出。

## 修复

给**文件域**单独加一层窄窗修复（与 TG 同族，断点更宽，因为右槽更宽）：

```tsx
const gridCls = cn(
  'grid min-w-0 flex-1 items-center gap-3',
  view === 'tg'
    ? 'grid-cols-[minmax(0,1fr)_auto_minmax(0,1fr)] max-[1100px]:grid-cols-[auto_minmax(0,1fr)_auto]'
    : view === 'files'
      ? 'grid-cols-[minmax(0,1fr)_auto_minmax(0,1fr)] max-[1300px]:grid-cols-[minmax(0,1fr)_minmax(0,1fr)_auto]'
      : 'grid-cols-[minmax(0,1fr)_auto_minmax(0,1fr)]',
)
```

- 宽窗（>1300px）：仍 `1fr auto 1fr`，搜索框**真居中**（与改动前逐像素一致，不回归）。
- 窄窗（≤1300px）：改 `1fr-1fr-auto`——右槽 `auto` 按内容取宽**永不溢出**，中槽
  `minmax(0,1fr)` 吸收剩余、让搜索框经 `min-w-0` 自动收缩。

**断点选 1300px**（而非 TG 的 1100）：文件域右槽比 TG 宽 126px，需更宽的窗口才放得下
`1fr auto 1fr` 的居中形态。实测 `1fr auto 1fr` 在内容宽 ≈1036px（窗口≈1260，侧栏展开）
以下开始重叠，取 1300 留足余量。

> 只改文件域（`view==='files'`）：用户报的范围＝授权范围（BUG-374），download/status 视图
> 未报告重叠，不擅动。

### 反向证伪（候选对比，确认根因）

`tauri-shell/verify/_diag_ctxbar_candidates.cjs` 在真实 DOM 上把候选 class 临时换上去量：
原 `current(1fr auto 1fr)` 在 1200/1100/1000/900 实测 overlap = **+30 / +80 / +130 / +180px**
（重叠、即用户截图现象）；`tg-narrow / shrink-mid / 1fr-1fr-auto` 等候选**全宽度 overlap≤0**、
`spillRight=0`。故采用 `1fr-1fr-auto` 作为文件域窄窗修复（与最终落地的 `max-[1300px]` 分支一致）。
