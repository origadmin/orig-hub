# 追溯归档：登记册建立之前的修复提交

登记册（`docs/bugs/BUG-001.md` 起）不是从第一天就存在的。审计 `git log` 后发现
**22 条 `fix` 提交里有 19 条不含 `BUG-<编号>`**，这些修复只活在 git 历史里，
登记册无法回答「修没修」「修在哪」。本文件把 19 条逐一对账，给出三种结论。

**边界声明（不许编造）**：归档**不**为这 19 条补写「现象/根因」——
当时的上游记录（对话、日志）已不完整，事后编写即为伪造。能确证的只有
「提交改了什么」；能映射到已登记 BUG 的给映射，映射不到的正式立档并标注
**事后追认、无独立验收脚本**。

生成方式（可复现）：

```sh
git log --format="%h|%ad|%s" --date=short | grep -i 'fix' | grep -v 'BUG-'
```

## 以后的规则

自 BUG-067 起：

1. `fix` 类提交**必须**引用 `BUG-<编号>`（`scripts/hooks/commit-msg` 拦截）；
2. `fixed` 状态**必须**有可核验收章节，引用路径与提交 hash 由
   `scripts/check-bugs.py` 校验真实存在；
3. 编号自 1 起连续、索引与文件双向一致，由同一门禁校验。

本文件是历史欠账的**一次性对账**，不参与上述门禁（它不是登记条目）。
