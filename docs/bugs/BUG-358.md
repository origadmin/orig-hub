# BUG-358: `/api/config` 契约把插件名写死（`tg_enabled`/`tg_running`/`tg_port`/`tg_last_error`/`tg_link`），违背「插件化、即插即用」

- 状态: fixed
- 发现日期: 2026-10-21
- 模块: engine+shell
- 严重程度: high

## 现象

用户 2026-10-21 裁定（原话）：「`/api/config` 请求也发现了严重问题……一个是返回值，
**"tg_enabled"这些都是什么？毫无共通性，最初定义就是以共通插件化来做**，现在TG叫这个，
以后其他插件叫什么？**如何达成0修改，我把TG改成BB，这个还能用吗？** 禁止修改任何代码的！
插件是要即插即用的，当前设计实现完全错误」。

活栈实测 `/api/config` 顶层键：

```
tg_enabled / tg_running / tg_port / tg_last_error / tg_link
```

这五个键把**一个具体插件的名字**写进了全局配置契约。后果：

- 前端 `useStore` / `SettingsPanel` / `selectors` 共 9 处直接读 `cfg.tg_*`；
- 换插件（TG→BB）要同时改 daemon 契约 + 前端 9 处读取点 + 三个接口函数名 —— 与「即插即用」相反；
- 每加一个插件就会长出一族 `bb_enabled` / `bb_port`，契约无限膨胀。

## 根因

`/api/config` 的 `json!({...})` 是**手写平铺**的，TG 的生命周期状态被当作 daemon 的
「自身配置」直接铺在顶层，从未抽象成「插件清单」。前端同理：没有适配层，
每个组件直接认 `tg_*` 字段名。

## 修复

**裁定**：契约里只能出现**与插件无关**的形状 —— `plugins: [{id, label, enabled, running,
port, lastError, health}]`；前端按 `id` 取自己那一份，不认识的 id 直接跳过。

### 引擎侧（`crates/orig-daemon/src/routes.rs`）

- 新增插件注册表 —— 契约的**唯一声明点**：

  ```rust
  struct PluginSpec { id: &'static str, label: &'static str }
  const PLUGIN_TG: &str = "tg";
  const PLUGINS: &[PluginSpec] = &[PluginSpec { id: PLUGIN_TG, label: "Telegram" }];
  ```

- 新增 `plugins_snapshot(&st)`：遍历注册表产出运行态（`id/label/enabled/running/port/
  lastError/health`）；`health` 的字段名转 camelCase（`linkDown`/`downStreak`/
  `confirmsRequired`/`restarts`/`lastRestartAt`/`reason`），与其它 HTTP 边界一致。
- `/api/config`：**删除** `tg_enabled`/`tg_running`/`tg_port`/`tg_last_error`/`tg_link`，
  改下发 `plugins`。
- 新增插件无关端点：`PUT /api/plugins/:id/enabled`、`POST /api/plugins/:id/restart`
  （未知 id ⇒ 404）。旧路径 `PUT /api/config/tg` / `POST /api/tg/restart` 保留为**别名**
  （桌面壳 `lib.rs` 仍在调，只读状态行不看 body），语义完全一致。
- 启停/重启的响应体同步改为 `{ok, plugins}`，不再回 `tg_*`。

### 前端（`tauri-shell`）

- `api/daemon.ts`：新增 `DaemonPlugin` 接口 + `TG_PLUGIN_ID` 常量 + `findPlugin(cfg, id)`；
  `DaemonConfig` 删除五个 `tg_*` 字段、加 `plugins?: DaemonPlugin[]`；
  `saveTgConfig`/`restartTgService` 替换为 `setPluginEnabled(id, req)` / `restartPlugin(id)`。
- `store/useStore.ts`：新增**唯一适配点** `tgServiceFromPlugins(cfg)` ——
  把 `plugins[id=tg]` 映射回既有的 `TgServiceState`（`health` camel→snake 也在这一处转换），
  4 处读取点（`init` / `setTgEnabled` / `restartTg` / `refreshTgState`）全部改走它。
  上层组件与选择器**零改动** —— 这正是可替换性的检验点。
- `lib/mediaSources.ts`：`ensureAvailable` 改调 `restartPlugin(TG_PLUGIN_ID)`。

## 验收证据

- **真栈实测**（`curl http://127.0.0.1:19786/api/config`，daemon release 重启后）：
  顶层键 = `classify_enabled, classify_rules, default_download_dir, download_dir,
  effective_download_root, library_root, logs, manual_download_root, max_connections,
  plugins, port, proxy` —— **五个 `tg_*` 键全部消失**，`plugins` 为 1 元素数组：
  ```json
  [{"id":"tg","label":"Telegram","enabled":true,"running":true,"port":19787,
    "lastError":null,
    "health":{"linkDown":false,"downStreak":0,"confirmsRequired":3,
              "restarts":0,"lastRestartAt":null,"reason":null}}]
  ```
- **插件无关端点实测**：`PUT /api/plugins/bb/enabled` ⇒ **404**（未知 id 不静默成功）；
  `POST /api/plugins/tg/restart` ⇒ `{ok:true, plugins[0].running=true, port=19787}`。
- **判据进门禁**：`verify/_diag_smoke_stack.cjs` S4 改为「plugins 契约 + 路径单形态」，
  含两条**结构性反判据**（顶层不得有 `tg_` 前缀键；5 个路径字段 + `logs` 三项不得含 `\`）。
  真栈 **10/10 ALL PASS**（`泄漏tg_键=无 路径反斜杠=无 logs反斜杠=无`）。
- **反向证伪**：同一判据喂旧形态 ⇒ 判红（`旧形态判定 = false`，泄漏 `tg_enabled,tg_running,
  tg_port,tg_last_error,tg_link`），证明判据有牙齿。
- `cargo test -p orig-daemon` **68/68**；`tsc --noEmit` **0 错**；
  `grep -rn "tg_enabled|tg_running|tg_last_error|tg_link" tauri-shell/src` 仅剩**注释**
  （无任何读取点）。

- **代码真源（跨机器可核验）**：
  - `download-engine/crates/orig-daemon/src/routes.rs`：`PluginSpec` / `PLUGINS` /
    `PLUGIN_TG` 注册表、`plugins_snapshot`、`put_plugin_enabled` / `post_plugin_restart`
    与路由 `/api/plugins/:id/enabled`、`/api/plugins/:id/restart`（旧路径为别名）；
  - `download-engine/crates/orig-core/src/paths.rs`：`ENGINE_DIR_NAME` / `LIBRARY_DIR_NAME` /
    `library_root_of`（daemon 与 orig-tg 共用的派生函数）；
  - `tauri-shell/src/api/daemon.ts`：`DaemonPlugin` / `TG_PLUGIN_ID` / `findPlugin` /
    `setPluginEnabled` / `restartPlugin`；
  - `tauri-shell/src/store/useStore.ts`：`tgServiceFromPlugins`（唯一适配点）；
  - `tauri-shell/verify/_diag_smoke_stack.cjs`：S4 判据（plugins 契约 + 路径单形态 +
    两条结构性反判据）。
