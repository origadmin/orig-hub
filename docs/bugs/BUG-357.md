# BUG-357: `/api/config` 下发的路径形态混乱——同一响应里三种斜杠，前端按字符串比较必然误判

- 状态: fixed
- 发现日期: 2026-10-21
- 模块: engine
- 严重程度: high

## 现象

用户 2026-10-21 复报（原话）：「`/api/config` 请求也发现了严重问题。**一个是路径，返回的路径混乱错误**」。

活栈实测（`curl http://127.0.0.1:19786/api/config`，同一份响应内）：

| 字段 | 实测值 | 斜杠形态 |
|---|---|---|
| `download_dir` | `D:/OrigDown` | 正斜杠 |
| `effective_download_root` | `D:/OrigDown` | 正斜杠 |
| `library_root` | `D:/OrigDown/.orighub/library` | 正斜杠 |
| **`manual_download_root`** | **`D:\OrigDown`** | **反斜杠** |
| **`default_download_dir`** | **`C:\Users\godcong\Downloads`** | **反斜杠** |
| `logs.dir` / `logs.orig_tg` / `logs.errors` | `C:\Users\…\AppData\Roaming\…` | 反斜杠 |

## 根因

路径在内部各走各的派生链，**出参没有统一形态**：

- `effective_download_root` / `library_root` 自己调了 `normalize_dir_path`（BUG-356/357 前序修复）；
- `manual_download_root` 走 `content_root()`（`PathBuf::from(r"D:\OrigDown")` 的原始常量）与
  `default_download_dir()`（OS known-folder API，原生 `\`），**都没归一化**；
- `logs.*` 由 `log_dir()` 直出，同样原生 `\`。

前端拿这些值做「是否同一目录」的字符串比较与展示 ⇒ 同一个目录被判成两个（BUG-323 的边界判定
正是按字符串前缀比较），显示层则一半正斜杠一半反斜杠。

## 修复

**裁定**：凡是**给外面看 / 给外面比**的路径，形态必须唯一（正斜杠 + 折叠重复分隔符）；
内部语义（`PathBuf`、落盘、边界判定）不变。

- `crates/orig-daemon/src/routes.rs` 新增 `fn dir_out(p: &Path) -> String` ——
  一律 `orig_core::paths::normalize_dir_path(...)` 后序列化；
- `get_config` 的**全部**路径字段改走 `dir_out`：`download_dir` / `library_root` /
  `effective_download_root` / `manual_download_root` / `default_download_dir` /
  `logs.dir` / `logs.orig_tg` / `logs.errors`；
- 顺带修掉一个**会让整个 future 变成 `!Send`** 的隐患：原实现持着
  `RwLockReadGuard` 跨 `await`（`plugins_snapshot` 要探活子进程），axum 只报
  「`Handler` 未实现」，报错完全看不出根因是 guard。改为先在独立语句块里把配置读成
  无 guard 的快照，再 await。
