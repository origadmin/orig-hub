# BUG-015: TG 面板交互结构错误：订阅/监控混排、内容无历史分页、非聊天式时序

- 状态: open
- 发现日期: 2026-09-16
- 模块: engine+shell
- 严重程度: high

## 现象（用户 UAT 反馈，2026-09-16 Web 调试模式实测）

1. 左栏把**全部订阅频道与监控开关平铺**在同一列表，「添加监控」的频道与未监控频道没有分区；用户期望「分组 → 组内频道 → 加入监控 → 监控列表」是清晰的三级关系。
2. 监控列表才是用户日常使用的「真列表」，应直接读本地 SQLite 秒显，不应受订阅枚举（TG 网络加载）影响。
3. 点击监控频道后的内容区**只能加载一页**（后端 `list_messages` 仅 `limit`，无历史游标；`Client::messages` 无 `max_id`），更早的媒体无法获取。
4. 内容顺序为「新→旧自上而下」，与 Telegram 聊天习惯相反；用户要求最新消息在底部，**向上滚动到顶后加载更早历史**。

## 根因

1. 前端 `TgPanel` 单栏承载「分组+频道+监控开关」，缺少独立的「监控中」本地视图（`tauri-shell/src/components/TgPanel.tsx`）。
2. 后端 `GET /api/tg/monitor/messages` 只有 `channelId/limit`；store `list_messages` 无 `before_id`；`Client::messages` 未暴露 grammers `MessageIter::offset_id()`（等价 max_id，exclusive，默认新→旧）。
3. 监控同步只覆盖最近窗口（cursor=0 首轮 200 条），窗口外历史没有「按需向上回补」路径。
4. 入库未过滤非媒体消息（纯文本也入 `media_message`），分页计数口径混杂。

## 修复（v0.4.0，2026-09-16 定案）

### 后端

1. `Client::messages(chat_id, limit, before_id: Option<i64>)`：grammers 用 `iter_messages(peer).offset_id(before).limit(n)`；**只返回媒体消息**（循环翻页直到收集够 limit 条媒体或无更多，设原始消息扫描上限）。
2. store：
   - `list_messages(channel, before: Option<i64>, limit)` → `WHERE message_id < before`（before=None 时不加条件）`ORDER BY message_id DESC`；
   - `upsert_message` 只入库媒体（调用方过滤），带 `media_type/msg_date`（见 BUG-014）。
3. `GET /api/tg/monitor/messages?channelId=&limit=&beforeId=`：
   - 先查本地；本地不足一页时，以 `beforeId 或本地最小 id` 为锚调 TG 实时回补并 upsert，再重查本地；
   - 返回 `{items, hasMore}`（TG 拉满 limit → true；拉空 → false；本地命中整页 → true，待滚顶再回补）。
4. `sync_once` 同步逻辑改用新签名（媒体过滤 + 日期/类型入库）。

### 前端（三栏）

```
左栏：导航          中栏：频道          右栏：内容
─ 监控中 (N) ★     组内频道行           聊天式消息流
─ <TG 文件夹A>     [标题] + 添加监控     最新在底部
─ <TG 文件夹B>     已监控显示「已添加」  滚到顶 → beforeId 加载更早
─ 未分组           （监控中视图：       图片缩略图(自然比例)/视频海报▶
                  本地频道，可移除）    点击才播/才看原图
```

- 左栏「监控中」读 `GET /monitor/channels`（本地秒显，与 dialogs 加载状态解耦）。
- 中栏文件夹视图读 dialogs 缓存；搜索框仅过滤当前视图。
- 右栏：首屏最新 30 条，渲染时反转为旧→新并滚动到底；滚顶触发 prepend，锚定 scrollHeight 保持视觉位置；顶部加载指示与 hasMore=false 的「没有更多」。
