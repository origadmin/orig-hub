# BUG-344: TG 面板控件无统一尺寸规范——按钮过大、节头右侧文字、搜索/标题/按钮各自为政

- 状态: fixed
- 发现日期: 2026-10-20
- 模块: shell
- 严重程度: mid

## 现象（用户原话，2026-10-20）

> 「筛选右边还有文字,按钮过大,这些都破坏了整体样式,这点需要严格标准.
> 按钮长宽高都需要规范化,和搜索,标题,样式这些都需要统一标准并严格执行.」

## 根因

面板控件尺寸全部硬编码、无 token；同一「节头动作按钮」在三处三个样：

| 控件 | 现状 | 位置 |
|---|---|---|
| 筛选节「+ 新建」按钮 | h-9 + 图标 + 文字 label（第三次复报刚从 28px 纯图标放大而来，见 `:1945-1946` 注释） | `TgPanel.tsx:1948-1961` |
| 监控节「同步」按钮 | h-7、text-[11px] | `:2167-2175` |
| 频道节「重新扫描订阅」按钮 | h-7、text-[11px] | `:2268-2282` |
| 规则行行尾 ✕ | h-8 w-8 | `:2105-2114` |
| 节折叠 chevron | h-6 w-6 | `:1922-1936` |
| 节内检索框 | h-7、text-[12px] | `:2026-2033` |

「按钮过大」+「筛选右边还有文字」= 筛选节头动作按钮既超尺寸又带文字 label。
两个方向相反的反馈（第三次复报：28px 纯图标被当成「什么都没有的空白」⇒ 放大加字；
本次：过大 + 有字 ⇒ 破坏样式）指向同一结症：**没有可信的小尺寸可见按钮范式**——
裸图标无 affordance 像空白，加大加字又破坏节头密度。缺的是一套**有边框有底色的
小按钮**token，而不是在「看不见」与「太大」之间来回翻车。

## 复现

1. TG 面板筛选节头：右侧「+ 新建」h-9 带文字，与监控/频道节 h-7 按钮明显两套；
2. 全面板量控件高度：{28, 32, 36}px 三档并存；搜索框 / 节头 / 行高无统一刻度。

## 修复（已实施）

1. **控件 token 全域执行**（`TgPanel.tsx` 三节 + 筛选命中面板 + 新建弹窗）：
   - 节头动作按钮：**h-7（28px）、有边框有底色**（secondary）——可见性由
     `border + bg` 承担，不由尺寸 + 文字标签承担（BUG-327「存在≠可用」与
     BUG-344「过大 + 有字」的共同解，终结「看不见 ⇒ 放大加字 ⇒ 破坏样式」循环）；
   - 行尾 ✕：h-7 w-7；节内检索/弹窗输入：h-8 / text-[12px]-[13px]；
     规则行计数徽标：12px tabular-nums；
2. **「筛选右边还有文字」** ⇒ 新建入口收敛为**图标按钮**（Plus 图标 +
   `aria-haspopup="dialog"` + aria-label/title），无文字 label；文字进弹窗标题；
3. 设计文档（`docs/design/tg-secondary-menu-2026-10-20.md`）补控件 token 节。

## 实施中抓到的真缺陷（比原方案更深一层）

原方案「调用方传 `className="h-7 …"` 覆盖」**根本立不住**：`cn` 是裸 join
（`tauri-shell/src/lib/utils.ts`，无 tailwind-merge），调用方的 `h-7` 与
`sizeClasses.sm` 的 `h-8` 同在 class 列表，胜负由**样式表源序**决定（h-8 排在
h-7 之后 ⇒ h-8 赢）⇒ 左栏全部「h-7」按钮**实际渲染 32px**，声明与实测不一致
且无声无息。第一版探针 F1a 的 `h ∈ [24,32]` 宽松区间正是把这个形态放过去的。

结构性修法（让错误状态不可表达）：尺寸冲突不许用 override 表达——
`button.tsx` 补一等尺寸 token `xs`（h-7 px-2 text-[11px]）与
`icon-sm`（h-7 w-7 p-0），TG 面板 8 处按钮全部改走 token、清掉 override
（`TgPanel.tsx` 新建钮/行尾 ✕/同步/重扫/清除检索/返回/取消监控/添加监控 +
`TgFilterPanel.tsx` 返回钮）。全仓其余域（缓存/媒体库）的同类 `h-7 px-2`
override 模式是已知边界，不在本 BUG 执行面内，留待后续。

## 验收证据

- 探针 `tauri-shell/verify/_probe_tgm04_filter_section.cjs` F1a（**精确 28×28**，
  无文字，`aria-haspopup=dialog`，边框 1px + 底色）PASS：`{"w":28,"h":28,
  "text":"","borderW":"1px","bg":"rgb(39, 39, 42)"}`；
- **反向变异**：把新建钮装回 `size="sm" className="h-7 w-7 p-0"` 坏形态 ⇒
  实测 `h:32`，F1a 如预期 FAIL（断言对「曾放跑 32px 的缺陷」有牙，非恒绿）；
- 探针 `tauri-shell/verify/_probe_tgm02_left_column.cjs` P8：主列「取消监控」
  60×28（h===28 精确判据；原 `>=28` 是给 32px 放水的判据，一并收紧）；
  同探针 ALL PASS（15 项）；
- 左栏全量实测（CDP，逐个按钮量 `getBoundingClientRect`）：动作钮
  新建 28×28 / ✕ 28×28 / 立即同步 62×28 / 重新扫描订阅 84×28 全 28px 高；
  24px 为折叠 chevron token、36/48px 为规则行/监控行行高（非动作钮）；
- 结构性修法的落点：`tauri-shell/src/components/ui/button.tsx`（`xs` /
  `icon-sm` 一等 token）、`tauri-shell/src/components/TgPanel.tsx`（8 处）、
  `tauri-shell/src/components/TgFilterPanel.tsx`（返回钮）；
- 顺带修掉 tgm02 的**恒绿缺陷**：`querySelector('aside')` 命中全局导航侧栏
  （DOM 有两个 aside），P1c/P4b/P5 三条 BUG-340/148 护栏一直在对全局侧栏
  断言 ⇒ 改为选含 `tg-filter-row` 的 TG 面板左栏后才真有牙。
