# BUG-337: 设置「通用」区块命名两套文案、默认优先级倒挂——点进去是「常规设置」，且「通用」高居「下载」之上

- 状态: open
- 发现日期: 2026-10-20
- 模块: shell
- 严重程度: mid

## 现象（用户原话，2026-10-20 第 5 点）

> 「『通用』点进去是『常规设置』，而且这部分优先级不应该高于『下载』设置，当前被设置为最高位，主次基础逻辑混乱。」

侧栏第一项写「通用」，点进去大标题是「常规设置」；且「通用」排在「下载与存储」之前，是进设置页的默认落地页。

## 根因

1. **命名两套文案未对齐**：侧栏标签 `sec.general`（`tauri-shell/src/i18n/locales/zh-CN.json:51` =「通用」）vs 区块标题 `general.heading`（同文件 `:130` =「常规设置」），无同源约束；
2. **顺序与默认锚点是 M0 重整历史遗留**：`SettingsPanel.tsx:51-59` `SECTIONS` 中 `general` 居首，`:133` `useState<SettingsSection>(section ?? 'general')` 默认落通用；文件头注释自述本阶段「只移动，不改读写」（`:40-42`），顺序问题因此被原样保留。

## 复现

打开设置页 → 落地「通用」区、标题「常规设置」；侧栏七区块顺序 = 通用 / 下载与存储 / 网络与代理 / 播放引擎 / Telegram 插件 / 共享 / 关于。

## 修复方向

- 命名统一：「通用」或「常规」二选一，侧栏标签与区块标题同源（一个 key 或派生关系）；
- 默认分区与排序把「下载与存储」提为第一/默认（具体顺序以用户拍板为准）。

判据（建议）：

- 侧栏标签与区块标题逐字一致；
- 默认落地区块 = 下载与存储（不是通用）；
- 反向证伪：恢复旧顺序/旧文案 ⇒ FAIL。

## 关联

- BUG-298 / M0-T07（「只移动不改读写」保留顺序问题的出处）

## 设计方案（2026-10-20，待用户选定；现状取证 = `SettingsPanel.tsx:51-59` + `:133` + i18n `:51/:52/:130`）

现状：侧栏第一项「通用」（`sec.general`），点进去大标题「常规设置」（`general.heading`）；默认落地 `'general'`；七区块顺序 = 通用 → 下载与存储 → 网络与代理 → 播放引擎 → Telegram 插件 → 共享 → 关于。

### 方案 A —— 命名统一 + 下载置顶（推荐）

- 命名：统一为「**通用**」，区块标题 `general.heading` 改「通用」（与侧栏同源；「常规设置」一词从界面消失）。备选统一为「常规」——但「通用」更短，侧栏 288px 等宽下不易折行。
- 顺序：**下载与存储 → 通用 → 网络与代理 → 播放引擎 → Telegram 插件 → 共享 → 关于**；默认落地「下载与存储」。
- 理由：设置页默认落在最高频决策面（目录/分类都在下载区）；「通用」收外观与行为，频次低于下载。

### 方案 B —— 只调顺序，不改名

- 保留「通用 / 常规设置」两个词，仅把 downloads 提前为第一 + 默认落地。
- 改动最小，但「点进去变了词」这个违和感原样残留。

### 方案 C —— 命名对齐 + 「通用」并入各区

- 「通用」区块取消，外观（主题/语言）并入各区头部、行为类（开机启动/通知）并入下载区——概念数 7 → 6。
- 最彻底，但改动面最大（每区都要接控件），且「设置项归哪个区」会引发新讨论。

**建议 A**：命名同源 + 下载置顶，一步解决用户点的两个症状（重名、优先级倒挂）；B 是保守排期选项，C 建议等 M0 之后整体 IA 再议。

> **与 BUG-333 的分界（用户问「333 和 337 不是同一条吗」，2026-10-20）**：
> **不是同一条。** 本档（337）改**左侧导航**（七区块命名统一 + 顺序/默认落点）；
> BUG-333 改**下载与存储区块内部**（三个目录概念分层，已定标方案 A）。

> **可一个批次落地，但缺陷各自独立、各自验收**。**337 的 A/B/C 尚未选定**（待用户答复）。
