# BUG-440: 新建筛选关键字输入框应「收缩到 + 边上 展开收起」

- 状态: fixed
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: low

## 现象

用户 2026-10-27 原话（与 BUG-439 同一句，但读法不同）：

> 文字筛选 的 过滤输入框可以收缩到 + 边上 展开收起

同一句话在登记时被 BUG-439 误读成了「节内检索框（放大镜那行）」，并把检索框做成了
`+` 旁的收起（`tg-filter-search-toggle`）。但字面「**过滤输入框**」= 新建筛选时用来
填**关键字**的那个输入框（`tg-filter-input`，`aria-label` 为「过滤关键词」），不是检索框。

该输入框此前是点 `+` 弹出的**浮层对话**（`absolute right-0 top-full`）：虽然满足「点 +
展开 / 再点收起」，但浮层会**遮挡**下方规则列表，且视觉上不贴合「收缩到 + 边上」——
它悬在 `+` 右下方、盖住内容，而不是在 `+` 所在节头下方行内展开。

## 根因

BUG-439 把「过滤输入框」与「检索框」当成同一控件来统一，实际这是两个独立输入
（`tg-filter-input` vs `tg-filter-search`），语义不同：
- `tg-filter-input`：新建一条筛选**规则**的关键字；
- `tg-filter-search`：在已有规则列表里**检索**。

BUG-439 只搬了检索框，漏了字面指向的 `tg-filter-input`。而 `tg-filter-input` 虽已「收起成
+」，却用了浮层形态，与用户要的「边上 / 行内」不符。

## 修复

- 把 `tg-filter-input` 从浮层对话改为**节头下方的行内卡片**：点 `+`（`tg-filter-new`）
  即在 `#tg-filter-list-body` 顶部展开一张含「关键字 + 显示名 + 取消/添加」的卡片，
  再点 `+` 或 Esc 收起。不再浮层遮挡列表。
- **保留**在 `tg-filter-dialog` 容器内 ⇒ 不违反验收约束「节内不得有常驻输入行」
  （输入框只在 `filterDlgOpen` 时存在）；`tg-filter-input` 仍在弹层容器内。
- 既有的 `tg-filter-search-toggle`（检索框收起）保留，与本条目同源原则。

文件：`tauri-shell/src/components/TgPanel.tsx`（节头去掉浮层 `relative` 包裹；在
`#tg-filter-list-body` 内按 `filterDlgOpen` 条件渲染行内卡片）。
