# BUG-441: `cache_task_msg_index` 去重忽略 `series_key`，无归档轴任务遮蔽筛选归档轴，同相册裂成两部剧

- 状态: fixed
- 发现日期: 2026-10-27
- 模块: engine
- 严重程度: high

> 来源：TG→剧集流程走查（Explore 子代理）锁定。是 **BUG-438 修复的回归**——BUG-438 在
> `cache_task_msg_index` 的返回里加了归档轴 `(series_key, series_hint)` 第四项，但去重逻辑
> **完全没用它**。

## 现象

`download-engine/crates/orig-tg/src/media.rs` 的 `cache_task_msg_index`（约 5754-5762 行）把每条
TG 消息映射到「它属于哪个任务」，去重时只认 `group_id`：

```rust
match map.get(&(chat, m)) {
    Some((Some(_), _, _, _)) => {}            // 已有带 group → 保留
    Some((None, _, _, _)) if group.is_none() => {}  // 已有无 group 且当前也无 group → 保留
    _ => { map.insert(...); }                 // 否则覆盖
}
```

第四条 `filing`（含 `series_key`）**完全不参与优先级**。于是：

- 任务 A「先创建」：`group_id = 11`、`series_key = NULL`（组下载，无筛选归档轴），含消息 101/102；
- 任务 B「后创建」：`group_id = 11`、`series_key = "tg:filter:7"`（筛选入库，带归档轴），含 101/102/103。

遍历按 `id ASC`：A 先 insert `(101 → (Some(11), None filing))`；B 处理 101 时命中
`Some((Some(_),_,_,_))` ⇒ **保留** ⇒ 101 的归档轴被 A 的无键 filing 遮蔽。

下游 `file_items_into_series`（5540-5550 行）从 `index` 取 `filing.0` 作显式归档轴；一旦被遮蔽，
`explicit_filing = None` ⇒ 101/102 按 `group`/caption 退化建**占位剧集**，103 走筛选剧集 ⇒
**同一相册裂成两部剧**（正常标题一部 + 占位名一部）——即 BUG-292 的形态，且破坏 BUG-438「筛选
入库归到对应剧集」的意图。

## 根因

去重优先级维度缺失 `series_key`。用户的**筛选归档轴是明确意图**（「这批内容进那部剧」），
比「组下载的退化口径」更具体，必须先于 `group` 被采纳。

## 修复

去重优先级改为 `(series_key, group)`——带归档轴的永远优先，其次带 group 的，同优先级保留先创建的：

```rust
let new_prio = (filing.0.is_some(), group.is_some());
match map.get(&(chat, m)) {
    Some((ex_g, _, _, ex_f)) => {
        let ex_prio = (ex_f.0.is_some(), ex_g.is_some());
        if ex_prio.0 >= new_prio.0 && ex_prio.1 >= new_prio.1 { continue; }
        map.insert((chat, m), (group, first, msgs.clone(), filing.clone()));
    }
    None => { map.insert((chat, m), (group, first, msgs.clone(), filing.clone())); }
}
```

`series_key` 为 `NULL`（绝大多数历史任务）时，新逻辑与旧逻辑等价（`group` 优先、先创建优先），
不引入回归。
