# BUG-168: 媒体库图片与剧集无集级关联 —— 一集无法挂自己的图，图片只能独立占集

- 状态: fixed
- 发现日期: 2026-09-24
- 模块: engine+shell
- 严重程度: medium
- 档位: standard

## 现象

用户诉求（原话语义）：媒体库中图片要跟着剧集的「集」走——一集可以挂 1..n 张图、
一张图也可以挂到多集、不同的集挂不同的图；前端剧集详情要能看到每集自己的图片。

现状是图片（photo kind 的 media_item）只能作为**独立条目**存在：要么不入集，
要么在自动成剧时各占一个集号（BUG-044 第 4 轮裁定「图片是浏览位内容」后，混编组
的照片按消息顺序被编成分集，挤占视频的集数——「第 2 集」可能是一张图）。

## 根因

数据模型没有「集级图片挂载」这一层关系：`media_episode.item_id` 是单值外键
（每集一个主内容），`media_episode_source` 是播放来源（只认 video），二者都无法
表达「一集配多张浏览图、一图可挂多集」。

## 修复

### 引擎（download-engine/crates/orig-tg）

1. **新表** `media_episode_image`（`migrate()` 幂等建表 + 索引 + 三个触发器）：
   主键 `(episode_id, item_id)`（一图可挂多集）、`sort_no` 保序、
   `trg_media_episode_image_cleanup_*` 级联清理（分集/条目删除时），
   `trg_media_episode_image_photo_only_ins` 数据层兜底「只有 photo 能挂图位」。
2. **Store 方法**：`attach_episode_images`（**replace-all**，事务内删旧插新、
   去重保序）、`add_episode_image`（幂等追加，自动路径专用）、
   `detach_episode_image`、`list_episode_images`、`episode_id_of_item`。
3. **视图**：`EpisodeView.images: Vec<EpisodeImageMeta>`（camelCase，
   空不下发）；`get_series` 组装时**一条 join 批量补齐**全剧集挂图（避免逐集 N+1）。
4. **路由**：`POST /api/media/episodes/:id/images`（replace-all 挂图；
   集不存在 404、非 photo 条目 422 附明细）、`DELETE /api/media/episodes/:id/images/:item_id`
   （幂等，`removed:0` 如实回报）。
5. **自动入库语义细化**（routes.rs 缓存任务）：组内**同时含视频与照片**时，
   照片不再各占集号，改挂到组内消息顺序中它之前最近的视频所在集的图片位
   （首个视频之前的照片归首个视频那一集）；photo-only 组保持现状（照片各自成集，
   BUG-044 浏览位语义不变）。追加式挂载（不清用户已挂的图）；历史数据不回填。

### 壳（tauri-shell）

6. `MediaEpisode.images?: EpisodeImageMeta[]` + `attachEpisodeImages` /
   `detachEpisodeImage` API。
7. 剧集详情集卡：有挂图时渲染缩略条（复用 `mediaItemUrl` resolver，与剧集图册
   同一取图路径），每张可 ✕ 摘除；集卡新增「挂图」按钮 → 图片选择对话框
   （列出 kind=photo 条目、多选；确认时把「既有挂图 + 新勾选」一起下发，
   replace-all 对用户表现为「勾选即追加」）；失败走 `onError` toast。
   i18n 键中英齐备（`media.attachImages` 等 7 键）。

```
POST  /api/media/episodes/399/images {"itemIds":[403]}     -> 200 {"ok":true,"attached":1}
POST  /api/media/episodes/400/images {"itemIds":[393]}     -> 200 {"ok":true,"attached":1}
POST  /api/media/episodes/399/images {"itemIds":[403,393]} -> 200 {"ok":true,"attached":2}   (replace-all)
GET   /api/media/series/80
        ep399 images = [(403),(393)]   ep400 images = [(393)]    ← 不同集不同图、可重复挂多集
DELETE /api/media/episodes/399/images/393                  -> 200 {"ok":true,"removed":1}
GET   回读 ep399 images = [403]                              ← 确认移除
DELETE（再删一次）                                         -> 200 {"ok":true,"removed":0}   ← 幂等
POST  非photo条目(itemId=414)                               -> 422 "only photo items can be attached..., rejected: [414]"
POST  /api/media/episodes/99999999/images                  -> 404 "episode not found"
```
