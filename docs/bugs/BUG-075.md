# BUG-075: `/src/components/TgPanel.tsx?t=...` 直连 .tsx 请求——Vite 开发服务器行为（非缺陷）

- 状态: wontfix
- 发现日期: 2026-09-20
- 模块: shell
- 严重程度: low

## 现象

用户在浏览器 DevTools Network 里看到大量形如
`http://localhost:5180/src/components/TgPanel.tsx?t=1789772963669` 的请求，疑问是：
「这些请求是干什么的？为什么可以直接请求 tsx？」

## 根因（这是预期行为，不是缺陷）

1. **端口 5180 是 Vite dev server，不是生产服务**：`tauri-shell/vite.config.ts` 固定
   `server.port = 5180 / strictPort = true`，`tauri dev` 时 WebView 直接加载这个地址。
   生产构建（`npm run build` → `dist/`）产出的是打包后的 JS，**不存在 .tsx 请求**。
2. **浏览器不认 TSX，Vite 在服务端即时转译**：dev 模式下 Vite 把每个源文件当作一个
   ESM 模块按需提供，`import` 谁就请求谁。请求 `/src/components/TgPanel.tsx` 时，
   Vite 先用 esbuild 把 TSX 转成 JS 再回包（`Content-Type: application/javascript`），
   所以网络面板看到的是 `.tsx` 路径，拿到的是转译后的 JS。
3. **`?t=<毫秒时间戳>` 是 HMR 缓存穿透参数**：修改文件后 Vite 给该模块及其引用链换
   新的 `t` 值，迫使浏览器放弃旧缓存重新拉取。数字会变 = 刚热更新过，属正常。
4. **只有 dev 模式才有**：生产包是 bundle，模块边界被抹掉，不会逐个拉源文件。

一句话：**开发态「一个源文件 = 一个 HTTP 请求 + 服务端即时转译」**，是 Vite 的核心机制。

## 复现 / 自证

```sh
curl -i "http://localhost:5180/src/components/TgPanel.tsx" | head -5
# → HTTP/1.1 200；Content-Type: application/javascript；body 已无 JSX 语法
```

`tauri dev` 未运行时该地址不可达，也侧面证明它是开发服务器而非应用后端。

## 修复

无需修复。判定依据：符合设计（Vite dev server 机制），与 `AGENTS.md` R-D「符合设计即非 bug」一致。

**需要注意的反面**：若在生产/发行包里仍见到 `.tsx` 请求，才说明打包配置错了（走了
dev server 而非 `dist/`）——那是另一个缺陷，届时另立单。
