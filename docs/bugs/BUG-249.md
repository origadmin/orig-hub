# BUG-249: 入库流水线缺少批量合规操作——大量失败无法批量重试，不合规/残留文件无法批量清理

- 状态: open
- 发现日期: 2026-10-10
- 模块: engine+shell
- 严重程度: high
- 排期: 2026-11-10

## 现象

用户原文：「入库文件缺少批量合规操作，大量失败没法重试，不合规文件删除，等等基础批量逻辑。」

入库流水线（`CacheManagerDialog`）当前只有**一种**批量动作：**批量删除记录**。
面对一批失败任务时，用户能做的一件批量事就是「把它们删掉」，而真正需要的动作一个都没有：

1. **大量失败无法批量重试**：几十条 `failed` 只能逐条点「重试」（`onRetry`），
   而失败往往是同一原因（网络中断/代理抖动），逐条点 = 不可用；
2. **无法批量取消**：排队队列想清掉/停掉一批，只能逐条「取消」；
3. **不合规文件无法批量清理**：失败任务可能已留下部分字节/临时文件，
   界面没有任何「把这些残留一并清掉」的入口，只能去回收站或文件系统里手工找；
4. 缺少「按当前筛选态作用于可操作子集」的批量动作条（选中集里混着活跃任务时，
   界面不告知哪些会被真正作用）。

## 根因

**后端只有单条动作端点 + 一个批量删除端点，前端只对接了删除这一种批量能力。**

- 后端（`/api/cache/tasks*`）：
  - `POST /api/cache/tasks/:id/retry`（`tauri-shell/src/api/tg.ts:427`）——**单条**重试；
  - `DELETE /api/cache/tasks/:id`——**单条**删除；
  - `DELETE /api/cache/tasks?ids=…`——批量删除（BUG-149，走原子端点不循环单条）。
  - **没有**批量重试、**没有**批量取消、**没有**「删记录同时清字节」的批量端点。
- 前端（`tauri-shell/src/components/CacheManagerDialog.tsx`）：
  - 选择态存在（`selectedIds`，`cache-select-row`）；
  - 但唯一的批量确认条是 `cache-confirm-batch`（:1014，删除确认，BUG-054 验收形态：
    任何删除都要确认且如实报出活跃任务数）；
  - 行内单条动作有 `重试/取消/删除`（:351/:363/:374），**没有对应的批量版本**。

即「动作存在（单条）+ 选择态存在」，但两者的**组合层缺失**。

## 复现

1. 让一批任务失败（断网或代理失效后恢复）；
2. 打开入库流水线 → 有 N 条 `failed`，界面只提供逐条重试；
3. 全选 → 唯一可用批量按钮是「删除记录」；残留字节无处清理。

## 修复方向

**补「动作 × 批量」的组合层，且遵守本仓契约（一动词一端点，差异走参数）。**

后端（新增两个批量端点，**不新造动词**）：
- `POST /api/cache/tasks/retry?ids=1,2,3`——仅对**终态**（`failed`/`cancelled`/`interrupted`）
  生效；对 `queued`/`running`/`done` 一律 **422** 并在 body 里说明哪几条不合法；
- `POST /api/cache/tasks/cancel?ids=…`——仅对活跃态（`queued`/`running`）生效，其余 422；
- 参数契约沿用既有批量删除的口径：非法/空 `ids` 一律 **422**，越界 id 不静默成功
  （参照 `/api/cache/clear` 的既有裁定）。
- 单条端点**保留**（前端行内仍用），批量端点与单条端点共用同一处理内核，**不写两份**。

前端：
- 批量动作条：选中集非空时出现，提供「**批量重试 / 批量取消 / 批量删除**」三个动作，
  每个动作**只作用于可操作子集**并**如实显示**「选中 N 条，其中 M 条可重试」
  （不可操作的不静默跳过，也不假装全部执行）；
- 「不合规文件删除」= 批量删除时提供**是否同时清理已落盘字节**的二次确认
  （沿用 BUG-054 形态：先确认 + 报出影响面，包括将删除的文件数与字节数）；
  清理只认**与这些任务关联**的文件，不得扫盘式删除；
- 判据必须成对：批量重试后任务状态由终态转回 `queued`/`running`（具体 id 列表），
  且对非法状态的批量请求返回 422（不是静默成功）。
