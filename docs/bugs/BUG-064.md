# BUG-064: Vite dev server 未监听 0.0.0.0，Tauri webview 连不上（connection refused）

- 状态: fixed
- 发现日期: 2026-08-27
- 模块: shell
- 严重程度: high

## 现象

`tauri dev` 起来后窗口白屏，控制台报 `connection refused` 指向 `127.0.0.1:5180`——
浏览器里同一个地址能打开，壳里打不开。

## 根因

Vite 的 `server.host` 未显式设置时监听行为随环境而变（默认仅绑定 `localhost` 的字面含义
在不同 Node/系统上落到 IPv4 或 IPv6 回环），而 Tauri webview 走的是 `127.0.0.1`
（IPv4）。两者落到不同协议族时，`devUrl: http://localhost:5180` 在壳内解析失败，
表现为连接直接被拒 —— 与 Vite 日志显示的「已监听」并不矛盾。

## 复现

1. 不设置 `TAURI_DEV_HOST`，直接 `tauri dev`；
2. 窗口白屏，webview 控制台报 `ERR_CONNECTION_REFUSED`；
3. 外部浏览器访问 `http://localhost:5180` 正常。

（事后追认：本条由已发生的修复提交反推登记，无当时的独立复现脚本。）

## 修复

提交 `38abc59`（`fix(tauri-shell): bind Vite dev server to 0.0.0.0 to avoid Tauri webview localhost->127.0.0.1 connection refused`）：
`tauri-shell/vite.config.ts` 的 `server.host` 改为 `host || true`（显式监听全部接口，
同时保留 `TAURI_DEV_HOST` 覆盖）。该改动当前仍在生效，属于**回归会复发**的类型。

## 验收证据

事后追认，无独立验收脚本。证据为提交本身：`38abc59`（1 file changed, 1 insertion(+), 1 deletion(-)）。
当前态复核：`tauri-shell/vite.config.ts` 仍为 `host: host || true`。
