# BUG-379: 出网路径 `/` 与 `\` 混用——代码修了（a525bc7），二进制没上线

- 状态: fixed
- 发现日期: 2026-10-22
- 模块: engine
- 严重程度: high

## 现象

用户 2026-10-22 报：「接口返回的内容路径也有问题，"/"和"\"的错误没有修复，
这点提出无数遍了。」

实测（2026-10-22 21:00，orig-tg 19787 / daemon 19786）：

| 出口 | 返回值 |
|---|---|
| `GET /api/media/items/1586` | `absolutePath = "D:/OrigDown\\.blobs\\7f\\41\\7f41fca…"`（盘上是 `D:/OrigDown/.blobs/...`） |
| `GET /api/downloads` | `dest_path = "D:/OrigDown\\bug322ui.bin"` |

## 根因

**不是没修，是修了没上线**：`a525bc7`「Normalize outbound paths to '/'」
（`orig-core::paths::to_wire`，媒体出口统一 `/`）提交于 **2026-10-22 18:19:03**，
但 `download-engine/target/release/orig-tg.exe` 的 mtime 是 **06:15**——
在跑的进程（20:37 启动）加载的是 18:19 之前的旧二进制。daemon 侧
`dest_path` 同样未经 `to_wire` 规范化。

用户视角就是「提出无数遍也没修复」：每一遍都只落在源码里，没有一次
走到「重建 + 部署 + 实测出口」这后三步。

## 修复

1. 走 redeploy 握手（`dev_services.py --redeploy-request` → build →
   `sync-sidecars.sh` → `--redeploy-done`）把含 `to_wire` 的二进制换上，
   **不停 daemon**。
2. daemon 侧下载任务出口补 `to_wire` 规范化。
3. 验收探针直接打 API 断言「出口串不含 `\`」，并对媒体/下载两个出口都验。
