# BUG-192 Telegram 置顶（pinned）频道在应用频道列表里既排不到前面、也认不出来

- **状态**: open
- **发现日期**: 2026-09-29
- **模块**: engine+shell
- **严重程度**: mid

关联 BUG-017（folder 实时修正）、BUG-179（缓存优先服务）、BUG-149（判据打在实质而非名字上）。

## 现象

用户 2026-09-29 反馈：「列表里面 Pin 的频道好像丢失不显示了」。

**「置顶」在本仓是 Telegram 自己的语义，不是应用功能** —— 全仓检索确认：前端无 pin / 置顶相关代码
与 i18n 文案（`tauri-shell/src` 零命中，`zh-CN.json` 零命中），`dialog_cache` 表无 pinned 列。
用户说的是**在 Telegram 里置顶的频道**，在本应用的频道列表里找不到。

## 根因

**置顶语义在枚举阶段就被丢了，而且丢了三层：**

1. **应用数据结构不承载置顶** —— `Channel` 只有 `{id, title, username, folder}`；
   `dialog_cache` 建表语句（`store.rs:328-334`）列为 `id / title / username / folder / init_at`，
   **无 pinned 列**。`channel_from_dialog`（`grammers.rs:888-900`）只取
   `peer().id().bot_api_dialog_id()`、`peer().name()`、`peer().username()` 加 folder 映射，
   **从不读 `dialog.pinned()`**。

2. **即便现在想读也读不到** —— grammers-client **0.10.0** 的高层 `Dialog`
   （`~/.cargo/registry/.../grammers-client-0.10.0/src/peer/mod.rs`）公开方法只有
   `from_raw` / `id` / `name` / `username` / `usernames`，**「pinned」在该文件零命中**。
   置顶位只存在于原始 TL 层：`grammers_tl_types` 的 `tl::Dialog.pinned`
   （`target/debug/build/grammers-tl-types-*/out/generated_enums.rs:3905-3908`，
   `Dialog(i) => i.pinned`）。⇒ 要走**原始 TL 调用**另取，或改用 `messages.getDialogs`
   的默认顺序（该接口本来就把置顶放在最前）。

3. **列表顺序与 Telegram 完全无关** —— `read_dialogs`（`store.rs:1317-1338`）是
   `SELECT ... FROM dialog_cache ORDER BY id LIMIT ?1 OFFSET ?2`，**按 id 升序**。
   Telegram 的顺序是「置顶在前、其余按最近活跃」，落库后**彻底丢失**。
   实测：total 519，首页 200 条 id 区间 `-1004493170102 … -1001315917022`，
   全是负 id（频道/组），顺序既非置顶序也非活跃序。

⇒ 置顶频道混在这 519 条里按 id 排的某个位置，**既不在顶部，也没有任何标识**，
用户的主观体验就是「丢了 / 不显示了」。

## 已排除（均为实测，不是推理）

- **不是缓存缺条数**：`GET /api/tg/dialogs?limit=1&refresh=1` 触发后台全量重扫，
  `scanning` True→False 走完后 `total` **仍为 519**（重扫前后一致）。
- **不是分页截断**：后端单页上限 200（`routes.rs` `limit.clamp(1,200)`），
  前端 `TgPanel.tsx:487-493` 有循环翻页（最多 10 页，按 `hasMore` 终止）。
  实测 200 + 200 + 119 = **519 个唯一 id 全部取到**，与 `total` 一致。
- **不是 id 塌缩**：`channel_from_dialog` 里 `bot_api_dialog_id().unwrap_or(0)`
  未产生 `id=0` 行（全量 519 条中 `id==0` 计数为 0），不存在多会话塌缩成一行。

## 修复

三层都要补，只补一层不算修复：

1. **取到置顶位**：枚举时走原始 TL 取 `tl::Dialog.pinned`（或依赖 `messages.getDialogs`
   的默认置顶优先顺序），`dialog_cache` 增 `pinned` 列并随 upsert 写入
   （`upsert_dialog`，`store.rs:1294-1306` 的 `ON CONFLICT` 需一并带上）。
2. **排到前面**：`read_dialogs` 排序改为「`pinned` 优先，其余按活跃/最近消息」，
   不能再是 `ORDER BY id`。
3. **看得出来**：前端列表对置顶项给可识别标识（置顶角标或分区），
   不许静默混入普通列表。

## 验收

- 用户在 Telegram 置顶的指定频道，在应用频道列表**第一屏**可见**且带置顶标识**；
- 取消置顶后该项回到普通位置（同一频道名可复验，不是一次性）；
- 判据打在**真实 API 数据**上（按频道名反查它在返回列表中的下标），
  不看「有没有 pinned 字段」这种存在性判据；
- **反向证伪**：把排序注回 `ORDER BY id`，验收脚本必须**变红**（EXIT ≠ 0）；
  证伪须自动还原并自证（`sha256` 前后一致）。
