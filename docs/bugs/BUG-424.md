# BUG-424: 合并剧集弹窗「集号规则」段英文缺空格——`fromafter` / `numberonward` 黏连

- 状态: fixed
- 发现日期: 2026-10-24
- 模块: shell
- 严重程度: low
- 影响面: 纯英文文案，中文不受影响；但英文用户读到的是病句
- 修复提交: （待提交；改动仅 i18n 文案，已在库内）

## 现象

`SeriesDialog`（合并剧集弹窗）第二步前的「集号规则」说明段，英文界面渲染为：

> Episode numbering: each season of the target continues **fromafter** the current
> highest episode number**onward** (existing numbers are never overwritten; …)

`from` 与 `after` 之间、`number` 与 `onward` 之间各缺一个空格，两个词黏连。
中文界面不受影响（`集号规则：目标各季从现有最大集号之后续编（…`，本就不需要空格）。

实测证据（`verify_bug_252_merge_dialog_i18n.cjs` ①f 的原始读数，2026-10-24）：

```
"Merging is fully automatic — …"
"Episode numbering: each season of the target continues fromafter the current
 highest episode numberonward (existing numbers are never overwritten; …)"
```

## 根因

`src/components/media/SeriesDialog.tsx:275-279` 把一句文案拆成三个 i18n 键拼接，
强调片段用 `<span className="font-medium">` 包住：

```jsx
{t('media.seriesMergeNumberPrefix')}
<span className="font-medium text-fg-mid">{t('media.seriesMergeNumberEmph')}</span>
{t('media.seriesMergeNumberSuffix')}
```

JSX 对「表达式之间仅由换行/缩进构成的空白」做**整块丢弃**（只有文本节点里的
空白才保留），于是三段被零间隔拼接。引入提交 `9b057a0`（BUG-407/408 改合并语义时
重写这套文案）：旧文案 `seriesMergeOrderHint` 是单键整句，没有拼接问题；新文案把
「集号规则」拆成 Prefix / Emph / Suffix 三键后触发了本缺陷，而当时的验收脚本
（①e/①f）只断言片段存在（`includes('the current highest episode number')`），
不断言拼接处的空格 ⇒ 缺陷漏过。

## 修复

空格是**语言相关**的关注点，归 i18n 文件管：只给 en-US 的两个键补空格
（Prefix 尾补一个、Suffix 头补一个），zh-CN 保持不变（中文不需要空格，
无条件加空格反而会在中文句子里插出两个空格）。

判据补牙（`verify_bug_252_merge_dialog_i18n.cjs`，两种语言都断言）：
- en：集号规则段必须含 `from after the current highest episode number onward`
  （三个片段被空格正确分隔）；
- zh：集号规则段必须含 `从现有最大集号之后续编`（无空格插入——
  防的就是后来者「顺手加 `{' '}`」把中文搞出空格）。

## 验收证据

**根因复核（2026-10-27）**：原判据成立，但修复早已落到库内、BUG 未关闭。两项证据：

1. `tauri-shell/src/i18n/locales/en-US.json:457-459` 的 `media.seriesMergeNumberPrefix`
   已以空格结尾（`"...continues from "`），`media.seriesMergeNumberSuffix` 已以空格开头
   （`" onward (..."`）。JSX 只丢弃表达式容器**之间**的折行空白，不丢弃字符串字面量**内部**
   的空格 ⇒ 三段拼接为 `...continues from after the current highest episode number onward`，
   `fromafter` / `numberonward` 黏连不再发生。zh-CN 三段保持零空格紧拼（`:457-459` 同样核对）。

2. 验收脚本 `tauri-shell/verify/verify_bug_252_merge_dialog_i18n.cjs` 已有反向可证伪断言：
   - ①k（en）：段落必须含 `from after the current highest episode number onward`
     且不含 `fromafter` / `numberonward`（`:293-297`）；
   - ②e（zh）：段落含 `从现有最大集号之后续编` 且不含 `从 现有`（`:342-344`）。

**结论**：缺陷现象已消除（en 侧空格已就位、zh 侧无空格插入），判据已带牙齿，状态转 `fixed`。
无代码改动需求；如需可核验运行记录，须活栈复跑该验收脚本（dev stack 由用户掌控，本回合不启）。
