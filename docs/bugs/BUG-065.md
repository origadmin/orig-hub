# BUG-065: TG 页签可见性由「插件开关」驱动而非「绑定态」

- 状态: fixed
- 发现日期: 2026-09-16
- 模块: shell
- 严重程度: mid

## 现象

TG 相关入口的显示/隐藏与实际登录状态不一致：插件开关打开但会话实际未绑定（或反之）时，
侧栏里会出现点进去什么都不能做的入口，或者已经登录却看不到入口。

## 根因

可见性判据用了**配置态**（插件开关）而不是**运行态**（是否已绑定、服务是否可用）。
配置态是用户的意愿，运行态是实际能力，两者不同步时界面就在说谎。
同类问题在后续 BUG（绑定态双向校准 BUG-012）里再次出现，说明「用什么驱动可见性」
这件事当时只改了一半。

## 复现

1. 打开插件开关但不完成 TG 登录；
2. 观察侧栏：出现 TG 入口，点入为空态（或报错）。

（事后追认：本条由已发生的修复提交反推登记，无当时的独立复现脚本。）

## 修复

提交 `f979b19`（`fix(shell): drive TG tab visibility by bound state, not plugin toggle`）：
`MainLayout.tsx` / `Sidebar.tsx` / `store/useStore.ts` 三处把可见性判据换成绑定态；
随后由提交 `f31295a` 补齐反向校准（`refreshTgSession` 双向设置绑定态，并更新 `docs/bugs/BUG-012.md`）。
