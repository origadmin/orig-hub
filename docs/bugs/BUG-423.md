# BUG-423: 16 个验收脚本仍直读 `/api/config` 旧键 `tg_port`——BUG-358 改插件契约后恒得 undefined，环境探测假红

- 状态: fixed
- 发现日期: 2026-10-24
- 模块: shell
- 严重程度: mid
- 修复提交: （待提交；脚本已双契约，无新改动）

## 现象

BUG-358 把 daemon `/api/config` 里写死插件名的 `tg_enabled` / `tg_running` /
`tg_port` / `tg_last_error` 四个键收成 `plugins: [{id, label, enabled, running,
port, lastError, health}]`（用户原话：「"tg_enabled"这些都是什么？毫无共通性…
我把TG改成BB，这个还能用吗？」）。前端 `useStore.tgServiceFromPlugins` 与
`verify/lib/_lib_endpoints.cjs` 都已双契约兼容，但**一批验收脚本仍在直读旧键**
`cfg.tg_port` ⇒ 恒得 undefined ⇒ 环境探测判「未就绪」而退出（或更糟：静默用错端口）。

BUG-422 回归时实测两例：
- `verify_bug_214_qa_independent.cjs` → `daemon /api/config 未给出 tg_port —— 环境未就绪`
- `verify_bug_214_series_bulk_ops.cjs` → 探测失败后试图 `python scripts/dev_services.py`
  二次拉起（栈已在跑）⇒ `Command failed`

## 根因

`/api/config` 的响应体自 BUG-358 起不再含 `tg_port` 顶层键；端口真源是
`plugins[]` 里 `id === 'tg'` 的 `port`（daemon 可能在保留区顺延改写它，BUG-178）。
直读旧键的脚本全部拿到 undefined。

## 修复

BUG-422 已在 `verify/lib/sandbox.cjs` 增加双契约适配器 `tgPortOf(cfg)` /
`tgRunningOf(cfg)`（plugins 优先、旧键兜底），并修掉回归集里的 7 个脚本
（bug_214_qa_independent / bug_214_series_bulk_ops / bug_251 / bug_258 /
bug_260 / bug_281 / bug_239）。

## 验收证据

**根因复核（2026-10-27）**：本回合对 `tauri-shell/verify/` 全量脚本复核 `tg_port` / `tg_running` /
`tg_enabled` / `tg_last_error` 的引用。结论：BUG-358 改插件契约后，登记条目里描述的
「16 个脚本直读旧键 ⇒ 恒 undefined ⇒ 环境探测假红」**已不再成立**——这些脚本彼时已被改为
**双契约**（先读 `plugins[]` 里 `id='tg'` 的 `port`，旧键 `tg_port` 仅作兜底）：

- `tauri-shell/verify/verify_bug232_ingest_title.cjs:33`：`plug && Number(plug.port) > 0 ? Number(plug.port) : Number(d.tg_port) > 0 ? Number(d.tg_port) : null`
- `tauri-shell/verify/verify_bug300_ingest_aggregation.cjs:83`、`:86`
- `tauri-shell/verify/verify_bug318_unavailable_window.cjs:156`、`:159`
- `tauri-shell/verify/verify_bug316_segment2_render.cjs:70`、`:73`
- `tauri-shell/verify/verify_bug329_monitor_filters.cjs:312`、`:313`
- `tauri-shell/verify/verify_bug323_single_root.cjs:202`
- `tauri-shell/verify/verify_bug233_about_tg.cjs:48-56`（`plug ? plug.enabled : d.tg_enabled` 同形）

`sandbox.cjs` 另提供 `tgPortOf(cfg)` / `tgRunningOf(cfg)` / `tgEnabledOf` 集中适配器
（`:394`/`:409`/`:475` 导出），供后续统一收口用。

**结论**：旧键已非「唯一真源」，双契约下不会因 `tg_port` 缺失而假红；缺陷现象消除，状态转 `fixed`。
少数脚本（如 `tauri-shell/verify/verify_bug_133_e2e_drop.cjs:72`、`tauri-shell/verify/verify_bug_133_disk_occupancy.cjs:112`）
**刻意**向 stub 注入 `tg_port` 以验证前端回落逻辑——
属设计内行为，不改动。如需把内联双契约统一替换为 `tgPortOf` 适配器的收口工作，属整洁性改进，
非缺陷修复，可另立轻量档。
