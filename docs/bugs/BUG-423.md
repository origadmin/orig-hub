# BUG-423: 16 个验收脚本仍直读 `/api/config` 旧键 `tg_port`——BUG-358 改插件契约后恒得 undefined，环境探测假红

- 状态: open
- 发现日期: 2026-10-24
- 模块: shell
- 严重程度: mid

## 现象

BUG-358 把 daemon `/api/config` 里写死插件名的 `tg_enabled` / `tg_running` /
`tg_port` / `tg_last_error` 四个键收成 `plugins: [{id, label, enabled, running,
port, lastError, health}]`（用户原话：「"tg_enabled"这些都是什么？毫无共通性…
我把TG改成BB，这个还能用吗？」）。前端 `useStore.tgServiceFromPlugins` 与
`verify/lib/_lib_endpoints.cjs` 都已双契约兼容，但**一批验收脚本仍在直读旧键**
`cfg.tg_port` ⇒ 恒得 undefined ⇒ 环境探测判「未就绪」而退出（或更糟：静默用错端口）。

BUG-422 回归时实测两例：
- `verify_bug_214_qa_independent.cjs` → `daemon /api/config 未给出 tg_port —— 环境未就绪`
- `verify_bug_214_series_bulk_ops.cjs` → 探测失败后试图 `python scripts/dev_services.py`
  二次拉起（栈已在跑）⇒ `Command failed`

## 根因

`/api/config` 的响应体自 BUG-358 起不再含 `tg_port` 顶层键；端口真源是
`plugins[]` 里 `id === 'tg'` 的 `port`（daemon 可能在保留区顺延改写它，BUG-178）。
直读旧键的脚本全部拿到 undefined。

## 修复

BUG-422 已在 `verify/lib/sandbox.cjs` 增加双契约适配器 `tgPortOf(cfg)` /
`tgRunningOf(cfg)`（plugins 优先、旧键兜底），并修掉回归集里的 7 个脚本
（bug_214_qa_independent / bug_214_series_bulk_ops / bug_251 / bug_258 /
bug_260 / bug_281 / bug_239）。

stub 里**注入** `tg_port` 来验「前端用 daemon 下发端口覆盖初值」——前端现已改读
`plugins[]`，这两条判据要么改注入 `plugins`，要么明确记录「契约已变、判据重锚」。
