# BUG-390: 文字筛选命中数在无监控频道时全 0，被读成「数据全没了」

- 状态: fixed
- 模块: shell (TgPanel 侧栏)
- 发现日期: 2026-10-23
- 严重程度: 中
- 报告: 用户 2026-10-23 03:57 截图 + 原话「数据全空了」——侧栏「文字筛选」4 条规则全部显示「0 条」且「监控中」为空。

## 现象

TG 域侧栏：4 条文字筛选规则命中数全部 0 条；「监控中」空（暂无监控频道）。用户据此判断全部数据丢失。

## 取证（数据未丢，三层实证）

- 库 `Roaming\com.origadmin.orighub\tg\store.db`：media_message 8658 / media_item 589 / monitor_filter 4 全在。
- 接口 `/api/tg/monitor/filters` 正常返回 4 条规则（含 hits 字段）。

## 根因

`store.rs count_filter_hits / count_filter_new_hits` 的 SQL `JOIN monitored_channel`——**命中数只统计「监控中」频道的消息**（行为被单测 `filter_ignores_unmonitored_channels` 钉死，是有意设计）。监控列表为空 ⇒ 所有关键词命中恒 0。而 UI 对这个 0 没有任何作用域解释，铁律「取不到 ≠ 没有」的反面：**0 被渲染成了没有数据**。

监控列表为空的来源是另一件事：当前栈数据目录（Roaming）里 monitored_channel 在本轮接手前已为空（01:39 首查即空，见 2026-10-23 日志），用户旧监控配置在旧栈数据目录 `%LocalAppData%\OrigHub\tg\store.db`——双数据目录分裂，另案处理。

## 修复（最小可见性）

无监控频道且存在筛选规则时，筛选节内渲染一条作用域提示（`tg-filter-scope-hint`）：命中数只统计监控中频道、当前无监控频道所以全部显示 0。让 0 自带解释，不改计数语义。

  - S1（stub `/api/tg/monitor/channels`→`[]`，URL 参数 `?probe390=1` 门控）：筛选规则行=4（真实端点，未被 stub）、`tg-filter-scope-hint` 可见且文本含「监控」、监控区空态成立。
