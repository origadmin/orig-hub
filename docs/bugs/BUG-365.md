# BUG-365: 剧集详情页「N 集」把集级挂图算进集数，与剧集卡口径互相矛盾 ⇒ 用户判定「1 个文件丢失」

- 状态: fixed
- 发现日期: 2026-10-22
- 模块: engine+shell
- 严重程度: high

## 现象

用户 2026-10-22 复报（原话）：

> 「4. 现在内容丢失,入库内容丢失. 时停手表EP1-3 原档观享 连载中 -> 视频3,下载2,图片1,其中1个文件丢失.」

真栈取证（`GET /api/media/series/486`，标题 `🌟⚡️🔥《时停手表》EP1-3 原档观享 连载中 ⭐⭐⭐`）：

| 事实 | 值 |
|---|---|
| `episodeCount` | **3** |
| `videoCount` | 2 |
| `photoCount` | 1 |
| `episodes[]` 实返 | **2 条**（item 1586 / 1587，均 `kind=video`） |
| item 1586（EP1） | `bytesPresence: present`，238,614,792 B，**在盘** |
| item 1587（EP2） | `bytesPresence: present`，193,659,037 B，**在盘** |
| item 1259（EP2 的挂图） | `bytesPresence: missing`，`filePath: null`，`title: "TG 图片 #3265"` |

**没有任何视频内容丢失。** 两个视频的字节都在盘上。

## 根因

三层叠加，全部是**计数与呈现**问题，不是数据问题：

1. **`episodeCount` 的口径含挂图**（`media.rs:2697-2703`，BUG-255 设计）：`COUNT(DISTINCT item_id)` 取 `media_episode ∪ media_episode_image`。本剧 = 2 视频 + 1 张挂在 EP2 上的集级挂图 = **3**。该设计对「1 预告片 + N 海报」的相册是对的，但把它当成「集数」显示就会误导。
2. **详情页与剧集卡口径互相矛盾**：`SeriesCard.tsx:222-243` 已在 BUG-220 修为「视频 N · 图片 N」，而 `SeriesDetail.tsx:631` 仍渲染 `media.episodeCount`（`{n} 集`）⇒ 同一部剧，卡片说「视频 2 · 图片 1」，详情页说「3 集」。**一个剧两个数**，用户无从判断哪个对。
3. **第 3 项在界面上不可见为一行**：挂图只作为 EP2 展开态里的一张 88×120 小瓦片存在，左栏选集器只有 2 行。用户按「3 集」去找第 3 集，找到 2 行 + 1 张说不清用途的小图 ⇒ 判定「其中 1 个文件丢失」。

**附带澄清（不构成缺陷）**：item 1259 的 `bytesPresence: missing` 是 **BUG-049 的设计**——「图片 = 浏览条目（`media_item` kind=photo，`file_path=NULL`），永不下载落盘；浏览字节由 raw 端点现场代理 TG 缩略图」。所以挂图没有 `file_path` 是正常态，不是丢失。BUG-296 §复报补充也为下载域的 `gap` 立了同型红线（「先减挂图：图集是设计，不是丢失」），但**剧集级的 `episode_count` 从来没做同样的减法**——这就是本次误判的入口。

## 修复

`tauri-shell/src/components/media/SeriesDetail.tsx`（`series-meta` 行）：

- 与 `SeriesCard` **同源**：优先渲染 `player.mixedCount`（`视频 {v} · 图片 {p}`，复用既有 i18n 键，不新增），视频数可与左栏选集器行数一一对上；
- 老后端不下发 `videoCount`/`photoCount` 时退回原 `media.episodeCount`（不编造 0）。

**不做的事（及理由）**：不改后端 `episode_count` 的 SQL 口径。它服务的是「相册集数」这个语义（BUG-255 修的就是它），改了会把 BUG-255 的回归引回来；正确做法是**显示层选对字段**，与 BUG-220 在卡片上已经做过的一致。

## 验收证据

真栈实测（CDP 探针 `tauri-shell/verify/_diag_20261022_report.cjs`，dev 栈）：

- 修复后 `series-meta` 文本 = **「剧集 · 视频 2 · 图片 1 · 1 季」**（修复前为「剧集 · 3 集 · 1 季」）；
- 左栏选集器实有 **2 行**（item 1586 / 1587，均 video）⇒ 与 meta 里的「视频 2」一一可对上；
- 同一探针里剧集卡的 `series-content-kinds` 与详情页同为「视频 2 · 图片 1」口径 ⇒ 同一部剧一个数；
- 右栏区块顺序（`data-zone`）：`header` y=160 → `primary` y=196 → `secondary` y=280；`episode-play` y=196、高 36px ⇒ 播放仍在主区首位（BUG-350 不回退）。

入库：`tauri-shell/src/components/media/SeriesDetail.tsx`（提交 `4d49c9f`）。
判定脚本：`tauri-shell/verify/_verify_bug365_series_count.cjs`（G1–G5，含 `--expect-legacy` 反向证伪）。

**字节侧复核（证明「没有丢失」）**：`GET /api/media/items/{1586,1587,1259}` ⇒ 1586 `bytesPresence: present`（238,614,792 B，文件在盘）、1587 `bytesPresence: present`（193,659,037 B，文件在盘）、1259 `bytesPresence: missing` + `filePath: null` —— 后者是 BUG-049 的设计态（图片永不落盘，浏览字节由 raw 端点现场代理 TG 缩略图），不是丢失。

## 关联

- BUG-255：`episode_count` 含挂图的设计来源（本登记不改其口径，只改显示选段）；
- BUG-220：剧集卡同口径修复（本登记把详情页对齐到它）；
- BUG-049：图片永不落盘 ⇒ 挂图 `file_path=NULL` 是设计，不是丢失；
- BUG-296：下载域 `gap` 已立「先减挂图」红线，剧集级计数缺同款处理。
