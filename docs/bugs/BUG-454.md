# BUG-454: TG 频道行 ICON 未取真实头像，fallback 成标题首字母

- 状态: in_progress
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: mid
- 排期: 2026-10-30（阶段二：真头像端点）

## 现象

TG 面板频道行头像显示为标题首字母（实测出现「【」「琼」等首字符），没有拿到频道真实头像。
在 fd 模式下状态栏也要收敛 TG 监控态，头像缺失会让状态栏频道识别项同样退化成字母占位。

## 根因

1. `TgChannel` 类型（types.ts:250-253）只有 `id/title/username?/folder?`，**无 `photo` 字段**；
   后端 `GET /api/tg/dialogs` 响应当前不返回频道头像 URL。
2. 前端无字段可渲染，TgPanel 频道行用首字母兜底：
   `(ch.title || '?').charAt(0).toUpperCase()`（TgPanel.tsx:2369 / 2854 / 2901）。
   标题含装饰括号时即渲染成「【」，用户判定「ICON 不对」。

## 复现

- 进入 TG 面板 → 任一已登录账号的频道列表 → 频道行圆形头像显示首字母而非真实图标。

## 修复

**阶段一（已落地）**：兜底只取「可辨识字符」——新增 `components/TgAvatar.tsx`
（头像**唯一渲染点**），`channelInitial()` 先剥离开头的空白/标点/符号
（`/^[\p{P}\p{S}\p{C}\s]+/u`），再取首字符；剥完为空（整标题都是装饰）兜到 `#`，
**绝不退回原串首字符**（那正是「【」被当头像的路径）。`TgPanel` 三处 fallback
（监控行 / 频道行 / 详情头）全部换成 `<TgAvatar>`，不再有散落副本。

**阶段二（待排期，需 orig-tg 侧改造）**：真实头像。
- orig-tg：枚举 dialogs 时把 `ChatPhoto.photo_small` 的 `InputFileLocation` 记进内存
  （**零额外 RPC**，信息已在枚举结果里），新增 `GET /api/tg/avatar/:chat_id`，
  复用 thumb 的三级缓存（内存 LRU / 落盘 / 同 key 合并）+ 并发闸门，取不到按 404 降级（thumb 同纪律）；
- 协议：`Channel` 增 `hasPhoto`（枚举时零成本判定，避免无头像频道反复打 404）；
- 前端：`TgAvatar` 在 `hasPhoto` 时渲染 `<img src="/api/tg/avatar/:id">`，`onError` 回落到阶段一兜底。
  **只改这一个组件**，三个调用点不动（阶段一已把渲染点收敛到这里）。
- 阻塞项：本机无已登录 TG 会话，端到端取头像无法自证 ⇒ 需 UAT 或先备登录态。

## 关联

- BUG-194（title 空串 → 渲染成空白行，与首字母兜底同源「无真实标识」问题）。
- fd 模式底部状态栏重构（本回合主任务）会把 TG 监控态收入状态栏，头像缺失会连带退化。
