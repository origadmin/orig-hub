# BUG-461: 无用的常驻占位说明应改为「带圈功能按钮」——点击后短时高亮，不常驻

- 状态: open
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: low
- 排期: 2026-12-26

> 来源：用户报告「**无用的占位说明能不能采用 功能按钮带圈的？点击后短时间显示高亮，
> 而不是常驻？**」（用户标注：优先级不高）

## 现象

编辑/空态界面上有一批**常驻说明文案**，它们不是数据、不是控件，却长期占据版面：

1. `EpisodeEditPanel.tsx:138` —— `media.episode.editAffectsAll`（改写范围说明），
   每次打开编辑面板都占一行。
2. `EpisodeEditPanel.tsx:191` —— `media.episode.endHintRow`（结束集号说明），
   常驻在槽位行末尾，与三个数字框同行，挤压输入区。
3. `ImportDialog.tsx:103-105` —— `media.import.desc`（对话框头部整段说明）。
4. `i18n/locales/zh-CN.json:214` —— `media.emptyHint` 空态长说明（约 90 字），
   在没有任何内容时占住整屏主区。

## 根因

1. **说明与控件同级常驻。** 现有规则只管到「说明文案不允许出现在行态、只允许在
   面板内」（R11，`EpisodeEditPanel.tsx:13-14` 注释），但没有管「面板内是否可收起」
   ⇒ 说明从行态搬进面板后依然常驻，只是换了个占地方的位置。
2. **说明的读者是「第一次遇到的人」**，而常驻呈现让它对所有人一视同仁地收版面税：
   看过一次之后它就是纯噪音。
3. 没有统一的「说明」组件 ⇒ 每处各自手写 `<p className="text-[10px] text-muted">`，
   形态、字号、位置都不一致，无法一次性调整策略。

## 复现

1. 文件管理 → 剧集 → 展开任一分集 → 「编辑本集」。
2. 观察：面板顶部一行小字说明常驻；槽位行末尾另一句说明常驻，与输入框同行。
3. 关闭再打开 ⇒ 说明再次出现（无「已读」概念、无收起态）。

## 修复方向（未实施；≥2 实质选项 + 1 个「不做」）

### 选项 A（推荐）：统一「ⓘ / ? 带圈按钮」，点击后浮出说明并短时高亮

- 抽出 `HintBubble` 组件：默认只显示一个带圈图标按钮（直径 ~14px，`aria-label`
  走 i18n）；点击后在按钮旁浮出说明气泡，**短时高亮**（建议 5s）后自动淡出，
  或点击别处即刻消失；键盘可聚焦、可再次唤出。
- `涉及:` 新增 `components/ui/HintBubble.tsx`；改造
  `EpisodeEditPanel.tsx:138 / :191`、`ImportDialog.tsx:103-105`、`media.emptyHint` 落点；
  i18n 复用既有键（不新增语义，仅新增 1 个 aria 键）。
- `量化:` 版面省下每条说明 1 行（编辑面板实测省 ≥2 行）；新增 1 类 testid。
- `回归风险:` 低 —— 文案内容不变，只是呈现从「常驻」变「按需」；
  既有 `data-testid` 若绑在说明节点上需保留（改为气泡内容节点，id 不变）。
- `后果:` 说明仍在（不丢信息），但不收常驻版面税；与用户诉求逐字一致。

### 选项 B：常驻说明改为默认收起的「说明」折叠行

- 文案旁放一个「说明」小字开关，点击展开，再点收起（状态不记忆）。
- `涉及:` 同上各落点，新增 1 个折叠组件（比 A 少一个浮层概念）。
- `量化:` 每条省 1 行 + 1 个开关常驻 12px。
- `回归风险:` 低。
- `后果:` 比 A 多占一个常驻开关，且没有「短时高亮自动消失」，用户可能忘了收起。

### 选项 C：只删掉最冗长的两条（空态长说明 + 编辑面板顶部说明）

- `涉及:` 2 处删除 + i18n 键保留不用。`量化:` 省 2 处。
- `回归风险:` 低。
- `后果:` 信息丢失，第一次用的用户没有解释 —— 与「不丢能力」判据冲突。不推荐。

### 选项 D：不做

- `涉及:` 无。`量化:` 0。`回归风险:` 无。
- `后果:` 说明继续常驻占版面（用户已标注优先级不高，可接受延后）。
