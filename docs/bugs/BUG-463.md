# BUG-463: 详情态工具条整行只放一个「← 返回」，与面包屑重复且白占一行版面

- 状态: open
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-26

> 来源：用户报告「**返回按钮占用了文件管理的一整行，非常浪费空间，需要重新设计排布。**」

## 现象

1. 文件管理主区工具条 `MediaLibraryPanel.tsx:1417`（`<header className="flex shrink-0
   flex-wrap items-center gap-2 border-b px-3 py-2">`）在**详情态**只渲染一个控件：
   `← 返回`（`:1421-1438`，`data-testid="series-back"`）。
   行高 = `py-2`(16) + `h-7`(28) ≈ 44px（含 1px 分隔线），整行服务一颗按钮。
2. 同一屏上方的上下文栏**已经有面包屑**「文件管理 › 剧集 › 《剧名》」
   （`shell/ContextBar.tsx` 的 `ViewTitle`，`:96-97` 由 `filesCrumb` 拼出，
   BUG-409 补的层级）⇒ 导航语义重复，两条路都能回上一级。
3. 详情态下这条工具条的其余槽位全空（排序下拉只给 `view === 'items' && tab !== 'all'`，
   `:1444`），从视觉上就是「一整行只放了一个返回」。

## 根因

1. **返回被当成「工具栏控件」单独占栏。** `:1418-1420` 的注释写明裁定是
   「返回是页面导航 ⇒ 属工具栏作用域」，但详情态工具栏没有第二个控件，
   于是「作用域正确」与「版面浪费」同时成立。
2. **同一文件里已经写过相反判据却没有应用到详情态**：`:1441-1443` 明写
   「只剩一个控件的整行就是『多余的栏』」（当初据此撤掉了 cat-all 的排序行），
   详情态 header 是同一形态却未被同一判据覆盖。
3. **导航入口重复**：面包屑（ContextBar）+ 返回按钮（Panel header）两条，
   增加了一条需要维护的布局契约，也让用户多一个「哪个才是返回」的判断。

## 复现

1. 文件管理 → 剧集 → 打开任一部剧集进入详情。
2. 观察：内容区顶部一整行（≈44px）只居中/左置一个「← 返回」；
   上方上下文栏同时显示「文件管理 › 剧集 › 剧名」。
3. 内容区可用高度比列表态少一整行。

## 修复方向（未实施；≥2 实质选项 + 1 个「不做」）

### 选项 A（推荐）：撤掉详情态工具条，返回并入左栏总览卡动作行

- `MediaLibraryPanel.tsx:1421-1438` 的返回按钮移到 `SeriesDetail` 左栏总览区顶部
  （与 `series-play-all` 等动作同排，`:747` 的 `flex flex-wrap gap-1.5`），
  详情态 `<header>` 整条不渲染。
- `涉及:` `MediaLibraryPanel.tsx`（删 1 段）+ `SeriesDetail.tsx`（左栏顶部加 1 颗按钮，
  需要新增 `onBack` prop 或从 store 取）。`量化:` 内容区 +44px 可用高度。
- `回归风险:` 中 —— `series-back` testid 必须保留（验收脚本依赖），
  只是宿主组件变更；需重跑引用它的 verify 脚本。
- `后果:` 返回落在实体表面（与剧集级动作同排，符合「实体操作不上提到工具栏」的
  既有裁定），且不再单独占栏。

### 选项 B：保留返回，但把它并进上下文栏面包屑（面包屑可点返回）

- `ViewTitle`（`ContextBar.tsx:72-97`）的「剧集 › 剧名」做成可点击返回，
  删除面板 header 的返回按钮。
- `涉及:` `ContextBar.tsx` + `MediaLibraryPanel.tsx`（删 1 段）。`量化:` +44px。
- `回归风险:` 中 —— 面包屑点击语义需与 store 的 `filesCrumb` 生命周期对齐
  （下钻写入、返回清空）。
- `后果:` 导航唯一入口在面包屑，符合 Web 惯例；但「返回」不再是显式按钮，
  可发现性略降。

### 选项 C：保留整行，把详情态常用控件补进这一行（让它不再是「一个控件的行」）

- 把「播放全部 / 编辑」等高频动作上提到该行（**与「剧集实体操作不上提到工具栏」
  的既有裁定冲突**）。
- `涉及:` `MediaLibraryPanel.tsx` header + 动作分组设计。`量化:` 0 高度收益。
- `回归风险:` 高 —— 与 BUG-465（按钮入口混乱/库级与实体级混排）方向相反。
- `后果:` 版面不浪费但制造新的作用域混乱。**不推荐**，列出以说明边界。

### 选项 D：不做

- `涉及:` 无。`量化:` 0。`回归风险:` 无。
- `后果:` 详情态永久少一整行可用高度，导航入口继续双份。

## 关联

- BUG-409（fixed）：上下文栏面包屑层级 —— 本档方案 B 的前提。
- BUG-465（open）：文件管理按钮入口混乱 —— 本档移返回按钮须与该档的分组方案一并设计。
- BUG-317 / BUG-451：库级动作组与上下文栏版面判据。
