# BUG-457: 频道回溯无进度，应按天分配并显示读取/回溯进度

- 状态: partial
- 发现日期: 2026-10-27
- 模块: engine+shell
- 严重程度: high
- 排期: 2026-11-03

## 现象

1. 频道回溯（backfill）发起后，界面**完全看不到进度**——用户点了「回溯到 1 月」之后毫无反馈，
   只会以为按钮没生效（用户原话：回溯功能进度没有，应该按天分配；读取进度也没有）。
2. 现有 `TgMonitoredChannel` 只有 `backfillUntil`（目标日期）与 `backfillBeforeId`（已翻到的最新消息号），
   二者都不是「按天」粒度，前端无法呈现「已回溯 X 天 / 共 Y 天」或「读取进度 %」。

## 根因

- **后端**：`POST /api/tg/monitor/backfill` 只登记 `untilDate` 目标，后台 tick 每轮每频道翻一页，
  但进度只以「消息号游标」暴露（`backfillBeforeId`），没有按天切片，也没有「已完成天数 / 总天数」口径。
- **前端**：状态栏监控下拉目前只显示 `backfillUntil` 目标（`statusbar.monitorBackfill`），
  没有进度维度；用户自然觉得「没反应」。

## 修复（设计契约，待排期实施）

### 后端（engine）
1. backfill 任务按**目标日期 → 今天**切成 N 个「天桶」（`day_buckets: [{date, status}]`），
   每轮翻页推进时标记对应天桶为 `done`；游标 `backfillBeforeId` 推进到该天桶边界即算该天完成。
2. `GET /api/tg/monitor/channels` 的 `TgMonitoredChannel` 增加：
   - `backfillTotalDays: number`（目标日期距今天数）
   - `backfillDoneDays: number`（已完成天数）
   - `backfillReading: boolean`（当前是否正在读取/翻页中——「读取进度」的实时态）
   - 保留 `backfillUntil` / `backfillBeforeId` 作为底层游标。
3. 服务端 `backfill` 表加 `total_days` / `done_days` 两列（幂等重算，重启可续）。

### 前端（shell）
1. 状态栏监控下拉的回溯行改为显示：`回溯至 {date} · {doneDays}/{totalDays} 天`
   + 当 `backfillReading` 为真显示「读取中…」（对应「读取进度也没有」）。
2. 若 `totalDays>0 && doneDays===totalDays` → 显示「回溯完成」。

## 关联

- BUG-382（回溯「已回溯至哪」真值缺失，仅 `backfillBeforeId` 半解）—— 本 BUG 从「天粒度」彻底补完。
- BUG-294（入库任务无逐条状态，黑盒）—— 同族「进度不可见」问题，本 BUG 解决回溯侧。
- D4.2（用户 2026-10-27 裁定：回溯现在就排，按天分配进度）。
