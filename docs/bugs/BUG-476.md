# BUG-476: 「自本集起顺延」批量控件错置于单集编辑面板——概念错位、UI 污染

- 状态: fixed
- 发现日期: 2026-10-28
- 模块: shell
- 严重程度: mid
- 排期: 2026-10-28

> 来源：用户报告「剧集编辑页面怎么又多了个什么：自本集起顺延 莫名奇妙的东西？
> 很多都是因为这个乱加乱写，然后 BUG 无限堆叠。」

## 现象

1. 打开任一分集的「编辑本集」面板（`EpisodeEditPanel.tsx`），在**本集编辑区**（标题 /
   介绍 / 挂图 / 槽位）下方，多出一组与本集编辑无关的东西：
   - 一行 `自本集起顺延 [顺延位数 ▢] 位 [批量应用（N 集）]`。
   - 它的作用是**整季批量重编号**——把「同季、集号 ≥ 本集」的所有分集整体后移 N 位，
     一次点击经壳层串行 `patchEpisode` 改写 N 条集的集号。
2. 用户编辑**某一集**时，面板里突然冒出「批量重编号整季」的工具，既无序列编辑上下文，
   也无「将影响 N 集」的强确认（仅 `title` 悬停提示），极易误点改写整季编号。
3. 这与 `EpisodeEditPanel.tsx:8-19` 自身写明的契约冲突——该组件是**单集编辑面板**：
   标题 + 介绍 + 槽位（季号/集号/结束集号）一次提交，**只编辑本集**。

## 根因

1. BUG-460 的原始诉求是用户问「季号 / 集号 / 多集编辑是不是更人性化一点」，其修复方向
   **选项 A（推荐）是独立序列编辑面板**（一次看到全部集、批量应用），选项 B 是单集面板内
   加「本剧槽位占用预览 + 撞号预告」。
2. 实际落地时，之前 agent 把**整季批量重编号**直接塞进了单集编辑面板（BUG-460 的「验收证据」
   段写进了 `shiftFrom` / `shiftApply` 等键），既没做独立序列面板，也没止步于单集内的预览——
   把面向「序列」的命令混进了面向「单集」的容器。这是**职责错位的乱加**，正是用户所指的
   「莫名奇妙 + 乱加乱写」。
3. 概念错位带来真实隐患：单集面板里一颗「批量应用」点下去即对整季 N 集发起 N 次改写，UI 无
   强确认、无影响范围清单——是「BUG 无限堆叠」的典型温床（误操作 → 数据错乱 → 再修）。

## 复现

1. 文件管理 → 任一部 ≥3 集的剧集 → 展开某集 → 「编辑本集」。
2. 在编辑面板**底部**看到 `自本集起顺延 … 位 批量应用（N 集）` 控件。
3. 它不属于「编辑这一集」，却与标题/介绍/挂图/槽位并列呈现。

## 修复方向（已实施）

### 已做：从单集面板移除错位控件，恢复契约纯粹性

- 删除 `EpisodeEditPanel.tsx` 中的批量顺延控件（`episode-shift-*` 块）、相关死代码
  （`shift` state、`shiftTargets` 计算、`shiftFromHere` 函数），以及两个语言包里 5 个
  无用 i18n 键（`shiftFrom` / `shiftBy` / `shiftUnit` / `shiftHint` / `shiftApply`）。
- 单集面板恢复为只编辑本集：标题 / 介绍 / 挂图 / 槽位（季号/集号/结束集号），符合其契约注释。
- 保留单集面板内**贴合单集语义**的辅助（撞号预告 `episode-slot-conflict`、本剧槽位一览
  `episode-slots` 折叠预览）——它们是改号前「预先看见撞谁」的选项 B 范畴，不污染序列操作。

### 待拍板：批量重编号能力不应消失，但必须换位置

- BUG-460 的**需求**（多集编辑更人性化）是用户提出、合理的；错的是**实现位置**。
- 正确落点 = BUG-460 选项 A：**独立的「编辑集号」序列面板**（本剧序列表格，就地改多行、
  一次应用、提交前可见影响范围与撞号结果），作为 SeriesDetail 的独立入口，而非藏在单集面板。
- `涉及:` 新增 `EpisodeSlotsEditor.tsx`；引擎若要做批量端点（`PATCH .../episodes:slots`）
  可降级为串行提交（BUG-460 已明列该路径）。

## 关联

- BUG-460（fixed）：本档所修的错位即源于其落地阶段把序列操作塞进单集面板；需求本体保留、
  待以选项 A 正确实现。
- BUG-153（fixed）：结束集号语义——序列面板的归一化规则必须复用其口径。
