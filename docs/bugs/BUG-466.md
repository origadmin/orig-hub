# BUG-466: 下载主列表误用 /api/downloads/native（引擎单源）而非统一 /api/downloads（全来源）—— BUG-392 回归

- 状态: in_progress
- 发现日期: 2026-10-27
- 模块: engine+shell
- 严重程度: high
- 排期: 2026-10-30

## 现象

用户在运行态实测发现：下载面板周期性发出 `GET /api/downloads/native`（来自 `useStore.refresh()`），
而非统一的 `GET /api/downloads?scope=...`。此前对 #9 的答复称「UI 走统一 `/api/downloads`、native
仅供调试」与实测不符——UI 主列表确实在调 native。

## 根因

### 真根：native 端点是统一改造时**自造**的分裂端点

`GET /api/downloads/native` 不是原始设计遗留，而是提交 **`eedd515a`**（2026-10-23
06:09，BUG-392「统一下载端点」那一轮）引入的：该提交同时造出 `list_unified`
（`/api/downloads`）与 `list`（`/api/downloads/native`），并把后者注释为
「engine-native projection / 调试·详情投影，非 UI 列表路径」。

**即：我在把列表统一成单一端点的同时，又造了第二个列表端点，并把主列表
`useStore.refresh()` 接到了它** —— 这才是 BUG-466 的源头。所以修复必须是
**删除 native**，而不是「把它降级保留作调试投影」：保留等于把错误状态继续留在
系统里，违反「让错误状态不可表达」，且下次仍会被接回主列表。

下载列表为**双源拼装**，两个端点各说一半，违反 BUG-392「下载只有一个列表接口」的裁定：

1. 引擎段：`DownloadPanel` 的 `items` prop = `store.downloads`，由
   `useStore.refresh()`（`useStore.ts:519`）经 `listDownloads()`（`daemon.ts:61`）
   调用 `GET /api/downloads/native` 填充。该端点（`routes.rs:131` `list()`）只回**引擎行**
   （`engine_rows`，仅原生引擎任务）。
2. 入库段：`DownloadPanel` 的 `ingestRows` 来自 `useIngestGroups`（`useIngestGroups.ts:197`）
   经 `fetchDownloads('all')`（`daemon.ts:521`）调用 `GET /api/downloads?scope=all`，
   回**全来源合并** `ActivitySnapshot`（引擎 + TG + BT）。

由此：同一个下载列表，引擎行走 native、入库行走 unified，等于 BUG-392 当年要灭掉的
「两个 endpoint 各说一半」重现。

### 代码内部注释自相矛盾（根因的元层）
- `routes.rs:766` 明确规定 native 是「**调试/详情投影，非 UI 列表路径**」；统一接口是 `/api/downloads`。
- `daemon.ts:55-59` 反向注释称「速度/分块等引擎原生字段只有 native 才有，store 必须取这一支」——
  **与代码事实相反**：统一端点的 `ActivityTask`（`activity.rs:200-220`）**已含 `speed: Option<f64>`
  与 `progress: f64`**，原生字段并未丢失。该注释是 native 残留调用的错误合理化依据。

## 复现

1. 起 dev 栈，打开下载面板；
2. 网络面板可见周期性 `GET /api/downloads/native`（useStore 轮询）与 `GET /api/downloads?scope=all`
   （useIngestGroups 轮询）并存；
3. 引擎任务数 == native 端点行数，入库任务数 == unified 端点 `tasks` 中 `cache` 类行数。

## 修复

**删除 native 分裂端点，把引擎原生细节并入统一列表**（单一端点即完整真源）：

1. 引擎 `activity.rs`：给统一视图 `TaskView` 增加引擎原生细节字段（`url`/`destPath`/
   `totalSize`/`downloaded`/`connections`/`eta`/`avgSpeed`/`addedAt`/`timeTaken`），
   在 `download_views()` 由 `EngineRow` 填充；`cache_view` 与测试夹具填诚实缺省。
2. 引擎 `routes.rs`：**删除** `GET /api/downloads/native` 路由与 `list()` 处理器
   （原生端点不再存在；`DownloadStatus::from_row` 仍由 `/api/downloads/:id` 使用，未孤立）。
3. 前端 `daemon.ts`：`listDownloads()` 由 `/api/downloads/native` 改为
   `fetchDownloads('all')`，过滤 `kind === 'download'` 的行并映射回 `DownloadStatus`
   （剥掉 `dl:` 前缀，保住引擎动作端点吃原生 id 的契约）；下游 `store.downloads` /
   `DownloadItem` 字段契约不变，无需改面板。
4. 验收脚本 `verify_bug392_unified_downloads.cjs`：原 U2「native 仍是引擎投影」改为
   「统一列表 download 行自带 destPath」+ 新增 U2b「native 已 404」。
