# BUG-456: 文件管理侧栏分类子项无状态数字

- 状态: in_progress
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: mid
- 排期: 2026-10-30

## 现象

文件管理侧栏各分类子项（视频 / 图片 / 音乐 / 文档 / 压缩包 / 其他）旁无状态数字，
用户无法一眼看出各类有多少内容，判定「文件管理分类状态数字丢失」。

## 根因

1. 侧栏分类子项只渲染 label、不渲染 count（Sidebar.tsx:255-270 的视频/图片等 `nav-child-*`
   按钮整段无 `{counts.xxx}` 输出）。
2. 下发到侧栏的计数对象仅含 `files / series / tags / downloading / paused / completed`
   （MainLayout.tsx:47-51 初始化 `filesCounts`、290-300 构造 `counts`），**无 per-category 计数字段**。
3. `FilesPanel` 通过 `onCounts` 上报的 `SidebarCounts` 也只含 `files/series/tags`，无分类粒度。
   → 分类数字没有真源，自然无处可显。

## 复现

- 进入文件管理 → 侧栏「视频 / 图片 / 音乐 / 文档 / 压缩包 / 其他」各行均无数字徽标。

## 修复

真源 = 分类视图**自己那一份**按 kind 的统计（`GET /api/media/stats` 的
`videos/photos/audios`）—— 不另起计数链路，避免又一处「两个答案」：

1. `nav/index.ts`：`SidebarCounts` 增 `byCategory?: Record<string, number>`；
   **缺键 = 该分类无真源**，与「值为 0 = 确认没有」严格区分。
2. `MediaLibraryPanel.tsx`：上报 `byCategory`（`video←videos` / `image←photos` /
   `music←audios`），并把三项 kind 计数并入 `countsKey`（变了才推）。
3. `MainLayout.tsx`：只中转 `byCategory`，不另算。
4. `Sidebar.tsx`：分类子项（video 行 + 其余分类 map）在有值时渲染数字，
   `0 / 缺键` 一律不渲染。

**已知边界（不是缺陷，是数据源现状）**：`doc / archive / other` 三类**没有真源** ——
媒体库只登记 `video/photo/audio` 三种 kind，非媒体文件不在 `media_item` 里
（BUG-299 已标「文件管理 = 全量受管字节」的设计违反）。故这三类**保持无数字**，
而不是拿 0 冒充。要它们有数，须先推进统一文件视图（计数真源切到 daemon
`/api/files` 的 `category` 聚合，那里六类齐全）。

## 关联

- BUG-125 / BUG-133（占用/计数口径不清，须先定「数什么」再渲染）。
- 统一文件管理视图立项（媒体库与下载成品合并展示，分类计数须跨两源汇聚）。
