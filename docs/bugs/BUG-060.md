# BUG-060: 图片（分集）没有归属建模，剧集图册只能在一条平铺行里浏览

- 状态: open
- 发现日期: 2026-09-19
- 模块: engine+shell
- 严重程度: high

## 现象

图片是以**分集**身份进入剧集的（`media_episode` 行，`kind='photo'`），但剧集详情把全剧集的
图片收成一个数组、用一条横向行平铺展示：

- `tauri-shell/src/components/media/SeriesDetail.tsx`：`photoEps` 收集全部 photo 分集，
  容器是 `<div className="flex gap-2 overflow-x-auto pb-1" data-testid="series-gallery">`；
- 每个缩略图只有 `data-testid="series-gallery-item"`，**没有任何分组结构**。

于是合并多个剧集之后，不同视频各自的图片被混在同一条行里：看不出哪张图属于哪个视频/哪一集，
图片多了只能横向拖到天荒地老。用户诉求是「合并后不同视频的不同图片要能分别浏览」。

## 根因

**图片与视频的归属关系没有被建模**。数据层只有「图片是一条分集」这一事实，
没有「这批图片随哪个视频/哪一集一起发布的」这一事实，界面自然只能平铺。

数据其实**已经存在**但没被利用：TG 相册同批发布的媒体共享 `group_id`
（`download-engine/crates/orig-tg/src/store.rs` 的 `media_message.group_id`，以及
`cache_task.group_id`），而 `media_item` / `media_episode` 都没有承接这个键 ——
批次信息止步于流水表，进不了媒体库模型，前端无从分组。

## 复现

1. 在 TG 里分两批发：第 1 批 = 1 个视频 + 3 张图；第 2 批 = 1 个视频 + 2 张图；
2. 缓存后各自成剧，把两个剧集合并；
3. 打开合并后的剧集详情：图册是 5 张图的一条平铺行，无法分辨哪 3 张属于第一个视频；
4. 点进任一视频播放：图片灯箱在**全部 5 张**里翻页，而不是该视频自己的那 3 张。

## 修复

待实施。方案见 `docs/design/ROUND9-DESIGN-EVAL.md` 第 4 节：把相册批次键从流水表
透传到媒体库（`media_item.album_group`），按「同批视频」建立图片归属；
图册改为按归属分组浏览（分组头 + 组内横向滚动），播放器灯箱的翻页范围收敛到当前集所属分组；
无归属图片进「未分组」组而不是被丢弃。

## 验收证据

未修复，暂无。修复后必须提供：①造数（第 1 批 1 视频 + 3 图、第 2 批 1 视频 + 2 图）
后断言分组计数逐字相等（3 / 2 / 总计 5）；②播放第 2 个视频时灯箱页数 = 2 且逐张命中该组；
③无归属图片落在「未分组」，总数守恒（分组计数之和 == 总图片数）。

## 方案修订（2026-09-19，用户裁定：图片存 hash）

用户第 1 问：「图片最好存 hash，因为很可能不同的消息指向同一图片」——**已实测证实**：

| 指标 | 实测值 |
|---|---|
| `kind='photo'` 条目 | 27（26 条有字节） |
| SHA-256 唯一值 | **22** |
| 重复组 | **4**（`149+157`、`150+158`、`151+159`、`152+254`） |
| 另有 | 视频 `34+35` 共用一个 554 KB 文件 |

即 **8 条记录只对应 4 张图**。故方案在「按 `album_group` 派生归属」之外，
**必须增加内容寻址层**：`media_item.content_hash` + 索引 + 浏览层同 hash 只展示一次
（组内其余折叠为「另有 N 处引用」，可点开看到引用它的消息）。

**新增不变量（必须与 hash 同批实现，不允许先上 hash 后补）**：
多条记录共享同一 `file_path` 之后，`DELETE /api/cache/items/:id` 与
`DELETE /api/media/items/:id` 在 `unlink` 之前**必须**查引用数；`count > 1` 时只解绑、
不删文件，并如实回报 `{unlinked, sharedWith}` —— 否则「删一条重复图片」会删掉
仍在被引用的文件，比多占几 MB 严重得多。

完整方案（四层：内容寻址 → 归属派生 → 分组浏览 → 删除引用计数）见
`docs/design/ROUND9-DESIGN-EVAL.md` §4。
