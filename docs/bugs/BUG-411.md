# BUG-411: 集统计错误——多集视频未按区间计数、重叠未去重

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: engine+shell
- 严重程度: high

## 现象
剧集的「集数」统计错误：实测 7 集视频却显示 19 集。即使有 19 个视频文件，也只应算 7 集。
计数规则应为：多集视频（如 1-3）按 3 集计算；不同区间/单集若有重叠需去重——例如
1-3、3、4 合并去重后为 4 集（1,2,3,4）。当前统计把视频文件数当集数、未展开区间、
未对重叠集号去重。

## 根因（实测定位）
「19」并非 19 个视频文件。实测 `store.db` 的 sid=485「未命名视频 #1574」= **7 个视频分集
（S1E1–E7，无区间、无多源）+ 12 张集级挂图**（`media_episode_image`：E1 挂 5、E2 挂 5、
E3/E4 各 1）。旧 `list_series_filtered` 的 `episode_count` 是
`COUNT(DISTINCT item_id)`（分集条目 ∪ 集级挂图）⇒ 7 + 12 = 19。

第二处（区间）实测 sid=118「50 元买断人妻」：8 个分集行覆盖 **15 个集号**（含合集
`episode_no_end`），旧口径只数行/条目 ⇒ 显示 9，规则要求展开为 15。

旧口径两个错误：① 把**集级挂图**当集数（BUG-255 旧口径，与 BUG-411 冲突）；
② 只数行/条目、**不按 `episode_no..episode_no_end` 展开**，也不对重叠集号去重。

## 修复
用户 2026-10-23 裁定：**集级挂图不计入集数**——集数只回答「有多少集」，图由
`photo_count` 表达（卡片本就并列展示 `videoCount · photoCount`，图不会被吞掉）。
改动在 `download-engine/crates/orig-tg/src/media.rs`：
- `list_series_filtered` 的 `episode_count` SQL 列改为占位 `0`（保持列序）；
- 循环后调用新增的 `episode_number_counts()`：把 `media_episode` 的
  `episode_no..=COALESCE(episode_no_end, episode_no)` 展开、按 `(season, 集号)` 去重取大小；
- 集级挂图（`media_episode_image`）、多源（`media_episode_source`）均不计；单行区间
  展开上限 10_000 集，防脏数据区间撑爆内存；
- `get_series` 复用 `list_series()` 的 `SeriesView`，随之修正，无第二处计算点。

## 复现
- 单测 `bug411_episode_count_expands_ranges_and_dedupes`：1-3 合集 + 单集 3 + 单集 4
  ⇒ `episode_count == 4`；
- 修订后的 `bug255_mixed_group_counts_gallery_photos_as_episodes`：1 视频 + 3 挂图
  ⇒ `episode_count == 1`、`photo_count == 3`。
