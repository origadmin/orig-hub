# BUG-220: 入库流水线只显示频道不显示内容，无法知道入库的是什么

- 状态: open
- 发现日期: 2026-10-09
- 模块: engine+shell
- 严重程度: high
- 排期: 2026-11-10

## 现象

用户原文：「入库流水线有严重问题，显示频道而不是内容，导致完全无法知道具体的入库内容是什么。」

打开「入库流水线」（`CacheManagerDialog`）后，每一行形如：

```
[已入库]  频道名 · 成组 · 3 条
```

只有**频道名 + 条目条数**。当同一频道有多批入库时，屏幕上是一排长得一模一样的「同一个频道 · N 条」，
用户无法判断某一行对应哪几条内容、这批东西到底进没进、失败的那批是哪一批内容。

## 根因

1. **前端只渲染频道维信息**（`tauri-shell/src/components/CacheManagerDialog.tsx:234-237`）：
   `titleOf(task.chatId) ?? 频道 {chatId}` + `单条/成组` + `N 条`。任务对象里没有任何内容字段可用。
2. **后端任务行确实不带内容**（`download-engine/crates/orig-tg/src/store.rs:151` `CacheTask`）：
   只有 `chat_id` / `group_id` / `item_key` / `message_ids` / `total` / `done` / `status`。
   `GET /api/tg/cache/tasks/all`（`routes.rs:1208`）只额外注入了 `itemBytes`/`itemBytesTotal`
   （`task_with_progress`），**没有注入任何标题**。
3. **内容其实已经在库里，只是没被带出来**：BUG-170 已把登记前移，缓存 T0 就
   `upsert_media_item(source="tg", ref="{chat}:{msg}", title=…)`（`routes.rs:1764` 附近），
   `media_item` 表有 `title`/`kind`（`media.rs:224-238`），且已有 by-ref 查询能力
   （`/api/media/items/by-ref`）。缺的不是数据，是**任务端点没有把标题带出来**。

## 复现

1. 起 daemon + orig-tg（`scripts/dev_services.py`）；
2. TG 面板对同一频道分别缓存两批（一批 1 条视频、一批 3 条图片）；
3. 打开「入库流水线」→ 两行都只显示「<同一频道名> · N 条」，无法分辨内容。

## 修复方向（结构性，非加一列穷举）

- **后端**：`list_all_cache_tasks` 用**一次 `IN` 查询**按 `ref = "{chat}:{msg}"` 批量取
  `media_item.title/kind`，注入 `itemTitle` / `itemKind`（禁止前端按行 N 次 by-ref 请求 —— 500 行
  就是 500 个请求）。整组任务取首条消息的标题，并保留条数。
- **前端**：行内**内容标题为主**、频道降为次级（`标题 · 频道名`），多条目显示「<首条标题> 等 N 项」；
  拿不到标题时必须如实显示可辨认的回退（消息号 `#msg`），**禁止渲染成空串或纯频道名**。
- 契约约束：新增字段一律可选（老库/未登记条目没有），缺失即回退，不得让空值变成「未知」。
