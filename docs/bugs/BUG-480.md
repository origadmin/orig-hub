# BUG-480: 剧集标签选择器重设计——弹出标签堆无组织逻辑

- 状态: open
- 发现日期: 2026-10-28
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-04

> 来源：用户 2026-10-28 逐条裁决 BUG-478 时的内容级问题：
> 「本剧标签逻辑更乱，上面弹出一大堆标签，毫无逻辑性。」
> 同日二次裁决（BUG-478 二次记录）：卡片级「本剧标签」按钮 + 顶部独立标签编辑条
> 已整体拆除（`SeriesEditPanel` 本就含 tags，R10 一次提交；原标签条的「保存」
> 从未提交过）——标签编辑唯一入口 = 编辑面板。**本档承接选择器本身的重设计**。

## 现象

1. 编辑面板里的标签选择区渲染一大堆平铺标签，无分组、无组织、无搜索定位，
   标签一多就是「标签堆」。
2. 已选态与未选态视觉区分弱，勾了什么、影响什么不直观。
3. 标签与内容的对应关系（这个标签覆盖哪些剧）在选择时不可见。

## 根因

- `TagPicker` 按标签全量平铺渲染，是「实现最省事」的形态，不是「用户可理解」的形态。
- 选择器没有复用库级标签云已沉淀的组织规则（BUG-259 排序 / BUG-068 零计数不渲染 /
  BUG-405 紧凑筛选框），两处形态割裂。

## 修复方向（待拍板后实施）

1. 按语义分组（或至少按片数降序 + 名称序，对齐 BUG-259 口径），超过阈值收起/展开。
2. 提供搜索框（对齐 BUG-405 标签筛选框同一视觉语言），标签多时可定位。
3. 已选态清晰化：已选标签前置/置顶分区，勾选计数即时可见。
4. 零计数标签不渲染的规则（BUG-068）在选择器侧同步适用，不给必空入口。

## 关联
