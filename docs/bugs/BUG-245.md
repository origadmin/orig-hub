# BUG-245: 播放器常驻「已切换实时转码兼容流」横幅——stream-first 成为默认路径后，UI 仍把「走转码流」当异常播报

- 状态: fixed
- 发现日期: 2026-10-10
- 模块: shell
- 严重程度: mid

## 现象

- 打开任意视频，播放器顶部**常驻**一条横幅：
  「浏览器不支持该视频编码，已切换实时转码兼容流（首次转码需要片刻，之后秒开）」。
- 常驻 = 不自动消失、无关闭入口、不随播放稳定而撤下，整段观看期间压在画面上；
  逐条浏览时每条视频都出现同一条（用户观感即「大量同类污染提示」）。
- 关键误导：「浏览器不支持该视频编码」在**多数条目上并不成立**——浏览器解得动，
  只是产品选择走服务端转码流。文案把「我们的实现选择」说成了「浏览器的缺陷」。

## 根因

**B-1 直接根因：横幅的可见性判据是「当前在用兼容流」，而 stream-first 之后该条件恒真。**

- `tauri-shell/src/components/MediaViewer.tsx:222` 对每个视频条目无条件提供
  `compatSrc={mediaItemStreamUrl(cur.messageId)}`。
- `tauri-shell/src/components/media/VideoPlayer.tsx:619` `streamFirst = Boolean(compatSrc && compatSrc !== src)`
  → 有 compatSrc 即为真；`:629` `const [usingCompat, setUsingCompat] = useState(streamFirst)`
  → **挂载即 `usingCompat === true`**。
- `tauri-shell/src/components/media/VideoPlayer.tsx:1244-1251` `{usingCompat && …}` 渲染
  `data-testid="player-compat-banner"`，常驻显示 `player.compatStream`。

**B-2 为什么它会恒真**：BUG-230（2026-10-09 用户拍板）把播放主路径翻转为 **stream-first**
——挂载即取服务端转码流，raw 退役为下载/导出端点，不再「先试原始流、解不动再降级」。
横幅原本是为「降级发生了」这一**异常事件**设计的；异常消失后判据没跟着改，
于是「默认路径」被当成「例外」播报——**把实现细节当成用户需要知道的事件**。

**B-3 设计层原则（本条要立的规矩）**：用户可见的常驻提示只服务两件事——
① 用户需要行动（可重试 / 可换播放器 / 可改设置）；② 影响使用且无法自行恢复（真失败）。
「本条视频走哪条传输路径」两条都不是：用户既不能据此行动，它也不是失败。
冷启动等待已由既有缓冲转圈覆盖，无需再配文字。

## 复现

打开任一视频条目（媒体库或 TG），横幅立即出现并全程不消失。

## 修复

- 删掉 `VideoPlayer.tsx` 的 compat 横幅渲染块（含 `player-compat-banner` 测试锚点）；
  `usingCompat` 状态保留（换档 effect 仍依赖它）。
- 删除 i18n 键 `player.compatStream`（`zh-CN.json` / `en-US.json` 各一处）。
- 保留真失败呈现：`fatal` 遮罩与 `halted` 停载遮罩不动（那两条是 B-3 的 ②）。
- 冷启动转码等待由既有 `isBuffering` 转圈承载，不新增文案。
- 同步清理已失效的历史断言：`tauri-shell/verify/verify_compat_stream.cjs` 中依赖该横幅的
  A/B 判据（其「先原始流 → 再切兼容流」前提已被 BUG-230 作废）。

## 关联
