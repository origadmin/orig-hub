## 现象

1. **没有诊断面**：ffmpeg 解没解到、什么版本、支不支持硬解、当前生效配置是什么，用户与排障者都看不到。
2. **无可设置项**：`ffmpeg.path` / `ffmpeg.hwaccel` / `ffmpeg.device` 无处配置，
   优先级（env > 持久化 > auto 探测）无定义。
3. **缺失时错误不可行动**：转码请求打到缺失的 ffmpeg 上得到 5xx/裸错误，
   而非「未安装 → 去设置安装/指定路径」的可行动文案。
4. **无受管安装**：用户要自己去找静态构建、手动放路径。

## 根因

- ffmpeg 以**隐式外部依赖**形态存在于转码泵里：能跑就跑，不能跑就报错，无显式「能力探测」层；
- 生效配置没有单一真源（auto/off/指定后端/指定显卡四态未建模），
  因此也无法回答「这次转码到底用了什么」。

## 复现

1. 环境无 ffmpeg（或 `PATH` 拿不到）→ 播放转码流 → 观察错误形态（5xx / 裸错误，无可行动下一步）；
2. 已装 ffmpeg → 设置内无任何 ffmpeg 区块；`/api/config` 无 ffmpeg 生效值；
3. 双显卡机器 → 无选择项。

### 出口判据

1. 干净环境一键安装（含代理）、篡改校验失败**不留残文件**、离线安装三种路径各一次证据；
2. 双卡命令行证据（四态：auto / off / 指定后端 / 指定显卡，每次转码实际命令行断言）；
3. `ffmpeg -version` 回读一致；重启后配置保留（单测）；
4. ffmpeg 缺失时 UI 给出「去设置」可行动文案（501 语义对齐），**不是 5xx 裸错误**；
5. **反向证伪**：令解析路径为一个不可执行文件 → 诊断端点必须 `ok:false` 且带原因，绝不允许 5xx。
