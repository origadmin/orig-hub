# BUG-467: 文件管理与正式内容之间有一条空白条；剧集过滤标签在「没有可筛内容」时仍占位

- 状态: fixed
- 发现日期: 2026-10-27
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-26

> 来源：用户报告「**现在文件管理和正式内容之间有一条未知的空白条，占用了一部分空间，
> 功能没有的时候剧集的过滤标签仍然显示，这个位置的问题需要看下。**」

## 现象

1. **未知空白条**：上下文栏（`shell/ContextBar.tsx`，显示「文件管理 › 剧集 › 剧名」）
   与正式内容区之间有一条**既无控件也无文字**的横向条带，占用版面。
2. **过滤标签空转**：剧集的过滤标签（标签云）在没有可筛内容时仍然显示并占位
   （剧集墙为空 / 当前筛选结果为空 / 该视图下过滤根本不起作用）。

## 根因（候选点，需 CDP 实测确认其一或全部）

### 候选 1：`<header>` 在剧集墙态**整条为空**

`MediaLibraryPanel.tsx:1417-1462`：

```tsx
<header className="flex shrink-0 flex-wrap items-center gap-2 border-b border-border-subtle/60 px-3 py-2">
  {view === 'seriesDetail' && detail ? (<Button … >← 返回</Button>) : null}   /* :1421 */
  {view === 'items' && tab !== 'all' ? (<select … />) : null}                  /* :1444 */
</header>
```

两个条件在 **`view === 'series'`（剧集墙）** 下都不成立 ⇒ 整条 header 只剩
`py-2`（上下各 8px）+ `border-b`（1px）≈ **17px 空白带**，位置恰好在上下文栏与内容区之间。
同一文件里已经写过相反判据却没应用到这一态：`:1441-1443`
「只剩一个控件的整行就是『多余的栏』」—— 这里连一个控件都没有。

### 候选 2：标签云只绑 `view`，不绑「有没有可筛的东西」

`MediaLibraryPanel.tsx:1470-1600`：`{view === "series" && (<>…</>)}` 内部渲染
筛选 pill（`media-tag-filter-wrap` `:1478`、`media-tag-filter` `:1482`）与标签云
（`media-tag-list` `:1500`），还有「展开/收起」（`media-tag-toggle` `:1584`）。
门控只有 `view === 'series'`，**没有**「`series.length > 0` / 有内容可筛」这一层 ⇒
剧集墙为空态（`:1739` `series.length === 0`）时，标签条仍然占一行。
而在 `items` / `seriesDetail` 视图它整体不渲染 ⇒ 视图切换时「有时有、有时没有」，
用户感知为「该有的时候没有、不该有的时候还在」。

### 判据同源

`ContextBar.tsx` 注释已确立过同类判据（BUG-131）：**「恒渲染但恒无效等于控件撒谎」**
—— 一个对当前上下文不起作用的过滤控件，与一个点了必空的入口是同一种缺陷。

## 复现

1. 文件管理 → 剧集墙（未进入任何一部剧集）。
2. 观察上下文栏正下方：一条无按钮、无文字的横向条带（候选 1）
   —— 与上下内容之间只有一条分隔线。
3. 在库里没有剧集（或筛选结果为空）时观察：标签 pill 与标签云仍渲染（候选 2）。
4. 切到「内容」视图 / 进入剧集详情 ⇒ 标签条整体消失（同一控件两种存在性）。

## 修复方向（未实施；≥2 实质选项 + 1 个「不做」）

### 选项 A（推荐）：无控件即无栏 + 过滤控件按「可筛内容」门控

- `MediaLibraryPanel.tsx:1417` 的 `<header>` 在无任何子控件时不渲染（与 `:1441-1443`
  已有判据一致，一控件 = 多余栏，零控件 = 不该存在的栏）。
- 标签云块（`:1470`）增加门控：`series.length > 0`（或有可筛结果）才渲染；
  空态由 `:1739` 的空态分支承担，不再叠加一排无效过滤器。
- `涉及:` `MediaLibraryPanel.tsx` 2 处（约 6 行）。
- `量化:` 剧集墙态回收 ≈17px + 标签行（约 28~32px，实测确认）。
- `回归风险:` 低 —— 不删 testid（空态下不渲染 ≠ 删除能力）；
  需确认验收脚本没有在空库状态下断言 `media-tag-list` 存在。
- `后果:` 版面还给内容；过滤控件只在真能过滤时出现。

### 选项 B：保留栏位，把详情态的返回 / 剧集墙的过滤并进这一行

- 剧集墙态把标签 pill 移进 header（header 有内容 ⇒ 不再是空白条），
  空态时 header 仍不渲染。
- `涉及:` `MediaLibraryPanel.tsx:1417` + `:1472-1499` 搬家。`量化:` 版面净省一行的高度。
- `回归风险:` 中 —— 与 BUG-463（详情态返回占整行）相邻，两档须同一版式一起改，
  否则改完又出现「一控件一栏」。
- `后果:` 栏位复用（有内容才存在），但改动面比 A 大。

### 选项 C：只修空白条，不动标签云

- 仅做候选 1（header 无控件不渲染）。
- `涉及:` 1 处。`量化:` ≈17px。`回归风险:` 低。
- `后果:` 空白条消失，但「空库仍显示过滤标签」仍在。

### 选项 D：不做

- `涉及:` 无。`量化:` 0。`回归风险:` 无。
- `后果:` 每个视图顶部永久有一条不明用途的条带；空库时过滤控件继续空转。

## 修复后必须满足（可证伪判据，预先声明）

1. 剧集墙态：上下文栏与内容区之间**不存在**无内容的横向条带
   （CDP 实测该区域高度 ≤ 内容区首个容器的 padding，且无 `border-b` 空节点）。
2. 库内无剧集 / 筛选结果为空时，`media-tag-list` **不渲染**（`querySelector` 返回 null）；
   有剧集时照常渲染 —— 反向证伪：把门控去掉（恢复候选 2 现状）后本判据必须 FAIL。
3. `media-tag-filter` / `media-tag-list` / `media-tag-toggle` 三个 testid 的
   **定义不删除**（空态不渲染 ≠ 删能力，BUG-149）。
4. 与 BUG-463 一并验：详情态不得以「一控件一整行」的形式复现同一问题。

## 关联

- BUG-463（open）：详情态工具条整行只有一个「← 返回」—— 同一文件、同一类版面判据。
- BUG-131：恒渲染但恒无效 = 控件撒谎（本档候选 2 的判据来源）。
- BUG-456（open）：侧栏分类计数无源 —— 若标签云改为「按可筛内容门控」，计数口径同源。
- BUG-458（open）：添加目录 + 对账 —— 空库态的呈现由那一档决定内容何时不再为空。

## 验收证据
剧集墙态那条零控件的 header 不再渲染（空白条消失）；过滤标签在没有可筛内容时不占位。

落点 `tauri-shell/src/components/MediaLibraryPanel.tsx`（header 条件渲染、标签云按可筛集合判空）。
反向证伪：把 header 改回无条件渲染，空白条与空标签位同时回来。
