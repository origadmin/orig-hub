# BUG-052 退役触发器未 DROP：升级库上图片分集被拒 → 剧集建成却 0 分集（静默数据丢失）

- **严重级**: critical / silent-data-loss
- **状态**: fixed（2026-09-19 已验收）
- **报告轮次**: 2026-09-19 第六轮（用户第 6 项：「剧集没有正确抓取图片作为浏览，也缺少图片浏览位」）

## 现象

用户第 6 项要求「图片能作为剧集的浏览位内容归档」。代码层已放宽（新增
`trg_media_episode_media_only_ins`，放行 `video|photo`），**单测 34/34 全绿**，
但真实库上图片**永远不会成为分集**：

| 取证 | 事实 |
|---|---|
| `media_series` id=69 | `title='🌟⚡️《我把兄弟变母狗》EP1…'`（第 4 轮的 caption 首行逻辑生效了）、`description` 也正确取自 caption 正文 |
| `SELECT * FROM media_episode WHERE series_id=69` | **零行** —— 剧集建成但 0 分集 |
| `media_item` 383 / 384 | 图片条目**已入库**（`kind='photo'`），且 `tags=7` —— 但**不在任何剧集里**（孤儿） |
| API `GET /api/media/series/69` | `episodeCount=0`、`episodes=[]` —— 用户看到「一部点进去什么都没有的剧」 |
| 全库扫描 | 10 个剧集**无一**含 `kind='photo'` 分集（图片归档能力 0 覆盖） |

即：**失败被伪装成成功** —— 剧集建出来了，内容没进去，日志之外无任何提示。

## 根因

`media.rs::migrate()` 用 `CREATE TRIGGER IF NOT EXISTS` 新增了放宽版触发器，但**从不 DROP 旧的**：

```
trg_media_episode_video_only_ins   ← 遗留：WHEN kind IS NOT 'video' → RAISE(ABORT)
trg_media_episode_media_only_ins   ← 新增：WHEN kind NOT IN ('video','photo') → ABORT
```

两套**同时存在**于升级库里，INSERT 图片分集时旧的先 ABORT。

`CREATE TRIGGER IF NOT EXISTS` 只防「重复创建**同名**对象」，**不会让另一个名字的旧触发器失效**。
所以这是一个**只在「旧库 → 新代码」路径上暴露**的缺陷：

| 路径 | 旧触发器 | 结果 |
|---|---|---|
| 全新库（所有单测 / CI） | 不存在 | 图片分集一路绿灯 → **34/34 全绿也测不出来** |
| 用户升级库（真实场景） | **仍在** | 图片分集被 ABORT → 空剧集 |

## 二次缺陷（失败被吞）

`routes.rs` 成剧段原本对 `append_episodes_ranged` 的错误**只写日志**，`sid` 照常返回：

```rust
Err(e) => st.push_log(&format!("cache task {task_id}: append episodes: {e}")),
...
Some(sid)   // ← 剧集已建、0 分集，却当作成功返回
```

于是「建剧失败」与「建剧成功」在调用方不可区分，空剧集被留在库里。

## 修复

1. **退役触发器显式 DROP（根因）** —— `media.rs::migrate()` 在建新触发器**之前**执行：

   ```sql
   DROP TRIGGER IF EXISTS trg_media_episode_video_only_ins;
   DROP TRIGGER IF EXISTS trg_media_episode_video_only_upd;
   ```

   迁移是幂等的（`Store::open` 每次都会跑），故对已升级库与全新库都收敛到同一状态。
   注意 `media_episode_source` 的 `*_video_only_*` **保留不动** —— 播放源仍然只认 video
   （这是本轮唯一合法的硬门）。

2. **空剧集回滚（让失败不可表达）** —— `routes.rs` 新建剧集分支改为：
   挂载失败**或** `n == 0` 即回滚该剧集（`delete_series`）并如实记日志，返回 `None`。
   依据：新建的剧集**没有既存分集可跳过**，故 `n == 0` 与报错同义 ——
   二者都只能是归档失败。留下空剧集等于把失败伪装成成功。

   > 不用「启动期删除所有 0 分集剧集」兜底：UI 有「+ 新建剧集」，空剧集可能是**用户意图**。
   > 精确的处置是在**成剧这一步内**回滚，而不是事后无差别清扫。

3. **迁移单测（补上唯一漏网路径）** —— 新增
   `media::tests::upgrade_drops_superseded_video_only_episode_trigger`：
   全新库 → 装回旧 `video_only` 触发器（复刻升级库）→ 重新 `Store::open` → 断言图片能成为分集。
   无此项修复时该测试必然失败。

## 教训

- **凡「放宽/替换既有契约」的 schema 变更，必须同时 DROP 被替换的旧对象。**
  `CREATE ... IF NOT EXISTS` 的幂等性只覆盖同名对象，**不同名的遗留学生物不会被它清理**。
- **单测全绿 ≠ 真实库正确**：所有测试都跑在全新库上时，「旧库 → 新代码」这条迁移路径
  零覆盖。这正是项目既有规约「凡 schema 变更必配『旧库→新代码』迁移单测」要防的情形 ——
  本轮第 4 轮放宽分集时漏了它。
- **失败不得只写日志**：`push_log` + 照常返回 `Some(sid)` 让调用方无法区分成败。
