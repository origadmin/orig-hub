# BUG-392: 下载域未按共识统一——列表两个端点、状态变更两个域，`/api/downloads` 只剩遗留 mock 夹具

- 状态: fixed
- 模块: engine+shell
- 发现日期: 2026-10-23
- 严重程度: high
- 报告: 用户 2026-10-23 04:25 原话「为什么下载/downloads还是返回bug322ui.bin一个数据? 和之前确定的完全不一样,不论插件下载,原生下载,BT下载,最终体现的都是统一的一个API接口,状态另一个接口,这是之前确定的共识吧. 为什么没修复」。

## 现象

`GET /api/downloads` 返回 1 条 `mock://bug322ui.bin`（BUG-322 遗留夹具）。用户按共识检查该端点，看到的不是「全部下载」的统一列表。

## 根因（三条，均为「共识未落地」）

1. **列表未统一**：`/api/downloads` = daemon 引擎原生面（只含 HTTP 直下/mock/BT 单文件）；统一聚合面是另一个端点 `/api/activity`（含 TG 插件入库 + 引擎）。UI 只请求 `/api/activity`，`/api/downloads` 因此长期挂着 1 条夹具无人使用。
2. **状态变更未统一**：写操作按 `control` 分流两个域 —— 引擎行走 daemon `/api/downloads/:id`，TG 入库行走 **orig-tg** `/api/tg/cache/tasks/:id`（削/重试/优先），UI 直连两个服务；BUG-077 五铁律把这种分流写成「架构裁定」，于是共识被降级成「口径澄清」（见 `docs/design/download-activity-api-contract-2026-10-22.md`：结论写「都不是缺陷」）⇒ 用户诉求从未进入实现队列。这是本次「说必记、记必改」未兑现的直接原因：记录在案的是「不需要改」。
3. **夹具残留**：BUG-322 验收建的 `mock://bug322ui.bin`（32MiB，已完成）未清理，成为用户眼中该端点的全部内容。

## 共识（用户裁定，本次落地）

- **一个列表接口**：`GET /api/downloads?scope=all|active` 返回全部来源（插件/TG 入库、原生引擎、BT）的统一行 + `sources` 健康度。
- **一个状态变更接口**：`POST /api/downloads/:id?action=…` 与 `DELETE /api/downloads/:id`，按行 id 前缀（`dl:` / `tg:`）**服务端分流**到对应侧；UI 只认这个入口，不再直连 orig-tg。TG 无断点续传 ⇒ pause/resume 如实 422（不造假）。
- UI 列表只发一个请求（状态栏计数同源），不再并行两个域。

## 修法

1. daemon：`/api/downloads` GET 改为统一快照（复用 `activity::collect`）；原引擎原生列表退居 `/api/downloads/native`（调试/详情用，非 UI 列表路径）。
2. daemon：`/api/downloads/:id` 的 POST(action)/DELETE 增加 `tg:` 前缀分流（代理到 orig-tg cache 任务端点）。
3. shell：`useIngestGroups` 与下载域控制动作改走统一端点，移除对 orig-tg 控制端点的直连。
4. 清理 `mock://bug322ui.bin` 夹具任务（验收后残留=0）。
5. `/api/activity` 保留为**已废弃别名**（既有探针依赖），文档标注不再由产品代码调用。
