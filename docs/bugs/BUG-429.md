# BUG-429: 本集图组平铺露边太薄（后卡点不到、后 3 帧完全叠住）+ 编辑态缩略图按图标尺寸渲染

- 状态: fixed
- 发现日期: 2026-10-26
- 模块: shell
- 严重程度: mid
- 影响面: 剧集详情右栏「本集图组」与编辑面板的图片区；帧数越多越明显

## 现象（用户 2026-10-26 原话）

> 「本集图组 平铺需要再展开一点,后面的图片不容易点击.
> 编辑中的图片展示也需要稍微放大点,这是图片不是ICON.」

## 修复前实测（剧集 217 / 分集 573，9 帧竖版）

`tauri-shell/verify/_probe_deck_peek.cjs` 在真实 DOM 上量到：

| 项 | 实测值 | 问题 |
|---|---|---|
| 单卡宽 `w` | 170px | — |
| 平铺总宽 `total` | **300px** | 父容器可用宽 **830px**，富余 530px 没用上 |
| 相邻卡左边界间距 `steps` | `[26,26,26,26,26,0,0,0]` | 后卡只露 **26px**（卡宽的 15%） |
| 槽位 | `min(n,6)` 写死 | 9 帧里**后 3 帧完全叠在同一槽位**（间距 0）⇒ 根本点不到 |
| 编辑态缩略图 | **80×56** | 接近图标尺寸，认不出画面 |

两个问题叠加：露边薄 → 点不准；槽位截断 → 后几帧连「薄」都没有，直接不存在于可点面。

## 根因

1. `SeriesDetail` 传 `maxW={420} peek={26}`，而 `Deck` 里
   `step = min(peek, (cap − w) / (vis − 1))`：
   - 竖版 `cap=420, w=170, vis=6` ⇒ `(420−170)/5 = 50`，但 `peek=26` 更小 ⇒ **step 被 peek 钉死在 26**；
   - 横版 `cap=420, w=300, vis=6` ⇒ `(420−300)/5 = 24` ⇒ **step 被上限钉死在 24**（比 26 还薄）。
2. `visible = min(n, 6)` 是硬编码：第 7 张及以后 `slot` 全部钳到 `visible−1`，
   `zIndex` 递减 ⇒ 完全被前一张盖住。
3. `Deck` 的上限 `maxW` 是**写死的数**，与父容器实际可用宽无关 ——
   窗口最小 900（`tauri.conf.json` `minWidth`）时右栏会窄于该值，写死上限会横向溢出。
   这是既有隐患：本档要放大 `maxW`，必须先把这条兜住，否则等于拿溢出换露边。
4. 编辑面板缩略图 `h-14 w-20`（56×80），是图标量级。

## 修复

### `tauri-shell/src/components/media/Deck.tsx`

1. **上限改为「声明值 ∩ 父容器可用宽」**：新增 `boxRef` + `ResizeObserver` 量外层
   `w-full` 容器的宽度，`cap = min(maxW, max(w, avail))`。
   ref 必须挂**外层**而不是 `width=total` 那个盒子 —— 后者会自己量自己，
   `total` 变 → 可用宽变 → `total` 再变，形成抖动回路。
2. **槽位数自适应**：新增 `maxSlots` 入参（默认 6，保持 v3 原契约），并按宽度预算推导
   `maxByStep = floor(room / MIN_PEEK_PX) + 1`，
   `vis = max(1, min(n, maxSlots, maxByStep))`。
3. **露边下限** `MIN_PEEK_PX = 44`（与 BUG-327「按钮高 ≥ 36px」同量级，留视觉余量）。

### `tauri-shell/src/components/media/SeriesDetail.tsx`

`maxW 420→580`、`peek 26→56`、`maxSlots 6→10`。

### `tauri-shell/src/components/media/EpisodeEditPanel.tsx`

缩略图 `h-14 w-20`（56×80）→ `h-20 w-28`（**80×112**，+43%，比例不变）。

**刻意没做的事**：没有改 `Deck` 的点击语义（点左半=上一张 / 右半=下一张，v3 定档）。
用户诉求是「露边太薄点不到」，放大露边就能解决；把「点后卡直接翻到它」变成新交互
属另一次拍板，不夹在本轮里。
