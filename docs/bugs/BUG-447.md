# BUG-447: i18n 引用了不存在的 key，界面直接显示 `media.card.delete` 等原始 key；门禁只校验双语对齐不校验引用

- 状态: fixed
- 发现日期: 2026-10-27
- 修复日期: 2026-10-28
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-26

## 现象

多个页面把 **i18n key 本身**渲染给用户，而不是文案。逐页截图（`verify_shots/eval-2026-10-27/`）实测到：

| 页面 | 泄漏的 key |
|---|---|
| 文件域（视频/剧集） | `media.card.delete`、`media.card.edit`、`media.readout.occupancy`、`media.readout.registered` |
| 下载域（全部/已暂停/已完成） | `download.ingest.tgBadge`、`download.ingest.status.interrupted`、`download.ingest.status.done`、`download.ingest.action.retry`、`download.ingest.remove`、`download.ingest.goLibrary`、`download.ingest.entriesUnit` |
| 下载域（进行中） | `download.panel.emptyTitle`、`download.panel.emptyHint` |

## 根因

两层，缺一不可：

1. **key 根本没定义**。实测两个 locale 均无这些 key：
   ```
   media.card.delete            zh=0 en=0
   media.card.edit              zh=0 en=0
   download.ingest.status.done  zh=0 en=0
   download.panel.emptyTitle    zh=0 en=0
   media.readout.occupancy      zh=0 en=0
   ```
   `t()` 在 key 未命中时回退返回 key 字面量，于是界面显示原始 key。

2. **门禁没有覆盖这一侧**。`scripts/check-i18n-keys.py` 输出
   `OK - i18n keys aligned (2 locales, 876 keys)` —— 它只校验 **zh-CN 与 en-US 是否互相对齐**，
   **不校验「代码里 `t('...')` 引用的 key 是否存在于 locale」**。所以「双语完全对齐」与
   「引用了一批不存在的 key」可以同时成立，门禁全绿。

这与 BUG-141（硬编码中文，绕过 i18n）是**相反方向**的缺陷：BUG-141 是没用 `t()`，
本条是用了 `t()` 但 key 不存在。两者都不会被当前门禁拦住。

## 修复

1. 补齐缺失 key（zh-CN 与 en-US 同时补，保持对齐），以实际引用点为准逐条扫：
   `grep -rnE "t\(['\"](media\.card|media\.readout|download\.ingest|download\.panel)\." tauri-shell/src`。
2. `check-i18n-keys.py` 增加一条不变量：**代码引用的 key 集合 ⊆ locale key 集合**，
   任一缺失即 ERROR。反向证伪：临时删一个已引用 key，门禁必须 FAIL。

## 修复落地

1. **补 key**：按门禁报出的引用点逐条补，zh-CN 与 en-US 同时补（**245 条**，
   `download.*` / `media.*` / `dir.*` / `nic.*` / `ui.*` / `source.*` 等命名空间）。
   文案取自引用点在改动前的中文原文，占位符名以**调用点实参**为准
   （`t('download.detail.remaining', { eta })` ⇒ `{eta}`，不是 `formatEta(...)` 的原文）。
2. **门禁补不变量**（`scripts/check-i18n-keys.py` 检查项 4）：
   代码引用集合 ⊆ locale 定义集合。抓两类引用：
   - `t('a.b.c')` 直接调用；
   - key 映射表里的字面量（`const STATUS_KEY = { idle: 'download.detail.status.idle' }`）——
     只认**首段属已知 i18n 命名空间**的点分字面量，避免把 `bg.surface.2`、
     `com.origadmin.orighub` 之类误判成 key。
   降噪三条（都是实测假阳性）：跳过注释行（`nav.fmode`、`media.rs` 只在注释里出现）、
   跳过以 `.` 结尾的前缀拼接（`t('category.' + c.category)`）、跳过文件名形状的字面量。
   动态键 `t(\`media.exportIssue.${iss.kind}\`)` 静态不可判定 ⇒ 显式 **warn** 输出，不静默放过。
3. **`media.organize.templateDefault`** 的 `{剧名}` / `{series}` 是**展示给用户的模板语法**
   （`organize.rs` 两种拼写都认），故并入 `LITERAL_BRACE_KEYS` 白名单，与既有的
   `media.organize.varsHint` 同理。
