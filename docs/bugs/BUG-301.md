# BUG-301: TG 面板三级钻取过深且账号控件混在工作区——「文件夹→频道→消息」栈式导航易迷路，多文件夹时文件夹行挤成两行，账号 CRUD 与频道监控点击区相邻易误触（模块重整 M4）

- 状态: open
- 发现日期: 2026-10-13
- 模块: shell
- 严重程度: mid
- 档位: standard

> **来源**：用户 2026-10-13 规划包 `docs/design/module-restructure-2026-10-13/tasks.md` §M4（D10=A 前半：禁三级 Navi、账号已在设置、单账户）。
> 数据/接口**零改动**，只换前端 IA。

## 现象

1. **三级钻取栈**：「文件夹 → 频道 → 消息」逐层下钻，返回路径靠面包屑/栈，
   用户在多文件夹（10+）场景下**容易迷失当前所在层级**。
2. **文件夹行布局退化**：文件夹 chips 横向溢出时挤成两行，把频道列表挤下去。
3. **账号控件混在工作区**：账号 CRUD 出现在 TG 工作区，与「监控切换」「打开会话」点击区相邻 ⇒ 误触（监控开关被点成账号操作）。
4. **复合过滤无清除手段**：多个过滤条件叠加后只能整条重置，无法单独清除某一个条件。
5. 列表信息密度与未读/最新预览/监控态在两级化后**不得退步**（09 §10.4 的优点与改进清单）。

## 根因

`TgPanel.tsx` 是**单文件三职责怪兽**（容器 + 会话列表 + 媒体流 + 账号 + 搜索 + 缓存入口），
内部用 `selectedId` 之类的本地 state 表达「当前在哪一层」，
层级本身没有类型化 ⇒ 三层栈只能靠组件内条件渲染硬扛，无法只改 IA 不动数据。

## 复现

1. 打开 TG 面板 → 进入有 ≥10 个文件夹的账号 → 观察文件夹行换行、下钻三级后返回路径；
2. 在频道行点「监控」图标 → 观察是否误触相邻的账号/会话点击区；
3. 叠加「文件夹 + 关键词」两类过滤 → 尝试只清除其中一类。

### 具体口径

- 取消三级钻取栈，改 segmented（全部 / 监控 / 群组 / 私聊，**过滤非导航**）；
- 文件夹 chips 横向滚动 + 「更多 ▾」弹层（禁止挤成两行）；
- 复合过滤渲染可单独清除的条件 chip；
- 监控切换与打开会话**点击区视觉分离、防误触**；
- 右栏媒体流「缓存 / 入库并打开」现状不动；发起缓存 toast「已加入下载」。

### 出口判据

1. **接口零改动 diff 证据**（`git diff` 中 `/api/tg/*` 契约无变化）；
2. TG 全链路 verify 对照；多文件夹（10+）夹具；三账户态（M7 前单账户）；
3. 账号增删改只在设置·Telegram，工作区无账号控件残留；
4. 未读/最新预览/监控态信息密度不退步（逐项对照）；
5. **反向证伪**：把条件 chip 的单独清除去掉 → 复合过滤判据必须 FAIL。
