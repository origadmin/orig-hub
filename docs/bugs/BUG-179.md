# BUG-179: 调试模式下 TG 与媒体库服务不正常 —— 数据目录分叉 + 离线短路连本地数据一起拒绝

- 状态: fixed
- 发现日期: 2026-09-29
- 模块: engine
- 严重程度: critical

## 现象

用户报告（2026-09-29）：**「TG 显示正常，数据获取异常。媒体库数据异常。核心问题：
TG 和媒体库服务是否正常，调试模式下也必须正常，这是核心规范和需求。」**

实测（修前，调试栈 = 手动/脚本启动，无壳）：

| 观测 | 值 | 应该是 |
|---|---|---|
| `/api/tg/dialogs` | `{"error":"offline debug mode: MTProto connect skipped"}`（503） | 200 + 518 条订阅 |
| `/api/media/items` | `total: 0` | `total: 137` |
| 数据目录 | `%LOCALAPPDATA%/OrigHub/tg`（`media_item=0`） | `%APPDATA%/com.origadmin.orighub/tg`（`media_item=137`、`media_episode=45`、`dialog_cache=516`） |

生产数据（壳的 app_data_dir）与调试数据（引擎回落目录）是**两份不同的库**；
调试构建默认离线短路把所有 TG 端点变成 503，连本地已落库的 516 条频道缓存也不给。

## 根因

三个独立缺陷叠加：

| # | 事实 | 位置（修前） |
|---|---|---|
| 1 | **数据目录分叉**：壳传 `ORIG_TG_DATA=app_data_dir()`（生产路径），无壳启动回落 `%LOCALAPPDATA%/OrigHub` —— 调试栈永远读不到真实数据，137 条媒体库条目在另一个目录里 | `orig-daemon/src/state.rs::tg_data_dir`；无调试启动入口兜底 |
| 2 | **调试构建默认离线**：`offline_short_circuit()` 以 `cfg!(debug_assertions)` 兜底 → 调试栈永远 `UnavailableClient`，所有 TG 端点 503。与用户规范直接冲突：调试模式与生产是同一个产品，不该有第二套可用性语义 | `orig-tg/src/main.rs` |
| 3 | **cache-first 契约被鉴权前置阻断**：`dialogs` 处理器文档承诺「永远先读 SQLite 缓存」，但 `ensure_authorized` 排在读取之前 —— 客户端不可用时本地 `dialog_cache`（516 行）明明有数据却一律 503 | `orig-tg/src/routes.rs::dialogs` |

## 修复

1. **离线默认翻转**（`orig-tg/src/main.rs`）：默认在线（所有构建一致，凭证齐全就连
   MTProto）；`ORIG_TG_OFFLINE=1` 显式才离线（CI / 端口隔离验收）。`debug_assertions`
   不再参与可用性判定；`ORIG_TG_ONLINE=1` 兼容保留。
2. **dialogs cache-first 落地**（`orig-tg/src/routes.rs`）：客户端不可用但有本地缓存 →
   照常服务缓存（跳过鉴权 / folder 修正 / 扫描）；缓存也为空才如实 503（附可用性原因）。
3. **daemon 默认端口 9876 → 19786**（`orig-daemon/src/config.rs`）：9876 落在 Windows
   保留区（9857–9956 实证），bind 恒 10013；与前端 `api/daemon.ts` 初值、壳
   `DAEMON_PORT=19786` 对齐，bind 失败仍有顺延兜底，实际端口以 `/api/config` 为准。
4. **调试模式唯一启动入口** `scripts/dev_services.py`：解析数据目录（`--data-dir` 显式 >
   壳 app_data_dir 存在即用 > 引擎默认回落）→ 设 `ORIG_TG_DATA` → 启动 daemon
   （**daemon 是唯一启动者**，orig-tg 由它拉起并注入端口/会话/凭据）→ 幂等复用 →
   打印 `/api/config` 真源端口与 TG 状态。支持 `--check` / `--stop`。
