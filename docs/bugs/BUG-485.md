# BUG-485: 筛选面板入库无终态——已提交单元可无限重复勾选提交

- 严重程度: mid
- 模块: shell
- 状态: fixed
- 发现日期: 2026-10-28
- 发现: 2026-10-28（用户截图：底部提示「已提交 1 条入库」的同时顶部仍是「已选 1 条 / 入库选中 (1)」可再点）

## 现象

筛选命中面板（TgFilterPanel）点「入库选中 (n)」提交成功后：

1. `selected` 集合不清空 → 「已选 n 条」与「入库选中 (n)」按钮原样保持、可再点；
2. 已提交单元不移出可选集（`selectableUnits` 只按 `downloaded` 过滤，任务刚入队时字节未落盘）；
3. `hits` 的 `downloaded` 也不刷新 → 条目行仍呈「缺字节可勾选」态。

⇒ 用户可以无限次勾选/提交同一条目，全靠后端 `alreadyIngested` 幂等兜底（第二次起 queued=0 → 提示「没有可入库的条目」，更迷惑）。UI 层面「入库工作台」没有完成态，违背「让错误状态不可表达」。

## 根因

`ingest()` 成功路径只发 notice，不做三件事中的任何一件：不清选中、不记已提交、不使单元退场。翻页/新命中并入的增量勾选（`loadMore`/`pullNewHead`）也会把已提交单元重新勾回（判据只有 `!m.downloaded`）。

## 修复

- 新增会话内 `submitted` 集合（已提交单元键）：
  - `selectableUnits` 与行级 `pickable` 排除 submitted；
  - `ingest()` 成功后把 picked 键并入 submitted、并从 `selected` 移除 → 按钮因 `size===0` 自动禁用；
  - `pullNewHead`/`loadMore` 增量勾选不得勾回 submitted 单元；
  - 已提交行显示「已提交」徽标（与不可勾一起构成可见终态），不静默装没发生。
