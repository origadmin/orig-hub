# BUG-385: 剧集链路没有「跳入 TG 对应消息」的入口（BUG-364 撤档后归零）

- 状态: fixed
- 发现日期: 2026-10-22
- 模块: shell
- 严重程度: high

## 现象

用户 2026-10-22 报（继「时停手表 EP3 丢失」后）：「另外缺少跳入对应那一条的
跳转入口。」

实测（代码 + CDP）：

| 位置 | 入口 | 依据 |
|---|---|---|
| items 网格卡片 | **无** | `MediaLibraryPanel.tsx:1700` 注释：BUG-307 设计锁「items 网格不烤入 TG 跳转」 |
| 剧集详情分集行 | **无** | `SeriesDetail.tsx:1105`：BUG-364 入口重复整改把 `episode-row-view-tg` 撤销 |
| 文件域行列表 | **无** | `FileListView` 行内动作只有 打开/打开目录/删除 |

⇒ 用户路径「筛选时停手表 → 点开剧集 → 看分集」**全程没有任何一跳能回到
TG 原消息**。BUG-364 为「入口重复」撤掉行级入口后，没有在剧集链路补回
单一入口，从「三颗」直接归零。

## 修复

按 BUG-307 设计锁（2026-10-14 拍板：「视频 = 通用类，TG 跳转 = 剧集链路专有」）
补**剧集链路唯一**入口，items 网格卡片不烤入口：

1. **剧集详情来源块**（`SeriesDetail.tsx`）：主版本行 + 每条备用源行各两个出口 ——
   应用内跳转（`data-testid="episode-source-jump-tg"`，BUG-305：切 TG 面板并
   `setPendingTgFocus` 定位高亮，不离开应用）+ t.me 外链
   （`data-testid="episode-source-view-tg"`，BUG-285：href 逐字还原坐标）。
   本地来源（无坐标）两个都不渲染（坐标门控）。BUG-350：应用内跳转按钮视觉
   降级为次要样式（左栏选集器每行已有同入口，右栏再放高亮主位即主次颠倒）。
   BUG-364：外链文案改「在浏览器打开」（`media.episode.openInBrowser`）与应用内
   跳转区分。
2. **文件域 cat-all 行**（`FileListView.tsx` → FileRow）：有 TG 坐标的行渲染
   `file-list-view-tg-<itemId>` 按钮（同一 `onViewInTg` 坐标门控）。
3. **定位契约修复**（`TgPanel.tsx`，根因见下）：AlbumBubble 相册组容器挂
   `data-message-keys`（空格分隔全成员键），`findHit()` 定位循环加
   `[data-message-keys~="k"]` 回退查询。

### 根因（为什么入口有了也跳不动）

单条消息有 `data-message-key`，**相册组容器没有** ⇒ 定位循环 `findHit()` 对
组内非首条消息永远命中不了（实测 209092 属相册组 14340124445628985，翻到
410 条仍报 `tg.locateFailed`）。入口是渲染了，点击后定位失败 —— 属于
「跳转入口存在但定位契约裂口」，修容器键 + 回退查询后命中。

另有一次中间态：vite transform 缓存停在旧模块图（磁盘 mtime 1792677343 <
模块图 `?t=` 1792678336），浏览器跑缺 `onViewInTg` 下传的旧 transform，
表现为「行有按钮代码但 renderItem 不下传」。touch 全部改动文件强制重新
transform 后恢复（不许重启 vite —— 归用户）。
