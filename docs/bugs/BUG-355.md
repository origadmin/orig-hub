# BUG-355: 下载域横幅谎报——全 outage 下仍写「普通下载不受影响」，把全栈失败渲染成下载正常

- 状态: fixed
- 发现日期: 2026-10-21
- 模块: engine+shell
- 严重程度: high

## 现象

用户实测（2026-10-21）：服务全挂（接口全 200、所有任务全失败、TG 全失败、所有功能全异常），但下载域横幅仍显示：

> 「TG 入库任务暂时无法读取（普通下载不受影响）」

即「普通下载不受影响」是**假的**——全 outage 下 UI 仍在谎称下载正常。这与 BUG-354（「采集未启用」误显）、BUG-351（重启不可见）同属**状态谎报家族**：把「未知/错误状态」表达成「健康」。

## 根因

横幅范围由两个独立写死点共同造成：

- **引擎侧写死 `available`**：`activity.rs::collect` 把 `sources[0]`（下载源）的 `available` 直接置 `true`，完全不反映真实下载根健康度；
- **壳侧写死文案**：`DownloadPanel.tsx` 把「（普通下载不受影响）」作为固定后缀拼进横幅，无论下载源真实状态如何都照常渲染。

于是「下载根非法 / 服务全挂」这一真实态被两层写死掩盖成「下载正常」，与用户实测的「所有功能全异常」直接矛盾。

## 修复

**裁定**：横幅范围必须由 `/api/activity` 的 `sources` 真实推导，不得写死任何「某源不受影响」。

- **`activity.rs::collect`**：不再把下载源 `available` 写死 `true`，改为按真实下载根健康度赋值——
  ```rust
  let dl_root = crate::config::effective_download_root(&cfg);
  let dl_ok = orig_core::paths::is_valid_content_root(&dl_root);
  snap.sources[0].available = dl_ok;
  if !dl_ok {
      snap.sources[0].error =
          Some("下载根目录无效或不可写（检查设置中的下载目录）".to_string());
  }
  ```
- **`useIngestGroups.ts`**：新增 `downloadUnavailable: string | null`，从 `data.sources` 取 `download` 项，`available === false` 时落 `dlSrc.error ?? '普通下载不可用'`；
- **`DownloadPanel.tsx`**：删掉写死的「（普通下载不受影响）」，横幅范围改由两源联合推导——
  ```ts
  const daemonDown = error != null
  const dlDown = daemonDown || downloadUnavailable != null
  const tgUnavailable = daemonDown || unavailable != null || downloadUnavailable != null
  const tgReason = unavailable ?? downloadUnavailable ?? error
  const tgScopeText = daemonDown
    ? '服务未连接，TG 入库与普通下载均不可用'
    : unavailable != null && dlDown ? 'TG 入库与普通下载均不可用'
    : unavailable != null ? 'TG 入库任务暂时无法读取'
    : dlDown ? '普通下载不可用' : ''
  ```
  横幅文案 `{tgScopeText}：{tgReason}`，且仅当「仅 TG 取不到且有快照行」才显示「断开前的最后快照」。
