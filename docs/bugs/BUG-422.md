## 根因（两个同日落地的不兼容变更，2026-10-14）

1. **BUG-304/D18「导入即成剧」**：`POST /api/media/items` 内部
   `file_items_into_series` 把每条导入条目自动归档进单集剧集（写 `media_episode` 行）。
   而 `media_episode` 有 `UNIQUE(item_id)`。老夹具模式是
   「建 item → 建自己的剧集 → `POST /episodes` 挂载」，第二步之后 item 已有归属，
   挂载即撞唯一约束 ⇒ HTTP 500 `UNIQUE constraint failed: media_episode.item_id`。
   （实测复现：建 item 1650 → `GET /api/media/items/1650` 得 `seriesId:550`
   → 直接挂载到新剧集 551 报 500；先 DELETE 550 再挂 ⇒ 200。）

2. **M0 前端模块重整（BUG-298，提交 `3b53227`）**：删掉了 `media-rail-*` 系列入口，
   侧栏 `nav-child-lib-series` 直达剧集墙。28 处 `media-rail-series-all` 引用留在
   验收脚本里，脚本走到「点 rail」即抛 `入口不存在`。

**为什么没人发现**：`verify_bug285` 在 BUG-378 批次（`2d4ea90`，2026-10-23）里
已经修好了夹具那一半（`detachCurrentEpisode`，带完整根因注释），但**只修了那一个脚本**；
其余 13 个从未同步，也没有任何机制会因「脚本跑不了」而报警。fixed 档的验收证据指向
一个入库但已腐烂的脚本路径，`audit-bug-evidence.py` 只验「路径在库里」，不验「脚本还能跑」。

## 修复

1. `verify/lib/sandbox.cjs` 增加 `detachAutoSeries(base, itemId)`（从
   `verify_bug285` 的 `detachCurrentEpisode` 提炼，注明出处）；13 个脚本的
   `createItem` 在建档后调用一次。
2. 删除验收脚本里的 `media-rail-*` 点击步，改为等 `series-card-root` 直接渲染。
3. `verify_bug259_rail_reachability` 的标的（rail 可达性）已随 M0 取消，
   按 M0 导航模型重新锚定或明确标注「标的已取消」。
4. 复查 14 个脚本全部 exit 0（或明确记载为何跳过）。
