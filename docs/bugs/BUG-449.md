# BUG-449: 点播放弹出一串后端控制台黑窗——硬解探测的 4 条子进程没设 CREATE_NO_WINDOW

- 状态: fixed
- 发现日期: 2026-10-27
- 模块: engine
- 严重程度: mid

## 现象

用户 2026-10-27 原话：

> 播放视频点击后, 出现大量后端 Terminal 弹窗, 不清楚是干什么的.

点一次播放 ⇒ 屏幕上连续闪出**多个黑色控制台窗口**，每个存活零点几秒到几秒，用户完全不知道它们在做什么。

## 根因

`orig-tg` 是 `windows_subsystem = "windows"` 的无控制台进程，但它启动的**子进程默认会分配新控制台**。Windows 上必须显式传 `CREATE_NO_WINDOW (0x0800_0000)`。

仓库里同一个动作有两种写法，说明这是**遗漏**不是设计：

| 位置 | 是否设 `CREATE_NO_WINDOW` |
| --- | --- |
| `orig-tg/src/routes.rs:5899`（转码 `ffmpeg`） | ✅ `command.creation_flags(0x0800_0000)` |
| `orig-tg/src/ffmpeg_caps.rs:819`（`run_capture`，探测用） | ❌ **没有** |
| `orig-net/src/probe.rs:151` | ✅ |

### 触发链

`routes.rs:5503` `ffmpeg_config()` 是一个 `OnceCell`，**首次播放**时初始化，内部依次跑 4 条命令，每条都走 `run_capture`：

| # | 命令 | 用途 |
| --- | --- | --- |
| 1 | `ffmpeg -hide_banner -hwaccels` | 有哪些硬解后端 |
| 2 | `ffmpeg -hide_banner -encoders` | 有没有硬件编码器 |
| 3 | `nvidia-smi -L` | 有没有 N 卡 |
| 4 | `powershell -NoProfile -NoLogo -Command "Get-CimInstance Win32_VideoController \| Select-Object Name,AdapterRAM \| ConvertTo-Csv -NoTypeInformation"` | Windows 显卡型号 |

```rust
// orig-tg/src/ffmpeg_caps.rs:816-825
async fn run_capture<P: AsRef<OsStr>>(program: P, args: &[&str]) -> Result<String, String> {
    let child = Command::new(program)
        .args(args)
        .stdin(Stdio::null())
        .stdout(Stdio::piped())
        .stderr(Stdio::piped())
        .kill_on_drop(true)
        .spawn()          // ← 缺 creation_flags
```

⇒ **4 个黑窗一起闪**。其中 `powershell` 那条尤其显眼（PowerShell 冷启动 1–3 秒，窗口大、停留久），正是用户说的「大量后端 Terminal」。

### 为什么「感觉每次都弹」

`FFMPEG_CONFIG` 是 `static OnceCell`（`routes.rs:5500`），一个 daemon 进程只探测一次。但 BUG-448 让 daemon **反复被重启/重复拉起**，于是每次换进程都会重新探测一次 ⇒ 用户体感是「点播放就弹」。

## 修复

`run_capture` 补上平台条件编译（与 `routes.rs:5899`、`orig-net/src/probe.rs:151` 同一写法）：

```rust
#[cfg(windows)]
{
    // CREATE_NO_WINDOW：orig-tg 无控制台，防止探测子进程弹黑窗
    command.creation_flags(0x0800_0000);
}
```

注意 `Command::new(program)` 现在是链式一步到底，要改成 `let mut command = Command::new(program); command.args(…);` 才能拿到可变绑定。

## 验收证据

- 代码落地：`download-engine/crates/orig-tg/src/ffmpeg_caps.rs` `run_capture`——
  `Command::new(program)` 改为 `let mut command = Command::new(program);` 链式赋值，
  并在 `#[cfg(windows)]` 块内 `command.creation_flags(0x0800_0000)`。
  与 `routes.rs:5899`（转码）、`orig-net/src/probe.rs:151`（探测）**同一写法**。
- 编译：`CARGO_TARGET_DIR=target-check cargo check -p orig-tg -p orig-daemon` **通过**
  （仅 3 条既有 dead-code warning，无新增）。
- 未在本轮验证：**视觉复核（是否还弹窗）**。本会话是非交互会话，没有可观察的桌面，
  且按纪律未重启 APP。这一项需用户重启后在桌面确认——判据见下。

### 判据（带被测前提，供重启后复核）

- **S-1 无黑窗**：daemon 换新二进制后**首次**点播放（`FFMPEG_CONFIG` 这个 `OnceCell`
  尚未初始化）⇒ 屏幕**零个**新控制台窗口（修复前 4 个：`ffmpeg -hwaccels`、
  `ffmpeg -encoders`、`nvidia-smi -L`、`powershell … Win32_VideoController`）。
- **S-2 探测仍然有效**：硬解结论不变（`-hwaccels` 文本仍能取到）——**只改窗口属性，
  不动管道与超时**。
- **S-3 反向证伪**：临时删掉 `creation_flags` 那 3 行重编译 ⇒ 黑窗必须复现。
  不复现说明黑窗另有来源（例如 daemon 自身的别的 spawn 点），要重新归因。
