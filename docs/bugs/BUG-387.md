# BUG-387: 订阅浏览排版三连——图小文高、上下左右混杂、展开缺收起

- 状态: fixed
- 发现日期: 2026-10-23
- 模块: shell
- 严重程度: mid

## 现象

用户 2026-10-23 报（对订阅浏览/TG 消息流的三点复报）：

1. 「订阅浏览当前图片过小,导致文字高度>图片高度. 需要调整.」
2. 「订阅浏览部分还是上下,部分左右,修复不完整,样式突兀.」
3. 「点击展开缺少收起,且展开不符合当前所有排布模式样式(展开后变成上下了,
   需要重新设计).」

## 根因

首轮修复（h-20→h-32 + 相册并入左右框架 + 状态行收起钮）只覆盖 ≤4 行
caption；实测本订阅频道 caption 动辄 8-10 行（≈250px）：

- **图仍小于文**：左图列固定 `h-32`(128px)，长 caption 时右列 ≈250px
  ⇒ DOM 左右、**视觉上下**——这正是用户「部分还是上下」的来源（布局
  类名是左右，高度失衡让它看起来还是上下堆叠）。
- **二轮修法踩坑**：直接把 `h-32` 换 `h-full` 是循环依赖——flex 行高
  由 items 的假想高度决定，`height:100%` 对 auto 父级解析回 auto ⇒
  图片按固有比例撑高（实测 160 宽缩略图撑到 284px），失衡反向放大
  （图 284 vs 文 18）。

## 修复

单一机制贯穿四类块（photo/video/file 图标/相册封面）：

1. 左列容器改 **flex 容器**（`flex w-40 shrink-0 flex-col self-stretch`），
   行高 = max(右列, `min-h-32`)；
2. 子块（PhotoBlock/VideoBlock 根、file 图标块、相册封面 button）
   `flex-1 min-h-32` —— 高度由 flex 布局给出，短 caption 保底 128px、
   长 caption 等高拉伸；
3. 媒体 img `absolute inset-0` 铺满 + `object-cover` 裁切 —— img 不参与
   高度计算，从根上杜绝固有比例撑高；
4. 收起入口三处（首轮已落）：状态行「⌃ 收起」按钮 + 封面点击 toggle +
   封面通栏底条文案（展开态=收起）；展开宫格限右列宽，折叠/展开同一
   左右框架。

## 追记

- 首轮修复由并发写者落于工作树（注释署「2026-10-23 复报」），本轮在其上
  补齐长 caption 失衡与 h-full 循环依赖两个缺口。
- 判据注意：等高断言比对对象是**媒体块与卡片内容区**，卡片盒含 p-2.5
  padding（+20px）与边框（+2px），直接比 cardH 会假红（22px 恒差）。
