# BUG-339: 时序用例 `wall_clock_accumulates_across_restarts_instead_of_resetting` 全量并行必然假红（测试基础设施）

- 状态: open
- 发现日期: 2026-10-21
- 模块: engine
- 严重程度: mid

## 现象

BUG-330 第二批次（TGM-05/06）收尾跑全量回归时，`cargo test -p orig-tg` 唯一失败：

```
routes::tests::wall_clock_accumulates_across_restarts_instead_of_resetting ——
panicked at routes.rs:8638, assert!(restarts >= 3, ...) 一线
```

同批另两次全量并行分别表现为：一次 STATUS_ACCESS_VIOLATION (segfault)、一次同断言失败。

## 因果实验（三联，排除与本批改动的关联）

| 实验 | 命令 | 结果 |
| --- | --- | --- |
| ① 隔离单跑 | `cargo test -p orig-tg wall_clock_accumulates -- --nocapture` | **2/2 绿**（4.64s、5.17s） |
| ② 全量并行（本批改动在场） | `cargo test -p orig-tg` | 3/3 红（segfault / 断言 / 断言） |
| ③ 全量并行、排除本批新测试 | `cargo test -p orig-tg -- --skip filter_` | 仍红（298 passed / 1 failed） |

实验③证明：失败在**完全排除本批 5 条 `filter_*` 新测试**后依然出现 ⇒ 与 TGM-05/06 改动（`monitor_filter.last_read_at`、`count_filter_new_hits`、`filter_messages` 游标）**无因果**。隔离单跑稳定绿 ⇒ 被测代码路径本身正确，红的是**测试运行时环境**。

## 根因（定位结论，未修）

并行争抢打穿时序类用例的判定阈值（同项目既有前科族：D 盘 fsync 慢烧墙钟阈值——BUG-276 弧；project memory `2026-10-*`）。该用例以真实重启次数与墙钟间隔为判据（`assert!(restarts >= 3)`），全量并行时 CPU/磁盘被同批其它用例挤占，重启节奏被打穿 ⇒ 假红。实验②中出现 segfault 亦符合「并行资源争抢下的进程级表现」。

## 影响

- 不是产品缺陷，是**测试基础设施缺陷**：让「全量回归」长期带一条与本批无关的确定性红，掩盖真实回归信号（正是 BUG-331 批评的「范围外失败混入本回合结论制造假红」的同构）。
- 本批（BUG-330 TGM-05/06）验收口径：筛选类单测 `filter_*` **11/11 全绿** + `tsc --noEmit` 0 错，已独立证明本批正确。

## 修法方向（待实施，独立批次）

1. 时序/墙钟类用例串行化：给用例加共享 `Mutex`/`static LOCK`，或整类迁移到专用单线程测试目标（`--test-threads=1` 只对含墙钟用例的二进制生效）；
2. 判据从「墙钟间隔」改为**进程内单调时钟差值**（排除并行抖动），仅在重启次数这类必须实测的项上保留墙钟；
3. 修后须复现本条三联实验：隔离绿 + 全量并行连续 3 次全绿（当前全量并行确定性红）。
