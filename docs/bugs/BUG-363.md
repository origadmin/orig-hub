# BUG-363: TG 面板 101 个文字节点 < 12px（70 个 10px、25 个 9px、6 个 11px），低于项目自订可读性阈值

- 状态: fixed
- 发现日期: 2026-10-21
- 模块: shell
- 严重程度: high
- 排期: 2026-11-10

## 现象

用户 2026-10-21 复报（原话）：「大量各种这种基础逻辑,基础排版问题,导致项目完全无法推进」。

真栈实测（`tauri-shell/verify/_diag_cn_effect.cjs`，1440×900 真实渲染，TG 面板）
**自有文字节点**字号直方图：

```
9px  : 25      10px : 70      11px : 6      12px : 13
13px : 40      14px : 9       16px : 3      18px : 2
< 12px 合计 = 101 个节点
```

这直接违反 BUG-327 已落地并进门禁的阈值：「正文 ≥13px、次级 ≥12px、
**面板内不得有 <12px 可读文字**」。9px/10px 主要分布在 TG 消息气泡的元信息行
（`#msgId`、`fmtSize`、`fmtTime`、相册宫格时长徽标、缓存进度）。

## 根因

`TgPanel.tsx` 的气泡族（`MessageBubble` / `AlbumBubble` / `VideoBlock` /
`PhotoBlock`）大量使用 `text-[9px]` / `text-[10px]` / `text-[11px]`。
这批类是**逐个调用点手写**的，没有走 `Button` 的 size token，因此 BUG-361 的
`cn` 合并管不到它们（它们不在 `Button` 的 `sizeClasses` 里）。

## 修复方向

- 元信息行统一抬到 `text-[12px]`（次级），正文行 `text-[13px]`；
- 抬字号会抬高气泡行高 ⇒ 必须同步复测「最矮受支持窗口」（`minHeight=600`）下
  首屏可见气泡数，不得为抬字号把列表压到只剩一两条；
- 判据：`<12px` 自有文字节点数 = 0（按同一脚本同一口径复算）。

## 验收证据
TG 面板内所有可见文字节点提到 ≥12px（原 70 个 10px、25 个 9px、6 个 11px，共 101 个），
含 `ui/button.tsx` 的 `xs` 档上调；布局结构未改。

落点 `tauri-shell/src/components/TgPanel.tsx`、`tauri-shell/src/components/ui/button.tsx`。
判据：面板内计算字号 <12px 的文本节点数 = 0（按渲染值，不按 class 名义值）。
