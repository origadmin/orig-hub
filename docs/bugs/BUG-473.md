# BUG-473: 「用系统播放器打开」在网页调试模式静默降级为复制路径——点了没有任何可见反馈

- 状态: open
- 发现日期: 2026-10-28
- 模块: shell
- 严重程度: mid
- 排期: 2026-11-26

> 来源：BUG-139 修复（主入口统一为内置播放器、系统播放器降为**显式命名**的次要动作）
> 过程中发现的相邻缺口。BUG-139 之后「用系统播放器打开」是用户**明确选中**的动作，
> 静默失败的观感比修前更刺眼：「我点的就是这个，怎么什么都没发生」。

## 现象

1. **网页调试模式（无 Tauri IPC）**点「用系统播放器打开」：界面无 toast、无错误、
   无任何变化 —— 只是把路径写进剪贴板，而用户不知道。
2. **条目已标记已下载、但本地路径尚未回填**（`downloadedPaths` 里没有该 key）时，
   点击同样静默 return：既不打开、也不说明原因。
3. **桌面模式**下 `openPath` 抛错（文件被移动/删除、权限不足）只 `console.error`，
   UI 一无声息 —— 用户看到的仍是「点了没反应」。

## 根因

`TgPanel.tsx:1998-2012` `openDownloaded` 两条提前退出路径都是**静默**的：

```ts
const path = downloadedPaths.get(item.key)
if (!path) return                       // ① 无路径 → 静默
if (!isTauri()) {
  await copyToClipboard(path)           // ② 网页模式 → 只复制，无提示
  return
}
try { ... await openPath(path) }
catch (e) { console.error('openPath failed', e) }   // ③ 桌面失败 → 只进控制台
```

`copyToClipboard` 只是「尽力而为」的降级（注释自陈「失败即静默」），但**降级结果
没有回传给界面**。这与 BUG-389 同一条铁律相冲：取不到 / 做不到 ≠ 没有发生，
必须显式说清是「已复制路径」还是「没有本地文件」，不能让用户把「静默」读成「没响应」。

与 BUG-286 的区别：286 是**缺 `isTauri()` 守卫**导致抛错；本条守卫已在位，
缺陷是**守卫分支把不可达折叠成了静默**（且 286 只覆盖设置页入口）。

## 修复方向（建议，未实施）

1. **降级必须可见**：网页模式复制成功后 `setToast(...)`，文案可直接复用现成键
   `settings.openPathWebCopied`（`"网页调试模式不支持打开系统文件夹，路径已复制：{path}"`），
   不新增 key；复制失败则给失败提示，不能两头都静默。
2. **`!path` 不静默、也不给死入口**：有 `state === 'bytesMissing'` 时按钮就该 disabled
   （BUG-324：能渲染的按钮必须做得了它承诺的事）；否则至少 toast 说明「暂无本地路径」。
3. **桌面打开失败收口**：`openPath` 的 catch 走既有错误收口（`setError` / `ErrorDetail`，
   BUG-384），原文只进日志、界面给分类文案（`lib/tgReason.ts` 同款纪律）。
4. **不要**为此新增探测或轮询：`downloadedPaths` 已经是唯一真源，只补反馈。

## 验收要点（可证伪）

- 网页模式点「用系统播放器打开」→ **出现 toast** 且剪贴板内容 = 该条目本地路径；
- 反向证伪：注释掉那条 `setToast` 后，同一断言必须 **FAIL**；
- 桌面模式：把目标文件移走再点 → 出现分类错误提示（不是只有 devtools 里一行）；
- `downloadedPath` 缺失时按钮 `disabled`（断言 `aria-disabled`/`disabled`，不断文案）。
