## 0. 定义澄清（重要）

**「共享 D3」不是转码/投递的技术维度**，而是决策清单里第 3 条待拍板项：
「共享的第一形态 = 局域网 HTTP 只读 / FTP / 不做」。「三形态」= 该条的 A / B / C 三选项。
全仓 `D3` 是**每文档独立编号**（BT 扩展、宽高回填等文档里 D3 另有所指），与共享无关。

## 2. 三形态对比（量化 + 回归面）

| | **A. 局域网 HTTP 只读** | **B. FTP/SFTP** | **C. 不做** |
|---|---|---|---|
| 复用既有链路 | 高（复用 `/stream` + 投递节流） | 低（另起协议栈） | — |
| 新增监听/依赖 | 1 组共享端点 + 认证/绑定策略 | FTP 服务端依赖 + 被动端口防火墙 | 0 |
| 观看体验 | 好（流式 seek，手机/电视直看） | 差（无 seek，文件管理器挂载） | 只能手工拷文件 |
| 安全姿态变更 | **首次非环回监听**（必须先定认证+绑定） | 同样首次非环回 + 明文协议 | 无 |
| 可逆性 | 可逆（关开关） | 可逆 | — |
| 主要风险 | 未认证即把媒体库暴露到局域网 | 依赖膨胀 + 防火墙规则数量级更多 | 「强化功能」长期缺位 |

## 3. 推荐与前置条件

**推荐 A（局域网 HTTP 只读）**，理由：与「媒体为核心 + stream-first 播放」最契合，可复用既有
流式端点与投递节流；B 的观看体验与主目标不匹配且引入依赖膨胀。

**A 的强制前置（缺一不可，否则等于上线无认证局域网服务 = 安全事故）**：
1. **认证**（token/口令）——共享端点必须校验，不能匿名读媒体库；
2. **绑定策略**（仅用户显式开启、显式选网卡/端口，默认关闭）；
3. **共享路径复验投递节流**（非环回下 `ORIG_TG_DELIVERY_BPS` / 代理 LRU 在共享路径生效）。

## 4. 拍板请求（三段）

- **因果**：共享零实现且默认环回；D3 未裁定直接阻塞 PD-T05。若先做后定，有上线无认证局域网
  服务的风险；若不定，「跨设备观看」只能长期缺位。
- **处置**：选 **A**（附上述 3 条前置）／**B**／**C**。选 A 则落点是新建共享绑定配置（与现有
  `bind` 分离）、共享端点组 + 认证、设置页开关与二维码，并复验共享路径的节流/代理 LRU。
- **请求**：请拍板 **D3 = A / B / C**。本文件只做取证与推荐，不改任何代码。
