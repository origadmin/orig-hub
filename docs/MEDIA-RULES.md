# 核心流水线定稿：TG → 缓存(判定) → 媒体库 → 剧集

> 单一真源。逻辑只依赖**结构与类型**，禁止依赖**内容**——数据是变动的，
> 固定的逻辑不读内容做分支。标题/标签/caption 只是随行元数据，存档展示用，
> 永远不是逻辑的输入。任何改动先对齐本文，违反即 BUG。

## S0 TG（源头，只读）

- 消息 = 媒体附件（`kind`：video/photo/…）+ 元数据（caption 等）。
- 结构信号只有两个：**消息所属频道**、**消息所属相册组**（group_id）。
- 本阶段只采集，不做任何决策。

## S1 缓存判定（唯一决策点）

- **输入仅有 `kind`**，与内容无关：

| kind | 是否缓存 | 理由（固定的，不随数据变） |
|------|---------|------|
| video | 缓存落盘 | 播放需要本地字节、可控码率、离线可用 |
| photo | 不落盘 | 浏览用缩略图足够；落盘即浪费 |

- 判定是纯函数：同一 kind 永远得到同一结果。新增类型（audio/document…）
  按「播放/使用是否需要本地字节」归类，仍只看类型。
- 禁止在缓存判定里读标题、标签、caption 做分支。

## S2 媒体库（一切媒体的唯一事实源）

- **所有**媒体一律入库为条目（幂等：source+ref 去重），缓存与否不影响入库。
- 条目自足：无本地文件的条目合法（浏览条目，字节经代理现取不持久化）。
- kind 决定条目的展示与交互语义（缓存按钮 vs 入库按钮），一一对应 S1 的判定。

## S3 剧集（组织层，只组织 video）

- 剧集 ≠ 内容，是**视频条目的组织单元**；图片永远不入剧（数据层触发器强制）。
- 入剧信号唯一：**TG 相册组**（S0 的结构信号）。组内视频 → 该剧集的分集，
  顺序 = 消息顺序；caption 解析出的集号区间只是**位置声明**（S5 冲突模型）。
- 组含 ≥1 视频即成剧；纯图组不成剧（结构上没有可组织的视频），但必须留日志。
- 幂等：组 → 剧集按 source_key 复用，重复缓存不建二剧。
- **跨组归并是唯一的人工环节**：结构上不存在自动归并信号（内容不可作为信号），
  归并只能由用户显式执行（搬移 + 保序 + 如实回报 skipped）。
- 剧集 kind 恒为 `series`；启动迁移重算残留。
- 剧集标题是**展示名**，不是逻辑键；同名不同剧/同名堆积不是逻辑缺陷，
  是固定逻辑作用于变动数据的正常输出，归并由用户决定。

## S4 标签（随行元数据，与成剧解耦）

- 每次缓存收集 caption `#标签`：有剧集挂剧集（并集），无剧集挂条目（并集）。
- 标签永远不参与 S1/S3 的任何分支。

## S5 冲突模型（不变量）

- 槽位 = 位置语义：`UNIQUE(series_id, season, episode_no)`；合集区间列占位。
- 区间冲突自动回退终点之后，不覆盖既有编排。
- 同一集多来源：备用源表；切主单事务。
- 播放序列只由视频分集构成——播放视频永远不能播到图片。

## 验收铁律

- 不变量用触发器/类型表达（让错误状态不可表达），不用应用层约定。
- 跳过/不成剧必须留日志（禁止静默）。
- 每次改动：单测 + 真实实例 e2e + 截图；边界数据保留。
- 改动自检问题：**这个分支读了内容吗？** 读了即违规，改为读结构或类型。
