# 字节所有权修订（设计补丁 v1，2026-09-24）

> 触发：用户裁定「TG 入库流水线 vs 清除缓存文件已实际冲突，后续更不清楚」；
> 需求锚点：「1 份存档（不要过度占用空间）」「一处管理、本地文件夹可读」
> 「元数据瞬间完成，只有视频/图片需要时间」「图片完成出现图片，视频完成出现视频，
> 没完成进 TG 看入库进度」。
> 定位：**不是整体重评**——模块划分（M1/M2/M3）与清理铁律健康且有 169 个 BUG 的
> 定位效率背书；本补丁 = 实现向既有设计对齐 + 三条新增条款。

## 0. 关键核实：设计早已定「事实先登记」，实现违背了它

`docs/MEDIA-DESIGN.md` 流水线契约（§入队→终态）：

```
入队(幂等 item_key) → 登记事实(条目先存在) → 取字节 → 回填 file_path → 终态显式
事实先登记：入队即 import item（file_path=NULL 待回填）
失败：只标记任务 failed，事实不回滚（可重试，重试只重做字节）
```

**实现漂移（本补丁的主修对象）**：`routes.rs::run_one_cache_task` 把 ingest 放在
**任务结束**（收集 `ingested` 列表、终态时统一 `append_episodes_ranged`）——
登记被推迟到字节全部就绪之后。这正是「缓存→不见了→完成→出现」闪烁的根因：
登记前条目不存在，登记瞬间条目才出现；前端状态再由任务进度（1s 轮询）/
`downloadedPaths` 快照/库条目三源拼接，过渡窗内三源不一致。

## 1. 已拍板决策（不可违反）

| # | 决策 | 用户原话锚点 |
|---|---|---|

| D5 | 未完成 → TG 流水线看进度（含失败态：条目保留、可重试/可移出） | 「没有完成进TG看到入库进度」 |

## 2. 定稿状态机（每条资产独立执行）

```
任务开始处理某条消息
  └→ T0 元数据登记（瞬间）：media_item 行 + episode 槽位建立，bytesPresence=absent
       ├→ T1 图片字节落仓（移动入库根）→ 图片点亮
       ├→ T2 视频字节落仓（移动入库根）→ 视频点亮 → 条目「可导出」
       └→ Tf 失败 → 条目保留（缺字节）+ 流水线 failed（可重试只重做字节 / 可移出）
```

- 条目一旦登记**永不消失**；界面状态单源派生自 `media_item.bytesPresence` +
  `cache_task`（读侧只读，不做三源拼接）。
- 相册内 photo 与 video 本就是独立 `media_item`（BUG-044 / BUG-168 模型），
  资产级点亮**不需要新数据模型**，只需登记时机前移 + 回填按资产独立。

## 3. 不变式（修订后全文以本节为准）

- **I1 事实先登记**（对齐 MEDIA-DESIGN §2，修复实现漂移）：任务开始处理某条消息时
  立即登记 `media_item`（`file_path=NULL`），严禁把 ingest 推迟到任务终态。
- **I2 归仓 = 移动**：字节落仓路径 = `<库根>/<series-slug>/<ep-NN>-<资产>;<ext>`；
  `file_path` 存**库根相对路径**；移动失败（跨盘）降级为登记原路径并记日志，不阻断。
- **I3 清理让位**：缓存清理链（`all/orphan/stale/failed` 全部 scope）对**库根内字节
  一律跳过**；`orphan` 判定把库根内文件视为有主。暂存区里未登记的字节才可清。
- **I4 只删自己产出的字节**（既有铁律保留）：外部路径条目只登记、永不清理。
- **I5 删条目 = 连字节**（既有铁律保留，BUG-135 语义：清标记失败即中止）。
- **I6 导出闸口完备性校验**：缺文件/缺简介/缺图/零字节在导出预览强制列出——
  「媒体库里的一切都可导出，暂存区里的一切都可丢弃」。

## 4. 实施清单

| 阶段 | 内容 | 主要落点 |
|---|---|---|
| P1 登记前移 | `run_one_cache_task` 逐消息处理时先 ingest（登记）后取字节；回填走专用语句（防 COALESCE 粘路径，MEDIA-DESIGN C3） | `routes.rs`、`store.rs` |
| P2 归仓移动 | 字节落盘改写到库根（临时名 → 原子 rename）；存量条目懒迁移（下次回填时顺带归仓），不做一次性大迁移。**实现偏离注记**：落仓命名采用 `<库根>/<chatSlug>-<chatId>/<messageId>-<titleSlug>.<ext>`，而非 I2 的 `series-slug/ep-NN` —— 集号随剧集重编/重排漂移，消息号 + 标题 slug 是稳定标识，重命名成本为 0；`file_path` 相对路径、失败降级等其余 I2 语义不变 | `cache.rs`、`store.rs`（库根解析链）、`routes.rs`（config/投递/删除） |
| P3 清理让位 | 清理链按路径前缀（库根）跳过；orphan 判定排除库根 | `cache.rs` |
| P4 状态单源 | 流水线/条目状态改由 `bytesPresence` + task 单源派生；消灭三源拼接过渡窗 | `TgPanel.tsx`、`CacheManagerDialog.tsx` |
| P5 设置+校验 | 库根设置项（默认同级 library）；导出完备性校验端点+预览 | 设置页、`routes.rs` |
| P6 EE 导出 | 目录 + manifest.json（schema `orighub-export/1`，视频/内容/图片三要素，另出） | 后续设计 |

## 5. 验收口径

- 闪烁：CDP 200ms 采样一次真实缓存任务全程，断言条目从 T0 起在库列表中**连续可见**
  （修复前必现消失窗口，判据非恒绿）。
- 归仓：入库后文件位于库根、`file_path` 为相对路径、暂存区无副本（1 份存档）。
- 清理让位：对含库根字节的库执行 `scope=all` 清理 → 库根字节 0 删除、暂存区字节回收。
- 失败路径：制造单条失败 → 条目保留缺字节 + 流水线 failed + 重试只重做字节。
