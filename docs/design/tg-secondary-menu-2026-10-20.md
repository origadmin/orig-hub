# TG 二级菜单面板重排 —— 频道 → 监控 → 筛选三层漏斗（单一 `tgMode` 状态机）

> **来源**（用户 2026-10-20 报障原话）：
> 「最严重的筛选出来的内容,无法看到内容信息. 筛选过滤将来会有很多条.
> 而且进入筛选后下面的分组无法进去,这是层次逻辑问题.
> 整个层次逻辑和功能都需要重新设计排版设计, 频道->监控->筛选,这是3层逻辑.」
>
> **口径澄清**（用户 2026-10-20，已锁）：
> 「整条流程线的核心逻辑是监听我需要的内容,筛选添加的就是我需要监听的更新内容.
> 监控是需要监听的内容监控,只检查这些频道的实时更新.」
>
> **结论（先答，v2 · 2026-10-20 修订）**：当前左栏是三节**平铺** + 主列一条**四态优先级链**，
> 三层逻辑在结构上不存在。重排 = ① 左栏变成**监听链漏斗**——构建序（频道→监控→筛选）
> 由面板顶部的**监听链状态条**承载，三节版面按**消费序**排列（筛选→监控→频道），
> 行内溯源 + 层级编号 + 跨层计数把包含关系显式化；② 分流判据从四个独立状态 +
> 优先级链收敛为**单一 `tgMode` 五值**（对齐文件域 `fmode` 范式）；③ 筛选层补
> **「+N 新命中」**——用户口径「筛选添加的就是我需要监听的**更新**内容」，而筛选层
> 目前只有命中总数，「监听更新」在筛选层是断的。
>
> **v1 → v2 的原因**（用户 2026-10-20 批：「面板设计体现不出层级结构和优先级」）：
> v1 把用户的**构建序**（先选频道 → 再加监控 → 后定筛选）直接当成了**版面序**——
> 三节平铺成三个货架，面板上没有任何东西说明「监控 ⊆ 频道」「筛选命中来自监控的
> 更新」（**层级丢失**）；且最常用的筛选面被压到最底、偶尔一用的频道管理占据
> 首位（**优先级丢失**）。「漏斗」只出现在散文里，没有出现在结构里。v2 起两序分离（§2.0）。
>
> **本文不改代码**（用户 2026-10-20 定：当前只做前置流程/文档部分，开发等指令，
> 因别的组正在正常开发）。本文是 BUG-330 修复方案的**二级菜单面板**部分；
> 主列命中列表的「可预览 + 分页」规格见 BUG-330.md §修复，本文只定菜单与主列的契约。

## 1. 面板定位与边界

- **是什么**：TG 域的**二级菜单**（一级 = 主侧栏 `nav-tg`）。宽 **288px**（维持现 `w-72`），贴左，单列。
- **不是什么**：不是第三个导航域、不新增一级导航位（BUG-314：NAVI 数量严格标准化）；不做内容呈现（内容归主列）；**不回迁全局搜索**（BUG-100 方案 A：搜索框在顶部上下文栏，本面板顶部保持干净）。
- **唯一职责**：把「监听谁 / 监听什么 / 我要什么」三层变成可点、可数、可 scale 的入口，并把点击**独占式**地译成主列的一个 `tgMode`。

## 2. 面板设计（本文主体）

### 2.0 总体结构（v2：监听链漏斗，两序分离）

**v1 为什么不成立**（用户 2026-10-20 批：「面板设计体现不出层级结构和优先级」）：
v1 把用户的**构建序**（先选频道 → 再加监控 → 后定筛选）直接当成**版面序**——
三节平铺成三个货架，面板上没有任何东西说明「监控 ⊆ 频道」「筛选命中来自监控的更新」
（**层级丢失**）；且最常用的筛选面被压到最底、偶尔一用的频道管理占据首位
（**优先级丢失**）。

**v2 核心：两序分离。**

| 序 | 回答的问题 | 载体 |
|---|---|---|
| 构建序（频道 → 监控 → 筛选） | 系统是怎么搭起来的 | 面板顶部**监听链状态条**（常驻、可点击跳转） |
| 消费序（筛选 → 监控 → 频道） | 用户每天来干什么 | 三节版面顺序 + 默认折叠态 |

产出端（筛选）同时是漏斗最深处与每日第一眼——**层级深度与消费优先级在产出端重合**，
这是整个面板的构图原则。

```
┌─ 监听链 ──────────────────────────────┐
│ 12 频道 → 3 监控 → 247 命中     +4 新 │ ← 构建序·数据流；阶段可点击（跳转+展开）
├─ ③ 筛选 · 我需要监听的内容 ──── +4 新 ──[+]┤ ← 消费序①（每日第一眼，默认展开）
│ ▸ 规则1 "4K"      搜 3 个监控频道  +3  │
│ ▸ 规则2 "纪录片"   搜 3 个监控频道  +1  │
│ ▸ +3 条规则 ▾（超 K 折叠，v3）          │
│ [🔍 规则内搜索…]                        │
├─ ② 监控 · 只检查这些频道的更新 ─ +6 ──┤ ← 消费序②（默认展开，只读投影）
│ ● 频道A · 来自 分组A            +5    │
│ ● 频道B · 来自 未分组            +1    │
├─ ① 频道 · 来源 ──────────── 12 · 3 监控中│ ← 消费序③（偶尔动作，**默认折叠**）
│ ▸ 分组A (5) ▸ 分组B (4) ▸ 未分组 (3)   │
└────────────────────────────────────────┘
        ↑ 单一滚动容器；③②① = 漏斗深度编号（① 最宽在底，③ 最窄在顶）
```

三节仍对应用户原话的三层（频道/监控/筛选一字不减），变的是**层与层之间的关系被看见**：
状态条给数据流、编号给深度、行内溯源给依赖、默认折叠给优先级。

### 2.2 频道节（① · 来源面，默认折叠）

- **副标（节头下 12px muted）**：「来源——加监控在主列频道页/管理列表完成」。
- **行**：「全部频道 (N)」+ 每个分组（folder 名 + count）。分组顺序 = Telegram pin 顺序（BUG-196 缺陷②：`folder.channelIds` 即 pin 顺序，现有逻辑保留）。
- **行点击** → `tgMode = 'channels'` / `` `group:${folder}` `` → 主列 = 分组频道管理列表（**现有组件保留**：频道头像/标题/@username + 监控 Switch + 频道搜索框 `tg-group-search-scope`）。
- **监控开关的单一写面在本节之外**（§2.7）：栏内不展开组内频道、不放 Switch——那是主列管理列表与 `channel:<id>` header 的职责；栏内再放一份就是双写面。
- **默认折叠**：`aria-expanded=false`；节头计数 `(12)` 与「3 监控中」常驻可点（BUG-320：折叠入口是真控件，折叠 ≠ 隐藏）。
- **空态**：「扫描中…」/「没有可选频道」+ 重扫入口（现状 `fetchDialogs` 保留）。

### 2.3 监控节（② · 实时更新面，只读投影）

- **副标**：「只检查这些频道的实时更新」（用户口径原话落文案）。
- **行**：头像圆（首字母）+ 标题 13px + `@username` 12px（可选）+ **行内溯源**「来自 <分组>」12px muted（L2→L1 出处；频道可属多个分组，显首个 + `等 N 组`）+ **「+N」新徽标**（12px，`newCount === 0` 不渲染——BUG-329）。
- **行尾无 ✕**（§2.7 单一写面）：取消监控在主列频道实体上完成；本节是投影，不是编辑面。
- **行点击** → `tgMode = ` `` `channel:${id}` `` + **mark read**（`POST /api/tg/monitor/channels/:id/read`；本地先乐观归零、失败静默回服务端真值——BUG-329 现行为保留）。
- **同步按钮**：现状 `doSync`（单飞，BUG-102：`started:false` 时什么都没做，不得假装成功）保留。
- **空态**：「还没有监控频道」+ **行动出口**（一句话引导去「频道」节点选，点击直接展开 ① 节；「未就绪」≠「无可监控」）。

### 2.4 筛选节（③ · 内容定义面，默认展开，置顶）

- **副标**：「我需要监听的内容」。
- **行**：规则名 13px + 关键词 12px muted（`"kw"`）+ 命中总数 12px tabular-nums + **行内溯源**「搜 N 个监控频道」12px muted（L3→L2 依赖；N = monitored 端点真值）+ **「+N」新命中徽标**（**新增**，0 不渲染）+ 行尾 ✕ 删除规则（规则实体只在本节出现，✕ 不构成双写面）。
- **行点击** → `tgMode = ` `` `filter:${id}` `` + **mark filter read**（**新增**：`POST /api/tg/monitor/filters/:id/read`，清 +N；契约见 §4）。
- **节内检索框**（**新增**，常驻）：按规则名/关键词前端过滤（rules 量级 ≤ 几百，纯客户端）。常驻而非「规则多了才出现」——入口可见性是 BUG-320 的教训。
- **新建（v3 改写，用户 2026-10-20 裁定）**：节标题**右上角「+ 新建」按钮**（lucide `Plus`，热区 ≥24px）→ 弹出「添加筛选规则」小窗：关键词（必填）+ 显示名（可选，缺省同关键词）+ 添加，Enter 提交保留；弹窗内控件沿用 BUG-329 既有 testid `tg-filter-input`/`tg-filter-add`（红线 5：验收脚本 selector 不变）。**撤掉规则列表下方常驻的「一行输入框 + 添加按钮」**（`TgPanel.tsx:1930-1952` 现状，用户原话「当前下方一行的方式严重破坏了整体设计」）——添加是偶发动作，不占常驻版面；节首屏只剩规则本体。
- **label≡keyword 去重（v3 新增）**：`routes.rs:3182-3186` label 缺省 = keyword、前端 `addFilter` 不传 label ⇒ UI 所建规则 **100% label≡keyword**，左栏行（标题 `{f.label}` + 副行 `“{f.keyword}”`，`TgPanel.tsx:1903-1906`）与主列头（`筛选：{label}` + 副条 `“{keyword}”`，`TgFilterPanel.tsx:176/184`）两处同词重复（用户「同一文字显示 2 串」）。渲染判据：`label === keyword` 时左栏只留标题行、主列副条只留匹配说明；用户自起显示名（两者不同）时才两行都显。
- **规则折叠（v3 新增，用户「多个显示超出规则后的折叠和展示」）**：规则数 > K 时默认渲染前 K 条，其余折叠为一行「+N 条规则 ▾」（真 button + `aria-expanded`/`aria-controls`，BUG-320 纪律）；展开后显示全部、尾行「收起 ▴」。K 按最矮受支持窗口 900×600 实测取值（建议先 8，实现弧量几何后定）；节头计数 `(N)` 恒显全量真值（折叠不改计数口径，BUG-125/133）。与 §2.1 单一滚动容器配合：折叠 = 首屏只给常用量，不是限高滚动。
- **空态**：解释筛选是什么——「在监控范围的更新里找我需要的内容：加一条关键词规则，命中的更新会在这里列出，可勾选入库」。

### 2.5 层级结构如何被看见（四机制）

三层不是三个割裂的列表，而是**数据层已成立**的包含关系（监控 ⊆ 频道：监控开关挂在频道实体行上；筛选 ⊆ 监控：`filter_messages` JOIN `monitored_channel`，`store.rs:1156`——未监控频道的命中永不出现）。v1 的错是只把这句话写在散文里；v2 用四个机制把它变成面板上看得见的结构：

1. **监听链状态条**（层级的第一表达）：`N 频道 → N 监控 → N 命中`——箭头即漏斗方向，三数即三层规模，常驻面板顶部。任一阶段可点击（展开并滚至对应节）。「取不到」渲染 `—` + 原因，不得渲染 0（BUG-318 纪律：「取不到」≠「没有」）。
2. **层级编号 ①②③**：节头常驻小编号。① 来源（最宽，在底）→ ③ 定义（最窄，在顶）。**编号 = 漏斗深度，位置 = 消费优先级**，两者在产出端（③）重合。
3. **行内溯源**（层级的第二表达）：③ 行显「搜 N 个监控频道」（L3→L2 依赖）；② 行显「来自 <分组>」（L2→L1 出处）；① 行只显计数（源头无上游）。层级不靠缩进猜，靠每行自报上游。
4. **跨层计数**：状态条三数 + 节头计数 + 行内徽标全部同源（三个 list 端点真值，BUG-125/133）——父集的数是子集数的父集，一致性可验。

### 2.6 优先级如何被结构表达（三机制）

1. **消费序版面**：③ 筛选（每日第一眼）→ ② 监控（实时更新）→ ① 频道（偶尔动作）。用户每天来干什么，决定版面顺序；系统怎么搭，归状态条。
2. **默认折叠态**：① 默认折叠（节头 + 计数 + 入口常驻可点，BUG-320 真控件）；②③ 默认展开。折叠是优先级表达，不是功能隐藏。
3. **聚合徽标**：节头显示本节 +N 合计（③ 新命中 / ② 未读），状态条显示全局 +N 新——不点进任何一节，也知道「有没有我要的新东西」。

### 2.7 单一写面（层级完整的保证）

- **监控开关只出现在频道实体行**：主列 `channel:<id>` header Switch + 分组/全部管理列表 Switch。面板 ① 是导航索引（分组行），不提供第二写面。
- **② 监控节是只读投影**：无 Switch、无 ✕；行点击 = 进入内容流 + mark read（BUG-329 保留）。未读清零只发生在 ② 行点击与主列内容流内；① 行点击不动游标。
- **理由**：两个写面 = 双真源，徽标与状态必然漂移（BUG-125/133 同款病）；且投影节不可能改状态，「显示与真实不一致」这类错误态不可表达。

## 3. 状态机：单一 `tgMode`（消灭优先级链）

### 3.1 定义（`nav/index.ts` 增补，与 `dlFilter`/`fmode` 同构）

```ts
/** TG 域内选择（二级菜单 → 主列的唯一分流判据）。
 *  与 fmode 同构：字符串模板，进 React state、可直接当 key/比较值。 */
export type TgMode =
  | 'search'              // 跨监控频道全局搜索（上下文栏驱动，瞬态）
  | `channel:${number}`   // 某频道内容流（监控中/未监控均可浏览，header 给监控开关）
  | `filter:${number}`    // 某筛选规则的命中列表（可预览入库工作台）
  | 'channels'            // 频道层·全部（分组管理列表）
  | `group:${string}`     // 频道层·某分组（分组管理列表）
```

`NavState` 增 `tgMode: TgMode`；`navigate('tg', { tgMode })` 进入/切换；
离开 TG 域再回来**保留** `tgMode`（`navigate()` 规则 1：切域保留树选择，与 fmode 同构）。

### 3.2 不变量（让错误状态不可表达）

1. **互斥切换**：任何行点击 = `setTgMode(新值)`（覆盖），不存在「叠加」。
   「筛选激活 + 分组已选」这种错误态**不可表达**——诉求③的结构性修法。
2. **`selectedId` 降级**：仅记录「当前频道」（供内容流数据与 read 游标），**不再是主列分流判据**。
3. **删除四态一链**：`activeFilter` / `groupMode` / `detail` / `globalSearch`（面板内订阅的那份）
   全部删除；`TgPanel.tsx:2011` 的 `activeFilter ? … : …` 优先级链整条删除，
   主列改 `switch (tgMode)` 五分支。
4. **mark read 只在真实切换时发生**：点已在当前模式的同一行 = 不重复请求
   （幂等 + 免请求风暴）；从未监控频道行进 `channel:<id>` 照常 mark（该行只可能来自监控节）。
5. **`search` 无左栏高亮行**：全局搜索是上下文栏驱动的瞬态，`tgMode='search'` 时左栏不高亮任何行
   （现状即如此，不新增「搜索结果」导航位——BUG-314）。

### 3.3 主列契约（本文只定接口，面貌见 BUG-330）

| `tgMode` | 主列 | 现状复用度 |
|---|---|---|
| `` `channel:${id}` `` | 频道内容流（feed/同步/定位/缓存/气泡） | 100% 保留 |
| `` `filter:${id}` `` | 命中列表：可预览（点行展开 `MessageBubble`，BUG-151 范式）+ 分页 + 勾选按相册入库 | 重做（规格在 BUG-330） |
| `'channels'` / `` `group:${f}` `` | 分组频道管理列表（含频道搜索 + 监控 Switch） | 100% 保留 |
| `'search'` | 全局搜索结果（按频道分组，点行展开） | 100% 保留 |

## 4. 数据契约（后端；实现期取用，本文不改代码）

> 三个增量全部是**纯增量、无破坏性迁移**；老客户端忽略新字段/新端点。

### 4.1 per-filter 已读游标（「+N 新命中」的数据基础）

| 项 | 规格 |
|---|---|
| 为什么需要 | 用户口径「筛选添加的就是我需要监听的**更新**内容」；`monitor_filter` 表（`store.rs:556-561`）**没有已读游标**（`monitored_channel` 有 `last_read_message_id`，:553）⇒ 筛选层只有命中总数，「监听更新」在筛选层是断的 |
| 游标口径 | **时间戳** `last_read_at`（unix 秒）。为什么不复用 message_id 游标：命中**跨频道**，message_id 跨频道不可比；per-channel 游标表（filter×channel）过重。时间戳跨频道可比、单调、与 `ORDER BY COALESCE(msg_date, created_at)` 同源 |
| `newHits` | 命中中 `COALESCE(msg_date, created_at) > last_read_at` 的条数，**现算不另存计数列**（BUG-329 纪律：存了就和真实行漂移） |
| 迁移 | `monitor_filter` 加 `last_read_at INTEGER NOT NULL DEFAULT 0`（幂等，仿 `migrate_monitored_channel_last_read`）；**存量行初始化为迁移时刻 now**——与 BUG-329 频道游标同坑：不初始化则升级后首屏全是假「新命中」 |
| 端点 | `POST /api/tg/monitor/filters/:id/read` → `last_read_at = MAX(last_read_at, now)`（**只进不退**：消息被清理后 `MAX()` 会变小，直接赋值等于把已读的旧命中重新变成新的） |
| 列表端点 | `GET /api/tg/monitor/filters` 每条形目增 `newHits`（与 `hits` 同来源现算） |

### 4.2 命中内容预览的数据基础（诉求①的数据根因）

`filter_messages` 的 SELECT 补 `m.mime_type, m.file_path`（`store.rs:1153-1154`；`get_message:1192` 已有先例，两列都在 `media_message` 表内），`MonitorFilterHit` 增 `mimeType?`/`filePath?` 两个 Option 字段。缺这两列，前端即使想展开也驱动不了 `PhotoBlock`/`VideoBlock`/`MessageBubble`。

### 4.3 分页游标（诉求②的命中侧）

`filter_messages` 加 `before_date`/`before_channel_id`/`before_message_id` 三参数；定序已是
`COALESCE(msg_date, created_at) DESC, message_id DESC`——注意 **message_id 跨频道不唯一**，
游标必须是 `(date, channel_id, message_id)` 复合，否则同刻跨频道行会重复/跳过。
前端「加载更多」按钮取代现行 `limit=200` 硬顶（后端 clamp 500 保留）。

## 6. 判据（可证伪，预先声明；实现弧执行）

1. **进筛选后点分组行/监控行，主列必须切换**（诉求③）。验牙：装回 `activeFilter ? … : …` 优先级链 ⇒ 该断言必败。
2. **mark read 只在真实切换时发生**：同态重复点击不得发第二次 read 请求（请求风暴断言：排除 preflight、作用域锚到 `[data-testid="tg-panel-root"]`）。
3. **+N 新命中**：加规则 → 造新匹配消息 → 徽章出现且数值 = API `newHits`；点开规则 → 归零；徽标数⇔API 真值一致（BUG-125/133）。
4. **scale**：造 30 条规则 + 20 个分组，三节不互挤（单一滚动容器），节内检索可命中目标规则；最矮窗口 900×600 下三节头均可见可点。
5. **存量迁移无假新命中**：老库（`last_read_at` 缺列）升级后首屏 `newHits` 全为 0。
6. **命中可预览**：点命中行展开完整内容气泡（caption 全文 + 缩略图 + 可播时有播放按钮）；`mimeType`/`filePath` 缺失的旧数据行降级为「只有标题」且**不得**崩。
7. **监听链三数 ⇔ API 真值**：状态条的 频道/监控/命中 三数分别等于三个 list 端点返回值；新增一个监控频道后「3→4」在一个轮询周期内更新（无需手动刷新）。反向：硬编码数字 ⇒ 必败。
8. **行内溯源可见**（BUG-320 双向验牙）：③ 每行渲染「搜 N 个监控频道」且 N = monitored 端点值；② 每行渲染所属分组名。反向变异（溯源文案 `opacity-0` 或删渲染）⇒ 断言必败——尺寸/可见性类断言必须双向。
9. **默认态 = 优先级**：首次进入 TG 域，③② 展开、① 折叠（`aria-expanded` + `getBoundingClientRect`，viewport-相对，BUG-321 教训）；900×600 下 ③ 节头在首屏内。反向：三节全部强制展开 ⇒ 必败。
10. **单一写面**：监控 Switch 只出现在主列频道实体（`channel:<id>` header + 分组管理列表）；② 监控节行无 Switch、无 ✕（DOM 断言 + testid grep）。反向：给 ② 行加 ✕ ⇒ 必败。
11. **v3 新增**：① 添加入口 = 节标题右上角 button（弹窗内才有输入控件），规则列表**下方无常驻输入行**（DOM 断言下方一行 Input 计数 = 0）；② label≡keyword 时左栏行文字节点与主列副条**不出现同词两次**（render → textContent 比对）；③ 造 20 条规则：默认渲染 ≤ K、折叠行文案含 `+N`、`aria-expanded` 可切换、节头计数恒 = 20；④ 全面板 emoji 计数 = 0（`⭐` 清除）。每条各配反向变异（装回旧入口/同词两行/全量渲染/塞回 ⭐）⇒ 必败。
