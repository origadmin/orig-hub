# 下载域显示统一评估：「任务组（1..N 条目）」范式 —— 引擎单文件是 N=1 的特例

> **来源**：用户 2026-10-16 报障原话：「mock://bug322ui.bin?size=33554432&rate=256k
> 测试和 TG 入库在下载中的显示完全不一样，这违反了统一设计逻辑，后续 BT 下载也是
> 需要使用到多文件选择下载逻辑的，需要重新评估，当前 TG 无法单独设置/选择哪些我
> 不要下载了。」
>
> **结论**：当前下载域存在**两套互不相通的行形态**（引擎单文件行 / TG 入库组行），
> 不是「样式漂移」而是**范式缺失**——下载任务的统一抽象「任务组（1..N 条目）」
> 从未确立，两套实现各自长成了不同物种。BT 下载（多文件种子）落地时若仍不统一，
> 将出现**第三套**形态。本档确立统一范式并给出分层实施方案。

## 一、现状分裂盘点（dev :5180 实测形态对比）

| 维度 | 引擎下载行（DownloadItem，mock/BT 单文件） | TG 入库行（IngestGroupRow，组式多条目） |
|---|---|---|
| 任务粒度 | 单文件（一个 URL = 一个任务） | 组（一次入队 = N 条消息，`itemKey` 聚合） |
| 主标识 | 文件名 + URL 副行 | 「TG 入库」Badge + 对象名 + 状态 Badge + 优先徽标 + 「共 N 次」 |
| 操作按钮 | 暂停/恢复/取消/重试/打开文件/打开目录/删除，**hover 显形**（终态行常驻） | 状态动作 + 去媒体库查看 + 删除，**常驻可见** |
| 进度呈现 | 进度条 + 百分比 | 进度条 + `done/total 条` + 字节 + 时间戳 |
| 明细入口 | **无**（单文件无明细可言） | 「明细 N」折叠按钮（与动作按钮同排） |
| 展开形态 | 整行点击 → 底部详情 Sheet（块进度/连接详情） | 行内展开区（条目清单 + 历史批次） |
| 条目级操作 | 不存在 | 缺字节条目「下载」（无「不要这条」） |

两条裂缝：

1. **明细入口两制**：引擎任务整行点击开 Sheet；TG 任务用行内「明细 N」按钮 + 内联展开。
   同一「下载中」列表里，两行点下去的行为完全不同。
2. **条目选择能力两制**：引擎单文件没有条目概念（N=1 时「选不选这条」等价于任务级取消）；
   TG 组有 N 条但**只能加（下载）不能减（排除）**——「我不要其中几条」在后端
   （orig-tg）**没有对应能力**（`/api/tg/cache/clear` 只清已下字节，条目永不删除，
   无 excluded 标记、无 total 重算）。

## 二、统一范式：「下载任务 = 任务组（1..N 条目）」

**裁定（用户 2026-10-16）**：下载域的统一抽象是**任务组**：

- **引擎单文件任务** = N=1 的任务组（URL 即唯一条目）；
- **TG 入库任务** = N 条目的任务组（消息条目，`itemKey` 聚合）；
- **BT 种子任务**（前瞻）= N 文件的任务组（种子内文件列表）。

三者共享同一行结构与同一详情入口，差异只收敛在**组级元信息**（URL / itemKey /
种子 info_hash）与**条目能力集**（按来源推导），不再分裂成两种行组件。

### 行结构统一（下载中/全部档）

```
[来源 Badge] 任务组名（文件名 / 对象名 / 种子名）
[状态 Badge]  [优先]  [共 N 条目（N>1 时显示）]
[进度条]  done/total · 字节 · 速度/时间
[操作按钮组：按状态的能力集，恒常驻可见]
[明细入口：N>1 时显示「明细 N」→ 底部弹出 Sheet]
```

- **整行点击 = 打开底部详情 Sheet**（统一：引擎的块进度/连接详情、TG 的条目清单+历史批次，
  BT 的文件列表，全部走 Sheet；行内不再内联展开区——行高由窗口化组件统一收敛，
  内联展开会把 estimate 打穿）。
- **操作按钮组**按状态能力集推导（暂停/恢复/取消/重试为传输控制，删除/打开为资产管理），
  恒常驻可见（BUG-315「无控制」裁定：活跃行必须有可见干预手段）。
- **明细 Sheet 内含条目选择**（见下）。

### 条目选择下载（BT 文件勾选的统一模型）

BT 种子的文件勾选 = 「选哪些文件下」；其补集语义「哪些不要」必须同样可表达——
用户明确点出「当前 TG 无法单独设置/选择哪些我不要下载了」。统一模型：

- 条目有**三态**：待下载（默认）/ 已排除（用户明示不要）/ 已完成（有字节）；
- 「排除」在**任务未终态**时生效：被排除条目不进入下载队列、不占 `total` 分母
  （进度口径重算），恢复可逆；
- 排除不删数据（与「清字节」正交：清字节删已落盘的字节，排除是选择语义）。

## 三、后端能力缺口（登记，非本档可闭）

| 能力 | 现状 | 缺口 |
|---|---|---|
| 条目级排除标记 | orig-tg 无（`cache_task_item` 无 excluded 字段） | 需新增 excluded 标记 + 任务 total/done 重算投影 |
| 排除的写入端点 | 无 | 需 `POST /api/cache/items/exclude`（taskId + messageIds）与恢复端点 |
| 聚合视图投影 | `/api/activity` 的 cache 任务带 groupKey/messageIds | total 需按「未排除条目数」下发（否则前端分母与后端实际拉取分裂） |
| BT 引擎支持 | 无 | 另档（引擎 BT 接入，前瞻） |

**条目级「不要下载」的前端**（明细 Sheet 内勾选/排除）可先做（UI 先行、落
`excluded` 本地态展示），但**持久化与生效依赖后端**——后端未落地前，排除操作
必须**明示「未生效」**（不可假能力，AGENTS.md 同源纪律）。

## 四、分层实施方案（DLU 任务）

| 任务 | 内容 | 依赖 |
|---|---|---|
| DLU-T01 | 明细入口统一为底部弹出 Sheet（「明细 N」按钮保留在折叠头独立位，点击开 Sheet；行内展开区废除） | 无（与 BUG-316 段② 窗口化兼容：Sheet 是 fixed 层，不占列表流） |
| DLU-T02 | 行结构对齐：来源 Badge 文案统一（「TG 入库」/「引擎下载」/「BT」）、进度读数统一（done/total · 字节 · 时间） | 无 |
| DLU-T03 | 明细 Sheet 内条目清单重排（列对齐、去冗余「有字节/无字节」、状态徽标收敛） | DLU-T01 |
| DLU-T04 | 条目排除 UI（三态条目选择）——**前端先行**，后端未落地前明示未生效 | DLU-T01 + 后端缺口登记 |
| DLU-T05 | 后端条目级排除（excluded 标记 + total 重算 + 写入端点） | 另开缺陷档 |
| DLU-T06 | BT 引擎接入与文件选择 | 另开设计档（前瞻） |

**反向证伪（DLU-T01）**：把 Sheet 改回行内展开 ⇒ 窗口化组件的 estimate 被打穿
（展开行 432px vs 折叠 108px 混排 ⇒ 滚动跳动），段② 的 longtask 断言必 FAIL。
