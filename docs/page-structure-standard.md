# 页面结构规范（四件套）与全站评估 —— BUG-317

> doc-first：本条先把标准与评估表定稿，再动代码。与 BUG-313（组件级排版）并存不覆盖。

## 1. 标准样板（用户 2026-10-15 裁定）

下载页为标杆，信息层级四件套：

1. **顶部标题**：页面级标题（`page-title`），唯一、固定位置（页面顶部），说明本页是什么。
2. **主按钮**：每页唯一主操作（`page-primary-action`），位于标题区右侧；其余操作降级为次级/图标，不得与主按钮平铺竞争。
3. **次级信息**：计数 / 状态摘要（`page-secondary-info`，如「已入库 10 · 入库中 2 · 失败 1」），位于标题区下方，恒定口径。
4. **三级按钮筛选**（`page-filter`，第④项，**先评估再定去留**）：仅当有真实筛选刚需时存在；空转入口（参照 BUG-304 标签 TAB 空转）一律不上。

## 2. 层级与位置契约

- 标题区 = 顶部 sticky 条：左标题、右主按钮、下次级信息。
- 筛选在第③层之下、内容列表之上；**无筛选刚需的页面省略该层**（不是留空占位）。
- testid 契约（门禁用，反向证伪锚点）：
  - `page-title`
  - `page-primary-action`
  - `page-secondary-info`
  - `page-filter`（可选，按需）

## 3. 全站评估表（逐页核对）

> 实勘结论（2026-10-15）：全站**没有任何页面落地四件套 testid 契约**（`page-title` /
> `page-primary-action` / `page-secondary-info` / `page-filter` 在代码中 0 命中）。
> 各面板自行渲染头部，`MainLayout` 仅按 `view` 切换、不提供共享页头。 ⇒ 真问题不是
> 「某页违反了标准」，而是「标准本身尚未实现」。下列「当前态」按各面板实际头部结构记录，
> 最终以 §4 门禁逐页断言落实。

| 页面 | 当前头部结构 | 四件套契约 | 主要差距 | 严重度 |
|---|---|---|---|---|
| 下载（标杆） | 自有概览口径（在传/待处理/已完成/已取消对象数）+「新建下载」入口；状态档走侧栏树 | 元素在，无 testid | 标题/主按钮/次级信息未标准化、无 `page-*` 锚点 | 中（先立契约） |
| 文件 | `FilesPanel` 薄包 `MediaLibraryPanel`；媒体库内部有标签云/类型切换（rail 能力，非页级筛选） | 无 testid | 标题与次级信息口径随媒体库内部视图漂移；无统一页头 | 高 |
| Telegram | `TgPanel` 自有头部；未登录走 `TgOnboarding` 引导卡 | 无 testid | 标题/主操作随会话态变化，无恒定页头；引导卡与主视图头不统一 | 高 |
| 设置 | `SettingsPanel` 自带标题 + 多 Tab（下载/Telegram/关于…） | 无 testid | Tab 是「设置分组」非「筛选」；标题在 Tab 之上但无 `page-title` 锚点 | 中 |

判定口径：
- 标题缺失 / 主按钮多于一处且互相竞争 / 次级信息位置漂移 / 把筛选当主按钮平铺 = 违反。
- 筛选④去留（先评估再定）：下载域状态档已用侧栏树承担（非页内筛选），页内 `page-filter`
  无刚需 → 不上；文件/媒体库的标签云、类型切换是 rail 能力，不是页级 `page-filter`，不强行归并；
  设置 Tab 是分组不是筛选。⇒ 当前四页**均无页级 `page-filter` 刚需**，④暂缓，待「全站检索」
  等真实需求出现再评估。

## 4. 门禁

`tauri-shell/verify/` 加页面结构回归（逐页断言四件套层级存在 + 位置）；反向证伪：删标题 /
把筛选提为主按钮必须 FAIL。当前状态：**门禁未写**，随契约落地一并补。

## 6. 实施顺序（doc-first，按严重度）

1. **抽共享 `PageHeader` 组件**：统一 sticky 顶条（左 `page-title`、右 `page-primary-action`、
   下次级信息 `page-secondary-info`），四件套强制出 testid。`page-filter` 留可选插槽。
2. **下载页先行（标杆落地）**：把现有概览口径 + 「新建下载」迁入 `PageHeader`，补 testid；
   同时是反向证伪锚点（删标题/把筛选提为主按钮 → FAIL）。
3. **文件页**：`MediaLibraryPanel` 头部接入 `PageHeader`；标签云/类型切换保留为 rail 能力，
   不冒充 `page-filter`。
4. **Telegram 页**：`TgPanel` 与 `TgOnboarding` 共用同一 `PageHeader`，引导态也恒定有标题。
5. **设置页**：标题上提为 `page-title`；Tab 维持分组语义（非筛选），不套 `page-filter`。
6. 补 §4 门禁脚本，CI 跑反向证伪。

> 待拍板（第④项）：页级 `page-filter` 当前四页均无刚需，是否同意④暂缓、不强行上筛选入口？
